# 成交价格与撮合

回测撮合引擎将记录的订单簿和成交数据视为不可变数据。模拟成交不会修改历史订单簿。
这样既能保持回放市场不变，也要求明确设定：同一份展示流动性是否可以供多个模拟订单成交。

引擎提供以下两个控制项来设定这些假设：

- `liquidity_consumption=True` 会跟踪每个价格档位已消耗的展示数量。
- 为成交模型固定 `random_seed`，可使该模型的概率决策重复再现。
  它不会配置该模型以外的随机性或执行顺序。

## 成交价格的确定

成交价格取决于订单类型、流动性方向、订单簿类型，以及促成撮合的市场状态。

### L2 和 L3 订单簿

使用深度数据时，市价类订单会逐档扫过可成交的订单簿档位。限价类订单作为吃单方时，
按可成交的订单簿价格成交；作为挂单方时，则按其限价成交。

| 订单类型               | 成交行为                                           |
| ---------------------- | -------------------------------------------------- |
| `MARKET`               | 作为吃单方逐档扫过可成交的订单簿档位。             |
| `MARKET_TO_LIMIT`      | 扫过订单簿，然后将剩余数量以首次成交价挂单。       |
| `LIMIT`                | 作为吃单方时使用可成交档位，作为挂单方时使用限价。 |
| `STOP_MARKET`          | 触发后逐档扫过可成交档位。                         |
| `STOP_LIMIT`           | 触发后使用限价类规则。                             |
| `MARKET_IF_TOUCHED`    | 触发后逐档扫过可成交档位。                         |
| `LIMIT_IF_TOUCHED`     | 触发后使用限价类规则。                             |
| `TRAILING_STOP_MARKET` | 激活并触发后逐档扫过可成交档位。                   |
| `TRAILING_STOP_LIMIT`  | 激活并触发后使用限价类规则。                       |

当可成交档位的可用数量小于使用深度数据撮合的订单的剩余数量时，该订单可以部分成交。

### L1 订单簿

使用 L1 订单簿时，记录的市场仅提供最优买价和最优卖价：

| 订单类别                                                               | 成交行为                                                                       |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `MARKET`、`MARKET_IF_TOUCHED`、`STOP_MARKET` 和 `TRAILING_STOP_MARKET` | 使用市价或触发价规则，然后将任何剩余数量以劣化一个最小价格变动单位的价格成交。 |
| `MARKET_TO_LIMIT`                                                      | 使用对手方最优报价，然后将剩余数量以首次成交价挂单。                           |
| 限价类吃单方                                                           | 使用最优的可成交报价，但不越过限价。                                           |
| 限价类挂单方                                                           | 因成交或市场变动而撮合时使用限价。                                             |

符合条件的市价类订单耗尽 L1 展示数量后，剩余数量适用劣化一个最小价格变动单位的成交规则。
如果该价格会越过已配置的边界，价格保护可以阻止这笔剩余数量成交。
这项确定性的剩余数量规则独立于成交模型的概率性滑点。

由成交数据驱动的撮合还有一项额外规则。如果一笔成交在订单簿中不存在的价格上提供了成交依据，
引擎会按订单的限价成交，并将成交数量限制在该笔成交的数量以内。
参见[基于成交数据的执行](trade-execution.md#trade-driven-matching)。

成交模型可以改变价格或提供合成深度订单簿。参见
[成交模型](fill-models.md)。

### 使用 K 线时触发的市价单成交

对于 `STOP_MARKET`、`MARKET_IF_TOUCHED` 和 `TRAILING_STOP_MARKET` 订单，K 线执行会区分跳空与
K 线内价格变动。

如果 K 线开盘价已越过触发价，订单会按模拟市场价格成交。例如，触发价为 100 的 SELL 止损单，
在下一根 K 线以 90 开盘时，可以按 90 成交。

如果 K 线开盘价尚未越过触发价，而之后的最高价、最低价或收盘价越过了触发价，
引擎会使用触发价。例如：

1. 一张 SELL 止损单的触发价为 100。
1. K 线开盘价为 102。
1. 最低价触及 98。
1. 订单按 100 成交。

此规则假设价格连续移动并穿过触发价。如果策略需要更精确的跳空和价格路径行为，
请使用报价、成交或订单簿数据。

## 价格保护

价格保护会限制 `MARKET` 和 `STOP_MARKET` 订单扫过订单簿的最大距离。将偏移量配置为
该交易品种最小价格变动单位的倍数：

```python
from vibe_trader.config import BacktestVenueConfig
from vibe_trader.model import AccountType
from vibe_trader.model import BookType
from vibe_trader.model import OmsType

venue = BacktestVenueConfig(
    name="SIM",
    oms_type=OmsType.NETTING,
    account_type=AccountType.MARGIN,
    book_type=BookType.L2_MBP,
    starting_balances=["100_000 USDT"],
    price_protection_points=100,
)
```

引擎会在成交时计算边界：

- BUY：`ask + (points * price_increment)`
- SELL：`bid - (points * price_increment)`

对于最小价格变动单位为 0.01 的交易品种，100 点允许 BUY 订单的成交价最多比当前卖价高 1.00。
超出边界的档位会被排除，因此订单可能保持部分成交状态。

市价单在处理时获得其边界。止损市价单在触发时获得其边界，所用的是当时的买价或卖价。
设置 `price_protection_points=0` 可禁用保护。

## 订单簿不可变性

模拟成交绝不会扣减历史订单簿。默认情况下，每次撮合迭代都可以使用记录的全部数量：

```python
from vibe_trader.config import BacktestVenueConfig
from vibe_trader.model import AccountType
from vibe_trader.model import BookType
from vibe_trader.model import OmsType

venue = BacktestVenueConfig(
    name="SIM",
    oms_type=OmsType.NETTING,
    account_type=AccountType.CASH,
    book_type=BookType.L1_MBP,
    starting_balances=["100_000 USD"],
    liquidity_consumption=True,
)
```

使用 `liquidity_consumption=True` 时，引擎会记录每个价格档位的原始数量和已消耗数量。
可用数量为 `original_size - consumed`。该档位收到新的订单簿更新时，记录会重置为新的展示数量。

### L1 被动成交

当 L1 市场价格越过被动限价单的限价时：

| `liquidity_consumption` | 剩余数量的处理方式                                     |
| ----------------------- | ------------------------------------------------------ |
| `False`                 | 将订单的全部剩余数量按其限价成交。                     |
| `True`                  | 仅成交尚未消耗的展示数量，其余部分继续保持未成交状态。 |

例如：

1. 卖价为 100.10，数量为 50 单位。
1. 一张数量为 1,000 单位、限价为 100.05 的 BUY LIMIT 订单正在挂单。
1. 下一笔卖价为 100.00，数量为 30 单位。
1. 启用流动性消耗后，30 单位成交，970 单位继续保持未成交状态。
1. 后续更新可以提供更多新数量。

### 成交数据消耗

一笔成交可以在当前订单簿中不存在的价格上提供可执行数量。启用流动性消耗后，
由成交数据驱动的各笔成交会共享这份数量，而不是让每个订单都消耗该笔成交的全部数量。

对于 L2 和 L3 订单簿，触发撮合的成交可能已经消耗了展示深度。引擎会先计入这部分成交量，
再让已触发订单使用该档位的剩余数量。如果已有更新的订单簿更新反映了该笔成交，
引擎会跳过这项调整。

成交模型返回的合成订单簿不使用逐档流动性消耗跟踪。模型必须自行表达其流动性假设。

### 局限性

流动性消耗跟踪估算的是可用数量，而不是订单优先级。若要跟踪展示队列，
请在同时使用订单簿和成交数据时设置 `queue_position=True`；也可以使用 `prob_fill_on_limit`
进行概率近似。

由成交数据驱动的成交也只能利用当时碰巧可用的流动性：一笔成交记录只能证明流动性曾在某个瞬间存在，
并不能证明在记录的成交发生后，这份流动性仍然可用。

## 精度要求

价格和数量必须使用交易品种配置的 `price_precision` 和 `size_precision`。
精度不匹配的结果取决于数据从何处进入撮合引擎：

| 输入         | 校验字段                               | 不匹配时的结果                             |
| ------------ | -------------------------------------- | ------------------------------------------ |
| `QuoteTick`  | 买价、卖价及其数量                     | 记录警告并跳过该条报价数据。               |
| `TradeTick`  | 价格和数量                             | 记录警告并跳过该条成交数据。               |
| 可执行 `Bar` | 开盘价、最高价、最低价、收盘价和成交量 | 记录警告并跳过该 K 线。                    |
| 新订单       | 数量、展示数量、价格和触发价           | 拒绝该订单。                               |
| 订单更新     | 数量、价格和触发价                     | 拒绝该修改。                               |
| 生成的成交   | 成交价格和数量                         | 兼容时进行归一化；否则警告并跳过该笔成交。 |

连续发生 20 次市场数据精度不匹配后，引擎会记录错误。使用 `shutdown_on_error=True` 时，
该错误可以请求正常关闭回测。有效的报价、成交或可执行 K 线会重置连续不匹配计数。

`Bar.volume` 必须使用交易品种的数量单位和数量精度。创建 K 线前，
请转换数据提供商特有的计价币成交量字段。

使用交易品种工厂方法构造兼容的值：

```python
price = instrument.make_price(raw_price)
quantity = instrument.make_qty(raw_quantity)
```

还应确认交易品种定义与数据源相符，并确认自定义加载器保留了源数据的精度。
