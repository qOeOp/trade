# 回测数据与交易场所

## 数据

历史数据会推进回测时钟、更新模拟市场状态并驱动策略回调。交易场所的 `book_type`
决定哪些数据可以更新撮合订单簿，因此配置必须与可用数据相匹配。

订单簿数据比报价、成交或 K 线提供更多执行细节，但即使是记录下来的订单簿，也无法
呈现模拟订单本会如何改变市场。VibeTrader 按细节从多到少支持以下数据：

```mermaid
flowchart LR
    L3["L3 订单簿<br/>（逐笔委托）"]
    L2["L2 订单簿<br/>（逐价位）"]
    L1["L1 报价<br/>（最优档）"]
    T["成交"]
    B["K 线"]

    L3 --> L2 --> L1 --> T --> B

    style L3 fill:#2d5a3d,color:#fff
    style L2 fill:#3d6a4d,color:#fff
    style L1 fill:#4d7a5d,color:#fff
    style T fill:#5d8a6d,color:#fff
    style B fill:#6d9a7d,color:#fff
```

粒度越细的数据，能呈现的已记录队列与深度就越多；粒度越粗的数据，则需要越多的
模拟假设。

- **L3 订单簿数据（按订单记录）**：记录每个价格档位上的单笔订单。
- **L2 订单簿数据（按价格记录）**：记录每个价格档位上的聚合数量。
- **L1 报价 tick（按价格记录）**：记录最优买卖价及其数量。
- **成交 tick**：记录已经发生的成交。
- **K 线**：聚合固定区间内的价格与成交量。

### 选择数据：成本与准确度

在策略开发早期，K 线数据可能已经足够，而且通常比 tick 或订单簿数据更便宜、更容易
获取。不过，它无法确定 K 线内部的价格先后顺序、价差、深度或队列位置，因此对执行
敏感的策略需要使用粒度更细的数据验证。

:::tip
合适时，可以先用 K 线测试核心信号。若结果依赖价差、精确的 K 线内价格顺序、严格的
退出条件或队列位置，应先改用报价、成交或深度数据验证，再据此作出判断。
:::

## 交易场所

初始化回测交易场所时，必须从以下选项中指定用于执行处理的内部订单 `book_type`：

- `L1_MBP`：一级按价格记录（默认）。仅维护订单簿最优档位。
- `L2_MBP`：二级按价格记录。维护订单簿深度，每个价格档位聚合为一笔订单。
- `L3_MBO`：三级按订单记录。维护订单簿深度，并按数据原样跟踪所有单笔订单。

`book_type` 决定哪些数据会更新订单簿状态并驱动撮合。不适用于所选订单簿的数据会被
订单簿和价格更新忽略，但外层回测时钟仍会推进。策略仍会通过数据引擎收到已订阅的
数据。精度验证取决于撮合路径；例如，被 L2 或 L3 交易场所忽略的 K 线，会在可执行
K 线精度检查之前返回。

| 数据类型           | L1_MBP     | L2_MBP     | L3_MBO     |
| ------------------ | ---------- | ---------- | ---------- |
| `QuoteTick`        | 更新订单簿 | *忽略*     | *忽略*     |
| `TradeTick`        | 触发撮合   | 触发撮合   | 触发撮合   |
| `Bar`              | 更新订单簿 | *忽略*     | *忽略*     |
| `OrderBookDelta`   | *忽略*     | 更新订单簿 | 更新订单簿 |
| `OrderBookDeltas`  | *忽略*     | 更新订单簿 | 更新订单簿 |
| `OrderBookDepth10` | 更新订单簿 | 更新订单簿 | 更新订单簿 |

:::note
数据粒度必须与指定的订单 `book_type` 相匹配。Vibe 无法从报价、成交或 K 线等低粒度数据
生成更高粒度的数据（L2 或 L3）。
:::

:::warning
如果将交易场所的 `book_type` 指定为 `L2_MBP` 或 `L3_MBO`，报价和 K 线将不会更新
订单簿。请确保提供订单簿增量数据，否则订单可能看起来始终无法成交。
:::

:::warning
使用 `L1_MBP`（默认值）时，撮合引擎会忽略订单簿增量。如果订阅订单簿增量，请将
交易场所的 `book_type` 设为 `L2_MBP` 或 `L3_MBO`。这同样适用于沙盒执行，因为其
撮合引擎使用相同的 `book_type` 配置。
:::
