# 快速开始

本流程是研究产品的操作顺序与端到端验收目标。[交付路线](../architecture/)以 V0.1 的 R-1 数据/编写/回放为首版，V0.2 再扩展持续迭代；完整研究循环不作为首版前置。先确认[当前能力](./agent-implementation/)和服务部署，
缺失步骤按具名状态停止；它不假设目标已实现，也不需要 Paper 或 Live 会话。

## 1. 登记研究范围

用外部代理经 R&D 工具提交来源、主题、风险容忍、比较目标、资源上限和停止规则。读取接纳回执与冻结身份，
而非只看工具送达。范围内可自主迭代；改变通过标准或范围需要新确认。

## 2. 准备点时数据

通过 Market Data MCP 查询标的与覆盖，提交有界 backfill 并保存 job 身份。服务运行任务；代理查询状态。
缺口与保护分区按名拒绝。`dataset_ref` 描述市场和窗口，后端解析并绑定准确托管，不由代理搬运 bar 数据。

## 3. 编写并封存策略

提交 JSON `research.strategy-authoring.v1`，校验信号/保护规则、有界仓位规则及获准执行政策引用，读取不可变 Artifact。
当前支持的编写子集见 R&D 正文；完整 R-1 挂单与分段退出不能用目标描述替代实现。

## 4. 提交回测并读回结果

调用 Backtest MCP 提交运行。后端持有完整确定性链路，返回稳定任务/运行身份；断开重连后查询同一身份。
报告须绑定输入、模型、原生订单/成交与组合统计。任务完成而业务结果未知时保持未决，不盲目重跑。

## 5. 决定下一步

比较预登记的组合收益、回撤和基线。R&D 记录修复、后继、停止或选择，不隐去失败与资源消耗。
只有已选择的冻结候选才能另行提交 Qualification；保护结论不回流策略优化，资格不授权交易。

## 完成条件

代理可按原身份恢复来源、Artifact、数据、运行和决定，用户可检查事实与具名失败。各步骤的接线与准入状态
按实现指南及所属 Owner 核验，不能用日志或图表冒充结果。[研究设计](../scenarios/research/)给出完整 R-1 验收。
