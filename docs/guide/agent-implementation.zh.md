# Agent 实现指南

本页说明如何按产品设计修改当前引擎。先按[能力扩展图](../architecture/capability-adoption/)选择原生接入点，再定位下表中的契约与消费者。
源码、示例或可调用 API 不授予产品权限；内部调用与直接 MCP 调用执行相同的准入、预算、保护读取和恢复检查。

## 两层文档

规范层由已发布的 `guide`、`architecture`、`owners`、`scenarios` 根目录以及 canonical 架构契约组成。
它决定一次变更的写入者、消费者、身份以及 accepted、rejected、unknown、replay 行为。

实现参考层继续保留在仓库中。它解释当前工具链、API、引擎机制、测试工具、扩展点与示例。
这些页面没有被删除，但它们不是产品权威；文件存在也不代表内容自动符合当前版本。

## 研究任务入口映射

先检查当前仓库的 Nautilus API、扩展点和原生消费者。复用已有机制，只补最小缺口，并同步设计。
只有用户意图无法从已有故事确定，或测量揭示产品取舍时才提问；说明已有机制、缺口与选项。
分别验证原生能力、当前源码与产品接线；新版官方文档不证明本候选已实现。
复用必须保留 Owner 权威、冻结研究协议和保护边界。

先读[研究场景](../scenarios/research/)与准确当前候选版本，选择最早缺失转换，再按此表读取生产者、消费者与边界依赖。

| 有界交付结果                       | 所属设计                                                  | 验收消费者                                                   |
| ---------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------ |
| 在用户范围内登记家族并恢复计数实验 | R&D Intent、census、读取血缘、支出上限；Product Edge 授权 | 代理在结果读取前登记，并按原生身份恢复试验                   |
| 封存并加载 R‑1u/R‑1s 原生 Strategy | R&D 编写；Strategy Factory 共享生命周期/订单契约          | 真实模拟器驱动挂单、到期、保护、分段退出、成交反馈与事件顺序 |
| 异步产出永续研究报告               | Market Data 托管；R&D 运行准入；Backtest Result           | 原生报告含资金费、成本、组合风险收益、重叠、比较与逐交易诊断 |
| 诊断、暂停、停止或复核新证据       | R&D Iteration Decision 与知识台账                         | 亏损与未决试验可见，未合格不关闭机制                         |
| 资格评估与只记录前向证据           | Qualification；Backtest 共享回放语义                      | 二级公开判决、内部保护细节、持久模拟订单且没有交易效果       |
| R‑1 后复现动态 B3 与多腿 carry     | Strategy Factory 动态标的池；Market Data 与 Backtest      | 换成员时权益/状态连续，多腿资本、资金费与保证金可计量        |

此表不宣称实现成熟度，也不准入 Dashboard 路由。在当前候选核对生产者与读回，旧 `CURRENT` 标签不是证据。
每项任务点名一个用户可见结果、一个 Owner、被扩展或取代的既有路径以及正向/拒绝读回；设计被否定时把测量与修改
放在同一交付里。不能为了补缺失原生 operation 而加第二 registry、模拟器或任务台账。

## 开发工作流

1. 从用户故事选一个可观察结果，明确负责的 Owner、输入、消费者与禁止的写入。
2. 核对当前候选的原生 API、相关源码、`Makefile`、pre-commit 与 CI；只读取相关实现参考。
3. 优先复用 Nautilus 或现有基础设施。Agent 决定最小接线；只有已有机制不能满足场景时才增加扩展。
4. 用真实消费者验证结果、拒绝、未知与同身份恢复，按实际风险选择检查，不为每次改动强制创建同一套测试。
5. 在同一交付中更新受影响文档，保留准确候选、执行命令、终态结果及尚未证明的能力。

源码与参考不匹配时，以当前源码定位缺口，修改设计或实现；不能照抄过时 API，也不能把缺失证据当作通过。
验证证据须能定位实际候选与输入，不能只写 "checked"。这些要求由 Agent 的工作记录与真实检查承接，
不要求另建 JSON 规划包、逐字段签发回执或为了开工登记首页图中的节点 ID。
[开发切片](./development-chunk-contract/)提供简短的范围检查。

实现参考不授予业务事实写入权、Market Data 读取权、保护信息访问权或 Paper/Live 效果权限。
授权、输入身份、保护隔离和实际消费验证仍由对应服务执行；简化开发流程不能绕过这些边界。

## 冲突与过期规则

把已记录 Owner 契约作为当前设计阅读，再对照真实消费者与当前源码检验。引用过期 symbol 或命令的参考已过时；
源码可调用或旧示例曾成功不能证明目标产品路径。无法承接所需用户故事的设计要带着迫使它改变的观测显式修改，
不能被当作最终蓝图。

Main 可把范围内的过时设计与实现一起修正并交付审阅。记录差异、重规划依赖它的切片并验证新契约，
不要求独立文档 PR。`AGENTS.md` 对产品目的或用户路径变化、生产效果以及移除拒绝、封口、界或不变量的
用户授权边界仍适用；保留无关工作。

## 验证注意事项

- 搜索已跟踪源码时使用 `git grep` 或明确范围的 `rg -uu`，避免忽略规则漏掉 workflow、迁移和测试。
- CI 重跑后按检查名读取最新一次结果，并核对准确 PR head；旧绿灯不是当前通过。
- Squash 合并用实际 `mergeCommit` 和文件内容核对，不以原 PR head 的祖先关系判断改动是否落地。
- 原生 API 的可调用性、部署镜像的 feature 和实际消费者分别核验；只在测试中调用的 helper 不证明服务可用。
- 资源和时延结论来自具体任务测量；构建通过不证明目标规模可以运行。
- 文档双语、图示和路由通过当前门禁验证；失败定位到具体差异，不用固定章节文字或关键词测试锁住蓝图。

## 能力核对与开发入口

| 开发目标       | 核对位置                                | 可用性的证据                     |
| -------------- | --------------------------------------- | -------------------------------- |
| 数据查询与准备 | Market Data、原生 catalog 与 DataClient | 准确绑定可读取，缺口具名返回     |
| 原生策略封存   | R&D、Strategy 包与加载器                | 实际源码闭包和环境被封存并加载   |
| 原生回放与报告 | Backtest、原生结果及持久读取            | 服务执行真实请求，完整结果可回读 |
| 研究记录与知识 | R&D MCP/API                             | 准确项目、实验与引用可持久查询   |
| 用户界面与运行 | Dashboard、Governance、原生节点         | 所属路由准入和真实消费者验收     |

目标设计不宣称当前实现已接通。每次任务核对准确源码、接线与消费者；完成最早缺失依赖，
不为接线缺口创建替代引擎。文档修改合入所属正文与直接链接，不保留修订日记或竞争蓝图。
