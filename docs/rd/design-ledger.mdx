# Database

当前研究账本为模式第 3 代：一次执行只用 `trial_id`，结果表与子表复用它；旧第 2 代账本保持原样，由固定旧版代码读取，不原地迁移或重写历史。新库不清除既有研究暴露，接续须先明确跨代边界。同一代里新加的表（如 `line_target`）由 `ledger upgrade` 补建，不改代数；没有这张表的提交读作没有这类记录。

Find a record by responsibility, then inspect its fields, relations and writers.

| Responsibility | Stored facts or reading surface |
|---|---|
| [Candidates and lineage](/en/docs/design-database-candidates/) | Complete strategy source, content identity and parent links identify each candidate revision. |
| [Trials and registration bindings](/en/docs/design-database-trials/) | Execution identity, purpose and window are recorded separately from the registration grid point that consumed the trial. |
| [Runs and sealed readings](/en/docs/design-database-runs/) | Execution validity, audits, fingerprints, sealed reports, daily returns and native position cycles have distinct records. |
| [Evidence bundles and originals](/en/docs/design-database-evidence/) | Bundles organize file paths pointing to content-addressed originals. Research lines and registration declarations use these bundles rather than duplicate records. |
| [Research judgments and subjects](/en/docs/design-database-judgments/) | Append-only judgments retain supersession links and the candidates, trials and registrations they refer to; the user's research targets for research lines are kept beside them. |
| [Validation and timestamp witnesses](/en/docs/design-database-validation/) | Preregistered conditions, one execution binding and timestamp tokens retain separate responsibilities. |
| [Market data and universe](/en/docs/design-database-market/) | Contract specifications, last/mark bars, inferred bid/ask quotes, the complete source aggTrades, funding and the monthly universe. |
| [Schema versions and write coordination](/en/docs/design-database-coordination/) | Schema versions and the ledger write head coordinate storage; Dolt system tables and stored tests support history and consistency checks. |
| [Read views and research history](/en/docs/design-database-views/) | Business and research-history views derive a reading surface from stored facts. They add neither stored facts nor an access boundary. |
