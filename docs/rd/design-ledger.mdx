# Database

The research ledger is a Dolt database at schema generation 1 (`ledger/schema.sql`, `SCHEMA_VERSION` in code). The user backed up and deleted the old ledger on 2026-11-10; generation 1 starts from an empty ledger and migrates no old data. Until 1.0 a schema change starts a new ledger and migrates no data (AGENTS.md); within a generation, a changed reading (`run_reading`) is recomputed by resealing with the new code.

Tables fall into three tiers:

- **Commitments**: every business table except `run_reading`. Append only: the writer holds SELECT and INSERT, and `ledger review` reports any changed or removed row.
- **Readings**: `run_reading`. One current reading per passed run, written only by the product's seal commands; a reseal replaces it after the fingerprints match, and earlier values stay in Dolt history and the public copy.
- **Write coordination**: the single `ledger_head` row, which the writer may UPDATE.

Every write is exactly one transaction, one Dolt commit and one `ledger_head` step; times that prove order come from server triggers and content hashes are generated columns. Paper runs live in a separate Paper database and market data in Parquet files in the market directory, neither in the research ledger.

Find a record by responsibility, then inspect its fields, relations and writers.

| Responsibility | Stored facts or reading surface |
|---|---|
| [Candidates, lineage and source reviews](/en/docs/design-database-candidates/) | Complete strategy source, content identity and parent links; the independent source review after each native precheck. |
| [Registrations and trials](/en/docs/design-database-trials/) | A research registration's prediction, grid and execution identity; each replay's trial row, instruments, capture outcome and file dispositions. |
| [Runs and sealed readings](/en/docs/design-database-runs/) | A run's verdict and fingerprints, its resealable reading, daily returns and native position cycles. |
| [Evidence bundles and originals](/en/docs/design-database-evidence/) | Bundles organize file paths pointing to content-addressed originals stored once. |
| [Research lines, targets and judgments](/en/docs/design-database-judgments/) | Research lines with their fixed development period, line closings, the user's research targets, and append-only Agent judgments with their subjects. |
| [Validation and timestamp witnesses](/en/docs/design-database-validation/) | Preregistered conditions and timestamp tokens proving a registration commit existed before a given time. |
| [Schema version, write coordination and review](/en/docs/design-database-coordination/) | The schema generation, the write head, and the Dolt history tables `ledger review` reads with its checks. |
| [Read entry points and research history](/en/docs/design-database-views/) | How read commands read the ledger (there are no SQL views), and the closing history test's segments and verdicts. |
| [Paper database](/en/docs/design-database-paper/) | Paper run declarations, copied sources and sealed files; a separate database, never the research ledger. |
| [Market data and universe](/en/docs/design-database-market/) | Contract specifications, last/mark bars, inferred bid/ask quotes, complete source aggTrades, open interest and long/short ratios, funding rates and the monthly common universe; not in Dolt but plain Parquet files per table and month in the market directory. |

## Database relationships

The research ledger, the Paper database and the market directory are drawn apart: no foreign key crosses them.
