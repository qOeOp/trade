# 10　绩效归因：比较出结果之后，把两个版本的差拆开：钱从哪来、规模多大、在哪些合约和哪些天、靠哪些交易，再落到具体职责，指向下一个假设。

第 9 章回答的是「这个差可不可信」，本章回答「这个差从哪来」。对比报告和单个运行的报告用同一套第 8 章的报告模板，栏目和顺序都固定。归因的结果最后落到 27 项职责上，也就是策略文件开头逐项写明立场的那些事，比如止损、仓位、入场方式。

本章做四件事。代码先算 Agent 不该自己打分的部分：账户利润来源桥、每个切面的几个标量，以及登记时的预测和实测对照。逐合约、逐月这类明细，由 Agent 按skill（写给 Agent 的工作规程）自己算，驱动决定的数再交给另一个 Agent 复算。两处改动会不会相互影响，要在登记时事先声明才读。最后 Agent 按职责写解释，交给第 11 章排研究优先级。

举个例子：全池 RSI 路线里，H07 在 H06 的基础上加了按历史资金费方向过滤新入场，账户净值多了约 658 USDT。拆开看，资金费多赚约 829，价格盈亏反而少了约 282，13 个月里只胜了 6 个月。账户差是正的，但过滤改变的不只是资金费，下一个假设可以单独检验价格这一腿。十组比较的配对区间全部跨零，所以这些读数只是下一个假设的线索，不是结论。

### 报告的边界 [#P-1-1]

归因只解释已经检验过的差；拆成哪些切面、给哪些数，由代码固定。

#### 归因只解释已检验过的差，不改检验结果 [#P-1-1-1]

归因的输入是一份检验结果所绑定的候选和对照，身份直接沿用比较入口。比较被拒绝，归因也拒绝，拒绝码原样带出。输出是各切面两侧的标量和差，和检验结果并排放，不重新做检验。

明细的拆法太多，不适合都写进代码；但 Agent 用自己算的数来支撑自己的结论，就是给自己打分，所以关键的数要别人再算一遍。

## 10.2　机制预测：登记时写在切面标量上 [#P-2]

登记时就写好预测：改动会让哪个切面的哪个数往哪个方向变，回放后拿实测对照。

<Steps>

<Step>

登记时，每个改动到的职责至少写一项预测：某个切面标量会升还是降。

</Step>

<Step>

回放后，报告把每项预测和实测并排列出，只标方向对不对。

</Step>

<Step>

机制成不成立看预测有没有落空，不看账户差是不是正的。

</Step>

</Steps>

### 预测的写法与核对 [#P-2-1]

预测是登记内容里的一组结构化条目，登记时核对并锁定。

#### 预测写成某个切面标量的升或降，登记时核对并锁定 [#P-2-1-1]

机制预测是登记内容里的结构化条目。每项写切面、标量、方向（升或降）、职责编号和一句理由；某项职责没有对应的切面，就写空切面并写理由。登记时代码核对，不符就拒绝（PREDICTION_INVALID）。预测随登记的证据包一起锁定，回放后不能改。

预测要写在能量出来的数上，事后才能判断它落没落空。登记时不核对，预测就可能写成谁也核不了的空话，或者漏掉某个改动到的职责。

<div className="rd-example">

比如资金费过滤这类改动，可以写一项：切面 profit_bridge，标量 funding，方向升，职责 H1，理由是避开要付资金费的方向。演练里 H07 的预测本就针对资金费，并写明不声称资金费的单项因果。

</div>

1. mechanism 里逐项写切面、标量、方向、职责编号和理由。
2. outcomes 里写好五类结果各自的后续动作（<Ref id="H.3.1.2" />）。
3. 登记时核对：职责必须在本次改动的职责清单里，每个改动到的职责至少一项，切面和标量必须在目录里；不符即拒绝。
4. 预测随登记证据包锁定，回放后不改。

#### 报告把预测和实测并排，只标方向对不对 [#P-2-1-2]

报告逐项列出预测的方向、实测的差值，以及两者是否同号。标量留空或切面为空的项，标为「无法核对」并写原因。报告不据此下结论，落空的预测同样是证据。

只标同号与否，是为了不让报告替 Agent 判机制成不成立。预测落空也要原样留着，它说明原先对机制的理解可能不对。

<div className="rd-example">

比如 H07 登记时若写了「funding 升」和「price 升」两项，报告会标前一项同号（实测 +829），后一项不同号（实测 −282）。两项都照样列出，不删落空的那项。

</div>

### 读法 [#P-2-2]

读报告时，账户差和机制要分开说。

<a id="P-2-2-1" />

**账户差为正但预测落空，只能说赚了，不能说机制成立**

账户差是正的，但预测的那个切面标量方向反了，解释里只写账户差，不写机制成立。

钱可能是从别处来的。把账户差为正当成预测对了，就会把运气或别的原因记到这个机制头上。

<div className="rd-example">

比如登记预测「放大预算后 unit_return 升」，实测账户差为正，但 unit_return 降了。解释只能写「账户差为正」，不能写「放大预算提升了品质」。

</div>

## 10.3　交互：两处改动是否相互影响 [#P-3]

两处改动会不会相互放大或抵消，要事先声明四个版本，才读这个交互。

<Steps>

<Step>

只改一处的比较本身就是这项职责的消融，不用另跑回放。

</Step>

<Step>

想读两处改动的交互，在补齐最后一个版本的那次登记里声明四个版本。

</Step>

<Step>

交互只用来解释差从哪来，不当作改善的证据。

</Step>

</Steps>

<a id="P-3-1" />

四个版本的形状由源码审查确认，交互用配对检验的同一套重抽来算。

### 只改一处的比较就是这项职责的消融，不另跑回放 [#P-3-1-1]

一个假设只改一处，它和对照的配对比较，本身就是去掉这项改动的消融。不为归因另跑消融回放。

另跑回放要多花试验次数，而且得到的还是同一个比较。已有的比较已经回答了「这一处改动值多少」。

<div className="rd-example">

H06 对 H05 只把单笔预算从 100 提到 500，账户差 −63 USDT。这个比较就是单笔数量这项职责的消融，不需要再跑一个去掉预算改动的版本。

</div>

### 声明过的二乘二：给交互项、平均贡献和未校正区间 [#P-3-1-2]

四个版本是：两处都没改、只改甲、只改乙、两处都改。绑定的源码审查要确认每个版本的源码都等于基础版本加上声明的改动。交互读数在账户日对数收益上算，区间标为「未校正」，不给 p。

两处改动可能互相放大或抵消，单独看各自的比较看不出来。只取一种加入顺序，分到的贡献会偏向后加的那个，所以两种顺序取平均。

<div className="rd-example">

推演里，资金费过滤在单笔预算 100 时日对数收益差合计约 0.0002，在 500 时约 0.0065，两者相差约 0.0063，像是存在交互。但这四个版本的形状还没经源码审查确认，不能当作交互读数。

</div>

1. 源码审查确认四个版本的形状：每个版本等于基础版本加上声明的改动。
2. 交互项＝两处都改 − 只改甲 − 只改乙 ＋ 都没改。
3. 甲的贡献取两种加入顺序下甲的边际效应的平均，甲、乙两份贡献相加等于总差。
4. 区间用配对检验的块自助法，对四条日收益序列的加权和重抽，标为未校正，不给 p。
5. 涉及仓位或容量的改动，另给按平均名义敞口归一后的交互项。

### 要读交互，就在补最后一个版本的登记里声明 [#P-3-1-3]

想读两处改动的交互，在补齐最后一个版本的那次登记里，声明四个版本。交互只用来解释差从哪来，不当作改善的证据。

### 沿谱系逐段加出来的差只是按顺序分摊 [#P-3-1-4]

沿着谱系一段一段加出来的差，取决于改动的先后顺序。不能把它写成各个改动的独立效应。

同样两处改动，先加哪个，后加的那个分到的数就不同。把顺序分摊当成独立效应，会高估或低估某个改动。

<div className="rd-example">

沿 H05→H06→H07，先加预算那段账户差 −63，再加过滤那段 +658。换个顺序，H08 对 H05 是先加过滤，只有 +17。同一个过滤，顺序不同，分到的数差了很多。

</div>

## 10.4　从归因到下一个假设 [#P-4]

<Step>

</Step>

<Step>

</Step>

<Step>

写成一条解释判断，交给第 11 章排研究优先级。

<a id="P-4-1" />

### 按对照表把切面信号落到职责，给出常见的下一假设 [#P-4-1-1]

对照表放在skill的归因参考文件里，每一行写：看到什么信号、看哪个切面、指向哪些职责、常见的下一假设是什么。由skill规定，Agent 照表落到职责，代码不强制。

同一个信号，不同的 Agent 可能读出不同的方向。有一张共用的表，指向才前后一致，也方便核对 Agent 是不是照做。

<div className="rd-example">

演练里，FHE 在 H05 到 H10 六个版本里都排在闭仓净盈亏最差的三个合约之内，ROOT 的原生摘要记为不设止损。按表里「同一批合约持续亏损」这一行，指向 A1、A2 或 F3；演练中这条线索没有被提成假设。

</div>

1. 资金费差主导而价格差为负：看 profit_bridge，指向 H1、B1；常见下一假设是把资金费写成显式的收益来源，或单独检验价格腿。
2. 规模放大后单位敞口收益下降：看 capital_scaled，指向 G3、E1；常见下一假设是按流动性定数量，或改容量上限。
3. 两侧都亏，候选少亏但单位敞口收益不变或更差：看 capital_scaled，指向 B1、A3；少亏来自少暴露而不是品质，回到信号或条件过滤。
4. 择时项为正，涨月敞口大、跌月敞口小：看 capital_scaled，指向 E3、A3；常见下一假设是保留并细化仓位随行情调整的规则。
5. 择时项为负或接近零：看 capital_scaled，指向 E3、A3；常见下一假设是加入随行情或波动调整仓位的规则。
6. 盈亏平衡费率倍数接近一：看 fee_stress，指向 G1、C2；常见下一假设是换执行方式，或加不交易带。
7. 差集中在少数合约，同一批合约在多个版本里持续亏损：看 by_instrument，指向 A1、A2、F3；常见下一假设是改资格或选择，或加保护边界。
8. 截距差接近零，斜率差解释大部分差：看 market_exposure，指向 E2、D2；常见下一假设是控制组合净方向或同向持仓数，或加对冲。

10. 胜率升而每笔期望降，平均赢变小：看 trade_structure，指向 F3、F4、C1；常见下一假设是改退出或保护边界，或改触发。
