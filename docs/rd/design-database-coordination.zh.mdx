### `ledger_head` [#def-table-ledger_head]

写入头指针单行：每次写入加一并记下本次操作 ID，是并发写冲突的碰撞点，也是幂等重放的索引

<TypeTable type={{ "singleton": { type: "TINYINT", description: "恒 1", required: true }, "seq": { type: "BIGINT", description: "每次成功写入加一；运行的 `sealed_seq` 取它", required: true }, "op_id": { type: "VARCHAR(160)", description: "本次写入的操作 ID；两事务写相同值会被 Dolt 静默合并，所以每次都写自己的值", required: true } }} />

**键与约束**

- 主键　`singleton`
- CHECK　`singleton = 1`
- CHECK　`seq >= 0`

**保护与读写规则**

- 写账号对本表有 UPDATE（协调行）；两个事务把它改成不同值，提交时冲突，后到者回滚并报 CONCURRENT_WRITE
- `ledger review` 把本表的改动当作正常写入

**写入方**　`ledger.db.write`（每次写入）

### `dolt_diff_<table>` / `dolt_history_<table>` [#def-table-dolt_system_tables]

Dolt 为每张表自动维护的系统表：`dolt_diff_<table>` 给出两次提交之间每行的增改删，`dolt_history_<table>` 给出每行在每个提交上的值、提交哈希和时间。账本不另存审计日志，改和删都在这里留痕。

**读取方**　`ledger review`（`report.review`）：只读账号钉住一个版本，对上次检查之后的提交逐表检查：

- 承诺层（除 `run_reading` 外的业务表）出现非 added 的行：ROW_CHANGED
- `run_reading` 的改动不是重封提交，或重封提交同时写了承诺行：READING_REPLACED_OUTSIDE_RESEAL
- 新增或改动的行对不上它的外键（从 `information_schema.key_column_usage` 逐个外键查；写账号能在会话里关掉外键检查，读账号又没有 `DOLT_VERIFY_CONSTRAINTS` 要的分支写权限）：CONSTRAINT_VIOLATED
- 见证凭证盖章的提交不是插入其登记的提交：WITNESS_UNBOUND
- 上次检查的提交或最新备份的头不在当前历史里：HISTORY_REWRITTEN；备份落后：BACKUP_BEHIND

发现只报告，不写入。

### 约束放在哪里

CHECK、ENUM、主键和唯一键对写账号成立，绕不过去；外键不一样，写账号能在会话里关掉检查，所以外键挡的是产品代码的错误，`ledger review` 事后复查。旧账本的 `dolt_tests` 版本内测试已删除，它们的规则改写成了上面各表的约束（新账本 schema 稿第 5 节）。时间由 BEFORE INSERT 触发器写服务器 UTC，不用调用方的值，也不用可以伪造的提交日期。
