## `market/aggtrades.py` [#def-mod-market-aggtrades-py]

完整源 aggTrades 的导入：一个已结束的月份，每个合约一个文件，同一个月的几个合约各在自己的工作进程里同时写入，逐日按官方校验和读取归档，按独立的 1e8 整数编码精确写入 <Ref id="table:agg_trade" />。推算报价（<Ref id="market.import_quotes" />、<Ref id="market.derive" />）从这些文件读成交；它不参与 K 线读取或周期派生；回放只在入口请求成交时由 <Ref id="market.trade_rows" /> 读它、<Ref id="market.write_trades" /> 写成 TradeTick。

| 入口 | 职责 |
|---|---|
| <Ref id="implementation:impl-market-aggtrades-py-import_month">import_month</Ref> | 一个已结束月份的一个或几个合约：持导入锁，核对市场非空，每个合约一个工作进程同时写文件，前一日续接核对，逐日分批写入，整月写完放到位 |
| <Ref id="implementation:impl-market-aggtrades-py-batches">batches</Ref> | 逐行读一日 CSV，按批产出行；核对编号连续、时间不倒退且落在当日，累计日读数 |
| <Ref id="implementation:impl-market-aggtrades-py-scaled">scaled</Ref> | 十进制字串精确转为 1e8 定标的有符号 64 位整数，放不进即 SCALE_LOSS |

#### `import_month` [#impl-market-aggtrades-py-import_month]

```python
def import_month(profile: dict, month: date, cache: Path, symbols: list[str], log=print) -> dict:
```

一个已结束月份的一个或几个合约，每个合约一个文件，文件写完不再改。合约清单为空、重复或格式不对即 IMPORT_SCOPE；`month` 不是月初或还没结束即 MONTH_INVALID（store.closed_month）。以 import 角色打开市场目录、持导入锁（lock）直到全部写完；目录里没有 K 线文件即 MARKET_EMPTY。每个合约在各自的工作进程里写自己的文件（解析每日 CSV 是主要的活）：这个合约月已有文件即 MONTH_EXISTS。前一日归档只过 batches 的校验与续接，不写入；没发布的前一日只在市场里还没有该合约更早的文件时放过。随后逐日 fetch_archive → batches，产出的批交 write_file 写成该合约该月的文件，写完由主进程 place 放到位，按合约顺序（store.contract_files）。整个调用返回 month、imports（按合约顺序，每项 month、symbols、codec、trade_rows、seconds）、trade_rows（合计）、market_commit 与 seconds。一个合约被拒不影响其他合约的文件，抛出的是第一个被拒合约的拒绝，消息里列出其他合约已写的文件。进程中断时没放到位的临时文件由下一次取锁删除，目录里的文件不变。

### `coverage_facts` [#def-market-coverage_facts]

在固定市场提交上为一个合约产出 market-coverage-v1 事实字典：成员月份、输入区间内成交价与标记价的缺口区间与零成交量分钟、两者时刻对齐、资金费结算条数与首末时刻；首末数据只作上市下架的代理（不是交易所事实，不另标状态）。导出器据此写回执进入输入身份，并写进开始回执的 input-coverage.json。

```python
def coverage_facts(
    market: Market,
    commit: str,
    symbol: str,
    start_ms: int,
    end_ms: int,
    last_bars: MinuteTable,
    mark_bars: MinuteTable,
    funding_rows: list[tuple[int, Decimal]],
) -> dict
```

<TypeTable type={{ "market": { type: "Market", description: "market.open_market 以 reader 角色打开的市场目录；全部读取经 market.read_table 按 commit 读" }, "commit": { type: "str", description: "已解析的市场提交：32 位 [0-9a-v]，不接受 main、head；区别于 Git 的 40 位十六进制 build_revision" }, "symbol": { type: "str", description: "合约公开名（非 ASCII 用原名，不用别名）" }, "start_ms": { type: "int", description: "输入区间起点（含预热与可能延续持仓所需的最早分钟），UTC 毫秒，整分钟" }, "end_ms": { type: "int", description: "输入区间终点，左闭右开，UTC 毫秒，整分钟" }, "last_bars": { type: "MinuteTable", description: "该合约 LAST 1 分钟 K 线（ts_open 升序，含 volume），调用方已按 commit 与区间读出" }, "mark_bars": { type: "MinuteTable", description: "该合约 MARK 1 分钟 K 线（ts_open 升序，无 volume）" }, "funding_rows": { type: "list[tuple[int, Decimal]]", description: "该合约区间内 (funding_time_ms, rate)，按实际结算时刻升序" } }} />

**返回**　dict，格式 market-coverage-v1：\{format, commit, symbol, input_interval_ms:[start,end], last:\{rows, first_open_ms, last_open_ms, gap_intervals_ms, missing_minutes, zero_volume_minutes\}, mark:\{同结构，无 zero_volume_minutes\}, last_mark_unmatched_minutes, funding:\{rows, first_ms, last_ms\}, member_months:[YYYY-MM-01…], listing_delisting:\{data_bounds_proxy:\{last:\{first_open_ms,last_open_ms\}, mark:\{…\}\}\}, interpretation\}；导出回执原样存入（market.export_episode）

**期望行为**

1. 核对区间：start_ms \< end_ms 且两者落在整分钟网格；核对 commit 为 32 位 `[0-9a-v]` 的已解析提交；不满足即拒绝，不做任何读。
2. 核对合约存在于该提交的 instrument 表（market.read_table）；不存在即拒绝；存在但无 K 线不拒绝，照实记零行。
3. 核对 last_bars、mark_bars 的 ts_open 均为整分钟且升序去重；不满足即拒绝（输入形状，不是市场事实）。
4. 对 LAST 与 MARK 各算 missing_intervals(ts_open, start_ms, end_ms, 60000) 得缺口区间与缺失分钟数；LAST 另计 volume == 0 的分钟数；两者 ts_open 对称差的条数记为 last_mark_unmatched_minutes。
5. 按 commit 读 universe_month 得该合约的成员月份；读 bar 表每价格类型的首末 ts_open 作上市下架的数据边界代理，只记边界，不另标状态或原因。
6. 组装字典返回：资金费只记条数与首末时刻（逐笔时刻留在钉住的提交里，market bars 可读），结算间隔与缺失结算由 market.diagnose_coverage 另算；不评级、不删币、不缩窗、不补数；interpretation 写明零活动与缺口不等于经济失败，也不替策略判定指标就绪。

| 拒绝码 | 条件 |
|---|---|
| `INTERVAL_INVALID` | start_ms >= end_ms，或任一端点不在整分钟网格上 |
| `MARKET_COMMIT_INVALID` | commit 不是 32 位 `[0-9a-v]` 的已解析提交（传入了 main、head、Git 的 40 位哈希或空值） |
| `UNKNOWN_SYMBOL` | 该提交的 instrument 表无此合约（市场里从没有这个合约，区别于有合约无 K 线） |
| `SOURCE_SHAPE` | last_bars 或 mark_bars 的 ts_open 不是整分钟、无序或重复 |

### `diagnose_coverage` [#def-market-diagnose_coverage]

入口与命令行的只读覆盖读口：按钉住的市场提交对显式给出的合约清单逐个产出覆盖事实，并在给了生命周期证据包时附上校验后的生命周期回执（上市、禁新仓、下架结算、ticker 重用）。只返回输入事实，不做资格评级，不删币、不缩窗、不补数、不判经济失败。

```python
def diagnose_coverage(
    profile: dict,
    at: str | None,
    symbols: list[str],
    start: str,
    end: str,
    lifecycle_bundle: tuple[dict, dict[str, bytes]] | None,
) -> dict
```

<TypeTable type={{ "profile": { type: "MarketProfile", description: "市场档案（市场目录），以 reader 角色打开" }, "at": { type: "str", description: "用户或研究路线记录给出的提交引用（市场提交；缺省 main，即最新的截至日），由 market.resolve_commit 解析" }, "symbols": { type: "list[str]", description: "显式合约清单；本读口不做全范围隐式展开，范围由调用方自 universe_month 读出后显式传入" }, "start": { type: "str", description: "输入区间起点，ISO-8601 显式 UTC，整分钟（含预热）" }, "end": { type: "str", description: "输入区间终点，ISO-8601 显式 UTC，整分钟，左闭右开" }, "lifecycle_bundle": { type: "LifecycleBundle | None", description: "调用方已从账本证据包读出的 native-lifecycle-v1 清单与来源原件（body, files）；None 表示不附生命周期回执。本层不读账本" } }} />

**返回**　dict：\{commit, scope:'explicit_symbols', input_interval_ms:[start,end], coverage:[market-coverage-v1 … 加 quotes:\{months:[\{month, rows\}], first_ms, last_ms, uncovered_intervals_ms\}，trades:\{同结构\}，metrics:\{months:[\{month, rows, empty:\{比值列: 空行数\}, missing_rows, missing_days\}], first_ms, last_ms, uncovered_intervals_ms\}，terms:\{observed_at, terms_source, price_increment, size_increment, min_quantity, max_quantity, min_notional, min_price, max_price\}，与 symbols 同序], lifecycle:\{symbol:[episode …]\} | None, lifecycle_missing:[symbol …], interpretation\}

**期望行为**

1. 解析区间：start、end 转 UTC 毫秒并核对整分钟与 start \< end；核对 symbols 非空且无重复；不满足即拒绝。
2. 经 market.open_market 以 reader 角色打开市场目录，market.resolve_commit(market, at) 得市场提交；解析失败按其拒绝码原样向上。
3. 若给了 lifecycle：先 market.validate_lifecycle(body, commit, files) 核对清单绑定同一提交、事件为引擎原生字典、时钟单调、来源原件在包内；不符即 LIFECYCLE_INPUT 拒绝整次读，不部分返回。
4. 逐合约经 market.read_table 读该提交 bar 表的 LAST、MARK 1 分钟 K 线与 funding 表区间内结算行，调用 market.coverage_facts 得事实字典；单个合约的 UNKNOWN_SYMBOL 不吞掉，按拒绝向上。再并入该合约的 quotes：与区间相交、该提交读得到的每个 quote 文件（月份、该提交下的行数：文件在提交的日子前结束时取自文件尾，否则读这个文件；一个月 BTCUSDT 数千万行，不为此读表），该提交的 quote 表在区间内的首末时刻，以及区间内没有文件的 [from, to) 段。trades 同样读 agg_trade 文件。metrics 同样读 metrics 文件，每个月另给三个比值列的空行数（empty）、持有的日子按 5 分钟格点少的行数（missing_rows）和到提交为止这个月没有的日子（missing_days），没有的日子并入 uncovered_intervals_ms。这三项都不进导出回执。再按 funding_spacing 并入该合约的结算间隔：相邻结算各取最近整点后的间隔，相等的连成一段（spacing:[\{spacing_ms, from_ms, to_ms\}]，换段即间隔变化）；单个间隔是两侧同一间隔的整数倍 k≥2 时记 k−1 次缺失结算（missing_settlements:[\{after_ms, before_ms, missing\}]），不算间隔变化。不进导出回执。再并入 market.terms(market, commit, symbol) 的规格行（去掉 symbol）：导出器对整个窗口用的就是这一行（提交上最新观测，CURRENT_SNAPSHOT_APPROXIMATION）。规格不进导出回执，回执已记 terms_source 与 terms_observed_at。
5. 把每合约的校验后生命周期片段并入返回；清单里没有该合约的记入 lifecycle_missing，只作事实不作判定。
6. 组装返回，不排序、不筛除、不改窗口；interpretation 固定说明缺口、零量、资金费缺失、首末数据均为输入事实，入口不据此删币、缩窗、补数或判经济失败，也不替策略判定指标就绪。

| 拒绝码 | 条件 |
|---|---|
| `INTERVAL_INVALID` | start、end 缺时区、不在整分钟网格或 start >= end |
| `EMPTY_SYMBOLS` | symbols 为空或含重复项（读口只接受显式清单，不做全范围展开） |
| `UNKNOWN_REF` | at 解析不了（由 market.resolve_commit 传出） |
| `UNKNOWN_SYMBOL` | 任一合约在该提交下不存在于 instrument 表（由 market.coverage_facts 传出） |
| `LIFECYCLE_INPUT` | 给出的生命周期证据包绑定的不是该提交、事件非引擎原生字典、时钟不单调或来源原件缺失（由 market.validate_lifecycle 传出） |

3. 费率以规范化十进制字符串写出，不改精度。
4. 按引擎 Catalog 布局写入 data/funding_rates/\<instrument_id>/\<首时刻>_\<末时刻>.parquet，元数据记 instrument_id 与数据类型，供回放节点装载。

#### `run_round` [#impl-market-follow-py-run_round]

```python
def run_round(profile: dict, scope: Scope, cache: Path, memory: Memory, now: datetime, log) -> dict:
```

先以 reader 角色列出市场目录持有什么（K 线每个月的第一个未持有日、每月成员、每个合约持仓量与多空比的日子、成交与报价的月份）；目录读不了（MARKET_UNREACHABLE 等）就整轮不导，状态为 unknown，一小时后再试。然后依次：

1. K 线：从 bar_months 给的月份起一月一月导到当月，传配置的 `bar_symbols`；要导到的最后一个收盘日，等前一天有日 K 线归档的合约这一天的归档都出了才导（下载进导入读的缓存；两天都没有的合约已停止交易，不等），收盘超过 LAG_DAYS（3 天）还没出全就照导（那天由 REST 补）。这样一个月封住时最后一天不会只有 REST 的数据。当月第一天没有已收盘的日子：上个月已导到月末、这个月还没有名单时，只导这个月的名单，上个月最后一天这个截至日由此才可读。
2. 持仓量与多空比：每个没停下的合约、每个还缺日子的月（missing，从 metrics_from 起），先在锁外下载日归档，一天都没发布就跳过、不拿锁，否则对这一个合约调用导入。收盘超过 SETTLE_DAYS（3 天）还没有归档的日子不再问，到进程重启（状态里的 unpublished）。
3. 成交，然后报价：每个合约从 following 给的月份起，只导已收盘的整月，最早的先导。成交先在锁外把这个月的日归档连同前一天（eve）流式下进缓存，有一天没出就等，收盘满 GIVE_UP_DAYS（40 天）还没出、或它之后已收盘的一个月全部出齐，就跳过这个月，它成为洞；同月要导的合约放在一次调用里，一组被拒就重新列文件、已写好的算导完、其余逐个再导。SEQUENCE_GAP 断档那天在这个月里：先清掉这个月（连同 eve）的缓存重导一次，还被拒就跳过这个月接着导下一个；断档在 eve 那天就停下。报价一个合约一次调用，等成交持有这个月才导；成交已越过这个月（持有更晚的月份而没有这个月）就跳过它。
4. 每个 UTC 月的第一轮：成交对 holes 里的每个月，日归档在本地缓存里没有或 Binance 已换了校验和（每天一个小请求），先在锁外把这个月（连同 eve）按导入的规则读一遍，断档还在就不拿锁；否则整月导入一次。报价的空月等成交持有这个月再导。被拒保持原样，下个月再试。

第 3、4 步在两次导入之间的失败（列文件、下载或校验和请求）记为这种数据各合约的 retry，下一轮再试；属于 all 的拒绝停下全部。

拒绝按 sort 分类。最后重新列出目录给出每一项的状态：caught_up、waiting、lagging（还缺的最早那天或月份收盘已超过 LAG_DAYS）、stopped（附拒绝）或 unknown；K 线另给 through；持仓量与多空比另给 missing_from、missing_days 和 unpublished；报价与成交另给 next_month、skipped 和 filled。有项 waiting 或目录读不了时 next_round 是一小时后，否则是下一天 00:30 UTC。

[源码](https://github.com/qOeOp/trade/blob/main/market/follow.py#L476)

**返回**　(minute_table, gap_intervals, source_rows)：minute_table 为按 open_time 排序、无重复、落在 [start_ms, end_ms) 内的 1 分钟 K 线表（列 open_time, open, high, low, close, volume, close_time，字段为交易所原始十进制字符串，无来源列）；gap_intervals 为三来源都没有的左闭右开区间 [(from_ms, to_ms)]；source_rows 为 \{monthly, daily, rest\} 各来源采用行数，只进导入报告

**期望行为**

1. 列出窗口覆盖的月份，经 market.monthly_archives 取已发布月归档作主来源；没有月归档的月份（当月或缺失月）改为按天经 market.fetch_archive 取日归档
2. 裁到窗口之前先核形状：归档行落在其所属月或日之外、或不在分钟网格上（如微秒时间戳），即 SOURCE_SHAPE，不静默丢弃。
3. 合并各来源：裁到窗口、按 open_time 排序；同一 open_time 出现多行时逐字段比较，任一字段不等即 SOURCE_CONFLICT 并指明时刻，相等则只留一行；close_time ≠ open_time + 1 分钟 − 1 毫秒的行即 SOURCE_SHAPE
4. 用 market.missing_intervals 在 [low, high) 上求缺口：low 取 start_ms（resumed）或首个持有分钟，high 取 end_ms（trading）或末个持有分钟 + 1 分钟
5. 对缺口覆盖的日期，以及持有分钟之外缺口不计的月份边缘（resumed 为 false 时首个持有分钟之前、trading 为 false 时末个持有分钟之后），补取日归档并重新合并；边缘与仍缺的区间逐段经 market.rest_klines 从公开接口补取；完全没有归档且 trading 或 resumed 时整窗口经公开接口取；market.rest_klines 的 SOURCE_UNKNOWN_SYMBOL 在 trading 为 false（已下架）时视为无补充、返回空，trading 为 true 时原样上抛
6. 最终再合并一次并重算缺口，原样返回：不插值、不前值填充、不以标记价代替成交价；表中不记录来源，拼接对运行器与策略不可见
7. start_ms ≥ end_ms 返回空表与空缺口，不拒绝
8. 多来源同一分钟按存储刻度的数值比较；标记价 K 线带成交量即 SOURCE_SHAPE；公开接口只有错误码 -1121 视为未知合约。

| 拒绝码 | 条件 |
|---|---|
| `SOURCE_CONFLICT` | 同一 open_time 被两个来源持有且任一字段不等；不以任一来源覆盖另一来源 |
| `SOURCE_SHAPE` | 某行不是已收盘的整分钟 K 线（close_time 不等于 open_time + 1 分钟 − 1 毫秒），或 symbol 含非法字符；或归档目录列举里有条目没有键、某页标为未完却无从续读（来自归档列举，原样上抛） |
| `PRICE_TYPE_UNKNOWN` | price_type 不是 LAST 或 MARK |
| `SOURCE_UNKNOWN_SYMBOL` | trading 为 true 而公开接口不识别该合约（来自 market.rest_klines，原样上抛） |
| `CHECKSUM_MISMATCH` | 某归档校验和不符（来自 market.fetch_archive，原样上抛） |
| `SOURCE_UNREACHABLE` | 归档或公开接口重试耗尽仍不可达（来自来源函数，原样上抛） |

### `fetch_archive` [#def-market-fetch_archive]

下载一个月、日或 aggTrades 归档并按交易所随文件发布的 SHA-256 校验和核对，不符不落盘；是所有归档共用的取数原语

```python
def fetch_archive(cache_root: Path, key: str) -> Path
```

[源码](https://github.com/qOeOp/trade/blob/main/market/sources.py#L169)

<TypeTable type={{ "cache_root": { type: "Path", description: "本地归档缓存根目录（工作副本目录），归档按交易所原始键名存放" }, "key": { type: "str", description: "交易所归档键，形如 <market>/monthly|daily/<kind>/<symbol>/[<interval>/]<symbol>-<interval|kind>-<period>.zip；kind ∈ klines | markPriceKlines | fundingRate" } }} />

**返回**　Path：已通过校验和核对的本地归档文件路径（旁有同名 .CHECKSUM）

**期望行为**

1. 本地缓存中存在归档与 .CHECKSUM 且重算 SHA-256 相符时直接返回，不再联网（幂等）；不符则视为损坏，重新下载
2. 先取交易所发布的 \<key>.CHECKSUM（不是 64 位十六进制即拒绝 CHECKSUM_MISMATCH），再把归档本体分块流式写到 .part；两者任一返回 404 即拒绝 ARCHIVE_NOT_PUBLISHED（归档尚未发布或该序列不存在，由调用方改用日归档或公开接口）
3. 对 .part 重算 SHA-256，与 .CHECKSUM 首个字段比较（不分大小写）；不等即拒绝 CHECKSUM_MISMATCH，删掉 .part，缓存里不留任何字节
4. 相符后原子改名为正式文件，.CHECKSUM 与归档一起落盘，不留半成品
5. 网络错误、5xx 或限频在有限重试（指数退避）后仍失败即拒绝 SOURCE_UNREACHABLE；不静默返回空

| 拒绝码 | 条件 |
|---|---|
| `CHECKSUM_MISMATCH` | 下载内容的 SHA-256 与交易所随文件发布的 .CHECKSUM 不等 |
| `ARCHIVE_NOT_PUBLISHED` | 归档或其 .CHECKSUM 在交易所公开地址上不存在（HTTP 404） |
| `SOURCE_UNREACHABLE` | 重试耗尽后仍无法从交易所取到归档或校验和 |

2. 按交易所单页上限分页：从 start_ms 起请求，游标推进到上页末行开盘时刻加 1，直到页空或越过 end_ms；请求间按公开接口权重限速
3. 丢弃 open_time ≥ end_ms 的行与 close_time 仍在未来的未收盘行；校验每行字段数与开盘时刻在网格上，否则拒绝 SOURCE_SHAPE
4. 接口返回 HTTP 400 且错误码为 -1121 即拒绝 SOURCE_UNKNOWN_SYMBOL（合约已从交易所移除，公开接口不再识别），其余 400 拒绝 SOURCE_SHAPE；错误体不是 JSON 时，拒绝消息带解码后的文字；是否视为无补充由 market.stitch_series 决定
5. 网络错误、5xx 或限频重试耗尽即拒绝 SOURCE_UNREACHABLE；不返回部分页冒充完整

| 拒绝码 | 条件 |
|---|---|
| `SOURCE_SHAPE` | 参数不合法，或返回行字段数不对、开盘时刻不在网格上，或接口以其他错误码返回 HTTP 400 |
| `SOURCE_UNKNOWN_SYMBOL` | 公开接口不识别该合约代码（HTTP 400，错误码 -1121） |
| `SOURCE_UNREACHABLE` | 重试耗尽后公开接口仍不可达或持续限频 |

**返回**　ImportResult：\{month, universe_rule, scope, through, instruments_appended, bar_rows, funding_rows, universe_members, gaps: \{symbol: \{LAST: [(from_ms, to_ms)], MARK: [...]\}\}, source_rows: \{monthly, daily, rest\}, excluded, inferred_terms, rounded_volumes, derived_findings, per_symbol, universe_filled, market_commit, seconds\}；当月同一天重跑不写文件，追加计数为 0

**期望行为**

1. 经 market.open_market 以 import 角色打开市场目录并持导入锁（lock）。该月已导到月末即 MONTH_EXISTS
2. 取条款：market.rest_exchange_info 的原文连同该月归档里出现的合约交给 market.classify_contract 得到合格合约与逐合约排除原因；条款与 instrument 最新一行不同者按观测时刻追加（exchange_info），已移除、无原文的合约按成交推断步长追加（inferred）；条款状态为交易中的合约以 trading=true 拼接
3. 拼数据：对每个合格合约、每个价格类型调用 market.stitch_series；资金费由 market.monthly_archives 与 market.rest_funding 按实际结算时刻同法拼接，同一结算时刻两来源不等即 SOURCE_CONFLICT；来源函数与拼接的任何拒绝指明合约、价格类型与时刻并拒绝整次导入；缺失区间记入返回值
4. 算范围：只算本次导入的月份。K 线只追加，每月的回看都在它之前，已存月份的名单不会再变，所以不重扫全部历史；本月的交易日由 1 分钟成交 K 线（volume > 0）判出，回看窗口固定为上市天数所需的范围。这个月已有名单时（再次导入当月），算出的名单须等于已存行，否则 UNIVERSE_CHANGED。
5. 写入：一张表只在这次导入有新行时经 market.write_file 写这个月的整个文件：bar 是重新拼出的合约的行加其余合约已存的行（LAST 与 MARK 同一文件），funding 是 K 线已持有的日子里已存的结算加新的（崩溃的导入留在 K 线最后一天之后的行丢掉，重跑时再取），instrument 是已存的观测加新的（条款没变不写；observed_at 是导入时的观测时刻），universe_month 是这个月的名单（已有不写）。data_tests 任一检查未通过即 DATA_TESTS_FAILED，什么都不放到位。最后由 market.place 按 universe_month、funding、instrument、bar 的顺序放到位：bar 最后，最新的截至日由它推出，中途崩溃只会少推进，下一次导入重写这个月。
6. 任何拒绝都发生在 place 之前，目录里的文件不变；没放到位的临时文件在锁释放时删除，被杀的导入留下的由下一次取锁删除。
7. 再次导入未完整的当月时，整月重新拼接：文件已持有的日子（[月初, 这个月第一个未持有日)）逐字段（K 线按存储整数、资金费逐次结算）与来源重读结果比较，任一不同即 MONTH_EXISTS，不让先前从公开接口补的值悄悄留下；来源现在在已持有的日子里多出的行也算不同（上次导入时没出的分钟不能再补进已持有的日子）。之后的日子是新行。比较不把已存的一个月读进内存：主进程按合约和价格类型逐行组流式算出已存行的行数与 SHA-256，各工作进程拿重读结果去比，不同时才读已存行，指出不同的分钟。
8. 资金费跨来源去重：结算时刻归到最近的整点，同一整点里两个来源的费率须相同（保留先到来源的时刻）；同一来源在一个整点里有两次结算即 SOURCE_SHAPE。
9. 整个导入持有导入锁（市场目录上 `lock` 文件的 fcntl 锁），第二个并发导入拒绝 CONCURRENT_IMPORT；fcntl 锁只在共用一个内核的进程间互斥，所有写者因此都在 compose 项目的容器里跑（见 lock），place 改名前再核对目标文件没变（同一拒绝码）。
10. 每行在 market.write_file 里按表的行规则检查（CHECK_FAILED）。
11. 月份只在两端延伸：补完最新月份、导入它的下一个月，或补录最早月份的前一个月；其他月份即 MONTH_INVALID。首个导入月没有名单（缺上市天数的回看）。补录只写新月份的文件和名单，已存月份的行都不变：补录月份里不得已有任何合约的 K 线行（否则 MONTH_EXISTS），已有的资金费行须和这次算出的相同（崩溃的补录在 K 线到位之前留下的，否则 MONTH_EXISTS）；它成为新的首月，没有名单；回看因此补齐的已存月份（此前因缺历史而没有名单）此时算出并写入名单，已有名单时须相同，否则 UNIVERSE_CHANGED。逐月倒着补完的市场，与从该月向后导入的市场逐行相同，只差条款的观测时刻。当月第一天还没有已收盘的 UTC 日：上一个月已导到月末时，导入只写这个月的名单（和观测到的条款），不写 K 线和资金费；名单只取决于上个月最后一天及以前的数据。market follow 在这一天做这种导入。空目录的首次导入没有名单可写，仍是 MONTH_INVALID。
12. 可给合约清单（--symbols）：只拼这些合约、只观测它们的条款，名单因此只在清单内计算；清单为空、重复或格式不对即 IMPORT_SCOPE。部署把 K 线名单写在配置里（market follow 的 --bar-symbols）。

| 拒绝码 | 条件 |
|---|---|
| `MONTH_INVALID` | 不是最新月份、它的下一个月或最早月份的前一个月；月份尚未开始；空目录首次导入的月份还没有已收盘日 |
| `MONTH_EXISTS` | 该月已导到月末；或本次数据在文件已持有的日子里有不同的行；或补录月份里已有 K 线行，或资金费行和这次算出的不同（相同的是崩溃的补录留下的，接着导） |
| `CHECKSUM_MISMATCH` | 某归档文件与交易所随文件发布的 SHA-256 不符（由 market.fetch_archive 触发） |
| `SOURCE_CONFLICT` | 同一分钟或同一资金费结算时刻被两个来源同时持有且字段不等 |
| `SOURCE_SHAPE` | 来源给出非整分钟对齐的 K 线或无法解析的行，或归档目录列举里有条目没有键、某页标为未完却无从续读（由 market.stitch_series 或来源函数触发） |
| `SOURCE_UNREACHABLE` | 交易所归档或公开接口重试耗尽仍不可达（来自来源函数或 market.stitch_series） |
| `SOURCE_UNKNOWN_SYMBOL` | 合约仍在交易而公开接口不识别（来自来源函数或 market.stitch_series） |
| `PRICE_TYPE_UNKNOWN` | 传给拼接的价格类型不是 LAST 或 MARK（来自 market.stitch_series） |
| `UNIVERSE_CHANGED` | 算出的这个月名单与 universe_month 已存行不一致（再次导入、补录要补名单的月份） |
| `CHECK_FAILED` | 某行违反表的行规则（由 market.write_file 触发） |
| `DATA_TESTS_FAILED` | 放到位前 market.data_tests 任一检查未通过 |
| `CONCURRENT_IMPORT` | 另一个导入正持有市场目录的导入锁，或要放到位的文件在这期间变了 |
| `IMPORT_SCOPE` | 合约清单为空、重复或格式不对 |

3. 逐个合约（一个合约日的推算整天放在内存里）：从 agg_trade 文件逐日读行，逐日 <Ref id="market.derive" /> 后分批交 <Ref id="market.write_file" />，写成该合约该月的一个 <Ref id="table:quote" /> 文件；不整月积攒报价。
4. 一个合约整月写完由 <Ref id="market.place" /> 放到位，文件不再写。一个合约被拒不影响其他合约，抛出的是第一个被拒合约的拒绝，消息里列出已写的合约。
5. 返回的计数相加；两种 trade_gap 读数取各日最大值，因此汇总 p99 是最大日 p99，不能写成整月合并分位数。规则已定不等于所有合约已适用，见 <Ref id="W.1.2.1" />。

| 拒绝码 | 条件 |
|---|---|
| `MONTH_INVALID` | 月首参数不合法，或这个月还没结束 |
| `IMPORT_SCOPE` | `symbols` 为空、重复或格式不对 |
| `MARKET_EMPTY / TERMS_UNKNOWN / UNIVERSE_UNKNOWN` | 缺基础数据、合约条款或所需月份成员 |
| `TRADES_NOT_HELD` | 这个合约没有这个月的 agg_trade 文件 |
| `MONTH_EXISTS` | 目标合约这个月已有报价 |
| `SEQUENCE_GAP / SOURCE_SHAPE / SCALE_LOSS` | 推算失败 |

下载校验、导入锁与行规则的拒绝（CHECKSUM_MISMATCH、CONCURRENT_IMPORT、CHECK_FAILED）由下层原样上抛。

ZIP 原件只在下载缓存里，不进数据文件。

1. 给了 commit 时，读到的终点不晚于 commit_end(table, commit)（<Ref id="table:market_directory" /> 的「截至 D」）；commit 不是市场提交即 UNKNOWN_REF。
2. 经 entries 挑出 table 的文件里与请求区间相交、symbol 在 symbols 里的（导入已写未放到位的也算）；一张表没有文件时不产出任何行，不拒绝，导出据此跳过没有的表。
3. 按表的时间列与 symbols 过滤行，跳过时间列统计值落在请求区间之外、或 symbol 统计值的范围不含所请求合约的行组。每个文件只装一个合约、表的主键又以（合约, 时间列）开头时，文件按（合约, 区间起点）依次产出，即主键顺序；否则（有装几个合约的文件）把过滤后的行合在一起按主键排序后产出，所以调用方按合约或时间收窄读取。
4. 只读；文件内存映射，页归页缓存，文件之后被替换也不影响这次读取。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_REF` | commit 不是市场提交 |

### `write_file` [#def-market-write_file]

逐批核对行规则与主键后把一个文件写在它的位置旁边，这次导入此后把它当那个文件读

```python
def write_file(
    market: Market,
    table: str,
    month: date | None,
    symbol: str | None,
    batches: Iterable[pa.RecordBatch],
) -> Written
```

<TypeTable type={{ "market": { type: "Market", description: "以 import 角色打开、持有导入锁的市场目录" }, "table": { type: "str", description: "表名，须在代码的 TABLES 里" }, "month": { type: "date | None", description: "文件的月份；instrument 一个文件，为 None" }, "symbol": { type: "str | None", description: "一个合约一个文件的表（agg_trade、quote、metrics）的合约名；其余为 None" }, "batches": { type: "Iterable[RecordBatch]", description: "这个文件的全部行，按主键顺序逐批给出；内存里只留一个行组" } }} />

**返回**　Written：文件的相对路径、临时文件、目标写之前的 (inode, 修改时间)，交 market.place

**期望行为**

1. 调用方持有导入锁（lock）。
2. 逐批核对：列名与类型与表定义一致，非空列没有空值，每行满足该表的行规则（如报价 bid > 0 且 ask > bid）；每行的时间列落在文件的月份里；symbol 不为空时每行都是这个合约；主键跨批严格递增。不满足即 CHECK_FAILED，指明表与行。
3. 写进目标旁边的临时文件 `.<随机>.tmp`（zstd 3 级，每 ROW_GROUP 行一个行组，写入参数固定在代码里：同样的行不论调用方怎样分批，都写出同样的字节），关闭后 fsync；macOS 上 fsync 用 fcntl `F_FULLFSYNC`（只调 os.fsync 不写到盘上）。
4. 不碰目标：记进 market.pending，这次导入此后读这个路径读的是它。目标的 (inode, 修改时间) 取导入第一次读这个文件时的值，没读过时取现在的。

| 拒绝码 | 条件 |
|---|---|
| `CHECK_FAILED` | 列与表定义不同、某行违反该表的行规则或落在文件之外，或主键不严格递增 |

def place(market: Market, written: Iterable[Written]) -> None

<TypeTable type={{ "market": { type: "Market", description: "持有导入锁的市场目录" }, "written": { type: "Iterable[Written]", description: "market.write_file 写好的文件，按要放到位的顺序" } }} />

### 实现入口

下列实现与上方主要接口同属该模块；链接定位当前源码，签名保留实际参数和默认值。

#### `Market` [#impl-market-files-py-Market]

```python
class Market
```

One opened market directory as one role: its root, whether this process holds the import lock, the files written and not yet placed (which the import reads as those files) and the (inode, mtime) of each file read under the lock. `empty` is no bar file yet.

#### `DataFile` [#impl-market-files-py-DataFile]

```python
class DataFile
```

One file of a table: its path under the market directory, table, contract (None when it holds several) and the [start_ms, end_ms) its rows lie in: its month; instrument's file spans all time.

#### `Written` [#impl-market-files-py-Written]

```python
class Written
```

A file written beside its place by write_file, and its place's (inode, mtime) when the import read it.

#### `LEGACY` [#impl-market-files-py-LEGACY]

```python
LEGACY: dict[str, date]
```

The eight market commits the ledger cites from before commits were days, each read as the last day of data it held (the mapping is in <Ref id="table:market_directory" />). An export at one is not promised to equal the one made then: the data before that day may have been completed since.

#### `TABLES` [#impl-market-files-py-TABLES]

```python
TABLES: dict[str, Table]
```

The tables this code reads and writes: instrument, bar, funding, universe_month, quote, agg_trade and metrics, each with its Arrow schema (columns, integers at series.PRICE_SCALE and VOLUME_SCALE), primary key, time column and layout (one file a month, one a contract and month, or one file). A table with no file reads as empty.

#### `lock` [#impl-market-files-py-lock]

```python
@contextmanager
def lock(market: Market) -> Iterator[None]
```

A context manager holding the fcntl (flock) lock on `<root>/lock` for the whole import: one import at a time; a second import refuses CONCURRENT_IMPORT. Only the import role takes it (ROLE_UNKNOWN); write_file and place need it. On taking it, the `.*.tmp` files a killed import left are removed; what this import leaves unplaced is removed at its end. fcntl excludes only processes sharing one kernel: every writer runs in a container of the compose project whose volume holds the market directory, and place checks its targets for a writer outside it.

#### `entries` [#impl-market-files-py-entries]

```python
def entries(market: Market, table: str, symbols: list[str] | None=None, start_ms: int | None=None, end_ms: int | None=None) -> list[DataFile]
```

The files of `table` that may hold rows of the request, those the import has not placed yet included, in start order (a table's files of one contract are disjoint in time, so for one contract this is time order); readers that need only the first or last rows (coverage bounds, freshness) open just those files.

#### `scan` [#impl-market-files-py-scan]

def scan(market: Market, commit: str | None, table: str, symbols: list[str] | None=None, start_ms: int | None=None, end_ms: int | None=None) -> Iterator[pa.RecordBatch]

The rows read_table gives, file by file in start order and unsorted across contracts, so a caller that needs no key order (a count, a set of days, a digest per contract) holds one row group at a time; the imports read stored bars and funding through it.
