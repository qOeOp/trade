### `execute` [#def-replay-execute]

同一运行环境内先运行器后独立审计器：报表齐全才启动审计器；各阶段命令、状态与退出码分文件落盘；无论结局都封存执行捕获

```python
def execute(
    ledger: db.LedgerProfile,
    trial_id: int,
    identity: Mapping,
    mounts: list[tuple[Path, str, bool]],
    workdir: Path,
    runner_args: list[str],
    conn: db.LedgerConnection | None,
    purpose: str,
    timeout: float | None=None,
) -> tuple
```

<TypeTable type={{ "ledger": { type: "dict", description: "账本连接配置（封存用）" }, "trial_id": { type: "int", description: "子进程启动前已写下的试验编号" }, "identity": { type: "dict", description: "运行环境身份：image_ref（含摘要）、平台、运行契约" }, "mounts": { type: "list[tuple[Path, str, bool]]", description: "挂载声明（宿主路径、容器路径、是否可写）：只读输入与运行器唯一可写的报告目录" }, "workdir": { type: "Path", description: "回放工作目录：source/、reports/、audit/ 与覆盖回执 input-coverage.json" }, "runner_args": { type: "list[str]", description: "容器内运行器参数" }, "conn": { type: "connection | None", description: "账本写连接；封存时与写试验行同一会话" }, "purpose": { type: "str", description: "试验用途 explore | precheck | research | validation，写入封存包" }, "timeout": { type: "float | None", description: "秒数上限；超过即停止运行中的容器并封存为中断（ReplayTimeout）" } }} />

**返回**　tuple(native_exit: int, audit_exit: int | None)；audit_exit 为空表示审计器未运行

**期望行为**

1. 按运行契约取布局常量（runtime.layout），生成运行器容器命令（runtime.container_command），写 process.json 记录阶段 native=started。
2. 运行器 stdout/stderr 分别写 native.stdout.txt、native.stderr.txt；进程无法启动记退出码 127 并把错误写入 stderr 文件；更新阶段为 exited 与退出码。每个阶段的 stdout、stderr 文件超过 768 KiB 加 256 KiB 时，只留开头 768 KiB 与结尾 256 KiB 以内的整行，中间换成一行，写明省去的字节数和行数：引擎对每次被吞下的回调异常都记一行，而 runtime_failures.jsonl 已按类计数。
3. 仅当全部必需报表文件齐全时生成审计器命令并运行：同一镜像摘要，reports/ 与覆盖回执只读挂载，唯一可写挂载为 audit/，输出 audit/audit.json，不挂载 source/；stdout/stderr 同样分文件落盘。报表不全则审计阶段留空，不运行。
4. 无论正常返回、中断或宿主异常，finally 调用 ledger.seal_capture 把阶段记录、stdout/stderr、结构化异常回执与审计结果按试验封存（源码与覆盖回执只记哈希），结局标 completed / interrupted / host_failed。
5. 中断或宿主失败时原异常继续向上抛出，工作目录保留。
6. 本函数不拒绝：报表不全、进程无法启动、中断或宿主失败都如实记入阶段记录并封存，由 ledger.audit_problems 转成无效原因。
7. 挂载：运行器只写 reports/（运行期回调失败写 reports/runtime_failures.jsonl）；审计器只写 audit/，结果为 audit/audit.json，原生报告对它只读；运行器因此写不出审计结果。
8. 入口保留的运行器选项包括输出目录、市场根与提交、成员文件与 --describe；Agent 传入即 RUNNER_OPTION_RESERVED。
9. 指纹阶段：审计之后在同一镜像里单独运行 engine.report_fingerprint，原生报告只读挂入，唯一可写目录为 fingerprint/；其阶段状态随执行封存；预检的指纹原件留在执行捕获；正式运行的指纹留在结果行，捕获只记哈希，入账从工作目录读出并按该哈希核对，调用方给不了。
10. 容器按试验命名；中断或可选超时到期时按名停止容器再封存，结局记 interrupted。

### `explore` [#def-replay-explore]

非登记探索：把未发布的策略文件装入钉死运行环境回放，试验行 purpose=explore，报告留在新建的临时目录，账本只有试验行、开始回执与执行封存

```python
def explore(
    ledger: db.LedgerProfile,
    market: dict,
    at: str | None,
    strategy_file: Path,
    strategy_class: str,
    output: Path,
    runtime: str | None,
    runner_argv: list[str],
) -> dict
```

<TypeTable type={{ "ledger": { type: "dict", description: "研究账本连接配置" }, "market": { type: "dict", description: "市场库连接配置" }, "at": { type: "str | None", description: "市场提交；空表示当前头" }, "strategy_file": { type: "Path", description: "未发布的单文件策略源码" }, "strategy_class": { type: "str", description: "入口类名，须是合法 Python 标识符" }, "output": { type: "Path", description: "输出目录，须是尚不存在的临时目录" }, "runtime": { type: "str | None", description: "运行环境引用；空取 main 标签" }, "runner_argv": { type: "list[str]", description: "运行器窗口与范围参数" } }} />

**返回**　dict \{purpose: explore, status: passed|invalid, problems, path, trial_id, image_ref, market（输入身份）, metrics（未核验目录绩效指标）\}

**期望行为**

1. 经 ledger.temporary_path 核对 output 在临时根之下且不存在（NOT_TEMPORARY_PATH / PATH_EXISTS）；核对 strategy_class 是标识符、runner_argv 不含保留选项；读源码字节算内容哈希。
2. runtime.resolve 解析运行环境身份；registration.market_inputs 导出输入（不要求新鲜，可用缓存导出），registration.input_key 算输入身份；按挂载改写运行器参数后经 runtime.inspect_runtime 探针检视。
3. 建 source/ 与 reports/，写入源码、运行环境检视与覆盖回执（replay.input_coverage），并写 source/execution.json 执行绑定（运行环境身份、探针读出的有效配置及其哈希），与研究封存回放一样以 --execution-binding 交给运行器。
4. 容器启动前经 ledger.open_trial 与 ledger.start_receipt 写 purpose=explore 的试验行与开始回执，记源码哈希、运行环境引用、合约集与窗口。
5. 挂入源码、报告目录与覆盖回执调用 replay.execute，结束后由 ledger.audit_problems 得出问题清单；执行捕获由 replay.execute 交 ledger.seal_capture 封存。
6. 目录保留；绩效指标由 report.directory_report 从未核验的临时报告读出，只供导向不作证据；finally 清理导出目录。

| 拒绝码 | 条件 |
|---|---|
| `NOT_TEMPORARY_PATH` | output 不在平台临时根之下 |
| `PATH_EXISTS` | output 已存在 |
| `ENTRY_CLASS_INVALID` | strategy_class 不是单个 Python 类名 |
| `RUNNER_OPTION_RESERVED` | runner_argv 含入口保留选项（策略文件、策略类、源码哈希、执行绑定、输出目录） |

### `precheck` [#def-replay-precheck]

对已发布候选做事前声明用途的原生预检：核对运行环境与运行契约，在启动容器前写 purpose=precheck 的试验行与开始回执，执行后封存原始技术事实、审计与指纹；完整成功且具备指纹的原生表作为临时缓存，并返回封存包名

```python
def precheck(
    ledger: db.LedgerProfile,
    market: dict,
    at: str,
    candidate: str,
    runtime: str | None,
    runner_argv: list[str],
    output: Path,
) -> dict
```

<TypeTable type={{ "ledger": { type: "dict", description: "研究账本连接配置" }, "market": { type: "dict", description: "市场库连接配置，只读" }, "at": { type: "str", description: "市场提交，须与随后登记用同一提交" }, "candidate": { type: "str (strategy_id@revision)", description: "已发布候选" }, "runtime": { type: "str", description: "运行环境引用，须与随后登记用同一摘要" }, "runner_argv": { type: "list[str]", description: "运行器的窗口与合约参数（覆盖改动的最短窗口、最少合约）" }, "output": { type: "Path", description: "尚不存在的临时目录" } }} />

**返回**　dict \{purpose: 'precheck', trial_id, execution_bundle, source_sha256, image_ref, input_key, config_key, status: passed|failed, problems, path, metrics, scope: '仅工程证据；接口、因果、活动、就绪由独立 Agent 审查'\}。status 为 passed 表示原生与审计退出为零、无回调异常且审计问题清单为空

**期望行为**

1. 核对：经 ledger.read_candidate 读候选；经 ledger.temporary_path 核对 output；runner_argv 不含保留选项；经 runtime.resolve 解析运行环境，构建源码版本为空即拒绝；候选 runtime_contract 等于镜像运行契约。任一不符即拒绝，不启动任何进程。
2. 按 at 以 registration.market_inputs 新鲜导出输入（与登记同一提交；导出器源码可以已改，input_key 只比导出内容与选择），算 registration.input_key；经 runtime.inspect_runtime 在镜像内读出有效配置，算 registration.config_key。
3. 建工作目录 source/、reports/，写入源码原字节、运行环境检视结果与 replay.input_coverage 覆盖回执，并与研究封存回放一样写 source/execution.json 执行绑定、以 --execution-binding 交给运行器，使预检与正式回放走同一条加载路径，执行绑定不符在预检即暴露。
4. 在一个写事务里经 ledger.open_trial 写 purpose=precheck 的试验行（不带登记绑定器），并经 ledger.start_receipt 写开始回执（用途 precheck、源码哈希、运行环境、input_key、config_key）；事务成功后才启动容器。
5. 调用 replay.execute（标预检用途）：先运行器后审计器，结束时（含中断与宿主失败）由 ledger.seal_capture 封存原件；再由 ledger.audit_problems 给出问题清单，report.directory_report 读出工程诊断用绩效指标。
6. 保留 output，清理导出目录，返回结果。预检不消耗网格点；失败或重复的预检都不成为登记尝试。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_CANDIDATE` | 候选在账本中不存在 |
| `NOT_TEMPORARY_PATH` | output 不在临时根之下 |
| `PATH_EXISTS` | output 已存在 |
| `RUNNER_OPTION_RESERVED` | runner_argv 含入口自己写入的选项（策略文件、策略类、源码哈希、执行绑定、输出目录） |
| `RUNTIME_NOT_CI_BUILT` | 运行环境镜像缺构建源码版本标签，不是 CI 构建 |
| `RUNTIME_CONTRACT_MISMATCH` | 候选运行契约与镜像运行契约不一致 |

**期望行为**

1. 核对 hypothesis 与 validation 恰给其一；读账本头提交（table:ledger_head）；runtime.resolve 解析身份，候选运行契约不等于镜像契约即拒绝；runtime.inspect_runtime 取有效配置并由 registration.config_key 算配置身份
2. registration.export_fingerprint 语义模式结果须等于 inputs.identity 的导出内容哈希，否则拒绝；同时记下原始模式指纹
3. 新建临时工作目录，写 source/strategy.py、execution.json（运行环境身份、有效配置及其哈希；与探索、预检、复现同一写法）与 replay.input_coverage 产出的 input-coverage.json

5. replay.execute 挂入源码目录、报告目录与覆盖回执执行；之后汇总无效原因：原始指纹前后不等（exported inputs changed）、原生报表不可读、ledger.summary_problems、ledger.audit_problems，逐条去重互不覆盖

7. 内容原因导致的入账失败（原生报表缺失或不可读、摘要缺键、覆盖身份不符、绩效指标计算出错）都作为失败原因存成 invalid 运行（NATIVE_REPORT_UNREADABLE 等）；只有账本不可用、并发写这类基础设施错误才让试验暂时没有运行。容器启动前就被拒绝时删除工作目录。

| `RUNTIME_CONTRACT_MISMATCH` | 候选运行契约与镜像运行契约不一致 |
| `EXPORT_CHANGED_BEFORE_EXECUTION` | 执行前导出语义指纹不等于输入身份记录的导出内容哈希 |

### `reproduce` [#def-replay-reproduce]

按正式结果或预检的原身份再生 /tmp 报告，核原语义指纹后交出目录；另写一条 purpose=explore 的试验行

```python
def reproduce(
    trial_id: int,
    output: Path,
    *,
    ledger: db.LedgerProfile,
    market: MarketProfile,
) -> dict
```

<TypeTable type={{ "trial_id": { type: "int", description: "已封存的运行" }, "output": { type: "Path", description: "临时根下的新目录" }, "ledger": { type: "LedgerProfile", description: "研究账本档案（关键字参数）" }, "market": { type: "MarketProfile", description: "市场库档案（关键字参数），按运行记下的市场提交导出" } }} />

**返回**　dict：\{directory, trial_id, reproduction_trial_id, fingerprints_match\}

**期望行为**

1. 按原 trial_id 读取正式结果或预检原 capture，取源码、镜像摘要、市场提交、配置、合约集、窗口和原指纹。
2. 按同一市场提交导出输入，从封存有效配置恢复执行环境；报价环境同时恢复原初始／维持保证金率。先核对输入与有效配置一致，不符即拒绝，不启动新试验。
3. 核对通过后开一条 purpose=explore 的试验，写与封存回放相同的 source/execution.json 执行绑定，在钉死的环境里重放并封存执行，不新增正式结果或审查。仅成功且完全等价于本次登记所引用豁免预检的再生获暴露豁免；其他失败或不匹配执行仍可能影响登记。
4. 镜像内计算语义指纹，与原正式结果行或预检 capture 的原指纹比较；两边执行须完整成功且身份一致。无指纹、不等价或执行失败均拒绝 REPRODUCTION_MISMATCH，保留新试验与目录；不覆盖原件。
5. 目录不入账，用完由调用方清理。
6. 正式回放保持单次封存，首次使用某种订单机制不自动调用本入口；首次封存本身不证明已验证可复现。

| 拒绝码 | 条件 |
|---|---|
| `REPRODUCTION_MISMATCH` | 重建输入或有效配置与原身份不符，或重放出的报告指纹／执行事实与原记录不一致；前者在新试验前拒绝，后者保留新试验及目录 |
