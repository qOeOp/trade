# 研究图：research-graph

从研究账本把一条研究线画成图：按试验编号排开的策略版本谱系，以及回放、预测、源码审阅、推荐与资格变化，渲染成本地页面。检验账本能否还原会话的反向测试归 product-doctor（[references/fidelity.md](https://github.com/qOeOp/trade/blob/main/.agents/skills/product-doctor/references/fidelity.md)），复用这里的数据格式与对比工具。

## `SKILL.md` [#def-file-research-graph-SKILL-md]

**触发**　用户要看、要画一条研究线的历史、进展或决策路径。

**职责**

1. 图由产品命令 `research graph` 只从账本读出：只组合产品已有的读取函数、不加自己的规则，同一账本提交永远得到同一张图；图里带该提交上这条路线生效的两个用户目标，从账本读出。
2. 图须通过 `ide.py check`；不为迁就数据放宽格式。
3. 用 `ide.py render` 出页面，交给用户时说明图里显示了什么、缺什么。
4. 要跟着研究看，用户起交易 IDE 服务（`docker compose -f services/ide/docker/compose.yaml up -d`）并打开 `http://127.0.0.1:8765/`（`?line=`、`since=`，或 `at=` 看固定版本）；它读公开的 DoltHub 副本，写入发布后才显示。
5. 新渲染器只读视图模型；新图表是新的 widget 类型；图的新事实是新的格式版本，格式、`research graph`、布局、对比与 product-doctor 的反向测试一起改。

## 工具：services/ide

| 阶段 | 输入 → 输出 | 负责 |
|---|---|---|
| 抽取 | 账本 → graph.json | 一条研究线在账本里的全部记录：版本、本线自己的研究运行（同一窗口与市场提交）、审阅与判断（产品命令 `research graph`） |
| 格式 | graph.json（research-graph@3）→ 问题清单 | 图的形状（schema/graph.schema.json） |
| 布局 | graph.json → view.json（research-graph-view@1） | 画什么、放在哪，以试验编号和行为单位，不含像素；按 widget 分块（summary@1、lineage@2、progress@1、scatter@1、table@1、notes@1、candidate-detail@1、sources@1），每块自带类型、版本与位置 |
| 渲染 | view.json → 文件 | 像素、颜色、文字与交互；web 渲染器输出自包含的单个 HTML 页面，源码一变就重建 |
| 对比 | 两份 graph.json → 差异 | 哪些事实不同，不做归类（供 product-doctor 的反向测试） |

阶段之间只通过这些文件交接，任一阶段可单独替换。渲染器只有一个；另加的渲染器（如经 HTTP 发送 widget 文档的 server，只提供视图、不读写账本）读取同样的 widget。

**服务**　`ide.py serve`（只用标准库，不导入产品包）以子进程调产品命令行：`ledger sql` 读头提交，`research graph --at=<完整哈希>` 取图，再经布局得到视图。页面是 web 渲染器的同一份页面、不嵌视图：它读 `/api/view`（200 视图、202 状态、错误为拒绝 JSON），并订阅 `/api/events`（SSE：连上先发当前状态，15 秒心跳，每页只留最新状态）。只在有不带 `at` 的 live 页面开着时才轮询：每 5 秒先跑一次拉取命令再读头，头变了就为每个开着的 live 页面在新头上取一次图，只取最新的，全局同时只取一张；只开着固定 `at` 的历史页面时不拉取、不读头，图不变。成功的视图只放进程内存（LRU 8，键为库、镜像提交、账本提交、路线、since）。只接受本机 Host、拒绝跨站请求、不发 CORS 头；图接口自己没有写口。配置了 Agent 或 Paper 地址时，`/api/agent/`、`/api/paper/` 下的请求（含 POST、PUT、PATCH、DELETE）经同样的 Host 与跨站检查后原样转发给那两个服务，Paper 的写请求还须同源并带本服务启动时生成的令牌；代理不读写账本。

**镜像**　`services/ide/docker/` 由 CI（`.github/workflows/ide-image.yml`）构建，推到 `ghcr.io/qoeop/trade-ide`（main 打 `main`，PR 打 `pr-N`），内含构建提交的产品与其浅 `.git`、Dolt 2.4.2 与建好的页面。首次启动从 DoltHub 克隆研究账本与市场库到卷 `/data`，起容器内的 sql-server（带产品要求的提交校验组），只给产品 reader 账号，账本档案不标生命周期（kind 为 null），所以从不发布；拉取由容器管理员以 `DOLT_PULL('origin', 'main', '--ff-only')` 执行，公开副本历史被改写时停下并在页面报错，从不重置。
