# E　入口：每次开始或中断后，Agent 如何从账本恢复研究状态、给出综合推荐，并由用户选定研究路线。

入口是研究循环的起点和中断后的回归点。本章定义：从账本 ledger 恢复研究状态 research state 并核对环境就绪；逐条只追加的判断记录与读时的研究状态视图；在全部经济证据可用的候选 candidate 上给出综合推荐 recommendation 与路线选项；把用户的选择写成研究路线 research line 记录。读出、核哈希与路线窗口由代码强制，读的顺序、推荐写法与选定前等待由 skill 强制；不设达标门槛、不排除方向。候选谱系、检验结果、生命周期回执产出与账本机制见 T、V、W、J 章。

## E.1　恢复研究状态 [#E-1]

<Steps>

<Step>

经 <Ref id="cli.ledger_service" /> 读账本服务状态与当前提交；服务未起先启动，不可用即按 <Ref id="E.1.2.3" /> 报阻断。

</Step>

<Step>

经 <Ref id="report.candidates" /> 读候选清单，经 <Ref id="report.research_status" /> 读研究计数；两者只含账本事实，由代码按精确版本读出。

</Step>

<Step>

经 <Ref id="ledger.current_line" /> 读当前研究路线记录；无记录进入路线选择 <Ref id="E.4.1.1" />。

</Step>

<Step>

</Step>

<Step>

</Step>

</Steps>

### E.1.1　时机与从账本读的材料 [#E-1-1]

skill 规定何时恢复与读的顺序，代码保证候选清单与计数只来自账本精确版本，研究状态是代码读时拼合判断与事实的视图。

<Cap id="E.1.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="每次开始或中断恢复先从账本读状态，已选路线直接续做">

- 适用于每次开始研究，以及中断或暂停后恢复；全部读命令走声明的命令行接口 <Ref id="cli.main" />。
- 路线记录存在即表示用户已选路线：Agent 直接续做，不重问，不以推荐代替用户已做的选择。
- 路线记录不存在才进入路线选择 <Ref id="E.4.1.1" />。
- 研究状态 research state 的唯一来源是账本 ledger。
- 会话记忆、交接文件、工作副本中的结论与未入账的运行输出一律视为不存在，不得用于推荐或下一假设；要用须先写入账本（事实以证据包，判断经 <Ref id="ledger.add_judgment" />）再读回。
- 暂停只保留账本中的登记与未消耗的网格点；恢复后续做，不重开登记（<Ref id="A.1.2.1" />）。
- 每条读命令一条连接、JSON 输出、拒绝带码。
- 演练中两次在中断与运行故障后均按此恢复并续做已选路线（<Ref id="eval:research-start/resume-keeps-route" />）。

**输入**　账本当前提交。

**输出**　恢复后的研究状态与当前路线（或进入路线选择）。

**强制**　skill 强制恢复时机、读的顺序与来源规则（<Ref id="research-start/SKILL.md#resume-from-ledger" />）；代码保证读出的清单、计数与研究状态视图只来自账本且不带分数。

</Cap>

<Cap id="E.1.1.2" kind="code" tier="rehearsal" tierLabel="演练证据" title="候选清单与研究计数由代码从账本精确版本读出，不带分数或资格标记">

- <Ref id="report.candidates" /> 列出全部候选 candidate（引用名 strategy_id@revision）及精确源码身份（内容哈希）。
- 每个候选附研发父版本 parent 与改动说明，以及每次登记 registration 的尝试、运行 run 状态与当前经济证据可用性。
- 结果附所读账本提交。
- 给出账本提交或标签时，按精确版本读当时的清单。
- <Ref id="report.research_status" /> 读研究计数：尝试、审计通过、经济可用、仅诊断、无效、未完成。
- 研究计数含样本外 out-of-sample 登记状态（已登记未绑定、已绑定、已封存），由 <Ref id="table:validation_registration" /> 与 <Ref id="table:validation_binding" /> 读出。
- 候选身份与谱系边来自 <Ref id="table:candidate" />；登记与运行事实来自账本证据包 <Ref id="table:evidence_bundle" />。
- 经济证据可用性是读时由 <Ref id="qualification.assess" /> 按检查身份算出的视图，不是存储字段。
- 零成交或缺匹配记录的尝试在清单里只显示不可用的原因。
- 清单与计数不带推荐分数、资格标记、排序或停止标志；推荐由 Agent 作为 recommendation 判断经 <Ref id="ledger.add_judgment" /> 写入（<Ref id="E.3.1.1" />），读时由 <Ref id="report.research_state" /> 与这些事实拼合。

**输入**　账本当前提交，或用户给出的账本提交或标签。

**输出**　该版本下的候选清单与研究计数（JSON），附所读账本提交。

**强制**　代码：命令只从账本按精确版本算出清单与计数，经济证据可用性由 <Ref id="qualification.assess" /> 读时计算。

| 拒绝码 | 条件 |
|---|---|
| 按 <Ref id="cli.main" /> 的拒绝码 | 账本服务不可达或所给提交不存在；不返回部分清单。 |

</Cap>

<Cap id="E.1.1.3" kind="skill" tier="rehearsal" tierLabel="演练证据" title="研究状态由代码读时拼合当前判断与事实，未复盘的试验按提交差异给出">

1. 经 <Ref id="cli.research_state" /> 调用 <Ref id="report.research_state" />，按研究路线（缺省取 <Ref id="ledger.current_line" />）与账本提交或标签（缺省当前头）AS OF 读取。
2. 每种判断取未被取代的最新一条 recommendation、priority 与 review_cadence；interpretation 与 search_exposure 取全部未被取代的。
3. 为每个判断主体附读时事实：候选身份与谱系、试验 purpose 与运行状态、<Ref id="qualification.assess" /> 的当前资格（附检查身份）与绩效指标；facts 附 <Ref id="report.candidates" /> 子集与 <Ref id="report.research_status" /> 的研究计数。
4. unreviewed_trials 由 <Ref id="table:trial" /> 的提交间差异算出：最新 recommendation 的 based_on_commit 与读取提交之间新增、属于本路线市场提交与开发窗口的试验；没有推荐时为本路线全部试验。
5. 按 <Ref id="research-start/SKILL.md#read-research-state" />：unreviewed_trials 非空且到达声明的复盘节奏时先复盘（<Ref id="E.3.1.1" />），否则按 priority 续做。

- 判断是 Agent 逐条追加的记录，分五种：recommendation（推荐一版或一批候选及取舍）；priority（后续动作排序与理由，主体挂研发父版本 parent 与对照 control）；review_cadence（复盘节奏与理由）；interpretation（历史反馈的机制解释、适用条件与重评条件）；search_exposure（算过的视角与读过的报告）。
- 各种判断的记法与主体挂法见 <Ref id="research-round/references/judgments.md#what-to-record" /> 与 <Ref id="E.2.1.1" />；写入经 <Ref id="ledger.add_judgment" />（命令 <Ref id="cli.judgment_add" />），本能力只读。
- 判断正文只引用候选、试验、登记包与账本提交（<Ref id="research-round/references/judgments.md#body-references-only" />）；结果类别、绩效指标、计数与资格都在读时取。
- 视图不存储：任一账本提交都能读出当时的研究状态；上次复盘以来的试验与尝试计数按 based_on_commit 读时算。

**输入**　研究路线证据包（缺省当前路线），账本提交或标签（缺省当前头）。

**输出**　研究状态视图（JSON）：at、line、当前 recommendation、priority、review_cadence、interpretations、search_exposures 及各主体的读时事实，unreviewed_trials，facts\{candidates, counts\}。

**强制**　代码：<Ref id="report.research_state" /> 按精确版本读时拼合判断与事实，并按提交差异给出未复盘的试验；skill 强制据此决定是否先复盘（<Ref id="research-start/SKILL.md#read-research-state" />），由用例 <Ref id="eval:research-start/unreviewed-trials-from-commit-diff" /> 检验。

| 拒绝码 | 条件 |
|---|---|
| `LINE_UNKNOWN` | 研究路线不存在。 |
| `VERSION_UNKNOWN` | 所给账本提交、分支或标签解析不到。 |

</Cap>

### E.1.2　核对环境就绪 [#E-1-2]

代码按精确市场提交原样读出新鲜度与逐合约覆盖事实，skill 据此只报告就绪或阻断而不裁决。

<Cap id="E.1.2.1" kind="code" tier="verified" tierLabel="已验证" title="路线钉住一个市场提交，同一路线内登记与回放共用它">

1. 经 <Ref id="ledger.current_line" /> 读当前研究路线记录，取出钉住的市场提交 market commit、开发窗口 development window 与范围规则 universe_rule。
2. 经 <Ref id="market.freshness" /> 按该提交 AS OF 读交易所数据 exchange data 库的新鲜度。

- 新鲜度包括：成员月份、合约数、最新完整日、最新完整月与当前月覆盖到的时刻。
- 用户给出的引用（具名引用如 main、标签或哈希前缀）一律先经 <Ref id="market.resolve_commit" /> 解析为唯一提交哈希。
- 市场提交在用户选定路线时经 <Ref id="ledger.select_line" /> 写入研究路线记录。
- 同一路线内每次登记与回放都按同一提交导出输入并写入输入身份（<Ref id="J.6.1.3" />）；相同提交上的回放才可比。
- 市场库出现新月份时入口只报告可扩展范围（新月份、覆盖到的时刻），不自动换提交。
- 换提交即开发窗口或数据合同的变化，由用户经 <Ref id="E.4.1.1" /> 选择后写成新一条路线记录。
- 新鲜度来自 <Ref id="table:market_schema" /> 与 <Ref id="table:universe_month" />，只是事实，不判数据够不够用。
- 没有路线记录时返回空并进入路线选择。

**输入**　当前研究路线记录（或用户给出的市场引用）。

**输出**　钉住的市场提交、开发窗口、范围规则与该提交下的新鲜度事实。

**强制**　代码：<Ref id="ledger.current_line" />、<Ref id="market.freshness" /> 与 <Ref id="market.resolve_commit" /> 按唯一提交哈希 AS OF 读市场库与账本。

| 拒绝码 | 条件 |
|---|---|
| `NOT_A_COMMIT` | 给出的引用是工作集引用。 |
| `MARKET_EMPTY` | 该提交下没有任何月份。 |

</Cap>

<Cap id="E.1.2.2" kind="code" tier="rehearsal" tierLabel="演练证据" title="逐合约读覆盖与生命周期回执只返回事实，不删币缩窗补数">

- 经 <Ref id="cli.market_coverage" /> 按钉住的市场提交逐合约读覆盖事实与生命周期回执。
- 合约范围缺省为开发窗口（含预热）涉及月份在 <Ref id="table:universe_month" /> 中的全部成员；显式给出时按给出的清单。
- 命令把范围展开后交 <Ref id="market.diagnose_coverage" />，后者只接受显式清单。
- 每个合约的覆盖事实由 <Ref id="market.coverage_facts" /> 产出。
- 事实包括成员月份、输入区间内成交价与标记价 mark price 的缺口区间和零成交量分钟。
- 还包括两者时刻对齐，以及资金费 funding 结算时刻与条数。
- 首末数据只是数据起止，不等于上市或下架。
- 生命周期回执来自账本中的生命周期证据包：经 <Ref id="registration.load_lifecycle" /> 读出清单与来源原件。
- <Ref id="market.validate_lifecycle" /> 核对清单绑定同一市场提交、事件为引擎原生事件字典、时钟单调、来源原件在包内。
- 上市、禁新仓、下架结算与 ticker 重用以原生事件随证据包留存。
- 缺口、零量、资金费缺失、生命周期缺失都原样列出。
- 入口不据此删币、缩窗、补数或判经济失败。
- 入口不替策略判定指标是否就绪（<Ref id="W.3.3.2" />）。

**输入**　钉住的市场提交、输入区间，以及缺省范围或显式合约清单。

**输出**　逐合约的覆盖事实与已核对的生命周期回执。

**强制**　代码：命令只读事实，任一拒绝整次不返回部分结果；生命周期由 <Ref id="market.validate_lifecycle" /> 核对。

| 拒绝码 | 条件 |
|---|---|
| `INTERVAL_INVALID` | 区间非整分钟，或起点不早于终点。 |
| `EMPTY_SYMBOLS` | 展开后合约清单为空，或显式清单有重复。 |
| `UNKNOWN_REF` | 市场提交引用解析不到。 |
| `AMBIGUOUS_REF` | 市场提交引用解析不唯一。 |
| `NOT_A_COMMIT` | 市场提交引用不是提交。 |
| `UNKNOWN_SYMBOL` | 合约不在该提交。 |
| `LIFECYCLE_INPUT` | 生命周期证据包缺失、提交不符或事件非原生。 |

</Cap>

<Cap id="E.1.2.3" kind="skill" tier="rehearsal" tierLabel="演练证据" title="缺环境或数据时报精确阻断与可运行范围，改范围由用户选">

1. 核对运行环境 runtime image 经 <Ref id="runtime.resolve" /> 能解析为唯一摘要并读出身份。
2. 核对市场库经 <Ref id="market.freshness" /> 在钉住的市场提交下含开发窗口涉及的全部月份。
3. 核对覆盖与生命周期回执经 <Ref id="market.diagnose_coverage" /> 对范围内每个合约读出。
4. 任一项不满足：报告缺什么（镜像摘要、月份、合约、生命周期证据包）、哪一段窗口、哪些合约，以及当前可运行的范围（已就绪的合约与窗口）。
5. 只有改变用户选定的市场范围或开发窗口才能继续时，列出选项（缩范围、换提交、等数据到达）并等用户选。

- 阻断时保留恢复状态：账本中的登记、未消耗网格点与路线记录不动。
- 阻断不否定任何候选的身份、不否定路线的有效性、不记为经济失败、不进入研究计数。
- 运行限制（内存、容量）同样只暂停执行。
- Agent 不自行缩窄范围或窗口；新月份到达同样只报可扩展范围（<Ref id="D.1.1.3" />）。
- 全局规则见 <Ref id="A.3.1.2" />。

**输入**　研究路线记录里的市场提交、开发窗口与范围规则。

**输出**　就绪结论，或精确阻断与可运行范围。

**强制**　skill 强制只报告不裁决与等用户选（<Ref id="research-start/SKILL.md#readiness-and-blockers" />），由用例 <Ref id="eval:research-start/blocked-run-reports-range" />、<Ref id="eval:research-start/window-extension-user-decides" />、<Ref id="eval:research-start/coverage-gap-not-economic-failure" /> 检验。

</Cap>

## E.2　记录研究判断 [#E-2]

<Steps>

<Step>

Agent 按 <Ref id="research-start/SKILL.md#read-research-state" /> 经 <Ref id="cli.research_state" /> 读当前研究路线的研究状态视图（当前判断、读时事实与 unreviewed_trials），同时读本次试验的检验结果。

</Step>

<Step>

写当前决定：recommendation（推荐与取舍）、priority（后续研究动作及所选父版本与对照）、review_cadence（复盘节奏）。

</Step>

<Step>

对本次产生的负面、不显著与仅诊断发现逐条写 interpretation，各带适用条件与重评条件。

</Step>

<Step>

每条把涉及的候选、试验或登记包挂为主体并填 based_on_commit，正文只引用不抄写；算过的视角与读过的报告记为 search_exposure。

</Step>

<Step>

经 <Ref id="cli.judgment_add" /> 调 <Ref id="ledger.add_judgment" /> 逐条追加，代码核对路线、提交、主体与取代关系并拒绝不合规写入。

</Step>

<Step>

<Ref id="eval:research-round/search-exposure-recorded" /> 检验本次搜索暴露是否完整记为判断。

</Step>

</Steps>

### E.2.1　内容 [#E-2-1]

规定推荐、后续动作、复盘节奏与机制解释各记成哪种判断、写什么；资格、检验结果、计数等代码判定都不读判断正文，也不从中产生优先级或推荐分数。

<Cap id="E.2.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="推荐、后续动作与复盘节奏分记三种判断，三者互不推出">

- 当前推荐记为一条 recommendation 判断：推荐的一版或一批候选挂主体 role=recommended（引用名 strategy_id@revision），正文写依据与取舍，按 <Ref id="research-round/SKILL.md#review-and-recommendation" /> 写。
- 后续研究动作记为一条 priority 判断，动作按 <Ref id="research-round/references/feedback.md#priority-ranking" /> 排序。
- 每个动作所选的研发父版本 (parent) 与比较对照 (control) 挂主体 role=parent / control，正文各附理由。
- 对照须经济证据可用（<Ref id="research-round/SKILL.md#recommendation-vs-next-parent" />）。
- 复盘节奏记为一条 review_cadence 判断：按尝试次数或进展声明触发条件与理由（<Ref id="research-round/SKILL.md#review-cadence" />）；上次复盘以来的尝试由 <Ref id="report.research_state" /> 按最新 recommendation 的 based_on_commit 读时给出，不写进判断。
- 每条判断填 based_on_commit（做判断时读的账本提交）；改判断写新一条并以 supersedes 指向旧的（<Ref id="research-round/references/judgments.md#what-to-record" />）。
- 推荐候选不必是下一实验的父版本。
- 优先级最高的动作不必指向推荐候选。
- 复盘次数只触发复盘，不是停止条件。
- 任一判断缺理由或推荐候选没有经济证据可用时，Agent 不写，先补齐；父版本与对照的引用名在 <Ref id="table:candidate" /> 中不存在时由写入口拒绝（<Ref id="E.2.2.1" />）。
- 演练中推荐候选与最新派生版本不同，各写理由。

**输入**　经 <Ref id="report.research_state" /> 读到的全部经济证据可用候选的多维绩效指标（年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释、不确定性，来源见 <Ref id="R.5.1.2" />）、研究计数（<Ref id="research-round/SKILL.md#counts-from-code" />）与 Agent 的诊断。

**输出**　recommendation、priority、review_cadence 三条判断及其主体，经 <Ref id="ledger.add_judgment" /> 写入。

**强制**　由 skill 强制（<Ref id="research-round/references/judgments.md#what-to-record" />）；代码只核主体存在与角色（<Ref id="ledger.add_judgment" />），不读正文、不判理由。

</Cap>

<Cap id="E.2.1.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="历史反馈的机制解释逐条带适用与重评条件，旧负面结论不作硬排除">

- 对每次试验或登记的机制解释记一条 interpretation 判断，主体 role=about 挂该试验 trial_id 或登记包。
- 正文写机制解释与适用条件 (applicability conditions)：源码身份、改动说明、规则参数、输入身份、开发窗口、运行环境 (runtime image) 身份，以所挂候选与试验的引用表达，不抄写。
- 正文写重评条件（何时、凭什么重评）；方向的研究优先级 (research priority) 变化记在 priority 判断。
- 结果类别（负面、不显著、零成交、无效、未完成）不写进判断，由 <Ref id="report.research_state" /> 按 <Ref id="F.1.1.1" />、<Ref id="F.1.1.2" /> 与检验结果读时给出。
- 正文只引用候选、试验、登记包与账本提交，不抄绩效指标数值、研究计数或资格结论（<Ref id="research-round/references/judgments.md#body-references-only" />）。
- 旧的负面结论是当时条件下的历史判断，不是对机制或方向的硬排除（<Ref id="research-round/references/feedback.md#no-exclusion" />）。
- 毛边际为负只更新优先级。
- 低优先级方向保留并写明重评条件；未测方向记为「未知」而非「更差」。
- 不显著、亏损、零成交、低频都不写成排除。
- 缺适用条件或缺重评条件的解释 Agent 不写，先补。
- 演练中亏损或不显著的版本继续派生，零成交尝试只留诊断。

**输入**　经 <Ref id="report.research_state" /> 读到的每次试验 (trial) 的资格与可用性（零成交、无效、未完成只留诊断，见 <Ref id="F.1.1.1" /> 与 <Ref id="F.1.1.2" />）、检验结果（效应、区间、p）与 Agent 的诊断。

**输出**　逐条 interpretation 判断，主体 role=about 指向试验或登记包，经 <Ref id="ledger.add_judgment" /> 写入。

**强制**　由 skill 强制（<Ref id="research-round/references/judgments.md#body-references-only" />），eval <Ref id="eval:research-round/judgment-references-not-copies" />、<Ref id="eval:research-round/conditions-not-exclusion" /> 与 <Ref id="eval:research-round/gross-negative-updates-priority" /> 检验；代码只核主体存在，不读正文，也不拒绝内容。

</Cap>

### E.2.2　存法与读回 [#E-2-2]

判断逐条只追加存入账本，代码核对路线、提交、主体与取代关系，skill 规定每条的引用与搜索暴露，研究状态由读时视图拼出。

<Cap id="E.2.2.1" kind="database" tier="verified" tierLabel="已验证" title="判断逐条只追加存入账本，取代关系与按提交读回由代码保证">

- 每条判断存为 <Ref id="table:judgment" /> 一行：kind（recommendation、priority、review_cadence、interpretation、search_exposure）、line_bundle、based_on_commit、body、supersedes、op_id，created_at 由触发器写服务器时间。
- line_bundle 是所属研究路线的 research-line-* 证据包（<Ref id="table:evidence_bundle" />），当前路线取自 <Ref id="ledger.current_line" />。
- 涉及的候选、试验或登记包逐个存为 <Ref id="table:judgment_subject" /> 一行，带 role（recommended、parent、control、about）。
- 主体三类目标恰有一类非空；recommended、parent、control 只能指向候选（<Ref id="table:candidate" />）；trial_id 指向 <Ref id="table:trial" />，覆盖没有运行行的尝试；登记包须在 <Ref id="table:registration_attempt" /> 中出现过。
- 写入经 <Ref id="ledger.add_judgment" /> 在一个写事务（<Ref id="ledger.write" />）内完成；同 op_id 同载荷幂等返回原行。
- based_on_commit 入库前解析为提交哈希，须是当前头的祖先且不早于路线包所在提交。
- 改判断写新一条并以 supersedes 指向旧的；须同 kind、同路线，每条至多被取代一次。
- 写账号对两表只有 INSERT；dolt_tests 在提交时核对 dolt_diff_judgment 与 dolt_diff_judgment_subject 只出现 added（<Ref id="table:dolt_system_tables" />）。
- 经 <Ref id="ledger.read_as_of" /> 按账本提交哈希或标签读当时的判断；里程碑标签先解析到提交再读回。
- 研究状态不存：<Ref id="report.research_state" /> 按 at 取每种未被取代的最新判断并拼读时事实，未复盘的试验按最新 recommendation 的 based_on_commit 到 at 之间 dolt_diff_trial 的 added 行给出。
- 换市场提交或开发窗口即换研究路线，新判断挂新的 line_bundle；旧路线的判断保留，仍计为历史搜索暴露。
- 演练中按账本提交读回当时的研究状态。

**输入**　一条判断：kind、line_bundle、based_on_commit、body、主体列表、supersedes 与 op_id。

**输出**　judgment_id、账本提交哈希与是否幂等返回原行。

**强制**　由代码与账本强制：add_judgment 在写事务内核对路线、提交、主体与取代关系，表约束与只有 INSERT 的写账号保证只追加，dolt_tests 核对两表差异只有 added。

| 拒绝码 | 条件 |
|---|---|
| `LINE_UNKNOWN` | line_bundle 不存在或不是 research-line-* 包。 |
| `COMMIT_NOT_ANCESTOR` | based_on_commit 不是当前头的祖先。 |
| `COMMIT_BEFORE_LINE` | based_on_commit 早于路线包所在提交。 |
| `SUBJECT_UNKNOWN` | 主体指向的候选、试验或登记包不存在。 |
| `SUBJECT_ROLE_MISMATCH` | role 为 recommended、parent 或 control 而目标不是候选。 |
| `SUPERSEDES_INVALID` | 被取代的判断不同 kind、不同路线或已被取代。 |
| `OP_ID_CONFLICT` | 同 op_id 载荷不同。 |
| write_conflict | 并发写冲突；Agent 重读研究状态后再写。 |

</Cap>

<Cap id="E.2.2.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="每条判断挂可解析的账本对象与提交，搜索暴露记为判断">

- 每条判断经 <Ref id="cli.judgment_add" /> 调 <Ref id="ledger.add_judgment" /> 写入；based_on_commit 填做判断时读的账本提交，只引用账本提交，不引用 Git 提交。
- 支撑该条的对象挂为主体：候选 strategy_id@revision、试验 trial_id（<Ref id="table:trial" />）、登记包（<Ref id="table:registration_attempt" /> 所指）；正文提到的其他对象只写引用名，须在当前账本可解析。
- 正文只写解释与下一假设 (hypothesis)；事实（绩效指标、研究计数、审计与资格结论）不抄进正文，由 <Ref id="report.research_state" /> 按主体从试验与运行行（<Ref id="table:run" />）读时给出。
- 下一假设写在 priority 判断正文，按 <Ref id="research-round/references/feedback.md#next-hypothesis-record" /> 写观察事实（以引用表达）、机制解释、拟改部件、与历史候选的关系。
- 算过的每个视角（绩效指标、切分维度、参数视角）与读过的每份报告各记一条 search_exposure 判断，主体 role=about 指向所涉试验或登记包，带 based_on_commit。
- 每次尝试（含无效、未完成、预检失败）是 <Ref id="table:trial" /> 的一行，试验计数读自代码（<Ref id="R.4.2.1" />），不另记判断。
- search_exposure 补记代码计数之外的视角与报告阅读，供 DSR（<Ref id="nautilus-report-analysis/SKILL.md#deflated-sharpe" />）与样本外验证 (validation) 的多重比较判断使用。
- 不修改旧判断；后来找到的材料（论文、诊断、更正）写为新一条判断：更正以 supersedes 取代旧判断，补充材料另记一条挂同一主体的 interpretation。
- 任一条缺主体或引用不可解析，Agent 不写，先补；主体不存在由写入口拒绝（拒绝码见 <Ref id="E.2.2.1" />）。
- 演练中每条记录引用登记包、运行与账本提交，事实与解释、下一假设分开。

**输入**　本次的判断正文，及其涉及的候选、试验、登记包与做判断时读的账本提交。

**输出**　经 <Ref id="ledger.add_judgment" /> 写入的判断行与主体行，含 search_exposure 判断；返回 judgment_id 与账本提交。

**强制**　由 skill 强制（<Ref id="research-round/references/judgments.md#body-references-only" />），eval <Ref id="eval:research-round/search-exposure-recorded" /> 与 <Ref id="eval:research-round/judgment-references-not-copies" /> 检验；代码只核主体与提交可解析（<Ref id="ledger.add_judgment" />），不读正文。

</Cap>

### E.3.1　候选范围 [#E-3-1]

划定推荐选项从哪来。

<Cap id="E.3.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="入口呈现最新推荐，范围是全部经济证据可用的候选，含历史候选">

1. 经 <Ref id="cli.research_state" /> 读当前路线的研究状态视图 <Ref id="report.research_state" />（读法见 <Ref id="research-start/SKILL.md#read-research-state" />），取未被取代的最新 recommendation 判断呈现；其主体附读时的候选身份、资格与绩效指标。
2. 视图里没有 recommendation，或视图给出的未复盘试验 unreviewed_trials 中出现有效运行 run 时，Agent 现算一次。
3. 现算按复盘判据 <Ref id="research-round/SKILL.md#review-and-recommendation" /> 在全部经济证据可用的候选上多维综合。
4. 结果按 <Ref id="research-round/references/judgments.md#what-to-record" /> 经 <Ref id="cli.judgment_add" />（<Ref id="ledger.add_judgment" />）追加一条 recommendation 判断：推荐候选挂 role=recommended，based_on_commit 填现算时读的账本提交，supersedes 指向上一条推荐；旧判断不改。

- 范围是候选谱系 lineage 中全部经济证据可用的候选：不限最近几版、不限当前研究路线、不限非劣集。
- 历史候选与非劣绩效指标之外的候选都可被选。
- 非劣候选集由 Agent 按年化、回撤、夏普、胜率自算（<Ref id="nautilus-report-analysis/SKILL.md#pareto-range" />），只作范围描述，不是资格、不是排序。
- 仅诊断、无效与未完成的候选分列呈现，不与有效候选同列比较（分列口径见 <Ref id="R.5.1.2" />）。
- 推荐判断正文只写理由与取舍，只引用候选与账本提交，不抄绩效指标、计数或资格（<Ref id="research-round/references/judgments.md#body-references-only" />）；这些由视图读时给出。
- 候选清单、资格读取、视图读取与判断写入的拒绝由各自定义处规定。

**输入**　研究状态视图 <Ref id="report.research_state" />（当前 recommendation 与未复盘试验）；代码读出的候选清单 <Ref id="report.candidates" />（每个候选的源码身份、父版本与改动、每次登记尝试及其运行状态与经济证据可用性，附账本提交），以及每个候选的当前资格 <Ref id="qualification.assess" />（综合审计状态、执行捕获、独立源码审查与原生对账，附检查身份）。

**输出**　呈现给用户的最新推荐与候选范围；现算时追加一条 recommendation 判断。

**强制**　skill 指导，eval <Ref id="eval:research-round/all-comparable-candidates" /> 校验推荐覆盖全部可比候选；代码只保证候选清单不带分数、资格标记或排序，判断写入的核对由 <Ref id="ledger.add_judgment" /> 强制；本能力无代码拒绝码。

</Cap>

<Cap id="E.3.1.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="仅当没有任何候选或用户明确离开全部研究路线时，从策略库模板提根选项">

- 触发只有两种：候选清单 <Ref id="report.candidates" /> 为空（账本里没有任何候选）；或用户明确说离开全部研究路线（换路线由用户选，见 <Ref id="F.3.3.2" />）。
- 亏损、不显著、低优先级、复盘计数、运行限制或运行故障都不触发选新根，只更新研究优先级（<Ref id="research-round/references/feedback.md#no-exclusion" />）。
- 每个模板选项附该模板在当前开发窗口 development window 的首份报告。
- 模板按 <Ref id="research-round/references/template-transcription.md#intake" /> 从一手出处转写。
- 转写后的模板按 <Ref id="research-round/references/hypothesis.md#root-registration" /> 以无父、无对照登记一次并回放。
- 首份报告只有绩效指标，没有比较结果。
- 没有首份报告的模板也列出，但标明未回放。
- 模板之外的人造根由用户自己发起并提供信息源（<Ref id="research-start/SKILL.md#artificial-root" />），Agent 不主动提议。
- 用户选中模板后，它成为无父版本的根候选（<Ref id="research-start/SKILL.md#template-becomes-root" />）。

**输入**　候选清单 <Ref id="report.candidates" />、用户对研究路线的明确表态、策略库模板及其在当前开发窗口的首份报告。

**输出**　根节点 root 选项清单，每项附首份报告或「未回放」标记。

**强制**　skill 指导，eval <Ref id="eval:research-start/no-candidate-offers-templates" /> 校验触发条件；本能力无代码拒绝码。

</Cap>

### E.3.2　选项材料与呈现 [#E-3-2]

规定每个选项附哪些绩效指标、历史反馈与推荐措辞，只定呈现清单，不定判据。

<Cap id="E.3.2.1" kind="skill" tier="verified" tierLabel="已验证" title="每个选项附多维绩效指标与诊断，算不出的项留空写原因，不靠单一指标推荐">

- 绩效指标项：年化、最大回撤、夏普、计划胜率、成本、资金使用率 capital utilisation、利润来源拆分（价格盈亏、手续费、资金费）、机制解释、不确定性。
- 年化、回撤、夏普、胜率、成本与利润来源拆分从运行报告 <Ref id="report.run_report" /> 读出，经资格视图遮蔽（经济口径见 <Ref id="R.1.1.2" />）。
- 每项附总体与样本量、指标计算版本、检查身份和局限清单。
- 不确定性从比较入口 <Ref id="report.compare" /> 读出：配对检验的效应、区间、p 与登记时声明的检验条件。
- 显著性水平、最小改进均标为「未校准示例值」。
- 无对照或任一侧不可比时 <Ref id="report.compare" /> 拒绝并只留诊断，选项里照抄该诊断。
- 资金使用率由 Agent 按 <Ref id="nautilus-report-analysis/SKILL.md#capital-utilisation" /> 从封存敞口表自算（时间加权名义额、采样峰值、锁定保证金、在市时间）；无敞口表不填。
- 每项绩效指标附实质活动 substantive activity 与可比资格 comparability；无资格的候选整体只给诊断。
- 夏普或任何单一指标不单独决定推荐。
- 算不出的项留空并写原因，不估、不补。
- 机制解释写该候选利润来自哪类活动（如趋势持有、资金费收取）及其成立的市场条件；属 Agent 判断，须标为解释。

**输入**　<Ref id="report.run_report" /> 的遮蔽绩效指标、<Ref id="report.compare" /> 的比较结果或诊断、封存敞口表。

**输出**　每个选项的一组多维绩效指标与诊断。

**强制**　代码强制绩效指标遮蔽（<Ref id="report.run_report" />）与比较只给效应、区间、p 而不返回裁决（<Ref id="report.compare" />）；呈现清单由 skill 指导，eval <Ref id="eval:research-round/capital-use-read-from-first-root" /> 校验资金使用率与利润来源从首个有效根起主动读出。

</Cap>

<Cap id="E.3.2.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="历史反馈与研究顺序只从研究状态视图读，按适用条件呈现，不写成排除">

- 内容全部只从研究状态视图 <Ref id="report.research_state" /> 读出（经 <Ref id="cli.research_state" />，读法见 <Ref id="research-start/SKILL.md#read-research-state" />），不从会话记忆或交接文件读。
- 已试方向：机制解释、适用条件与重评条件取自未被取代的 interpretation 判断（写法按 <Ref id="research-round/references/judgments.md#body-references-only" />）；结果（试验与运行状态、资格、绩效指标）取视图的读时事实。
- 负面、不显著、仅诊断的结果逐条带适用条件。
- 旧负面是当时的决定，不是排除。
- 未试方向：视为未知，不写成更好。
- 低优先级方向：附 interpretation 判断里的重评条件，即何时、凭什么重评（<Ref id="research-round/references/feedback.md#no-exclusion" />）。
- 下一批研究动作：取最新 priority 判断的排序与理由（排序依据写法按 <Ref id="research-round/references/feedback.md#priority-ranking" />），写明为何此序；各动作的父版本与对照是该判断的 parent、control 主体。
- 不把亏损、零成交、低频写成方向失败。
- 模板选项没有谱系历史，附该模板在当前开发窗口的首份报告（按 <Ref id="research-round/references/hypothesis.md#root-registration" /> 登记并回放所得，只有绩效指标无比较）。

**输入**　研究状态视图 <Ref id="report.research_state" />：未被取代的 interpretation 与 priority 判断，以及各主体的读时事实。

**输出**　每个选项的已试方向、未试方向、低优先级方向与研究顺序依据；模板选项为首份报告。

**强制**　skill 指导；本能力无代码拒绝码，视图读取的拒绝由 <Ref id="report.research_state" /> 规定。

</Cap>

<Cap id="E.3.2.3" kind="skill" tier="rehearsal" tierLabel="演练证据" title="推荐写明哪一版、依据、取舍及与下一实验父版本的区别">

- 推荐哪一版或哪一批候选，用引用名 strategy_id@revision。
- 依据哪些绩效指标：指向 <Ref id="research-start/SKILL.md#option-metrics" /> 列出的项，不引入新指标。
- 取舍是什么，例如年化高但回撤或资金使用率不利、利润主要来自资金费。
- 推荐候选与下一实验的研发父版本 parent 分别是谁、为何不同（按 <Ref id="research-round/SKILL.md#recommendation-vs-next-parent" />）；父与对照分别给理由，对照须经济证据可用。
- 推荐不等于样本外验证 validation 或上线；认可与上线由用户看报告后判断。
- 推荐随时可做，不等待未来候选研究完，研究继续时即给出。

**输入**　本节各选项的绩效指标、诊断、历史反馈与研究顺序。

**输出**　一段推荐说明，含上述五项内容。

**强制**　skill 指导，eval <Ref id="eval:research-round/recommendation-not-next-parent" /> 校验推荐与父版本分开写；本能力无代码拒绝码。

</Cap>

## E.4　用户选定研究路线 [#E-4]

<Steps>

<Step>

Agent 呈现推荐与路线选项（经济证据可用的候选起点，或符合条件时的策略库模板），以提问结束并等待；选定前不登记、不回放、不发布，由 skill 强制。

</Step>

<Step>

用户选定一条路线；可附信息源或想法，可一次性明确授权选某个模板。

</Step>

<Step>

选中模板时，Agent 经 <Ref id="ledger.publish_candidate" /> 不带父版本、不带改动说明发布它，得到根候选 root。

</Step>

<Step>

Agent 经 <Ref id="cli.line_select" /> 调 <Ref id="ledger.select_line" /> 写研究路线记录（市场提交、universe_rule、开发窗口、起点候选、备注），账本以新版本证据包只追加入账，当前路线即最新版本。

</Step>

<Step>

用户附带的想法作为路线内的一条假设照常登记；模板根在当前窗口无父、无对照登记一次并回放出首份报告。

</Step>

<Step>

Agent 在路线内自主推进，每次登记以路线的窗口与市场提交为准（由登记校验强制）；需要换路线时回到第 1 步，给诊断与选项并等待用户。

</Step>

</Steps>

### E.4.1　选择权 [#E-4-1]

规定谁提选项、谁选、选定前怎么等，以及用户附带的想法、信息源与一次性授权如何进入路线，均由 skill 指导。

<Cap id="E.4.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="Agent 提出路线选项，用户决定选哪条；选定前 Agent 只等待">

- Agent 提出路线选项并附推荐材料（多维绩效指标、历史反馈、取舍）；选项是经济证据可用的候选起点。
- 只有在 <Ref id="research-start/SKILL.md#root-options" /> 规定的条件下（账本没有任何候选，或用户明确离开全部路线），才把策略库模板列为选项。
- 选哪条由用户决定；Agent 不把推荐第一名默认当作已选。
- 用户选定前 Agent 只等待：不登记、不回放、不发布新候选、不写路线记录。
- 账本侧没有可绕过的入口，因写路线记录的命令只在用户选定后由 Agent 调用。
- 路线内需要换路线时按 <Ref id="research-round/SKILL.md#route-change" /> 回入口，给诊断与选项，以提问结束并等待。
- 亏损、不显著、运行限制或故障都不是 Agent 自行开新路线的理由。

**输入**　入口呈现的综合推荐与路线选项。

**输出**　用户的一次明确路线选择。

**强制**　由 skill 强制（<Ref id="research-start/SKILL.md#user-selects-route" />）；eval <Ref id="eval:research-start/route-change-waits-for-user" /> 校验。

</Cap>

<Cap id="E.4.1.2" kind="skill" tier="unverified" tierLabel="待验证" title="用户附带的想法成为路线内一条须登记的假设，明确授权选模板一次即够">

- 想法 idea 成为选定路线内的一条假设 hypothesis，来源归『用户想法』，与报告诊断、来源研究走同一条登记路径（<Ref id="research-round/references/feedback.md#three-sources-of-hypotheses" />）。
- 想法先按 <Ref id="research-round/SKILL.md#sources-first" /> 查来源，再写机制与可反驳预测，登记后才回放。
- 不因来自用户而免登记、免对照，或直接改源码回放。
- 信息源 source（文档、论文、公开策略描述）按 <Ref id="research-round/references/template-transcription.md#user-source-transcription" /> 的核实、重写与文件头规则转写成单文件策略，来源记为『外部依据（用户提供）』。
- 转写出的策略经 <Ref id="ledger.publish_candidate" /> 无父发布为根并在路线内回放一次，即 <Ref id="research-start/SKILL.md#artificial-root" /> 的人造根。
- 用户明确授权选某个模板或人造根一次即够，Agent 随后不再重复请求。
- 授权只覆盖该模板的发布、路线记录与首份报告，不扩展到其他模板、其他路线，也不代替路线内各假设的登记。
- 缺少的证据：演练中未出现用户在入口补充想法或一次性授权选模板的实际过程。

**输入**　用户选路线时附带的想法、信息源或对某模板的明确授权。

**输出**　路线内一条待登记的假设，或一个经发布的人造根候选。

**强制**　由 skill 强制（<Ref id="research-start/SKILL.md#user-input-at-selection" />），eval <Ref id="eval:research-round/user-idea-registered-as-hypothesis" /> 与 <Ref id="eval:research-start/artificial-root-user-initiated" /> 校验。

</Cap>

### E.4.2　选定的结果 [#E-4-2]

选中候选直接写研究路线记录，选中模板先经发布入口成为根候选再写路线记录；记录形态、只追加与幂等由代码和账本强制。

<Cap id="E.4.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="选中的候选成为唯一当前路线的起点，路线内由 Agent 自主派生">

- 用户选中的候选 candidate（strategy_id@revision）成为当前唯一研究路线的起点。
- Agent 经 <Ref id="cli.line_select" /> 调 <Ref id="ledger.select_line" /> 写研究路线记录。
- 记录内容：市场提交 market_commit、范围规则 universe_rule、开发窗口（预热段与交易段，UTC，按 <Ref id="W.2.1.2" />）、起点候选 start_candidate、备注 note。
- 账本把记录作为研究路线证据包的新版本入账（<Ref id="table:evidence_bundle" />）：只追加不覆盖，旧版本保留并可按版本读回。
- 当前路线由最新版本定义，经 <Ref id="ledger.current_line" /> 读出，恢复时据此续做（<Ref id="eval:research-start/resume-keeps-route" />）。
- 换路线即写新版本（新编号），不编辑旧版；一次只推进一条路线。
- 起点候选不存在、市场提交无法解析或窗口形态不合法时，select_line 拒绝写入，拒绝码由 select_line 定义。
- 路线写入后，路线内每次登记必须以本路线的窗口与市场提交为准。
- 路线内由 Agent 自主选研发父版本（谱系中任一完整候选）、比较对照、假设与下一小批及研究优先级。
- 这些决定不逐项请用户批准（<Ref id="research-start/SKILL.md#record-selected-line" />）。

**输入**　用户选中的候选 strategy_id@revision，以及市场提交、universe_rule、开发窗口与备注。

**输出**　账本中研究路线证据包的一个新版本，成为当前路线。

**强制**　记录形态与只追加由账本代码（select_line 与证据包版本）强制；路线内登记一致性由 <Ref id="registration.validate" /> 强制；路线内自主由 skill 指导。

</Cap>

<Cap id="E.4.2.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="选中的模板经同一发布入口成为无父根候选，开启新谱系且保留既有记录">

1. Agent 经与所有候选相同的发布入口 <Ref id="ledger.publish_candidate" /> 发布模板源码，不带研发父版本、不带改动说明。
2. 得到根候选 root，开启新谱系 lineage（<Ref id="table:candidate" /> 中无父的一行）。
3. 相同字节已在账本时发布入口拒绝并返回既存版本，Agent 以该版本为起点，不再造一个。
4. Agent 按 <Ref id="E.4.2.1" /> 写研究路线记录，以该根为起点。
5. Agent 在当前开发窗口按 <Ref id="research-round/references/hypothesis.md#root-registration" /> 无父、无对照登记一次并回放，出首份报告；该次计入试验，没有检验结果。

- 只在账本没有任何候选或用户明确离开全部路线时才把策略库模板列为选项（<Ref id="research-start/SKILL.md#root-options" />），eval <Ref id="eval:research-start/no-candidate-offers-templates" /> 校验。
- 同一流程适用于按 <Ref id="research-start/SKILL.md#artificial-root" /> 由用户发起的人造根。
- 既有谱系、登记与试验记录全部保留，后来的路线仍可把其中任一候选选为父版本或对照。
- 根没有人造／系统之类的特殊标记：根只是无父的候选。

**输入**　用户选中的策略库模板或用户发起的人造根源码。

**输出**　一个无父根候选、以它为起点的研究路线记录，以及一份首份报告。

**强制**　流程由 skill 指导（<Ref id="research-start/SKILL.md#template-becomes-root" />）；无父即根与相同字节拒绝由发布入口 publish_candidate 的代码强制。

</Cap>
