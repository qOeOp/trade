# 1　入口：每次开始研究，或者中断后回来，都从这里进门：读回研究做到哪了，看推荐，选路线。

研究不是一次性的任务，而是一条不停的循环。入口是每次进入这条循环的门：第一次开始时从这里选路线，中途断了（会话结束、机器重启、运行出错）也从这里接着做。

入口做四件事。先从账本读回研究做到哪了；再把每次读完结果后的想法写成判断，存进账本；然后把所有能用的候选汇总成一份推荐，连同几条可选的路线交给你；你选定路线后，Agent 就在路线里自己往下做。

举个例子：全池 RSI 路线做到第六个假设时会话断了。重新开始时，Agent 不靠记忆，而是读账本：路线记录还在，说明你已经选过路线，不用再问；最近一次推荐之后又多了一个有效运行，所以先补一次复盘，再接着提下一个假设。

## 1.1　恢复研究状态 [#E-1]

研究做到哪了，只看账本里记着的，不看会话里记得的。

<Steps>

<Step>

确认账本能用，读出有哪些候选、试验做了多少次。

</Step>

<Step>

看有没有当前路线；没有，就转去让你选路线。

</Step>

<Step>

有路线，就读研究状态，决定先复盘还是直接往下做。

</Step>

<Step>

按路线定下的那份市场数据，核对运行环境和数据齐不齐。

</Step>

<Step>

齐了就继续；不齐就说清缺什么、眼下还能跑什么。

</Step>

</Steps>

### 时机与从账本读的材料 [#E-1-1]

恢复时读什么、从哪读。

#### 每次开始或中断后先读账本，中断恢复直接续做、新会话先问继续还是换线 [#E-1-1-1]

每次开始，或者中断后回来，Agent 第一件事是读账本：服务能不能用、有哪些候选、研究计数、研究状态、当前路线。账本里有路线记录，你定的两个目标就从它的备注里取。中断后回来，或你说继续，Agent 直接接着这条路线做，不再问；新开会话只说了 research-start，它先问一次：继续当前路线（附现状与下一步），还是换线。

例外是研究状态的 gates 里有 RUNTIME_UNSUPPORTED：这条路线的推荐与对照候选停在本产品已不再运行的旧契约上。Agent 直接告诉你这条线只能关闭、在新契约上重开，不提议继续，中断后也不续做，不为它建 Goal（用户 2026-10-25 定：契约升级即关闭旧线）。

会话会结束，记忆会丢，交接文件可能过时。只有入了账本的东西经过核对，可以信。所以没写进账本的结论，哪怕上一次会话里说过，也当作不存在。

<div className="rd-example">

比如上次会话里 Agent 说过「H06 放大预算没用」，但这句话没有作为判断入账。恢复后，它不能拿这句话当依据去选下一个假设：要么重新读结果，要么先把它写成判断入账。

</div>

#### 研究状态在读的时候当场拼出来，不另存一份 [#E-1-1-3]

研究状态不是一份单独保存的文件，而是每次读的时候，从账本里现有的判断、候选和试验当场拼出来的。账本里还没有研究路线时，它也不报错，照样给出候选和计数，并提示下一步记路线。

单独存一份，就有两个地方要保持同步，哪次忘了更新，两边就对不上。当场拼出来，它永远和账本一致。

<div className="rd-example">

研究状态包含三样：当前有效的判断，比如最新的推荐；这些判断涉及的候选眼下的资格和绩效指标；上次推荐之后新增、还没复盘过的试验。想看三天前的研究状态，按三天前的账本版本读就行。

运行环境升了契约、当前路线的推荐与对照候选还在旧契约上时，研究状态当场在 gates 里列出 RUNTIME_UNSUPPORTED 和这些候选，不另存标记。

</div>

#### 路线里每一次研究试验都计入试验次数，失败的也算 [#E-1-1-4]

一条路线里跑过的每一次研究试验都算数，包括审计判无效的和中途中断的。这个数由账本统计，不靠 Agent 自己数。

试验次数用来校正「试得多，总会碰上一个好看的结果」这种运气。只数成功的，就会少算试过的次数，把结果看得比实际更可信。

<div className="rd-example">

比如一条路线登记了 12 次研究试验，其中 2 次因为数据缺口中断、1 次审计判无效。做多重比较校正时仍按 12 次算，不是 9 次。

</div>

### 核对环境就绪 [#E-1-2]

回放之前先确认环境和数据齐不齐；入口只报告事实，不替你决定数据够不够用。

#### 一条路线钉住一份市场数据，路线里的回放都用它 [#E-1-2-1]

你选定路线时，市场数据的版本（市场提交）和开发窗口一起写进路线记录。这条路线里所有回放都用这一份数据。

两次回放只有用同一份数据，比较才公平。数据中途换了，前后结果就分不清是策略变了还是数据变了。

<div className="rd-example">

比如路线的窗口是 2025-10-09 到 2026-10-07。之后 10 月的新数据到了，入口只会告诉你「现在可以把窗口再延长一段」，不会自己换数据。要换，就是开一条新路线，由你来选。

</div>

#### 逐个合约列出数据覆盖，入口不删币、不缩窗、不补数 [#E-1-2-2]

入口按路线的数据版本，逐个合约列出数据缺口、零成交的分钟和资金费记录，以及上市、下架这类变化。

数据有缺口是事实，怎么应对是策略和你的事。入口要是自己删币或缩短窗口，等于悄悄改了研究范围。

<div className="rd-example">

全池 RSI 路线涉及 210 个合约：其中两个在窗口开始前就下架了，还有一个下架后重新上市，分成了两段。入口把这些原样列出来。某个币前几天没数据，只说明数据从那天开始有，不等于它那天才上市。

</div>

#### 缺环境或数据时，报清楚缺什么、哪些还能跑，改范围由你选 [#E-1-2-3]

回放前核对三样：运行环境能找到唯一的镜像；市场库里有开发窗口涉及的全部月份；每个合约的覆盖都能读出来。缺任何一样，Agent 报告具体缺什么、影响哪段窗口和哪些合约，以及眼下还能跑的范围。

缺数据不是策略失败，不该记进研究结果，也不该让 Agent 自己缩小范围凑合着跑。

<div className="rd-example">

比如运行环境的镜像还没构建好，Agent 会说「缺镜像，所有回放暂停；已有的登记和没跑的网格点都保留」，然后等着。如果只有缩小合约范围才能继续，它列出几个选项让你挑，而不是自己挑。

</div>

## 1.2　记录研究判断 [#E-2]

Agent 每次读完结果的想法，都写成一条判断存进账本，下次恢复时才能接着用。

<Steps>

<Step>

读研究状态和这次试验的检验结果。

</Step>

<Step>

写下当前的决定：推荐哪一版、下一步先做什么、多久复盘一次。

</Step>

<Step>

对亏损、不显著和只能诊断的结果，逐条写解释。

</Step>

<Step>

每条判断挂到它说的候选、试验或登记上；正文只引用，不抄数字。

</Step>

<Step>

逐条追加进账本；不合规的写入会被拒绝。

</Step>

</Steps>

### 内容 [#E-2-1]

判断分几种，各写什么。代码只管存，不读判断的正文。

#### 推荐和下一步做什么分开写成两种判断，复盘时机由产品定 [#E-2-1-1]

推荐哪一版、下一步做什么并按什么顺序做，是两种判断，分开写，谁也推不出谁，复盘时各写一条。什么时候复盘不是判断：上次推荐以来满 5 个研究试验，产品就拒绝下一次登记，Agent 不写、也改不了这个停点。

推荐的版本不一定是下一个实验的起点。推荐的可能是眼下收益最好的一版，而最值得改进的可能是另一版。写在一起，就容易把「推荐它」误当成「接下来就改它」。

<div className="rd-example">

全池 RSI 路线里，第三个假设是从 H02 改出来的，而当时收益最好、被推荐的是 H01；最后推荐的是 H09，不是最新的 H10。

</div>

<div className="rd-foot"><span className="rd-guard">skill</span> <span className="rd-impl"><Ref id="rule:E.2.1.1">research-round · references/review.md</Ref></span> <span className="rd-tier rd-tier-rehearsal">演练证据</span></div>

#### 每条解释写明在什么条件下成立、什么时候重新评估 [#E-2-1-2]

每次登记新假设之前，Agent 至少给上一次结果写一条解释：结论是在什么条件下得出的，什么情况下应该重新评估。被另一个登记以 retry_of 重试的无效运行不用写解释，只记修复。

一次亏损只说明在那次的数据、参数和环境下不行，不代表这个方向永远不行。不写条件，旧结论就容易变成谁也不敢再碰的禁区。

<div className="rd-example">

全池 RSI 路线里，H06 把单笔预算从 100 提到 500，结果比 H05 差。解释写成：「在这个窗口和这组 RSI 参数下，单纯放大预算没有改善，可能受到成交量上限的限制；改了容量规则后重新评估。」后来的 H07 和 H09 照样在仓位这个方向上继续做。

</div>

### 存法与读回 [#E-2-2]

判断怎么存、怎么改、怎么读回。

#### 判断只追加不修改，改主意就追加一条新的取代旧的 [#E-2-2-1]

判断写进账本后不能改，只能追加。要改，就写一条新判断，声明它取代哪一条；旧的那条保留。

这样任何时候都能查到当时是怎么想的，后来又为什么改了。

<div className="rd-example">

比如第一次复盘推荐 H05，后来出现了 H09，第二次复盘就写一条新推荐取代旧的。按第一次复盘时的账本版本读，看到的仍是推荐 H05。每条判断都挂在它所说的对象上，推荐、父版本和对照只能指向候选。

</div>

#### 自己写脚本额外看过的角度，也要记下来 [#E-2-2-2]

产品读出来的试验会自动计数；但 Agent 自己写脚本额外看过的角度，比如按月拆、按合约拆、算成交量占比，要记成一条判断；skill 要求算的视角也一样要记。

看的角度越多，碰巧看到一个好看数字的机会就越大。把看过的角度记下来，之后估计结果有多可信时才不会漏算。

<div className="rd-example">

比如为了解释 H09，Agent 又按合约、按月份、按多空各拆了一遍，就记一条判断，写明看过这三个角度，以及读的是哪个账本版本。

## 1.3　给出综合推荐与路线选项 [#E-3]

把所有能用的候选摆在一起，给你一份推荐和几条可选的路线。

<Steps>

<Step>

先拿出最新推荐；没有推荐，或者推荐之后又有新的有效运行，就重做。

</Step>

<Step>

把所有有经济证据资格的候选列为选项，只能诊断、无效和没跑完的另列；一个候选都没有，或者你要离开所有路线时，再加上策略库模板。

</Step>

<Step>

每个选项附同一组绩效指标和历史反馈。

</Step>

<Step>

读对照表：同一窗口、同一范围的候选里，代码已标出没被全面压过的那些。

</Step>

<Step>

写推荐说明，交给你选路线。

</Step>

</Steps>

### 候选范围 [#E-3-1]

推荐从哪些候选里选。

#### 入口先拿出最新推荐；推荐过时了就先重做 [#E-3-1-1]

入口先拿出最近一次的推荐。还没有推荐，或者推荐之后又出了新的有效运行，就先重做一次推荐。

推荐过时了还拿来用，等于让你在不完整的信息上选路线。

<div className="rd-example">

推荐的范围是谱系里所有有经济证据资格的候选，包括很早以前的版本，也包括别的路线上的版本。只能诊断、判为无效或没跑完的版本另列一栏，不和有效候选放在一起比。

</div>

<div className="rd-foot"><span className="rd-guard">skill</span> <span className="rd-impl"><Ref id="rule:E.3.1.1">research-start · references/recommendation.md</Ref></span> <span className="rd-tier rd-tier-rehearsal">演练证据</span></div>

#### 只有没有候选，或者你说要离开所有路线时，才从策略库模板起步 [#E-3-1-2]

只有两种情况会把策略库里的模板列为起点：账本里一个候选都没有；或者你明确说要离开所有现有路线。

亏损、不显著、跑得慢都不是换起点的理由，它们只影响下一步先做什么。轻易换起点，前面积累的研究就白费了。

<div className="rd-example">

每个模板选项附上它在当前开发窗口的第一份报告，比如年化、回撤和胜率，让你知道它大概是什么水平；还没回放过的模板也列出来，但标明「未回放」。

</div>

### 选项材料与呈现 [#E-3-2]

每个选项附什么材料，推荐说明写什么。

#### 每个选项列同一组指标，算不出的留空并写原因 [#E-3-2-1]

每个候选选项都列同一组数：年化、最大回撤、夏普、计划胜率、成本、资金使用率、利润来源，以及和对照相比的不确定性。算不出的项留空，写明原因，不估也不补。

只看一个指标会被误导。回撤小的版本可能只是资金几乎没用上，收益高的版本可能主要靠资金费。

<div className="rd-example">

全池 RSI 的 H08 最大回撤只有 0.62%，看起来很稳；但它平均只用了初始资金的 0.39%。不把资金使用率一起列出来，就会把「仓位小」误读成「风险控制好」。

</div>

<div className="rd-foot"><span className="rd-guard">skill</span> <span className="rd-impl"><Ref id="rule:E.3.2.1">research-start · references/recommendation.md</Ref></span> <span className="rd-tier rd-tier-verified">已验证</span></div>

#### 推荐写清是哪一版、凭什么、放弃了什么 [#E-3-2-3]

推荐说明写清四件事：推荐哪一版；依据哪些指标；取舍是什么；它和下一个实验的起点是不是同一版，不是的话为什么。

你要据此选路线，取舍不写清楚，就看不出推荐背后的代价。推荐也不等于样本外验证或上线，那要你看完报告再决定。

<div className="rd-example">

比如：「推荐 H09：年化 4.24%，高于其他候选；代价是回撤升到 8.44%，而且闭仓收益里将近一半来自资金费。下一个实验从 H09 出发，对照用 H08。」

</div>

### 跨候选汇总 [#E-3-3]

候选很多时，先筛掉明显不如别人的。

<a id="E-3-3-1" />

**在同一窗口、同一范围的候选里，代码标出没被全面压过的那些**

非劣候选集由代码算：研究状态的对照表里，同一开发窗口、同一可交易范围、有经济证据资格的运行，按年化、回撤、夏普、胜率四项两两比较，标出谁没被别人四项全面压过。哪一项缺值的，不参加比较。

四项都不如别人的候选没有理由推荐；剩下的各有长短，留给推荐说明去权衡。交给代码算，就不会手算漏掉某个运行，或混进别的窗口。

<div className="rd-example">

A 年化高、回撤也大，B 年化低、回撤也小，两个谁也没全面压过谁，都在集合里。C 四项都不如 A，就不在。推荐可以落在集合外面，但要说明理由。集合是从很多候选里挑出来的，看的时候要记得有挑选带来的乐观偏差。

</div>

## 1.4　用户选定研究路线 [#E-4]

每个研究账本同一时刻只有一条当前研究路线，选哪条由你决定；选定之后，路线里的事由 Agent 自己推进。

当前路线是最新入账的路线；你通过 <Ref id="ledger.select_line">select_line</Ref> 选择新路线，就接替旧路线（<Ref id="ledger.current_line">current_line</Ref>）。旧路线随之结束，封盘点为新路线诞生提交的父提交，由 <Ref id="ledger.close_line">close_line</Ref> 封盘。单一当前路线是共享研究上下文，不是执行锁；选线不会自动停止其他 Agent 或在途任务。

同一路线内可以分工查资料、审查和分析；正式实验仍遵守现有登记、解释、复盘与事务检查。本产品不将两条路线同时推进正式研究作为已支持能力。

当前 <Ref id="ledger.line_trials">line_trials</Ref> 按市场提交和开发窗口匹配研究试验，并非逐路线身份隔离；相同数据与窗口的路线可能共享试验集合。因此，多开会话不能视为两条研究路线已获得独立隔离。

<Steps>

<Step>

Agent 摆出推荐和路线选项，然后提问、等你回答。

</Step>

<Step>

你选定路线，可以附上资料、想法，或者一次性授权用某个模板。

</Step>

<Step>

选的是模板，就先核就绪，把它发布成起点，跑预检并经独立审查。

</Step>

<Step>

把市场数据版本、开发窗口、可交易范围和起点候选（新根取审查通过的那一版，审查没通过的起点代码不收）写成路线记录；新根随后登记一次，回放出第一份报告。

</Step>

<Step>

路线里由 Agent 自己推进；要换路线时，回到第一步。

</Step>

</Steps>

<a id="E-4-1" />

谁提选项，谁做决定。

### Agent 给出选项后就停下来问你，你选之前它什么都不动 [#E-4-1-1]

Agent 给出路线选项后以提问结束，然后等你选。你选之前，它不登记、不回放、不发布新候选，也不把推荐第一名当作你已经选了。

选哪条路线是研究方向的决定，属于你。Agent 能做的是把选项和材料准备好。

<div className="rd-example">

路线里遇到亏损、不显著或运行故障，Agent 都不会自己换路线。确实需要换的时候，它回到入口，给出诊断和选项，再问你。

</div>

### 你附带的想法照常登记；选模板的授权给一次就够 [#E-4-1-2]

选路线时你可以附上想法或资料。想法会变成路线里一个普通的假设，和其他假设一样先查来源、写预测、登记，再回放；资料会被转写成一个新的起点策略。

想法来自你，也要过同样的检验，不然分不清是想法好还是运气好。

<div className="rd-example">

比如你说「试试资金费为正时不做多」，Agent 会把它写成一个假设，找相关文献，写下预计会影响哪些交易，登记后再跑。你说「就用这个模板开始」，这一次授权就够了，后面的发布、路线记录和首份报告不用再问你。

</div>

### 开始研究时 Agent 自己设宿主目标，让研究连续跑下去 [#E-4-1-3]

进入路线之前，Agent 自己给这次会话设宿主的目标，你不用写。目标从账本拼出来：哪条路线、从哪一版开始、你选路线时定的两个目标，再加一句：写完报告、复盘或排好优先级都不算完，只有你叫停、路线做不下去或到了该换线的时候（<Ref id="F.3.1.3" />）才停。先检查并复用本路线已有的活动目标。宿主允许自动创建时，Agent 直接调用目标工具（比如 Codex 的 `create_goal`），不设 token 预算，并用一行告诉你。若宿主要求明确授权，Agent 提出上述具体目标，请你授权，获准后才创建，沉默不算批准。没有目标工具时，给出可直接激活的命令（Codex 用 `/goal <目标>`，Claude Code 用 `/loop <目标>`），核实目标激活后再开始研究。

一个回合里 Agent 能自己不停（<Ref id="A.1.1.3" />），但回合结束后要不要接着开下一个回合，由宿主的目标决定；没有目标，做完一轮就停了。目标的内容账本里都有，让你自己写既多一步，也容易漏掉路线或目标；所以能设就由 Agent 设。目标一直留着，路线还能做就不标完成，否则宿主会以为事情做完了。

<div className="rd-example">

比如你选了一条日线动量路线，宿主有 `create_goal`。Agent 调用它，目标写成「在日线动量路线（从选定的那一版开始）里持续研究，读报告时参照选路线时记下的两个目标；写完报告、复盘或优先级都不停，直到用户叫停或路线做不下去」，不设 token 预算，然后告诉你一句「已设好目标」，就去核就绪、跑第一次回放。换到没有目标工具的宿主，它会把同一句目标放进 `/goal <目标>` 请你激活，核实成功后继续；若有工具但宿主要求授权，就把具体目标放进“继续还是换线”的同一个问题，你选继续即批准，获准后调用工具。

</div>

### Goal 激活时只问卡住工作的问题，问之前先让 Goal 停下 [#E-4-1-4]

宿主的目标会在回合以提问结束后不等你回答就续跑。所以 Goal 激活时，Agent 只问会卡住这条线的问题（该换线了、需要你授权的事）；其余在自己权限内决定，用一句话告诉你。问之前先用宿主的工具暂停目标；宿主没有暂停工具时，在同一个问题里请你手动暂停。你没回答之前，续跑的回合不做任何依赖答案的事：只重复这个问题然后结束。没有你的消息，就不能说已获授权。

<div className="rd-example">

一次 Codex 会话里，Agent 问你扩窗起点选哪个，15 毫秒后目标就续跑了；它随后自己撤回了问题，在旧窗口里又跑了 12 小时。按这条规则，它会请你先暂停目标，续跑时只重复问题。

</div>
