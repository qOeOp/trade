# E　入口：每次开始或中断后，Agent 如何从账本恢复研究状态、汇总候选给出综合推荐，并由用户选定研究路线。

本章回答研究从哪里开始、中断后从哪里接着做：从账本读回研究状态与研究计数并核对环境就绪，把判断逐条记进账本，汇总各候选给出综合推荐与路线选项，再由用户选定研究路线。它承接 F 章的复盘与推荐。

## E.1　恢复研究状态 [#E-1]

<Steps>

<Step>

读账本里的候选清单和研究计数，确认账本可用。

</Step>

<Step>

读当前研究路线；没有路线就转去用户选路线。

</Step>

<Step>

有路线就读研究状态，决定先复盘还是续做。

</Step>

<Step>

按路线钉住的市场提交核对环境就绪。

</Step>

<Step>

就绪就继续；不就绪报告阻断和可运行范围。

</Step>

</Steps>

### E.1.1　时机与从账本读的材料 [#E-1-1]

研究状态和研究计数只从账本读出，不靠会话记忆。

<ul className="rd-rules">
<li id="E-1-1-1"><span className="rd-rule-id">E.1.1.1</span> 开始或恢复先读账本；有路线就续做，不重问用户 <Ref id="rule:E.1.1.1">research-start · SKILL.md</Ref></li>
</ul>

<Cap id="E.1.1.3" kind="skill" tier="rehearsal" tierLabel="演练证据" title="研究状态在读取时拼出，本身不另存">

- 只取当前有效的判断。
- 判断涉及的候选和试验，附上读取时的经济证据资格和绩效指标。
- 未复盘的试验是上次推荐之后新增、属于本路线的试验。
- 任何一个账本版本都能读出当时的研究状态。

### E.1.2　核对环境就绪 [#E-1-2]

入口只读出数据事实并报告就绪或阻断，不裁决数据够不够用。

<Cap id="E.1.2.1" kind="code" tier="verified" tierLabel="已验证" title="一条路线钉住一个市场提交，路线内回放共用它">

- 用户选定路线时，市场提交和开发窗口一起写进路线记录。
- 同一市场提交上的回放才可比。
- 市场数据出现新月份时只报告可扩展的范围，不自动换提交。
- 换市场提交就是换路线，由用户选择。

<Cap id="E.1.2.2" kind="code" tier="rehearsal" tierLabel="演练证据" title="逐合约覆盖只列事实，入口不删币、不缩窗、不补数">

- 按钉住的市场提交，逐合约列出缺口、零成交分钟和资金费记录。
- 上市、下架等成员变化按账本里留存的原件核对后列出。

- 缺口原样报告，不据此判经济失败，也不替策略判就绪。

## E.2　记录研究判断 [#E-2]

<Steps>

<Step>

读研究状态和本次试验的检验结果。

</Step>

<Step>

写当前决定：综合推荐、研究优先级和复盘节奏。

</Step>

<Step>

对负面、不显著和只有诊断的发现逐条写解释。

</Step>

<Step>

每条判断挂上涉及的候选、试验或登记，正文只引用不抄数字。

</Step>

<Step>

逐条追加进账本，不合规的写入被拒绝。

</Step>

</Steps>

### E.2.1　内容 [#E-2-1]

规定每类决定记成哪种判断、写什么；代码的判定都不读判断正文。

<ul className="rd-rules">
<li id="E-2-1-1"><span className="rd-rule-id">E.2.1.1</span> 复盘写推荐与优先级；复盘节奏按试验次数记，只能调小 <Ref id="rule:E.2.1.1">research-round · references/review.md</Ref></li>
<li id="E-2-1-2"><span className="rd-rule-id">E.2.1.2</span> 每次登记至少写一条解释：带适用与重评条件，结论限于登记条件 <Ref id="rule:E.2.1.2">research-round · references/feedback.md</Ref></li>
</ul>

### E.2.2　存法与读回 [#E-2-2]

判断只追加存进账本，任一账本版本都能读回。

<Cap id="E.2.2.1" kind="database" tier="verified" tierLabel="已验证" title="判断只追加入账；改判断就追加一条，取代旧的">

- 每条判断属于一条研究路线，挂上涉及的候选、试验或登记。
- 推荐、父版本、对照这几种角色只能指向候选。
- 改判断写新一条取代旧的，旧的保留，每条只能被取代一次。
- 任一账本版本都能读回当时的判断。

## E.3　给出综合推荐与路线选项 [#E-3]

<Steps>

<Step>

先读最新的综合推荐；没有推荐或有未复盘的有效运行就重做推荐。

</Step>

<Step>

有经济证据资格的候选都列为选项，诊断、无效和未完成的分列；没有候选或用户离开全部路线时加上策略库模板作根的选项。

</Step>

<Step>

每个选项附同一组绩效指标和历史反馈。

</Step>

<Step>

在同窗口同范围的可用运行上做跨候选汇总，找出未被全面压过的候选。

</Step>

<Step>

写推荐说明，交用户选路线。

</Step>

</Steps>

### E.3.1　候选范围 [#E-3-1]

划定推荐选项从哪来。

<ul className="rd-rules">
<li id="E-3-1-1"><span className="rd-rule-id">E.3.1.1</span> 入口先读最新推荐；没有推荐或有未复盘的有效运行就重做推荐 <Ref id="rule:E.3.1.1">research-start · references/recommendation.md</Ref></li>
<li id="E-3-1-2"><span className="rd-rule-id">E.3.1.2</span> 只在没有候选或用户离开全部路线时提出模板根 <Ref id="rule:E.3.1.2">research-start · SKILL.md</Ref></li>
</ul>

### E.3.2　选项材料与呈现 [#E-3-2]

规定每个选项附哪些材料，只定呈现，不定判据。

<ul className="rd-rules">
<li id="E-3-2-1"><span className="rd-rule-id">E.3.2.1</span> 每个选项列同一组绩效指标，缺项留空并写原因 <Ref id="rule:E.3.2.1">research-start · references/recommendation.md</Ref></li>
<li id="E-3-2-3"><span className="rd-rule-id">E.3.2.3</span> 推荐写明版本、依据与取舍；下一实验的父版本和对照另给理由 <Ref id="rule:E.3.2.3">research-start · references/recommendation.md</Ref></li>
</ul>

### E.3.3　跨候选汇总 [#E-3-3]

代码给出候选清单与计数事实，不含分数或排序；skill 规定汇总口径。

<ul className="rd-rules">
<li id="E-3-3-1"><span className="rd-rule-id">E.3.3.1</span> 只在同窗口同范围的可用运行上，按四项指标求未被全面压过的候选 <Ref id="rule:E.3.3.1">research-round · references/review.md</Ref></li>
</ul>

## E.4　用户选定研究路线 [#E-4]

<Steps>

<Step>

Agent 呈现推荐与路线选项，以提问结束并等待。

</Step>

<Step>

用户选定路线，可附信息源、想法，或一次性授权选某个模板。

</Step>

<Step>

选中模板时，把它发布成根，登记一次并回放出首份报告。

</Step>

<Step>

把市场提交、开发窗口、可交易范围和起点候选写成路线记录。

</Step>

<Step>

路线内由 Agent 自主推进；要换路线时回到第 1 步。

</Step>

</Steps>

### E.4.1　选择权 [#E-4-1]

Agent 提选项，用户选路线，选定前 Agent 只等待。

<ul className="rd-rules">
<li id="E-4-1-1"><span className="rd-rule-id">E.4.1.1</span> 给出路线选项后以提问结束；选定前不登记、不回放、不写路线 <Ref id="rule:E.4.1.1">research-start · SKILL.md</Ref></li>
<li id="E-4-1-2"><span className="rd-rule-id">E.4.1.2</span> 用户的想法当普通假设登记；选根的授权给一次就够 <Ref id="rule:E.4.1.2">research-start · references/selection.md</Ref></li>
</ul>
