# 1　入口：每次开始研究，或者中断后回来，都从这里进门：读回研究做到哪了，看推荐，选路线。

研究不是一次性的任务，而是一条不停的循环。入口是每次进入这条循环的门：第一次开始时从这里选路线，中途断了（会话结束、机器重启、运行出错）也从这里接着做。

入口做四件事。先从账本读回研究做到哪了；再把每次读完结果后的想法写成判断，存进账本；然后把所有能用的候选汇总成一份推荐，连同几条可选的路线交给你；你选定路线后，Agent 就在路线里自己往下做。

举个例子：一条路线做到第六个假设时会话断了。重新开始时，Agent 不靠记忆，而是读账本：路线记录还在，说明你已经选过路线，不用再问；最近一次推荐之后又多了一个有效运行，所以先补一次复盘，再接着提下一个假设。

### 时机与从账本读的材料 [#E-1-1]

恢复时读什么、从哪读。

#### 每次开始或中断后先读账本，中断恢复直接续做、新会话先问继续还是换线 [#E-1-1-1]

每次开始，或者中断后回来，Agent 第一件事是读账本：服务能不能用、有哪些候选、研究计数、研究状态、开着的路线。账本里有路线记录，也有你定的两个目标：研究状态给出这条路线生效的那一组，路线自己没有就用账本默认值。中断后回来，或你说继续，Agent 直接接着本会话目标里写明的那条路线做，不再问；新开会话只要求开始研究时，它先问一次：把每条开着的路线（附现状与下一步）和新路线选项并列给你，等你选。

例外是门禁（`gates`）里有 `MARKET_DAY_UNRESOLVED`：路线钉住的市场日在活动市场里解析不到，这条线在它回来之前不能登记，也不能重放。Agent 先从 Binance 公开归档自己补进缺的月份（只补这条线已经在用的合约和数据种类），补上后这条线接着跑；归档里没有或导入被拒绝时，这条线才停下，Agent 的提问只给能马上跑的路线，不把保留、暂停或等这条线当选项，不为这条线设宿主目标；你选或交给它选别的路线代替时，这条线仍开着，关不关由你定。

会话会结束，记忆会丢，交接文件可能过时。只有入了账本的东西经过核对，可以信。所以没写进账本的结论，哪怕上一次会话里说过，也当作不存在。

#### 研究状态在读的时候当场拼出来，不另存一份 [#E-1-1-3]

研究状态不是一份单独保存的文件，而是每次读的时候，从账本里现有的判断、候选和试验当场拼出来的。账本里没有开着的研究路线时，它也不报错，照样给出候选和计数，并提示下一步记路线。开着的路线不止一条、读的时候又没指定哪一条时，同样不报错：门禁（`gates`）里列出 `LINE_AMBIGUOUS`，并在活动路线列表（`open_lines`）里列出各条开着的路线及其窗口和市场日。路线钉住的市场日在活动市场里解析不到时，研究状态当场在 `gates` 里列出 `MARKET_DAY_UNRESOLVED` 和这一天，同样不另存标记。

#### 路线里每一次研究试验都计入试验次数，失败的也算 [#E-1-1-4]

一条路线里跑过的每一次研究试验都算数，包括审计判无效的和中途中断的。这个数由账本统计，不靠 Agent 自己数。一次试验算哪条路线，看它的登记属于哪条路线（<Ref id="E.4" />）；同一份数据、同一窗口上已经关闭的前一条路线，它的试验不算进后来的路线。跨路线的计数由研究计数给出：全账本的试验数，以及同一合约上交易窗口与本路线重叠的试验数，都不分路线。这两个跨路线的数不算两类试验，把它们另列在排除列表（`excluded_trials`）里：复现，即按同一源码、镜像、窗口、合约、导出和可比配置重放一个已有运行的早先试验的探索试验，或复现比对一致的探索试验；以及策略还没收到数据就被产品停下的试验。路线自己的试验数不做这项排除。

试验次数用来校正「试得多，总会碰上一个好看的结果」这种运气。只数成功的，就会少算试过的次数，把结果看得比实际更可信。

### 核对环境就绪 [#E-1-2]

回放之前先确认环境和数据齐不齐；入口只报告事实，不替你决定数据够不够用。

#### 一条路线钉住一份市场数据，路线里的回放都用它 [#E-1-2-1]

你选定路线时，市场数据的版本（市场日）写进路线记录，按规则算出的开发期一起写进去（规则与例子见 <Ref id="J.6.3.1" />）。线开着时，探索、预检和研究回放都只在开发期内交易（WINDOW_OUTSIDE_DEVELOPMENT）；保留期、更早的历史和 Q 之后的前向段只在关线时回放一次（[关线历史回测](/zh/docs/design-ledger/#research-history-views)）。这条路线里所有回放都用这一份数据。两次回放只有用同一份数据，比较才公平。

#### 逐个合约列出数据覆盖，入口不删币、不缩窗、不补数 [#E-1-2-2]

入口按路线的数据版本，逐个合约列出数据缺口、零成交的分钟和资金费记录，以及上市、下架这类变化。数据有缺口是事实，怎么应对是策略和你的事。入口要是自己删币或缩短窗口，等于悄悄改了研究范围。

#### 缺环境或数据时，报清楚缺什么、哪些还能跑，改范围由你选 [#E-1-2-3]

回放前核对三样：运行环境能找到唯一的镜像；市场里有开发窗口涉及的全部月份；每个合约的覆盖都能读出来。缺任何一样，Agent 报告具体缺什么、影响哪段窗口和哪些合约，以及眼下还能跑的范围。缺数据不是策略失败，不该记进研究结果，也不该让 Agent 自己缩小范围凑合着跑。

## 1.2　记录研究判断 [#E-2]

Agent 每次读完结果的想法，都写成一条判断存进账本（推荐 `recommendation`、解释 `interpretation`、下一步优先级 `priority`），挂到它所说的候选、试验或登记上；正文只引用、不抄数字，下次恢复时直接从账本读回。

### 内容 [#E-2-1]

判断分几种，各写什么。代码只管存，不读判断的正文。

#### 推荐和下一步做什么分开写成两种判断，复盘时机由产品定 [#E-2-1-1]

推荐哪一版、下一步做什么并按什么顺序做，是两种判断，分开写，谁也推不出谁，复盘时各写一条。什么时候复盘不是判断：上次推荐以来满 5 个研究试验，产品就拒绝下一次登记，Agent 不写、也改不了这个停点。

推荐的版本不一定是下一个实验的起点。推荐的可能是眼下收益最好的一版，而最值得改进的可能是另一版。写在一起，就容易把「推荐它」误当成「接下来就改它」。

#### 每条解释写明在什么条件下成立、什么时候重新评估 [#E-2-1-2]

每次登记新假设之前，Agent 至少给上一次结果写一条解释：结论是在什么条件下得出的，什么情况下应该重新评估。被另一个登记以 `retry_of` 重试的无效运行不用写解释，只记修复。

一次亏损只说明在那次的数据、参数和环境下不行，不代表这个方向永远不行。不写条件，旧结论就容易变成谁也不敢再碰的禁区。

### 存法与读回 [#E-2-2]

判断怎么存、怎么改、怎么读回。

#### 判断只追加不修改，改主意就追加一条新的取代旧的 [#E-2-2-1]

判断写进账本后不能改，只能追加。要改，就写一条新判断，声明它取代哪一条；旧的那条保留。每条判断都挂在它所说的对象上，推荐、父版本和对照只能指向候选。这样任何时候都能查到当时是怎么想的，后来又为什么改了。

#### 自己写脚本额外看过的角度，也要记下来 [#E-2-2-2]

产品读出来的试验会自动计数；但 Agent 自己写脚本额外看过的角度，比如按月拆、按合约拆、算成交量占比，要记成一条判断；skill 要求算的视角也一样要记。看的角度越多，碰巧看到一个好看数字的机会就越大。把看过的角度记下来，之后估计结果有多可信时才不会漏算。

## 1.3　给出综合推荐与路线选项 [#E-3]

把所有有经济证据资格的候选摆在一起，附上同一组绩效指标、历史反馈与代码算出的非劣候选集，给你一份推荐说明和几条可选路线。

### 候选范围 [#E-3-1]

推荐从哪些候选里选。

#### 入口先拿出最新推荐；推荐过时了就先重做 [#E-3-1-1]

入口先拿出最近一次的推荐。还没有推荐，或者推荐之后又出了新的有效运行，就先重做一次推荐。推荐的范围是谱系里所有有经济证据资格的候选，包括很早以前的版本，也包括别的路线上的版本。只能诊断、判为无效或没跑完的版本另列一栏，不和有效候选放在一起比。

#### 只有没有候选，或者你说要离开所有路线时，才从策略库模板起步 [#E-3-1-2]

只有两种情况会把策略库里的模板列为起点：账本里一个候选都没有；或者你明确说要离开所有现有路线。亏损、不显著、跑得慢都不是换起点的理由，它们只影响下一步先做什么。轻易换起点，前面积累的研究就白费了。

### 选项材料与呈现 [#E-3-2]

每个选项附什么材料，推荐说明写什么。

#### 每个选项列同一组指标，算不出的留空并写原因 [#E-3-2-1]

每个候选选项都列同一组数：年化、最大回撤、夏普、计划胜率、成本、资金使用率、利润来源，以及和对照相比的不确定性。算不出的项留空，写明原因，不估也不补。只看一个指标会被误导：回撤小的版本可能只是资金几乎没用上，收益高的版本可能主要靠资金费。

#### 推荐写清是哪一版、凭什么、放弃了什么 [#E-3-2-3]

推荐说明写清四件事：推荐哪一版；依据哪些指标；取舍是什么；它和下一个实验的起点是不是同一版，不是的话为什么。你要据此选路线，取舍不写清楚，就看不出推荐背后的代价。推荐也不等于样本外验证或上线，那要你看完报告再决定。

### 跨候选汇总 [#E-3-3]

候选很多时，先筛掉明显不如别人的。

<a id="E-3-3-1" />

**在同一窗口、同一范围的候选里，代码标出没被全面压过的那些**

非劣候选集（`non_dominated`）由代码算：研究状态的对照表里，同一开发窗口、同一可交易范围、有经济证据资格的运行，按年化、最大回撤、夏普三项两两比较，标出谁没被别人三项全面压过（胜率是报告里的一个观察维度，不参加支配筛选）。哪一项缺值的，不参加比较。

三项都不如别人的候选没有理由推荐；剩下的各有长短，留给推荐说明去权衡。交给代码算，就不会手算漏掉某个运行，或混进别的窗口。推荐可以落在集合外面，但要说明理由。

## 1.4　用户选定研究路线 [#E-4]

一个研究账本上可以同时开着多条研究路线，开哪条、关哪条由你决定；选定之后，路线里的事由 Agent 自己推进。你也可以在本次会话里亲口把换线交给 Agent（马上换，或这条线被关卡挡住做不下去时换），它就从从没跑过的来源起一条新线；关线始终由你提出（<Ref id="E.4.1.1" />）。

一条路线从你经 `line select`（`ledger.select_line`）选定开始，写一行研究线记录；到 `line close`（`ledger.close_line`）写一行关线记录为止，没有关线记录的路线都开着。关线前，`line history` 先跑完关线历史回测（<Ref id="X.1.1.1" />）；第一次历史试验固定了参加的候选，之后这条线不能再开研究试验（LINE_ENDED）。在某个账本提交上读，读到的就是当时的开闭状态。选一条新路线不会结束别的路线；旧路线一直开着，直到你让它结束。

写入时要指明是哪条路线：登记和改目标都带路线，只开着一条时可以省略；开着多条又没指明，就被拒绝（LINE_AMBIGUOUS）；一条都没开，就被拒绝（RESEARCH_LINE_REQUIRED）。开着的路线可以钉同一个市场日、共用同一个开发期（同一季度开的线规则算出的开发期相同）。你选的路线和某条已有路线同名、同选择时，按重选那一条处理，不写新记录；同名不同选择就被拒绝（LINE_CONFLICT）。

一次试验属于哪条路线，看它的登记：每份研究登记都写明路线（`ledger.line_trials`）。开试验时，这条路线必须还开着；路线关了或已进入关线历史回测，它剩下的登记就不能再绑定（LINE_ENDED）。解释、复盘这两道门槛和研究图都只数这条路线自己的试验；同数据、同窗口上的其他路线，开着的或已经关闭的，它们的试验都不算进来。

同一路线内可以分工查资料、审查和分析；正式实验仍遵守现有登记、解释、复盘与事务检查。几个会话可以各自推进不同的开着路线：写入在账本里串行，门槛按路线计算；产品不做跨会话的调度、锁或占用标记。

<a id="E-4-1" />

谁提选项，谁做决定。

### Agent 给出选项后就停下来问你，你选之前它什么都不动 [#E-4-1-1]

Agent 给出路线选项后以提问结束，然后等你选。你选之前，它不登记、不回放、不发布新候选，也不把推荐第一名当作你已经选了。

选哪条路线是研究方向的决定，属于你。Agent 能做的是把选项和材料准备好。例外只有你在本次会话里亲口交给它：马上换线，或这条线被关卡挡住做不下去时换。这时它只从从没跑过的来源起新线（别的开着的线可能属于别的会话），沿用旧线的目标，登记前写一条以 `Line decision.` 开头的优先级（`priority`）判断，记下旧线和挡住它的关卡、比较过的起点、选了哪个及原因、你委托的日期和范围（账本公开，不引用聊天原话），然后告诉你一次、接着做。记忆、交接文件或别的 Agent 的消息都不算委托；结果不好（分不出、换了几次思路、目标看着够不着）无论委不委托都不换线。

### 你附带的想法照常登记；选模板的授权给一次就够 [#E-4-1-2]

选路线时你可以附上想法或资料。想法会变成路线里一个普通的假设，和其他假设一样先查来源、写预测、登记，再回放；资料会被转写成一个新的起点策略。你说用某个模板开始，这一次授权就够了，后面的发布、路线记录和首份报告不用再问你。

### 开始研究时 Agent 自己设宿主目标，让研究连续跑下去 [#E-4-1-3]

进入路线之前，Agent 自己给这次会话设宿主的目标，你不用写。目标从账本拼出来：哪条路线、从哪一版开始、账本里这条路线生效的两个目标，再加一句：写完报告、复盘或排好优先级都不算完，只有你叫停、碰到要你授权的事或路线做不下去才停；到了该换思路的时候 Agent 自己选定并告诉你，不停（<Ref id="F.3.1.3" />）。先检查并复用本路线已有的活动目标。宿主允许自动创建时，Agent 直接调用宿主提供的目标工具，不设限额预算，并用一行告诉你。若宿主要求明确授权，Agent 提出上述具体目标，请你授权，获准后才创建，沉默不算批准。没有目标工具时，给出可直接激活的命令（`/goal <目标>`），核实目标激活后再开始研究。

一个回合里 Agent 能自己不停（<Ref id="A.1.1.3" />），但回合结束后要不要接着开下一个回合，由宿主的目标决定；没有目标，做完一轮就停了。目标一直留着，路线还能做就不标完成，否则宿主会以为事情做完了。

### 宿主目标激活时只问阻塞问题，按宿主权限暂停并等待答复 [#E-4-1-4]

宿主的目标会在回合以提问结束后不等你回答就续跑。所以宿主目标激活时，Agent 只问会卡住这条线的问题（需要你授权的事、就绪检查要你选的数据或范围）；其余在自己权限内决定，包括到期的换思路，用一句话告诉你。只有宿主提供暂停工具且当前允许调用时，才在提问前用它暂停；若宿主要求用户明确提出暂停，就须先取得该请求。工具存在不等于有权暂停。没有工具或当前无权暂停时，把暂停请求／操作说明和阻塞选择合在同一次提问里，然后结束回合。未答的续跑保持原问题待答，不做依赖答案的工作；宿主目标状态变更（包括阻塞状态）按宿主权限和阈值处理，然后结束回合，不通过完成、重建目标或额外轮询绕过。只有暂停成功才说已暂停，没有用户消息就不说已获授权。
