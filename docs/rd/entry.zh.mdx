# E　入口：每次开始或中断后，Agent 如何从账本恢复研究状态、给出综合推荐，并由用户选定研究路线。

入口是研究循环的起点和中断后的回归点。本章定义：从账本 ledger 恢复研究状态 research state 并核对环境就绪；只追加的研究状态清单；在全部经济证据可用的候选 candidate 上给出综合推荐 recommendation 与路线选项；把用户的选择写成研究路线 research line 记录。读出、核哈希与路线窗口由代码强制，读的顺序、推荐写法与选定前等待由 skill 强制；不设达标门槛、不排除方向。候选谱系、比较读数、生命周期回执产出与账本机制见 T、V、W、J 章。

## E.1　恢复研究状态 [#E-1]

恢复研究状态 research state 按固定顺序进行，输入是账本 ledger 的当前提交，输出是可直接续做的研究状态。第一步经命令行接口读账本服务状态与当前提交；第二步读候选清单（每个候选 candidate 的源码身份、研发父版本 parent 与改动说明、每次登记 registration 的尝试及其运行 run 状态与经济证据可用性）与研究计数；第三步读 Agent 维护的只追加研究状态清单 knowledge list 最新版并核内容哈希；第四步读当前研究路线 research line 记录取出钉住的市场提交 market commit 与开发窗口 development window，再核对市场库新鲜度、逐合约覆盖与生命周期回执、运行环境 runtime image 是否可解析。前四步的事实由代码从账本与市场库按精确版本读出，不带推荐分数或资格标记；skill 规定读的顺序、不认的来源（会话记忆、交接文件、工作副本）与读完后的行为。第五步缺什么就报告精确阻断与可运行范围，不改候选身份，不否定路线有效性，改范围由用户选。整段恢复不依赖会话记忆，任何未写入账本的事实视为不存在。

### E.1.1　时机与从账本读的材料 [#E-1-1]

三条能力分别规定何时恢复、读哪些代码产出的事实、读哪份 Agent 维护的清单。代码强制候选清单与计数只来自账本的精确版本且不带推荐分数或资格标记；skill 强制恢复的时机与顺序，并规定会话记忆与交接文件不算来源。输入是账本当前提交，输出是恢复后的研究状态与当前路线。

<Cap id="E.1.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="每次开始、中断或暂停后恢复都先从账本读状态；已选路线直接续做；不依赖会话记忆或交接文件">

每次开始研究、中断或暂停后恢复，Agent 先经声明的命令行接口 <Ref id="cli.main" /> 读账本 ledger：经 <Ref id="cli.ledger_service" /> 读服务状态与当前提交，经 <Ref id="report.candidates" /> 读候选清单，经 <Ref id="report.research_status" /> 读研究计数，再按 <Ref id="research-start/SKILL.md#read-state-list" /> 读研究状态清单，最后经 <Ref id="ledger.current_line" /> 读当前研究路线 research line 记录。路线记录存在即表示用户已选路线，Agent 直接续做，不重问，不以推荐代替用户已做的选择；记录不存在才进入路线选择 <Ref id="E.4.1.1" />。研究状态 research state 的唯一来源是账本：会话记忆、交接文件、工作副本中的结论与未入账的运行输出一律视为不存在，不得用于推荐或下一假设；要用必须先以证据包写入账本再读回。暂停只保留账本中的登记与未消耗的网格点，恢复后续做，不重开登记（<Ref id="A.1.2.1" />）。每条读命令一条连接、JSON 输出、拒绝带码；代码保证读出的清单与计数只来自账本且不带分数，skill 强制顺序与来源规则。演练中两次在中断与运行故障后均按此恢复并续做已选路线。

### E.1.2　核对环境就绪 [#E-1-2]

入口读完账本后核对三件事：市场库新鲜度与钉住的市场提交；逐合约的覆盖与生命周期回执；运行环境与数据是否可用。前两件由代码按精确市场提交读事实并原样返回，不排序不筛除；第三件由 skill 规定只报告不裁决。输入是研究路线记录里的市场提交、开发窗口与范围规则，输出是就绪结论或精确阻断与可运行范围。

<Cap id="E.1.2.1" kind="code" tier="verified" tierLabel="已验证" title="读市场库新鲜度并钉住一个市场提交，整段可比开发共用同一提交">

入口经 <Ref id="ledger.current_line" /> 读当前研究路线记录，取出钉住的市场提交 market commit、开发窗口 development window 与范围规则 universe_rule；再经 <Ref id="market.freshness" /> 按该提交 AS OF 读交易所数据 exchange data 库的新鲜度：成员月份、合约数、最新完整日、最新完整月与当前月覆盖到的时刻。用户给出的引用（具名引用如 main、标签或哈希前缀）一律先经 <Ref id="market.resolve_commit" /> 解析为唯一提交哈希，工作集引用拒绝 NOT_A_COMMIT。市场提交在用户选定路线时经 <Ref id="ledger.select_line" /> 写入研究路线记录；此后同一路线内每次登记与回放都按同一提交导出输入并写入输入身份（<Ref id="J.6.1.3" />），相同提交上的回放才可比。市场库出现新月份时入口只报告可扩展范围（新月份、覆盖到的时刻），不自动换提交；换提交即开发窗口或数据合同的变化，由用户经 <Ref id="E.4.1.1" /> 选择后写成新一条路线记录。新鲜度来自 <Ref id="table:market_schema" /> 与 <Ref id="table:universe_month" />，只是事实，不判数据够不够用。拒绝：没有路线记录时返回空并进入路线选择；该提交下没有任何月份拒绝 MARKET_EMPTY。

## E.2　维护研究状态清单 [#E-2]

研究状态清单 (research state list) 是 Agent 自己维护、只追加的证据包，按市场与开发窗口 (development window) 各一份，每次更新是一个新版本。数据流是单向的：Agent 从账本 (ledger) 读候选 (candidate) 清单、产品读数与研究计数，按 skill 规定写四节内容（当前决定、历史反馈、每次更新的引用与分类、搜索暴露），再以带版本号的包名经账本写入口追加为新证据包；代码只在写入时核内容哈希、拒绝占用保留命名空间与同名不同内容，并保证旧版可按包名、账本提交或标签读回。清单不是产品字段，任何代码判定（资格、检验读数、计数）都不读它；写什么、怎么分节、怎么引用全部由 skill 强制，并由 eval 检验。

<Steps>

<Step>

Agent 按 <Ref id="research-start/SKILL.md#read-state-list" /> 读最新版清单并核哈希，同时读候选清单、研究计数（<Ref id="research-round/SKILL.md#counts-from-code" />）与本次试验的比较读数。

</Step>

<Step>

按 <Ref id="research-round/references/state-list.md#current-decisions" /> 写三类当前决定：推荐与取舍、后续研究动作的优先级与所选父版本及对照、复盘节奏。

<Step>

### E.2.1　内容 [#E-2-1]

两条 skill 能力规定清单的「当前决定」与「历史反馈」两节分别记什么、历史发现怎么定性。输入是候选清单、产品读数、研究计数与 Agent 的诊断；输出是清单新版本中的对应章节。代码不读这两节，也不从中产生优先级或推荐分数。

<Cap id="E.2.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="分开记当前推荐与取舍、后续研究动作的优先级与所选父版本、复盘节奏及其理由">

清单的「当前决定」节分三小节，由 skill 强制，代码不读。输入：全部经济证据可用候选的多维读数（年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释、不确定性，读数来源见 <Ref id="R.5.1.2" />）、研究计数（<Ref id="research-round/SKILL.md#counts-from-code" />）与 Agent 的诊断。输出三小节：(1) 当前推荐 (recommendation)：一版或一批候选（引用名 strategy_id@revision）、依据与取舍，按 <Ref id="research-round/SKILL.md#review-and-recommendation" /> 写；(2) 后续研究动作：按 <Ref id="research-round/references/feedback.md#priority-ranking" /> 排序的具体动作，每条写所选研发父版本 (parent) 与比较对照 (control) 的引用名及各自理由，对照须经济证据可用（<Ref id="research-round/SKILL.md#recommendation-vs-next-parent" />）；(3) 复盘节奏：按尝试次数或进展声明的触发条件、理由，以及上次复盘所到的尝试计数（读自代码，<Ref id="research-round/SKILL.md#review-cadence" />）。三小节互不推出：推荐候选不必是下一实验的父版本；优先级最高的动作不必指向推荐候选；复盘次数只触发复盘，不是停止条件。何时不写：任一小节缺理由、推荐候选没有经济证据可用、父或对照引用名在候选表 <Ref id="table:candidate" /> 中不存在，Agent 不写新版本，先补齐；代码层不拒绝。演练中推荐候选与最新派生版本不同，各写理由。

### E.2.2　存法与版本 [#E-2-2]

清单以固定命名的证据包存入账本，每次更新是一个新包。database 能力由代码强制只追加、内容哈希与版本可读回；skill 能力规定每版引用什么、把内容分成事实、解释与下一假设，并把搜索暴露记全，由 eval 检验。

<Cap id="E.2.2.1" kind="database" tier="verified" tierLabel="已验证" title="按市场和开发窗口各一份，每次更新是新版本的证据包，只追加不覆盖，旧版可按提交或标签读回">

研究状态清单按市场与开发窗口各一份，以证据包存入账本，存于 <Ref id="table:evidence_bundle" />（包头）与 <Ref id="table:evidence" />（文件字节、长度与由字节派生的内容哈希 content hash）。包名即身份：`research_state/<market_commit>/<window_start>_<window_end>/v<version>`，market_commit 与开发窗口取自当前研究路线记录（<Ref id="ledger.current_line" />），version 为十进制整数、每次更新加一。输入：整份清单文件（一个或多个逻辑文件）与包名；输出：账本提交哈希与各文件内容哈希。写入经 <Ref id="ledger.add_bundle" /> 在一个写事务（<Ref id="ledger.write" />）内完成：同名同内容重试幂等返回原记录；同名不同内容拒绝（拒绝码 bundle_name_taken）；包名落在产品保留命名空间拒绝（reserved_namespace）；并发写冲突拒绝（write_conflict），Agent 重读最新版后再写。旧包永不编辑或删除；任一版本从未被改写由 <Ref id="table:dolt_system_tables" /> 的行历史证明。读回：按包名读指定版本并核哈希后导出（<Ref id="cli.evidence_export" />），或经 <Ref id="ledger.read_as_of" /> 按账本提交哈希或标签读当时的最新版；里程碑标签指向账本提交，按标签解析到提交后读回。换市场提交或开发窗口另开一份清单（新前缀从 v1 起），旧清单保留并仍计为历史搜索暴露。由代码与账本强制。演练中以逐版证据包写清单与检查点，旧版按包名与提交读回。

<Cap id="E.3.2.1" kind="skill" tier="verified" tierLabel="已验证" title="附多维读数与诊断：年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释、不确定性">

每个候选选项附一组多维读数 reading 与诊断：年化、最大回撤、夏普、计划胜率、成本、资金使用率 capital utilisation、利润来源拆分（价格盈亏、手续费、资金费）、机制解释，以及不确定性。读数来源有三：年化、回撤、夏普、胜率、成本与利润来源拆分从代码的运行报告 <Ref id="report.run_report" /> 读出，它经资格视图遮蔽并附总体与样本量、读数代码版本、检查身份和局限清单（经济口径见 <Ref id="R.1.1.2" />）；不确定性从代码的比较入口 <Ref id="report.compare" /> 读出，即配对检验的效应、区间、p 与登记时声明的检验条件（显著性水平、最小改进均标为「未校准示例值」），无对照或任一侧不可比时 <Ref id="report.compare" /> 拒绝并只留诊断，选项里照抄诊断；资金使用率由 Agent 按 <Ref id="nautilus-report-analysis/SKILL.md#capital-utilisation" /> 从封存敞口表自算（时间加权名义额、采样峰值、锁定保证金、在市时间），无敞口表不填。每项读数附实质活动 substantive activity 与可比资格 comparability，无资格的候选整体只给诊断。夏普或任何单一指标不单独决定推荐；算不出的项留空并写原因，不估、不补。机制解释写该候选利润来自哪类活动（如趋势持有、资金费收取）与它成立的市场条件，属 Agent 判断，须标为解释。强制层：skill 指导，eval <Ref id="eval:research-round/capital-use-read-from-first-root" /> 校验资金使用率与利润来源从首个有效根起主动读出；代码强制读数遮蔽与比较不裁决。

## E.4　用户选定研究路线 [#E-4]

入口把综合推荐与路线选项交给用户后停下等待，这一步由 skill 强制：选定前不登记、不回放、不发布。用户选定后，Agent 经命令行把选择写成一条研究路线 research line 记录——钉住的市场提交、共同可交易范围规则 universe_rule、开发窗口 development window、起点候选、备注——账本以新版本证据包只追加入账，当前路线即最新版本，旧版本保留可读。选中模板时顺序多一步：先经与所有候选相同的发布入口无父发布为根候选 root，再写路线记录，再在当前窗口登记并回放出首份报告。路线写入后，路线内的每次登记都必须以该路线的窗口与市场提交为准，由登记校验强制；路线内的父版本、对照、假设与下一小批由 Agent 自主决定，不逐项请用户批准，直到需要换路线再回入口。

<Steps>

<Step>

Agent 呈现推荐与路线选项（经济证据可用的候选起点，或符合条件时的策略库模板），以提问结束并等待。

</Step>

<Step>

用户选定一条路线；可附信息源或想法，可一次性明确授权选某个模板。

</Step>

<Step>

</Step>

<Step>

Agent 经 <Ref id="cli.line_select" /> 调 <Ref id="ledger.select_line" /> 写研究路线记录（市场提交、universe_rule、开发窗口、起点候选、备注），账本入账为新版本证据包。

</Step>

<Step>

用户附带的想法写成路线内的一条假设照常登记；模板根在当前窗口无父、无对照登记一次并回放出首份报告。

</Step>

<Step>

</Step>

### E.4.1　选择权 [#E-4-1]

两条能力都由 skill 指导：第一条规定谁提选项、谁选、选定前怎么等；第二条规定用户附带的想法与信息源如何进入路线、一次性授权覆盖多大范围。输入是入口呈现的推荐与选项，输出是用户的一次明确选择及其附件。

<Cap id="E.4.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="路线选项由 Agent 提出，选哪条由用户定；用户选定前等待，不自行开始">

决定权划分：Agent 提出路线选项并附推荐材料（多维读数、历史反馈、取舍），选项是经济证据可用的候选起点；只有在 <Ref id="research-start/SKILL.md#root-options" /> 规定的条件下（账本没有任何候选，或用户明确离开全部路线）才把策略库模板列为选项。选哪条由用户决定。用户选定前 Agent 只等待：不登记、不回放、不发布新候选、不写路线记录，也不把推荐第一名默认当作已选。路线内需要换路线时按 <Ref id="research-round/SKILL.md#route-change" /> 回入口，给诊断与选项、以提问结束并等待；亏损、不显著、运行限制或故障都不是自行开新路线的理由。由 skill 强制（<Ref id="research-start/SKILL.md#user-selects-route" />）；账本侧没有可绕过的入口，因为写路线记录的命令只在用户选定后由 Agent 调用。eval <Ref id="eval:research-start/route-change-waits-for-user" /> 校验换路线时以提问结束。

### E.4.2　选定的结果 [#E-4-2]
