# 市场数据与交易范围

保存合约规格、成交价与标记价 K 线、推算买卖报价、完整源 aggTrades、持仓量与多空比、资金费率、逐月共同交易范围，以及 Binance 与 Bybit 推送的爆仓和记录它们的时段。各表存为市场目录里按内容命名的不可变 Parquet 文件，每个市场版本由一份<Ref id="table:market_version">版本文件</Ref>列出；研究账本另在 Dolt。

[数据库总览](/zh/docs/design-ledger/)

### 版本文件 [#def-table-market_version]

市场的一个版本：一份 JSON，两种形式。起点（带 `market_schema`）列出该版本的全部数据文件和导入回执；增量（没有 `market_schema`）只列出它在父版本之上新加的。<Ref id="market.load_version" /> 从一个版本沿 parent 链读到最近的起点，按先后合成它的完整清单；版本号经 parent 钉住从起点到它的全部内容。市场提交就是版本文件的版本号；登记、路线和 paper 运行记下的 `market_commit` 都是它。

```
<市场目录>/
  files/<sha256>.parquet   数据文件：不可变，按内容命名
  files/<sha256>.json      导入回执：不可变，按内容命名
  versions/<版本号>.json    版本文件，每个版本一份
  head                     最新版本号
  lock                     导入锁文件
```

**键与约束**

- 版本号　版本文件规范 JSON（键排序、`separators=(",", ":")`、UTF-8、不转义非 ASCII）的 SHA-256，按 base32hex（字母表 `0-9a-v`）从高位取前 32 个字符（160 位）
- 只追加　增量只列新加的条目和回执；有父版本的起点原样、在前地列出父版本完整清单的全部 `files` 与 `receipts`，`market_schema` 的价量比例与范围规则与父版本相同
- 不重叠　同一版本里同表同合约的条目区间两两不相交，同表各文件的主键互不重复：写入时新条目与父版本的条目核对（ENTRY_OVERLAP），<Ref id="market.review" /> 逐版本独立复核。时间列不在主键里的表（爆仓两张表按 received_at 分文件），区间不相交推不出主键不重复：写者导入时对已存的行核对，<Ref id="market.review" /> 把各文件的主键放在一起查重
- 数据文件　按表的主键排序、主键严格递增，zstd 压缩，写入参数固定在代码里；读写都用 pyarrow

**存储保证**

- **W.1.3.2**　一次导入先让数据文件和回执落盘，再让版本文件落盘，最后让 `head` 的原子替换落盘：每个文件都写临时文件、`fsync`、改名，再对所在目录（`files/`、`versions/`、放 `head` 的根目录）`fsync`；macOS 上用 `F_FULLFSYNC`（只调 `os.fsync` 不写到盘上）。中途崩溃只留下没被引用的文件，`head` 不变
- **W.1.3.2**　<Ref id="market.read_table" /> 按市场提交读：只读该版本列出的文件，对实际读进来的字节算 SHA-256，对不上即 HASH_MISMATCH；任何时候都重现某次回放读到的内容
- **W.1.3.2**　导入开始时 `head` 的版本文件和它列出的每个文件都要在市场目录里，否则 HEAD_INCOMPLETE
- **J.3.2.2**　一次只有一个导入：导入全程持有 `lock` 的 fcntl 文件锁，第二个导入拒绝 CONCURRENT_IMPORT。fcntl 锁只在共用一个内核的进程之间互斥：市场目录在 Docker 卷上，所有写者（market-import 与任何市场写命令）都在这个 compose 项目的容器里跑，共用 Docker 虚拟机的内核；宿主命令行从不直接写市场目录
- **W.1.3.2**　<Ref id="market.review" /> 由任何读者对任何版本复核：文件都在且哈希对得上、行规则与 <Ref id="market.data_tests" />、同一版本里同表同合约的条目不相交且同表主键不重复、沿父版本链只追加、账本引用的市场提交都在 `head` 的链上（`legacy-20261025` 那两个转换版本除外：它们沿 parent 到 `l1kfbo4…` 全在 CONVERTED 里，其余各项照样核对）、公开副本的 `head` 在本地链上（否则 HISTORY_REWRITTEN）、CONVERTED 里的 8 个版本对得上 `CONVERTED`；只报发现，不改任何东西

**CONVERTED 里的 8 个版本**　账本钉住的 8 个市场提交，版本号是账本钉住的 Dolt 提交号，不由内容算出：`l1kfbo4b2of54ijpjnpn02ijdm175aqd`、`53tgna1pa02hb1t9v6r3h6pqh8d2e1s1`、`gc305h705ocn5fm3lcjjerln283gek2t`、`6ho8evfcea6p4680qbkeo3mdhaqjscp5`、`1kcbv73ptu3l3clg37g0f0k77c370kk8`、`dbnggsrnquf09evsncorvngiuan1br6a`、`pn5bee9mvj18qj1boc5v9b5faotu4ehb`、`iv711v5dpnv5qr62i5ejk3udk431f5k6`。`market/versions.py` 的 `CONVERTED` 写死 \{版本号: 版本文件的 SHA-256\}，<Ref id="market.load_version" /> 读这 8 个版本时核对版本文件的 SHA-256，其余版本核对版本号等于内容算出的号，对不上即 HASH_MISMATCH。`l1kfbo4…` 没有父版本，`53tgna1…`（`legacy-20261025` 的头，加了 BTCUSDT 报价）以它为父版本；main 上的 6 个按提交先后串成父子链。这 8 份版本文件、`CONVERTED_HEAD`（转换来的主线最新版本）及其祖先，和它们列出的全部数据文件都在公开副本里：它们按转换时的切分写成，导入写不出同样的文件。

**公开副本**　Cloudflare R2 桶，公开可读，市场档案的 `origin` 是它的公开地址。它存全部版本文件和回执，instrument、universe_month、bar、funding、binance_force_order、bybit_all_liquidation、liquidation_watch 的数据文件：它们是导入时观测到的（条款、成员，K 线和资金费里有当时从 REST 取的行，记录服务收到的爆仓推送和它在记的时段），过后拿不回来。metrics、agg_trade、quote 的文件不上传，转换来的版本列出的也不传：回执记着每个归档的 SHA-256，按回执重新导入，写出的文件哈希须等于条目的，回执的 writer 指出写它的代码。<Ref id="market.publish" /> 先上传新版本缺的数据文件和回执，然后上传版本文件，都只建不覆盖（`If-None-Match: *`）；最后以条件写替换 `head`（`If-Match` 发布开始时读到的公开副本 `head` 的 ETag），条件不成立即 PUBLISH_DIVERGED，两个发布者因此不会互相覆盖。写入密钥只在写者手里，由档案的 `upload` 指明。有自己可写市场目录的读者（例如没有写者目录的机器上的宿主命令行）缺的文件从 `origin` 取进自己的市场目录（只取上面上传的那些文件），按读到的字节核对 SHA-256，两处都没有即 MARKET_UNREACHABLE；市场目录只读挂载的读者（compose 里的 ide、paper）从不取，缺文件即 MARKET_UNREACHABLE。

### `market_schema` [#def-table-market_schema]

市场自述：整数价量比例、当前产出范围的规则版本；是版本文件里的一个对象，每个版本一份。有哪些表、各表的列由代码的表登记（TABLES）给出，不存在版本里

**键与约束**

- 父子版本的价量比例与范围规则相同；子版本照抄父版本的 market_schema（含旧的 `version`）
- 某版本没有列出一张表的文件时，<Ref id="market.read_table" /> 读为空，导出跳过它；版本列出代码的表登记里没有的表时，<Ref id="market.open_market" /> 拒绝 SCHEMA_VERSION_MISMATCH

**存储保证**

- **W.1.3.2**　随每个版本写在版本文件里，按市场提交读出该版本使用的规则版本与比例
- **W.1.3.2**　<Ref id="market.review" /> 沿父版本链核对它不变（升级的加一除外）
