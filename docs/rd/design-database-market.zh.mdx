# 市场数据与交易范围

保存合约规格、成交价与标记价 K 线、推算买卖报价、完整源 aggTrades、持仓量与多空比、资金费率、逐月共同交易范围。各表存为<Ref id="table:market_directory">市场目录</Ref>里的普通 Parquet 文件；研究账本另在 Dolt。

[数据库总览](/zh/docs/design-ledger/)

### 市场目录 [#def-table-market_directory]

金融数据放在普通 Parquet 文件里，路径说明它装的是什么；没有清单，文件里有什么，市场里就有什么。同样的代码和交易所归档导出同样的数据，Git 里的代码就是文件的来历。

```
<市场目录>/
  <表>/<YYYY-MM>.parquet            bar、funding、universe_month：一个月，全部合约
  <表>/<YYYY-MM>/<合约>.parquet     agg_trade、quote、metrics：一个月，一个合约
  instrument.parquet               合约条款，追加
  lock                             导入锁文件
```

**写入**

- 文件按表的主键排序、主键严格递增，zstd 3 级压缩，写入参数固定在代码里，同样的行写出同样的字节；读写都用 pyarrow。有哪些表、各表的列在代码的 `market/files.py` 的 `TABLES` 里
- 价量比例与规则是代码常量：`series.PRICE_SCALE`、`series.VOLUME_SCALE`、`universe.RULE`、`quotes.RULE`、`aggtrades.CODEC`。改规则时删掉受影响的派生文件重导，同一张表里不混两种
- **W.1.3.2**　`market.write_file` 写临时文件 `.<随机>.tmp` 并 `fsync`（macOS 用 `F_FULLFSYNC`），`market.place` 按固定次序改名到位、`fsync` 所在目录，最新截至日由它推出的文件（bar）最后放：中途崩溃只会少推进，不会让截至日指向不完整的数据
- **W.1.3.2**　已结束月份的 agg_trade、quote 文件不再写。进行中的月份重写：K 线与资金费已有的日子须与来源重读逐行相同，否则 MONTH_EXISTS；名单须与已存行相同，否则 UNIVERSE_CHANGED；metrics 已存的行原样留下
- **J.3.2.2**　一次只有一个导入：导入全程持有 `lock` 的 fcntl 文件锁，第二个导入拒绝 CONCURRENT_IMPORT。fcntl 锁只在共用一个内核的进程之间互斥：所有写者（market-import 与任何市场写命令）都在这个 compose 项目的容器里跑，共用 Docker 虚拟机的内核；锁管不到的写者由 place 核对目标的 inode 与修改时间拦下（同一拒绝码）

**市场提交**　它包含的最后一天 D：`%Y%m%d` 加 24 个 0，如 `20261103000000000000000000000000`，仍是账本 `market_commit` 的 32 位形状（否则 MARKET_COMMIT_INVALID）。按提交读，读到的是：

| 表 | 读到的行 |
|---|---|
| bar、funding、quote、agg_trade、metrics | 时间列在 D 当天及以前 |
| universe_month | 月份不晚于 D 次日所在的月：一个月的名单只取决于它之前的日子，所以月末这一天读得到下个月的名单 |
| instrument | observed_at 在 D 次日结束之前：一天的数据次日导入，条款同时观测 |

main 与 head 指最新的截至日：bar、metrics（在最新月份或它前一个月有文件的合约）各自最后完整的一天里较早的那天，没有行的表不算；没有 K 线就没有最新的截至日。比它晚的日期、其余引用都是 UNKNOWN_REF。登记、路线和 paper 运行记下的 `market_commit` 都是它。回填或晚到的归档可能改动一个截至日的内容，这时复跑导出的指纹对不上，由 REPRODUCTION_MISMATCH 报出。这一天是月末而下个月还没有名单时，退到它的前一天：月末这个提交等下个月的名单写好才可读，它读到的成员因此不会变。

**一份目录**　读者只读本机的文件：文件缺了读为没有这些行。目录丢了，market-import 从交易所归档重算，条款按当时的 exchangeInfo 重新观测。回放读到的内容相同，已封存运行照常能读、复现和比较；观测时刻不进输入身份（docs/plans/input-identity.zh.md）。

**恢复**　见 `deploy/README.md`。

**写入方**　`market.write_file`、`market.place`；空的市场目录由 `market.init_market` 建

**读取方**　`market.open_market`、`market.resolve_commit`、`market.read_table`

### `quote` [#def-table-quote]

保存声明规则从 aggTrades 推算的完整买卖价状态变化；来源是近似报价，不是逐档盘口或真实可成交深度。

**键与约束**

- 主键　`symbol`, `ts`, `agg_trade_id`；读取按 `ts, agg_trade_id` 排序，同毫秒状态不合并。
- 行规则　`bid > 0 AND ask > bid`；`market.write_file` 写入时核对。
- 五列均为 NOT NULL。没有 bid_size／ask_size、档位、逐侧年龄或来源文件列；导出用合约 max_quantity 填两侧数量，不等于实际盘口深度。

**职责与来源**　一个合约一个月一个文件，月份结束后才导入，不再写；不存订单、成交、仓位或账户。规则是代码常量 `quotes.RULE`，改规则删掉文件重导。归档 zip 在下载缓存，不进数据文件。

**写入方**　`cli.market_import_quotes` → `market.import_quotes`，从已存的 <Ref id="table:agg_trade" /> 文件推出，推算由 `market.derive` 负责。同合约同月已有文件时拒绝。

**读取方**　`market.quote_rows` 经 `market.read_table` 按市场提交流式读取，经 `market.write_quotes` 写为原生 QuoteTick，`market.export_episode` 把 `counts.quote`、`quote_size` 写入导出回执；报价环境由 `engine.execution_account` 选择。该提交下区间内没有本表文件时读为空流，默认 K 线导出仍可用；报价环境缺有效报价仍按现有检查拒绝。

**关联与边界**　`symbol` 在应用读取时与 instrument 条款、universe_month 成员及生命周期片段关联，没有外键。推算规则和逐合约／时段／用途的证据边界沿用 <Ref id="W.1.2.1" />，原生强平环境沿用 <Ref id="W.4.2.1" />。

### `agg_trade` [#def-table-agg_trade]

保存币安 USD-M 的完整源 aggTrades：官方七个字段加归档里的 symbol，含没有改变推算报价的成交。它是源交易原件，不参与 K 线、报价读取或周期派生；入口请求成交（`--trade-ticks`）时由 `market.trade_rows` 读出、`market.write_trades` 写成 TradeTick，只作策略信号输入，不驱动撮合。

**键与约束**

- 主键　`symbol`, `transact_time`, `agg_trade_id`；没有二级索引，没有派生列。

**职责与来源**　源交易原件，已结束的合约月一个文件，不再写。前一日归档只做续接核对（编号接上、同样的字段与编码校验），不插入；编号缺失、重复或跨日不连续即 SEQUENCE_GAP，不找替代来源、不修补；唯一例外是币安把同一编号重复给了另一笔更晚的成交，两行主键不同，都导入。

**关联与边界**　`symbol` 在应用读取时与 <Ref id="table:instrument" /> 条款、<Ref id="table:universe_month" /> 成员关联，没有外键。字段与编码的决定见第一阶段记录 docs/plans/aggtrades-source-import.zh.md。
