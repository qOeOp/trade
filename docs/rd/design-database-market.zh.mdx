### `quote` [#def-table-quote]

保存声明规则从 aggTrades 推算的完整买卖价状态变化；来源是近似报价，不是逐档盘口或真实可成交深度。

<TypeTable type={{"symbol": {"type": "VARCHAR(40)", "description": "公开合约名；与同提交条款及生命周期片段对应", "required": true}, "ts": {"type": "BIGINT", "description": "产生此状态的 aggTrade transact_time，UTC 毫秒；允许同毫秒多行", "required": true}, "agg_trade_id": {"type": "BIGINT", "description": "产生此状态的成交编号；区分同毫秒状态并用于来源核对，状态变化筛选后编号不必逐行连续", "required": true}, "bid": {"type": "BIGINT", "description": "推算买价 × 10^market_schema.price_scale；不是观测盘口", "required": true}, "ask": {"type": "BIGINT", "description": "推算卖价，采用同一定标", "required": true}}} />

**键与约束**

- 主键　`symbol`, `ts`, `agg_trade_id`；读取按 `ts, agg_trade_id` 排序，同毫秒状态不合并。
- CHECK　`bid > 0 AND ask > bid`。
- 五列均为 NOT NULL。没有 bid_size／ask_size、档位、逐侧年龄或来源文件列；导出用合约 max_quantity 填两侧数量，不等于实际盘口深度。

**职责与来源**　只追加输入状态，不存订单、成交、仓位或账户。`quote_rule`、实际读取的每日归档 SHA-256（含用于续接的前日）和日诊断读数保存在对应 Dolt 提交消息，由 <Ref id="market.quote_imports" /> 读取，不复制成表字段；市场提交钉住输入版本。归档 zip 在下载缓存，不因有哈希就声称原件已存入此表或完成独立备份。

**写入方**　<Ref id="cli.market_import_quotes" /> → <Ref id="market.import_quotes" />；推算与定标分别由 <Ref id="market.derive" />、<Ref id="market.scaled_rows" /> 负责。一个月一次事务／提交；同合约同月已有报价时拒绝，历史行不覆盖。

**读取方**　<Ref id="market.quote_rows" /> 按市场提交 AS OF 流式读取，经 <Ref id="market.write_quotes" /> 写为原生 QuoteTick，<Ref id="market.export_episode" /> 把 `counts.quote`、`quote_size` 写入导出回执；报价环境由 <Ref id="engine.execution_account" /> 选择。早于该表创建的历史提交读为空流，默认 K 线导出仍可用；报价环境缺有效报价仍按现有检查拒绝。

**关联与边界**　`symbol` 在应用读取时与 instrument 条款、universe_month 成员及生命周期片段关联，DDL 没有为它新增外键。推算规则和逐合约／时段／用途的证据边界沿用 <Ref id="W.1.2.1" />，原生强平环境沿用 <Ref id="W.4.2.1" />。本页记录既有存储，不增加字段或规则。

### `agg_trade` [#def-table-agg_trade]

保存币安 USD-M 的完整源 aggTrades：官方七个字段加归档里的 symbol，含没有改变推算报价的成交。它是源交易原件，不参与 K 线、报价读取或周期派生；入口请求成交（`--trade-ticks`）时由 <Ref id="market.trade_rows" /> 读出、<Ref id="market.write_trades" /> 写成 TradeTick，只作策略信号输入，不驱动撮合。

<TypeTable type={{ "symbol": { type: "VARCHAR(40)", description: "交易所公开合约名（归档文件名所带）", required: true }, "transact_time": { type: "BIGINT", description: "成交时刻，UTC 毫秒；同毫秒允许多行", required: true }, "agg_trade_id": { type: "BIGINT", description: "交易所聚合成交编号；一个合约内逐日、跨日连续，缺失或重复即拒绝", required: true }, "price": { type: "BIGINT", description: "成交价 × 1e8 的有符号整数，编码 binance-aggtrades-int64-scale8-v1，与 market_schema 的 bar 比例无关", required: true }, "quantity": { type: "BIGINT", description: "成交量 × 1e8，同一编码", required: true }, "first_trade_id": { type: "BIGINT", description: "聚合内第一笔逐笔成交编号", required: true }, "last_trade_id": { type: "BIGINT", description: "聚合内最后一笔逐笔成交编号", required: true }, "is_buyer_maker": { type: "BOOLEAN", description: "买方是否为挂单方；推算报价规则据此分买卖侧", required: true } }} />

**键与约束**

- 主键　`symbol`, `transact_time`, `agg_trade_id`；没有二级索引，没有派生列。
- 八列均为 NOT NULL。价格与数量放不进这个编码（精度损失或整数溢出）即整月拒绝 SCALE_LOSS 并回滚，不四舍五入、不换编码。aggTrades 本身不带 RPI 等成交类型标记，表也不另加这类字段。

**职责与来源**　只追加的源交易原件，一个合约月一次事务、一个提交。编码身份、每日归档的 SHA-256、日读数（行数、首末编号与时刻、最大成交间隔）记在导入提交消息里，由读取方从 Dolt 提交读，不复制成表字段。前一日归档只做续接核对（编号接上、同样的字段与编码校验），不插入；编号缺失、重复或跨日不连续即 SEQUENCE_GAP，不找替代来源、不修补；唯一例外是币安把同一编号重复给了另一笔更晚的成交，两行主键不同，都导入。

**写入方**　命令行 `market import-trades --month <YYYY-MM> --symbols <合约> ...`（一个月的一个或几个合约，同时写入、各一个提交）→ <Ref id="implementation:impl-market-aggtrades-py-import_month" />；表由管理员命令 `market upgrade` 补建。持同一导入锁、同一受限导入账号、同样的提交测试与自动发布；同合约月已有行即 MONTH_EXISTS，当月只到最后一个已收盘 UTC 日，之后不能续写。

**读取方**　目前没有产品读取方：K 线与报价导出、回放都不读它；推算报价 <Ref id="table:quote" /> 另从归档推算，不由本表派生。

**关联与边界**　`symbol` 在应用读取时与 <Ref id="table:instrument" /> 条款、<Ref id="table:universe_month" /> 成员关联，DDL 没有外键。字段与编码的决定见第一阶段记录 docs/plans/aggtrades-source-import.zh.md；本页记录既有存储，不增加字段或规则。

### `metrics` [#def-table-metrics]

保存币安 USD-M 每日 `metrics` 归档里的持仓量和三个多空比，每个合约每 5 分钟一行，列名照抄归档。一行描述的是 create_time + 5 分钟那一刻（持仓量与 REST 在该时刻的值逐位一致，2026-10-31 实测），导出时才定可见时刻。

<TypeTable type={{ "symbol": { type: "VARCHAR(40)", description: "交易所公开合约名（归档所带）", required: true }, "create_time": { type: "BIGINT", description: "归档的时间戳，UTC 毫秒，在 5 分钟格点上；不是可见时刻", required: true }, "sum_open_interest": { type: "DECIMAL(38,16)", description: "持仓量，基础资产数量，精确十进制", required: true }, "count_toptrader_long_short_ratio": { type: "DECIMAL(38,16)", description: "头部交易者账户多空比；归档为空时为 NULL" }, "sum_toptrader_long_short_ratio": { type: "DECIMAL(38,16)", description: "头部交易者持仓多空比；归档为空时为 NULL" }, "count_long_short_ratio": { type: "DECIMAL(38,16)", description: "全市场账户多空比；归档为空时为 NULL" } }} />

**键与约束**

- 主键　`symbol`, `create_time`；create_time 必须在 5 分钟格点上，各值不为负。
- 放不进 DECIMAL(38,16) 的值整日拒绝 SCALE_LOSS，不舍入。

**职责与来源**　只追加。每日归档的 SHA-256、每日读数（行数、合并的重复行、各比值的空行数）和没有归档的日子记在导入提交消息里，不复制成表字段。归档的主动买卖量比是成交的合计（已导入成交的合约可从 <Ref id="table:agg_trade" /> 精确算出），持仓价值是持仓量乘交易所的价格快照，两者都不存。

**写入方**　命令行 `market import-metrics --month <YYYY-MM> [--symbols <合约> ...]` → <Ref id="implementation:impl-market-metrics-py-import_month" />；表由管理员命令 `market upgrade` 补建。持同一导入锁、同一受限导入账号、同样的提交测试与自动发布；每个合约月可以分几次导，每次只追加还没有的日子。

**读取方**　`market coverage` 的 `coverage[].metrics`；回放入口给了 `--metrics` 时由 <Ref id="market.metrics_rows" /> 导出，按 `create_time + 10 分钟` 送给策略。

**关联与边界**　`symbol` 在应用读取时与 <Ref id="table:instrument" /> 条款、<Ref id="table:universe_month" /> 成员关联，DDL 没有外键。字段审阅与决定见 docs/plans/binance-open-interest-input.zh.md。

### `universe_month` [#def-table-universe_month]

共同可交易范围 universe：环境按事前规则在每个 UTC 月初产出的成员名单，不排名、不取前 N；后来下架的合约留在当时名单里；成员时间路径由本表按 AS OF 派生

<TypeTable type={{ "universe_rule": { type: "VARCHAR(60)", description: "产出该行的范围规则版本；不同版本的名单共存，旧行不改", required: true }, "month": { type: "DATE", description: "UTC 月初", required: true }, "symbol": { type: "VARCHAR(40)", description: "成员合约的交易所公开名；ticker 重用在导出时按生命周期拆为原生合约", required: true } }} />

**键与约束**

- 主键　`universe_rule`, `month`, `symbol`
- CHECK　`DAYOFMONTH(month) = 1`

**Dolt 能力**

- **W.1.3.2**　随导入在同一提交追加；导入前重算全部月份并与已存行比对，不一致 UNIVERSE_CHANGED 拒绝，旧提交上的名单不被改写
- **D.1.1.1**　dolt_diff_universe_month 只应出现 added；AS OF 重现任一提交的成员时间路径
- **W.3.1.2**　AS OF market_commit 派生范围规则、合约清单与每合约 [start, end) 成员时间路径，进入输入身份
- **X.1.3.1**　样本外绑定时在登记的 market_commit 与本次 market_commit 下逐行比对登记前各月名单
