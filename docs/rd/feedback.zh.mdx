# F　反馈与研究优先级：一个运行封存之后，Agent 怎样读反馈、决定下一步改什么，何时复盘并给出推荐。

本章定义比较证据之后、下一次登记之前的一段：读一个运行（run）的反馈并拆到部件（F.1），据此排研究优先级（research priority）、写下一假设（F.2），按研究计数触发复盘（review）并给出推荐（recommendation）（F.3）。代码只给只读读口（资格、产品读数、配对检验读数、研究计数），口径归 G、R、V 章；判断、排序、推荐由 skill 指导，结果只追加到研究状态清单。代码不设通过门槛、次数停止、方向排除、优化器或推荐分数；换研究路线回入口由用户选。

## F.1　读取反馈：先定资格，再拆部件 [#F-1]

一个运行（run）封存后，Agent 按固定顺序读它的反馈。第一步读资格视图，定这个运行能不能给经济反馈（F.1.1）。可用的运行接着读资金使用率、利润来源与出场拆分（F.1.2）。最后按诊断顺序与五部件判据把事实归类（F.1.3），交给 F.2 排研究优先级。代码只提供四样东西：读时算出的经济证据资格（<Ref id="qualification.assess" />）、产品读数（<Ref id="report.run_report" />）、经资格遮蔽的报告表（<Ref id="report.tables" />）、配对检验读数（<Ref id="report.compare" />），口径由 G、R、V 章定义。何时读、怎么读、怎样归类，由 research-round 与 nautilus-report-analysis 两个 skill 指导。诊断全程只读，不产生成交事实，不写裁决；结论作为自由文本追加到研究状态清单（<Ref id="E.2.1.2" />）。

<Steps>

<Step>

取运行的经济证据资格与原因（<Ref id="qualification.assess" />）；不可用的运行，经济读数已被整体置空。

</Step>

<Step>

不可用的运行分两路：零成交或缺匹配记录只做原因诊断；无效、未完成或预检未过只留修复轨迹，修复后的源码作为新候选重新预检、审查，再另行登记。

</Step>

<Step>

可用的运行读产品读数与报告表：资金使用率、利润来源拆分、入场计划标签 × 出场原因拆分。

</Step>

<Step>

登记声明了比较对照（control）时，读配对检验读数（效应、区间、p 与检验条件）。

</Step>

<Step>

按资格→钱从哪来→过程→稳定性→机制预测五步诊断，用五部件判据归类，事实、未证解释与拟改动部件分开写。

</Step>

<Step>

把反馈记录追加到研究状态清单，进入 F.2。

</Step>

</Steps>

### F.1.1　反馈资格 [#F-1-1]

资格由代码强制：<Ref id="qualification.assess" /> 在读取时按明确的检查身份算出四项结论：实质活动、可比资格、执行捕获、源码审查。任一项不过，<Ref id="qualification.mask" /> 把经济读数整体置空并附原因；报告、报告表、比较与计数共用这一视图。读法由 skill 指导：先读资格，再读任何读数。不可用的运行按成因分两路：零成交或缺匹配记录只做原因诊断（F.1.1.1）；无效、未完成与预检未过只留修复轨迹（F.1.1.2）。输入是一个运行，输出是能否给经济反馈及其原因。

<Cap id="F.1.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="读反馈先读资格视图：零成交只做诊断">

类型 skill：由 <Ref id="research-round/references/feedback.md#availability-first" /> 指导，<Ref id="eval:research-round/zero-fill-is-diagnostic" /> 检验；资格本身由代码强制（<Ref id="G.4.1.1" />、<Ref id="G.4.1.2" />、<Ref id="G.4.2.3" />）。
做什么：Agent 读任何运行的反馈之前，先读该运行的经济证据资格（economic evidence availability）视图。输入是运行；输出是可用或不可用、全部原因与检查身份。运行要给经济反馈，四个条件须同时成立：实质活动（substantive activity：有真实原生成交，并有与之匹配的订单、仓位周期与账户记录）成立；可比资格（comparability）成立；原始执行捕获完整；绑定的独立源码审查未失败。
不可用时：经济读数已被代码置空并附原因，Agent 不从原生文件或别的读口补算。零成交或缺匹配记录的运行只做诊断，按原生订单事件、指标就绪时刻与异常回执把原因归为六类：无信号、指标未就绪、无规则机会、下单未成交、被拒单、异常。这类运行不排在亏损的比较对照之上（账户未变不算优于亏损），不给改善、区间或 p，也不给方向记失败；它作为仅诊断的尝试写进研究状态清单。
拒绝：对无资格运行，报告表拒绝给经济表（NO_ECONOMIC_EVIDENCE）；任一侧无资格时，比较入口拒绝并只留诊断（<Ref id="V.2.3.3" />）。skill 层由 eval 判定：把零成交读成零收益，或与亏损对照比出正效应，即不通过。

做什么：Agent 只记原因、原件引用与修复轨迹，作为历史反馈追加到研究状态清单。不读经济读数（已被遮蔽），不给所选方向记亏损，不给未测方向记失败，不改研究优先级，也不作任何复盘判据的依据；试验次数照计（<Ref id="G.1.2.1" />）。
怎么修复：改过的源码就是新候选（candidate，<Ref id="C.1.1.2" />），按 <Ref id="research-round/references/strategy-authoring.md#precheck-and-review" /> 重新预检，经独立 Agent 审查后才能登记。代码在登记与绑定时拒绝以下情形：
- 网格源码没有通过的预检审查件：拒绝（SOURCE_PRECHECK_REQUIRED）；
- 审查件结论为失败或未定：拒绝（SOURCE_PRECHECK_FAILED）；
- 已消耗的网格点不在原登记下重跑，再次绑定即拒绝（GRID_ALREADY_ATTEMPTED，<Ref id="H.4.2.1" />）；须另行登记，并以 retry_of 指向实际消耗它的先前登记；
- 重用已执行过的源码而不写 retry_of：拒绝（SOURCE_ALREADY_EXPOSED，<Ref id="H.4.2.2" />）。
源码未改的基础设施失败，同样另行登记并写 retry_of。

### F.1.2　读数的读法 [#F-1-2]

代码提供两类数据：产品读数（闭仓利润来源拆分、按平仓年拆分、未平残差，<Ref id="report.run_report" />），以及经资格遮蔽的报告表（订单、成交、持仓、账户、日收益、敞口，<Ref id="report.tables" />）。skill 指导 Agent 何时读，怎样从报告表自算资金使用率与入场标签 × 出场原因拆分，并写进推荐理由。输入是经济证据可用运行的报告表，输出是注明总体与样本量、引用账本提交的描述统计。读数口径由 R 章定义（<Ref id="R.2.3.1" />、<Ref id="R.3.1.1" />），本组件只定时机与用法。

<Cap id="F.1.2.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺从首个有效根起未经追问即报告这两项并写进推荐理由的演练记录。" title="从首个有效根起主动读资金使用率与利润来源">

类型 skill：由 <Ref id="research-round/references/feedback.md#capital-and-profit-source" /> 指导，<Ref id="eval:research-round/capital-use-read-from-first-root" /> 检验；读数与遮蔽由代码强制，读的时机与用法只由 skill 指导。
何时读：从研究路线（research line）里第一个经济证据可用的根节点（root）运行起，每个经济证据可用的运行都主动读，不等用户追问。源码中的仓位或资金预算规则（<Ref id="C.1.4.2" />）一有改动，该改动的运行必读。
读什么：
- 资金使用率（capital utilisation）：时间加权名义敞口、采样峰值、锁定保证金（margin）与在市时间，由 Agent 按 <Ref id="nautilus-report-analysis/SKILL.md#capital-utilisation" /> 从封存敞口表自算；
- 利润来源拆分（profit attribution）：价格盈亏、手续费、资金费（funding）与未平残差，直接读产品读数，不另行自算。
怎么用：两项写进推荐理由，并在反馈记录里引用运行与账本提交。账户收益差要连同两项一起解读（<Ref id="V.4.2.4" />）：资金使用率上升带来的收益差不算规则改善，不以放大仓位代替改善。
拒绝：没有敞口表的运行不回答资金使用率，写明缺失；无资格运行的读数已被遮蔽，不读。

### F.1.3　诊断顺序、判据与边界 [#F-1-3]

全部由 skill 指导，代码不参与归类，账本不存部件字段。输入是 F.1.1 的资格结论与 F.1.2 的读数。Agent 按固定五步诊断（F.1.3.1），用五部件判据把事实归类（F.1.3.2），全程遵守只读边界（F.1.3.3）。输出是一份反馈记录，事实、未证解释与拟改动部件分开写，追加到研究状态清单后交给 F.2。

<Cap id="F.1.3.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="诊断顺序">

类型 skill：由 <Ref id="research-round/references/feedback.md#diagnosis-order" /> 指导，<Ref id="eval:research-round/diagnosis-order-before-hypothesis" /> 检验。
一个登记网格跑完后，Agent 按固定五步诊断，前一步写完才进入下一步：
1. 资格：实质活动与可比资格是否成立（<Ref id="research-round/references/feedback.md#availability-first" />）；不成立就止于诊断或修复，不进第 2 步。
2. 钱从哪来：读利润来源拆分与资金使用率（<Ref id="research-round/references/feedback.md#capital-and-profit-source" />）；登记声明了比较对照时，同时读配对检验读数（效应、区间、p 与检验条件，<Ref id="report.compare" />）。
3. 过程：订单漏斗、入场标签 × 出场原因的贡献（<Ref id="nautilus-report-analysis/SKILL.md#exit-reason-split" />）、持仓时长。
4. 稳定性：收益是否只靠某一个平仓年、少数几天或少数合约（<Ref id="R.2.3.2" />、<Ref id="nautilus-report-analysis/SKILL.md#position-structure" />）。
5. 机制：登记时写下的可反驳预测（<Ref id="H.3.1.1" />）是否相符。
五步走完才提下一假设。每步写明引用的登记、运行与账本提交，事实与解释分开写。缺步或未走完就提假设，eval 判不通过。

<Cap id="F.1.3.2" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺按五部件判据归类的演练诊断记录，以及部件判据可解析的外部依据。" title="五个部件判据">

类型 skill：由 <Ref id="research-round/references/feedback.md#five-components" /> 指导。归类只写进研究状态清单的自由文本，账本不存部件字段，代码不校验归类。
依据恒等式：闭仓净盈亏 ＝ 频次 × 规模 × 单位名义净优势，其中单位名义净优势 ＝ 毛优势 − 手续费 ＋ 资金费（资金费按方向可正可负）。三个因子相乘，所以胜率上升与收益下降可以同时出现，不能单看一个因子。
Agent 用以下判据把诊断事实归入五个部件：
- 毛边际：扣费前不赚，或只靠一个平仓年、少数几天；
- 成本：扣费前为正，被手续费或资金费吃掉；
- 尾部：少数亏损吃掉大部分利润，或回撤相对敞口过大；
- 频率：单笔净优势为正，但计划太少；
- 完整性：审计通过，但独立源码审查或自查发现写法、时钟或保护单问题。
一个事实指向多个部件时，都写出并说明主次。部件是下一项研究动作的类别，供 F.2 定倾向（<Ref id="F.2.2.1" />）；它不是互相独立的利润来源，不按部件分摊盈亏。

### F.2.1　优先级的依据与边界 [#F-2-1]

由 skill 指导，代码不强制。输入是配对比较读数、部件诊断和研究计数，输出是带依据的研究动作排序以及低优先级动作的重评条件，追加到研究状态清单。代码侧只读，不提供排序或排除视图。

<Cap id="F.2.1.1" kind="skill" tier="verified" tierLabel="已验证" title="综合排序下一项研究动作">

Agent 排序的对象是下一项具体研究动作，即一处登记的规则改动及其网格，不是候选的收益名次。排序依据六项：预期效应；不确定性，即 <Ref id="report.paired">配对检验</Ref> 给出的区间、p、块长敏感性与功效近似；机制佐证，即来源证据与诊断是否支持该机制；已探索覆盖，即谱系和研究状态清单里已试过的方向与条件；该动作的信息价值；执行成本，包括预检与回放耗时、网格点数。每条排序写明依据，并引用所读的运行（run）、登记和账本提交。输入只来自产品读数和计数。代码不返回优先级、推荐分数或调度建议，也不运行优化器：排序只借用「预测均值、方差与耗时共同决定下一试验」的思路，判断由 Agent 做。比较入口因无对照、不可比或任一侧无经济证据资格而拒绝的动作，不进入经济排序，只按 <Ref id="F.1.1.2" /> 修复。排序结果写进 <Ref id="research-round/references/state-list.md#current-decisions">当前决定</Ref> 的「下一动作优先级、所选父与对照及理由」，与推荐、复盘节奏分开写，三者互不推出。由 skill 强制，评测用例 <Ref id="eval:research-round/gross-negative-updates-priority" /> 检查毛边际为负时只更新优先级。

## F.3　复盘与推荐：次数触发，研究默认持续 [#F-3]

复盘（review）由计数触发，不终止研究。F.3.1 判断是否到了复盘：代码从账本给出研究计数，Agent 按自己在研究状态清单（knowledge list）里声明的节奏触发。F.3.2 规定复盘的内容：在全部经济证据可用的候选上综合给出推荐（recommendation），并与下一实验的研发父版本（parent）和比较对照（control）分开决定。F.3.3 决定复盘后的去向：路线内继续或调整由 Agent 定，换研究路线（research line）或选新根节点则回入口由用户选。代码只提供计数、候选清单与产品读数这三个只读读口，判断、推荐与去向全部由 skill 指导，结果作为状态清单的新版本经 <Ref id="ledger.add_bundle" /> 只追加入账。

### F.3.2　复盘的内容 [#F-3-2]

由 skill 指导：读代码给出的候选清单与经资格视图遮蔽的读数，在全部经济证据可用的候选上综合推荐并写明取舍；推荐与下一实验的父版本、比较对照分开决定。父与对照能否登记由登记入口在代码里核对。输入是候选清单与产品读数，输出是写进状态清单的推荐及理由。

<Cap id="F.3.2.1" kind="skill" tier="verified" tierLabel="已验证" title="在全部可比候选上综合推荐">

复盘的比较范围是截至当时全部经济证据可用的候选（candidate，引用名 strategy_id@revision），包括历史候选、非最新版本和其他研究路线上的候选。范围从 <Ref id="report.candidates" /> 取：它列出全部候选的源码身份、父与改动、每个登记尝试的运行状态与当前经济证据可用性，不带分数和排序。每个候选的读数从 <Ref id="report.run_report" /> 取：已经过资格视图遮蔽，附总体与样本量和局限清单。Agent 按 <Ref id="research-start/SKILL.md#option-readings" /> 的各维综合比较：年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释与不确定性。读数缺失时写原因，不自行补数。可以按 <Ref id="nautilus-report-analysis/SKILL.md#pareto-range" /> 自算非劣集来描述推荐范围，但非劣集不是资格，也不是排序。输出是推荐一版或一批，写明各维之间的取舍和保留的参考版；不只比最近几版，也不等后续候选研究完。仅诊断与无效的运行另列，不参加推荐。推荐理由作为研究状态清单的新版本经 <Ref id="ledger.add_bundle" /> 追加入账。推荐不等于样本外验证（validation，只由用户发起，见 <Ref id="X.1.1.1" />），也不等于上线。入口呈现推荐（<Ref id="E.3.1.1" />）时引用本条的判据。本条由 skill 指导，代码只给出不带排序的读口，由 <Ref id="eval:research-round/all-comparable-candidates" /> 检验。

### F.3.3　复盘后的去向 [#F-3-3]

由 skill 指导：在用户选定的路线内，继续还是调整由 Agent 自主决定；换路线或选新根时交回用户选。代码在这里强制一点：登记只能绑定当前的路线记录，而新的路线记录只能经 <Ref id="ledger.select_line" /> 写入。输入是复盘结论，输出是继续、调整方向、回入口三者之一及其依据。

<Cap id="F.3.3.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="路线内继续或调整由 Agent 定">

复盘后，在用户选定的研究路线内继续当前方向还是调整方向，由 Agent 自主决定，依据写进研究状态清单。转向看相对研究价值（按 <Ref id="F.2.1.1" /> 综合排序下一项研究动作），不要求证明旧方向价值归零。旧方向按 <Ref id="F.2.1.2" /> 保留：不显著、亏损、零成交、低频都不构成排除（<Ref id="research-round/references/feedback.md#no-exclusion" />）；它的适用条件和重评条件记在状态清单的历史反馈里（<Ref id="research-round/references/state-list.md#history-feedback" />）。路线内的调整不需要用户批准，也不回入口。演练中，路线内的方向由 Agent 自主从规模转到过滤，再回到规模；旧参数在新条件下重评结果不利，但仍保留重评。
