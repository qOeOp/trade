# 11　反馈与研究优先级：一个运行入账之后，Agent 在这里读反馈、定下一步改什么，登记被复盘停点拦下时复盘并给出推荐。

一个运行（一次回放结束后入账的结果）封存之后，前两章给出了检验结果和归因报告。这一章讲 Agent 拿到这些之后怎么做：先看这个运行能不能当证据，再决定下一步研究什么，隔一段就回头复盘一次。做完这一章，就回到第 5 章提下一个假设，循环接着转。

这一章做三件事。第一，读反馈：先查经济证据资格，没有资格的只做诊断或修复，有资格的再看钱从哪来、怎样出场。第二，排研究优先级：给下一项具体改动排先后，写明理由和选定的父版本、对照。第三，复盘：上次推荐以来的研究试验满 5 个，产品就拒绝下一次登记，Agent 在对照表里的全部候选上给一次综合推荐，然后继续研究。代码给只读的事实，并在该复盘时拦住登记；怎么读、怎么判断由 skill 指导，结论逐条写成判断记录入账。

举个例子：一条路线里，某一版把单笔预算从 100 提到 500，结果比对照差，回撤也变大。Agent 先确认它有真实成交、有经济证据资格，再读它的反馈。它不因此排除仓位这个方向，而是可以把下一步排成「按历史资金费方向过滤新入场」。复盘时推荐的也不一定是最新的一版。

### 反馈资格 [#F-1-1]

先看运行有没有经济证据资格；没有的，按原因分诊断和修复两路。

#### 读任何反馈前先查资格，零成交的运行只做诊断 [#F-1-1-1]

Agent 读一个运行的反馈之前，先看它的经济证据资格，结果是可用或不可用，附全部原因和检查身份。要有资格，四条必须同时满足：有实质活动（真的发生了成交，并且订单、持仓和账户记录对得上）；可比资格成立；原始执行记录完整；绑定的独立源码审查没有失败。资格由代码判定，Agent 不能改。

没有资格的运行，绩效指标已被代码置空并附上原因，Agent 不从原生文件或别的地方自己补算。零成交或记录对不上的运行只做诊断：按原生订单事件、指标就绪的时刻和异常记录，把原因归成六类之一（没有信号、指标没就绪、没有符合规则的机会、下了单没成交、被拒单、异常），作为「仅诊断」的尝试写进研究状态，不排在亏损的对照前面，也不给它所试的方向记失败。

#### 无效、没跑完或预检没过的运行只修复，修好后另行登记 [#F-1-1-2]

三种情况适用：完整性审计判为无效的运行；原始执行记录里有失败或没跑完阶段的运行；原生预检（登记前的工程短跑）没通过的源码。Agent 只记原因、原件引用和修复经过，作为历史反馈追加到研究状态。这些记录不读绩效指标（已被遮蔽），不给所选方向记亏损，不改研究优先级，也不当任何复盘判断的依据，但试验次数照算：

1. 记下失败原因、原件引用和修复经过，追加到研究状态；试验次数照算。
2. 改过的源码当作新候选，重新预检，再交给没参与编写的 Agent 审查。
3. 没有通过的预检审查件就登记，会被拒绝（`SOURCE_PRECHECK_REQUIRED`）；审查结论是失败或未定，也会被拒绝（`SOURCE_PRECHECK_FAILED`）。
4. 已经消耗过的网格点不能在原登记下重跑，再次绑定会被拒绝（`GRID_ALREADY_ATTEMPTED`）；要另行登记，用 `retry_of` 指向实际消耗它的那次登记。
5. 在跑过它的合约上重用已经执行过的源码却不写 `retry_of`，会被拒绝（`SOURCE_ALREADY_EXPOSED`）。

### 绩效指标的读法 [#F-1-2]

绩效指标怎么算前面已经讲过，这里先区分候选自身表现、相对变化和收益差的统计支持，再读原生出场原因。

| 要回答的问题 | 读取的证据 | 结论范围 |
|---|---|---|
| 候选自身表现怎样 | 候选指标，连同总体、成本、敞口和局限 | 描述这次运行，不替代相对比较 |
| 相对对照改变了什么 | 可比报告的两侧差值、`pairwise` 值及已登记预测 | 描述变化和方向一致性，不自动证明因果或显著性 |
| 账户收益优势有多少统计支持 | 配对检验的效应、区间、p 和假设 | 只解释登记的账户日对数收益差，不推广为各归因指标的检验 |

机制预测沿用现有比较定义：有专门 `pairwise` 值时读该值，否则读候选减对照的差；`same_sign` 只表示方向一致，不是机制成立或职责合格。指标与职责的关联用于定位待研究的政策，多个职责共享同一指标仍是一项观察，不能据此逐个判好坏。解释机制还须看实际源码差异、敞口、成本与竞争解释。

<a id="F-1-2-2" />

**按入场计划和出场原因交叉拆贡献，出场原因只读原生记录**

对有经济证据资格的运行，Agent 通过 `report.tables` 取持仓周期表，做一张交叉表：每行是一种入场计划标签，每列是一种出场类别。每格给闭仓数和闭仓净盈亏，价格盈亏、手续费、资金费分开列。还没平的仓位单独一行，不并进任何出场类别。

出场类别在封存时只按引擎原生记录定下，也就是平仓单上的标签或订单类型，写在持仓周期里。合约下架时引擎会生成不带标签的平仓单，这类单按 <Ref id="C.5.2.2" /> 的唯一对应规则归属，对应不上就记为「未归属」。如果计划统计因为缺标签、一单多标签或对不上而被置空（<Ref id="C.5.2.1" />），这个运行就不出交叉表，只报原因。交叉表的合计必须等于产品给的闭仓拆分，不相等就不能引用。

## 11.2　更新研究优先级：决定下一步改什么 [#F-2]

Agent 根据反馈给下一项具体改动排先后，写成一条研究优先级判断；代码不排序。

<a id="F-2-1" />

给下一项研究动作排先后看哪些依据，以及哪些结果不能拿来排除一个方向。

### Agent 按七项依据给下一项研究动作排先后，代码不排序 [#F-2-1-1]

排序的对象是下一项具体的研究动作，即一处登记的规则改动和它的网格，不是候选的收益名次。依据有七项：离你两个目标的差距；预期效应；不确定性，即配对检验给出的区间、p 和功效估计；机制佐证，即来源和诊断支不支持这个机制；已经探索过哪些方向和条件；这个动作能带来多少新信息；执行成本，包括预检和回放耗时、网格点数。

每条排序写明依据，并引用读过的运行、登记和账本版本。排序结果写进当前决定里的「下一动作优先级、所选父版本与对照及理由」，和推荐分开写，两者谁也推不出谁。一次不显著或亏损，不说明这个方向永远不行，只该影响先试什么。

### 排第一的动作说明报告依据、受影响政策与待检验解释 [#F-2-1-2]

`priority` 的首位动作说明报告切面或栏目、度量与观察方向，引用运行及账本提交而不复制数值；定位受影响职责，区分已观察的事实与待检验的政策解释。参数选择有报告依据，或明确标为探索，不能由标签代替理由。

## 11.3　复盘与推荐：产品停点触发，研究默认继续 [#F-3]

上次推荐以来满 5 个研究试验，产品就拦住下一次登记（`REVIEW_DUE`），Agent 复盘一次、给出综合推荐；复盘完研究照常继续。

### 复盘的触发与计数 [#F-3-1]

什么时候复盘由产品的固定停点决定，用到的次数一律从账本读。

#### 复盘用的次数一律读账本计数，Agent 不自己数 [#F-3-1-1]

复盘时用到的次数，都从 `report.research_status` 读。它按 <Ref id="V.4.4.1" /> 的口径从账本分项给出：尝试、审计通过、经济可用、仅诊断、无效、没跑完，以及样本外登记状态，并附账本版本。可比候选数取「经济可用」那一项，由资格判定 `registration.assess` 给出；「审计通过」的数不能当成可比候选数。

#### 复盘停点只触发复盘，复盘完继续研究，没有停止规则 [#F-3-1-2]

上次推荐以来，本路线的研究试验满 5 个，产品就拒绝下一次登记（`REVIEW_DUE`）。5 是写在代码里的常数，Agent 不能声明、调高或调低。拒绝信息直接给出下一步：读研究状态里的对照表，写推荐和优先级，推荐一入账，登记就放行。停点只触发复盘，复盘完照常研究，不预设总次数或总预算。

#### 差异连续都分不出来时在线内换个思路，Agent 自己选定并告诉你 [#F-3-1-3]

这条线最近一次换思路之后，连续若干次研究运行的比较都分不出候选和对照，即比较报的四个区间（基本区间 `mean_log_basic_interval`、学生化区间 `mean_log_studentized_interval`、年化差区间 `annual_return_difference_interval`、最大回撤差区间 `max_drawdown_difference_interval`）没有一个排除零，Agent 就在这条线里比较两三个新思路，自己选排第一的，不停下等你。登记它的第一个实验之前，Agent 写一条正文以 `Change of approach.` 开头的 `priority` 判断：列出几个思路的排序和选它的理由，把计入的几次运行作为 `trial` 主体。下一次计数只算这条判断点名的最新 `trial` 之后的运行。任一区间排除零的一次，变好或变差都是分出来的结果，计数从它之后重算。

选新思路时，先从 **5 类瓶颈**（`opportunities` 交易机会数、`signal quality` 信号质量、`costs` 手续费与资金费成本、`capital use` 资金使用率、`tail drawdown` 尾部回撤）诊断当前对照卡在哪一类，再检查本路线**从未改动过的职责**以及对照文件头里仍处于 **`default`（缺省）的职责**：每个新思路要么动一项这几次没动过或仍处缺省的职责（目标效应超过这几次的可检出年化差，并沿用对照的合约和输入），要么**消融一条此前从未单独测过独立贡献的既有规则**。每个思路写明第一个实验和对照、哪种结果会改变下一步、哪些来自来源原文、哪些是 Agent 自己的设计，各带报告读数，标出一项推荐，并在本轮消息里告诉你一次后直接做第一个实验。

### 复盘的内容 [#F-3-2]

复盘时在对照表的全部候选上综合推荐，逐个点名本路线的候选，推荐和下一实验的父版本分开定。

<a id="F-3-2-1" />

**在对照表的全部候选上多方面比较，推荐要点名本路线的每一个**

复盘的比较范围是研究状态里的对照表：本路线开发窗口和范围规则下，全部有经济证据资格的运行，包括旧候选、不是最新的版本和别的研究路线上的候选。表里每个运行附年化、标记价最大回撤、夏普、计划胜率、盈亏平衡费率倍数，以及对等权篮子的 alpha（附标准误）和 beta；并标出它有没有被同一执行身份下别的运行在年化、回撤、夏普三项上全面压过（`non_dominated`）；不带分数和排序。

Agent 从年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释和不确定性几方面综合比较；推荐判断要把表的 `candidates`（本路线的试验和路线起点中有路线执行身份运行的候选）都挂为主体（推荐的挂 `recommended`，其余可挂 `about`），漏一个，代码就拒绝（`RECOMMENDATION_INCOMPLETE`）并列出漏掉的；别的路线上的运行仍在比较范围里，不必点名。回答单指标排行查询（例如「所有策略里夏普最高的是哪个」）用的是 `research runs`，不替代这里的综合推荐。
