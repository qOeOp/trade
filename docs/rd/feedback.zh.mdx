# 11　反馈与研究优先级：一个运行入账之后，Agent 在这里读反馈、定下一步改什么，登记被复盘停点拦下时复盘并给出推荐。

一个运行（一次回放结束后入账的结果）封存之后，前两章给出了检验结果和归因报告。这一章讲 Agent 拿到这些之后怎么做：先看这个运行能不能当证据，再决定下一步研究什么，隔一段就回头复盘一次。做完这一章，就回到第 5 章提下一个假设，循环接着转。

这一章做三件事。第一，读反馈：先查经济证据资格，没有资格的只做诊断或修复，有资格的再看钱从哪来、怎样出场。第二，排研究优先级：给下一项具体改动排先后，写明理由和选定的父版本、对照。第三，复盘：上次推荐以来的研究试验满 5 个，产品就拒绝下一次登记，Agent 在对照表里的全部候选上给一次综合推荐，然后继续研究。代码给只读的事实，并在该复盘时拦住登记；怎么读、怎么判断由 skill 指导，结论逐条写成判断记录入账。

举个例子：全池 RSI 路线里，H06 把单笔预算从 100 提到 500，结果比 H05 差，回撤也变大。Agent 先确认 H06 有真实成交、有经济证据资格，再读它的反馈。它没有因此排除仓位这个方向，而是把下一步排成「按历史资金费方向过滤新入场」，这就是 H07。十轮做完时它复盘推荐的是 H09，不是最新的 H10。

## 11.1　读取反馈：先定资格，再拆到职责 [#F-1]

运行封存后，Agent 先定它能不能当经济证据，再看钱从哪来、怎样出场，全程只读。

<Steps>

<Step>

先读这个运行的经济证据资格；没有资格的，绩效指标已经被代码置空。

</Step>

<Step>

没有资格的运行按原因分两路：零成交或记录对不上的做诊断，无效或没跑完的去修复。

</Step>

<Step>

有资格的运行，读绩效指标和原生报告，看利润来源和出场原因。

</Step>

<Step>

登记时带了比较对照的，再读检验结果。

</Step>

<Step>

带了对照的，读完第 10 章的归因报告再写解释，作为判断追加入账。

</Step>

</Steps>

### 反馈资格 [#F-1-1]

先看运行有没有经济证据资格；没有的，按原因分诊断和修复两路。

#### 读任何反馈前先查资格，零成交的运行只做诊断 [#F-1-1-1]

Agent 读一个运行的反馈之前，先看它的经济证据资格，结果是可用或不可用，附全部原因和检查身份。要有资格，四条必须同时满足：有实质活动（真的发生了成交，并且订单、持仓和账户记录对得上）；可比资格成立；原始执行记录完整；绑定的独立源码审查没有失败。资格由代码判定，Agent 不能改。

没有资格的运行，绩效指标已被代码置空并附上原因，Agent 不从原生文件或别的地方自己补算。零成交或记录对不上的运行只做诊断：按原生订单事件、指标就绪的时刻和异常记录，把原因归成六类之一，即没有信号、指标没就绪、没有符合规则的机会、下了单没成交、被拒单、异常。它作为「仅诊断」的尝试写进研究状态。

零成交时账户纹丝不动，看上去是「零收益」，比亏损的对照还好。拿它去比，会得出一个假的正效应。所以这类运行不排在亏损的对照前面，不给改善幅度、区间或 p，也不给它所试的方向记失败。

<div className="rd-example">

一次早期的 BTC/ETH 演练里，H06 和 H10 都是零订单、零成交，报告却照样给出 100000 的权益和零收益，H06 和亏损的根比较，还得出了正的账户差和 p。按这条规定，报告表会拒绝给这类运行出经济表（NO_ECONOMIC_EVIDENCE）；只要有一侧没有资格，比较也会拒绝，只留诊断。Agent 把零成交读成零收益，或者拿它和亏损对照比出正效应，评测就判不通过。

</div>

#### 无效、没跑完或预检没过的运行只修复，修好后另行登记 [#F-1-1-2]

三种情况适用：完整性审计判为无效的运行；原始执行记录里有失败或没跑完阶段的运行；原生预检（登记前的工程短跑）没通过的源码。Agent 只记原因、原件引用和修复经过，作为历史反馈追加到研究状态。

这些记录不读绩效指标（已被遮蔽），不给所选方向记亏损，不给没测的方向记失败，不改研究优先级，也不当任何复盘判断的依据。但试验次数照算。

运行坏了是工程问题，不是策略结论。拿坏掉的运行当反馈，会把一次故障误当成「这个方向不行」。修好后另行登记，才能让每个网格点只被消耗一次，试过几次也查得清。

<div className="rd-example">

比如某次回放因为数据读取出错中途退出。Agent 修了源码，修过的源码就是一个新候选，要重新预检、经另一个 Agent 审查后才能登记。如果源码没改、只是运行环境出了故障，同样要另行登记，并用 retry_of 指向之前那次登记；故障出在产品代码里，就先修好并合并到 main 再重试。根在首份报告之前的修复不带父版本，没有消耗过登记就不写 retry_of。

</div>

1. 记下失败原因、原件引用和修复经过，追加到研究状态；试验次数照算。
2. 改过的源码当作新候选，重新预检，再交给没参与编写的 Agent 审查。
3. 没有通过的预检审查件就登记，会被拒绝（SOURCE_PRECHECK_REQUIRED）；审查结论是失败或未定，也会被拒绝（SOURCE_PRECHECK_FAILED）。
4. 已经消耗过的网格点不能在原登记下重跑，再次绑定会被拒绝（GRID_ALREADY_ATTEMPTED）；要另行登记，用 retry_of 指向实际消耗它的那次登记。
5. 重用已经执行过的源码却不写 retry_of，会被拒绝（SOURCE_ALREADY_EXPOSED）。

### 绩效指标的读法 [#F-1-2]

绩效指标怎么算前面已经讲过，这里先区分候选自身表现、相对变化和收益差的统计支持，再读原生出场原因。

| 要回答的问题 | 读取的证据 | 结论范围 |
|---|---|---|
| 候选自身表现怎样 | 候选指标，连同总体、成本、敞口和局限 | 描述这次运行，不替代相对比较 |
| 相对对照改变了什么 | 可比报告的两侧差值、`pairwise` 值及已登记预测 | 描述变化和方向一致性，不自动证明因果或显著性 |
| 账户收益优势有多少统计支持 | 配对检验的效应、区间、p 和假设 | 只解释登记的账户日对数收益差，不推广为各归因指标的检验 |

机制预测沿用现有比较定义：有专门 `pairwise` 值时读该值，否则读候选减对照的差；`same_sign` 只表示方向一致，不是机制成立或职责合格。指标与职责的关联用于定位待研究的政策，多个职责共享同一指标仍是一项观察，不能据此逐个判好坏。解释机制还须看实际源码差异、敞口、成本与竞争解释。

例如，在同一可比窗口内，对照净亏 100 USDT、候选净亏 40 USDT，应同时说明“少亏 60 USDT”和“候选仍亏损”；收益差的不确定性另读配对检验，少亏本身不证明所改职责有效。缺少可比对照时，只能描述候选自身，不能用绝对值代替相对改善。代码继续提供事实和预测方向，不新增职责评分、阈值或资格条件。

<a id="F-1-2-2" />

**按入场计划和出场原因交叉拆贡献，出场原因只读原生记录**

对有经济证据资格的运行，Agent 通过 <Ref id="report.tables" /> 取持仓周期表，做一张交叉表：每行是一种入场计划标签，每列是一种出场类别。每格给闭仓数和闭仓净盈亏，价格盈亏、手续费、资金费分开列。还没平的仓位单独一行，不并进任何出场类别。

出场类别在封存时只按引擎原生记录定下，也就是平仓单上的标签或订单类型，写在持仓周期里。合约下架时引擎会生成不带标签的平仓单，这类单按 <Ref id="C.5.2.2" /> 的唯一对应规则归属，对应不上就记为「未归属」。

一笔亏着平掉的仓，可能是止损，也可能是中性退出或合约下架。按盈亏正负、价格高低或离止损止盈多远去猜，会把它们混在一起，拆出来的结论就不可信。只读平仓单本身的记录，才是引擎实际发生的事。

<div className="rd-example">

比如一笔仓位亏损 30 USDT 平掉，平仓单标签是「中性退出」，它就记在中性退出这一列，不因为亏了就算作止损。如果计划统计因为缺标签、一单多标签或对不上而被置空（<Ref id="C.5.2.1" />），这个运行就不出交叉表，只报原因。交叉表的合计必须等于产品给的闭仓拆分，不相等就不能引用。

</div>

## 11.2　更新研究优先级：决定下一步改什么 [#F-2]

<Steps>

<Step>

<Step>

<Step>

<Step>

</Step>

<Step>

回到第 5 章提假设，登记之后才回放。

</Step>

</Steps>

<a id="F-2-1" />

给下一项研究动作排先后看哪些依据，以及哪些结果不能拿来排除一个方向。

### Agent 按六项依据给下一项研究动作排先后，代码不排序 [#F-2-1-1]

排序的对象是下一项具体的研究动作，即一处登记的规则改动和它的网格，不是候选的收益名次。依据有六项：预期效应；不确定性，即配对检验给出的区间、p、块长敏感性和功效估计；机制佐证，即来源和诊断支不支持这个机制；已经探索过哪些方向和条件；这个动作能带来多少新信息；执行成本，包括预检和回放耗时、网格点数。

每条排序写明依据，并引用读过的运行、登记和账本版本。排序结果写进当前决定里的「下一动作优先级、所选父版本与对照及理由」，和推荐分开写，两者谁也推不出谁。

一次不显著或亏损，不说明这个方向永远不行，只该影响先试什么。代码只给绩效指标和计数，不返回优先级、推荐分数或调度建议，也不跑优化器；排序只借用「预期效果、不确定性和耗时一起决定下一个试验」的思路，判断由 Agent 做。

<div className="rd-example">

全池 RSI 路线里，H02 改用原生限价退出，结果不如 H01，Agent 仍从它派生出 H03（120 秒撤单重报）；H06 放大预算比 H05 差，仍接着做 H07。另外，比较因为对照运行不存在、不可比或有一侧没资格而被拒绝的动作，不进入这里的经济排序，只按 <Ref id="F.1.1.2" /> 去修复。评测会检查：比较结果的毛边际为负时，Agent 只更新优先级，不排除方向。

</div>

### 排第一的动作说明报告依据、受影响政策与待检验解释 [#F-2-1-2]

priority 的首位动作说明报告切面或栏目、度量与观察方向，引用运行及账本提交而不复制数值；定位受影响职责，区分已观察的事实与待检验的政策解释。参数选择有报告依据，或明确标为探索，不能由标签代替理由。

优先级综合效应、不确定性、机制支持、既有探索、信息价值与成本，说明决定排序的理由；信息价值在于能区分竞争解释，而不是重复多少指标或标签。

## 11.3　复盘与推荐：产品停点触发，研究默认继续 [#F-3]

上次推荐以来满 5 个研究试验，产品就拦住下一次登记，Agent 复盘一次、给出综合推荐；复盘完研究照常继续。

<Steps>

<Step>

每次登记前，代码数上次推荐以来本路线的研究试验；满 5 个就拒绝登记（REVIEW_DUE）。

</Step>

<Step>

没满就接着登记下一个实验；被拒就复盘。

</Step>

<Step>

复盘时读研究状态里的对照表，在表里全部有经济证据资格的候选上比较，给出推荐并写明取舍。

</Step>

<Step>

推荐（点名对照表里每个候选）和下一步优先级（含下一实验的父版本和对照）各写一条判断入账；推荐入账后登记放行。

</Step>

<Step>

要换研究路线或选新的根，就给出选项并提问，由你来选。

</Step>

</Steps>

### 复盘的触发与计数 [#F-3-1]

什么时候复盘由产品的固定停点决定，用到的次数一律从账本读。

#### 复盘用的次数一律读账本计数，Agent 不自己数 [#F-3-1-1]

复盘时用到的次数，都从 <Ref id="report.research_status" /> 读。它按 <Ref id="V.4.4.1" /> 的口径从账本分项给出：尝试、审计通过、经济可用、仅诊断、无效、没跑完，以及样本外登记状态，并附账本版本。Agent 引用这些分项、解释它们的含义；不自评进度，不自己数尝试次数，也不按会话里的记忆计数。

可比候选数取「经济可用」那一项，由资格视图 <Ref id="qualification.assess" /> 判定；「审计通过」的数不能当成可比候选数。

审计通过只说明记录自洽，不代表真有交易可比。拿它当可比候选数，会把零成交的运行也算进去。这个读口只读，不返回停止标志、目标或分数，所以没有拒绝码：代码保证数字是事实，解释是否走样由评测检查。

本条是“账本提供计数，Agent 负责解释”的工程选择，依据是本产品的实现与演练记录。身份未列明的“三篇 Agent 自评预印本”不作为依据，也不据此声称论文证明了研发效果或校准了复盘次数。文献引用须对应可核查的来源及具体主张，不能仅凭预印本身份判断其证据强弱；现有复盘次数、skill 和检查不变。

<div className="rd-example">

一次早期演练里，研究计数只按「运行通过」统计有效运行，零成交的运行也被算成有效，之后改为按资格视图计数。全池 RSI 路线到收尾时，账本里有 67 次试验，其中只有 11 次绑定了正式研究运行（含根）；复盘时要按这些分项说话，不能说成「跑完了 67 次」。

</div>

#### 复盘停点只触发复盘，复盘完继续研究，没有停止规则 [#F-3-1-2]

上次推荐以来，本路线的研究试验满 5 个，产品就拒绝下一次登记（REVIEW_DUE）。5 是写在代码里的常数（没校准过的示例值），Agent 不能声明、调高或调低；判断里也没有复盘节奏这一种。拒绝信息直接给出下一步：读研究状态里的对照表，写推荐和优先级，推荐一入账，登记就放行。

停点只触发复盘，复盘完照常研究。不预设总次数或总预算，没有任何「试满多少次就停」的规则。

研究是不停的循环，但不能一直跑新试验不回头看。复盘时机写死在代码里，而不是让 Agent 自己声明节奏：自己定的节奏可以定得很宽，也可能忘了执行，硬停点不会。反过来，按次数叫停研究，会把「还没找到」误当成「这个方向没救」，所以停点只拦登记、不结束研究，研究计数里也没有停止字段；复盘后接着做由 skill 指导、评测检验。

<div className="rd-example">

全池 RSI 演练跑十轮，只是因为你给的测试长度是十次，不代表方向已经试尽。你设的运行限制（时长、次数、花费）到了，只会让执行暂停：账本里的登记和还没消耗的网格点都保留，恢复后接着做，不能据此判定方向无效。

#### 推荐连续不变、差异都分不出来时就该换线，交给你选 [#F-3-1-3]

推荐版本连续若干次研究运行都没变（次数与 REVIEW_DUE 的固定次数相同），而且这几次比较的 `mean_daily_log_difference` 都落在各自的 `detectable_mean_log_difference_80pct_normal_approx` 以内，Agent 就停止登记线内变体，经 research-start 把这条线连同其他选项交给你选，等你回答。

交给你选就是走 research-start 的列线：先读账本（`candidate list`、`research state` 里的最新推荐），把这条线和账本里其他候选能起的线一起列出，各带报告读数；Agent 自己想到的线内新范围或新起点只是其中几项，不能代替这份列表。

条件只用已经发生的事实：推荐有没有变、每次差异是否小于可检出差。早先的写法是「线内已没有任何改动能超过可检出差」，那是对还没跑的实验下结论，Agent 永远无法确认，所以从来不触发。换线由你选，不是 Agent 宣布方向无效；它也不按次数或预算叫停（<Ref id="F.3.1.2" />）。

### 复盘的内容 [#F-3-2]

复盘时在对照表的全部候选上综合推荐并逐个点名，推荐和下一实验的父版本分开定。

<a id="F-3-2-1" />

**在对照表的全部候选上多方面比较，推荐要点名每一个**

复盘的比较范围是研究状态里的对照表：本路线开发窗口和范围规则下，全部有经济证据资格的运行，包括旧候选、不是最新的版本和别的研究路线上的候选。表里每个运行附四项度量，即年化、标记价最大回撤、夏普、计划胜率，并标出它有没有被表里别的运行四项全面压过；不带分数和排序。每个候选更多的绩效指标从 <Ref id="report.run_report" /> 取，已经按资格遮蔽，附样本量和局限。

Agent 从年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释和不确定性几方面综合比较；指标缺的写原因，不自己补。推荐一版或一批，写明各方面的取舍和保留哪几版作参考。推荐判断要把表里每个候选都挂为主体（推荐的挂 recommended，其余可挂 about），漏一个，代码就拒绝（RECOMMENDATION_INCOMPLETE）并列出漏掉的。仅诊断和无效的运行另列，不参加推荐。

只比最近几版，会漏掉早先更好的版本；等后面的候选都研究完再推荐，又永远等不到。范围由代码算、点名由代码查，Agent 就没法只比自己挑的几版。推荐也不是样本外验证，那只由你发起（<Ref id="X.1.1.1" />），更不是上线。

全池 RSI 十轮复盘推荐的是 H09，不是最新的 H10：H10 用了更多资金，净收益反而更低（年化 3.65% 对 4.24%），回撤也从 8.44% 升到 12.05%；同时保留 H08 作为小规模的参考版。对照表里的非劣标记只描述推荐范围，它不是资格，也不是排序。入口呈现推荐时（<Ref id="E.3.1.1" />）引用这里的判据。
