# 5　提假设：每次回放之前，先想清楚改什么、凭什么、预计会怎样，再把这些写下来锁进账本。

提假设夹在策略文件和回放之间。第 3 章的候选谱系给出能从哪一版改起，第 4 章的原生预检和独立源码审查确认候选能跑；这一章决定这一次具体改什么、拿什么来比，并在回放之前把这些写死。

这一步做四件事。先界定假设：选父版本和对照，把改动收成一处规则。再查来源：先读已有的，缺什么再检索，原件入账。然后写下五样：理由和预测、来源、检验条件、网格、适用条件。最后登记：代码把这些和执行身份一起锁进账本，回放开始时再核对一遍。怎么想、怎么写由 skill 指导；锁定和核对由代码强制。

举个例子：一个候选的父版本是加了资金费过滤的上一版，改动只有一处，把单笔预算从 500 降回 100。对照不必用父版本的运行，可以选同样 100 预算、不带过滤的另一版。这些都在回放之前登记好，回放开始时代码逐项核对，对不上就不跑。

## 5.1　界定一个假设 [#H-1]

回放前的第一步：选好从哪一版改、拿什么来比，并把改动收成一处规则。

<a id="H-1-1" />

从谱系里定下父版本、对照和改动的范围。

### 谱系里任何一个完整候选都能当父版本，不看推荐和成绩 [#H-1-1-1]

研发父版本，就是这次要在它基础上改的那一版。谱系里任何一个完整候选都可以，不限于当前推荐的、最新的或成绩最好的；亏损、不显著、只作诊断的有效候选也照样能派生。选父版本的理由写进登记，和选对照的理由分开写。

推荐和检验结果说的是哪一版眼下最好，不是哪一版还值得改。用成绩卡派生资格，有潜力的方向会因为一次失利被提前放弃。代码只在登记时核对父版本是账本里已发布的候选（否则拒绝，`REGISTRATION_INVALID`），不评价它的成绩；选亏损候选作父版本时，Agent 也不用请示、不用质疑它的资格。

### 对照和父版本分开选，必须已通过、已封存、有资格、可比 [#H-1-1-2]

比较对照是拿来和本次结果配对比较的一个已有运行，不必是父版本的运行。它的状态必须是通过并已封存，有经济证据资格，而且和本次回放可比：运行环境、账户配置、输入数据都相同。根不带对照；父版本的研究运行全部出故障或零成交时可以暂时没有对照，但要引用那份诊断，登记时产品按账本里的运行核对。换了运行契约就开新一代账本，研究以根重新开始，旧候选的思路写进理由。

比的对象不可比，差异就分不清是改动带来的还是环境、账户或数据不同带来的。这几项由代码在登记和绑定时核对，不合就拒绝，不靠 Agent 自觉。

### 一个假设只改一处规则，网格各点以同一句改动说明发布 [#H-1-1-3]

一个假设只含一处实际的规则改动：网格每个点的候选都以同一句改动说明发布，登记从候选取这句话存为 `change`，登记体不再重写一遍（各点父版本或改动说明不一致会被拒绝，`LINEAGE_MISMATCH`）。改选币范围（排名、前 N 个、信号筛选、调整频率）、改仓位和资金预算，也都算规则改动。受影响的几个职责可以属于同一个联动政策。由已有规则推出来的量、没启用的方法的参数，不算改动。

一次改好几处，结果变了也说不清是哪一处的功劳。方向模糊时，Agent 要先把它收束成机制、一处改动、预测、网格和适用条件再登记，而不是先跑一遍父版本看结果再调。

### 从相关策略政策与证据提出可检验假设，登记受影响职责 [#H-1-1-4]

27 项职责声明用于定位策略政策、缺省选择与适用范围。选择假设时围绕当前证据检查相关政策及其依赖，说明一个实际规则改动能区分哪些解释，并在 `changed_duties` 声明受影响职责；不要求每轮重列全部候选的职责清单。登记时代码硬对账：每个格点候选的文件头相对父版本改动的职责行（增删一行也算）必须正好是 `changed_duties`，否则拒绝为 `DUTY_HEADER_MISMATCH`。

职责编号定位改动范围；缺省或未探索本身不证明增加规则有价值，参数选择仍需证据或明确标作探索。

## 5.2　先查来源并留存 [#H-2]

写理由之前先查来源：读已有的、补检缺口、逐份读，原件入账后登记才能引用。

### 检索 [#H-2-1]

把要改的机制变成检索记录和一份候选来源清单。

#### 提经济假设前先读已留存的来源，只为缺口另行检索 [#H-2-1-1]

提经济假设之前，Agent 先读账本里已经留存的来源证据包；机制和适用条件仍然相符的，直接引用，只针对机制上的缺口补检。查哪类来源、怎么查按 `research-sources` 的规定：同一个问题至少换三种说法、至少查两个索引，只引用能解析的 DOI 或 arXiv。可信实践优先找认得出的原作者、官方研究材料或能看到的代码，并记下位置、日期和实际看了什么。产出是检索记录和一份候选来源清单。

先读已有的，避免每次重查、各查各的。工程修复（策略构造、订单接口、因果时钟）不需要盈利论文，依据是引擎的技术文档和原生预检。

#### 每次检索记一行；说没找到，只能说按这些查询没找到 [#H-2-1-2]

每次检索在检索记录里写一行：索引名、查询原文、过滤条件、命中数、查询日期、读到哪一层（只有题录、摘要还是全文），以及访问限制（没有密钥、401/403、配额用完）。同一项工作在几个索引都命中时合并成一条，保留各索引的标识。检索记录作为文件，随来源证据包一起入账。

检索有范围，访问也会失败。只写「没有相关研究」就把查询的局限说成了事实。所以否定的话只写「按这些查询没找到」，附上查询和日期；访问失败或全文读不到，记为检索限制，不等于没有先前研究。期刊和出版社的付费文献常常另有作者或机构公开的版本，先找它，再向用户要文件。

### 理由三分类与来源的作用 [#H-2-2]

理由分三类，分类只是写在登记里的文字，代码不读，只影响研究优先级。

#### 经济理由逐条标为外部依据、本地诊断或自身推测 [#H-2-2-1]

每条经济理由标成三类之一：外部依据，即别人的研究；本地诊断，即本路线运行里看到的事实；自身推测，即 Agent 自己的猜想。外部依据要写出处位置、市场、窗口、频率、成本和验证条件，并说明它支持的是机制、具体的规则参数，还是只有方法；没读到的条件写「未知」。外部依据一栏总写两者之一：针对所改机制的引用（DOI、arXiv 编号或网址），`sources` 列出存有原件的来源证据包；或者按 `research-sources` 的写法说明所列查询在哪里查了什么、找到了什么，`sources` 列出存有那份检索记录的证据包。不针对所改机制的引用等于没有依据；没找到也写在外部依据里，不挪进本地诊断。写策略的模型可能从训练数据里记得开发窗口的价格、资金费和事件；「记得这段时间怎么走」既不是外部依据，也不是本地诊断，不能当理由。

三类分不开，就会把一句猜想或一份模板出处当成论文背书。代码不解析分类，也不设分类字段，只在外部依据非空而 `sources` 为空或所引包不在账本时拒绝（`SOURCES_REQUIRED`）。

#### 来源只影响研究优先级，不证明在本市场有效，事后材料只追加 [#H-2-2-3]

来源只进入研究优先级里的「机制佐证」一项，不进入审计、资格或检验结果。没有论文的方向照样可以低优先级探索；不按引用数排名、不设引用门槛、不因缺来源关闭方向。出处要记版本或日期，只有登记之前就能看到的版本算事前依据。回放后才找到的材料，另开一个带日期的新证据包追加，原登记和原分类不改。

### 留存来源原件 [#H-2-3]

代码保证登记引用的证据包都在账本里；包里放什么由 skill 规定。

#### 来源原件登记前要先入账成证据包，所引的包不在就拒绝登记 [#H-2-3-1]

证据包是按包名入账的一组材料。来源入账的是原件副本、摘录和检索记录，不只是一个链接；入账走 Agent 写证据的唯一入口 `cli.evidence_add`。证据包只增不改，后来补到的材料另开新包。登记时，代码逐个核对所引用的包名都已在账本里，缺一个就拒绝。

链接会失效，网页会改版，只留链接日后就核对不了当初读的是什么。账本的提交历史还能给出来源和登记谁先谁后，据此可以核对哪些算事前依据。

#### 每份来源记状态和条件；撤稿不算，复述不算独立来源 [#H-2-3-2]

读每份来源时记下：状态（期刊、工作论文、预印本还是学位论文）、市场、窗口、频率、有没有样本外检验、有没有扣成本、依据在哪一页哪一节哪张表或图；只读到摘要的标「仅摘要」。这些记录和原件放进同一个来源证据包，供写外部依据时说明支持范围。已撤稿的不算来源；同一工作的预印本、工作论文和期刊版合并成一条，引用发表版；别人对同一工作的复述不算独立来源。

## 5.3　写下五样 [#H-3]

把理由与预测、来源、检验条件、网格、适用条件这五样写进登记。

### 经济理由与预测 [#H-3-1]

理由和预测写进登记，随登记一起锁定。

#### 理由写清机制、谁在付钱和代理；预测要能被回放结果否定 [#H-3-1-1]

经济理由说清三件事：什么市场机制带来这笔收益；谁在付钱，也就是对手方是谁、转移的是谁的成本；为什么这个机制在本路线的共同可交易范围和开发窗口里仍应存在。机制依赖回放输入里没有的量时，写明用什么代理以及代理的局限。预测写改动的职责在度量目录某个切面度量上的变化方向，以及预计体现在哪些成交或持仓特征上。

「会赚钱」「表现更好」这类说法怎么都否定不了，不算预测；只有能被结果否定的预测，回放才真正检验了点什么。预测按归因切面（报告里固定的拆法）上的标量写，每项改动的职责至少一项，结构见 <Ref id="P.2.1.1" />。代码只核对理由和预测都是非空、长度有限的文本，不合就拒绝（`REGISTRATION_INVALID`），不评价写得好不好；登记后两者随登记一起锁定。

#### 回放前写定五类结果各自的下一步，事后不改写 [#H-3-1-2]

Agent 在预测里同时写一份结果到行动的对照：改善、不显著、亏损、零活动（没有实质交易，只留诊断）、无效（完整性审计不通过），每类一句话，写出现这种结果时后续研究怎么做、研究优先级怎么变。可选的动作有沿这个方向细化、换对照、修复后重试、降低优先级并写明什么时候重新评估。

结果出来后再决定怎么解读，很容易把不利结果说成「这个方向不行」。对照表回放前就随登记锁定；回放后按它更新优先级，不能根据结果改写，也不能把不利结果改成排除整个方向。

### 检验条件 [#H-3-2]

检验用的数值由 Agent 声明并写明理由，随登记锁定。

<a id="H-3-2-2" />

**检验条件随登记声明并锁定，数值只是没校准过的示例**

检验条件是登记时声明的比较方式。Agent 写明检验方法、显著性、最小改进、块长、重抽次数和随机种子，另写设计理由：误判和漏检怎么权衡、样本有多长、块长为什么这么选。数值由 Agent 按情境选，不是产品常数，登记后不改。结果出来后再挑检验方法和门槛，就可以把任何结果说成显著。代码只查各项是否齐全、类型和范围对不对，不评价数值合不合理。

### 网格与适用条件 [#H-3-3]

网格定这次试什么，适用条件定结论在什么范围内成立。

<a id="H-3-3-1" />

**网格一次写定一到五个点，每个点都是已发布、谱系一致的候选**

网格是这次登记要试的那几个版本。每个网格点都是账本里的一个候选，附上全部参数的文字说明；每个点的父版本必须和登记一致、改动说明彼此相同，根登记时各点都没有父版本。每个点要求的运行环境必须和登记时探测到的一致，同一份源码不能出现两次。试过的配置不写进网格，就等于偷偷多试了几次，最后只报好看的那个；所以每个试过的配置都要写进网格，点数计入试验次数。

## 5.4　登记先于回放并锁定 [#H-4]

登记先于回放：代码先校验登记体、职责头差异与前置门禁，再探测运行环境并导出市场数据锁进账本；回放开始时在同一事务里再核对并绑定网格点。

### 登记身份与先后顺序 [#H-4-1]

登记写定内容和执行身份；回放开始时核对先后顺序和是否一致。

#### 登记把假设的全部内容锁进账本里不能改的一行 [#H-4-1-1]

登记就是回放前把假设锁进账本：`research_registration` 表里的一行，有假设的各项内容、检验条件、对照，以及每个网格点的审查引用，并写明改动涉及的职责编号：根为空，派生至少一项。网格里的源码必须已在该运行环境下通过原生预检和独立源码审查。登记写入后不改，每次读回都核对内容哈希；要改，另行登记。

#### 执行身份在登记时由代码探测合成，不能手填 [#H-4-1-2]

执行身份是一次回放用的源码、运行环境、账户与撮合配置、输入数据这几样的身份。它在登记时由代码探测出来，随登记写入；登记的窗口必须等于研究路线的开发窗口。这些身份要是能手填，就没法保证回放跑的和登记写的是同一套东西。

1. 先核对登记字段、谱系一致性和父子职责头差异（`DUTY_HEADER_MISMATCH`），不合格在导出市场数据前直接拒绝。
2. 读所选的研究路线：开发窗口、钉住的市场日和范围规则；路线已关闭就拒绝。
3. 把运行环境解析成唯一的摘要，在隔离容器里探测它的要求和配置。
4. 按路线钉住的市场日导出一份不可变的输入，算出内容身份，合成执行身份随登记一起写入。

#### 启动引擎前，要在开试验的同一事务里绑定登记 [#H-4-1-3]

试验是每次回放开始前先写进账本的一条记录。开试验时，代码在同一个事务里读回登记并重新校验，全部通过才把这次回放绑到一个网格点上，记下一次消耗，和试验一起提交。提交成功才启动引擎，任何一项不符就整笔撤销、不留试验：

1. 先写试验记录，同一事务里读回登记并重新校验。
2. 核对所跑的源码在网格内，执行身份和登记逐项一致。
3. 核对登记所属的路线仍开着、预检和审查仍然有效、登记早于试验、这个网格点没用过。
4. 全部通过就记下这次消耗，和试验一起提交；提交成功才启动引擎。

#### 登记内容按字段说明校验，失败时附上该字段的含义 [#H-4-1-4]

登记内容的每个字段都带一段说明。校验失败时，代码把出错字段的说明原样放进拒绝信息里，Agent 不必靠 skill 记住每个字段的含义，看拒绝信息就知道该怎么改。

#### 下一次登记前，要先补齐解释和到期的复盘 [#H-4-1-5]

复盘是回看全部可用候选、给出推荐。下一次登记前代码核对两件事：每个已完成的试验都有一条解释判断（无效、且已被本路线另一个登记以 `retry_of` 重试的运行除外）；上次推荐以来本路线的研究试验满 5 个时，已经写了新的综合推荐。5 是产品常数 `REVIEW_EVERY`，Agent 不能声明、调高或调低。研究状态会提前列出下一次登记还缺什么。复盘时机为什么写在代码里见 <Ref id="F.3.1.2" />。

### 网格点消耗与已跑源码 [#H-4-2]

每个网格点只能用一次，已经回放过的源码不能当新的来登记。

#### 每个网格点只用一次；同一源码再试要另行登记并指明前一次 [#H-4-2-1]

网格点是一次登记里列出的待试候选之一。绑定成功就记下一次消耗，和试验同时成立、同时撤销；之后回放无效或中断，照样算用掉了一次。同一份源码想再试，要另行登记，并指明实际用掉它的那次登记（`retry_of`）。无效或中断就不算数的话，可以一直重跑到出现好看的结果为止。

#### 回放过的源码不能当新的登记，只有事前声明的预检例外 [#H-4-2-2]

登记时，代码按内容哈希查试验记录：一次试验在本次登记要交易的某个合约上封存了研究者能读到的这份源码的经济结果，源码就算在这些合约上跑过，不能当新候选登记；只在别的合约上跑过不算，没记下合约的试验算在每个合约上。没登记就跑过的回放，也不能事后补成登记结果。没有可读结果或结果已经计入的试验不算：同一登记与它的再试链上的尝试；没有封存经济结果的预检（即策略收到任何行情之前就失败，或交易窗口不超过 7 天、封存原件完整而零成交零持仓、没有被登记消费）；登记所引的原生预检（事先声明用途，同一源码、同一运行环境，交易窗口不超过 7 天且未绑定任何登记）；以及与上述某次试验逐字节相同的已验证复现。跑过的源码只能按再试的规则另行登记。
