# 12　样本外验证：用户发起的一次性检验：你认可一个候选之后，可以在一段登记之后才开始的新行情上，把它只跑一次，照实看结果。

样本外验证不在研究循环里。研究循环里的每一次回放都用开发窗口，也就是路线规定的那段历史行情；Agent 在这段行情上反复改、反复比，结果难免带着「挑过」的痕迹。样本外验证是另一回事：你看完报告、认可了某个候选，再决定要不要拿一段它从没见过的新行情检验一次。它沿用第 5 章的登记方式和第 8 章的绩效指标，但研究循环的任何一步都不等它。

这一章做两件事。先是发起、登记与准入：由你指定验哪一版、用哪段窗口、在哪个合约范围里跑；登记写进账本，并请外部机构盖一个时间戳，证明这份计划在那一刻已经存在；窗口必须在登记之后才开始；回放前代码逐项核对，一次登记只换一次回放。然后是报告结果：代码按和开发报告相同的口径给出绩效指标和区间，不下裁决；Agent 照实转述，写明这些数字的局限，立即交给你判断。

举个例子：全池 RSI 路线最后推荐了 H09，它在开发窗口（2025-10-09 至 2026-10-07）上年化 4.24%。演练里没有做过样本外验证。比如你认可了 H09，想再看看它在新行情上表现如何，就要先登记一段从登记之后才开始的窗口，比如三个月；等这三个月过完、新数据入库，才能跑一次，结果无论好坏都原样报给你。

### 发起与选择 [#X-1-1]

谁发起、窗口怎么建议，由 skill 指导。

#### 样本外验证只由你发起，产品和研究循环都不会自动触发 [#X-1-1-1]

你在报告里认可某个候选后，Agent 问你要不要做样本外验证，并说明它检验什么、不检验什么，然后停下来等你指定。产品不会自己登记或回放；研究循环的任何一步都不以它为前提。结果出来后，Agent 再来找你（见 <Ref id="X.2.1.4" />）。

要不要验、验哪一版，是看完报告后的判断，属于你。让 Agent 或产品自己发起，就会在你还没认可的时候消耗掉一段新行情。

### 登记与窗口准入 [#X-1-2]

登记锁住验什么，窗口必须在登记之后才开始。

#### 样本外回放前先登记入账，并取一份公共时间戳凭证 [#X-1-2-1]

登记锁定四样：被验候选、共同可交易范围、窗口和检验条件（显著性、块长等检验数值）。登记入账后，系统把它所在账本版本的哈希交给公共时间戳机构，换回一份凭证。登记只追加不改；取凭证失败时登记仍在，但必须在窗口开始前补取（<Ref id="cli.ledger_witness" />）。

凭证由外部机构签发，证明这份计划在某一时刻之前已经存在，事后没法倒填。它只证明「存在过」，不证明这是唯一的计划。

<div className="rd-example">

比如 10 月 20 日登记验 H09，账本把这次登记所在版本的哈希发给时间戳机构，只发哈希、不发内容，拿回一份写着签发时间的凭证。要是那天网络不通，取凭证失败，登记照样留在账本里，在窗口开始之前补取一次就行。

</div>

#### 样本外窗口必须在登记凭证的时间之后才开始 [#X-1-2-2]

登记时，窗口起点不晚于登记时间，就拒绝。回放前代码再核一次：最初登记没有可验证的凭证，或者凭证时间不严格早于窗口起点，也拒绝；失败重试沿用最初登记的时间边界。

这份凭证只提供最初登记先于窗口起点的外部时间证据，不能单独证明研究者没有提前接触数据、没有登记其他方案或没有重复使用窗口。开发窗口、候选身份、绑定消耗与重试限制按各自检查核对，不能归功于时间戳。取证失败须在窗口开始前补取；错过后保留记录，另选未来窗口，不降级为本机时间证明。

### 一次性与一致性 [#X-1-3]

一次登记只换一次回放，回放必须和登记逐项相同。

#### 一次登记只能绑定一次回放，一绑定就算用掉 [#X-1-3-1]

登记和这次回放的试验在同一笔写入里绑定，第二次绑定会被拒绝。回放中断、运行无效或者没有实质活动，登记也同样算用掉了。只有三种情况可以另行登记重试：中断了且没有产出运行、运行无效、运行没有经济证据资格；重试的候选、窗口、范围规则与检验设计必须和最初登记相同，成员核对和账户基准也沿用最初登记。

允许一段窗口跑多次，就能一直跑到结果好看为止，样本外就失去了意义。

<div className="rd-example">

比如 H09 的样本外回放跑到一半机器重启，没有产出运行，可以按原来的候选、窗口和范围另登记一次重试。要是它完整跑完、亏了 2%，这不是重试的理由，结果不好看就是结果。

</div>

#### 样本外回放必须和登记逐项一致，否则整笔撤回、不启动 [#X-1-3-2]

回放启动前，代码逐项核对四类事：运行环境是正式自动构建、按摘要钉死的，源码是登记的那一版；范围规则不变，最初登记前各月的成员名单不变，窗口内的成员没有被剔除；交易落在登记窗口内，回放在窗口结束后才发起，每个合约的输入数据覆盖齐全；账户配置和最初登记提交中这个候选最近一次通过的研究回放相同，后来的研究运行和重试登记不能替换这个基准。

只要有一项悄悄变了，结果就分不清是策略本身的表现，还是换了环境、范围或账户带来的差别。核对不过就整笔撤回，回放根本不启动，避免白白用掉一次登记。

未执行的登记遇到正常补齐或修正行情，只要仍满足原登记的范围、覆盖和其他准入条件，就按原登记执行一次，不为数据修正另开一次验证；保留新旧市场提交与修正证据。已绑定后仅按 <Ref id="X.1.3.1" /> 的失败条件重试；已有经济证据的成功结果，不因数据修正获得再次正式验证的机会，原结果与修正影响都照实披露。

主分支更新不自动作废登记，也不强制改用新镜像。确需换镜像时，Agent 先按 <Ref id="J.5.3.2" /> 做原生配对，结论只覆盖实际对照；撮合、保证金等实质条款改变，或无法证明兼容，就停止旧验证，由用户另定新的未来窗口。停止原因通过现有证据与判断追加记录，注明登记编号、账本提交、相关市场提交及镜像身份；不改删登记，不新增作废状态，也不自动释放其预留窗口。成员、账户和正式构建检查由代码执行；镜像兼容判断、修正说明及停止后的交接由 skill 负责，不宣称已有自动兼容裁决。

### 绩效指标 [#X-2-1]

代码只读账本，算绩效指标、区间和校正，不下裁决。

#### 样本外报告与开发报告同口径；没有资格就留空，不下裁决 [#X-2-1-1]

绩效指标从绑定的那次封存运行读出，口径和开发报告相同。运行没有经济证据资格时，绩效指标整体留空，只留原因和诊断。报告还列出登记内容、最初登记的凭证及所属登记和提交、审计状态，以及这个候选的全部样本外登记。重试保留自身的 retry_of，但展示实际准入所依据的最初凭证；verified 只表示凭证验签成功，不是准入或研究结论。

口径一样，你才能把样本外的数和开发窗口的数放在一起看。报告只读账本、不写账本，也没有通过、裁决或推荐这类字段，判断留给你。

<div className="rd-example">

比如 H09 的样本外运行有经济证据资格，报告就给出年化、最大回撤、夏普、计划胜率等，栏目和开发报告一样。要是这次运行没有经济证据资格，这些数全部留空，只写原因和诊断。资金用了多少，也在这次运行的单运行报告里，和开发报告同口径。

</div>

#### 用窗口内每天的账户收益，给出均值和夏普的区间与 p [#X-2-1-2]

代码取窗口内交易段的账户日收益，按日历日排，不缺不重；做不到就留空。报告给出平均日收益和年化夏普的观测值、区间、单侧 p，以及换一个块长后这些数怎么变。这里的均值和夏普按日对数收益算（零基准，按 365 天年化），区间只对应这两个统计量；栏目里与开发报告同口径的全程夏普（<Ref id="X.2.1.1" />）按日简单收益算，两个夏普数值不同，不能把这里的区间套到那个数上。

#### 同一窗口登记了多个候选，就按候选个数校正 p [#X-2-1-3]

窗口和范围规则都相同的样本外登记算作一组，一起计入校正的个数。计入哪些只看账本里的登记，事后不能增减。报告把原始 p 和校正后的 p 并列，区间也按个数放宽，不判通过。

同一段窗口试多个候选，总会有一个碰巧好看。不按个数把 p 调大，就会把运气当成本事。

#### 样本外结果照实报告、立即找你，认不认可和上不上线由你判断 [#X-2-1-4]

样本外结果不论好坏，Agent 都照实报告，绩效指标只作分析，报告一出来就找你。它不因为结果不利换窗口或范围再登记，不在同一候选的多次样本外登记里挑着报，也不拿开发窗口的指标顶替样本外指标。

结论定稿前，由未参与本次策略及结论编写的第二个 Agent 独立复读一次。材料限定为登记、账本提交、正式样本外报告及结论引用到的开发报告；先据证据形成判断，再核对草稿是否遗漏不利结果、未知项或模型限制，是否超出窗口与统计支持。不给整段研发讨论或作者解释，也不把新开会话当成已证明完全隔离。

原始结果仍立即披露；复读未完成或暂不可用时说明结论待复读，不宣称已获独立确认。出现分歧就保留争议、修正解释，不换窗口、不重跑来求一致。复读检查文字解释，不改变产品资格，也不构成第二份独立市场证据；产品已算指标不重算，自算补充统计继续按 <Ref id="R.1.2.3" /> 独立复算。

样本外只有一次机会，挑着报或换着跑，就又回到了在数据上反复试的老路。代码只保证一次登记一次绑定（<Ref id="X.1.3.1" />）和窗口晚于凭证（<Ref id="X.1.2.2" />），其余靠 skill 规定、评测用例检查。

<div className="rd-example">

比如 H09 样本外三个月亏了 1%，Agent 照实写「样本外窗口内年化为负」，马上交给你。报告本身已经列出这个候选的全部样本外登记，挑不了。同一窗口只在既有中断、无效或无经济证据条件下重试；修复什么缺陷、改变哪些数据或环境都须写清，不能因亏损另跑。

### 读结果的边界与用语 [#X-2-2]

结论里要写明哪些局限、用什么措辞，由 skill 规定。

#### 样本外绩效受执行模型与窗口限制，短窗口不能证实高收益 [#X-2-2-1]

样本外回放仍由引擎模拟，解释须读取正式报告中的实际执行环境与局限：K 线与报价环境的输入、撮合和强平边界不同，见 <Ref id="W.4.2.1" />、<Ref id="W.5.1.2" />。不把 K 线路径或成交量假设套到报价环境，不推定报告未提供的订单方式或统一偏差方向。短窗口只能反驳明显失败，不能证实高收益；窗口能分辨的效应缺少依据时保留未知。

夏普估计的误差随窗口变长才变小；要达到某个把握最短需要多长的记录，取决于目标夏普和收益分布的偏度、峰度，本产品和 skill 都不算这个长度，也不要求 Agent 给出。样本内的夏普对样本外几乎没有预测力，所以结论不能只看一个数。

<div className="rd-example">

Agent 在结论里写出窗口有多长、能分辨多大的效应，分辨不了的留未知，不凭空给一个最短记录长度；折扣夏普按 `nautilus-report-analysis/references/ratios.md` 给出范围，不给单值。结果是正的，只写「未被否定」。H09 开发窗口的闭仓净利约 4050 USDT，其中约 1976 来自资金费，将近一半；所以样本外结论也要把回撤、成本、利润来源和资金用量并列写出来。

</div>

#### 开发比较用于探索，本产品样本外只认凭证之后的窗口 [#X-2-2-2]

本产品的正式样本外只使用登记凭证之后开始、并满足既有登记与绑定条件的窗口。开发窗口内比较出来的进步属于开发观察，推荐不等于独立验证；不能仅凭这些结果声称泛化或没有过拟合。正式样本外结果也只能在其窗口和执行模型下照实解释。

开发窗口的数据 Agent 已经反复看过、挑过，在上面跑得好，说明不了它在新行情上也好。用词不严，就会把开发窗口的成绩当成已经验证过。

已有的其他历史时段或同期标的，可以通过现有探索回放检查稳健性、比较机制、发现失效条件和提出新假设，不必等待未来窗口。报告说明候选、测试方案、窗口与标的的选择理由及已知数据暴露，保留结果和局限；未在某段数据上运行过策略，不等于策略设计未受其影响。结果好看也不事后改名为样本外，不进入正式样本外登记链路。

本产品不引入“降级的样本外”类别。这是当前可审计的产品口径，不意味着所有历史数据都已污染，或任何历史数据隔离设计都不能支持独立验证；当前产品没有历史留出数据的隔离及暴露证明机制。既有未来窗口与公共时间戳检查保持不变。
