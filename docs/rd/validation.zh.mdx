# X　样本外验证：用户发起的一次性检验：样本外验证由谁发起，怎样登记与准入，怎样一次性回放并照实报告。

本章定义样本外验证（out-of-sample validation）：用户在报告里认可一个候选（candidate）后，用一个在登记（registration）凭证之后才开始的市场窗口回放一次，照实报告与开发报告同口径的读数（reading）和一次性区间，不出裁决。代码与账本强制四件事：回放前登记并取 RFC 3161 凭证、窗口起点晚于凭证、一次登记只绑定一次回放、回放与登记一致，读数和区间也由代码算。发起、窗口长度建议、结果用语由 skill 指导。样本外验证不是研发循环的步骤；读数口径以 R 章为准，凭证与运行环境以 J 章为准。

## X.1　发起、登记与准入 [#X-1]

三个组件按固定顺序衔接，前一步的输出是后一步的输入。发起与选择（X.1.1）全由 skill 指导：用户在报告里认可某个候选后，Agent 询问是否做样本外验证（out-of-sample validation），先披露该候选开发读数的集中度与资金使用率并给窗口长度建议，由用户指定被验候选、窗口与共同可交易范围。登记与窗口准入（X.1.2）由代码与账本强制：登记写入账本并对登记所在提交取 RFC 3161 凭证，窗口起点必须晚于登记时间与凭证时间。一次性与一致性（X.1.3）由代码与账本强制：窗口结束、交易所数据导入新的市场提交后，经唯一回放入口跑一次，子进程启动前在同一事务里绑定登记并逐项核对，一次登记只消耗于一次回放。已存在的数据不进这条链，只能用于探索或反驳。

### X.1.1　发起与选择 [#X-1-1]

全部由 skill 指导：发起、被验候选、窗口与范围都由用户决定，Agent 只提供披露与窗口长度建议。输入是候选报告与研究状态，输出是用户的指定：候选 strategy_id@revision、窗口、共同可交易范围。

<Cap id="X.1.1.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺一次由用户发起并走完登记、回放、报告的演练记录。" title="只由用户发起">

样本外验证只由用户发起，属于用户看报告后的判断（<Ref id="A.2.3.2" />），不是研发循环的必经步骤。用户在报告里认可某个候选（candidate）后，Agent 询问是否做样本外验证，并说明它检验什么（凭证之后才开始的市场窗口上同口径的读数与一次性区间）、不检验什么（不给裁决，不证明实盘表现）；然后停下等用户指定。产品不自动登记或回放；研发循环的任何步骤都不以样本外验证为前提；综合推荐（recommendation）不等于验证，推荐候选也不自动成为被验候选。结果出来后由 Agent 找用户（<Ref id="A.3.2.2" />）。由 skill 强制：<Ref id="research-round/references/validation.md#user-initiated" />，eval <Ref id="eval:research-round/validation-user-initiated" /> 校验。

### X.1.2　登记与窗口准入 [#X-1-2]

代码与账本强制：登记内容写入 validation_registration 并对登记所在提交取凭证，窗口起点必须晚于服务器登记时间（登记时核）与凭证时间（绑定时核），否则拒绝；已存在数据的用法由 skill 指导。输入是用户指定的候选、窗口、范围与声明的检验条件，输出是带服务器时间与公共时间戳凭证的登记。

<Cap id="X.1.2.1" kind="database" tier="verified" tierLabel="已验证" title="回放前登记并取公共时间戳凭证">

样本外回放之前，在账本（ledger）写一行 <Ref id="table:validation_registration" />：被验候选（strategy_id、revision，精确源码身份经 <Ref id="table:candidate" /> 的内容哈希确定）、共同可交易范围身份（登记时的市场提交 market_commit 与 universe_rule；登记前各月的成员时间路径由 <Ref id="table:universe_month" /> 按该提交 AS OF 派生，不另存快照）、窗口 [window_start, window_end)、声明的检验条件（declared test conditions，形态由 <Ref id="registration.validate_design" /> 校验，数值为未校准示例值），可选 retry_of。写入只经 <Ref id="registration.validation_register" />，一次登记恰一个账本提交（<Ref id="ledger.write" />）；created_at 由服务器触发器写（<Ref id="J.4.1.1" />）。提交后经 <Ref id="ledger.witness" /> 把登记所在提交的哈希送公共时间戳机构，取得的 RFC 3161 凭证存入 <Ref id="table:witness" />；只发送哈希，不发送登记内容。取凭证失败时登记仍在，可在窗口起点前补取。这是预登记（preregistration）：凭证证明计划在 genTime 时已存在，不证明它是唯一的计划。登记行只追加，dolt_diff 出现非 added 行即篡改发现；<Ref id="table:dolt_tests" /> 的提交校验核非重试登记 window_start 晚于 created_at，作为留痕保证。

样本外窗口起点必须晚于登记凭证的 genTime，分两处由代码强制：登记时 <Ref id="registration.validation_register" /> 在写事务内读回服务器写入的 created_at，非重试登记的 window_start 不晚于它即回滚并拒绝（REGISTRATION_TOO_LATE）；绑定时 <Ref id="registration.validation_bind" /> 经 <Ref id="ledger.stamped_at" /> 离线验证登记提交的凭证，无凭证或 genTime 不早于 window_start 即拒绝（REGISTRATION_TOO_LATE）。重试登记（retry_of）不再核本次写入时间，准入沿用原登记的凭证时间。用户入口是命令 <Ref id="cli.validation_registration" />。凭证之后才开始的窗口在登记时数据尚不存在，这一条同时排除三种情况：与候选谱系（lineage）开发暴露数据的重叠、开发时跑过的运行事后充作验证、已用于验证的窗口再次登记；因此不需要暴露表或「已用于验证」标记。其他拒绝：候选不存在（CANDIDATE_UNKNOWN）、窗口起点不早于终点（WINDOW_INVALID）、检验条件不合形态（DESIGN_INVALID）、重试条件不满足（RETRY_NOT_ALLOWED）。

### X.1.3　一次性与一致性 [#X-1-3]

代码与账本强制：validation_binding 以登记为主键，一次登记只绑定一次回放；回放走唯一回放入口，子进程启动前在同一事务里写试验行并由 registration.validation_bind 核对，源码、范围、窗口、凭证、账户条款、运行环境任一项与登记不一致即整笔回滚。输入是登记 ID 与本次回放的源码、市场输入与运行环境身份，输出是绑定的试验行与之后入账的运行。

<Cap id="X.1.3.1" kind="database" tier="unverified" tierLabel="待验证" tierNote="缺一登记一回放与重试条件在账本上的实际拒绝记录。" title="一次登记绑定一次回放">

一次登记只绑定一次回放：<Ref id="table:validation_binding" /> 以 registration_id 为主键、trial_id 唯一，由 <Ref id="ledger.open_trial" /> 与试验行在同一事务写入；第二次绑定主键冲突即拒绝（REGISTRATION_CONSUMED）。登记一经绑定即消耗：回放被中断、完整性审计判为无效，或 <Ref id="qualification.assess" /> 判为无实质活动（substantive activity）时，登记同样已消耗，运行只留诊断，不出读数。修复环境缺陷后，以 retry_of 另登记同一候选、同一窗口、同一范围规则；只有原登记绑定的试验中断无运行、运行无效或无经济证据资格时才允许（否则 RETRY_NOT_ALLOWED），准入沿用原登记的凭证时间。结果有效但不好看不是重试理由，也不得换窗口或范围再登记（<Ref id="X.2.1.4" />）。相同源码在新身份下重放另成登记（<Ref id="D.2.1.1" />）。<Ref id="table:dolt_tests" /> 的提交校验核绑定试验的源码与窗口符合登记、重试登记与原登记同候选同窗口，作为留痕保证。

## X.2　报告结果 [#X-2]

样本外回放的运行封存并绑定登记后，由代码出样本外报告：<Ref id="cli.validation_report" /> 调用 <Ref id="report.validation_report" />，读登记、凭证时间与绑定状态，经同一经济证据资格视图取与开发报告同口径的读数，对窗口内账户日收益跑单序列循环块自助区间，同一窗口有多个候选登记时加 Holm 校正；报告只读账本、不写账本，没有裁决字段。代码强制口径、资格遮蔽与检验族成员；Agent 按 skill 照实转述、写明边界并立即找用户，用语受限：开发窗口内的结果只叫改善，样本外读数只是模拟成交下的实盘上限。认不认可、上不上线由用户看报告判断。

### X.2.1　读数 [#X-2-1]

读数、区间与校正由代码算（<Ref id="report.validation_report" />、<Ref id="report.single" />、<Ref id="report.holm" />），只读封存运行与登记；照实报告与找用户由 skill 指导。输入是样本外登记标识与可选账本版本，输出是带登记身份、凭证时间、绑定状态、资格与局限的报告，不含裁决。

<Cap id="X.2.1.1" kind="code" tier="unverified" tierLabel="待验证" tierNote="缺样本外报告的实际产出，以及它与开发报告口径的逐项对照。" title="与开发报告同口径的读数">

命令 <Ref id="cli.validation_report" /> 以样本外登记标识 registration_id 和可选账本版本 at 为输入，调用 <Ref id="report.validation_report" /> 输出样本外报告。报告从绑定的封存运行读出与开发报告同口径的读数：年化（<Ref id="R.2.1.1" />）、标记价（mark price）回撤（<Ref id="R.2.2.1" />）、夏普（<Ref id="R.2.1.2" />）、计划胜率（<Ref id="R.2.1.3" />）、成本，以及利润来源拆分（价格盈亏、手续费、资金费，<Ref id="R.2.3.1" />）；全部经与开发报告同一的经济证据资格视图（<Ref id="G.4.2.3" />）遮蔽，资格不可用时经济读数置空只留原因与诊断，不拒绝出报告。资金使用率不由代码给，报告只给封存敞口表读口，由 Agent 按 <Ref id="R.3.1.1" /> 自算后并列。报告同时列出登记内容（候选 strategy_id@revision、窗口、共同可交易范围规则 universe_rule、检验条件、retry_of）、凭证时间与验证结果、绑定试验与审计状态、同一候选版本的全部样本外登记，并附账本提交、读数代码版本与局限清单；未绑定时只返回登记与凭证部分并记「未绑定」局限。报告不写账本，没有裁决、通过或推荐字段。拒绝码：REGISTRATION_NOT_FOUND（登记不存在于所读版本）、LEDGER_CORRUPT（绑定引用的试验或运行缺失，或登记内容哈希不符）、VERSION_UNKNOWN（at 解析不到提交或标签）。由代码强制。

<Cap id="X.2.1.2" kind="code" tier="verified" tierLabel="已验证" title="日净收益均值与夏普的一次性区间">

<Ref id="report.single" /> 对样本外窗口内交易段的账户日收益序列（由 <Ref id="ledger.daily_returns" /> 取得，UTC 日历日、无缺无重、复利到期末权益）做单序列循环块自助（circular block bootstrap）：报日对数收益均值与年化夏普的观测值、基本区间、嵌套学生化区间，块长半倍／一倍／两倍的敏感性，以及均值不大于零的单侧 p。显著性水平、块长、重抽次数、种子是登记时声明的检验条件（字段与配对检验相同，由 <Ref id="registration.validate_design" /> 校验），随 p 与区间一起呈现并标「方法示例值，未校准」；p 是原假设下的尾概率，不是策略有效的概率。序列缺日、不足两个完整块或含非有限值即不可用（COMPARISON_UNAVAILABLE），报告中 single 置空并写原因，不以其他区间替代；检验条件不合法即 REGISTRATION_INVALID。只返回读数，不返回裁决。由代码强制。

<Cap id="X.2.1.3" kind="code" tier="verified" tierLabel="已验证" title="多候选同一窗口的 Holm 校正">

窗口起止与 universe_rule 都相同的样本外登记构成一个检验族（Bonferroni / Holm 校正对象），族成员只由账本中的登记行决定，事后不能增减。<Ref id="report.validation_report" /> 取族内每个成员绑定运行的原始单侧 p，交 <Ref id="report.holm" /> 得 Holm 逐步校正 p；报告同时给原始 p 与校正 p，无 p 的成员（未绑定、资格不可用或序列不可用）校正 p 为空并照列。区间覆盖按族大小 m 以 Bonferroni 调整（覆盖率 1−alpha/m）并注明 Holm 不对应单一区间。p 列表为空或含越界值即 COMPARISON_UNAVAILABLE。不做任何通过判定。由代码强制。

### X.2.2　读结果的边界与用语 [#X-2-2]

全部由 skill 指导：样本外读数的物理边界（模拟成交、短窗口）与可用的措辞。输入是样本外报告与开发报告，输出是写给用户的结论段。

<Cap id="X.2.2.1" kind="skill" tier="verified" tierLabel="已验证" title="边界：实盘上限与短窗口">

skill research-round 的 <Ref id="research-round/references/validation.md#limits" /> 指导：样本外回放的成交仍由引擎按撮合模型模拟（缺省假设为限价触及即成交、无滑点），读数只是实盘表现的上限，结论段须写明这一点。短窗口只能否定明显失败，不能证实高收益：夏普估计的标准误随窗口长度缩小，达到给定置信所需的最短记录长度随目标夏普与收益分布的偏度、峰度变化；Agent 按 <Ref id="nautilus-report-analysis/SKILL.md#deflated-sharpe" /> 自算最短记录长度，并在结论段写出窗口长度与可分辨效应。正结果只写「未被否定」。样本内夏普对样本外几乎无预测力，结论不以单一维度下，回撤、成本、利润来源与资金使用率并列。评测用例 <Ref id="eval:research-round/short-window-refutes-only" /> 校验。

## 待定事项 [#X-pending]

**待用户定**

- **回溯窗口（开发暴露外的历史时段、同期其他标的）能否登记为降级的样本外**　只认凭证之后开始的窗口，已存在数据只作探索或反驳（<Ref id="X.1.2.3" />）；若允许降级登记，需另立准入规则与分级用语。
- **独立复读是否在本章留一句**　读数由代码算，通则见 <Ref id="R.1.2.3" />；若用户要求，在 <Ref id="X.2.1.4" /> 加一句：样本外结论段由干净上下文的第二个 Agent 复读报告。
- **数据被修正或运行环境变更后，进行中的样本外登记怎么办**　窗口数据已存在就不能再登记；修正数据只按 retry_of 重试使用；运行环境或账户条款不一致即拒绝绑定。是否作废登记、如何记录归 D 章。

- **不进文档**　样本外回放是否计入研究尝试计数：样本外试验照写 trial 行，研究计数把样本外单列（<Ref id="R.4.2.1" />）；计数不触发任何规则，本章不另写。
