## Deployment topology [#platform-deployment]

One compose file (`services/ide/docker/compose.yaml`) is the whole deployment, the same on a workstation and a server: four services on one Docker engine, with these read, write and Docker boundaries.

**Paper**　Every action of the Paper panel is a verb of the command line `paper`: start declares a paper run and starts its containers, stop stops and seals it, seal seals a run that ended on its own, delete removes a sealed run (the user's own action, never an agent's; the service administrator commits it as `paper_delete:<id>`), list, reconcile (a background replay on the archive compared order by order, writing nothing) and serve. `python -m cli.main paper <verb> --help` is the contract. The daemon itself only reads runs and journals; every write is the command line run with an allowlisted environment.

**Agent**　The chat service (`services/ide/agent`, Node, run inside the ide container) can call only the product's read-only commands: research state, research status, candidate list, candidate show, replay report, ledger sql, market coverage; it cannot write the ledger or start or stop a run. The research graph API (/api/view, /api/events) is read-only; live refresh versus a fixed commit is described in [the trade IDE](/en/docs/design-code-ide/). Deployment steps and environment variables: [services/ide/README.md](https://github.com/qOeOp/trade/blob/main/services/ide/README.md).

## Deployment

Compose runs four services: `ide`, `ledger`, `paper` and `docker-api`. Ledger and Paper share the `trade-service` service image. This is separate from the digest-pinned `strategy-runtime` image that executes strategies. Only the Paper daemon accesses Docker through the restricted API proxy.

<a id="ide" />

## IDE

The IDE maintains its own read-only research and market copies, cloned from DoltHub and updated by fast-forward only. Local Chat runs read-only commands and keeps conversations in its volume. The Paper panel proxies requests and streams to the daemon; the daemon uses the CLI to write to the active research ledger.

<a id="paper" />

## Paper execution

Each PaperRun starts a runner and an egress container from the same digest-pinned image on an internal network. Only egress connects to Binance public market data; Nautilus Sandbox handles orders and fills. PaperRun and capture records live in the research database: a PaperRun is not a research trial, and Paper has no separate database.

<a id="data" />

## Data and evidence

The active Dolt SQL service hosts the research ledger and market databases; connection profiles specify their names. `dolt_backup`, DoltHub and the IDE retain historical copies rather than create new sources of fact. Native reports are caches: reconstruct them from pinned inputs and runtime, then compare them against their stored fingerprints.
