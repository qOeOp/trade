## Deployment topology [#platform-deployment]

One compose file (`services/ide/docker/compose.yaml`) is the whole deployment, the same on a workstation and a server: four services on one Docker engine, with these read, write and Docker boundaries.

<Mermaid chart={"flowchart LR\n  U[Browser 127.0.0.1:8765] --> IDE[ide research graph page and agent chat service]\n  IDE -->|api/paper proxy same-origin plus token| P[paper daemon 8767]\n  IDE --> V[(trade-ide-data volume read-only copy of the public DoltHub databases)]\n  P -->|TRADE_DOLT_HOST| L[ledger Dolt service 13330]\n  P -->|restricted Docker API| D[docker-api haproxy]\n  D --> E[host Docker engine]\n  C[host command line python -m cli.main] --> L\n  L -->|bootstrap and publish| H[(public DoltHub copies)]"} />

| Service | Image | Reached by | Reads | Writes |
|---|---|---|---|---|
| ide | ghcr.io/qoeop/trade-ide | the browser on 127.0.0.1:8765; only the configured Host is served, cross-site requests are refused, no CORS header | its own read-only copy of the public DoltHub databases (volume trade-ide-data, cloned on first start, fast-forwarded by the container administrator with DOLT_PULL --ff-only) | no database; /api/agent/ and /api/paper/ are forwarded as they are |
| ledger | ghcr.io/qoeop/trade-service | the host command line and paper, 127.0.0.1:13330 | the Dolt service of the research ledger and the market database (`ledger service run`) | the only writing service of both databases; bootstraps from the public copies on first start and publishes back to them; the only holder of the DoltHub key |
| paper | ghcr.io/qoeop/trade-service | ide only, over the project network (8767) | the ledger's paper runs, their journals, a version's last research replay | the ledger through the command line `paper start/stop/seal/delete` (<code>paper_run</code> declarations and sealed capture bundles); run containers through docker-api |
| docker-api | haproxy | paper only, on an internal network | — | exactly the Docker calls paper makes (docker/docker-api.cfg); the only path to the host's Docker engine |

**Paper**　Every action of the Paper panel is a verb of the command line `paper`: start declares a paper run and starts its containers, stop stops and seals it, seal seals a run that ended on its own, delete removes a sealed run (the user's own action, never an agent's; the service administrator commits it as `paper_delete:<id>`), list, reconcile (a background replay on the archive compared order by order, writing nothing) and serve. `python -m cli.main paper <verb> --help` is the contract. The daemon itself only reads runs and journals; every write is the command line run with an allowlisted environment.

**Agent**　The chat service (`services/ide/agent`, Node, run inside the ide container) can call only the product's read-only commands: research state, research status, candidate list, candidate show, replay report, ledger sql, market coverage; it cannot write the ledger or start or stop a run. The research graph API (/api/view, /api/events) is read-only; live refresh versus a fixed commit is described in [the research graph service](/en/docs/design-skill-research-graph/). Deployment steps and environment variables: [services/ide/README.md](https://github.com/qOeOp/trade/blob/main/services/ide/README.md).
