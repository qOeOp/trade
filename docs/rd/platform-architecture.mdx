**Paper**　Every action of the Paper panel is a verb of the command line `paper`: start declares a paper run and starts its containers, resume continues the same unsealed run from a verified native checkpoint, stop stops and seals it, seal seals a run that ended on its own, delete removes a sealed run (the user's own action, never an agent's; committed in the Paper database as `paper_delete:<id>`), list, compare (a background replay on the archive compared order by order, writing nothing) and serve. `python -m cli.main paper <verb> --help` is the contract. The daemon itself only reads runs and journals; every write is the command line run with an allowlisted environment.

**Market**　Market data does not pass through the ledger service: it is a market directory in the host directory `${TRADE_DATA}/market` that market-import writes (`market.write_file`, `market.place`); paper and ide mount it read-only and the host command line reads the directory itself, all through the market commands (`market.read_table`). The market directory is the only copy; if lost, it is recomputed from the exchange's archives. The import lock is an fcntl lock and excludes only processes that share one kernel: every writer runs in a container of this compose project and shares the Docker VM's kernel; on the host, a market write command runs through `docker compose exec` (or `run`) in the market-import service, and the host command line never writes the market directory directly.

**Agent**　The chat service (`ide/agent`, Node, run inside the ide container) can call only the product's read-only commands: research state, research status, research runs, candidate list, candidate show, replay report, ledger sql, market coverage; it cannot write the ledger or start or stop a run. The research graph API (/api/view, /api/events) is read-only; live refresh versus a fixed commit is described in [the trade IDE](/en/docs/design-code-ide/). Deployment steps and environment variables: [ide/README.md](https://github.com/qOeOp/trade/blob/main/ide/README.md).

## Deployment

Compose runs five services: `ide`, `ledger`, `market-import`, `paper` and `docker-api`. All but `ide` and `docker-api` share the `trade-service` service image. This is separate from the digest-pinned `trade-runtime` images that execute strategies: replays run the replay image, Paper and Live the execution image (`exec-` tags). Only the Paper daemon accesses Docker through the restricted API proxy.

<a id="ide" />

## IDE

The IDE reads the research ledger from the active Dolt SQL service through reader accounts and the read-only mounted market directory through the market commands, and keeps no copy of its own. Local Chat runs read-only commands and keeps conversations in its volume. The Paper panel proxies requests and streams to the daemon; the daemon uses the CLI to write to the separate `paper` database, never to the research ledger.

<a id="paper" />

## Paper execution

Each PaperRun starts a runner and an egress container from the same digest-pinned image on an internal network. Only egress connects to Binance public market data; Nautilus Sandbox handles orders and fills. A PaperRun is not a research trial. Both the base deployment and a [remote host](#remote) keep PaperRuns and their sealed files in the separate `paper` database on the same Dolt service (ledger/paper.sql, never published); the research ledger holds no Paper record.

<a id="remote" />

## Remote host and release

`deploy/remote/` sits on top of the base deployment and adds HTTPS and GitHub login, with a read-only research mirror and an isolated `paper` database for execution records. `ledger mirror` bootstraps the read-only research database from the public replica and creates the empty `paper` database; it holds no DoltHub publishing key and refuses to take over an existing research writer. `ledger sync` fetches the public replica, validates the immutable commit and fast-forwards only, never publishing; the mirror runs it every 60 s. The host follows version tags only: a `main` build only reaches `main-ready`, and shipping a version is the user's call; a release does not interrupt running strategies. [deploy/remote/README.md](https://github.com/qOeOp/trade/blob/main/deploy/remote/README.md) owns the steps, boundaries and release scope.

<a id="live" />

## Live execution

Real orders start only from the Live page, through its paired control (the `live` package). Its records stay in a private directory, out of the research ledger, the `paper` database and DoltHub. Research never uses it. [engine/README.md](https://github.com/qOeOp/trade/blob/main/engine/README.md#live-execution) owns its behaviour and boundaries.

<a id="data" />

## Data and evidence

The Dolt SQL service hosts the research ledger and the separate `paper` database, each named by its connection profile; `dolt_backup` keeps a local copy of each; only the research ledger is published to DoltHub, the `paper` database never is. Market data lives in the market directory as plain Parquet files by table and month, with no copy. No copy creates a new source of fact. Native reports are caches: reconstruct them from pinned inputs and runtime, then compare them against their stored fingerprints.
