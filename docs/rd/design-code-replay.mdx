### `audit_problems` [#def-replay-audit_problems]

把运行器与审计器的执行结果写成无效原因：退出码、审计是否运行与其结论、结构化异常回执，逐条列出互不覆盖；基础设施错误原样保留为原因，不改写成证据不足

```python
def audit_problems(
    workdir: Path,
    native_exit: int,
    audit_exit: int | None,
) -> tuple
```

<TypeTable type={{ "workdir": { type: "Path", description: "回放工作目录；读 reports/audit.json 与 reports/runtime_failures.jsonl" }, "native_exit": { type: "int", description: "运行器退出码" }, "audit_exit": { type: "int | None", description: "审计器退出码；空表示审计器未运行" } }} />

**返回**　tuple(reasons: list[dict], audit: dict | None)；reasons 每条 \{code, message, locator\}，audit 为读出的审计结果原件，缺失或不可读为空

**期望行为**

1. native_exit 非零：追加 NATIVE_EXIT_NONZERO，message 带退出码。
2. audit_exit 为空：追加 AUDIT_NOT_RUN；非零：追加 AUDIT_EXIT_NONZERO。
3. reports/audit.json 不存在追加 AUDIT_RESULT_MISSING，不可读追加 AUDIT_RESULT_UNREADABLE（附读取错误原文）；自报未通过或 findings 非空追加 AUDIT_FINDINGS，每条发现的定位原样转为 locator。
4. reports/runtime_failures.jsonl 非空：每行须是结构化异常回执，全部合规追加 RUNTIME_FAILURE_RECORDED（locator 带阶段与合约标识），否则 RUNTIME_FAILURE_MALFORMED；不可解析追加 RUNTIME_FAILURE_UNREADABLE。
5. 只按退出码、文件存在性与结构化字段判定，不匹配日志文本；每条独立追加，前一条成立不省略后一条；只读不写。本函数不拒绝：任何缺失、不可读或不合规都写成无效原因返回，不抛出带码拒绝。

### `execute` [#def-replay-execute]

同一运行环境内先运行器后独立审计器：报表齐全才启动审计器；各阶段命令、状态与退出码分文件落盘；无论结局都封存执行捕获

```python
def execute(
    ledger: dict,
    trial_id: int,
    identity: dict,
    mounts: list[tuple[Path, str, bool]],
    workdir: Path,
    runner_args: list[str],
    conn: connection | None,
    purpose: str,
) -> tuple
```

<TypeTable type={{ "ledger": { type: "dict", description: "账本连接配置（封存用）" }, "trial_id": { type: "int", description: "子进程启动前已写下的试验编号" }, "identity": { type: "dict", description: "运行环境身份：image_ref（含摘要）、平台、运行契约" }, "mounts": { type: "list[tuple[Path, str, bool]]", description: "挂载声明（宿主路径、容器路径、是否可写）：只读输入与运行器唯一可写的报告目录" }, "workdir": { type: "Path", description: "回放工作目录：source/、reports/、audit/ 与覆盖回执 input-coverage.json" }, "runner_args": { type: "list[str]", description: "容器内运行器参数" }, "conn": { type: "connection | None", description: "账本写连接；封存时与写试验行同一会话" }, "purpose": { type: "str", description: "试验用途 explore | precheck | research | validation，写入封存包" } }} />

**返回**　tuple(native_exit: int, audit_exit: int | None)；audit_exit 为空表示审计器未运行

**期望行为**

1. 按运行契约取布局常量（runtime.layout），生成运行器容器命令（runtime.container_command），写 process.json 记录阶段 native=started。
2. 运行器 stdout/stderr 分别写 native.stdout.txt、native.stderr.txt；进程无法启动记退出码 127 并把错误写入 stderr 文件；更新阶段为 exited 与退出码。
3. 仅当全部必需报表文件齐全时生成审计器命令并运行：同一镜像摘要，reports/ 与覆盖回执只读挂载，唯一可写挂载为 audit/，输出 audit/audit.json，不挂载 source/；stdout/stderr 同样分文件落盘。报表不全则审计阶段留空，不运行。
4. 无论正常返回、中断或宿主异常，finally 调用 ledger.seal_capture 把阶段记录、stdout/stderr、源码字节、覆盖回执、结构化异常回执与审计结果按试验封存，结局标 completed / interrupted / host_failed。
5. 中断或宿主失败时原异常继续向上抛出，工作目录保留。
6. 本函数不拒绝：报表不全、进程无法启动、中断或宿主失败都如实记入阶段记录并封存，由 replay.audit_problems 转成无效原因。

### `explore` [#def-replay-explore]

非登记探索：把未发布的策略文件装入钉死运行环境回放，试验行 purpose=explore，报告留在新建的临时目录，账本只有试验行、开始回执与执行封存

```python
def explore(
    ledger: dict,
    market: dict,
    at: str | None,
    strategy_file: Path,
    strategy_class: str,
    output: Path,
    runtime: str | None,
    runner_argv: list[str],
) -> dict {purpose
```

<TypeTable type={{ "ledger": { type: "dict", description: "研究账本连接配置" }, "market": { type: "dict", description: "市场库连接配置" }, "at": { type: "str | None", description: "市场提交；空表示当前头" }, "strategy_file": { type: "Path", description: "未发布的单文件策略源码" }, "strategy_class": { type: "str", description: "入口类名，须是合法 Python 标识符" }, "output": { type: "Path", description: "输出目录，须是尚不存在的临时目录" }, "runtime": { type: "str | None", description: "运行环境引用；空取 main 标签" }, "runner_argv": { type: "list[str]", description: "运行器窗口与范围参数" } }} />

**返回**　dict \{purpose: explore, status: passed|invalid, problems, path, trial_id, image_ref, market（输入身份）, metrics（未核验目录绩效指标）\}

**期望行为**

1. 经 ledger.temporary_path 核对 output 在临时根之下且不存在（OUTPUT_NOT_TEMPORARY / OUTPUT_EXISTS）；核对 strategy_class 是标识符、runner_argv 不含保留选项；读源码字节算内容哈希。
2. runtime.resolve 解析运行环境身份；registration.market_inputs 导出输入（不要求新鲜，可用缓存导出），registration.input_key 算输入身份；按挂载改写运行器参数后经 runtime.inspect_runtime 探针检视。
3. 建 source/ 与 reports/，写入源码、运行环境检视与覆盖回执（replay.input_coverage）。
4. 容器启动前经 ledger.open_trial 与 ledger.start_receipt 写 purpose=explore 的试验行与开始回执，记源码哈希、运行环境引用、合约集与窗口。
5. 挂入源码、报告目录与覆盖回执调用 replay.execute，结束后由 replay.audit_problems 得出问题清单；执行捕获由 replay.execute 交 ledger.seal_capture 封存。
6. 目录保留；绩效指标由 report.directory_report 从未核验的临时报告读出，只供导向不作证据；finally 清理导出目录。

| 拒绝码 | 条件 |
|---|---|
| `OUTPUT_NOT_TEMPORARY` | output 不在平台临时根之下 |
| `OUTPUT_EXISTS` | output 已存在 |
| `STRATEGY_CLASS_INVALID` | strategy_class 不是单个 Python 类名 |
| `RUNNER_OPTION_RESERVED` | runner_argv 含入口保留选项（策略文件、策略类、源码哈希、绑定文件、输出目录） |

### `precheck` [#def-replay-precheck]

对已发布候选做事前声明用途的原生预检：核对运行环境与运行契约，在启动容器前写 purpose=precheck 的试验行与开始回执，执行后把原生输出、退出码、审计与报告随试验封存，并返回封存包名

```python
def precheck(
    ledger: dict,
    market: dict,
    at: str,
    candidate: str (strategy_id@revision),
    runtime: str,
    runner_argv: list[str],
    output: Path,
) -> dict {purpose
```

<TypeTable type={{ "ledger": { type: "dict", description: "研究账本连接配置" }, "market": { type: "dict", description: "市场库连接配置，只读" }, "at": { type: "str", description: "市场提交，须与随后登记用同一提交" }, "candidate": { type: "str (strategy_id@revision)", description: "已发布候选" }, "runtime": { type: "str", description: "运行环境引用，须与随后登记用同一摘要" }, "runner_argv": { type: "list[str]", description: "运行器的窗口与合约参数（覆盖改动的最短窗口、最少合约）" }, "output": { type: "Path", description: "尚不存在的临时目录" } }} />

**返回**　dict \{purpose: 'precheck', trial_id, execution_bundle, source_sha256, image_ref, input_key, config_key, status: passed|failed, problems, path, metrics, scope: '仅工程证据；接口、因果、活动、就绪由独立 Agent 审查'\}。status 为 passed 表示原生与审计退出为零、无回调异常且审计问题清单为空

**期望行为**

1. 核对：经 ledger.read_candidate 读候选；经 ledger.temporary_path 核对 output；runner_argv 不含保留选项；经 runtime.resolve 解析运行环境，构建源码版本为空即拒绝；候选 runtime_contract 等于镜像运行契约。任一不符即拒绝，不启动任何进程。
2. 按 at 以 registration.market_inputs 新鲜导出输入（与登记同一导出器、同一提交），算 registration.input_key；经 runtime.inspect_runtime 在镜像内读出有效配置，算 registration.config_key。
3. 建工作目录 source/、reports/，写入源码原字节、运行环境检视结果与 replay.input_coverage 覆盖回执。
4. 在一个写事务里经 ledger.open_trial 写 purpose=precheck 的试验行（不带登记绑定器），并经 ledger.start_receipt 写开始回执（用途 precheck、源码哈希、运行环境、input_key、config_key）；事务成功后才启动容器。
5. 调用 replay.execute（标预检用途）：先运行器后审计器，结束时（含中断与宿主失败）由 ledger.seal_capture 封存原件；再由 replay.audit_problems 给出问题清单，report.directory_report 读出工程诊断用绩效指标。
6. 保留 output，清理导出目录，返回结果。预检不消耗网格点；失败或重复的预检都不成为登记尝试。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_STRATEGY` | 候选在账本中不存在 |
| `NOT_TEMPORARY_PATH` | output 不在临时根之下 |
| `PATH_EXISTS` | output 已存在 |
| `RUNNER_OPTION_RESERVED` | runner_argv 含入口保留选项 |
| `RUNTIME_NOT_CI_BUILT` | 运行环境镜像缺构建源码版本标签，不是 CI 构建 |
| `RUNTIME_CONTRACT_MISMATCH` | 候选运行契约与镜像运行契约不一致 |

### `run` [#def-replay-run]

研究封存回放与样本外回放的主体：读已发布候选，用同一市场提交新鲜导出输入，绑定已登记网格点或样本外登记，在临时目录完成回放并一次写入账本；入账后删目录，失败保留目录供诊断

```python
def run(
    ledger: dict,
    market: dict,
    at: str | None,
    strategy: str（strategy_id@revision）,
    runtime: str | None,
    runner_argv: list[str],
    hypothesis: str | None,
    validation: str | None,
) -> dict {purpose
```

**返回**　dict \{purpose: research|validation, strategy, trial_id, run_id, status: passed|invalid, failure_reasons, image_ref\}

**期望行为**

1. 核对 hypothesis 与 validation 恰给一个（REGISTRATION_REQUIRED）；解析 runner_argv，含入口保留选项拒绝 RUNNER_OPTION_RESERVED。
2. purpose=validation 时先经 runtime.require_main_build 与 registration.require_fresh 核对运行环境来自 main 构建、产品工作树干净且含 main 最新提交，否则拒绝 MAIN_BUILD_REQUIRED。
3. 经 ledger.connect 打开写会话，ledger.read_candidate 读已发布候选（源码字节、内容哈希、入口类、运行契约）；不存在拒绝 CANDIDATE_NOT_FOUND。
4. 按 at 解析市场提交，经 registration.market_inputs 新鲜导出到临时导出目录，registration.input_key 算输入身份。
5. 交 replay.seal 完成同事务绑定、执行、核对与入账（ledger.ingest_run）；finally 删除导出目录。
6. 成功返回封存结果；replay.seal 的异常原样上抛，工作目录由其保留并在标准错误打印位置。

| 拒绝码 | 条件 |
|---|---|
| `REGISTRATION_REQUIRED` | hypothesis 与 validation 都未给或同时给出 |
| `RUNNER_OPTION_RESERVED` | runner_argv 含入口自己写入的选项（策略文件、策略类、源码哈希、绑定文件、输出目录） |
| `CANDIDATE_NOT_FOUND` | strategy_id@revision 在账本中不存在 |
| `MAIN_BUILD_REQUIRED` | purpose=validation 但运行环境不是 main 构建或工作树不含 main 最新提交 |
