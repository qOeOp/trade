# Candidates and lineage

Complete strategy source, content identity and parent links identify each candidate revision.

[Database overview](/en/docs/design-ledger/)

### `candidate` [#def-table-candidate]

候选 candidate：一份完整单文件策略源码的精确字节；身份是账本从字节派生的内容哈希，引用名是 strategy_id@revision；父版本与改动说明构成候选谱系的边。只增不改，每次发布恰一个账本提交。

**键与约束**

- 主键　`strategy_id`, `revision`
- 唯一　`source_sha256`
- 唯一　`op_id`
- 外键　`parent_strategy_id, parent_revision` → <Ref id="table:candidate">candidate</Ref> `strategy_id, revision`
- CHECK　`revision > 0`
- CHECK　`(parent_strategy_id IS NULL AND parent_revision IS NULL AND difference IS NULL) OR (parent_strategy_id IS NOT NULL AND parent_revision IS NOT NULL AND difference IS NOT NULL)`
- CHECK　`NOT (parent_strategy_id = strategy_id AND parent_revision = revision)`
- 生成列　`source_sha256 = SHA2(source, 256) STORED UNIQUE`

**Dolt 能力**

- **J.3.2.1**　每次发布恰一个 DOLT_COMMIT，整笔成或整笔不成：候选只增
- **J.3.1.1**　dolt_diff_candidate 正常路径只应出现 added；出现 modified 或 removed 即篡改线索
- **J.3.1.3**　AS OF 读任一账本提交时刻的候选谱系，候选清单按版本读历史
- **T.2.1.2**　父外键指向已存在行且表只追加，所以谱系是无环森林；父早于子由提交顺序与 created_at 证明，无需额外字段
- **T.1.1.1**　dolt_history_candidate 单元格级历史证明父列与改动说明从未被改
- **J.3.4.1**　内容寻址：生成列哈希加 UNIQUE，读回重算比对，重复身份拒写
