# 登记与试验

研究登记在回放之前写下预测、网格和执行身份；每次回放在容器启动前写一条试验，带上自己的执行身份；捕获结束后记下各阶段的结局和每个文件的去向。

[数据库总览](/zh/docs/design-ledger/)

### `research_registration` [#def-table-research_registration]

研究登记：一条开着的研究线上，回放前提交的预测、网格、对照和执行身份；之后的研究试验必须与它的执行身份逐列相同

<TypeTable type={{ "registration_id": { type: "INT AUTO_INCREMENT", description: "登记编号，自增", required: true }, "line_id": { type: "INT", description: "所属研究线；不可空", required: true }, "retry_of": { type: "INT", description: "重试的原登记；只能指向更早的登记", required: false }, "control_trial_id": { type: "INT", description: "对照运行的试验", required: false }, "comparison_design_id": { type: "INT", description: "承诺的比较方法", required: false }, "image_ref": { type: "VARCHAR(300)", description: "钉死的运行环境引用 `<仓库>@sha256:<摘要>`", required: true }, "market_day": { type: "DATE", description: "市场日：读市场数据截至的那一天，默认取研究线钉住的市场日", required: true }, "universe_rule": { type: "VARCHAR(60)", description: "共同交易范围的规则名", required: true }, "lifecycle_bundle": { type: "VARCHAR(160)", description: "该市场日的上下架事实证据包；没有生命周期事件时为 NULL", required: false }, "export_sha256": { type: "CHAR(64)", description: "导出内容哈希：输入身份的一部分", required: true }, "comparable_config_sha256": { type: "CHAR(64)", description: "可比的有效配置哈希", required: true }, "body": { type: "JSON", description: "预注册的文字：prediction、conditions、changed_duties、rationale、sources（JSON 对象）", required: true }, "op_id": { type: "VARCHAR(160)", description: "幂等操作 ID：同一载荷重试返回原记录；UNIQUE", required: true }, "created_at": { type: "DATETIME(6)", description: "服务器 UTC 时间，BEFORE INSERT 触发器覆盖调用方给的值；研究试验的 created_at 晚于它即登记在先", required: true } }} />

**键与约束**

- 主键　`registration_id`
- 唯一　`op_id`
- 唯一　`registration_id`, `line_id`, `image_ref`, `market_day`, `universe_rule`, `export_sha256`, `comparable_config_sha256`
- 索引　`line_id`
- 外键　`line_id` → <Ref id="table:research_line">research_line</Ref> `line_id`
- 外键　`retry_of` → <Ref id="table:research_registration">research_registration</Ref> `registration_id`
- 外键　`comparison_design_id` → <Ref id="table:comparison_design">comparison_design</Ref> `design_id`
- 外键　`lifecycle_bundle` → <Ref id="table:evidence_bundle">evidence_bundle</Ref> `bundle`
- 外键　`control_trial_id` → <Ref id="table:trial">trial</Ref> `trial_id`
- CHECK　`retry_of IS NULL OR retry_of \< registration_id`
- CHECK　`JSON_TYPE(body) = 'OBJECT'`

**保护与读写规则**

- 一次写入一个事务、一个 Dolt 提交，并把 `ledger_head` 加一；写账号对本表只有 INSERT，`ledger review` 报告任何被改或被删的行（ROW_CHANGED）
- 登记行、网格点、比较方法和 `source-<sha256>` 来源包在同一提交写入
- 研究回放的交易窗口必须等于研究线的开发期（`registration.register`）；研究线已关则拒绝
- 执行身份的七列组成唯一键，研究试验用复合外键指向它：试验的镜像、市场日、范围规则、导出和配置哈希不能与登记不同

**写入方**　`registration.register.register`（`registration add`）

**读取方**　`research state`、`hypothesis compare`、`research history`

### `registration_grid_point` [#def-table-registration_grid_point]

登记网格点：登记承诺要跑的候选，每点引用同一源码的一条通过的源码审查；一点最多被一次研究试验消耗

<TypeTable type={{ "registration_id": { type: "INT", description: "所属登记", required: true }, "source_sha256": { type: "CHAR(64)", description: "网格点候选的源码哈希", required: true }, "source_review_id": { type: "INT", description: "该点依赖的源码审查；复合外键要求它审查的是同一源码", required: true } }} />

**键与约束**

- 主键　`registration_id`, `source_sha256`
- 外键　`registration_id` → <Ref id="table:research_registration">research_registration</Ref> `registration_id`
- 外键　`source_sha256` → <Ref id="table:candidate">candidate</Ref> `source_sha256`
- 外键　`source_review_id`, `source_sha256` → <Ref id="table:source_review">source_review</Ref> `review_id`, `source_sha256`

**保护与读写规则**

- 与登记同一提交写入，之后只读
- 研究试验用 (`research_registration_id`, `source_sha256`) 外键指向网格点，试验表上的唯一键保证一点只被消耗一次；无效和中断的试验同样算消耗
- 外键挡的是产品代码的错误：写账号能在会话里关掉外键检查，所以 `ledger review` 对新提交逐个外键查对不上的行（CONSTRAINT_VIOLATED）

**写入方**　`registration.register.register`

- 研究试验以复合外键对上登记的执行身份和一个网格点；样本外试验以复合外键对上登记的源码、范围规则和窗口

- 工作目录只参与 op_id 的哈希，不存：换目录重跑是另一次试验
- 外键挡的是产品代码的错误：写账号能在会话里关掉外键检查，所以 `ledger review` 对新提交逐个外键查对不上的行（CONSTRAINT_VIOLATED）
