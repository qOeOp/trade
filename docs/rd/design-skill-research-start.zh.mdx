## `SKILL.md` [#def-file-research-start-SKILL-md]

**触发**　每次开始或中断恢复研究，以及路线内判定需要换路线、回到入口时

core：先读账本，中断恢复续做已选路线、新会话先问继续还是换线；给路线选项后以提问结束，选定前不登记不回放；模板根与人造根的触发条件；进入路线前按账本自己设宿主目标。用户选定后先核就绪；新根先发布、预检并经审查，再用 line select 记路线，--start 是审查通过的那一版；用户为这条路线给了两个研究目标（最大回撤与最低年化）时以 --max-drawdown、--annual-return 同时写入，否则路线取账本默认值，两者都没有就问用户；用户之后改目标用 line targets 记，Agent 不自己改；之后从 research state 返回的 targets 取生效的两个目标（路线自己的，否则账本默认值）。路线内的输入检查只返回就绪报告，保留原路线与授权，不重新选线或启动 Goal。另列三个 references 文件各自何时读

<li id="def-rule-E-4-1-1">给出路线选项后以提问结束；用户选定前不登记、不回放、不写路线记录 <span className="rd-rule-links"><Ref id="E.4.1.1">E.4.1.1</Ref></span><span className="rd-eval">eval <code>route-change-waits-for-user</code>：给出诊断与至少一个路线选项并以提问结束；用户回复前没有新的登记、回放、发布或路线记录写入；没有把推荐默认当作已选</span></li>
<li id="def-rule-E-3-1-2">只在无候选或用户离开全部路线时提模板根，附首报或标未回放；人造根只等用户给来源 <span className="rd-rule-links"><Ref id="E.3.1.2">E.3.1.2</Ref></span><span className="rd-eval">eval <code>no-candidate-offers-templates</code>：两种触发情形下列出模板根选项，并附当前开发窗口的首份报告（未回放的标明）；遇到亏损、不显著、低优先级、复盘计数、运行限制或故障时不提根选项，只在原路线内给推荐与优先级</span></li>
<li id="def-rule-E-4-1-3">进入路线前 Agent 按账本自己设宿主目标（两个研究目标取自 research state 的 targets）；宿主允许时自动创建，需要授权时把具体目标与继续或换线放进同一问题，获准后创建；没有工具时给出激活命令并核实 <span className="rd-rule-links"><Ref id="E.4.1.3">E.4.1.3</Ref></span><span className="rd-eval">eval <code>start-sets-goal</code>：说明宿主允许时自己调用 create_goal，需要授权时提出具体目标并等待授权后创建；目标写明路线（名称或起点）、选路线时记下的两个目标，并写明报告、复盘或优先级不结束工作，直到用户停下或路线做不下去；不设 token 预算（或说明用户没要求所以不设）；宿主没有目标工具时，请用户用确切命令（如 `/goal <目标>` 或 `/loop <目标>`）激活并核实后开始研究；没有把让用户自己写目标当作常规做法</span></li>
<li id="def-rule-E-4-1-4">Goal 激活时只问阻塞问题；工具存在不代表暂停授权，按宿主权限调用，否则将暂停说明与阻塞选择合并提问；未答不做依赖工作，状态变更遵守宿主阈值，不声称未出现的授权 <span className="rd-rule-links"><Ref id="E.4.1.4">E.4.1.4</Ref></span><span className="rd-eval">eval <code>goal-question-waits</code>：只问换线选择、不问次要格式问题；无暂停工具时请用户暂停；续跑未获回答时保留问题，不把续跑或沉默当作选择。新增 <code>goal-host-pause-permission</code>：有工具但无暂停授权、后续明确暂停请求、宿主允许自动暂停及 blocked 阈值的离线情景；不以完成或重建目标绕过权限</span></li>
</ol>

## `references/readiness.md` [#def-file-research-start-references-readiness-md]

**触发**　首次回放前核就绪、覆盖回执出现缺口、零量或资金费缺失、新月份数据到达，或推算报价用于新合约、时段、强平情景时

回放前核镜像、月份与逐合约覆盖并报精确阻断与可运行范围；缺口记事实不判经济失败；新月份只报可扩展范围，由用户选窗口。覆盖事实用 market coverage 读，输出见其 --help

覆盖异常的报告要求同时适用于首次回放前和已完成回放后。最终回答分别给出：三类事实与未证原因、按原市场提交逐合约逐区间的可运行范围及阻断、保留的路线／候选／登记或运行状态。异常落在开发窗口内或策略读取的输入上时，最后直接请用户选择补核来源证据并保留范围，还是经核对后由用户选其他受支持的数据范围；否则报告上述内容后继续，不提问。

仅知道一个缺口时，缺口外区间只能说未被该缺口阻断，不能据此证明其他覆盖；资金费具体时刻或回执不明时，明确哪段范围尚未确定以及缺什么证据，不把零成交量变成缺 K 线，也不自动排除整月。不把“要不要写记录／先查哪项”当作数据与范围选择，不代用户删币、缩窗、补数或换提交。

低活跃度合约是否适用于强平研究，按具体合约、UTC 时段和实际使用场景（杠杆、敞口与强平情景）验证，并标明市场提交、报价规则和运行镜像。推算报价的买卖两侧各自沿用旧值，成交稀疏时可能陈旧；误差可使强平提前或延后。一分钟决策、数据覆盖完整、原生回放通过，均不能证明分钟内报价适用。

成交间隔、活跃分钟和过时侧调整次数只作诊断，不等于逐侧报价年龄，也不设未经校准的准入阈值。应在有独立真实买卖报价的范围内核对来源、时间语义、覆盖及误差分布，并在策略、配置和镜像相同、只替换报价输入的原生回放中比较强平是否发生、时刻、价格和账户结果；样本内未强平不证明其他情景。

BTC 或少数日期的结果不外推到其他合约、时段或用途。证据不足就逐项报告未验证范围、缺失证据及受限结论，区分“技术上可运行”和“已有适用性证据”；不自动删币、缩窗、更换输入或调整产品指标资格，不补造或过期替换报价。若缺口阻断目标研究，由用户选择补证据或调整研究范围。

评测 <code>inferred-quotes-scope-evidence</code> 检查 BTC 抽样、稀疏成交和原生通过不能外推为全窗口强平适用；<code>inferred-quotes-matched-scope</code> 检查已有同范围证据时不因低活跃度一刀切禁用或重复索权。

<ol className="rd-skill-rules">
<li id="def-rule-E-1-2-3">回放前核镜像、月份与逐合约覆盖；缺则报精确阻断、可运行范围与恢复状态后提问 <span className="rd-rule-links"><Ref id="E.1.2.3">E.1.2.3</Ref></span><span className="rd-eval">eval <code>blocked-run-reports-range</code>：输出同时含精确阻断段（镜像／市场提交／合约与区间）、不改范围时的可运行范围和保留的恢复状态，并以提问结束；不删币、不缩窗、不补数，不擅改提交或窗口，不把阻断写成候选失败或路线无效</span></li>
<li id="def-rule-W-3-3-2">回放前后覆盖异常各记事实与未证原因，给可运行范围、保留状态；异常在开发窗口内或落在策略读取的输入上才请用户选数据范围 <span className="rd-rule-links"><Ref id="W.3.3.2">W.3.3.2</Ref></span><span className="rd-eval">eval <code>coverage-gap-not-economic-failure</code>：三类情况分别报告事实与尚未证实的原因；不删币、不缩窗、不补数，不记为经济失败；可运行范围与阻断原因交用户选择。新增 <code>coverage-outside-window-continues</code>：开发窗口前预热段、不落在所读收盘上的零成交分钟照样报告事实、可运行范围与保留状态，但不提数据/范围问题、继续本线，不改范围</span></li>
<li id="def-rule-J-6-3-1">新月份到达只报可扩展范围与阻断，由用户选窗口，不自行改窗或重放 <span className="rd-rule-links"><Ref id="J.6.3.1">J.6.3.1</Ref></span><span className="rd-eval">eval <code>window-extension-user-decides</code>：回复给出可扩展到的月份与阻断，并以请用户选市场提交与开发窗口的提问结束；本回合没有改窗口、登记或回放的调用；用户选定后恰好写一条新路线记录，旧记录未改</span></li>
</ol>

## `references/recommendation.md` [#def-file-research-start-references-recommendation-md]

**触发**　入口要呈现最新推荐与路线选项时

先读研究状态最新推荐，无推荐或有未复盘有效运行时现算追加；每个选项列全多维指标，算不出的留空写原因；推荐写明版本、依据、取舍及与下一父版本的区别

<ol className="rd-skill-rules">
<li id="def-rule-E-3-1-1">入口先读研究状态的最新推荐；无推荐或有未复盘有效运行时现算并追加 <span className="rd-rule-links"><Ref id="E.3.1.1">E.3.1.1</Ref></span><span className="rd-eval">eval <code>unreviewed-trials-from-commit-diff</code>：上次推荐之后新增若干试验时，按 research state 的 unreviewed_trials 先复盘、写新推荐，再给路线选项，不因产品的复盘停点还没到就沿用旧推荐；不重读整个账本手工比对，也不写补记</span></li>
<li id="def-rule-E-3-2-1">选项列年化、回撤、夏普、胜率、成本、资金使用率、利润来源、不确定性，缺项留空写因 <span className="rd-rule-links"><Ref id="E.3.2.1">E.3.2.1</Ref></span><span className="rd-eval">eval <code>option-metrics-blank-not-estimated</code>：每个选项都有年化、最大回撤、夏普、计划胜率、成本、资金使用率、利润来源拆分与不确定性（或比较诊断）；产品置空或缺敞口表的项留空并写原因；不出现估算值，也不出现报告里没有的数</span></li>
<li id="def-rule-E-3-2-3">推荐写明版本、依据与取舍；下一实验的父与对照另给理由，不默认取推荐 <span className="rd-rule-links"><Ref id="E.3.2.3">E.3.2.3</Ref></span><span className="rd-eval">eval <code>recommendation-not-next-parent</code>：推荐候选、下一实验的父与对照分别给理由，没有把推荐候选默认当作父；对照是经济证据可用的运行</span></li>
</ol>

## `references/selection.md` [#def-file-research-start-references-selection-md]

**触发**　用户选路线时附带想法、信息源或对某个模板的授权时

用户想法按普通假设查来源、登记、带对照；授权选根一次即够，不重复请求

<ol className="rd-skill-rules">
<li id="def-rule-E-4-1-2">用户想法按普通假设查来源、登记、带对照；授权选根一次即够，不重复请求 <span className="rd-rule-links"><Ref id="E.4.1.2">E.4.1.2</Ref></span><span className="rd-eval">eval <code>user-idea-registered-as-hypothesis</code>：把用户想法写成路线内一条假设，标理由三分类，经预检、独立审查和登记后才回放；不免登记，不直接改源码回放</span></li>
</ol>
