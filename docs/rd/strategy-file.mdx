## 4.1　写成一份可登记的单文件 [#C-1]

<Steps>

### 单文件、入口与身份一致 [#C-1-1]

发布记下内容哈希，执行按同一哈希核对，两头都由代码强制。

#### 策略是单个文件，只有一个引擎策略入口类 [#C-1-1-1]

- 一个策略是一份完整的 UTF-8 单文件，含全部交易规则与参数。
- 文件里恰有一个与声明同名的顶层入口类，继承引擎的策略基类。
- 回放只实例化这个入口类。
- 根、策略库模板和派生候选走同一检查，没有第二种入口形态。

- 构造策略时只传入合约、交易起点和预热数据这类回放输入。

## 4.2　把交易事实交给引擎 [#C-2]

<Steps>

<Step>

回放把所有候选共用的账户与撮合条款配置给引擎。

</Step>

<Step>

策略从引擎读订单、持仓与账户，并提交订单。

</Step>

<Step>

引擎审单撮合，产生成交、费用、资金费、持仓和账户变化。

</Step>

<Step>

回放把引擎报告原样写出，成为原生报告。

</Step>

<Step>

完整性审计与绩效指标只读这些报告，不重算交易事实。

</Step>

</Steps>

<a id="C-2-1" />

交易事实只有引擎一个来源，回放只做配置和原样写出。

<a id="C-2-1-1" />

**交易事实只由引擎产生，回放原样写出报告**

- 成交、费用、资金费、持仓、余额与订单状态只由引擎产生。
- 所有候选共用同一套固定的账户与撮合条款。
- 回放只配置和写出，不计算、不修改、不补造交易事实。
- 写出时缺少必需的引擎事实，运行非零退出并记为无效。

## 4.4　给每个持仓挂保护单 [#C-4]

<Steps>

<Step>

源码声明是否设止损，不写即视为设。

</Step>

<Step>

入场连同止损和止盈一次提交给引擎。

</Step>

<Step>

入场单终止时引擎撤掉保护单；补挂和收尾由源码负责。

</Step>

<Step>

声明写进执行身份随运行入账，回放后不能改。

</Step>

<Step>

完整性审计重建持仓：声明设止损的运行出现裸仓即无效。

</Step>

</Steps>

<a id="C-4-1" />

声明由代码检查并记下，裸仓后果由完整性审计按声明判定。

<a id="C-4-1-1" />

**止损声明缺省为设；声明不设时裸仓只报告，不判无效**

- 源码在入口类上声明是否设止损，不写即为设。
- 声明必须是「是」或「否」，否则不加载，也不产生运行。
- 声明写进执行身份随运行入账，要改只能发布新候选。
- 不设止损的理由写在文件头立场里。

## 4.5　把交易切成可计数的计划 [#C-5]

<Steps>

<Step>

从持仓报告重建持仓周期，核对每笔成交恰被计入一次。

</Step>

<Step>

读出订单上的计划标签，下架结算平仓单按规则归属。

</Step>

<Step>

核对计划与周期一一对应，同一合约上计划不重叠。

</Step>

<Step>

算出计划数和计划胜率。

</Step>

<Step>

任一违例只置空计划统计并写明原因，随运行入账。

</Step>

</Steps>

### 计划的定义与标签 [#C-5-1]

策略下单时写计划标签，代码据此把订单归成计划。

#### 每张订单带一个计划标签，计划胜率按计划计数 [#C-5-1-1]

- 一个计划是一个信号的全部订单：入场、止损止盈、改仓和平仓。
- 每张订单恰带一个回放内唯一的标签，补挂的保护单也要带。
- 赢指已平且含费用与资金费的实现盈亏大于零。
- 计划胜率 = 赢数 ÷（已平计划数 + 期末未平计划数）。

#### 计划与持仓周期一一对应，同一合约同时只有一个计划 [#C-5-1-2]

- 持仓周期指一个合约从开仓到持仓归零的一段。
- 每笔成交恰属一个周期，一个周期只装一个计划的成交。
- 前一计划持仓归零、订单全部终止前，同合约不开新计划。
- 持仓归零时策略撤掉剩余订单；分批加仓仍算同一计划。

### 不合规与原生平仓单 [#C-5-2]

计划违例不影响运行有效性；引擎自动平仓单只在无歧义时归入计划。

#### 计划不合规只置空计划统计，不判运行无效 [#C-5-2-1]

- 计划规则是计划统计的前提，不是账户事实。
- 违例时只置空相关绩效指标，并写明原因和可定位的细节。
- 完整性审计与经济证据资格不受影响，其余指标照常。
- 空值不当零，也不能手工填补。

### 原生预检 [#C-6-1]

预检的用途事前声明、运行环境与登记一致、原件完整封存，都由代码强制。

<a id="C-6-1-1" />

**预检须用与登记相同的运行环境，事前声明用途并完整封存**

- 运行环境必须是自动构建、与随后登记同一摘要的镜像。
- 用途在回放前写进试验，事后不能改，其他用途的回放不能改称预检。
- 只跑覆盖改动所需的最短窗口与最少合约，不消耗网格点。
- 结束时（含中断）把原生输出、退出码和审计原样封存。
