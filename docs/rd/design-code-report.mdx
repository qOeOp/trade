### `candidates` [#def-report-candidates]

全部候选的源码身份、父与改动、每个登记尝试及其运行状态与当前经济证据可用性，附账本提交，可按版本读历史；不带分数、资格标记或排序

```python
def candidates(profile: LedgerProfile, at: str | None) -> dict
```

<TypeTable type={{ "profile": { type: "LedgerProfile", description: "账本档案（连接位置与只读账号）；经 ledger.read_as_of 打开只读连接，是本函数与 cli.candidate_list 唯一的连接来源" }, "at": { type: "str | None", description: "可选账本版本：提交哈希或标签；None 读当前。按版本读出当时的全部候选与尝试，用于复读入口当时看到的森林" } }} />

**返回**　dict：\{ledger_commit: 实际读到的账本提交哈希, checker: 本次计算经济证据可用性的检查身份 \{check, reader_revision, source_sha256\}, candidates: [\{strategy_id, revision, source_sha256, entry_class, runtime_contract, description, parent_strategy_id, parent_revision, difference, created_at, attempts: [\{bundle, trial_id, run_id, run_status: 'passed' | 'invalid' | 'unfinished', availability: \{economic_evidence_available, reasons, checker\}\}], valid_evidence: bool\}]\}。候选按 (strategy_id, revision) 自然顺序列出，仅为稳定输出，不是排序或推荐；不含任何读数、分数或裁决键。

**期望行为**

1. 经 ledger.read_as_of(profile, at) 打开 AS OF 只读连接，核对 ledger_schema 版本与代码一致，取该连接实际指向的提交哈希作 ledger_commit；at 不能解析为提交或标签时拒绝。
2. 读 candidate 全部行（strategy_id、revision、source_sha256、entry_class、runtime_contract、description、parent_strategy_id、parent_revision、difference、created_at）；不读任何收益、显著性或推荐相关列，候选身份只看 source_sha256。
3. 读 registration_attempt 左连 trial 与 run：每个尝试带登记证据包 bundle、消耗它的 trial_id、对应 run_id 与 run.status；无 run 行的尝试（中断、未完成、失败）仍列出并标 run_status = unfinished，因为网格点已被消耗。
4. 对有 run 的尝试经 ledger.load_run 读封存报表，再经 qualification.assess 按 qualification.check_identity 给出的检查身份算当前经济证据可用性（读时视图，不改写存储的 run.status 与审计结论；封存缺失或哈希不符由 assess 标为不可用）；无 run 的尝试 availability = \{economic_evidence_available: false, reasons: ['unfinished'], checker\}。
5. 按 attempt.source_sha256 = candidate.source_sha256 把尝试挂到候选，valid_evidence = 任一尝试经济证据可用；返回 \{ledger_commit, checker, candidates\}。全程不写账本，不生成分数、资格标记、排序或占位推荐。
6. 核对一致性：某尝试引用的 source_sha256 在同一版本的 candidate 里不存在，或 run.trial_id 指向不存在的 trial，经 ledger.refusal 以 LEDGER_CORRUPT 拒绝并指明行，而不是静默丢行。

| 拒绝码 | 条件 |
|---|---|
| `LEDGER_REF_NOT_FOUND` | at 给出的提交或标签在账本里不存在或不可解析 |
| `LEDGER_SCHEMA_MISMATCH` | 所读版本的 ledger_schema 版本与当前代码不一致，或账本未初始化 |
| `LEDGER_CORRUPT` | registration_attempt 引用的候选源码哈希在同一版本的 candidate 中缺失，或 run.trial_id 指向不存在的 trial；指明首个不一致的行 |

### `compare` [#def-report-compare]

只读比较入口：读登记→取登记声明的对照→核候选运行绑定本登记网格→两侧可比→两侧经济证据资格→取交易窗口账户日收益→日钟逐日一致→配对循环块自助→绑定身份；任一项不符即拒绝并留诊断，不返回裁决

```python
def compare(
    profile: str,
    bundle: str,
    run_id: str,
    at: str | None,
) -> dict
```

<TypeTable type={{ "profile": { type: "str", description: "账本档案名，决定连接哪一份研究账本" }, "bundle": { type: "str", description: "登记证据包名，比较条件（对照、网格、检验条件、研发父版本）全部从它读出" }, "run_id": { type: "str", description: "候选运行编号，必须是被本登记某网格点消耗的试验所产出的封存运行" }, "at": { type: "str | None", description: "账本版本（提交或标签），缺省为当前 HEAD；用于复读历史读数" } }} />

**返回**　dict：\{bundle, run_id, control_run_id, research_parent, ledger_commit, registered_at, reader_revision, comparison_source_sha256, availability\{candidate, control\}, evidence\}；evidence 为 report.paired 的返回，并附 observed_account_annual_return_difference（两侧封存运行年化之差，账户口径，与自助统计分列）

**期望行为**

1. 以 at 打开只读连接，经 ledger.load_bundle 读登记证据包并重验内容哈希，取 control_run、grid、comparison、parent 与服务器登记时间；control_run 为空即 NO_CONTROL
2. 经 ledger.load_run 读候选与对照的运行⨝试验记录；在 registration_attempt 中核（bundle, 候选 trial_id）存在且其 source_sha256 等于候选运行源码哈希，否则 RUN_NOT_IN_GRID
3. 两侧各过 registration.check_comparable（对登记的执行身份），再各过 qualification.require 取资格与检查身份；任一侧拒绝即原码透传，不出读数
4. 两侧各经 ledger.daily_returns 取交易窗口账户日收益；某侧不可用即 COMPARISON_UNAVAILABLE 并附该侧局限
5. 核两侧日钟逐日相同，否则 CLOCK_MISMATCH；读当前账本提交哈希
6. 以对照、候选两序列、登记的 comparison 与网格点数调用 report.paired；附账户年化差、登记时间、研发父版本、读数代码版本、本模块源码哈希与两侧资格后返回。全程不写账本

| 拒绝码 | 条件 |
|---|---|
| `NO_CONTROL` | 登记体 control_run 为空（根登记或声明暂无对照的修复派生），或对照运行不存在 |
| `RUN_NOT_IN_GRID` | 候选运行的试验不在本登记的 registration_attempt 中，或绑定记录的源码哈希与运行源码哈希不符 |
| `RUN_NOT_PASSED` | 任一侧运行 status 非 passed 或试验 purpose ∉ \{research, validation\}（由 registration.check_comparable 抛出并透传） |
| `COMPARABILITY_MISMATCH` | 任一侧的运行环境摘要、有效配置或输入内容身份与登记记录不一致（由 registration.check_comparable 抛出并透传，消息列冲突项） |
| `ECONOMIC_EVIDENCE_UNAVAILABLE` | 任一侧无实质活动或缺匹配记录、执行捕获记有失败、绑定源码审查记为失败（由 qualification.require 抛出并透传，附原因） |
| `COMPARISON_UNAVAILABLE` | 任一侧交易窗口日收益为空、非法或复利不等于期末权益；或 report.paired 判定天数不足两个完整块 |

### `holm` [#def-report-holm]

同一样本外窗口登记族（窗口起止与 universe_rule 相同）的 Holm 逐步校正 p：排序后取 p_(k)·(m−k+1) 的逐步最大值并截到 1，按原顺序返回；族成员由调用方从账本登记行取得

```python
def holm(p_values: Sequence[float]) -> list[float]
```

<TypeTable type={{ "p_values": { type: "Sequence[float]", description: "族内有 p 的成员的原始单侧 p，顺序与调用方的成员列表一致；m 为列表长度" } }} />

**返回**　list[float]：与输入等长、按原顺序排列的 Holm 校正 p，每个值在 [0, 1]

**期望行为**

1. 核列表非空且每个值是 [0, 1] 内的有限数，否则 COMPARISON_UNAVAILABLE。
2. 按原始 p 升序排序并记原位置；第 k 小的 p 乘以 (m−k+1)。
3. 自小到大取逐步最大值使序列单调，并截断于 1。
4. 按原位置还原顺序返回；不做通过判定，不增减族成员。

| 拒绝码 | 条件 |
|---|---|
| `COMPARISON_UNAVAILABLE` | 列表为空，或含非有限值、负值或大于 1 的值 |

### `paired` [#def-report-paired]

配对循环块自助：取两侧账户日收益的对数差，按登记块长循环分块、两侧共用同一组块起点共同重抽；报效应（平均日对数差与由之换算的年化差）、基本区间与嵌套学生化区间、年化差百分位区间、单侧 p 与网格 Bonferroni p、半倍/一倍/两倍块长敏感性、差值集中度、80% 功效（未校准示例值）可分辨效应与固定局限句；不返回任何裁决字段

```python
def paired(
    left: Sequence[float],
    right: Sequence[float],
    design: dict,
    grid_points: int,
) -> dict
```

<TypeTable type={{ "left": { type: "Sequence[float]", description: "对照侧交易窗口账户日简单收益，按 UTC 日历日排列" }, "right": { type: "Sequence[float]", description: "候选侧账户日简单收益，与 left 日钟逐日对应、等长" }, "design": { type: "dict", description: "登记锁定的检验条件：method（paired-circular-log-mean-v1）、block_days、resamples、inner_resamples、seed、alpha、minimum_effect（年化收益比例，仅描述）、design_reason；数值为未校准示例值" }, "grid_points": { type: "int", description: "本次登记网格点数（≥1），用于 Bonferroni 校正与区间覆盖调整" } }} />

**返回**　dict：\{method, days, mean_daily_log_difference, mean_log_basic_interval, mean_log_studentized_interval | None, annual_return_difference, annual_return_difference_interval, interval_coverage_grid_adjusted, p_one_sided | None, p_bonferroni | None, predeclared_alpha, predeclared_minimum_effect, detectable_mean_log_difference_80pct_normal_approx, top_five_absolute_difference_share, block_sensitivity[\{block_days, available, mean_log_interval?, p_one_sided?\}], degenerate_nested_samples, design, limitations[]\}；无任何裁决、采纳或排序字段

**期望行为**

1. 经 registration.validate_design 校验 design，核 grid_points 为正整数；核两序列一维、等长、天数不少于 2×block_days、全部有限且大于 -1，否则按 refusals 拒绝。
2. 两侧取 log(1+r)，差为候选减对照，观测效应为差的均值；年化差 = exp(365·候选平均日对数收益) − exp(365·对照平均日对数收益)。以 seed 建随机源，按 block_days 与 resamples 生成循环块起点索引矩阵，两侧共用。
3. 外层：按同一索引重抽两侧得均值差分布与标准误 se，减观测效应得中心化分布；单侧 p =（中心化值 ≥ 观测效应的次数 + 1）/（resamples + 1）；α′ = alpha/grid_points 下给基本区间、年化差百分位区间与 interval_coverage_grid_adjusted = 1 − α′；p_bonferroni = min(1, p·grid_points)。
4. 嵌套：每个外层重抽内以 inner_resamples 次内层块自助估标准误并算学生化统计量，由其分位数乘 se 给学生化区间；se 退化时 p、p_bonferroni 与学生化区间留空，任一内层退化时学生化区间留空并计入 degenerate_nested_samples，均写入 limitations，不以其他区间替代。
5. 稳健性：对 max(1, ⌊block_days/2⌋)、block_days、2×block_days 各以 seed 重建随机源重做外层重抽，报基本区间与单侧 p，天数不足两块的档标 available=false；报绝对日对数差最大五日占总和比例；报 se·(z_\{1−α′\}+z_\{0.8\})。
6. 附 predeclared_alpha、predeclared_minimum_effect、完整 design 与固定局限句（Bonferroni 只覆盖本网格；p 是零模型尾概率，不是策略有效的概率；自适应搜索后的开发窗口比较不是独立验证；块自助假定日差近似平稳弱相关；年化差区间不检验最小改进）后返回；不写账本。

| 拒绝码 | 条件 |
|---|---|
| `REGISTRATION_INVALID` | design 字段不恰为八项、method 不是 paired-circular-log-mean-v1、整数字段低于下限、alpha 不在 (0, 0.5)、minimum_effect 非有限或为负、design_reason 为空（由 registration.validate_design 抛出）；或 grid_points 不是正整数 |
| `COMPARISON_UNAVAILABLE` | 两序列不等长或非一维；天数少于两个完整块；任一值非有限或不大于 -1 |

### `single` [#def-report-single]

单序列循环块自助：对样本外窗口内账户日收益报日对数收益均值与年化夏普的基本区间、嵌套学生化区间、半倍／一倍／两倍块长敏感性，以及均值不大于零的单侧 p；缺日或不足两个完整块即不可用；不返回裁决

```python
def single(
    returns: Sequence[float],
    design: dict,
    family_size: int,
) -> dict
```

<TypeTable type={{ "returns": { type: "Sequence[float]", description: "样本外窗口内交易段账户日简单收益，按 UTC 日历日排列且无缺日（调用方经 ledger.daily_returns 取得并对账）" }, "design": { type: "dict", description: "样本外登记锁定的检验条件：method、block_days、resamples、inner_resamples、seed、alpha、minimum_effect、design_reason" }, "family_size": { type: "int", description: "同窗口检验族大小 m，缺省 1；区间覆盖率取 1−alpha/m" } }} />

**返回**　dict：\{method, days, mean_daily_log, mean_log_basic_interval, mean_log_studentized_interval | None, sharpe_annualised, sharpe_interval, p_one_sided | None, interval_coverage, block_sensitivity[\{block_days, available, mean_log_interval?, p_one_sided?\}], degenerate_nested_samples, predeclared_alpha, predeclared_minimum_effect, design, limitations[]\}

**期望行为**

1. 经 registration.validate_design 校验 design，核 family_size 为正整数；核序列一维、天数不少于两个完整块、全部有限且大于 -1，否则 COMPARISON_UNAVAILABLE。
2. 取日对数收益，观测统计为均值与年化夏普（均值除以标准差，按 365 个日历日开方年化）；按 seed 建随机源，用与 report.paired 相同的固定块长循环块索引做 resamples 次重抽。
3. 外层：重抽的均值与夏普分布减观测值得中心化分布；单侧 p 为中心化均值不小于观测均值的频数加一平滑；按 1−alpha/family_size 给均值与夏普的基本区间。
4. 嵌套：每个外层重抽内以 inner_resamples 估标准误得学生化区间；外层标准误退化时 p 留空，内层退化时学生化区间留空并计数写入 limitations，不以其他区间替代。

6. 附登记的 alpha、minimum_effect、完整 design 与固定局限句（p 是零模型尾概率，不是策略有效的概率；检验条件为方法示例值，未校准；单序列块自助假定近似平稳弱相关）后返回。

| `REGISTRATION_INVALID` | design 字段、方法名、整数下限、alpha 范围、minimum_effect 或设计理由不合法（由 registration.validate_design 抛出） |
| `COMPARISON_UNAVAILABLE` | 序列非一维、天数少于两个完整块、任一值非有限或不大于 -1，或 family_size 不是正整数 |
