# 待定与待验证事项

## 状态怎么读

本页列出仍有证据缺口的事项，不是待开发功能表。以下说明区分三个层面：

- **已实现／已合入**：代码、skill 或文档已经存在；合入只表示修复进了代码。
- **工程测试／技能评测通过**：只支持记录中注明的版本、用例和场景。用例存在不等于已运行，历史评测通过也不保证当前所有会话都遵从。
- **仍待真实场景验证**：尚缺指定研究路径或市场场景的执行证据。工程测试、合成原生验收和状态文档回读不代替完整真实场景验证。

因此，已实现或已有评测通过记录的能力仍可能列在这里；实际数据缺口也不会因规则确认而消失。

## 数据缺口（规则已定）

这两项是市场数据本身的缺口，与账本代数无关。

- **W** 具体合约的下架结算价证据　<Ref id="W.3.2.2" /> 的证据标准和缺证据时的清仓撤单边界已定；没有官方最终价格、或缺完整官方算法及输入的合约，仍记为数据缺口。规则确定不等于已取得全部真实结算价。
- **W** 推算报价的逐合约适用性证据　<Ref id="W.1.2.1" /> 的边界已定；仍需按具体合约、时段、杠杆敞口与强平情景取得真实买卖报价对照及匹配的原生回放结果。低活跃度不自动禁用，缺证据不自动删币缩窗，也不视为已验证。
