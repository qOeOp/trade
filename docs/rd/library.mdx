# L　策略库：候选谱系的根节点从哪来，怎样作为候选入账，又怎样得到第一份可供比较的报告。

<p className="rd-translation-note">English translation pending: this page shows the Chinese source text.</p>


本章定义候选谱系（lineage）的根节点（root）从哪来、怎样得到首份报告。根只有两类：有公认一手出处（primary source）的原版模板，与用户发起并提供信息源的人造根（artificial root）。转写由 skill 指导、eval 核验，出处原件以证据包入账本（ledger）；发布与首次回放由代码与账本强制：经唯一发布入口入账、无研发父版本（parent）即根，预检与审查后登记并回放一次，封存首份报告。出处只是外部依据，不为参数背书；何时选模板作根由用户在入口决定。

## L.1　从出处或用户信息源转写成根文件 [#L-1]

本节把一个有出处的策略形态变成一份守策略文件契约（<Ref id="C.1.1.1" />）的根文件（root file），交给 <Ref id="L.2.1.1" /> 发布。顺序是收录→核实→重写与文件头→（用户信息源时）发起与转写。收录只认有公认一手出处（primary source）的原版形态并定首批名单；核实把每个默认参数钉到出处原件的具体位置，核实不了的模板换候补；重写按出处从头写成单文件，出处未定而运行所需的部分作为实现者选择（implementer choice）补上，并在文件头九组立场行里标出每行是出处原话、实现者缺省还是研究者推广。人造根（artificial root）由用户发起并提供信息源，之后走与模板完全相同的核实、重写与文件头规则。全部四个组件由 skill 指导、eval 核验；代码与账本只在两处介入：出处原件先以证据包入账本（<Ref id="H.2.3.1" />），原生执行正确只由原生预检 <Ref id="replay.precheck" /> 与独立源码审查 <Ref id="registration.record_review" /> 给出。数据流：出处原件→证据包（<Ref id="table:evidence_bundle" />）→参数—出处定位表→根文件（含文件头）→<Ref id="L.2.1.1" /> 发布→<Ref id="L.2.2.1" /> 登记并回放一次。

</Step>

</Step>

</Step>

### L.1.1　收录 [#L-1-1]

两条能力都是 skill 规则：收录标准（一手出处、原版形态、不要求有效）与首批名单。输入是候选形态及其出处链接，输出是待核实的模板清单（每项带出处定位）；无代码或账本检查。eval 核 Agent 不把出处写成本市场实证。

<Cap id="L.1.1.1" kind="skill" tier="verified" tierLabel="已验证" title="只收有公认一手出处的原版形态">

策略库（template library）只收录有公认一手出处的原版形态，出处限三类：原始论文（DOI 或 arXiv 可解析）、作者公开发表的规则文本、交易平台的官方说明页。输入是一个候选形态与其出处链接；输出是待核实清单中的一项（形态名、出处类型、出处定位）或一条不收原因。没有公认原版的形态不收，例如单腿资金费策略、加密市场的开盘区间突破：这类形态只能作为研究路线内的假设由 <Ref id="H.2.1.1" /> 查来源后提出，不进策略库。判断是否存在公认原版前先按 <Ref id="research-round/SKILL.md#sources-first" /> 与 <Ref id="research-sources/SKILL.md#which-source" /> 检索论文与可信实践，否定结论只写按这些查询没找到。模板不要求在本市场有效：出处在理由三分类 <Ref id="research-round/references/source-evidence.md#three-classes" /> 中记为外部依据（external basis），只证明作者研究了什么，不证明规则或默认参数在本市场有效，也不为任何参数值背书；有效与否只由 <Ref id="L.2.2.1" /> 的首份封存回放和后续派生候选的比较证据给出。由 skill 强制；eval <Ref id="eval:research-round/template-attribution-not-backing" /> 核收录说明与文件头是否把出处写成了实证或参数依据。

### L.1.2　核实 [#L-1-2]

核实分三件事且不互相代证：源码与规则说明一致、规则忠实出处，由转写者对照一手出处原件给出并由 skill 指导、eval 核验；原生执行正确只由原生预检与独立源码审查给出，由代码封存预检原件、由账本只追加审查结论。输入是待核实模板（或根文件）与已入账本的出处原件，输出是参数—出处定位表、可发布的根文件与预检审查证据包。

<Cap id="L.1.2.1" kind="skill" tier="verified" tierLabel="已验证" title="默认参数逐项对照一手出处核实">

每个默认参数（回看周期、倍数、阈值、入场条件、出场条件）逐项对照一手出处核实，记下出处内的位置（页码、节号、公式号或页面锚点），形成参数—出处定位表；输入是待核实模板与已入账本的出处原件（<Ref id="H.2.3.1" />），输出是定位表，随根文件进入文件头（<Ref id="L.1.3.3" />）与发布说明（<Ref id="L.2.1.2" />）。任一参数无法在出处定位则该模板不收，换下一个候补并记不收原因；不得凭记忆、二手转述或估计取值，也不得用社区常见默认值补。出处以文字未给默认值而页面控件给出的（平台说明页常见），定位写到控件所在页面与字段名。由 skill 强制；eval <Ref id="eval:research-round/template-params-verified-or-dropped" /> 核每个参数有定位、无定位即弃。

根文件要核三件事，分开核、不互相代证：(1) 源码与规则说明一致；(2) 规则忠实出处；(3) 原生执行正确。(1) 与 (2) 由转写者对照出处原件与根文件给出，结论写入发布说明（<Ref id="L.2.1.2" />）。(3) 只由两项给出：原生预检 <Ref id="replay.precheck" />——对已发布的根候选，以 purpose=precheck 写一条试验并在锁定引擎与实际运行环境里跑最小预检，封存原生输出、退出码、审计与报告——和独立源码审查 <Ref id="registration.record_review" />——另一个 Agent 对预检原件按接口、因果、活动、就绪四项给结论并绑定源码哈希与运行环境身份只追加入账本。静态编译通过、干净退出或转写者自述都不算执行正确。预检内容与审查四项对模板和派生候选相同（<Ref id="research-round/references/strategy-authoring.md#precheck-and-review" />），且都是登记（<Ref id="L.2.2.1" />）的前置：缺预检或任一审查项不通过，登记拒绝。预检失败或审查不通过时修复源码并按 <Ref id="L.2.2.2" /> 以新源码发布为新根，不记经济负面。(1)(2) 由 skill 强制；(3) 由代码（预检封存）与账本（审查结论只追加、登记前置）强制。

### L.1.3　重写与文件头 [#L-1-3]

三条都是 skill 规则，输出一份守策略文件契约的根文件：规则与默认参数照出处从头重写并补上运行所需的实现者选择；记录作者决策依赖的条件与所用出处版本；文件头写可定位出处，并在九组立场行里标出出处原话、实现者缺省与研究者推广。输入是参数—出处定位表、出处原件与实现者选择清单，输出是根文件源码与文件头。eval 由策略文件契约的 header-nine-groups、hard-contracts-declared 与本节的 template-no-unsourced-additions 覆盖。

<Cap id="L.1.3.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺：模板按出处重写的实例与对照出处的独立复核记录。" title="照出处从头重写，实现者选择列明">

规则与默认参数照出处原样从头重写为一份守策略文件契约的单文件（<Ref id="C.1.1.1" />），输入是核实过的参数—出处定位表与出处原件，输出是根文件源码。三不：不复制出处附带的或任何第三方代码；不补出处没有的止损、止盈；不加没有出处的过滤、确认条件或参数。原版不设止损的，在源码里声明不设止损（<Ref id="C.4.1.1" />），裸仓只报告不拒绝；原版设止损的，每个持仓时刻的只减仓止损覆盖按 <Ref id="research-round/references/strategy-authoring.md#stop-coverage" />。运行所需而出处未定的部分作为实现者选择补上，每项写一句理由并在文件头标为实现者缺省：仓位与资金预算规则（<Ref id="C.1.4.2" />）、成员变化时旧仓旧单处置（<Ref id="C.1.4.3" />）、同账户多机会共享资本分配（<Ref id="C.1.4.4" />）。实现者选择不得改变出处给出的入场、出场或参数。由 skill 强制；eval <Ref id="eval:research-round/template-no-unsourced-additions" /> 核规则与参数相对出处无增删改、三项实现者选择各有理由；eval <Ref id="eval:research-round/hard-contracts-declared" /> 核三条硬契约写明。

### L.1.4　发起与转写（人造根） [#L-1-4]

人造根由用户发起并提供信息源，Agent 不主动提议；随后按模板同一套核实、重写与文件头规则转写成一个策略文件，用户来源记为外部依据。两条都是 skill 规则：发起在入口 skill，转写在研究 skill；输出进入 <Ref id="L.2.1.1" /> 发布。

<Cap id="L.1.4.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺：用户发起人造根并完成转写、发布与首次回放的执行证据。" title="人造根由用户发起并提供信息源">

人造根（artificial root）由用户发起并提供信息源（文档、文章、视频笔记或用户自述的规则）；Agent 不主动提议建人造根，也不要求信息源是公认原版——用户的信息源就是它的出处。入口的分工按 <Ref id="research-start/SKILL.md#user-selects-route" />：选项由 Agent 提、选由用户，用户选定前不登记不回放；用户明确授权一次即够，之后的转写、发布、登记与首次回放不再请求（<Ref id="E.4.1.2" />）。输入是用户信息源与一次授权；输出是交给 <Ref id="L.1.4.2" /> 的转写任务（信息源原件以证据包入账本，<Ref id="H.2.3.1" />）。由 skill 强制；eval <Ref id="eval:research-start/artificial-root-user-initiated" /> 核无用户信息源时不提议、有授权后不重复请求。

## L.2　发布为根并出首份报告 [#L-2]

根节点（root）从 L.1 的转写产物开始，走与所有候选（candidate）相同的两步：发布与首次回放。发布由代码与账本（ledger）强制：源码字节经唯一的发布入口只解析不执行地核对后原样入账，以源码内容哈希（content hash）唯一，不带研发父版本（parent）与改动说明即根；发布说明的内容由 skill 规定（规则、来源声明、非声明）。首次回放由代码强制顺序：原生预检（native precheck）与独立源码审查先于登记（registration），登记在当前开发窗口（development window）以无父、无比较对照（control）锁定一个点，回放入口绑定该点、在钉死的运行环境（runtime image）内回放、完整性审计后封存（seal）运行（run）与原生报告，资格在读取时判定。skill 只规定根怎样用这条路径：不编造对照，不以探索回放当首份报告，故障修复后以新源码重新发布为新根。输出是候选引用 strategy_id@revision 与一份封存的首份报告，供入口推荐与后续候选作比较对照。

<Steps>

<Step>

1. 把守策略文件契约的根文件与发布说明交给发布入口；解析核对通过后原样入账，得到 strategy_id@revision 与源码内容哈希；相同字节返回先前候选的引用。

</Step>

<Step>

2. 对该候选做原生预检（purpose=precheck）并封存原生输出；独立 Agent 按四项审查，结论绑定源码哈希与运行环境身份写入账本。

</Step>

<Step>

3. 在当前开发窗口登记：父版本为空、对照为空、网格只含该根一点，带预检与审查引用，锁进不可变登记证据。

</Step>

<Step>

4. 回放入口写试验行（purpose=research）并绑定该登记点，在钉死的运行环境内回放，完整性审计，封存运行与原生报告（含原生 stdout/stderr/退出码）。

</Step>

<Step>

5. 读取时按检查身份判实质活动与可比资格；根的报告无比较读数，供入口推荐并作后续候选的比较对照，回放计入试验计数。

</Step>

<Step>

6. 预检、审计或资格暴露的故障只修复：新源码重新发布为新根并重走 1–5，原根的运行保留为历史。

</Step>

</Steps>

### L.2.1　发布为根 [#L-2-1]

发布由代码与账本强制：发布入口对源码只解析不执行地核对后写候选表一行并提交，唯一约束与 CHECK 保证相同字节不成两个候选、父版本与改动说明同空即根。发布说明的内容由 skill 指导。输入是根文件与发布说明，输出是候选引用 strategy_id@revision 与源码内容哈希。

<Cap id="L.2.1.1" kind="database" tier="rehearsal" tierLabel="演练证据" title="经同一发布入口入账，无父即根">

策略库模板根与人造根（artificial root）经 <Ref id="ledger.publish_candidate" /> 入账，与派生候选同一入口。输入：根文件的源码字节、发布说明；不带研发父版本与改动说明。处理：先由 <Ref id="ledger.check_source" /> 只解析不执行地核对（源码非空且在上限内、可解析为 UTF-8 Python、恰有一个与声明同名的顶层类），通过后把字节原样写入 <Ref id="table:candidate" /> 一行，由 <Ref id="ledger.write" /> 在一个事务里提交为账本的一个提交。输出：候选引用 strategy_id@revision 与源码内容哈希。拒绝：解析核对不过（码由 <Ref id="ledger.check_source" /> 定）；相同字节已是某个候选时拒绝并返回那个候选的引用（SOURCE_EXISTS）；父版本与改动说明只给其一（候选表的 CHECK 要求二者同空或同非空，码由 <Ref id="ledger.publish_candidate" /> 定）；并发写冲突。根没有专门的模板表、初始化批量写入或系统／人造节点标记：父版本与改动说明同空就是根的全部定义，来源类型只在文件头与发布说明里（<Ref id="L.2.1.2" />）。账本的单元格级历史（dolt_history_candidate）证明根的字节与父字段自发布起从未被改；修复后的根是重新发布的新候选，不改旧行（<Ref id="L.2.2.2" />）。强制层：代码（发布入口与解析核对）与账本（唯一约束、CHECK、只追加提交）。策略源码只存账本，不进代码仓库（<Ref id="J.1.2.2" />）。

### L.2.2　首次回放 [#L-2-2]

首次回放由代码强制顺序：预检与独立审查 → 登记（无父、无对照）→ 回放入口绑定登记点 → 完整性审计 → 封存 → 读时资格。skill 只规定根用这条路径：不编造对照，不以探索回放当首份报告，故障修复后以新源码重新发布为新根。输入是候选引用与当前开发窗口，输出是封存的运行与原生报告。

<Cap id="L.2.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="在当前开发窗口以无父、无对照登记并回放一次">

每个根在当前开发窗口登记一次并回放一次。登记经 <Ref id="registration.register" />：研发父版本为空、比较对照为空、网格只含该根一个点、窗口等于当前研究路线（research line）的开发窗口，带预检与审查引用；<Ref id="registration.validate" /> 对根的核对是「根不得带对照」，带了拒绝。回放经 <Ref id="registration" /> 入口：写试验（trial）行（purpose=research）的同一事务里由 <Ref id="registration.bind" /> 绑定该登记点，在钉死的运行环境内回放，<Ref id="replay.audit_problems" /> 汇总无效原因，完整封存运行与原生报告（含原生 stdout/stderr/退出码）。输出：一条消耗了该登记点的 <Ref id="table:registration_attempt" /> 行与一个封存的运行；无效与中断同样消耗该点，再试另登记。根的运行没有比较读数（无效应、区间、p）；它的报告供入口推荐（<Ref id="E.3.1.2" />）并作后续候选的比较对照。根的回放计入全部试验计数，计数由 <Ref id="report.research_status" /> 从账本按用途统计（口径在 R 章）。强制层：登记与绑定由代码强制；skill 规定不为根编造对照，不以 purpose=explore 的回放当首份报告；eval <Ref id="eval:research-round/root-registered-without-control" />。

## 待定事项 [#L-pending]

**待用户定**

- **候补名单从哪来、由谁定**　可由 Agent 按 <Ref id="L.1.1.1" /> 的收录标准提候补、用户选，尚未定；<Ref id="L.1.2.1" /> 只写换下一个候补并说明原因。

- **不进文档**　一手出处类型与不收形态的例子：不单列成节；收与不收的例子写进 <Ref id="L.1.1.1" /> 的规则正文。
- **不进文档**　出处列表与参照的因子库：不单列成节；经核实的出处作为一手出处例子放 <Ref id="L.1.1.1" /> 的依据，机制未核实的因子库参照与引擎仓库链接不作出处。
