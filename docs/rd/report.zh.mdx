# 8　报告：一次运行跑完并通过审计后，把它的成绩算出来、摆出来：有哪些数，谁算，按什么口径，只呈现不裁决。

报告接在第 7 章之后。只有通过完整性审计、又具备经济证据资格的运行，才有绩效指标；绩效指标就是年化、夏普、回撤、胜率这类成绩数。报告只把这些数摆出来，不判好坏，也不说该不该采纳。单运行报告和第 10 章的对比报告用同一套栏目（<Ref id="R.3" />）。

这一章讲三件事。先分工：哪几项由产品代码算、封存时算一次存进账本，哪些描述统计由 Agent 按 skill 自己算、还要交给别人复算。再定口径：年化、夏普、计划胜率、最大回撤、利润来源和资金使用率各按什么分母、什么总体、什么采样来算。最后给模板：报告按固定栏目输出，算不出的栏留着写原因。

举个例子：全池 RSI 路线里，H09 的报告给出年化 4.24%、最大回撤 8.44%。光看这两个数还不够。报告同时列出闭仓收益里将近一半来自资金费；再配上同一运行的资金使用，平均名义敞口约 4161 USDT。读的人能看出它赚的钱从哪来、用了多少资金，再自己判断。

## 8.1　绩效指标分工：谁算、怎么保证可信 [#R-1]

哪些成绩数由产品代码算、哪些由 Agent 自己算，以及各自怎么保证可信。

</Step>

<Step>

</Step>

<Step>

### 产品算的绩效指标 [#R-1-1]

代码只算 Agent 不该给自己打分的那几项，封存时算一次，读回时按资格决定给不给看。

#### 产品只算四类 Agent 不该自评的绩效指标 [#R-1-1-1]

代码只算四类：账户年化、标记价最大回撤、计划胜率、利润来源拆分。利润来源拆成价格盈亏、手续费、资金费三项。每类都附上总体（统计的是谁）、样本量、局限清单和计算版本；某一项算不出来，只把这一项置空并写明原因，运行本身不会因此被拒绝。

这几项直接用来比较和推荐。让 Agent 自己算，就等于自己给自己打分。

#### 绩效指标在封存时算一次，之后只读不重算 [#R-1-1-3]

封存时，代码把绩效指标算一次，连同计算代码的版本一起存进账本。之后任何读取都不重算、不覆盖；无效运行不存指标。复核时用当时那个代码版本重算比对，不一致只报告差异，不改存好的值。

如果每次读都重算，算法一改，旧运行的成绩就悄悄变了，以前的比较和推荐也跟着失去依据。所以口径改了，只影响之后封存的运行。

#### 没有经济证据资格的运行，绩效指标整体置空 [#R-1-1-4]

### Agent 自算的描述统计 [#R-1-2]

代码给一个统一的读取入口，从封存的原生报告取表并注明账本版本；其余统计 Agent 自己算，代码只管按资格遮蔽，不核对结果。

#### 描述统计只从产品解析好的表里算 [#R-1-2-1]

Agent 自己算的描述统计，只能从读取入口（<Ref id="report.tables" />）给出的表里取数：订单、成交、持仓周期、账户、开发窗口的日收益、敞口。每次都注明它返回的账本版本。持仓时长用持仓周期自带的时长，出场原因读平仓订单的标签。

### 年化、夏普与计划胜率 [#R-2-1]

年化和夏普由引擎写进原生摘要，计划胜率在封存时算；三项都只算开发窗口，不含预热段。

#### 年化按开发窗口的实际天数复利折算，分母是初始权益 [#R-2-1-1]

年化 ＝（期末权益 ÷ 初始权益）的（365 ÷ 窗口天数）次方 − 1。窗口不含预热段，天数按实际时长算，不取整。期末权益取引擎的组合快照，包括没平仓的浮动盈亏。

窗口不满一年时，按实际天数折算，不同长度的窗口才能放在一起比。期末权益不为正时，这个公式没有意义，年化留空写原因，运行不会因此判无效。

#### 计划胜率＝已平仓且算上费用后赚钱的计划 ÷ 全部计划 [#R-2-1-3]

计划就是策略用标签划出的一笔完整交易。一个计划算「赢」，要已经平仓，且算上手续费和资金费后的已实现盈亏大于零。分母包括已平和没平的计划，期末还没平的算「没赢」。每张订单恰好带一个计划标签，一个计划只交易一个合约。

### 最大回撤 [#R-2-2]

最大回撤按每根 K 线的标记价权益来算，并写明用的是什么价、多久采一次。

<a id="R-2-2-1" />

**最大回撤看每根 K 线的标记价权益，比峰值最多跌了多少**

回撤 ＝（峰值 − 权益）÷ 峰值，取窗口内的最大值，峰值从初始权益算起。权益 ＝ 账户余额 ＋ 没平持仓按标记价算的浮动盈亏。标记价就是交易所算保证金和强平用的那个价。

交易所按标记价算保证金和强平。只看账户余额，就看不到持仓中途的浮亏，会低估回撤。缺标记价或者估值时点对不齐，完整性审计就不通过。

skill 规定资金使用率怎么算、怎么和回撤一起读；算它用的数据可信，由代码保证。

#### 资金使用率由 Agent 从封存的敞口表自己算四项，产品不存 [#R-2-3-1]

资金使用率由 Agent 经读取入口，带上敞口和账户数据（<Ref id="report.tables">tables(run_id, exposures=True, account=True)</Ref>）自己算，产品不存这个指标。敞口表每行标在 K 线时刻 T，表示到下一根 K 线之前所有事件发生后还持有的仓位，按 T 的标记价估值；字段是引擎原生的名义额、浮动盈亏和所属持仓周期。某根 K 线没有行，就是空仓。T 时刻的权益，等于下一根 K 线之前最近一条账户状态的总额，加上 T 的浮动盈亏。

回撤小可能只是钱几乎没用上，不读资金使用就会看错。Agent 不重新给仓位估值，也不只凭账户报告推算资金使用。读取入口给的敞口为空时，这次运行不回答资金使用问题，并写进局限；读取入口拒绝时（没通过审计、对账不平或敞口有缺陷），Agent 不分析这个运行，改为报告缺陷。从谱系里第一个有效的根候选起，每个有效运行都主动算；仓位或资金预算规则改了，必须算。这条由 skill 规定，用评测用例检查。

<div className="rd-example">

全池 RSI 路线里，H09 在全部 523230 个交易分钟上（空仓的分钟也算）平均名义额约 4161 USDT，按分钟采样的峰值约 40229 USDT。这个峰值是按分钟采的，不是真实的盘中极值，也不是保证金。这些数事后经过另一个 Agent 复算。

</div>

1. 名义额在开发窗口全部 K 线上的时间加权平均：从交易起点算，空仓的 K 线计零，同时给出占同一时刻权益的比例。
2. 采样峰值：写明是按 K 线采样的峰值，不是逐笔的极值。
3. 锁定保证金：取自账户数据，包括挂单占用的部分。
4. 在市时间：有敞口的 K 线根数占开发窗口根数的比例。

#### 回撤用产品算的值，而且必须和同一运行的资金使用率一起读 [#R-2-3-2]

回撤以产品算的标记价最大回撤为准，Agent 不为任何比较或目标重算。读回撤时，必须同时给出同一运行按 <Ref id="R.2.3.1" /> 算的资金使用率。比较两个候选时，回撤下降的同时平均名义额或在市时间也下降，只能写成「敞口下降」，不写成风险效率提高或风控改善。

敞口小了，回撤自然小，这不是风控变好。只有两边敞口相当时，才能把回撤的差别归到规则改动上。净收益除以平均名义额只作描述，要写明分母，不用来排序，也不当推荐的主要依据。

<div className="rd-example">

全池 RSI 路线的 H08 最大回撤只有 0.62%，看起来很稳；但它平均名义敞口只有 393.72 USDT，约为初始 10 万的 0.39%。按这条规则，它只能写成「敞口很小」，不能写成「风险控制好」。

</div>

### 单运行报告和对比报告按同一组栏目输出 [#R-3-1-1]

报告固定一组栏目和顺序，单运行和对比共用。单运行给本次的值；对比给两边并列的值和差。检验结果、交易配对、预测对照三栏只出现在对比报告里。栏目来自第 10 章的归因切面目录。

没有固定栏目，每次报告拆什么、拆多深全凭 Agent 临场决定，有的版本拆得细，有的一笔带过，前后没法比，也容易只挑对自己有利的角度。

<div className="rd-example">

全池 RSI 路线 H07 对 H06 的利润来源一栏，账户口径的差是：价格 −281.67，手续费 ＋119.38，资金费 ＋828.73，期末浮动 −8.62，合计 ＋657.82 USDT。这一栏让人一眼看出：资金费多出的部分比总改善还大，价格腿反而变差了。

</div>

1. 身份与资格：单运行给运行身份、经济证据资格和原因；对比给两边身份和可比资格。
2. 检验结果：只在对比报告里，给效应、区间、p 和检验条件（<Ref id="V.4.1.1" />）。
3. 绩效指标：单运行给年化、标记价最大回撤、计划胜率、夏普；对比给两边并列和差。
4. 利润来源：单运行给价格、手续费、资金费、期末浮动；对比给四项的差（<Ref id="P.1.2.1" />）。
5. 规模与仓位择时：单运行给平均敞口、单位敞口收益、水平项和择时项、涨月和跌月的敞口、年化与回撤之比；对比给各项的差（<Ref id="P.1.2.2" />）。
6. 费用：单运行给吃单占比、盈亏平衡费率倍数；对比给盈亏平衡费率倍数（<Ref id="P.1.2.3" />）。
7. 品种与方向：单运行给前五个合约占绝对盈亏的比例、多空分开列；对比给同样几项的差（<Ref id="P.1.2.4" />）。
8. 市场暴露：单运行给对等权篮子和 BTC 永续的斜率与截距；对比给斜率之差和截距之差（<Ref id="P.1.2.5" />）。
9. 时期：单运行给盈利月份占比、去掉最好五天后剩下多少；对比给胜出月份占比和剩余的差（<Ref id="P.1.2.6" />）。
10. 交易结构：单运行给周期数、胜率、平均赢亏、每笔期望、持仓时长、出场类别；对比给同样几项的差，以及每笔期望之差的拆分（<Ref id="P.1.2.7" />）。
11. 交易配对：只在对比报告里，给覆盖、删掉的和新增的交易、同一机会上的差（<Ref id="P.1.2.8" />）。
12. 回撤：单运行给最大回撤、持续天数、回撤期间的主导合约；对比给同样几项的差（<Ref id="P.1.2.9" />）。
13. 预测对照：只在对比报告里，给每项登记的预测与实测是否同方向；登记时声明了交互的，附上交互读数（<Ref id="P.2.1.2" />、<Ref id="P.3.1.2" />）。
14. 局限：单运行给合并去重的局限清单；对比把两边的局限合并去重。

### Agent 写报告和解释按模板栏目来，空栏写原因，不删栏 [#R-3-1-2]

Agent 写一次运行或一次比较的报告时，按模板的栏目顺序写。某一栏是空的，就留着这一栏，写明为什么空。

删掉空栏，读的人分不清是「没这个问题」还是「没算」。栏目顺序固定，不同报告才能对着看。

<div className="rd-example">

比如某次比较时，本地没有对应窗口的 BTC 日收益，市场暴露一栏算不出来。报告里这一栏照样保留，写明「缺 BTC 永续日收益，未算」，而不是直接跳到下一栏。

</div>
