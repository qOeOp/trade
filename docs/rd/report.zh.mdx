## R.2　四维与利润来源的口径 [#R-2]

### R.2.1　年化、夏普与计划胜率 [#R-2-1]

### R.3.1　资金使用率 [#R-3-1]

代码保证敞口行完整：封存时估值未覆盖计为完整性发现，读取时 <Ref id="report.tables" /> 校验网格与周期归属并在不符时拒绝。skill 规定资金使用率的算法（R.3.1.1）和它与回撤的联合解读（R.3.1.2）。输入是 tables() 返回的 exposures 与 account 行，输出是 Agent 写进反馈与推荐理由的描述读数。

<Cap id="R.3.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="从封存敞口表自算资金使用率">

资金使用率由 Agent 从 <Ref id="report.tables">tables(run_id, exposures=True, account=True)</Ref> 自算，产品不存这个读数。敞口行标为 K 线时刻 T，表示下一根 K 线时刻之前全部事件发生后仍持有的仓位，按 T 的标记价估值，字段是引擎原生名义额、未实现盈亏和所属持仓周期；某根 K 线没有行，就是空仓。读数有四项：(1) 名义额在交易窗口全部 K 线上的时间加权平均，从交易起点算起，空仓根计零，同时给出占同刻权益的比例；(2) 采样峰值，标明是按 K 线采样的峰值，不是逐笔极值；(3) 锁定保证金（margin），取自账户行，包含挂单占用；(4) 在市时间，即有敞口的根数占交易窗口根数的比例。T 时刻的权益等于下一根 K 线时刻之前最近一条账户状态的总额，加上 T 的未实现盈亏。Agent 不重新估值仓位，也不只凭账户报告推算资金使用。tables 返回的 exposures 为空（运行没有敞口表）时，这次运行不回答资金使用问题，并在读数局限里写明；tables 拒绝时（运行未通过审计、对账不平或敞口有缺陷），Agent 不分析该运行，改为报告缺陷。演练中，Agent 在全窗口上自算名义额，结果经过复算。从首个有效根起，每个有效运行都主动算；仓位或资金预算规则改动后必须算。由 skill 规定，eval 检查。

<Cap id="R.3.2.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺演练中实际计算这组读数的证据。" title="持仓结构">

### R.4.1　比较读数的呈现 [#R-4-1]

<Cap id="R.4.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="效应、区间、p 与检验条件并列">

### R.5.1　跨候选汇总 [#R-5-1]

代码强制汇总的输入：候选清单与研究计数只给事实、身份与当前资格，不给分数、排序或裁决，输入不符时按各自函数的拒绝码拒绝。skill 规定汇总的口径：非劣集只作描述，只在经济证据可用的候选上算，其余候选按 <Ref id="E.3.1.1" /> 分列。

<Cap id="R.5.1.1" kind="skill" tier="verified" tierLabel="已验证" title="多维非劣候选集只作描述读数">

Agent 对全部经济证据可用的候选自算多维非劣候选集（Pareto front）。总体：<Ref id="qualification.assess" /> 判为 economic_evidence_available 的运行，按同一开发窗口与同一共同可交易范围分组，跨窗口或跨范围不放进同一集合。维度固定四个：账户年化与标记价（mark price）回撤取运行行上的产品读数（<Ref id="R.1.1.3" />），夏普取引擎统计类结果（<Ref id="R.1.2.2" />），胜率取计划（plan）胜率。候选 A 支配 B，当且仅当 A 在四维上都不差于 B，且至少一维更好；集合由不被任何其他候选支配的候选组成。输出是描述读数：给出集合成员（strategy_id@revision）、每维数值、所读账本提交与总体规模。它不是资格边界，也不按单一指标排序；推荐（recommendation）可以落在集合之外，但须说明在成本、资金使用率、利润来源、机制解释或不确定性上的取舍。仅诊断、无效与未完成的候选不进入计算，分列给出。驱动推荐的集合须由第二个 Agent 独立复算（<Ref id="nautilus-report-analysis/SKILL.md#self-checks" />），还要提醒读者：集合是从许多候选里挑出来的（<Ref id="R.4.2.3" />）。由 skill 指导，eval 校验；无代码拒绝码。

可读摘要是研究状态清单的最新版，是合并了全部更正（correction）的简洁视图。清单按市场与开发窗口各一份，每次更新是一个新版本证据包（<Ref id="E.2.2.1" />）。摘要只写当前成立的表述：被更正的旧表述用更正后的内容代替，并留标记指向更正。后续读者（含入口与复盘）先读最新版摘要，按包名读并核哈希（<Ref id="research-start/SKILL.md#read-state-list" />）；需要细节或核对来源时，再按摘要里的引用经 <Ref id="ledger.load_bundle" /> 读原件，不默认读入全部原件。摘要缺失或落后于账本（引用的提交早于最新登记或运行）时，以候选清单与研究计数为准，并写一个新版补齐。由 skill 指导，eval 校验；无代码拒绝码。
