# 8　报告：一次运行跑完并通过审计后，把它的成绩算出来、摆出来：有哪些数，谁算，按什么口径，只呈现不裁决。

报告接在第 7 章之后。只有通过完整性审计、又具备经济证据资格的运行，才有绩效指标；绩效指标就是年化、夏普、回撤、胜率这类成绩数。报告只把这些数摆出来，不判好坏，也不说该不该采纳。单运行报告和第 10 章的对比报告用同一套栏目（<Ref id="R.3" />）。

这一章讲三件事。先分工：哪几项由产品代码算，其中哪些封存时算一次存进账本、哪些读时按当前代码现算，哪些描述统计由 Agent 按 skill 自己算、还要交给别人复算。再定口径：年化、夏普、计划胜率、最大回撤、利润来源和资金使用率各按什么分母、什么总体、什么采样来算。最后给模板：报告按固定栏目输出，栏目来自一套固定的切面，算不出的栏留着写原因。

举个例子：一个候选的报告给出年化和最大回撤。光看这两个数还不够。报告同时列出闭仓收益里有多少来自资金费；再配上同一运行的资金使用，比如平均名义敞口占初始资金的多少。读的人能看出它赚的钱从哪来、用了多少资金，再自己判断。

## 8.1　绩效指标分工：谁算、怎么保证可信 [#R-1]

哪些成绩数由产品代码算、哪些由 Agent 自己算，以及各自怎么保证可信。

### 产品算的绩效指标 [#R-1-1]

代码只算 Agent 不该给自己打分的那几项：推不出的读数封存时算一次，推得出的读时按当前代码算，读回时按资格决定给不给看；每项只有一个算者和一个时机。

#### 每项绩效指标只有一个算者和一个时机 [#R-1-1-1]

直接用来比较和推荐的绩效指标由代码算，Agent 只能读。谁算、什么时候算，全章只认下面这一份清单，别处只引用它。

- **引擎，回放结束时**：原生报告（订单、成交、持仓、账户、日收益、敞口、订单事件）和摘要，摘要里带年化和夏普（<Ref id="R.2.1.1" />、<Ref id="R.2.1.2" />）。原生报告是可重放的缓存，账本只存它们的语义指纹；摘要、审计结果和日志随执行封存（<Ref id="J.2.2.3" />、<Ref id="J.2.3.2" />）。
- **代码，封存时算一次并冻结**：原生报告移走后再也算不出的读数，即资格事实、标记价最大回撤及其区间和主导合约、资金使用峰值与在市时间、锁定保证金峰值、按挂单吃单分的手续费与成交额、订单漏斗、计划统计是否成立，连同逐日序列（日收益和当日平均名义敞口）和每个持仓周期一行（<Ref id="R.3.1.3" />）。
- **代码，读时按当前产品代码现算，不存**：账户年化、夏普、计划胜率、利润来源拆分（价格盈亏、手续费、资金费三项）、交易结构、资金切面，都从读数、逐日序列和持仓周期派生（<Ref id="R.1.1.3" />）。
- **Agent，按 skill 自己算**：目录以外的描述统计，从读取入口取表，更细的先重放到 `/tmp` 并核对指纹（<Ref id="R.1.2.1" />）；会左右决定的数要另一个 Agent 独立复算。

每项都附上总体（统计的是谁）、样本量、局限清单和计算版本；某一项算不出来，只把这一项置空并写明原因，运行本身不会因此被拒绝。

#### 利润来源拆分要逐项对上账，有一处对不上就整体不给 [#R-1-1-2]

代码在给出利润来源拆分之前，要逐项对账。任何一项对不上，整个拆分置空并写明原因，不给只对上一部分的结果：

1. 逐个已平的计划核对：价格盈亏 − 手续费 ＋ 资金费 ＝ 已实现盈亏。
2. 核对各计划的手续费合计和成交报表一致。
3. 核对已平计划的个数和原生摘要一致。
4. 和完整性审计算出的账户经济数逐项对账。
5. 任何一项不符，整个拆分置空并写明原因。

#### 读数在封存时算一次，代码改了只能经复现后重封替换 [#R-1-1-3]

封存时，代码把原生报告移走后再也算不出的指标（比如要用逐分钟权益的标记价回撤）连同其余读数算一次，和算它的产品提交一起存进运行读数（<Ref id="table:run_reading">run_reading</Ref>）。能从持仓周期和逐日序列算出的度量，比如年化和计划胜率，读的时候按当前产品代码的定义算，不另存。无效运行没有读数。

指标代码改了，旧运行的读数不会悄悄跟着变：只有 `replay reseal` 能替换它。它先按原镜像复现这个运行，每张原生报告都和封存的指纹一致，才用当前代码重算读数，在一个 `reseal:<操作>` 提交里替换；复现对不上就拒绝（`REPRODUCTION_MISMATCH`），读数不动。旧读数留在 Dolt 历史和公开副本里，按旧账本版本仍能读到。

#### 没有经济证据资格的运行，绩效指标整体置空 [#R-1-1-4]

读回报告时，代码按资格决定给什么。无效运行只留失败原因和原生摘要的引用。有效但没有实质活动（一笔交易都没发生），或者不可比的运行，指标整体置空，只留诊断。算不出或对不上的单项留空写原因，不猜，也不填占位数。

### Agent 自算的描述统计 [#R-1-2]

代码给一个统一的读取入口，从账本存的持仓周期和逐日序列取表并注明账本版本，原生明细要先重放；其余统计 Agent 自己算，代码只管按资格遮蔽，不核对结果。

#### 描述统计从持仓周期和逐日序列算，更细的先重放 [#R-1-2-1]

Agent 自己算的描述统计，从读取入口（`report.tables`）取账本里的持仓周期和逐日序列：持仓时长、出场类别、逐合约、逐月都从这里来。要看订单、成交或账户这类原生明细，先按复现清单把这次运行重放到 `/tmp`，语义指纹对上了才读（<Ref id="R.3.1.5" />）。每次都注明账本版本。不可用运行的经济数据已经被资格遮蔽，不能另找来源补算。

#### 夏普这类比率用引擎自带的统计工具，对开发窗口的日收益来算 [#R-1-2-2]

夏普、索提诺、卡玛等比率，以及它们分时段或滚动算的分布，都用引擎自带的统计类，对读取入口给的开发窗口的日收益来算。日收益按 UTC 日历日，不含预热段，按 365 天年化，不引入别的分析库。全程夏普以原生摘要里的值为准（<Ref id="R.2.1.2" />）；自算的和它对不上，先查口径，再引用。

#### 自算的数写明统计的是谁，要对上账；左右决定的数要独立复算 [#R-1-2-3]

Agent 自算的数，要写明总体（闭仓、持仓还是账户整体）、权重和频率。涉及闭仓经济的合计，必须等于读取入口给出的对账量，不等就不引用。用来做推荐或选下一个实验的数，要由第二个 Agent 从同一运行、同一账本版本独立复算，两者不一致就不下结论。

### 每个绩效指标附带什么 [#R-1-3]

每个绩效指标都带着算出它的代码版本和一份完整的局限清单。

#### 报告写明算指标和判资格各用的哪个代码版本 [#R-1-3-3]

读数记下算它的产品提交；资格判定在读回时用当前代码。资格判定还要注明用了哪项检查。两个版本不同时，报告把两个都列出来，谁也不替代谁。观察到的实际费率（按挂单和吃单分的手续费除以成交额）也在封存时算出，存在单运行报告里。

#### 局限清单去重后完整列出，不挑不删 [#R-1-3-4]

报告把四类局限合在一起：撮合和合约条款的局限、审计不查的范围、指标置空的原因、资格的局限。前三类封存时存进账本，资格局限在读回时并进来。去重后完整输出，不省略，也不按严重程度过滤。

## 8.2　年化、夏普、胜率、回撤与利润来源的口径 [#R-2]

固定年化、夏普、计划胜率、最大回撤、利润来源和资金使用率的算法：分母是什么、统计谁、怎么采样。

### 年化、夏普与计划胜率 [#R-2-1]

年化和夏普由引擎写进原生摘要；报告栏目里的年化、夏普和计划胜率由代码读时从逐日序列和持仓周期算；都只算开发窗口，不含预热段。

#### 年化按开发窗口的实际天数复利折算，分母是初始权益 [#R-2-1-1]

年化 ＝（期末权益 ÷ 初始权益）的（365 ÷ 窗口天数）次方 − 1。窗口不含预热段，天数按实际时长算，不取整。期末权益取引擎的组合快照，包括没平仓的浮动盈亏。期末权益不为正时，年化留空写原因，运行不会因此判无效。

#### 夏普用开发窗口的逐日收益算，按 365 天年化 [#R-2-1-2]

去掉预热段，只留开发窗口里按 UTC 日一天一个值的权益变化。用引擎统计类算夏普，按 365 天年化，因为加密永续全年都在交易。序列为空或者每天收益都一样（方差为零）时，夏普没法算，留空写原因。

#### 计划胜率＝已平仓且算上费用后赚钱的计划 ÷ 全部计划 [#R-2-1-3]

计划就是策略用标签划出的一笔完整交易。一个计划算「赢」，要已经平仓，且算上手续费和资金费后的已实现盈亏大于零。分母包括已平和没平的计划，期末还没平的算「没赢」。每张订单恰好带一个计划标签，一个计划只交易一个合约。标签不合规时，胜率置空写原因，运行不判无效。

### 最大回撤 [#R-2-2]

最大回撤按每根 K 线的标记价权益来算，并写明用的是什么价、多久采一次。

<a id="R-2-2-1" />

**最大回撤看每根 K 线的标记价权益，比峰值最多跌了多少**

回撤 ＝（峰值 − 权益）÷ 峰值，取窗口内的最大值，峰值从初始权益算起。权益 ＝ 账户余额 ＋ 没平持仓按标记价算的浮动盈亏。标记价就是交易所算保证金和强平用的那个价。

正式报告保留实际历史路径上的最大回撤，并结合资金使用率、峰谷区间、持续时间和贡献合约解释。块自助回撤分布不纳入默认报告，也不作为资格或策略优劣的判断依据：日收益分块重排没有重新执行策略的仓位调整、保证金占用和强平逻辑，合成日频路径不能充当上述分钟 MARK 最大回撤的置信区间。

### 资金使用率 [#R-2-3]

skill 规定资金使用率怎么算、怎么和回撤一起读；算它用的数据可信，由代码保证。

#### 资金使用在封存时由代码算出，存在单运行报告里 [#R-2-3-1]

资金使用的峰值类指标由代码在封存时从原生的逐分钟敞口算出：按 K 线采样的名义敞口峰值、在市时间、锁定保证金的峰值；同时把每天的平均名义敞口写进逐日序列，全窗口的平均名义敞口和它占权益的比例由逐日序列读时算。敞口每行标在 K 线时刻 T，表示到下一根 K 线之前所有事件发生后还持有的仓位，按 T 的标记价估值。某根 K 线没有行，就是空仓。

1. 名义额在开发窗口全部 K 线上的时间加权平均：从交易起点算，空仓的 K 线计零，同时给出占同一时刻权益的比例。
2. 采样峰值：写明是按 K 线采样的峰值，不是逐笔的极值。
3. 锁定保证金：取自账户数据，包括挂单占用的部分。
4. 在市时间：有敞口的 K 线根数占开发窗口根数的比例。

#### 回撤用产品算的值，而且必须和同一运行的资金使用率一起读 [#R-2-3-2]

回撤以产品算的标记价最大回撤为准，Agent 不为任何比较或目标重算。读回撤时，必须同时读同一份单运行报告里的资金使用（<Ref id="R.2.3.1" />）。比较两个候选时，回撤下降的同时平均名义敞口或在市时间也下降，要写明是敞口下降带来的。只有两边敞口相当时，才能把回撤的差别归到规则改动上。

#### 成交量占比在封存时由代码算出，只作容量警示 [#R-2-3-3]

引擎为每笔成交写出它那一分钟执行 K 线的 LAST 成交量（`fill_volumes.csv`），封存时算出资金块里的 `participation`：每笔市场成交的数量（乘合约乘数）除以那一分钟的成交量，逐笔等权给中位数、p95、p99、最大值，再给同一合约同一分钟成交合计占量的最大值；缺 K 线、零成交量、超过当分钟成交量的笔数，以及引擎自己的结算和强平成交，另外计数。Agent 读报告里的值，不重算；它用来提醒容量问题，不是实测的成交质量，要按运行的执行模式读。

## 8.3　度量目录与两种报告 [#R-3]

一套度量目录，两种报告，其余的分析保持动态。

### 两种报告与动态分析 [#R-3-1]

决定依赖的部分固定在产品代码里；其余的分析保持动态。

#### 两种报告共用一套度量目录，栏目顺序相同 [#R-3-1-1]

度量目录固定一组栏目和顺序，单运行报告和对比报告共用。单运行给本次的值；对比给两边并列的值和差。检验结果、交易配对、预测对照三栏只出现在对比报告里。栏目就是本章的切面与标量（<Ref id="R.3.2" />），每个标量在目录里只定义一次：

1. 身份与资格：单运行给运行身份、经济证据资格和原因；对比给两边身份和可比资格。
2. 检验结果：只在对比报告里，给效应、区间、p 和检验条件（<Ref id="V.4.1.1" />）。
3. 绩效指标：单运行给年化、标记价最大回撤、计划胜率、夏普；对比给两边并列和差。
4. 利润来源：单运行给价格、手续费、资金费、期末浮动；对比给四项的差（<Ref id="R.3.2.1" />）。
5. 规模与仓位择时：单运行给平均敞口、单位敞口收益、水平项和择时项、涨月和跌月的敞口、年化与回撤之比；对比给各项的差（<Ref id="R.3.2.2" />）。
6. 费用：单运行给按挂单吃单分开的费用与成交数、盈亏平衡费率倍数、每侧 2 与 5 个基点的滑点压力；对比给盈亏平衡费率倍数（<Ref id="R.3.2.3" />）。
7. 品种与方向：单运行给前五个合约占绝对盈亏的比例、多空分开列；对比给同样几项的差（<Ref id="R.3.2.4" />）。
8. 市场暴露：单运行给对等权篮子和 BTC 永续的斜率与截距；对比给斜率之差和截距之差（<Ref id="R.3.2.5" />）。
9. 时期：单运行给盈利月份占比、按总和方向去掉最多五天后剩下多少；对比给胜出月份占比和剩余的差（<Ref id="R.3.2.6" />）。
10. 交易结构：单运行给周期数、胜率、平均赢亏、每笔期望、持仓时长、出场类别集中度，以及各出场类别的闭仓净盈亏（`top_exit_share` 的 `exit_net`，读时派生，不存）；对比给同样几项的差，以及每笔期望之差的拆分（<Ref id="R.3.2.7" />）。
11. 入场单：单运行给入场单个数和成交比例；对比给两项的差（<Ref id="R.3.2.12" />）。
12. 交易配对：只在对比报告里，给覆盖、删掉的和新增的交易、同一机会上的差（<Ref id="R.3.2.8" />）。
13. 回撤：单运行给最大回撤、持续天数、回撤期间的主导合约；对比给同样几项的差（<Ref id="R.3.2.9" />）。
14. 波动状态：按前一日及以前篮子波动分高波动与低波动两组（<Ref id="R.3.2.11" />）。
15. 预测对照：只在对比报告里，给每项登记的预测与实测是否同方向（<Ref id="P.2.1.2" />）。
16. 局限：单运行给合并去重的局限清单；对比把两边的局限合并去重。

#### Agent 写报告和解释按模板栏目来，空栏写原因，不删栏 [#R-3-1-2]

Agent 写一次运行或一次比较的报告时，按模板的栏目顺序写。某一栏是空的，就留着这一栏，写明为什么空。删掉空栏，读的人分不清是「没这个问题」还是「没算」。

#### 封存时只算存储数据推不出的指标，存成一行读数 [#R-3-1-3]

封存时，代码只算原生报告移走后就再也算不出的指标：资格事实（每项是否通过、原因码和计数）、标记价回撤及其区间和主导合约、资金使用的峰值和在市时间、锁定保证金峰值、按挂单吃单分的手续费和成交额、订单漏斗、计划统计是否成立。它们存成每个运行一行读数（<Ref id="table:run_reading">run_reading</Ref>），连同算它的产品提交，金额用十进制字符串。年化、胜率、利润来源、交易结构这些能从持仓周期和逐日序列算出的量，不存，读的时候按当前代码算。

#### 对比报告读时按目录现算，一个入口给出全部栏目，不存 [#R-3-1-4]

比较只有一个入口：给出一份完整的对比报告，依次是可比资格、配对检验、两侧指标与差、交易配对、预测对照。它读两侧的封存结果，可派生的量和单运行报告调用同一个读时函数现算，结果不存；判断里只引用它的身份。

#### 下钻先重放到 /tmp，语义指纹一致才读原生明细 [#R-3-1-5]

要看持仓周期和逐日序列以外的原生明细，比如某笔订单的完整事件，先用 `replay reproduce` 按这次运行的身份重放到 `/tmp`。指纹在运行镜像里计算，覆盖订单、成交、持仓、账户、日收益、订单事件、敞口和成交分钟量：随机编号按首次出现的顺序重编，每表重编后的行整行排序，再给行数和整表哈希；账户、日收益和敞口三张表另给文件哈希。和封存时记下的一致，才交给读取入口；不一致就拒绝（`REPRODUCTION_MISMATCH`），列出哈希不同的表，重放目录留在原处。读取入口（`report.tables`）只给有经济证据资格的通过运行；没有资格的运行在这里被拒绝（`ECONOMIC_EVIDENCE_UNAVAILABLE`）。

#### 目录外的分析在 /tmp 做、不入账；驱动决定的数在判断里引用并交复算 [#R-3-1-6]

度量目录之外的分析都是动态的：Agent 为想清楚一个问题临时拆的表、写的脚本，放在 `/tmp`，格式自己定，不入账。其中驱动推荐或下一个假设的数，在判断里引用它的输入和账本版本，并交给另一个 Agent 复算。PBO/CSCV（回测过拟合概率）不纳入默认正式报告，不用于资格或自动选策略。

#### 反复驱动决定的度量，按设计变更加进目录 [#R-3-1-7]

动态分析里，某个数在几次决定里反复起作用，就提议把它加进度量目录：写清定义、总体和它驱动过的决定，按设计变更走。读时算的度量改了代码就对所有运行生效；封存时算的读数只影响之后封存的运行，老运行要新值，经 `replay reseal` 复现后替换（<Ref id="R.1.1.3" />）。

### 切面与标量 [#R-3-2]

报告的固定拆法：每个切面给几个标量、指向它能度量的几项职责，**27 项职责每项至少有一个切面**。指向只帮着定位，不限定假设，也不限定预测选哪个标量。单运行报告给本次的值，对比报告给两边的值和差；明细表由 Agent 自己算。

#### 利润来源桥：账户净值差拆成四项，加起来正好相等 [#R-3-2-1]

账户净值差拆成四项之差：价格盈亏（`price`）、手续费（`fee`，少付记正）、资金费（`funding`）、期末未平仓的浮动盈亏（`open_mark`），四项相加严格等于账户净值差（`account`）。口径是整个账户：价格项含全部已实现，手续费含全部成交，资金费含未平仓的，浮动取引擎的期末快照。前三项沿用封存时已对过账的利润来源拆分，容差同 <Ref id="R.1.1.2" />；对不上，整个切面留空。这个切面指向预期收益来源（`B1`）、跨机会分配（`E4`）、执行方式（`G1`）、持有成本（`H1`）和做空与融资中断（`H3`）。

#### 规模与仓位择时：描述敞口与每日单位收益的共同变化 [#R-3-2-2]

这个切面给出敞口与每日单位收益的描述性分解，指向条件过滤（`A3`）、预期收益来源（`B1`）、单笔数量（`E1`）、净值变化后的风险预算（`E3`）、跨机会分配（`E4`）、加仓（`F1`）、减仓（`F2`）、容量（`G3`）和保证金缓冲（`H2`）：

1. 逐日盈亏写成当日平均名义敞口乘当日每单位敞口的收益；没有敞口的日子单独列出。
2. 在有敞口的 T 天，水平项为 `T × mean(N) × mean(PnL/N)`，择时项为 `T × population_cov(N, PnL/N)`，两项相加等于这些天的盈亏；无敞口日另列。
3. 按等权篮子的月收益正负分别给平均敞口。
4. 标量：`mean_notional`、`unit_return`、`level_term`、`timing_term`、`up_month_notional`、`down_month_notional`、`return_over_drawdown`。

#### 费用压力：手续费乘几倍，账户差就没了 [#R-3-2-3]

这个切面给一个盈亏平衡费率倍数（`breakeven_fee_multiple`）：两侧手续费同时乘上多少倍，账户净值差正好归零。费用按净额算，已扣挂单返佣；候选本来就少付费用、差又是正的，就写「不会归零」。它指向预测期限（`B2`）、不交易与重入（`C2`）和执行方式（`G1`）。单次回放报告的成本基础（`cost_basis`）另给每笔成交按名义金额多付 2bp 和 5bp 的一阶滑点压力估算。

#### 品种与方向：差是不是集中在少数合约或一个方向 [#R-3-2-4]

这个切面给差最大的五个合约占全部绝对差的比例（`top5_abs_share`），去掉沿总和方向贡献最大的一个合约后剩下的闭仓净盈亏（`net_without_top_instrument`），只在一侧交易过的合约个数（`one_side_instruments`），以及多头和空头各自的闭仓净盈亏之差（`long_net`、`short_net`）。它指向交易对象资格（`A1`）、动态选择（`A2`）、单腿与多腿结构（`D1`）和做空与融资中断（`H3`）。

#### 市场暴露：赚的是跟着大盘走，还是自己的本事 [#R-3-2-5]

账户日收益分别对等权篮子和 BTC 永续的日收益做两次单因素回归，每次都加一项前一天的市场收益，斜率取两项之和；截距按日给。比较两个版本时，直接拿逐日收益差对市场回归，给斜率之差和截距之差。它指向单腿与多腿结构（`D1`）、对冲（`D2`）、组合敞口（`E2`）和保证金缓冲（`H2`）。标量：`beta_basket`、`alpha_basket`、`beta_btc`、`alpha_btc`（单次报告另把逐日盈亏之和拆成 `beta` 与 `alpha` 两份）。

#### 时期：差是均匀分布，还是靠少数几天 [#R-3-2-6]

这个切面给候选胜出的月份占比（`months_won_share`），以及配对日对数收益差按总和方向裁剪最多五天后的剩余（`residual_after_top5_days`）。剩余反号说明该方向的差集中在少数几天，可把 `A3`、`B2` 作为检查入口。

#### 波动状态：差出在高波动日还是低波动日 [#R-3-2-11]

按前一天及以前的篮子波动把日子分成高波动和低波动两组，看候选比对照的差出在哪一组，不偷看当天。它指向条件过滤（`A3`）和对冲（`D2`）。

#### 交易结构：两侧各自统计再比，不逐笔配对 [#R-3-2-7]

两侧各自统计闭仓周期的数量、胜率、平均赢、平均亏、每笔期望和持仓时长中位数，再给差；每笔期望之差拆成胜率变化和盈亏比变化两份（两种先后顺序各算一遍取平均，相加等于总差）；按平仓单类型或标签前缀分出场类别，两侧各给净盈亏，并给差最大的出场类别占全部绝对差的比例。它指向 `A3`、`B1`、`B2`、`B3`、`C1`、`C2`、`F1`、`F2`、`F3`、`F4`、`F5`、`I1` 和 `I2`。标量：`cycles`、`win_rate`、`avg_win`、`avg_loss`、`expectancy`、`median_holding_hours`、`top_exit_share`。

#### 入场单：挂出的入场单有几成成交 [#R-3-2-12]

两侧各给入场单的个数（`entry_orders`）和最终成交的比例（`entry_filled_share`），再给差。入场单是没有父单、也不是只减仓的单；数据取封存读数里按最终状态计数的订单漏斗，不另存。部分成交后撤掉的单算未成交。它指向入场（`C1`）、首次入场时机与价格（`C3`）、执行方式（`G1`）和等待与刷新（`G2`）。

#### 交易配对：用固定算法对上两侧的交易，先报覆盖 [#R-3-2-8]

代码按固定算法（`report.pair_trades`）把两侧的持仓周期配成四类：一一对应、拆并、只在对照、只在候选。配对只作描述，不进检验；Agent 不能自己按时间或编号去配。它指向 `A3`、`B1`、`C1`、`C2`、`G1` 和 `G2`。标量：`matched_share`、`matched_net_share`、`removed_net`、`added_net`、`matched_delta_net`、`win_to_loss`、`loss_to_win`、`median_entry_shift_minutes`。

#### 回撤：回撤差多少、持续多久、被谁拖下去 [#R-3-2-9]

这个切面给两侧按标记价算的最大回撤之差（`max_drawdown`）、回撤持续天数之差（`drawdown_days`），以及候选最大回撤区间里亏得最多的那个合约所占比例（`top_instrument_share_in_drawdown`）。回撤贡献按合约累计原生已实现收益变化加峰谷 MARK 变化计算，分母为负贡献合约的损失合计；各合约贡献之和必须与同一组峰谷权益端点核对（`DRAWDOWN_CONTRIBUTION_UNRECONCILED`）。它指向 `A3`、`E1`、`E2`、`E3`、`E4`、`F2`、`F3`、`H2` 和 `I2`。

#### 明细表由 Agent 自算，影响决定的数要独立复算 [#R-3-2-10]

逐合约表、逐月表和按出场类别的交叉表，由 Agent 从账本里的持仓周期和逐日序列自己算；更细的原生明细先重放再算。其中会驱动研究决定的数，要交给另一个 Agent 独立复算。
