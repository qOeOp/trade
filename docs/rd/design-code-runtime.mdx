### `build_image` [#def-runtime-build_image]

源码托管平台的自动构建：从 main 推送、本项目内发起的拉取请求或手动重建产出单平台镜像并推送到镜像注册表（registry），带构建源码版本与运行契约标签；本机无构建路径

```python
def build_image(
    event: enum{push, pull_request, manual},
    revision: str（40 位十六进制 Git 提交哈希）,
    request_number: int | None,
    build_paths: list[path],
    registry: str,
    platform: str,
) -> 推送结果
```

<TypeTable type={{ "event": { type: "enum{push, pull_request, manual}", description: "触发事件。push 只限主干 main；pull_request 只限本项目内发起（外部 fork 无镜像注册表写权限，跳过）；manual 为手动重建，只打 sha 标签。" }, "revision": { type: "str（40 位十六进制 Git 提交哈希）", description: "被构建的源码版本：push 取当前提交，pull_request 取请求头提交。写入标签 org.opencontainers.image.revision，是 runtime.resolve 的 build_revision 与 runtime.require_main_build 的唯一来源。" }, "request_number": { type: "int | None", description: "拉取请求编号，只在 pull_request 事件有值，用于 pr-<request_number> 标签。" }, "build_paths": { type: "list[path]", description: "触发构建的路径集合：运行环境目录（引擎运行器、报告写出、审计器、探针、Dockerfile）、依赖声明与依赖锁、构建工作流文件。其余路径变化不构建，也不改变摘要。" }, "registry": { type: "str", description: "镜像注册表中的镜像名，形如 ghcr.io/<owner>/trade-runtime，owner 小写。推送用平台颁发的短期令牌，项目源码中不存长期凭据。" }, "platform": { type: "str", description: "单一目标平台（如 linux/arm64），须属于 runtime.validate_identity 的受支持平台集合，构建机架构与之一致。" } }} />

**返回**　推送结果：镜像引用 \<registry>@sha256:\<manifest_digest>（单一清单，不生成清单列表）；标签集 \{sha-\<revision>\} 加 main 或 pr-\<request_number> 之一；镜像标签 org.opencontainers.image.revision=\<revision>、org.opencontainers.image.source=\<项目源码地址>、trade.runtime.contract=\<运行契约>；写入构建摘要页作为人可读回执。回放侧只按摘要引用它。

**期望行为**

1. 核对触发：事件属 main 推送、本项目内发起的拉取请求或手动，且改动落在 build_paths 内；fork 发起的拉取请求拒绝 FORK_PULL_REQUEST。同一引用的并发构建分组，拉取请求取消进行中的旧构建，main 不取消。
2. 命名：始终打 sha-\<revision>；main 推送追加 main，拉取请求追加 pr-\<request_number>，手动只有 sha 标签。
3. 取运行契约：从 runtime.layout 读当前契约版本写入 trade.runtime.contract；取不到或不在受支持集内拒绝 CONTRACT_UNDECLARED。
4. 构建：以项目源码根目录为上下文、运行环境 Dockerfile 为定义做单平台构建；镜像只装引擎与冻结安装的锁定依赖、运行器、报告写出、审计器与探针源码；关闭 provenance 与 SBOM 附件，保证产出单一清单、摘要唯一。失败拒绝 IMAGE_BUILD_FAILED，不推送任何标签。
5. 推送：一次推送全部标签与三条镜像标签；失败拒绝 REGISTRY_PUSH_FAILED，不留部分标签。成功后把 \<registry>@\<digest>、revision 与标签集写入构建摘要页。
6. 边界：不写账本、不跑回放、不验证镜像行为；身份读取归 runtime.resolve，main 来源核对归 runtime.require_main_build，内容核对归 runtime.inspect_runtime。

| 拒绝码 | 条件 |
|---|---|
| `FORK_PULL_REQUEST` | 拉取请求来自外部 fork，没有镜像注册表写权限；作业跳过，不产出镜像。 |
| `CONTRACT_UNDECLARED` | runtime.layout 未声明当前运行契约，或声明值不在受支持契约集内，无法写契约标签。 |
| `IMAGE_BUILD_FAILED` | Dockerfile 构建失败（锁定依赖冻结安装不通过、源码缺失、平台不匹配）；不推送任何标签。 |
| `REGISTRY_PUSH_FAILED` | 推送到镜像注册表失败（认证、网络、配额）；构建摘要页记录失败，不留部分标签。 |

### `container_command` [#def-runtime-container_command]

生成回放、审计与探针用的隔离容器命令：按摘要引用镜像、不拉取、无网络、只读根、去除能力、禁止提权、限进程数、当前用户；只读 bind 挂载声明的输入，唯一可写挂载为报告目录

```python
def container_command(
    identity: dict,
    mounts: list[dict],
    module: str,
    argv: list[str],
) -> list[str]
```

<TypeTable type={{ "identity": { type: "dict", description: "运行环境身份 {image_ref, image_digest, platform, runtime_contract}，由 runtime.resolve 产出；命令按含 @sha256: 的 image_ref 引用镜像，不用标签。" }, "mounts": { type: "list[dict]", description: "挂载清单，每项 {host_path, container_path, writable}。host_path 为已存在的宿主绝对路径；container_path 为容器内绝对路径；只有 /reports 可 writable=True，源码、导出数据目录、共同可交易范围成员文件、覆盖回执一律只读。" }, "module": { type: "str", description: "镜像内要执行的 Python 模块（运行器、审计器或身份探针），须是 runtime.layout 为该契约声明的模块。" }, "argv": { type: "list[str]", description: "原样追加在模块名之后的参数；每项须为字符串，不经 shell 解释。" } }} />

**返回**　list[str]：完整 docker run 参数列表（首项为 docker），调用方按参数列表直接执行；本函数不起容器、不写文件、不读账本

**期望行为**

1. 核对身份：经 runtime.validate_identity 校验，取 platform 填 --platform，取含摘要的 image_ref 作镜像引用。
2. 核对模块：取 runtime.layout(identity.runtime_contract) 声明的运行器、审计器与指纹模块；module 不在其中拒绝 MODULE_NOT_IN_LAYOUT。
3. 核对挂载：host_path 为存在的绝对路径；container_path 为绝对路径、不重复、不覆盖 /tmp；可写项只能是 /reports 且恰好一项，缺失拒绝 REPORTS_MOUNT_MISSING。
4. 拼固定隔离参数：--rm --pull never --platform \<platform> --network none --read-only --cap-drop ALL --security-opt no-new-privileges --pids-limit \<固定上限，未校准示例值> --user \<当前 uid:gid> --tmpfs /tmp；不加环境变量、端口、设备或额外能力。
5. 按清单顺序拼 --mount type=bind,src=\<host_path>,dst=\<container_path>,readonly（/reports 省略 readonly），相同输入得到相同命令行。
6. 追加镜像引用、python -m \<module> 与 argv 后返回；拒绝时抛带拒绝码的异常，不返回部分命令。
7. 每个阶段的命令都核：模块须在该契约的布局里；输入挂载须是已存在、不在 /tmp 下的绝对路径；该阶段唯一可写的挂载是它自己的输出目录（运行器 /reports、审计器 audit/、指纹阶段 fingerprint/）；不符即拒绝，不启动容器。
8. 挂载目标先规范化（含开头的 //）再核：拒绝根目录、/tmp 及其下、/opt/trade（镜像自身代码）及其上下、规范化后重复的目标。

| 拒绝码 | 条件 |
|---|---|
| `RUNTIME_IDENTITY_INVALID` | runtime.validate_identity 判身份形态不合，或 image_ref 不含 @sha256: 摘要、与 image_digest 不一致 |
| `RUNTIME_UNSUPPORTED` | platform 或 runtime_contract 不受支持 |
| `MODULE_NOT_IN_LAYOUT` | module 不是 runtime.layout 为该契约声明的运行器、审计器或指纹模块 |
| `MOUNT_HOST_PATH_INVALID` | 某项 host_path 不是绝对路径或在宿主上不存在 |
| `MOUNT_TARGET_INVALID` | 某项 container_path 不是绝对路径、重复出现，或等于或覆盖 /tmp |
| `MOUNT_WRITABLE_NOT_REPORTS` | 可写挂载目标不是 /reports，或可写挂载多于一项 |
| `REPORTS_MOUNT_MISSING` | 挂载清单中没有 /reports 可写挂载 |
| `ARGV_INVALID` | argv 含非字符串项 |

### `layout` [#def-runtime-layout]

返回某运行契约版本在镜像内的布局常量：运行器模块、审计器模块、指纹模块、运行器各源码路径、审计器源码路径、依赖锁路径；身份探针与 main 构建核对按它逐项核对

```python
def layout(runtime_contract: str | None) -> layout dict
```

<TypeTable type={{ "runtime_contract": { type: "str | None", description: "运行契约版本标识；None 返回全部契约的布局映射。" } }} />

**返回**　layout dict：runner_module、audit_module、fingerprint_module、source_paths（探针字段名 → 镜像内源码相对路径）、audit_path、lock_path；参数为 None 时返回 \{契约: layout\}

**期望行为**

1. 布局是模块级常量，每个契约版本一份：运行器、审计器与指纹阶段的模块及源码路径；身份探针就是运行器模块加 --describe。重构期间产品不兼容此前的镜像、运行与数据：镜像内模块搬迁（如 backtest.* → engine.*）直接改写布局，布局变动之前构建的镜像不再支持。
2. 每个契约声明运行器、审计器与指纹三个模块，以及运行器各文件、审计器、依赖锁三类源码路径；不声明策略源码、账本配置或市场数据路径。
3. 按给定契约查布局；契约未声明拒绝 RUNTIME_UNSUPPORTED。
4. 受支持契约集合即布局映射的键，供 runtime.validate_identity 与 runtime.build_image 读取。

| 拒绝码 | 条件 |
|---|---|
| `RUNTIME_UNSUPPORTED` | 请求的运行契约没有布局声明 |

样本外验证专用：核运行环境来自产品镜像注册表 registry、构建源码版本在产品源码 main 上、镜像内运行器与审计器源码及依赖锁哈希等于该版本源码中的字节；研究回放不调用，任一构建来源的镜像在研究中仍可用

```python
def require_main_build(
    identity: dict,
    inspection: dict,
) -> build_revision
```

<TypeTable type={{ "identity": { type: "dict", description: "经 validate_identity 核对的镜像身份；build_revision 来自镜像标签，未携带该字段时由函数读取镜像标签" }, "inspection": { type: "dict", description: "runtime.inspect_runtime 返回的检视（取 source_files_sha256、source_file_paths、audit_source_sha256、dependency_lock_sha256）" } }} />

**返回**　build_revision：在 main 上的构建源码版本（Git 提交哈希）；函数本身不写账本。运行身份的构建版本保存在开始凭证的 runtime_identity.build_revision 中，没有独立的 image_revision 存储列。

**期望行为**

1. 经 runtime.validate_identity 核身份形态，不过即 RUNTIME_IDENTITY_INVALID。
2. 核 image_ref 所在的镜像注册表 registry 与命名空间等于产品镜像注册表。
3. 取来自镜像标签的 identity.build_revision；该字段未携带时读取镜像标签；无法取得有效构建提交即拒绝。
4. 核该版本是产品源码托管远端 main 的祖先：先本地判定，失败则抓取一次远端 main 再判定；每次 git 调用（抓取在内）120 秒内未结束即拒绝 RUNTIME_UNAVAILABLE，与 docker 调用的超时一样。
5. 按 runtime.layout 取运行器各源码、审计器、指纹代码（engine/compare.py）与依赖锁路径，读该版本下每个文件字节算 sha256，逐项等于检视中对应哈希；任一不等即拒绝（防重贴标签的镜像）。
6. 返回 build_revision；不写账本。

<p className="rd-note">[隔离实测](https://github.com/qOeOp/trade/blob/main/docs/plans/validation-main-boundary-verification.zh.md)已用真实 main／PR 镜像和原生探针接入 Dolt 2.4.2 绑定事务，当前 rc7 与历史 rc3 两组各 35 个检查点通过；非 main 与七类哈希异常拒绝并回滚，合法绑定仅一次成功。既有相关测试 8 项通过、无跳过；市场、研究基线与 TSA 使用夹具，不代表完整真实样本外回放或报告验收。</p>

| 拒绝码 | 条件 |
|---|---|
| `RUNTIME_NOT_MAIN` | 镜像不在产品镜像注册表、无构建源码版本、版本不在 main 上，或镜像内源码与依赖锁哈希不等于该版本字节 |
| `RUNTIME_IDENTITY_INVALID` | 身份未通过 runtime.validate_identity |
| `RUNTIME_UNAVAILABLE` | 一次 git 调用（抓取远端 main 在内）120 秒内未结束 |

### `resolve` [#def-runtime-resolve]

把标签或摘要引用解析为该镜像名下唯一的清单摘要，并从镜像清单与标签读出身份；身份不能手写，缺省引用为镜像注册表中的 main 标签

```python
def resolve(reference: str | None) -> identity dict
```

<TypeTable type={{ "reference": { type: "str | None", description: "镜像引用：<镜像名>:<标签> 或 <镜像名>@sha256:<摘要>；None 取镜像注册表中的 main 标签。" } }} />

**返回**　identity dict：image_ref（\<镜像名>@sha256:\<摘要>）、image_digest（sha256:\<摘要>）、platform（os/arch）、runtime_contract（契约标签值）、build_revision（构建源码版本标签值，缺则 None）；已经 runtime.validate_identity 核对

**期望行为**

1. 标签引用每次都拉取以取最新清单；摘要引用只在本地缺失时拉取；拉取或检视失败，或检视 60 秒、拉取 300 秒内未结束，拒绝 RUNTIME_UNAVAILABLE；拉取超时的消息指出不应答的凭据助手（Docker 配置的 credsStore 或 credHelpers），并说明公开镜像可匿名拉取。
2. 读本地镜像的 RepoDigests，只保留与引用同镜像名的项；不是恰好一个拒绝 RUNTIME_DIGEST_AMBIGUOUS；取该摘要并把 image_ref 改写为 \<镜像名>@\<摘要>。
3. 从镜像配置标签读运行契约与构建源码版本；缺契约标签拒绝 RUNTIME_IDENTITY_INVALID，缺构建源码版本记 None。
4. 从镜像配置读 os 与 architecture 组成 platform。
5. 组装身份交 runtime.validate_identity 核对后返回；全部字段来自镜像，调用方不得改写。

| 拒绝码 | 条件 |
|---|---|
| `RUNTIME_UNAVAILABLE` | 引用无法拉取、本地检视失败，或拉取、检视超时 |
| `RUNTIME_DIGEST_AMBIGUOUS` | 本地镜像在该镜像名下没有恰好一个清单摘要 |
| `RUNTIME_IDENTITY_INVALID` | 镜像缺运行契约标签，或组装出的身份未通过 runtime.validate_identity |
| `RUNTIME_UNSUPPORTED` | 平台或运行契约不受支持（由 runtime.validate_identity 转发） |

### `validate_identity` [#def-runtime-validate_identity]

核对运行环境身份字典的形态：四个必需字段齐全、引用含不可变摘要且与摘要字段一致、平台与运行契约受支持；登记、回放、比较、样本外等所有接收身份的入口共用这一个核对

```python
def validate_identity(value: dict) -> 规范化身份 dict
```

<TypeTable type={{ "value": { type: "dict", description: "待核对身份：image_ref、image_digest、platform、runtime_contract 必需，build_revision 可选。" } }} />

**返回**　规范化身份 dict（只含上述五个字段）

**期望行为**

1. 核对四个必需字段存在且为非空字符串；缺字段或出现未知字段拒绝 RUNTIME_IDENTITY_INVALID。
2. 核对 image_ref 形如 \<镜像名>@sha256:\<64 位十六进制>、image_digest 形如 sha256:\<64 位十六进制>，且两者摘要相等。
3. 核对 platform 在受支持平台集合内、runtime_contract 是 runtime.layout 的键；否则拒绝 RUNTIME_UNSUPPORTED。
4. build_revision 若存在须为 40 位十六进制 Git 提交哈希。
5. 返回规范化身份；纯形态核对，不触碰容器运行时。

| 拒绝码 | 条件 |
|---|---|
| `RUNTIME_IDENTITY_INVALID` | 字段缺失或多余、形态不合、引用与摘要不一致，或 build_revision 形态不合 |
| `RUNTIME_UNSUPPORTED` | 平台不在受支持集合，或运行契约不是 runtime.layout 声明的契约 |
