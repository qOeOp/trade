### J.2.3　失败、无效与中断回放的去向 [#J-2-3]

失败、无效和中断都留下记录，Agent 不能补写或替换。

<Cap id="J.2.3.1" kind="database" tier="rehearsal" tierLabel="演练证据" title="失败或无效的回放照样入账，标无效并逐条列原因">

- 无效运行只留原因、原生摘要和审计结果，不留绩效指标。
- 原因由代码逐条汇总，不看日志文本，退出码为零也掩盖不了。
- 原生摘要与试验的源码、环境、配置身份不符即无效。
- 无效尝试照样消耗网格点、计入试验次数，但不进比较。

## J.3　写入保护：怎么证明没被改 [#J-3]

写入只经命令行接口进入，每次是一个整笔成败的事务，只追加不改；封存内容读出时重算哈希，事后由只读的整体复核检查全部规则。保证是留痕而非不可改：用管理权限绕过的改动拦不住，只能事后发现。

### J.3.1　只追加 [#J-3-1]

正常写入只有新增，改口靠追加更正。

<Cap id="J.3.1.1" kind="database" tier="verified" tierLabel="已验证" title="账本记录只增不改，审计结论写入后不可编辑">

- 写账号只能新增记录。
- 每次写入产生一个账本版本，任何增改删都留在差异历史里。
- 审计结论、绩效指标、登记和候选写入后只能追加更正。
- 正常路径外的改动写时不拦，由整体复核事后报出。

- 每行的新增版本可查，修改或删除会留下差异记录。
- 绕过校验的写入和改删，由整体复核事后报为发现。

## J.5　运行环境钉死：回放在什么里跑 [#J-5]

运行环境只由自动构建产出，回放只经统一入口，在按摘要钉死、隔离的容器里运行。换运行环境时，旧、新环境配对重放并由代码比对原生报告；有意变更或不一致时旧运行原样可读回，受影响运行由 V.2 恢复可比资格。

- 只有运行器、审计器、依赖锁等环境内容的改动会改变摘要。
- 构建不写账本、不跑回放、不判镜像行为。
