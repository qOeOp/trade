# 13　账本与运行环境：研究证据存在哪、谁能写、怎么证明没被改动、登记在回放之前，以及回放在什么环境里跑、凭什么能重跑。

前面各章讲研究怎么做：第 6 章钉住市场数据，第 7 章封存回放结果并做完整性审计，第 12 章做样本外验证。这一章讲它们脚下的地基：证据存在哪里、怎么防改动，回放的环境怎么固定、变了怎么认定。

这一章做六件事。先划定研究记录只存账本（ledger，唯一持久保存研究记录、只增不改的版本化数据库）和它的备份；再规定账本里每类记录装什么、谁来写；然后说明怎么证明记录没被改过，以及登记确实早于回放。最后两件讲运行环境（runtime image，自动构建、按摘要钉死的隔离容器镜像）：回放在什么里面跑，每次回放留下哪些身份，凭这些身份怎么重跑核对。

举个例子：全池 RSI 十轮演练结束后，整条路线的证据都在一个独立账本和它的备份里。复核时从关闭时的账本版本重新导出最终证据包，17 个文件的哈希全部和原封存一致。所有回放都钉在同一个运行环境摘要和同一个市场提交上，所以独立 Agent 能在同一版本上重算 H09、H10 的账户数字，没有发现实质差异。

<Steps>

### 账本及其备份 [#J-1-1]

下结论只能引用账本里的记录。

<a id="J-1-1-1" />

**研究记录只存账本和备份，没入账的材料当作不存在**

长期保存的研究记录只有账本和它的备份，会话记忆、交接文件和工作副本都不算。入账的有候选源码、登记、试验和运行记录、原生报告和执行日志、来源与审查证据、研究状态清单和备注，后几类以证据包入账，包名就是身份。引用结论要给出证据包名、运行或登记编号和账本版本，判断里不抄数字；没入账的材料先入账再引用。

只有入了账的东西有哈希、只追加，事后能查。入账形态、哈希和只追加由代码和账本强制；「结论只引用已入账的记录」靠 skill 指导，有评测用例检查。

### 账本之外的去向 [#J-1-2]

账本之外的东西都是临时工作副本；测试只写隔离账本。

#### 工作副本只放临时目录，测试和演练只写隔离账本 [#J-1-2-1]

没发布的策略、探索脚本、回放输出和派生报告都是临时工作副本。回放前代码核对输出目录：必须在临时目录下，而且是新建的，否则拒绝。研究回放的工作目录在报告入账后删除，失败时留着供诊断。

测试和演练只写隔离账本，和活动账本不共用任何路径。账本只追加，测试数据一旦写进活动账本就删不掉，会和真实研究混在一起。

<div className="rd-example">

全池 RSI 十轮演练写的是一个独立的 Dolt 账本，不是活动账本。演练的工作目录都在 /tmp 下，复核时以那个独立账本和它的备份为准。

</div>

#### 代码仓库只放产品代码和环境构建定义，策略和登记只在账本 [#J-1-2-2]

产品源码里只有产品代码和运行环境的构建定义，不放策略正文（包括模板）、登记、试验记录和回执。策略在临时目录写好后发布成候选；要改已发布的候选，先把它的源码字节导出到临时目录，改完再重新发布。运行环境随产品源码发布：引擎、运行器、审计器和依赖的改动，只能自动构建出新的镜像摘要后才进入回放，本机不构建。

## 13.2　记录：账本装什么、谁能写什么 [#J-2]

账本里每类研究记录装什么、由谁写：结构化事实由代码写，Agent 只追加文字。

<Steps>

<Step>

发布：策略源码核对过形态，成为一个候选。

</Step>

<Step>

登记：回放前把假设、网格和执行身份锁成一个证据包。

</Step>

<Step>

回放：启动前先写一条试验；结束后，通过的和无效的运行都入账。

</Step>

<Step>

判断：Agent 一条条追加判断，正文只引用账本记录。

</Step>

<Step>

读取：资格、计数和研究状态在读的时候算出来，不另存。

</Step>

</Steps>

### 研究对象的记录 [#J-2-1]

候选和登记由代码核对后入账，之后只能追加。

#### 候选是一份单文件源码的原字节，带内容哈希和谱系 [#J-2-1-1]

候选记下源码原字节、入口类、说明、父版本和改动说明。内容哈希由账本从字节算出，同样的字节不能再发布一次。派生候选必须同时给父版本和改动说明，根两样都不给。

以字节哈希为身份，改一个字节就是另一个候选，谁也冒充不了谁。账本只证明它是单文件、谱系对得上，不证明里面的规则对。

<div className="rd-example">

全池 RSI 演练里，H01 到 H04 账户都亏损，但每个版本照样留下了源码、父版本、改动说明、登记和原生证据。H08 的父版本是 H07，改动是把单笔预算从 500 降回 100。

</div>

#### 登记在回放前锁成不可变的证据包，要改只能另行登记 [#J-2-1-2]

登记锁住父版本、对照、那一处改动、理由来源、网格和检验条件，还锁住登记时探测到的执行身份。内容哈希和登记时间由账本写，调用方不能填。要改意图、网格或源码，只能另行登记，旧包不改也不删。

登记是事先说好要试什么、怎么比。允许事后改，就能看了结果再调假设，事先登记就没有意义了。

<div className="rd-example">

### 回放的记录 [#J-2-2]

试验在回放前写；运行和原生报告在回放后由代码一次写入。

#### 每次回放启动前恰好写一条试验，之后不再改 [#J-2-2-1]

试验记下用途、源码哈希、运行环境、合约集和窗口。研究回放消耗一个网格点，样本外回放绑定一次样本外登记；这两种回放的源码都必须是已发布的候选。

试验在出结果之前就写下，事后没法只挑好结果来登记。无效和中断的回放也有试验，也计入试验次数，试过多少次才算得准。

<div className="rd-example">

全池 RSI 演练的账本里共有 67 条试验，只有 11 条绑定了正式研究回放（含参考根），另外 56 条没有绑定。其中 8 条也登记了超过 300 天的窗口，可能失败或中断，所以不能说它们都跑完了全年。

</div>

#### 研究和样本外回放各入账一个运行，记结论和身份 [#J-2-2-2]

运行记下审计结论（通过，或无效及原因）、审计发现清单和原生报告的语义指纹；通过的运行另有一行封存结果，由代码从原生报告算出，某一项对账失败只把那一项置空。无效运行没有封存结果，通过的运行没有无效原因。执行身份不在运行上重复存，按试验的镜像摘要和登记包读。

运行的状态和绩效指标写入后不改，要重评只能追加更正。否则同一个运行在不同时间读出不同的数，比较就没法复查。

#### 通过的回放只存三样：封存结果、逐日序列和持仓周期 [#J-2-2-3]

封存时，代码从工作目录里的原生报告一次算出三样存进账本：一行封存结果（只含存储数据推不出的指标）、逐日序列（日收益和当日平均名义敞口）、每个持仓周期一行的紧凑记录。原生报告本身不入账，账本只记它们的语义指纹。只有通过的运行有这三样，和运行同时写入。

原生报告能用钉死的环境重放出来，是缓存；封存时算出的指标才是要冻结的记录。语义指纹剔除随机编号后比较内容，重放出来的报告和它对得上，就证明是同一次回放。

### 失败、无效与中断回放的去向 [#J-2-3]

失败、无效和中断的回放都留下记录，Agent 不能补写或替换。

#### 失败或无效的回放照样入账，标无效并逐条列原因 [#J-2-3-1]

无效运行只留原因、原生摘要和审计结果，不留绩效指标。原因由代码逐条汇总，不看日志里的文字，进程退出码为零也掩盖不了。原生摘要和试验记下的源码、环境、配置身份对不上，同样判无效。

无效的结果要留下，不然失败就被悄悄抹掉了。它照样消耗网格点、计入试验次数，但不进入比较。

<div className="rd-example">

全池 RSI 演练里有一次 27 号试验，引擎进程退出码是 0，审计器退出码是 1。它被记为失败，没有因为引擎正常退出就当作成功。

</div>

#### 每次回放不论成败，都封存原生日志、退出码和源码 [#J-2-3-2]

完成、中断和宿主失败的回放都会封存，这类证据包只由回放代码写，Agent 不能写。内容有各阶段的命令和退出码、原生输出、被执行的源码字节和启动记录。空文件、缺失和没开始各自如实标出，不写占位内容。

失败的原因常常只在原始输出里，不封存，事后只能猜。封存被拒或进程被杀时没有最终封存，就读为缺失。

<div className="rd-example">

#### 中断的回放读为缺失，恢复只能另起证据包追加 [#J-2-3-3]

中断的回放保留试验和启动时写下的记录，工作目录留着供诊断。缺少最终封存就读为缺失，不用别的材料顶替。要恢复，必须和启动记录的用途、源码、环境、输入一致，并写明原因。

### 写入分工 [#J-2-4]

Agent 只追加证据包和判断；结构化事实由代码写，资格和计数读的时候算。

#### Agent 只追加文字、原件和判断，不写分数和裁决 [#J-2-4-1]

Agent 写的是登记、理由、来源、审查结论、备注和更正这类证据包。判断一条条追加，改判断就写新的一条并指向旧的。判断正文只引用候选、试验、登记和账本版本，不抄数字。

绩效指标、计数和资格都在读研究状态时取出来。让 Agent 自己写分数，就等于让它给自己的工作打分。

<div className="rd-example">

比如 Agent 写一条推荐 H09 的判断，正文写「推荐 H09，依据是 H09 的候选、对应的试验和某个账本版本」，而不是把年化 4.24% 抄进去；读的时候，数字从账本当场取。

</div>

#### 样本外只认 main 自动构建的环境和含 main 最新提交的代码 [#J-2-4-4]

样本外验证绑定时，代码核对两件事：运行环境是由产品源码 main 自动构建的；执行命令的产品代码包含 main 的最新提交（本地工作树里的改动不核对）。研究、预检和探索不做这两项核对，只要求环境由自动构建产出、按摘要钉死，任何构建来源的镜像都能用。

样本外结果要经得起追问，环境和代码都必须能追到主干。两项核对都只读、不写账本；通过时，构建源码版本记在样本外运行上。

<div className="rd-example">

比如用功能分支自己构建的镜像做研究回放是可以的，但拿它绑定样本外验证会被拒绝（RUNTIME_NOT_MAIN）。本机代码落后于 main 时，样本外绑定也会被拒绝（STALE_CHECKOUT）。

</div>

1. 核对镜像在产品镜像注册表里。
2. 核对镜像的构建源码版本（只从镜像标签读出）在远端 main 的历史上，也就是 main 的祖先。
3. 核对镜像里运行器、审计器源码和依赖锁的哈希，逐项等于该版本源码中的字节；任一项不符就拒绝（RUNTIME_NOT_MAIN）。
4. 核对执行命令的产品 checkout 的 HEAD 含远端 main 的最新提交；证明不了就拒绝（STALE_CHECKOUT）。

### 读取视图 [#J-2-9]

各流程通过少数几个读取视图读账本；算出来的结果在读取入口里算，读历史按当时的版本读。

## 13.3　写入保护：怎么证明没被改 [#J-3]

写入只走命令行、整笔成败、只追加，读出时重算哈希，事后整体复核；保证的是留痕，不是改不了。

<Steps>

<Step>

写入只经命令行接口进来，每次是一个整笔成功或整笔不成的事务。

</Step>

<Step>

账本只追加；写错了追加一条更正，原记录不动。

</Step>

<Step>

封存内容的哈希由账本算出，每次读出都重算核对。

</Step>

<Step>

账本全部历史增量备份到服务目录之外。

</Step>

<Step>

整体复核用读账号钉住一个版本核对全部规则，只报发现；用管理权限绕过的改动拦不住，只能这样事后发现。

</Step>

</Steps>

### 只追加 [#J-3-1]

正常写入只有新增，改口靠追加更正。

#### 账本记录只增不改，审计结论写入后不能编辑 [#J-3-1-1]

写账号只能新增记录。每次写入产生一个账本版本，任何增、改、删都留在差异历史里。审计结论、绩效指标、登记和候选写入后，只能追加更正。

研究结论要经得起事后查证，旧记录就不能被悄悄改掉。正常路径之外的改动，写的时候不拦，由整体复核事后报出来。

<div className="rd-example">

比如三个月后想知道某次推荐当时依据的是哪个运行，按那时的账本版本读，看到的就是当时的记录，不会被后来的改动覆盖。

</div>

#### 改和删能查到但拦不住：保证的是留痕 [#J-3-1-4]

每次提交前账本自动跑校验，失败就整笔回滚，挡住正常路径上的错误。但这个校验能被管理权限跳过，所以它不是信任边界。

### 写入事务 [#J-3-2]

每次写入是一条连接上的一个整笔事务。

#### 一次写入在一个事务里整笔成功，或整笔不成 [#J-3-2-1]

## 13.4　登记先于回放：先后顺序怎么证明 [#J-4]

登记早于回放，由账本写的时间、同笔提交和绑定时的逐项核对三样来证明。

<Step>

<Step>

<Step>

</Step>

</Step>

### 时间的来源 [#J-4-1]

时间只由账本给，调用方不能提供。

#### 登记和试验的时间只由账本写，调用方给的会被覆盖 [#J-4-1-1]

需要证明先后的记录，插入时由账本写下 UTC 微秒时间。命令和 Agent 都不提供时间，给了也会被覆盖。登记先于试验，判据是两条记录的时间严格先后。

</div>

## 13.5　运行环境钉死：回放在什么里跑 [#J-5]

回放只在自动构建、按摘要钉死、相互隔离的容器里跑；换环境要新旧配对重放、由代码比对。

<Steps>

<Step>

运行环境由源码托管平台自动构建，本机不构建。

</Step>

<Step>

回放按摘要钉死环境，身份从镜像本身读出。

</Step>

<Step>

所有回放走同一个入口，在没有网络、只读的隔离容器里运行。

</Step>

<Step>

换运行环境时，同一组输入在新旧环境各跑一次，由代码比对两份原生报告。

</Step>

<Step>

有意改变行为或比对不一致时，旧运行原样可读回；受影响的运行由 <Ref id="V.2" /> 恢复可比资格。

</Step>

</Steps>

### 来源与身份 [#J-5-1]

运行环境只由自动构建产出，身份从镜像本身读出。

#### 运行环境只由自动构建产出，本机不构建 [#J-5-1-1]

本机没有构建路径，镜像只由源码托管平台自动构建并推送。每个镜像标明构建它的源码版本，以及它遵守的运行约定版本。只有运行器、审计器、依赖锁这类环境内容的改动，才会改变摘要。

本机构建，每台机器可能装出不一样的东西，同一个名字下跑的不是同一套代码。构建只产出镜像：不写账本、不跑回放、不评判镜像行为。

## 13.6　回放身份与复现：每次回放留下什么、怎么重跑 [#J-6]

<Step>

读取运行时核验身份和哈希，不符就标为不可用。

<Step>

复现时按摘要拉回环境，用同一个市场提交重放，逐条比对原生报告。

<Step>

**开发窗口要不要扩展由你选，Agent 只报范围和阻断**

新月份数据到了，Agent 在入口读出最新的完整月，和当前开发窗口、钉住的市场提交对比。它只报告能扩展到哪，以及精确的阻断：缺镜像、缺市场提交、缺覆盖回执，各影响哪一段，然后以提问结束。

市场提交和开发窗口合起来是这条路线的数据约定，改它就是改研究范围，由你决定。Agent 不自己改窗口，也不自动重放；你选定后写成新版本的路线记录，旧路线记录和证据都保留。
