### `attribution` [#def-report-attribution]

对比报告的归因部分：由 report.compare 调用，按度量目录算两侧标量之差、交易配对、预测对照与交互效应；没有单独的命令

```python
def attribution(
    profile: str,
    bundle: str,
    trial_id: str,
    at: str | None,
) -> dict
```

<TypeTable type={{ "profile": { type: "str", description: "账本档案名" }, "bundle": { type: "str", description: "登记证据包名；对照、预测与交互声明从它读出" }, "trial_id": { type: "str", description: "候选运行，须是本登记某网格点产出的封存运行" }, "at": { type: "str | None", description: "账本版本，缺省为当前 HEAD" } }} />

**返回**　dict：\{comparison（report.compare 的身份字段）, metrics_revision, slices: \{切面: \{measures: \{名: \{candidate, control, difference\}\}, available, reason\}\}, predictions: [\{slice, measure, direction, duty, observed, same_sign, reason\}], interaction\}

**期望行为**

1. 读两侧单运行报告里的切面标量，逐项给两侧值与差。
2. 交易配对调用 report.pair_trades，读两侧持仓周期；市场暴露经 market.daily_returns 读市场日收益。
3. 逐项读登记预测，取对应标量标是否同号；登记声明了交互时，按声明的四个角算交互项。
4. 不写账本。

| `（比较拒绝，见 [[report.compare]]）` | 对照运行不存在、运行不在网格、不可比、任一侧无经济证据资格或日钟不一致（登记没有对照时比较入口不调用归因） |
| `INTERACTION_UNATTESTED` | 登记声明了交互，但绑定的源码审查没有确认四个角的形状，或某个角不可比、无资格 |

### `pair_trades` [#def-report-pair_trades]

跨运行交易配对的唯一算法：把两侧持仓周期配成一一对应、拆并、只在对照、只在候选四类；只作描述，不进检验

```python
def pair_trades(
    control: list[dict],
    candidate: list[dict],
    window_end: datetime,
) -> dict
```

<TypeTable type={{ "control": { type: "list[dict]", description: "对照侧持仓周期（含期末未平），来自 ledger.load_run 的持仓报表" }, "candidate": { type: "list[dict]", description: "候选侧持仓周期" }, "window_end": { type: "datetime", description: "交易窗口终点，期末未平周期的区间止于此" } }} />

**返回**　dict：\{coverage: \{matched_share, matched_net_share, overlap_quantiles\}, classes: \{matched, split_merge, only_control, only_candidate: \{count, price, fee, funding, net\}\}, pairs: [\{control, candidate, overlap, entry_shift, exit_shift, net_difference, flip\}], open: \{...\}\}

**期望行为**

1. 按合约与方向分组；不用仓位编号，也不看盈亏。
2. 同组内两周期的持仓区间有交集即为候选对，重合度＝交集时长÷并集时长。
3. 按重合度从高到低一一配对，重合度相同先配开仓早的；配过的周期不再参与。
4. 未配上的周期若与已配周期有交集，记为拆并；其余记为只在对照或只在候选。
5. 期末未平的周期区间止于窗口终点，结果里单列。
6. 覆盖先于明细给出：配上的周期占两侧周期之和的比例，以及配上的周期占全部绝对闭仓净盈亏的比例。
7. 给配对重合度的分布；重合度低的配对可能是新增交易碰上了被删交易，读明细时单独看。
8. 候选与对照的周期只与同一合约、同一方向的周期比较。

### `candidates` [#def-report-candidates]

全部候选的源码身份、父与改动、每个登记尝试及其运行状态与当前经济证据可用性，附账本提交，可按版本读历史；不带分数、资格标记或排序

```python
def candidates(profile: LedgerProfile, at: str | None) -> dict
```

<TypeTable type={{ "profile": { type: "LedgerProfile", description: "账本档案（连接位置与只读账号）；经 ledger.read_as_of 打开只读连接，是本函数与 cli.candidate_list 唯一的连接来源" }, "at": { type: "str | None", description: "可选账本版本：提交哈希或标签；None 读当前。按版本读出当时的全部候选与尝试，用于复读入口当时看到的森林" } }} />

**返回**　dict：\{ledger_commit: 实际读到的账本提交哈希, checker: 本次计算经济证据可用性的检查身份 \{check, metrics_revision, source_sha256\}, candidates: [\{strategy_id, revision, source_sha256, entry_class, runtime_contract, description, parent_strategy_id, parent_revision, difference, created_at, attempts: [\{bundle, trial_id, run_status: 'passed' | 'invalid' | 'unfinished', availability: \{economic_evidence_available, reasons, checker\}\}], valid_evidence: bool\}]\}。候选按 (strategy_id, revision) 自然顺序列出，仅为稳定输出，不是排序或推荐；不含任何绩效指标、分数或裁决键。

**期望行为**

1. 经 ledger.read_as_of(profile, at) 打开 AS OF 只读连接，核对 ledger_schema 版本与代码一致，取该连接实际指向的提交哈希作 ledger_commit；at 不能解析为提交或标签时拒绝。
2. 读 candidate 全部行（strategy_id、revision、source_sha256、entry_class、runtime_contract、description、parent_strategy_id、parent_revision、difference、created_at）；不读任何收益、显著性或推荐相关列，候选身份只看 source_sha256。
3. 读 registration_attempt 左连 trial 与 run：每个尝试带登记证据包 bundle、消耗它的 trial_id 与对应结果 run.status；无 run 行的尝试（中断、未完成、失败）仍列出并标 run_status = unfinished，因为网格点已被消耗。
4. 对有 run 的尝试经 ledger.load_run 读封存报表，再经 qualification.assess 按 qualification.check_identity 给出的检查身份算当前经济证据可用性（读时视图，不改写存储的 run.status 与审计结论；封存缺失或哈希不符由 assess 标为不可用）；无 run 的尝试 availability = \{economic_evidence_available: false, reasons: ['unfinished'], checker\}。
5. 按 attempt.source_sha256 = candidate.source_sha256 把尝试挂到候选，valid_evidence = 任一尝试经济证据可用；返回 \{ledger_commit, checker, candidates\}。全程不写账本，不生成分数、资格标记、排序或占位推荐。
6. 核对一致性：某尝试引用的 source_sha256 在同一版本的 candidate 里不存在，或 run.trial_id 指向不存在的 trial，经 ledger.refusal 以 LEDGER_CORRUPT 拒绝并指明行，而不是静默丢行。
7. 某次尝试读回时报账本损坏或执行身份不符，只把它记为不可用（仅诊断）并列出原因，其余照常；研究状态另列 unverified_runs。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_REF` | at 给出的提交或标签在账本里不存在或不可解析 |
| `SCHEMA_MISMATCH` | 所读版本的 ledger_schema 版本与当前代码不一致，或账本未初始化 |
| `LEDGER_CORRUPT` | registration_attempt 引用的候选源码哈希在同一版本的 candidate 中缺失，或 run.trial_id 指向不存在的 trial；指明首个不一致的行 |

### `compare` [#def-report-compare]

对比报告的唯一入口：读时按度量目录现算，一次给出可比资格、配对检验、两侧指标与差、交易配对、预测对照与交互效应；不存

```python
def compare(
    profile: str,
    bundle: str,
    trial_id: str,
    at: str | None,
) -> dict
```

<TypeTable type={{ "profile": { type: "str", description: "账本档案名，决定连接哪一份研究账本" }, "bundle": { type: "str", description: "登记证据包名，比较条件（对照、网格、检验条件、研发父版本）全部从它读出" }, "trial_id": { type: "str", description: "候选运行编号，必须是被本登记某网格点消耗的试验所产出的封存运行" }, "at": { type: "str | None", description: "账本版本（提交或标签），缺省为当前 HEAD；用于复读历史绩效指标" } }} />

**返回**　dict：\{bundle, trial_id, control_trial_id, research_parent, ledger_commit, registered_at, metrics_revision, comparison_source_sha256, availability\{candidate, control\}, evidence\}；evidence 为 report.paired 的返回，并附 observed_account_annual_return_difference（两侧封存运行年化之差，账户口径，与自助统计分列）。登记没有对照时只返回 \{bundle, trial_id, control_trial_id: null, ledger_commit, evidence: null, attribution: null, reason, next_actions\}，next_actions 指向 replay report --trial-id

**期望行为**

1. 登记没有对照（control_trial_id 为空）时不拒绝：先核候选运行属于本登记网格（否则 RUN_NOT_IN_GRID），再如实回答没有可比的，evidence 与 attribution 为空，下一步是单独读这次运行的报告（replay report --trial-id）。
2. 读登记包，取对照、网格、检验条件与预测；核候选运行属于本登记网格。
3. 两侧核可比资格（身份取自登记包与试验行）与经济证据资格；任一不过即拒绝，只留诊断。
4. 两侧取逐日序列，核日钟一致，调用 report.paired 得效应、区间与 p。
5. 调用 report.attribution，用两侧单运行报告、持仓周期、逐日序列与市场日收益算各切面的差、交易配对、预测对照与交互效应。
6. 附完整身份与度量目录版本返回；不写账本，同样的输入任何时候重算都一样。
7. difference 一律为候选减对照；比较自己定义的量（单边合约数、前五绝对差占比、月胜比例、去掉前五天后的残差、首要出场占比、盈亏平衡费率倍数等）放在 pairwise 下；预测按 pairwise 里有定义的量核对，没有才用两次单运行值之差，并注明 observed_as。
8. 回归窗口太短或矩阵奇异时，该量置空并写原因，不抛异常。
9. 报告与对比读取时都记下产品 checkout 的 HEAD（report_revision）；工作树里有本地改动照常读取，不拒绝。

| 拒绝码 | 条件 |
|---|---|
| `NO_CONTROL` | 登记声明的对照运行不存在 |
| `RUN_NOT_IN_GRID` | 候选运行的试验不在本登记的 registration_attempt 中，或绑定记录的源码哈希与运行源码哈希不符 |

### `holm` [#def-report-holm]

同一样本外窗口登记族（窗口起止与 universe_rule 相同）的 Holm 逐步校正 p：排序后取 p_(k)·(m−k+1) 的逐步最大值并截到 1，按原顺序返回；族成员由调用方从账本登记行取得

```python

```

### `paired` [#def-report-paired]

配对循环块自助：取两侧账户日收益的对数差，按登记块长循环分块、两侧共用同一组块起点共同重抽；报效应（平均日对数差与由之换算的年化差）、基本区间与嵌套学生化区间、年化差百分位区间、单侧 p 与网格 Bonferroni p、半倍/一倍/两倍块长敏感性、差值集中度、80% 功效（未校准示例值）可分辨效应与固定局限句；不返回任何裁决字段

```python
def paired(
    left: Sequence[float],
    right: Sequence[float],
    design: dict,
    grid_points: int,
    weights: Sequence[float] | None,
) -> dict
```

<TypeTable type={{ "left": { type: "Sequence[float]", description: "对照侧交易窗口账户日简单收益，按 UTC 日历日排列" }, "right": { type: "Sequence[float]", description: "候选侧账户日简单收益，与 left 日钟逐日对应、等长" }, "design": { type: "dict", description: "登记锁定的检验条件：method（paired-circular-log-mean-v1）、block_days、resamples、inner_resamples、seed、alpha、minimum_effect（年化收益比例，仅描述）、design_reason；数值为未校准示例值" }, "grid_points": { type: "int", description: "本次登记网格点数（≥1），用于 Bonferroni 校正与区间覆盖调整" }, "weights": { type: "Sequence[float] | None", description: "可选：多条日序列的对比权重；给出时 left、right 换成对齐的序列列表，检验对象是加权和（交互效应用 +1, −1, −1, +1）" } }} />

**返回**　dict：\{method, days, mean_daily_log_difference, mean_log_basic_interval, mean_log_studentized_interval | None, annual_return_difference, annual_return_difference_interval, interval_coverage_grid_adjusted, p_one_sided | None, p_bonferroni | None, predeclared_alpha, predeclared_minimum_effect, detectable_mean_log_difference_80pct_normal_approx, top_five_absolute_difference_share, block_sensitivity[\{block_days, available, mean_log_interval?, p_one_sided?\}], degenerate_nested_samples, design, limitations[]\}；无任何裁决、采纳或排序字段

**期望行为**

1. 经 registration.validate_design 校验 design，核 grid_points 为正整数；核两序列一维、等长、天数不少于 2×block_days、全部有限且大于 -1，否则按 refusals 拒绝。
2. 两侧取 log(1+r)，差为候选减对照，观测效应为差的均值；年化差 = exp(365·候选平均日对数收益) − exp(365·对照平均日对数收益)。以 seed 建随机源，按 block_days 与 resamples 生成循环块起点索引矩阵，两侧共用。
3. 外层：按同一索引重抽两侧得均值差分布与标准误 se，减观测效应得中心化分布；单侧 p =（中心化值 ≥ 观测效应的次数 + 1）/（resamples + 1）；α′ = alpha/grid_points 下给基本区间、年化差百分位区间与 interval_coverage_grid_adjusted = 1 − α′；p_bonferroni = min(1, p·grid_points)。
4. 嵌套：每个外层重抽内以 inner_resamples 次内层块自助估标准误并算学生化统计量，由其分位数乘 se 给学生化区间；se 退化时 p、p_bonferroni 与学生化区间留空，任一内层退化时学生化区间留空并计入 degenerate_nested_samples，均写入 limitations，不以其他区间替代。
5. 稳健性：对 max(1, ⌊block_days/2⌋)、block_days、2×block_days 各以 seed 重建随机源重做外层重抽，报基本区间与单侧 p，天数不足两块的档标 available=false；报绝对日对数差最大五日占总和比例；报 se·(z_\{1−α′\}+z_\{0.8\})。
6. 附 predeclared_alpha、predeclared_minimum_effect、完整 design 与固定局限句（Bonferroni 只覆盖本网格；p 是零模型尾概率，不是策略有效的概率；自适应搜索后的开发窗口比较不是独立验证；块自助假定日差近似平稳弱相关；年化差区间不检验最小改进）后返回；不写账本。
7. 给出 weights 时，对各序列取日对数收益后按权重加总成一条序列，用同一组块起点重抽；效应、区间与功效按这条序列算。

| 拒绝码 | 条件 |
|---|---|
| `REGISTRATION_INVALID` | design 字段不恰为八项、method 不是 paired-circular-log-mean-v1、整数字段低于下限、alpha 不在 (0, 0.5)、minimum_effect 非有限或为负、design_reason 为空（由 registration.validate_design 抛出）；或 grid_points 不是正整数 |
| `COMPARISON_UNAVAILABLE` | 两序列不等长或非一维；天数少于两个完整块；任一值非有限或不大于 -1 |

2. 取全部 purpose=research、status=passed 的运行；交易段等于开发窗口、开始回执输入身份里的 universe_rule 等于路线的才进表，再按资格视图（qualification.assess 同一判据）只留有经济证据资格的；其余列入 without_economic_evidence，附资格原因，供读者知道哪些候选不在表里、为什么。
3. 四项度量由 report.derive_measures 算，与单运行报告的标题指标同一算法；只有回撤是封存时存下的值，其余三项每次从存下的逐日序列与持仓周期算。
4. 支配：A 在四项上都不差于 B（回撤越小越好，其余越大越好），且至少一项更好。dominated_by 列出压过它的运行；任一项缺值的运行不参与比较，non_dominated 为 null。
5. 只读，不写账本；表里没有分数、排名或门槛。
