# 5　提假设：每次回放之前，先想清楚改什么、凭什么、预计会怎样，再把这些写下来锁进账本。

<p className="rd-translation-note">English translation pending: this page shows the Chinese source text.</p>


提假设夹在策略文件和回放之间。第 3 章的候选谱系给出能从哪一版改起，第 4 章的原生预检和独立源码审查确认候选能跑；这一章决定这一次具体改什么、拿什么来比，并在回放之前把这些写死。

这一步做四件事。先界定假设：选父版本和对照，把改动收成一处规则。再查来源：先读已有的，缺什么再检索，原件入账。然后写下五样：理由和预测、来源、比较维度和检验条件、网格、适用条件。最后登记：代码把这些和执行身份一起锁进账本，回放开始时再核对一遍。怎么想、怎么写由 skill 指导；锁定和核对由代码强制。

举个例子：全池 RSI 路线的 H08，父版本是加了资金费过滤的 H07，改动只有一处，把单笔预算从 500 降回 100。对照没有用父版本 H07 的运行，而是同样 100 预算、不带过滤的 H05。这些都在回放之前登记好，回放开始时代码逐项核对，对不上就不跑。

## 5.1　界定一个假设 [#H-1]

回放前的第一步：选好从哪一版改、拿什么来比，并把改动收成一处规则。

<Steps>

<Step>

读候选清单和当前的研究优先级，定下这条路线接下来往哪个方向改。

</Step>

<Step>

对照父版本文件头里各项职责的立场和已有运行的原生报告，找出值得改的职责。

</Step>

<Step>

为每个假设选一个父版本，再另选一个可比、有经济证据资格的对照。

</Step>

<Step>

把改动收成一处规则，写出机制和比较维度的雏形，交给查来源和写五样。

</Step>

</Steps>

<a id="H-1-1" />

从谱系里定下父版本、对照和改动的范围。

### 谱系里任何一个完整候选都能当父版本，不看推荐和成绩 [#H-1-1-1]

研发父版本，就是这次要在它基础上改的那一版。谱系里任何一个完整候选都可以，不限于当前推荐的、最新的或成绩最好的；亏损、不显著、只作诊断的有效候选也照样能派生。选父版本的理由写进登记，和选对照的理由分开写。

推荐和检验结果说的是哪一版眼下最好，不是哪一版还值得改。用成绩卡派生资格，有潜力的方向会因为一次失利被提前放弃。代码只在登记时核对父版本是账本里已发布的候选（否则拒绝，REGISTRATION_INVALID），不评价它的成绩；选亏损候选作父版本时，Agent 也不用请示、不用质疑它的资格，有评测用例检查这一点。

<div className="rd-example">

全池 RSI 路线里，H02 比较结果不理想，H03 照样从 H02 派生，而当时被推荐的是 H01；H06 比 H05 差，之后的 H07 也照样进入谱系。推荐的版本不必是下一个实验的父版本。

</div>

### 对照和父版本分开选，必须已通过、已封存、有资格、可比 [#H-1-1-2]

比较对照是拿来和本次结果配对比较的一个已有运行，不必是父版本的运行。它的状态必须是通过并已封存，有经济证据资格，而且和本次回放可比：运行环境、账户配置、输入数据都相同。根不带对照；父版本出故障或零成交时可以暂时没有对照，但要引用那份诊断。

比的对象不可比，差异就分不清是改动带来的还是环境、账户或数据不同带来的。这几项由代码在登记和绑定时核对，不合就拒绝，不靠 Agent 自觉。

<div className="rd-example">

全池 RSI 路线里，H08 的父版本是 H07，对照却选了同样 100 预算、不带资金费过滤的 H05。父版本定从哪一版改，对照定和谁比，两件事分开定。

</div>

### 一个假设只改一处规则，并和每个网格点的改动说明逐字一致 [#H-1-1-3]

一个假设只含一处实际的规则改动，写进登记，并且要和每个网格点候选的改动说明逐字一致（不一致会被拒绝，LINEAGE_MISMATCH）。改选币范围（排名、前 N 个、信号筛选、调整频率）、改仓位和资金预算，也都算规则改动。入场和出场联动的改动算一个动作，按一个动作登记和描述，不拆开各自归因。由已有规则推出来的量、没启用的方法的参数，不算改动。

一次改好几处，结果变了也说不清是哪一处的功劳。方向模糊时，Agent 要先把它收束成机制、一处改动、比较维度、网格和适用条件再登记，而不是先跑一遍父版本看结果再调。这些由 skill 指导，有评测用例分别检查模糊方向先收束、改选币按假设登记、联动改动按一个动作登记。

<div className="rd-example">

H06 只把单笔预算从 100 提到 500，H10 只把分钟成交量占比上限从 1% 提到 5%，各是一处规则改动。比如「让出场更聪明」这样的说法，要先收束成一处具体的规则，就像 H03 的改动：普通退出等 120 秒没成交就撤单、余量重报。

</div>

### 下一个假设从缺省、不适用或归因指向的职责里提，写明职责编号 [#H-1-1-4]

策略文件开头的文件头逐项写明 27 项职责的立场：采用、缺省或不适用。Agent 提下一个假设时，先汇总本路线候选文件头里的立场，从标为缺省、不适用的职责，或者归因结果指向的职责里选，并在登记里写明职责编号。

这样每个假设都对准一项具体的缺口，而不是凭感觉随手改参数；写明编号，回放后的归因也知道该对照哪一项职责。

</div>

## 5.2　先查来源并留存 [#H-2]

写理由之前先查来源：读已有的、补检缺口、逐份读，原件入账后登记才能引用。

<Steps>

<Step>

先读账本里已经留存的来源，列出机制上还缺的依据。

</Step>

<Step>

只针对缺口检索，每次检索记一行。

</Step>

<Step>

逐份读来源，记下状态和条件；剔除撤稿，同一工作的几个版本合并成一条。

</Step>

<Step>

把每条经济理由标成外部依据、本地诊断或推测。

</Step>

<Step>

把原件、摘录和检索记录作为证据包入账，登记时按包名引用。

</Step>

</Steps>

### 检索 [#H-2-1]

把要改的机制变成检索记录和一份候选来源清单。

#### 提经济假设前先读已留存的来源，只为缺口另行检索 [#H-2-1-1]

提经济假设之前，Agent 先读账本里已经留存的来源证据包；机制和适用条件仍然相符的，直接引用，只针对机制上的缺口补检。查哪类来源、怎么查按 research-sources 的规定：同一个问题至少换三种说法、至少查两个索引，只引用能解析的 DOI 或 arXiv。可信实践优先找认得出的原作者、官方研究材料或能看到的代码，并记下位置、日期和实际看了什么。产出是检索记录和一份候选来源清单。

先读已有的，避免每次重查、各查各的。工程修复（策略构造、订单接口、因果时钟）不需要盈利论文，依据是引擎的技术文档和原生预检。这条由 skill 指导，评测用例检查先查来源再提假设的顺序，代码不拒绝。

<div className="rd-example">

全池 RSI 路线留存了 RSI 长度和数量容量两组先验证据包。比如要提一个跟成交量上限有关的假设，先读数量容量那一包，条件仍相符就直接引用，只为它没覆盖的部分再检索。比如修订单接口这类工程问题，依据就是引擎文档和原生预检，不用去找盈利论文。

</div>

#### 每次检索记一行；说没找到，只能说按这些查询没找到 [#H-2-1-2]

每次检索在检索记录里写一行：索引名、查询原文、过滤条件、命中数、查询日期、读到哪一层（只有题录、摘要还是全文），以及访问限制（没有密钥、401/403、配额用完）。同一项工作在几个索引都命中时合并成一条，保留各索引的标识。检索记录作为文件，随来源证据包一起入账。

检索有范围，访问也会失败。只写「没有相关研究」就把查询的局限说成了事实。所以否定的话只写「按这些查询没找到」，附上查询和日期；访问失败或全文读不到，记为检索限制，不等于没有先前研究。这条由 skill 指导，有评测用例检查，代码不拒绝。

<div className="rd-example">

比如在两个索引里用三种说法查资金费方向与永续收益，其中一个索引返回 403。记录要写出这三条查询、日期和那次 403，结论只能是「按这些查询在一个索引里没找到，另一个索引无法访问」。

</div>

### 理由三分类与来源的作用 [#H-2-2]

理由分三类，分类只是写在登记里的文字，代码不读，只影响研究优先级。

#### 经济理由逐条标为外部依据、本地诊断或自身推测 [#H-2-2-1]

每条经济理由标成三类之一：外部依据，即别人的研究；本地诊断，即本路线运行里看到的事实；自身推测，即 Agent 自己的猜想。外部依据要写出处位置、市场、窗口、频率、成本和验证条件，并说明它支持的是机制、具体的规则参数，还是只有方法；没读到的条件写「未知」。分类写在登记的理由和来源说明里。

三类分不开，就会把一句猜想或一份模板出处当成论文背书。模板出处、社区实践和方法论文都不为具体参数背书。这条由 skill 指导，有评测用例检查；代码不解析分类，也不设分类字段。

<div className="rd-example">

全池 RSI 演练里，各假设的理由都做了分层，并保留了论文或官方实践原件、实际读到的范围和原市场的限制。论文支持的是机制或规则的选择空间，并没有校准 2000 USDT 的预算、5% 的成交量占比或 120 秒的等待。

</div>

#### 来源只影响研究优先级，不证明在本市场有效，事后材料只追加 [#H-2-2-3]

来源只进入研究优先级里的「机制佐证」一项，不进入审计、资格或检验结果。没有论文的方向照样可以低优先级探索；不按引用数排名、不设引用门槛、不因缺来源关闭方向。出处要记版本或日期，只有登记之前就能看到的版本算事前依据。回放后才找到的材料，另开一个带日期的新证据包追加，原登记和原分类不改。

来源证明的是作者在他的市场和窗口里研究了什么，不证明在这里也有效。让来源决定资格，或者回放后再给旧假设补论文，都会让结果显得比实际更有依据。登记证据包写入后不能改，倒填在账本里根本做不到；另有评测用例检查后找到的来源只追加。

<div className="rd-example">

全池 RSI 演练里，后来补充的材料没有回填进旧的先验证据包。比如一个资金费过滤的假设回放后，又找到一篇讲资金费方向的论文。它只能作为一个新的、带日期的后续证据包入账，原来的登记和理由分类保持原样。

</div>

### 留存来源原件 [#H-2-3]

代码保证登记引用的证据包都在账本里；包里放什么由 skill 规定。

#### 来源原件登记前要先入账成证据包，所引的包不在就拒绝登记 [#H-2-3-1]

证据包是按包名入账的一组材料。来源入账的是原件副本、摘录和检索记录，不只是一个链接；入账走 Agent 写证据的唯一入口 <Ref id="cli.evidence_add" />。证据包只增不改，后来补到的材料另开新包。登记时，代码逐个核对所引用的包名都已在账本里，缺一个就拒绝。

链接会失效，网页会改版，只留链接日后就核对不了当初读的是什么。账本的提交历史还能给出来源和登记谁先谁后，据此可以核对哪些算事前依据。

<div className="rd-example">

比如一份登记引用了两个来源证据包，其中一个还没入账，整份登记被拒；Agent 先把它入账，再重新登记。

</div>

#### 每份来源记状态和条件；撤稿不算，复述不算独立来源 [#H-2-3-2]

读每份来源时记下：状态（期刊、工作论文、预印本还是学位论文）、市场、窗口、频率、有没有样本外检验、有没有扣成本、依据在哪一页哪一节哪张表或图；只读到摘要的标「仅摘要」。这些记录和原件放进同一个来源证据包，供写外部依据时说明支持范围。

同样一句结论，期刊版和预印本、扣没扣成本、有没有样本外，分量差很多。已撤稿的不算来源；同一工作的预印本、工作论文和期刊版合并成一条，引用发表版；别人对同一工作的复述不算独立来源，不然一项研究会被数成好几项。这条由 skill 指导，有评测用例检查，代码不拒绝。

</div>

## 5.3　写下五样 [#H-3]

把理由与预测、来源、比较维度与检验条件、网格、适用条件这五样写进登记。

<Steps>

<Step>

写经济理由和一个能被结果否定的预测，并写定各种结果对应的下一步。

</Step>

<Step>

引用上一节已经入账的来源证据包。

</Step>

<Step>

选唯一的比较维度，声明检验条件，并写设计理由。

</Step>

<Step>

把每个网格点发布成候选，写定一到五个点和每点的参数说明。

</Step>

<Step>

写下这次试验的适用条件，整份交给登记锁定；任何一项不合，整份都不写入。

</Step>

</Steps>

### 经济理由与预测 [#H-3-1]

理由和预测写进登记，随登记一起锁定。

#### 理由写清机制、谁在付钱和代理；预测要能被回放结果否定 [#H-3-1-1]

经济理由说清三件事：什么市场机制带来这笔收益；谁在付钱，也就是对手方是谁、转移的是谁的成本；为什么这个机制在本路线的共同可交易范围和开发窗口里仍应存在。机制依赖回放输入里没有的量时，写明用什么代理以及代理的局限。预测写在登记的比较维度上的变化方向，以及预计体现在哪些成交或持仓特征上。

「会赚钱」「表现更好」这类说法怎么都否定不了，不算预测；只有能被结果否定的预测，回放才真正检验了点什么。预测按归因切面（报告里固定的拆法）上的标量写，每项改动的职责至少一项，结构见 <Ref id="P.2.1.1" />。代码只核对理由和预测都是非空、长度有限的文本，不合就拒绝（REGISTRATION_INVALID），不评价写得好不好；登记后两者随登记证据包一起锁定。

<div className="rd-example">

H07 按已知的历史资金费支付方向过滤新入场。它登记时的预测正是针对资金费这一项，并写明不声称资金费单项的因果。回放后归因发现价格那一块反而变差，这个读数就可以和预测并排对照。

</div>

#### 回放前写定五类结果各自的下一步，事后不改写 [#H-3-1-2]

Agent 在预测里同时写一份结果到行动的对照：改善、不显著、亏损、零活动（没有实质交易，只留诊断）、无效（完整性审计不通过），每类一句话，写出现这种结果时后续研究怎么做、研究优先级怎么变。可选的动作有沿这个方向细化、换对照、修复后重试、降低优先级并写明什么时候重新评估。

结果出来后再决定怎么解读，很容易把不利结果说成「这个方向不行」。对照表回放前就随登记锁定；回放后按它更新优先级，不能根据结果改写，也不能把不利结果改成排除整个方向。有遗漏时，补充只追加在反馈记录里并注明写于结果之后，不回填登记。这条由 skill 指导、评测用例检查；代码不解析内容，只在预测非空的核对里覆盖到它。

<div className="rd-example">

比如提高成交量占比上限的假设，可以事先写：改善就再试更高一档；不显著就保持优先级、换一个对照；亏损就降低优先级，等容量规则改了再评估；零活动先查成交量上限是不是卡住了下单；无效就修复后重试。

</div>

### 比较维度与检验条件 [#H-3-2]

检验用的数值由 Agent 声明并写明理由，随登记锁定。

<a id="H-3-2-2" />

**检验条件随登记声明并锁定，数值只是没校准过的示例**

检验条件是登记时声明的比较方式。Agent 写明检验方法、显著性、最小改进、块长、重抽次数和随机种子，另写设计理由：误判和漏检怎么权衡、样本有多长、块长为什么这么选。数值由 Agent 按情境选，不是产品常数，登记后不改。

结果出来后再挑检验方法和门槛，就可以把任何结果说成显著。代码只查各项是否齐全、类型和范围对不对，不评价数值合不合理。

<div className="rd-example">

全池 RSI 演练里，十项都给出了 98.5% 的配对区间，用的 0.015 这类数值是与方法相容的探索值，并未经本产品校准；十项区间全部跨零，说明不能宣称稳定改善，也不能据此说机制无效。

</div>

### 网格与适用条件 [#H-3-3]

网格定这次试什么，适用条件定结论在什么范围内成立。

<a id="H-3-3-1" />

**网格一次写定一到五个点，每个点都是已发布、谱系一致的候选**

网格是这次登记要试的那几个版本。每个网格点都是账本里的一个候选，附上全部参数的文字说明；每个点的父版本和改动说明必须和登记一致，根登记时各点都没有父版本。每个点要求的运行环境必须和登记时探测到的一致，同一份源码不能出现两次。

试过的配置不写进网格，就等于偷偷多试了几次，最后只报好看的那个。所以每个试过的配置都要写进网格，点数计入试验次数。

<div className="rd-example">

比如要比较 RSI 长度 20、24、28 三个值，就发布三个候选，各写一句参数说明，三个点一次写进同一份登记；之后想加 32，只能另行登记。

</div>

## 5.4　登记先于回放并锁定 [#H-4]

登记先于回放：代码把五样和执行身份锁进账本，回放开始时在同一事务里再核对一次。

<Steps>

<Step>

网格里每个候选先做完原生预检和独立源码审查，结论入账。

</Step>

<Step>

登记时，代码读当前研究路线、探测运行环境、导出市场数据，合成执行身份。

</Step>

<Step>

代码在同一个账本事务里校验登记内容和执行身份，通过才写入，否则整份不写。

</Step>

<Step>

回放开试验时，代码在同一事务里重验登记，并把这次回放绑到一个网格点上。

</Step>

<Step>

绑定提交成功才启动引擎；任何一项不符就整笔撤销，不留试验记录。

</Step>

</Steps>

### 登记身份与先后顺序 [#H-4-1]

登记写定内容和执行身份；回放开始时核对先后顺序和是否一致。

#### 登记把假设的全部内容锁进一个不能改的证据包 [#H-4-1-1]

登记就是回放前把假设锁进账本。登记证据包里有假设的各项内容、检验条件、对照，以及每个网格点的审查引用，并写明改动涉及的职责编号：根为空，派生至少一项。网格里的源码必须已在该运行环境下通过原生预检和独立源码审查。

事先写下的东西事后能改，就等于没写。证据包写入后不改，每次读回都核对内容哈希；要更正，另立一个新包。

<div className="rd-example">

全池 RSI 演练里，顺序都是审查先于登记、登记先于研究运行；每项都保留了源码、父版本、改动、登记和原生证据。

</div>

#### 执行身份在登记时由代码探测合成，不能手填 [#H-4-1-2]

执行身份是一次回放用的源码、运行环境、账户与撮合配置、输入数据这几样的身份。它在登记时由代码探测出来，随登记写入；登记的窗口必须等于研究路线的开发窗口。

这些身份要是能手填，就没法保证回放跑的和登记写的是同一套东西，前后比较也就不可信。

<div className="rd-example">

全池 RSI 演练的正式运行都钉在同一个运行环境摘要和同一个市场提交上，开发窗口是 2025-10-09 至 2026-10-07。按这条规则，这些都由代码读出，Agent 不能自己写一个进去。

</div>

1. 读当前研究路线：开发窗口、钉住的市场提交和范围规则。
2. 把运行环境解析成唯一的摘要，在隔离容器里探测它的要求和配置。
3. 按路线钉住的市场提交导出一份不可变的输入，算出内容身份。
4. 把这几样合成执行身份，随登记一起写入。

#### 启动引擎前，要在开试验的同一事务里绑定登记 [#H-4-1-3]

试验是每次回放开始前先写进账本的一条记录。开试验时，代码在同一个事务里读回登记并重新校验，全部通过才把这次回放绑到一个网格点上，记下一次消耗，和试验一起提交。

核对和开跑要是分两步，中间就可能有东西变了。放在同一个事务里，要么全部成立，要么整笔撤销；提交成功才启动引擎，任何一项不符就不留试验。

<div className="rd-example">

全池 RSI 演练共有 67 次试验，绑定到正式研究运行的只有 11 次（含根），其余 56 次没有绑定登记，不算登记研究的结果。

</div>

1. 先写试验记录，同一事务里读回登记并重新校验。
2. 核对所跑的源码在网格内，执行身份和登记逐项一致。
3. 核对预检和审查仍然有效、登记早于试验、这个网格点没用过。
4. 全部通过就记下这次消耗，和试验一起提交；提交成功才启动引擎。

这样 Agent 不必靠 skill 记住每个字段的含义，看拒绝信息就知道该怎么改。

#### 下一次登记前，要先补齐解释、到期的复盘和复盘节奏 [#H-4-1-5]

复盘是未复盘的试验达到 Agent 自定的节奏时，回看全部可用候选、给出推荐。下一次登记前代码核对三件事：每个已完成的试验都有一条解释判断；没复盘的试验达到节奏时，已经写了新的综合推荐；派生登记前已声明复盘节奏，之后只能改得更频繁。研究状态会提前列出下一次登记还缺什么。

### 网格点消耗与已跑源码 [#H-4-2]

每个网格点只能用一次，已经回放过的源码不能当新的来登记。

#### 每个网格点只用一次；同一源码再试要另行登记并指明前一次 [#H-4-2-1]

网格点是一次登记里列出的待试候选之一。绑定成功就记下一次消耗，和试验同时成立、同时撤销；之后回放无效或中断，照样算用掉了一次。同一份源码想再试，要另行登记，并指明实际用掉它的那次登记。

无效或中断就不算数的话，可以一直重跑到出现好看的结果为止。重复尝试连成一串，不算独立证据。这一条由账本保证。

<div className="rd-example">

比如某个网格点回放到一半因为内存不足中断了，这个点已经用掉；修好后要再跑同一份源码，得另开一份登记，写明它是那一次的再试。

</div>

#### 回放过的源码不能当新的登记，只有事前声明的预检例外 [#H-4-2-2]

登记时，代码按内容哈希查试验记录，已经跑过的源码不能当新候选登记；没登记就跑过的回放，也不能事后补成登记结果。唯一的例外是原生预检：要事先声明用途，同一源码、同一运行环境，而且没有绑定任何登记。跑过的源码只能按再试的规则另行登记。

先跑看结果，再挑好的补登记，事前登记就失去意义了。预检只确认工程上能跑，不算经济证据，所以可以例外。

<div className="rd-example">

比如 Agent 先用探索回放跑了一版，看着不错想补一份登记，会被拒绝。全池 RSI 演练里，预检用的工程支架另行声明、单独保留，没有冒充自然小时级的策略机会。

</div>
