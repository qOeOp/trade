报告接在第 7 章之后。只有通过完整性审计、又具备经济证据资格的运行，才有绩效指标；绩效指标就是年化、夏普、回撤、胜率这类成绩数。报告只把这些数摆出来，不判好坏，也不说该不该采纳。单运行报告和第 10 章的对比报告用同一套栏目（<Ref id="R.3" />）。

### 产品算的绩效指标 [#R-1-1]

代码只算 Agent 不该给自己打分的那几项，封存时算一次，读回时按资格决定给不给看。

#### 产品只算四类 Agent 不该自评的绩效指标 [#R-1-1-1]

代码只算四类：账户年化、标记价最大回撤、计划胜率、利润来源拆分。利润来源拆成价格盈亏、手续费、资金费三项。每类都附上总体（统计的是谁）、样本量、局限清单和计算版本；某一项算不出来，只把这一项置空并写明原因，运行本身不会因此被拒绝。

这几项直接用来比较和推荐。让 Agent 自己算，就等于自己给自己打分。

#### 推不出的指标封存时算一次并冻结；推得出的按定义版本读时算 [#R-1-1-3]

封存时，代码只把原生报告移走后再也算不出的指标算一次，连同代码版本存进账本，之后不覆盖；比如标记价回撤要用逐分钟权益。能从持仓周期和逐日序列算出的指标，比如年化和计划胜率，读的时候按度量的定义版本算，同一版本任何时候算出的都一样。无效运行没有封存结果。

如果读的时候随意按最新口径重算，算法一改，旧运行的成绩就悄悄变了，以前的比较和推荐也跟着失去依据。每个度量带定义版本，口径改了就是新版本；旧版本仍可按原定义复算，新旧并列，谁也不替代谁。

#### 没有经济证据资格的运行，绩效指标整体置空 [#R-1-1-4]

读回报告时，代码按资格决定给什么。无效运行只留失败原因和原生摘要的引用。有效但没有实质活动（一笔交易都没发生），或者不可比的运行，指标整体置空，只留诊断。算不出或对不上的单项留空写原因，不猜，也不填占位数。

### 每个绩效指标附带什么 [#R-1-3]

每个绩效指标都带着算出它的代码版本和一份完整的局限清单。

#### 报告写明算指标和判资格各用的哪个代码版本 [#R-1-3-3]

度量目录的版本在封存时记下；资格判定所用的版本在读回时取。资格判定还要注明用了哪项检查。两个版本不同时，报告把两个都列出来，谁也不替代谁。观察到的实际费率（按挂单和吃单分的手续费除以成交额）也在封存时算出，存在单运行报告里。

这样每个绩效指标、每个资格结论，都能找到产生它的那份代码。出了问题能查到是哪段代码算的。

### 年化、夏普与计划胜率 [#R-2-1]

年化和夏普由引擎写进原生摘要，计划胜率在封存时算；三项都只算开发窗口，不含预热段。

#### 年化按开发窗口的实际天数复利折算，分母是初始权益 [#R-2-1-1]

年化 ＝（期末权益 ÷ 初始权益）的（365 ÷ 窗口天数）次方 − 1。窗口不含预热段，天数按实际时长算，不取整。期末权益取引擎的组合快照，包括没平仓的浮动盈亏。

窗口不满一年时，按实际天数折算，不同长度的窗口才能放在一起比。期末权益不为正时，这个公式没有意义，年化留空写原因，运行不会因此判无效。

#### 计划胜率＝已平仓且算上费用后赚钱的计划 ÷ 全部计划 [#R-2-1-3]

计划就是策略用标签划出的一笔完整交易。一个计划算「赢」，要已经平仓，且算上手续费和资金费后的已实现盈亏大于零。分母包括已平和没平的计划，期末还没平的算「没赢」。每张订单恰好带一个计划标签，一个计划只交易一个合约。

不扣费用，很多小赚的交易会被算成赢，胜率虚高。期末没平的不算赢，避免靠一直拿着亏损单不平来抬胜率。标签不合规时，胜率置空写原因，运行不判无效。

### 最大回撤 [#R-2-2]

最大回撤按每根 K 线的标记价权益来算，并写明用的是什么价、多久采一次。

<a id="R-2-2-1" />

**最大回撤看每根 K 线的标记价权益，比峰值最多跌了多少**

回撤 ＝（峰值 − 权益）÷ 峰值，取窗口内的最大值，峰值从初始权益算起。权益 ＝ 账户余额 ＋ 没平持仓按标记价算的浮动盈亏。标记价就是交易所算保证金和强平用的那个价。

交易所按标记价算保证金和强平。只看账户余额，就看不到持仓中途的浮亏，会低估回撤。缺标记价或者估值时点对不齐，完整性审计就不通过。

<div className="rd-example">

### 资金使用率 [#R-2-3]

skill 规定资金使用率怎么算、怎么和回撤一起读；算它用的数据可信，由代码保证。

#### 资金使用在封存时由代码算出，存在单运行报告里 [#R-2-3-1]

资金使用的峰值类指标由代码在封存时从原生的逐分钟敞口算出：按 K 线采样的名义敞口峰值、在市时间、锁定保证金的峰值；同时把每天的平均名义敞口写进逐日序列，全窗口的平均名义敞口和它占权益的比例由逐日序列读时算。敞口每行标在 K 线时刻 T，表示到下一根 K 线之前所有事件发生后还持有的仓位，按 T 的标记价估值。某根 K 线没有行，就是空仓。

回撤小可能只是钱几乎没用上，不读资金使用就会看错。这几个数会进推荐和比较，由代码算才不会被 Agent 按需挑口径；逐分钟敞口本身是缓存，算完不入账。从谱系里第一个有效的根候选起，每个有效运行都有这几项；Agent 读运行时必须同时读它们，这条由 skill 规定，用评测用例检查。

<div className="rd-example">

1. 名义额在开发窗口全部 K 线上的时间加权平均：从交易起点算，空仓的 K 线计零，同时给出占同一时刻权益的比例。
2. 采样峰值：写明是按 K 线采样的峰值，不是逐笔的极值。
3. 锁定保证金：取自账户数据，包括挂单占用的部分。
4. 在市时间：有敞口的 K 线根数占开发窗口根数的比例。

### 两种报告与动态分析 [#R-3-1]

决定依赖的部分固定、带版本；其余的分析保持动态。

#### 两种报告共用一套度量目录，栏目顺序相同 [#R-3-1-1]

度量目录固定一组栏目和顺序，单运行报告和对比报告共用。单运行给本次的值；对比给两边并列的值和差。检验结果、交易配对、预测对照三栏只出现在对比报告里。栏目就是本章的切面与标量（<Ref id="R.3.2" />），每个标量在目录里只定义一次。

没有固定栏目，每次报告拆什么、拆多深全凭 Agent 临场决定，有的版本拆得细，有的一笔带过，前后没法比，也容易只挑对自己有利的角度。

<div className="rd-example">

全池 RSI 路线 H07 对 H06 的利润来源一栏，账户口径的差是：价格 −281.67，手续费 ＋119.38，资金费 ＋828.73，期末浮动 −8.62，合计 ＋657.82 USDT。这一栏让人一眼看出：资金费多出的部分比总改善还大，价格腿反而变差了。

</div>

1. 身份与资格：单运行给运行身份、经济证据资格和原因；对比给两边身份和可比资格。
2. 检验结果：只在对比报告里，给效应、区间、p 和检验条件（<Ref id="V.4.1.1" />）。
3. 绩效指标：单运行给年化、标记价最大回撤、计划胜率、夏普；对比给两边并列和差。
4. 利润来源：单运行给价格、手续费、资金费、期末浮动；对比给四项的差（<Ref id="R.3.2.1" />）。
5. 规模与仓位择时：单运行给平均敞口、单位敞口收益、水平项和择时项、涨月和跌月的敞口、年化与回撤之比；对比给各项的差（<Ref id="R.3.2.2" />）。
6. 费用：单运行给吃单占比、盈亏平衡费率倍数；对比给盈亏平衡费率倍数（<Ref id="R.3.2.3" />）。
7. 品种与方向：单运行给前五个合约占绝对盈亏的比例、多空分开列；对比给同样几项的差（<Ref id="R.3.2.4" />）。
8. 市场暴露：单运行给对等权篮子和 BTC 永续的斜率与截距；对比给斜率之差和截距之差（<Ref id="R.3.2.5" />）。
9. 时期：单运行给盈利月份占比、去掉最好五天后剩下多少；对比给胜出月份占比和剩余的差（<Ref id="R.3.2.6" />）。
10. 交易结构：单运行给周期数、胜率、平均赢亏、每笔期望、持仓时长、出场类别；对比给同样几项的差，以及每笔期望之差的拆分（<Ref id="R.3.2.7" />）。
11. 交易配对：只在对比报告里，给覆盖、删掉的和新增的交易、同一机会上的差（<Ref id="R.3.2.8" />）。
12. 回撤：单运行给最大回撤、持续天数、回撤期间的主导合约；对比给同样几项的差（<Ref id="R.3.2.9" />）。
13. 预测对照：只在对比报告里，给每项登记的预测与实测是否同方向；登记时声明了交互的，附上交互效应（<Ref id="P.2.1.2" />、<Ref id="P.3.1.2" />）。
14. 局限：单运行给合并去重的局限清单；对比把两边的局限合并去重。

#### 封存时只算存储数据推不出的指标，存成一行封存结果 [#R-3-1-3]

封存时，代码只算原生报告移走后就再也算不出的指标：资格事实（每项是否通过、原因码和计数）、标记价回撤及其区间和主导合约、资金使用的峰值和在市时间、锁定保证金峰值、按挂单吃单分的手续费和成交额、订单漏斗、计划统计是否成立。它们存成一行封存结果，以运行和代码版本为键，每项指标写成「度量名@定义版本」，金额用十进制字符串。年化、胜率、利润来源、交易结构这些能从持仓周期和逐日序列算出的量，不存，读的时候按各自的定义版本算。

### 切面与标量 [#R-3-2]

报告的固定拆法：每个切面给几个标量、指向几项职责。单运行报告给本次的值，对比报告给两边的值和差；明细表由 Agent 自己算。

#### 利润来源桥：账户净值差拆成四项，加起来正好相等 [#R-3-2-1]

账户净值差拆成四项之差：价格盈亏、手续费、资金费、期末未平仓的浮动盈亏，四项相加等于账户净值差。口径是整个账户：价格项含全部已实现，手续费含全部成交，资金费含未平仓的，浮动取引擎的期末快照。前三项沿用封存时已对过账的利润来源拆分，容差同 <Ref id="R.1.1.2" />；对不上，整个切面留空。

只看账户差，分不清是行情赚的、少付了费用，还是资金费帮了忙。这个切面指向三项职责：预期收益来源（B1）、持有成本（H1）、执行方式（G1）。

#### 规模与仓位择时：分开算放大了多少和放得准不准 [#R-3-2-2]

仓位是策略的一部分，放大仓位赚的钱照算。但只看账户差，会把单纯加仓误读成品质变好；两个都亏的版本，仓位小的也会因为少亏而胜出。所以品质要另看和规模无关的数。

1. 逐日盈亏写成当日平均名义敞口乘当日每单位敞口的收益；没有敞口的日子单独列出。
2. 全窗口合计拆成两份：平均敞口乘平均单位收益是水平项，敞口和单位收益的协方差是仓位择时项，两份相加等于合计。
3. 按等权篮子的月收益正负分出涨月和跌月，各给平均敞口和单位敞口收益；仓位管得好，涨月敞口大、跌月敞口小，择时项为正。

5. 标量：mean_notional、unit_return、level_term、timing_term、up_month_notional、down_month_notional、return_over_drawdown。

#### 市场暴露：赚的是跟着大盘走，还是自己的本事 [#R-3-2-5]

账户日收益分别对等权篮子和 BTC 永续的日收益做两次单因素回归，每次都加一项前一天的市场收益，斜率取两项之和；截距按日给。比较两个版本时，直接拿逐日收益差对市场回归，给斜率之差和截距之差。它指向组合敞口（E2）、对冲（D2）和条件过滤（A3）。

全池的差可能只是净方向变了，跟着大盘涨跌。小币对行情的反应常常慢一天，不加前一天那一项，斜率会被低估。

<div className="rd-example">

比如两个版本的逐日收益差回归下来，截距差接近零，斜率差解释了大部分差。那么改善主要来自更多地跟着篮子走，下一步该看的是净方向和对冲，而不是信号。

</div>

1. 等权篮子是当天在共同可交易范围内、有交易的合约，按日等权；合约退出范围或下架的那天，按它最后一个日收益计入，然后移出。
2. 两次回归：对等权篮子、对 BTC 永续，各加一项前一天的市场收益，斜率取两项之和。
3. 截距附带对异方差和自相关都稳健的标准误，滞后阶数按样本长度自动选；不设显著性阈值。
4. 对比时用逐日收益差对市场回归，直接给斜率之差和截距之差。

#### 交易结构：两侧各自统计再比，不逐笔配对 [#R-3-2-7]

#### 交易配对：用固定算法对上两侧的交易，先报覆盖 [#R-3-2-8]
