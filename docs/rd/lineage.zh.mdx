# T　候选谱系：什么算一个候选，候选之间怎样经父版本和改动说明连成树和森林。

本章承接 A 章的研究循环，回答什么算一个候选：它以源码字节的内容哈希为身份，经父版本和改动说明连成树与森林，任一候选都能再派生；运行结果和推荐都不改变身份与谱系。

## T.1　认定候选：什么算一个候选 [#T-1]

<Steps>

<Step>

Agent 写完一份完整策略文件，决定它是根，还是带父版本和改动说明的派生候选。

</Step>

<Step>

发布时账本按源码字节算出内容哈希，核对谱系后入账。

</Step>

<Step>

账本返回引用名和内容哈希，之后都按内容哈希引用这个候选。

</Step>

<Step>

以后每次读出都重算哈希，与入账时的记录核对。

</Step>

</Steps>

### T.1.1　候选的身份与根 [#T-1-1]

候选的身份怎样确定。

<Cap id="T.1.1.1" kind="database" tier="verified" tierLabel="已验证" tierNote="演练中，每个假设的网格点都以已发布版本的内容哈希登记并绑定执行，报告与比较都指向精确源码。" title="候选以内容哈希为身份，相同字节不能再发布">

- 候选的身份是账本按源码字节算出的内容哈希，Agent 不能填写或改写。
- 名字和版本号只是引用名；改名、复制或只改注释，字节变了就是另一个候选。
- 同样的字节再次发布会被拒绝，并指回已有的那个候选。
- 候选只增不改，每次读出都重算哈希核对，不符即视为账本损坏。

## T.2　连成谱系：父、对照与分枝 [#T-2]

<Steps>

<Step>

Agent 选一个已有候选作父版本，写一句改动说明后发布新候选。

</Step>

<Step>

不带父版本的就是根，根不能带比较对照。

</Step>

<Step>

登记时只核对谱系，不读父版本或自身任何运行的绩效指标。

</Step>

<Step>

试验和运行的结果不改变候选身份和谱系。

</Step>

<Step>

要从任一候选（含旧的、亏损的）另开一枝，就以它为父版本回到第 1 步。

</Step>

</Steps>

### T.2.2　树、森林与候选清单 [#T-2-2]

每个候选指向父版本，直接连成森林，候选清单把它原样读出。

<Cap id="T.2.2.3" kind="code" tier="rehearsal" tierLabel="演练证据" title="候选清单列出全部候选与谱系，不带分数或推荐">

- 清单列出每个候选的身份、父版本和改动说明。
- 每个候选附上已被试验用掉的网格点，及对应运行是通过、无效还是未完成。
- 每个网格点附读取时判定的经济证据资格和原因；不可用的不附绩效指标，也不改写已存结果。
- 清单不含分数、排序或推荐；综合推荐由 Agent 另写判断记录。
