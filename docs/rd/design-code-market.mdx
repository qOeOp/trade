## `market/aggtrades.py` [#def-mod-market-aggtrades-py]

完整源 aggTrades 的只追加导入：每个合约月一次事务与提交，同一个月的几个合约同时写入，逐日按官方校验和读取归档，按独立的 1e8 整数编码精确写入 <Ref id="table:agg_trade" />。它不参与 K 线、报价读取或周期派生；回放只在入口请求成交时由 <Ref id="market.trade_rows" /> 读它、<Ref id="market.write_trades" /> 写成 TradeTick；推算报价（<Ref id="market.derive" />）另从同一批归档推算，不读这张表。

| 入口 | 职责 |
|---|---|
| <Ref id="implementation:impl-market-aggtrades-py-import_month">import_month</Ref> | 一个月的一个或几个合约：持导入锁，每个合约一个导入连接同时写入，各自核对库非空、工作集干净、提交校验组与表存在，前一日续接核对，逐日分批写入，读数与归档哈希进提交消息 |
| <Ref id="implementation:impl-market-aggtrades-py-batches">batches</Ref> | 逐行读一日 CSV，按批产出 INSERT 行；核对编号连续、时间不倒退且落在当日，累计日读数 |
| <Ref id="implementation:impl-market-aggtrades-py-scaled">scaled</Ref> | 十进制字串精确转为 1e8 定标的有符号 64 位整数，放不进即 SCALE_LOSS |
| <Ref id="implementation:impl-market-aggtrades-py-fetch_archive">fetch_archive</Ref> | 按官方日归档键取 ZIP 与 .CHECKSUM，流式下载并核对 SHA-256，缓存命中直接用 |

#### `import_month` [#impl-market-aggtrades-py-import_month]

```python
def import_month(profile: dict, month: date, cache: Path, symbols: list[str], log=print) -> dict:
```

一个月的一个或几个合约，每个合约一次事务与提交。先核对合约在库的允许范围内（重复或格式不对即 IMPORT_SCOPE）、`month` 是月初且有已收盘的 UTC 日（否则 MONTH_INVALID），以导入账号开一个连接持 GET_LOCK('market-import:\<库名>') 直到全部写完；每个合约另开一个导入连接，在各自的守护线程里同时写入。单个写入的时间大多耗在每批的往返等待上，Dolt 对不同合约的写入并行处理（2.4.2 实测：三个写入约为一个的三倍行速）。每个合约：库没有 K 线导入即 MARKET_EMPTY，工作集不干净即 DIRTY_WORKING_SET，服务的提交校验组不含 commit 即 COMMIT_CHECKS_DISABLED，没有 agg_trade 表即 SCHEMA_MISMATCH（先跑 `market upgrade`），早先导入用过别的编码即 RULE_VERSION_MISMATCH，同合约月已有行即 MONTH_EXISTS。前一日归档只过 batches 的校验与续接，不插入；没发布的前一日只在库里还没有该合约更早的成交时放过。随后逐日 fetch_archive → batches → INSERT，日读数、归档 SHA-256 与编码身份写进提交消息；每个合约的回执加 trade_rows 与 market_commit；整个调用返回 month、imports（按合约顺序的回执）、trade_rows（合计）与 seconds。任何拒绝都在该合约提交前回滚；一个合约被拒不撤销其他合约的提交，抛出的是第一个被拒合约的拒绝，消息里列出其他合约已做的提交。进程中断时所有连接一起断开，没提交的写入一律不落。

### `coverage_facts` [#def-market-coverage_facts]

在固定市场提交上为一个合约产出 market-coverage-v1 事实字典：成员月份、输入区间内成交价与标记价的缺口区间与零成交量分钟、两者时刻对齐、资金费结算条数与首末时刻；首末数据只作上市下架的代理（不是交易所事实，不另标状态）。导出器据此写回执进入输入身份，并写进开始回执的 input-coverage.json。

```python
def coverage_facts(
    conn: MarketConnection,
    commit: str,
    symbol: str,
    start_ms: int,
    end_ms: int,
    last_bars: MinuteTable,
    mark_bars: MinuteTable,
    funding_rows: list[tuple[int, Decimal]],
) -> dict
```

**返回**　dict，格式 market-coverage-v1：\{format, commit, symbol, input_interval_ms:[start,end], last:\{rows, first_open_ms, last_open_ms, gap_intervals_ms, missing_minutes, zero_volume_minutes\}, mark:\{同结构，无 zero_volume_minutes\}, last_mark_unmatched_minutes, funding:\{rows, first_ms, last_ms\}, member_months:[YYYY-MM-01…], listing_delisting:\{data_bounds_proxy:\{last:\{first_open_ms,last_open_ms\}, mark:\{…\}\}\}, interpretation\}；导出回执原样存入（market.export_episode）

**期望行为**

1. 核对区间：start_ms \< end_ms 且两者落在整分钟网格；核对 commit 为 32 位 `[0-9a-v]` 的已解析 Dolt 提交哈希；不满足即拒绝，不做任何读。
2. 核对合约在该提交上存在于 instrument 表（AS OF commit）；不存在即拒绝；存在但无 K 线不拒绝，照实记零行。
3. 核对 last_bars、mark_bars 的 ts_open 均为整分钟且升序去重；不满足即拒绝（输入形状，不是市场事实）。
4. 对 LAST 与 MARK 各算 missing_intervals(ts_open, start_ms, end_ms, 60000) 得缺口区间与缺失分钟数；LAST 另计 volume == 0 的分钟数；两者 ts_open 对称差的条数记为 last_mark_unmatched_minutes。
5. 按 commit AS OF 读 universe_month 得该合约的成员月份；读 bar 表每价格类型 MIN/MAX(ts_open) 作上市下架的数据边界代理，只记边界，不另标状态或原因。
6. 组装字典返回：资金费只记条数与首末时刻（逐笔时刻留在钉住的提交里，market bars 可读），结算间隔与缺失结算由 market.diagnose_coverage 另算；不评级、不删币、不缩窗、不补数；interpretation 写明零活动与缺口不等于经济失败，也不替策略判定指标就绪。

| 拒绝码 | 条件 |
|---|---|
| `INTERVAL_INVALID` | start_ms >= end_ms，或任一端点不在整分钟网格上 |
| `MARKET_COMMIT_INVALID` | commit 不是 32 位 `[0-9a-v]` 的已解析 Dolt 提交哈希（传入了可移动引用名、标签、Git 的 40 位哈希或空值） |
| `UNKNOWN_SYMBOL` | 该提交 AS OF 下 instrument 表无此合约（合约从不存在于市场库，区别于有合约无 K 线） |
| `SOURCE_SHAPE` | last_bars 或 mark_bars 的 ts_open 不是整分钟、无序或重复 |

### `diagnose_coverage` [#def-market-diagnose_coverage]

入口与命令行的只读覆盖读口：按钉住的市场提交对显式给出的合约清单逐个产出覆盖事实，并在给了生命周期证据包时附上校验后的生命周期回执（上市、禁新仓、下架结算、ticker 重用）。只返回输入事实，不做资格评级，不删币、不缩窗、不补数、不判经济失败。

```python
def diagnose_coverage(
    profile: dict,
    at: str | None,
    symbols: list[str],
    start: str,
    end: str,
    lifecycle_bundle: tuple[dict, dict[str, bytes]] | None,
) -> dict
```

**返回**　dict：\{commit, scope:'explicit_symbols', input_interval_ms:[start,end], coverage:[market-coverage-v1 … 加 quotes:\{imports:[\{month, through, quote_rule, commit, rows\}], first_ms, last_ms, uncovered_intervals_ms\}，terms:\{observed_at, terms_source, price_increment, size_increment, min_quantity, max_quantity, min_notional, min_price, max_price\}，与 symbols 同序], lifecycle:\{symbol:[episode …]\} | None, lifecycle_missing:[symbol …], interpretation\}

**期望行为**

1. 解析区间：start、end 转 UTC 毫秒并核对整分钟与 start \< end；核对 symbols 非空且无重复；不满足即拒绝。
2. 经 market.connect 只读打开市场库，market.resolve_commit(conn, at) 得唯一提交哈希；解析失败按其拒绝码原样向上。
3. 若给了 lifecycle：先 market.validate_lifecycle(body, commit, files) 核对清单绑定同一提交、事件为引擎原生字典、时钟单调、来源原件在包内；不符即 LIFECYCLE_INPUT 拒绝整次读，不部分返回。
4. 逐合约按提交 AS OF 读 bar 表的 LAST、MARK 1 分钟 K 线与 funding 表区间内结算行，调用 market.coverage_facts 得事实字典；单个合约的 UNKNOWN_SYMBOL 不吞掉，按拒绝向上。再按 market.quote_imports(conn, commit) 的导入回执并入该合约的 quotes：持有它的每次 quote 导入（月份、through 即不含的结束日、规则、提交、回执逐日 quote_changes 之和作行数），quote 表 AS OF 提交在区间内的首末时刻，以及区间内没有任何导入覆盖的 [from, to) 段；不数表行（一个月 BTCUSDT 数千万行），没有导入时不读 quote 表。quotes 不进导出回执。再按 market.trade_imports(conn, commit) 同样并入 trades：持有它的每次完整 aggTrades 导入（月份、through、codec、提交、回执逐日 trades 之和作行数），agg_trade 表 AS OF 提交在区间内的首末成交时刻，以及没有导入覆盖的段；同样不数表行、不进导出回执。再按 funding_spacing 并入该合约的结算间隔：相邻结算各取最近整点后的间隔，相等的连成一段（spacing:[\{spacing_ms, from_ms, to_ms\}]，换段即间隔变化）；单个间隔是两侧同一间隔的整数倍 k≥2 时记 k−1 次缺失结算（missing_settlements:[\{after_ms, before_ms, missing\}]），不算间隔变化。不进导出回执。再并入 market.terms(conn, commit, symbol) 的规格行（去掉 symbol）：导出器对整个窗口用的就是这一行（提交上最新观测，CURRENT_SNAPSHOT_APPROXIMATION）。规格不进导出回执，回执已记 terms_source 与 terms_observed_at。
5. 把每合约的校验后生命周期片段并入返回；清单里没有该合约的记入 lifecycle_missing，只作事实不作判定。
6. 组装返回，不排序、不筛除、不改窗口；interpretation 固定说明缺口、零量、资金费缺失、首末数据均为输入事实，入口不据此删币、缩窗、补数或判经济失败，也不替策略判定指标就绪。

| 拒绝码 | 条件 |
|---|---|
| `INTERVAL_INVALID` | start、end 缺时区、不在整分钟网格或 start >= end |
| `EMPTY_SYMBOLS` | symbols 为空或含重复项（读口只接受显式清单，不做全范围展开） |
| `UNKNOWN_REF` | at 不是 Dolt 引用名、标签或已知提交（由 market.resolve_commit 传出） |
| `AMBIGUOUS_REF` | at 的哈希前缀匹配多个提交（由 market.resolve_commit 传出） |
| `NOT_A_COMMIT` | at 指向工作集（由 market.resolve_commit 传出） |
| `UNKNOWN_SYMBOL` | 任一合约在该提交下不存在于 instrument 表（由 market.coverage_facts 传出） |
| `LIFECYCLE_INPUT` | 给出的生命周期证据包绑定的不是该提交、事件非引擎原生字典、时钟不单调或来源原件缺失（由 market.validate_lifecycle 传出） |

def stitch_series(
    archive_cache: Path,

    price_type: str,
    start_ms: int,
    end_ms: int,
    resumed: bool,

<TypeTable type={{ "archive_cache": { type: "ArchiveCache", description: "归档本地缓存句柄，取件统一经 market.fetch_archive（含校验和核对）" }, "symbol": { type: "str", description: "交易所原生合约代码，一次只拼一个合约" }, "price_type": { type: "Literal['LAST','MARK']", description: "成交价或标记价；标记价无成交量" }, "start_ms": { type: "int", description: "窗口起点（含），UTC 毫秒，整分钟" }, "end_ms": { type: "int", description: "窗口终点（不含），UTC 毫秒，整分钟" }, "resumed": { type: "bool", description: "true 表示 start_ms 紧接库内已存分钟，缺口从 start_ms 起算；false 从任一来源持有的首分钟起算" }, "trading": { type: "bool", description: "true 表示合约仍在交易（由 market.import_month 按条款原文状态给出），期望覆盖到 end_ms；false 只期望到任一来源持有的末分钟" }, "workers": { type: "int", description: "并行抓取归档的工作线程数，缺省 4" } }} />

**返回**　(minute_table, gap_intervals, source_rows)：minute_table 为按 open_time 排序、无重复、落在 [start_ms, end_ms) 内的 1 分钟 K 线表（列 open_time, open, high, low, close, volume, close_time，字段为交易所原始十进制字符串，无来源列）；gap_intervals 为三来源都没有的左闭右开区间 [(from_ms, to_ms)]；source_rows 为 \{monthly, daily, rest\} 各来源采用行数，只进导入报告

**期望行为**

1. 列出窗口覆盖的月份，经 market.monthly_archives 取已发布月归档作主来源；没有月归档的月份（当月或缺失月）改为按天经 market.fetch_archive 取日归档
2. 裁到窗口之前先核形状：归档行落在其所属月或日之外、或不在分钟网格上（如微秒时间戳），即 SOURCE_SHAPE，不静默丢弃。
3. 合并各来源：裁到窗口、按 open_time 排序；同一 open_time 出现多行时逐字段比较，任一字段不等即 SOURCE_CONFLICT 并指明时刻，相等则只留一行；close_time ≠ open_time + 1 分钟 − 1 毫秒的行即 SOURCE_SHAPE
4. 用 market.missing_intervals 在 [low, high) 上求缺口：low 取 start_ms（resumed）或首个持有分钟，high 取 end_ms（trading）或末个持有分钟 + 1 分钟
5. 对缺口覆盖的日期，以及持有分钟之外缺口不计的月份边缘（resumed 为 false 时首个持有分钟之前、trading 为 false 时末个持有分钟之后），补取日归档并重新合并；边缘与仍缺的区间逐段经 market.rest_klines 从公开接口补取；完全没有归档且 trading 或 resumed 时整窗口经公开接口取；market.rest_klines 的 SOURCE_UNKNOWN_SYMBOL 在 trading 为 false（已下架）时视为无补充、返回空，trading 为 true 时原样上抛
6. 最终再合并一次并重算缺口，原样返回：不插值、不前值填充、不以标记价代替成交价；表中不记录来源，拼接对运行器与策略不可见
7. start_ms ≥ end_ms 返回空表与空缺口，不拒绝
8. 多来源同一分钟按存储刻度的数值比较；标记价 K 线带成交量即 SOURCE_SHAPE；公开接口只有错误码 -1121 视为未知合约。

| 拒绝码 | 条件 |

| `SOURCE_CONFLICT` | 同一 open_time 被两个来源持有且任一字段不等；不以任一来源覆盖另一来源 |
| `SOURCE_SHAPE` | 某行不是已收盘的整分钟 K 线（close_time 不等于 open_time + 1 分钟 − 1 毫秒），或 symbol 含非法字符；或归档目录列举里有条目没有键、某页标为未完却无从续读（来自归档列举，原样上抛） |

| `SOURCE_UNKNOWN_SYMBOL` | trading 为 true 而公开接口不识别该合约（来自 market.rest_klines，原样上抛） |

| `SOURCE_UNREACHABLE` | 归档或公开接口重试耗尽仍不可达（来自来源函数，原样上抛） |

### `fetch_archive` [#def-market-fetch_archive]

下载一个月或日归档并按交易所随文件发布的 SHA-256 校验和核对，不符不落盘；是月归档与日归档共用的取数原语

```python
def fetch_archive(cache_root: Path, key: str) -> Path
```

[Source](https://github.com/qOeOp/trade/blob/main/market/sources.py#L166)

<TypeTable type={{ "cache_root": { type: "Path", description: "本地归档缓存根目录（工作副本目录），归档按交易所原始键名存放" }, "key": { type: "str", description: "交易所归档键，形如 <market>/monthly|daily/<kind>/<symbol>/[<interval>/]<symbol>-<interval|kind>-<period>.zip；kind ∈ klines | markPriceKlines | fundingRate" } }} />

**返回**　Path：已通过校验和核对的本地归档文件路径（旁有同名 .CHECKSUM）

**期望行为**

1. 本地缓存中存在归档与 .CHECKSUM 且重算 SHA-256 相符时直接返回，不再联网（幂等）；不符则视为损坏，重新下载
2. 先取交易所发布的 \<key>.CHECKSUM，再取归档本体；两者任一返回 404 即拒绝 ARCHIVE_NOT_PUBLISHED（归档尚未发布或该序列不存在，由调用方改用日归档或公开接口）
3. 对归档本体重算 SHA-256，与 .CHECKSUM 首个字段比较；不等即拒绝 CHECKSUM_MISMATCH，不写任何字节到缓存
4. 相符后先写 .part 临时文件再原子改名为正式文件，.CHECKSUM 与归档一起落盘，不留半成品
5. 网络错误、5xx 或限频在有限重试（指数退避）后仍失败即拒绝 SOURCE_UNREACHABLE；不静默返回空

| 拒绝码 | 条件 |
|---|---|
| `CHECKSUM_MISMATCH` | 下载内容的 SHA-256 与交易所随文件发布的 .CHECKSUM 不等 |
| `ARCHIVE_NOT_PUBLISHED` | 归档或其 .CHECKSUM 在交易所公开地址上不存在（HTTP 404） |
| `SOURCE_UNREACHABLE` | 重试耗尽后仍无法从交易所取到归档或校验和 |

### `import_month` [#def-market-import_month]

一次导入一个月成一个市场提交（最新月份之后，或补录最早月份的前一个月）：拼接交易所数据、追加条款、重算全部月份的共同可交易范围；已存月份被改、来源冲突或提交校验失败均拒绝整次导入；空库上的首次导入同时完成市场库模式初始化

```python
def import_month(
    profile: dict,
    month: date,
    cache_root: Path,
    workers: int=4,
    symbols: list[str] | None=None,
    log=print,

```

[Source](https://github.com/qOeOp/trade/blob/main/market/store.py#L541)

<TypeTable type={{ "profile": { type: "MarketProfile", description: "市场档案：服务地址、市场库名、导入账号；与研究账本是同一服务上的两个库，各自账号" }, "month": { type: "date", description: "UTC 月初；可以是尚未结束的当月，此时只能追加已存最后一分钟之后的尾段" }, "cache_root": { type: "Path", description: "归档文件与校验和的本地缓存目录" }, "workers": { type: "int", description: "并行下载数；只影响速度，不影响结果" }, "symbols": { type: "list[str] | None", description: "隔离市场库的工程允许列表；给了的库每次导入须给同一列表，记进提交信息的 scope" }, "log": { type: "Callable", description: "进度行的输出函数，缺省 print" } }} />

**返回**　ImportResult：\{month, market_commit, universe_rule, instruments_appended, bar_rows, funding_rows, universe_members, gaps: \{symbol: \{LAST: [(from_ms, to_ms)], MARK: [...]\}\}, source_rows: \{monthly, daily, rest\}\}；同月同内容重跑返回原提交且追加计数为 0

**期望行为**

1. 经 market.connect 以导入账号打开市场库；连接标记为空库时，在本次事务内先写 market_schema 单行与 market.dolt_tests 用例（模式初始化，此后导入只运行不改）；核对 market_schema.universe_rule 等于代码的范围规则版本（否则 RULE_VERSION_MISMATCH）、工作集干净（否则 DIRTY_WORKING_SET）；该月已完整则 MONTH_EXISTS，未完整只允许追加已存最后一分钟之后的尾段
2. 取条款：market.rest_exchange_info 的原文连同该月归档里出现的合约交给 market.classify_contract 得到合格合约与逐合约排除原因；条款与 instrument 最新一行不同者按观测时刻追加（exchange_info），已移除、无原文的合约按成交推断步长追加（inferred）；条款状态为交易中的合约以 trading=true 拼接
3. 拼数据：对每个合格合约、每个价格类型调用 market.stitch_series；资金费由 market.monthly_archives 与 market.rest_funding 按实际结算时刻同法拼接，同一结算时刻两来源不等即 SOURCE_CONFLICT；来源函数与拼接的任何拒绝指明合约、价格类型与时刻并拒绝整次导入；缺失区间记入返回值
4. 算范围：只算本次导入的月份。K 线只追加，每月的回看都在它之前，已存月份的名单不会再变，所以不重扫全部历史；本月的交易日由 1 分钟成交 K 线（volume > 0）判出，回看窗口固定为上市天数所需的范围。同一当月再次导入时，名单须等于已存行，否则 UNIVERSE_CHANGED。
5. 写入：一个事务里向 universe_month、instrument、bar、funding 只做 INSERT（与已存行主键重叠而字段相等的行跳过），market_schema.import_seq 加 1；运行 market.dolt_tests，任一失败即回滚并 DATA_TESTS_FAILED；全部通过后一次 DOLT_COMMIT，提交信息记月份与范围规则版本
6. 任何拒绝都在提交前发生并回滚全部追加，市场库停在导入前的提交；并发导入由第 9 条的导入锁拒绝
7. 再次导入未完整的当月时，整月重新拼接：已存部分逐字段（K 线按存储整数、资金费逐次结算）与来源重读结果比较，任一不同即 MONTH_EXISTS，不让先前从公开接口补的值悄悄留下；只追加最后一根已存分钟之后的尾段。
8. 资金费跨来源去重：结算时刻归到最近的整点，同一整点里两个来源的费率须相同（保留先到来源的时刻）；同一来源在一个整点里有两次结算即 SOURCE_SHAPE。
9. 整个导入持有 GET_LOCK('market-import:\<库名>')，第二个并发导入拒绝 CONCURRENT_IMPORT：Dolt 2.4.2 会合并相同值的写入，import_seq 本身挡不住并发。
10. 提交校验只在 DOLT_COMMIT 里跑一次，失败映射为 DATA_TESTS_FAILED 并给出失败的测试名；服务的提交校验组不是 commit 即拒绝 COMMIT_CHECKS_DISABLED：导入开始时核一次，DOLT_COMMIT 前再核一次，因为任何账号都能在导入途中改掉这项全局设置。
11. 月份只在两端延伸：补完最新月份、导入它的下一个月，或补录最早月份的前一个月；其他月份即 MONTH_INVALID。首个导入月没有名单（缺上市天数的回看）。补录只插不改，已存提交和钉在它们上的回放都不变：补录月份里不得已有任何合约的 K 线或资金费行（否则 MONTH_EXISTS）；它成为新的首月，没有名单；回看因此补齐的已存月份（原来因缺历史而没有名单）此时算出并写入名单，已有名单即 UNIVERSE_CHANGED。逐月倒着补完的库，与从该月向后导入的库逐行相同，只差条款的观测时刻；提交信息与向后导入同一格式，是否补录由提交顺序推出。
12. 工程期可给合约清单（--symbols），由市场库的首次导入定下（用户定 10-20，正式库也可）：名单只在清单内计算，之后每月必须相同，写进每次导入的提交信息，freshness 以 scope 报出；正式库不给清单。
13. 导入账号经 market_schema 上的更新触发器只能把 import_seq 加一，改不了范围规则与模式代数（Dolt 2.4.2 不支持列级授权）。

| 拒绝码 | 条件 |
|---|---|
| `RULE_VERSION_MISMATCH` | market_schema.universe_rule 与代码的范围规则版本不同；改规则必须先出新版本并记入市场库自述 |
| `DIRTY_WORKING_SET` | 导入前市场库工作集有未提交改动 |
| `MONTH_INVALID` | 不是最新月份、它的下一个月或最早月份的前一个月 |
| `MONTH_EXISTS` | 该月已存且已是完整月；或该月未完整但本次数据在已存最后一分钟之前有不同的行；或补录月份里已有行 |
| `CHECKSUM_MISMATCH` | 某归档文件与交易所随文件发布的 SHA-256 不符（由 market.fetch_archive 触发） |
| `SOURCE_CONFLICT` | 同一分钟或同一资金费结算时刻被两个来源同时持有且字段不等 |
| `SOURCE_SHAPE` | 来源给出非整分钟对齐的 K 线或无法解析的行，或归档目录列举里有条目没有键、某页标为未完却无从续读（由 market.stitch_series 或来源函数触发） |
| `SOURCE_UNREACHABLE` | 交易所归档或公开接口重试耗尽仍不可达（来自来源函数或 market.stitch_series） |
| `SOURCE_UNKNOWN_SYMBOL` | 合约仍在交易而公开接口不识别（来自来源函数或 market.stitch_series） |
| `PRICE_TYPE_UNKNOWN` | 传给拼接的价格类型不是 LAST 或 MARK（来自 market.stitch_series） |
| `UNIVERSE_CHANGED` | 重算后任一已存月份的范围与 universe_month 已存行不一致；或补录要补名单的月份已有名单 |
| `DATA_TESTS_FAILED` | 提交前 market.dolt_tests 任一用例失败 |
| `CONCURRENT_IMPORT` | 另一个导入正持有该市场库的导入锁 |
| `IMPORT_SCOPE` | 合约清单为空、重复或格式不对，或与首次导入定下的清单不同 |

**现有写入路径**

1. 使用导入账号与现有导入锁；库须已有基础数据和条款、工作集干净、提交校验启用。核对历史报价导入规则和本月合约是否已存报价。

3. 经 <Ref id="market.aggtrades_key" />、<Ref id="market.fetch_archive" />／fetch_all 下载并校验归档，由 <Ref id="market.aggtrades_table" /> 解析，逐日 <Ref id="market.derive" />、<Ref id="market.scaled_rows" /> 后分批插入 <Ref id="table:quote" />；不整月积攒报价、不覆盖旧行。
4. 同一事务内追加，并通过现有提交检查产生一个市场提交；异常回滚。提交消息保留规则、逐日归档（含实际读取的前日）SHA-256，以及逐日 `trades, quote_changes, stale_side_adjustments, trade_gap_max_ms`。归档原件在下载缓存，哈希回执不等于把 zip 字节存进 quote 表。
5. 返回的计数相加；两种 trade_gap 读数取各日最大值，因此汇总 p99 是最大日 p99，不能写成整月合并分位数。规则已定不等于所有合约已适用，见 <Ref id="W.1.2.1" />。

|---|---|
| `MONTH_INVALID` | 月首参数不合法，或尚无闭合 UTC 日 |
| `MARKET_EMPTY / TERMS_UNKNOWN / UNIVERSE_UNKNOWN` | 缺基础数据、合约条款或所需月份成员 |
| `DIRTY_WORKING_SET / COMMIT_CHECKS_DISABLED` | 工作集不干净或提交校验未启用 |
