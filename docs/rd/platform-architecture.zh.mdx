| `market-import` | `ghcr.io/qoeop/trade-service` | 宿主命令行的市场写命令（`docker compose exec`） | Binance 公开数据（`data.binance.vision`、`fapi.binance.com`）；市场目录 | 市场目录唯一的写者 |
| `paper` | `ghcr.io/qoeop/trade-service` | 只有 `ide` 经项目网络可达（`8767`） | `paper` 库里的模拟盘运行与封存文件、运行日志；研究账本里候选的源码和最近一次研究回放（只读账号）；市场目录，只读挂载 | 经命令行 `paper start/resume/stop/seal/delete` 写独立的 `paper` 库（`ledger/paper.sql`：复制来的源码、`paper_run` 声明行、封存与文件；不公开，不进研究账本）；经 `docker-api` 起停运行容器 |
| `docker-api` | Go 代理（`deploy/docker-api/`） | 只在内部网络，只有 `paper` 可达 | — | 只放行 `paper` 用到的 Docker 调用，容器也只放行 `runtime/container.py` 生成的规格；容器服务通往宿主 Docker 引擎的唯一通路 |

**模拟盘（Paper）**　模拟盘面板的每个动作都是命令行 `paper` 的一个动词：`start` 声明一次模拟盘运行并起容器、`resume` 从已核验的原生检查点续跑同一个未封存的运行、`stop` 停止并封存、`seal` 封存自行结束的运行、`delete` 删除已封存的运行（用户自己的动作，Agent 不代删；在 `paper` 库里以 `paper_delete:<id>` 提交完成）、`list`、`compare`（后台在归档上重放对比，不写账本）、`serve`。参数以 `python -m cli.main paper <动词> --help` 为准。守护进程本身只读运行与日志，所有写入都是它以白名单环境调用命令行。

**市场**　市场数据不经 `ledger` 服务：它是宿主目录 `${TRADE_DATA}/market` 里的市场目录，由 `market-import` 写入（`market.write_file`、`market.place`）；`paper` 与 `ide` 只读挂载，宿主命令行直接读这个目录，都经市场命令（`market.read_table`）读取。市场目录只有这一份，丢了从交易所归档重算。导入锁是 `fcntl` 文件锁，只在共用一个内核的进程间互斥：所有写者都在这个容器编排项目的容器里，共用 Docker 虚拟机的内核；宿主上的市场写命令经 `docker compose exec`（或 `run`）在 `market-import` 服务里跑，宿主命令行不直接写市场目录。

**Agent**　聊天服务（`ide/agent`，Node，随 `ide` 容器运行）只能调用产品的只读命令：`research state`、`research status`、`research runs`、`candidate list`、`candidate show`、`replay report`、`ledger sql`、`market coverage`；它不能写账本，也不能起停运行。研究图接口（`/api/view`、`/api/events`）只读，实时刷新与固定提交的区别见 [交易 IDE](/zh/docs/design-code-ide/)。部署步骤与环境变量见 [ide/README.md](https://github.com/qOeOp/trade/blob/main/ide/README.md)。

<a id="deployment" />

## 部署

容器编排运行五个服务：`ide`、`ledger`、`market-import`、`paper` 和 `docker-api`。除 `ide` 与 `docker-api` 外都用 `trade-service` 服务镜像；它与执行策略的、按摘要固定的 `trade-runtime` 镜像分开：回放用回放镜像，模拟盘和实盘用执行镜像（`exec-` 标签）。只有模拟盘守护进程经受限代理访问 Docker。

<a id="ide" />

## IDE

IDE 用只读账户直接读活动 Dolt SQL 服务里的研究账本，经市场命令读只读挂载的市场目录，自己不留副本。本地聊天服务运行只读命令，对话保存在独立的数据卷。模拟盘面板将请求与数据流代理给守护进程；守护进程经命令行写入独立的 `paper` 库，从不写研究账本。

<a id="paper" />

## 模拟盘执行

每次模拟盘运行从同一摘要镜像启动运行容器与出口代理两个容器，放在内部网络中。只有出口代理连接 Binance 公共行情；订单与成交交给 Nautilus 沙盒。模拟盘运行不是研究试验。本机与[远程主机](#remote)都把模拟盘运行与封存文件保存在同一 Dolt 服务上独立的 `paper` 库（`ledger/paper.sql`，不公开），研究账本里没有模拟盘记录。

<a id="remote" />

## 远程主机与发布

`deploy/remote/` 叠加在基础部署上，提供 HTTPS 和 GitHub 登录，研究库是只读镜像，执行记录放在隔离的 `paper` 库。`ledger mirror` 从公开副本引导只读研究库并新建空的 `paper` 库，不持有 DoltHub 发布密钥，拒绝接管已有的研究写入服务；`ledger sync` 只拉取并校验公开副本的不可变提交后快进，从不发布；镜像每 60 秒自动执行一次。主机只跟随版本标签自动发布，`main` 的构建只进 `main-ready`，发版由用户决定；发布不打断运行中的策略。步骤、边界和发布范围以 [deploy/remote/README.md](https://github.com/qOeOp/trade/blob/main/deploy/remote/README.md) 为准。

<a id="live" />

## 实盘执行

真实下单只从实盘页经配对的控制进程（`live` 包）启动，每次发布都在每台主机为页面服务配对一个；记录只留在私有目录，不进研究账本、`paper` 库或 DoltHub。研究从不使用它。行为与边界以 [live/README.md](https://github.com/qOeOp/trade/blob/main/live/README.md#live-execution) 为准。

<a id="data" />

## 数据与证据

Dolt SQL 服务承载研究账本和独立的 `paper` 库，实际库名由连接档案指定；`dolt_backup` 在本机各存一份副本；只有研究账本发布到 DoltHub，`paper` 库从不发布。市场数据在市场目录，是按表、按月的普通 Parquet 文件，没有副本。副本都不产生另一份事实来源。原生报告是缓存：按固定输入与运行环境重建，再与已存指纹核对。
