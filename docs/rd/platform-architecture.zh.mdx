**Paper**　Paper 面板的每个动作都是命令行 `paper` 的一个动词：start 声明一次 paper 运行并起容器、resume 从已核验的原生检查点续跑同一个未封存的运行、stop 停止并封存、seal 封存自行结束的运行、delete 删除已封存的运行（用户自己的动作，Agent 不代删；由服务管理员以 `paper_delete:<id>` 提交完成）、list、reconcile（后台在归档上重放对比，不写账本）、serve。参数以 `python -m cli.main paper <动词> --help` 为准。守护进程本身只读运行与日志，所有写入都是它以白名单环境调用命令行。

**市场**　市场数据不经 ledger 服务：它是宿主目录 `${TRADE_DATA}/market` 里的市场目录，由 market-import 写入（`market.write_file`、`market.place`）；paper 与 ide 只读挂载，宿主命令行直接读这个目录，都经市场命令（`market.read_table`）读取。市场目录只有这一份，丢了从交易所归档重算。导入锁是 fcntl 锁，只在共用一个内核的进程间互斥：所有写者都在这个 compose 项目的容器里，共用 Docker 虚拟机的内核；宿主上的市场写命令经 `docker compose exec`（或 `run`）在 market-import 服务里跑，宿主命令行不直接写市场目录。

**Agent**　聊天服务（`ide/agent`，Node，随 ide 容器运行）只能调用产品的只读命令：research state、research status、research runs、candidate list、candidate show、replay report、ledger sql、market coverage；它不能写账本，也不能起停运行。研究图接口（/api/view、/api/events）只读，live 刷新与固定提交的区别见 [交易 IDE](/zh/docs/design-code-ide/)。部署步骤与环境变量见 [ide/README.md](https://github.com/qOeOp/trade/blob/main/ide/README.md)。

<a id="deployment" />

## 部署

Compose 运行五个服务：`ide`、`ledger`、`market-import`、`paper` 和 `docker-api`。除 `ide` 与 `docker-api` 外都用 `trade-service` 服务镜像；它与执行策略的、按摘要固定的 `strategy-runtime` 镜像分开。只有 Paper daemon 经受限 API 代理访问 Docker。

<a id="ide" />

## IDE

IDE 用只读账户直接读活动 Dolt SQL 服务里的研究账本，经市场命令读只读挂载的市场目录，自己不留副本。本地 Chat 运行只读命令，对话保存在自己的 volume。Paper 面板将请求与数据流代理给 daemon；daemon 经 CLI 写入活动研究账本（远程主机上写隔离的 `paper` 库）。

<a id="paper" />

## Paper 执行

每个 PaperRun 从同一摘要镜像启动 runner 与 egress 两个容器，放在内部网络中。只有 egress 连接 Binance 公共行情；订单与成交交给 Nautilus Sandbox。PaperRun 不是研究 trial。基础部署把 PaperRun 与捕获记录保存在研究库中；[远程主机](#remote)保存在隔离的 `paper` 库。

<a id="remote" />

## 远程主机与发布

`deploy/remote/` 叠加在基础部署上，提供 HTTPS 和 GitHub 登录，研究库是只读镜像，执行记录放在隔离的 `paper` 库。`ledger mirror` 从公开副本引导只读研究库并新建空的 `paper` 库，不持有 DoltHub 发布密钥，拒绝接管已有的研究写入服务；`ledger sync` 只拉取并校验公开副本的不可变提交后快进，从不发布。通过检查的 main 构建会自动发布到这台主机，不打断运行中的策略。步骤、边界和发布范围以 [deploy/remote/README.md](https://github.com/qOeOp/trade/blob/main/deploy/remote/README.md) 为准。

<a id="live" />

## Live 执行

`live` 命令是操作者专用的真实下单入口，记录只留在私有目录，不进研究账本、`paper` 库或 DoltHub。研究从不使用它。行为与边界以 [engine/README.md](https://github.com/qOeOp/trade/blob/main/engine/README.md#live-execution) 为准。

<a id="data" />

## 数据与证据

活动 Dolt SQL 服务只承载研究账本（[远程主机](#remote)另有隔离的 `paper` 库），实际库名由连接档案指定；`dolt_backup` 与 DoltHub 保存它的历史副本。市场数据在市场目录，是按表、按月的普通 Parquet 文件，没有副本。副本都不产生另一份事实来源。原生报告是缓存：按固定输入与运行环境重建，再与已存指纹核对。
