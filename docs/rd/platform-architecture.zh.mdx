**Paper**　Paper 面板的每个动作都是命令行 `paper` 的一个动词：start 声明一次 paper 运行并起容器、stop 停止并封存、seal 封存自行结束的运行、delete 删除已封存的运行（用户自己的动作，Agent 不代删；由服务管理员以 `paper_delete:<id>` 提交完成）、list、reconcile（后台在归档上重放对比，不写账本）、serve。参数以 `python -m cli.main paper <动词> --help` 为准。守护进程本身只读运行与日志，所有写入都是它以白名单环境调用命令行。

**Agent**　聊天服务（`ide/agent`，Node，随 ide 容器运行）只能调用产品的只读命令：research state、research status、candidate list、candidate show、replay report、ledger sql、market coverage；它不能写账本，也不能起停运行。研究图接口（/api/view、/api/events）只读，live 刷新与固定提交的区别见 [交易 IDE](/zh/docs/design-code-ide/)。部署步骤与环境变量见 [ide/README.md](https://github.com/qOeOp/trade/blob/main/ide/README.md)。

## 部署

Compose 运行四个服务：`ide`、`ledger`、`paper` 和 `docker-api`。Ledger 与 Paper 共用 `trade-service` 服务镜像；它与执行策略的、按摘要固定的 `strategy-runtime` 镜像分开。只有 Paper daemon 经受限 API 代理访问 Docker。

<a id="ide" />

## IDE

IDE 维护自己的研究库与市场库只读副本，从 DoltHub 克隆并只做 fast-forward 更新。本地 Chat 运行只读命令，对话保存在自己的 volume。Paper 面板将请求与数据流代理给 daemon；daemon 经 CLI 写入活动研究账本。

<a id="paper" />

## Paper 执行

每个 PaperRun 从同一摘要镜像启动 runner 与 egress 两个容器，放在内部网络中。只有 egress 连接 Binance 公共行情；订单与成交交给 Nautilus Sandbox。PaperRun 与捕获记录保存在研究库中：PaperRun 不是研究 trial，也没有 Paper 独立数据库。

<a id="data" />

## 数据与证据

活动 Dolt SQL 服务承载研究账本和市场两个数据库，实际库名由连接档案指定。`dolt_backup`、DoltHub 与 IDE 保存历史副本，不产生另一份事实来源。原生报告是缓存：按固定输入与运行环境重建，再与已存指纹核对。
