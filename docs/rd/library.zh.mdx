# L　策略库：候选谱系的根节点从哪来，怎样作为候选入账，又怎样得到第一份可供比较的报告。

本章定义候选谱系（lineage）的根节点（root）从哪来、怎样得到首份报告。根只有两类：有公认一手出处（primary source）的原版模板，与用户发起并提供信息源的人造根（artificial root）。转写由 skill 指导、eval 核验，出处原件以证据包入账本（ledger）；发布与首次回放由代码与账本强制：经唯一发布入口入账、无研发父版本（parent）即根，预检与审查后登记并回放一次，封存首份报告。出处只是外部依据，不为参数背书；何时选模板作根由用户在入口决定。

## L.1　从出处或用户信息源转写成根文件 [#L-1]

<Steps>

<Step>

收录：按一手出处标准判定形态是否可收，列入首批名单或候补；人造根由用户发起并提供信息源（skill）。

</Step>

<Step>

留存：出处原件、摘录与检索记录以证据包（<Ref id="table:evidence_bundle" />）经 <Ref id="ledger.add_bundle" /> 入账本，记内容哈希与首次可见版本（账本）。

</Step>

<Step>

核实：每个默认参数定位到出处原件位置，任一定位不了即弃该模板换候补并记原因（skill）。

</Step>

<Step>

重写：照出处从头写成守 <Ref id="C.1.1.1" /> 的单文件，不加无出处内容，运行所需未定项作实现者选择列明，并记作者条件（skill）。

</Step>

<Step>

文件头：写可定位出处与九组立场行的来源标注，交 L.2.1.1 发布为无父根（skill）。

</Step>

<Step>

执行正确：由 <Ref id="replay.precheck" /> 与 <Ref id="registration.record_review" /> 给出，不由转写者自证，通过后进入 <Ref id="L.2.2.1" /> 登记并回放一次（代码与账本）。

</Step>

</Steps>

### L.1.1　收录 [#L-1-1]

把候选形态及其出处链接判成带出处定位的待核实模板，或一条不收原因。

<ul className="rd-rules">
<li id="L-1-1-2"><span className="rd-rule-id">L.1.1.2</span> 首批只转写名单内 12 个单品种形态，核实不了移候补不放宽 <Ref id="rule:L.1.1.2">research-round · references/template.md</Ref></li>
</ul>

### L.1.2　核实 [#L-1-2]

把待核实模板与已入账本的出处原件变成参数—出处定位表、可发布的根文件与预检审查证据包，三件事分开核。

<ul className="rd-rules">
<li id="L-1-2-1"><span className="rd-rule-id">L.1.2.1</span> 每个默认参数定位到出处页码或锚点，任一定位不了即弃模板 <Ref id="rule:L.1.2.1">research-round · references/template.md</Ref></li>
</ul>

### L.1.3　重写与文件头 [#L-1-3]

把参数—出处定位表、出处原件与实现者选择清单写成守策略文件契约的根文件源码与文件头。

<ul className="rd-rules">
<li id="L-1-3-1"><span className="rd-rule-id">L.1.3.1</span> 照出处从头重写，不补无出处的止损、过滤或参数，实现者选择列明 <Ref id="rule:L.1.3.1">research-round · references/template.md</Ref></li>
<li id="L-1-3-3"><span className="rd-rule-id">L.1.3.3</span> 文件头写原版出处与作者条件，搬到别处的行标研究者推广 <Ref id="rule:L.1.3.3">research-round · references/template.md</Ref></li>
</ul>

### L.1.4　发起与转写（人造根） [#L-1-4]

发起规则在入口 skill、转写规则在研究 skill，产出交 L.2.1.1 发布。

<ul className="rd-rules">
<li id="L-1-4-2"><span className="rd-rule-id">L.1.4.2</span> 人造根缺的参数列为实现者缺省，不弃模板也不标为出处原话 <Ref id="rule:L.1.4.2">research-round · references/template.md</Ref></li>
</ul>

## L.2　发布为根并出首份报告 [#L-2]

<Steps>

<Step>

把守策略文件契约的根文件与发布说明交给发布入口；只解析不执行地核对通过后原样入账，得到 strategy_id@revision 与源码内容哈希；相同字节返回先前候选的引用。

</Step>

<Step>

对该候选做原生预检（purpose=precheck）并封存原生输出；独立 Agent 按四项审查，结论绑定源码哈希与运行环境身份写入账本。

</Step>

<Step>

在当前开发窗口登记：父版本为空、对照为空、网格只含该根一点，带预检与审查引用，锁进不可变登记证据。

</Step>

<Step>

回放入口写试验行（purpose=research）并绑定该登记点，在钉死的运行环境（runtime image）内回放，完整性审计后封存运行与原生报告（含原生 stdout/stderr/退出码）。

</Step>

<Step>

读取时按检查身份判实质活动与可比资格；根的报告无检验结果，供入口推荐并作后续候选的比较对照，回放计入试验计数。

</Step>

<Step>

预检、审计或资格暴露的故障只修复：新源码重新发布为新根并重走 1–5，原根的运行保留为历史。

</Step>

</Steps>

### L.2.2　首次回放 [#L-2-2]

代码强制顺序为预检与独立审查、无父无对照登记、绑定登记点回放、完整性审计、封存、读时资格；skill 只规定根怎样用这条路径。

<ul className="rd-rules">
<li id="L-2-2-1"><span className="rd-rule-id">L.2.2.1</span> 新根无父无对照登记回放一次作首份报告，不以探索回放代替 <Ref id="rule:L.2.2.1">research-round · references/template.md</Ref></li>
</ul>

## 待定事项 [#L-pending]

**待用户定**

- **候补名单从哪来、由谁定**　可由 Agent 按 <Ref id="L.1.3.3" /> 的收录标准提候补、用户选，尚未定；<Ref id="L.1.2.1" /> 只写换下一个候补并说明原因。
- **第二批多品种／双腿模板的名单与启动时点**　产品允许做现货，但名单未给；<Ref id="L.1.1.2" /> 只写第二批范围：横截面动量、配对、资金费 carry。
- **模板首次回放的范围（全池全开发窗口一次到位，还是先有界先导）**　演练中全池回放工程成本高，多数试验被生命周期、原生身份或容量阻断；<Ref id="L.2.2.1" /> 只写回放一次，范围由用户选。

- **不进文档**　一手出处类型与不收形态的例子：不单列成节；收与不收的例子写进 <Ref id="L.1.3.3" /> 的规则正文。
- **不进文档**　出处列表与参照的因子库：不单列成节；经核实的出处作为一手出处例子放 <Ref id="L.1.3.3" /> 的依据，机制未核实的因子库参照与引擎仓库链接不作出处。
