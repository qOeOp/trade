# 2　策略库：研究的起点从这里来：把有出处的原版策略或你给的资料写成根，入账后回放一次，拿到第一份报告。

第 1 章入口选路线时，起点总是某个候选。候选靠父版本连成一棵棵树，叫谱系；树最上面的那个叫根，它没有父版本，也不带比较对照。本章讲根从哪来，怎样拿到它的第一份报告。

根有两种来源。一种是策略库模板，照有公认一手出处（最初提出这个策略的论文、书或官方说明）的原版策略转写；另一种是人造根，由你提供信息源。两种走同一套做法：先把出处原件存进账本，逐个核对默认参数在出处里的位置，照出处重写成一个策略文件，并在文件头标清每一项来自哪里；然后像所有候选一样发布、预检、审查、登记，回放一次。出处只说明策略从哪来，不证明参数在这个市场上好用。

举个例子：一条路线的起点是一个 RSI 根，第一个假设就是从它改出来的。根的首份报告里，p 值一栏是空的，因为根没有对照可比。它和后面的假设分开计，但照样算进路线的试验次数。

## 2.1　从出处或用户信息源转写成根文件 [#L-1]

把一个有出处的原版策略，或者你提供的信息源，写成一份守策略文件规则的根文件，交给发布。

### 收录 [#L-1-1]

判定一个原版策略能不能收进策略库，以及首批收哪些。

<a id="L-1-1-2" />

**首批只收 12 个单品种策略，每个仍要逐个核实**

首批收 12 个只交易一个品种的策略形态：EMA 交叉、Supertrend、Donchian/Turtle 系统 1、Turtle 系统 2、Channel BreakOut、Dual Thrust、Keltner 突破、布林带、RSI、Connors RSI(2)、单品种时序动量、Pivot Reversal。名单由你决定，代码和账本不检查它。每个形态仍要逐个通过收录标准、参数核实（<Ref id="L.1.2.1" />）和重写（<Ref id="L.1.3.1" />）；核实不了的暂缓并记下原因，留下缺位，不自动替换。

Agent 负责发现、核实和提名候补：说明机制、一手出处、默认参数的核实结果、替换理由和仍未解决的问题；来源原件及核实说明沿用现有证据包，不新增候补表或调度机制。你决定是否调整首批名单、是否启用该模板；两项可以一次授权。已有明确授权后，转写、发布、预检、独立审查和首份回放按现有流程继续，不再重复询问（<Ref id="E.4.1.2" />）。

第二批多品种／双腿模板按需提名、逐个验证，具体模板由你决定收录与启用，不固定预设名单。启用前，用既有原生预检、独立审查及必要的最小探针，验证该模板实际依赖的能力：横截面模板验证联合选取、共享资金分配（<Ref id="C.1.4.4" />）及成员切换时旧仓旧单的处理；双腿模板还验证一腿先成交、另一腿未成交或失去交易资格时的处置。每项只认实际覆盖到的原生证据，不把多个合约同场运行、两份独立回放或正常双腿成交当成全部能力已验证。当前市场导出构建的是 USDT 永续合约（`market.build_instrument`），运行器为每个合约创建策略实例并共用账户（`engine.replay`）；缺少所需数据、合约接入或执行证据的具体模板继续暂缓。

### 核实 [#L-1-2]

确认每个默认参数都出自出处原件，而不是凭记忆或惯例。

<a id="L-1-2-1" />

**每个默认参数都要在出处里找到位置，找不到就弃用模板**

回看周期、倍数、阈值、入场和出场条件，每个默认参数都逐项对照一手出处，记下它在出处里的位置：页码、节号、公式号或页面锚点。出处原件要先作为证据包入账（<Ref id="H.2.3.1" />）。核对的结果是一张参数和出处的对照表，随根文件写进文件头（<Ref id="L.1.3.3" />）和发布说明。

默认参数是原版策略的一部分。凭记忆、二手转述、估计值或社区常用值去填，写出来的就不再是原版，后面所有比较都建在一个来历不明的根上。只要有一个参数找不到位置，这个模板就不收并记下原因；如需替换，按前述提名和用户授权边界处理（<Ref id="L.1.1.2" />）。

### 重写与文件头 [#L-1-3]

照出处写成策略文件，并在文件头写明出处，逐项标清立场来自哪里。

#### 照出处从头重写成一个文件，不加出处没有的东西 [#L-1-3-1]

规则和默认参数照出处从头重写成一份守策略文件规则（<Ref id="C.1.1.1" />）的单文件。三条不做：不复制出处附带的或任何第三方的代码；不补出处没有的止盈；不加出处没有的过滤、确认条件或参数。运行必需而出处没定的部分，作为实现者选择补上（包括每个持仓必须有的止损、`E1` 单笔风险与数量、`E4` 多机会资本分配、`F5` 成员变化时存量处置、`H2` 保证金缓冲），每项写一句理由，在文件头标为实现者（`implementer`）。

加了出处没有的规则，报告测的就不是原版策略了。实现者选择逐项列出来，审查和后来的人才知道哪些部分不是出处给的；实现者选择也不能改动出处给出的入场、出场和参数。

#### 文件头先写能查到的出处，27 项职责立场逐行标明来源 [#L-1-3-3]

根文件的文件头开头先写能查到的出处：DOI、arXiv 编号或页面网址，加版本号或日期，并写上出处证据包的包名。之后 27 项职责每项各写一行，共 27 行，按九组排列：对象与适用性、预测与学习、首次行动与记忆、经济构型、风险与分配、持仓路径、实施、资本、生命周期与可行性；模板只有一份，由 `candidate new` 与 `candidate export` 给出（`cli/templates/strategy-header.md`）。每行的格式是「采用（`adopted`）、缺省（`default`）或不适用（`not applicable`）」加一句理由，再加来源标注。

来源标注有三种：出处原话（`source`），是出处明确给出的；实现者（`implementer`），是出处没定、转写者补的（<Ref id="L.1.3.1" />）；研究者推广（`researcher`），是把出处的结论搬到别的市场、周期或品种上。研究者推广的行在登记时会成为试验适用条件的一部分，所以必须标出来，不然后来的人会把推广当成出处本身的结论。

### 发起与转写（人造根） [#L-1-4]

你提供信息源时，按和模板相同的规则转写成人造根。

<a id="L-1-4-2" />

**你给的信息源按模板同一套规则转写，经同一入口发布为根**

你提供信息源时，Agent 按和模板相同的三步把它转写成一个策略文件。核实：每个参数定位到你的信息源里；信息源没给的参数，只能作为实现者选择补上并列明，不能标为出处原话。重写：不复制代码，不补没有来源的止盈或过滤；信息源没有止损时，补上每个源码必须有的止损，标为实现者选择。文件头：出处行写你的信息源、你提供它的日期和证据包名，九组 27 行逐行标来源。转写完成后，经同一个发布入口（`ledger.publish_candidate`）发布为没有父版本、没有改动说明的根，再按 <Ref id="L.2.2.1" /> 在当前开发窗口登记并回放一次。

## 2.2　发布为根并出首份报告 [#L-2]

根和所有候选走同一条路：经 `candidate publish` 校验 27 行职责头并入账，跑原生预检与独立源码审查，按无父版本、无对照登记，在已选路线的开发窗口回放一次，得到封存的首份报告。

<a id="L-2-2" />

根的首份报告：计入试验次数，没有检验结果，之后可以当派生候选的比较对照。

<a id="L-2-2-1" />

**每个根在当前开发窗口不带父版本和对照，登记并回放一次**

每个根按你已选研究路线的完整开发窗口和可交易范围登记一次、回放一次：选定全池就覆盖全池，选定明确的合约子集就覆盖该子集，不是所有模板一律要求全池。首份报告之前要是发现实现有错，修好后照样不带父版本重新发布，重新预检、重新审查，仍按根登记；研究路线从审查通过的那一版开始，审查没通过的起点记不成路线。结果是一条用掉这个网格点的研究试验（<Ref id="table:trial" />）和一个封存的运行。回放无效或中断，也算用掉了这个点，要再试就另行登记。登记和绑定由代码强制。

预检由 Agent 按待验证的技术行为选最小充分范围：单品种问题用最少合约和足够短的窗口，资金分配、成员切换、双腿异常则覆盖相应场景；不按收益好坏挑选窗口。预检通过不证明全池运行或正式首报已经完成，也不另设“先导首报”。正式范围由你选择，合约选择与输入身份由登记锁定（`registration.market_inputs`）。因环境、数据或容量问题跑不完时，Agent 报清具体阻碍及影响范围，不能自行删币、截短窗口或用短跑替代首报（<Ref id="E.1.2.3" />）。

根本来就没有可比的对象，所以首份报告没有效应、区间和 p 值；它的报告供入口推荐（<Ref id="E.3.1.2" />），也可以当后面派生候选的比较对照，并照常计入路线的试验次数。

1. 登记（`registration.register`）：父版本为空，对照为空，网格只放这个根，窗口等于所选研究路线的开发窗口，合约范围与输入身份一并锁定，附上预检和审查的引用。
2. 核对（`registration.validate`）：根带了对照，就拒绝登记。
3. 回放（`replay.run`）：写试验记录（用途为研究）的同一事务里，由 `registration.bind` 把试验绑定到这个登记点，然后在钉死的运行环境里回放。
4. 审计和封存：`ledger.audit_problems` 汇总无效原因；运行和原生报告完整封存，包括引擎原样的输出、错误输出和退出码。
