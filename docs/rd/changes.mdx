# D　变化之后：交易所数据、开发窗口或运行环境变了以后，旧结论怎样保留，又怎样在新条件下重新建立比较证据。

交易所数据（exchange data）会追加新月份与生命周期事实，运行环境（runtime image）会升级，用户也可能扩展开发窗口。本章定义什么算变化、旧运行（run）与比较证据怎样保留并按身份查出受影响范围、怎样在新身份下重新产生比较证据。代码与账本（ledger）强制身份区分、只追加、登记先于回放、可比资格拒绝与配对重放（paired replay）逐条比较；重放顺序、范围与推荐更新由 skill 指导；窗口扩展由用户选。身份定义见 <Ref id="J.6.1.3" />，样本外验证归 X 章。

## D.1　认定变化与受影响范围：什么算变了，旧记录怎么留 [#D-1]

变化分三类：交易所数据与环境事实、运行环境与读数代码、开发窗口。前两类在导入、回放与读取时由市场库只追加与执行身份自动区分，代码强制，不靠人工申报；第三类由用户在入口选择新的数据合同，skill 指导。认定变化后不改写任何旧记录：受影响范围按身份从账本只读查出，旧运行与比较证据保留为历史条件下的证据，资格由当前检查器读时重算，更正与新证据一律追加。重放顺序与推荐更新交给 <Ref id="D.2.1.1" /> 起的重建流程。

<Steps>

<Step>

导入新月份或回放时，代码自动记录新身份：市场提交、导出内容哈希、导出器哈希与生命周期证据包哈希；镜像摘要、运行契约、读数版本与检查身份。

</Step>

<Step>

新月份到达时，入口只报告可扩展范围与阻断；用户选定新数据合同后写成新研究路线记录。

</Step>

<Step>

按当前身份从账本只读查出受影响的运行、登记、比较证据与推荐理由。

</Step>

<Step>

旧记录原样保留，按账本提交或标签可读回；评价变化只追加新证据包。

</Step>

<Step>

读取旧运行时由当前检查器重算资格并附检查身份；更正追加为指向原记录的新记录。

</Step>

<Step>

在新身份下重新登记与重放，见 <Ref id="D.2.1.1" />。

</Step>

</Steps>

### D.1.1　变化的种类 [#D-1-1]

三条能力对应三类变化。交易所数据与环境事实由市场库只追加并经导出组装成输入身份，代码与存储强制；运行环境与读数代码由镜像摘要、运行契约、读数版本与检查身份自动区分，代码强制；开发窗口扩展由入口 skill 指导，输入是新月份的新鲜度，输出是用户选定的新研究路线记录。

<Cap id="D.1.1.1" kind="database" tier="verified" tierLabel="已验证" title="交易所数据与环境事实只追加，新事实即新的输入身份">

交易所数据（exchange data）与环境事实只追加，新事实即新的输入身份。已被试验（trial）引用的市场提交（market commit）永不改变；新的月份、新的生命周期事实（上市、禁新仓、下架结算、ticker 重用）与导出器源码的改动，都只产生新的输入身份——市场提交、导出内容哈希、导出器源码哈希与生命周期证据包哈希的组合——而不修改旧身份。强制分两层：代码层，<Ref id="market.import_month" /> 一次导入一个月并成一个市场提交，目标月份已存或来源互相冲突即拒绝整次导入，不写任何行（拒绝码由该函数定义）；存储层，市场库按提交保存行级全史，<Ref id="table:dolt_system_tables">dolt_diff_\<t></Ref> 上任何 diff_type 不是 added 的行都是篡改发现。输入：一次导入的月份数据；输出：新的市场提交。复现：按钉住的市场提交 AS OF 导出可逐字节重现旧输入，<Ref id="registration.market_inputs" /> 据此组装输入身份，登记、回放与比较时逐项核对。上游交易所公布的历史修正如何入库待用户定。

### D.1.2　旧记录的处置 [#D-1-2]

受影响范围由只读查询按身份给出，不写标记；旧记录的保留由账本只追加保证；读数与经济证据资格由当前检查器读时重算并附检查身份，更正只追加。三条能力都只读或只追加，不改写任何存储行。

<Cap id="D.1.2.1" kind="database" tier="unverified" tierLabel="待验证" tierNote="缺演练中按身份实际查出受影响运行、登记与推荐理由的执行。" title="受影响范围按身份从账本查出">

受影响范围从账本（ledger）按身份只读查出。输入：当前身份（运行环境摘要、有效配置身份、输入身份）与一个账本提交或标签；输出：运行环境、有效配置或输入身份与当前身份不同的运行（run），引用这些运行的登记（registration）尝试与候选 candidate（strategy_id@revision），以及引用这些运行的比较证据与推荐理由证据包。代码层由 <Ref id="report.affected_runs" /> 执行，身份比对用与可比资格相同的三项 <Ref id="registration.config_key" />、<Ref id="registration.input_key" /> 与运行环境摘要，判定逻辑与 <Ref id="registration.check_comparable" /> 一致；连接经 <Ref id="ledger.read_as_of" /> 只读，不写标记、不建表、不加字段，不依赖会话记忆或交接文件。没有可比较的当前身份时不给结果并说明缺哪项。

## D.2　恢复可比性：在新环境下重放对照与候选 [#D-2]

变化后的比较证据只能在新的执行身份下重新产生，旧比较不跨身份延续。数据流：<Ref id="report.affected_runs" /> 查出受影响运行 → skill 按研究价值排出重放范围并写入研究状态清单 → 每次重放是带 retry_of 的新登记（registration），先对照后候选 → <Ref id="report.compare" /> 在新身份下给出效应、区间、p → skill 更新综合推荐并告知用户。代码与账本强制登记先于回放、网格点一次性消耗、可比资格拒绝；skill 决定重放顺序、范围与推荐更新。研究默认持续，不设立即重放义务，不要求重放全部历史。

<Steps>

<Step>

Agent 用 <Ref id="report.affected_runs" /> 按变化的运行环境、有效配置或输入身份查出受影响运行，读研究状态清单最新版

</Step>

<Step>

### D.2.1　重放的登记与计数 [#D-2-1]

由代码与账本强制：新身份下的重放是新登记（retry_of）、新试验与新运行只追加、网格点一次性消耗、可比资格检查在登记与比较时拒绝不一致身份。重放顺序（先对照后候选）由 skill 指导，eval 校验。

<Cap id="D.2.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="相同源码在新身份下重放是新的登记">

运行环境（runtime image）摘要、有效配置身份、输入身份三者任一与原运行不同即为新身份。相同源码在新身份下重放必须作为一次新的登记提交，并以 retry_of 指向原登记：<Ref id="registration.register" /> 重新探测钉死的运行环境、用研究路线的市场提交导出不可变输入、在运行环境内读出有效配置，组成新的执行身份，在一个写事务里经 <Ref id="registration.validate" /> 核对后写成不可变登记证据包。源码已暴露而未带 retry_of 时以 SOURCE_ALREADY_EXPOSED 拒绝。回放开始前 <Ref id="registration.bind" /> 在写 <Ref id="table:trial" /> 行的同一事务里把试验绑定到网格点，登记不早于试验时以 REGISTRATION_TOO_LATE 拒绝；每个网格点在 <Ref id="table:registration_attempt" /> 只消耗一次，再次绑定以 GRID_ALREADY_ATTEMPTED 拒绝，无效与中断的尝试同样消耗。新试验与新运行只追加；原登记、试验、运行与失败原件原样保留，修复后的成功不回填为旧尝试的结果。相同身份下重复同一源码不算新的独立证据，只记为又一次尝试并计入搜索暴露。以上由代码与账本强制；何时、按什么顺序重放由 skill 决定（<Ref id="D.2.1.2" />、<Ref id="D.2.2.1" />），不设立即重放义务。演练中真实阻断修复后均以新登记重试并指向原登记。

## D.3　运行环境变更：先证明引擎行为没变 [#D-3]

运行环境（runtime image）变更后，先做配对重放（paired replay）：skill 组织 Agent 用同一源码、输入、窗口与账户在旧新运行环境各跑一次探索回放，代码逐条比较两份引擎原生报告并给出 passed；全部一致只证明这一配对下引擎（engine）行为未变，不是对策略的认可，新的比较证据仍按 D.2 在新身份下登记重放产生。有意改变引擎行为或配对不一致时，代码保证旧运行原样保留、旧运行环境身份永久可读回，并按身份查出受影响运行；运行契约变更时 skill 指导先发布适配候选，经原生预检与独立源码审查后再登记，按 D.2 重放。代码强制：身份解析与核对、探索回放不入研究证据、逐条比较、只读的影响查询；skill 指导：配对选择、结论边界、适配发布顺序。

### D.3.1　旧新运行环境配对重放 [#D-3-1]
