## 14.1　说清循环怎么转 [#A-1]

<Steps>

<Step>

入口：用户选定研究路线后，循环进入迭代。

</Step>

<Step>

迭代：Agent 在路线内反复试验，到自定的复盘节奏就复盘。

</Step>

<Step>

复盘：结束后默认回到迭代；Agent 判断该换路线时回到入口。

</Step>

<Step>

观察：用户随时读研究状态，不改变循环走向。

</Step>

<Step>

每项活动的产出都写进账本，账本是唯一的持久记录。

</Step>

</Steps>

<a id="A-1-1" />

迭代里的每一步都是 skill 指导的 Agent 行为，代码只在步骤之间做检查，不决定下一步。

<a id="A-1-1-2" />

**路线内迭代按固定顺序从查来源推进到反馈与优先级，不逐步请批**

路线内提假设、写候选、原生预检、独立源码审查、登记、回放，步间不请批

## 14.2　划清谁决定什么 [#A-2]

<Steps>

<Step>

用户从 Agent 给的选项里选研究路线或起点候选；选定前 Agent 不登记、不回放。

</Step>

<Step>

Agent 在路线内提假设、选父版本和对照、写源码、登记并回放，不逐项请批。

</Step>

<Step>

代码审计运行、判定经济证据资格，对可比的两个运行给检验结果，不判通过或失败。

</Step>

<Step>

Agent 读研究状态，追加研究优先级等判断，按节奏复盘并给综合推荐。

</Step>

<Step>

用户看报告决定是否认可、是否发起样本外验证；遇到授权事项，Agent 停下等用户。

</Step>

</Steps>

### Agent 决定的 [#A-2-2]

Agent 读研究状态，产出源码、登记和判断；代码只给绩效指标和计数，不做裁决。

<a id="A-2-2-1" />

**路线内研究动作由 Agent 自主决定；仓位与风险上限是设计变量而非用户约束**

仓位与风险上限由 Agent 自定，无需授权，也不算用户约束

<p className="rd-note">演练中 Agent 自行决定父版本与对照并在源码中改仓位规则，没有请求授权；所选父版本与当时的推荐候选不同。</p>

### 用户决定的 [#A-2-3]

用户的决定在产品之外做出，账本不存这类状态；skill 规定 Agent 遇到这些事项要停下。

<a id="A-2-3-3" />

**实盘、破坏性写、改检查与改研究目标，Agent 一律停下等用户授权**

实盘、删改已存记录、改检查或改回撤年化胜率要求前，须停下等用户授权

<p className="rd-note">演练中遇到的阻断都通过修复代码并发布新运行环境或新源码后重新登记解决，未放宽任何拒绝或审计检查。</p>

## 待定事项 [#A-pending]
