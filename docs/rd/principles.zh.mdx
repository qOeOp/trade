# A　总则：研发循环怎么转、代码／Agent／用户各决定什么、何时找用户、产品代码管到哪、保证到什么程度。

本章是总纲。外部 Agent（Claude Code 等）经 skill 与命令行做策略研发；产品只提供 Dolt 研究账本 ledger（唯一持久状态）、按摘要钉死的运行环境 runtime image 与发布版 NautilusTrader 引擎 engine。本章定义循环的四种活动与无终点、三层决定权、何时找用户、代码与 skill 的分界及保证强弱。代码只强制信任边界，其余由 skill 指导、eval 校验。各步骤规格在 E 至 D 章，本章只写分工、时机与边界。

## A.1　说清循环怎么转 [#A-1]

<Steps>

<Step>

入口：用户选定研究路线后进入迭代。

</Step>

<Step>

迭代：在同一路线内反复进行，到达 Agent 声明的复盘节奏时进入复盘。

</Step>

<Step>

复盘：结束后默认回到迭代；Agent 判断需换路线时回到入口。

</Step>

<Step>

观察：与以上活动并行，用户随时可读，不改变循环走向。

</Step>

<Step>

各活动的产出都由 Agent 经命令行写入账本；数据只有这一个方向，账本是唯一持久状态。

</Step>

</Steps>

### A.1.1　循环的步骤 [#A-1-1]

四步都是 skill 指导的 Agent 行为。输入是账本里的候选清单、运行绩效指标与研究状态视图 <Ref id="report.research_state" />；输出是写回账本的登记、证据包与判断。代码只在步骤之间强制登记先于回放并锁定网格点、完整性审计、实质活动与可比资格、检验结果，不决定下一步、不返回裁决。

<Cap id="A.1.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="入口先恢复研究状态并给综合推荐，再由用户选研究路线">

1. 经命令行读候选清单 <Ref id="report.candidates" />、运行绩效指标与当前路线的研究状态视图 <Ref id="report.research_state" />（命令 <Ref id="cli.research_state" />）。
2. 视图给出的未复盘试验非空且到达声明的复盘节奏时，先复盘再给推荐。
3. 在全部经济证据可用的候选上给多维综合推荐与路线选项，并说明取舍。
4. 等用户选研究路线，选定前不登记、不回放。
5. 把选定的起点候选、开发窗口与钉住的市场提交写成研究路线证据包（<Ref id="ledger.select_line" />）。

- 研究状态 research state 是读时视图：当前判断加候选身份、资格、绩效指标与研究计数等读时事实，按研究路线在读取提交上现算，不另存。
- 会话记忆不算研究状态。
- 仅诊断与无效候选分列，不入推荐。
- 推荐维度：年化、回撤、夏普、胜率、成本、资金使用率 capital utilisation、利润来源、机制、不确定性。
- 每个选项附绩效指标、资格与已试／未试历史。
- 选项由 Agent 提、由用户选，不以推荐代替选择。
- 只在两种情况下提根节点 root 选项：账本里没有候选谱系 lineage，或用户明确决定离开全部现存路线（<Ref id="research-start/SKILL.md#root-options" />）。
- 根来自策略库模板或用户自建的人造根 artificial root，附首份报告。
- 亏损、低优先级、复盘计数或运行限制都不触发选新根。

**输入**　账本中的候选清单、运行绩效指标与研究状态视图 <Ref id="report.research_state" />。

**输出**　综合推荐与路线选项；用户选定后的研究路线证据包。

**强制**　research-start skill 指导恢复、推荐、等用户选三阶段与提根条件；代码只提供只读读口（<Ref id="report.research_state" />）与路线证据包写入，不做选择。

</Cap>

<Cap id="A.1.1.2" kind="skill" tier="verified" tierLabel="已验证" title="路线内迭代按固定顺序从查来源推进到反馈与优先级，不逐步请批">

1. 查来源：先取账本中留存且仍适用的资料，再按 research-sources 补检缺口。
2. 写假设 hypothesis 五样：经济理由、来源证据、一个比较维度、网格、适用条件。
3. 发布候选：改动后的源码经 <Ref id="ledger.publish_candidate" /> 写入账本，得到 strategy_id@revision。
4. 原生预检与独立审查：跑 purpose=precheck 的试验，另一个独立 Agent 审源码四项并经 <Ref id="registration.record_review" /> 只追加入账。
5. 登记并锁定：经 <Ref id="registration.register" /> 在一个写事务里核对登记体与执行身份，写成不可变登记证据。
6. 回放：对每个网格点各跑一次 purpose=research 的试验，产生运行 run。
7. 审计与资格：运行环境内的独立审计器只对账不重算，实质活动与可比资格都通过才给经济反馈。
8. 读比较证据：经 <Ref id="report.compare" /> 取登记声明的对照，配对块自助给效应、区间、p，不返回裁决。
9. 反馈与优先级：机制解释、适用条件与重评条件记为 interpretation 判断，后续具体研究动作的排序记为 priority 判断（父版本与对照挂为主体），都经 <Ref id="ledger.add_judgment" />（命令 <Ref id="cli.judgment_add" />）只追加入账。

- Agent 不在步骤之间请用户批准。
- 理由分外部依据、本地诊断、自身推测三类；工程修复不需论文。
- 父 parent 可为谱系中任一完整候选，比较对照 control 分别声明。
- 预检用锁定引擎 engine 与实际运行环境 runtime image，核构造、订单接口、因果时钟、就绪与触发后活动。
- 预检或审查失败即修复、重新发布并重预检。
- 网格点一次性消耗，无效与中断同样算消耗；重试另登记 retry_of（<Ref id="table:registration_attempt" />）。
- 改网格、源码或意图即新登记。
- 零成交只诊断原因，不记亏损、不改优先级。
- 结论只在登记的适用条件内成立。
- 优先级按预期效应、不确定性、机制佐证、覆盖、信息价值与成本排定；低优先级保留重评。
- 算过的视角与读过的报告记为 search_exposure 判断（<Ref id="research-round/references/judgments.md#what-to-record" />）。
- 判断正文只引用候选、试验、登记包与账本提交，不抄绩效指标、计数、资格或结果类别（<Ref id="research-round/references/judgments.md#body-references-only" />）。

**输入**　选定的研究路线及其中的父候选、账本与外部来源资料。

**输出**　新候选版本、登记证据、运行、检验结果与只追加的 interpretation、priority 判断。

**强制**　步骤顺序与优先级由 research-round skill 指导；登记、回放、审计与资格、检验结果的拒绝由代码强制并写入账本。

| 拒绝码 | 条件 |
|---|---|
| <Ref id="registration.require_precheck" /> | 登记时任一网格点源码缺少同源码、同运行环境、同输入且通过的预检与审查。 |
| <Ref id="registration" /> | 回放时网格点已被消耗，或源码、输入身份与登记不符。 |
| 审计不通过（运行环境内独立审计器） | 完整性审计对账不通过，运行判为无效。 |
| <Ref id="report.compare" /> | 比较时无对照、运行未绑定本登记网格、两侧不可比或任一侧无经济证据资格；拒绝并留诊断。 |

</Cap>

<Cap id="A.1.1.3" kind="skill" tier="rehearsal" tierLabel="演练证据" title="复盘按声明的次数或进展触发并给综合推荐，换路线须回入口由用户选">

1. Agent 事先把复盘节奏（按尝试次数或按进展）及理由记为 review_cadence 判断。
2. 节奏到达即复盘：对照研究状态视图 <Ref id="report.research_state" /> 给出的未复盘试验，在全部经济证据可用的候选上综合推荐一版或一批，说明取舍与不确定性。
3. 推荐记为 recommendation 判断，经 <Ref id="ledger.add_judgment" /> 追加入账，based_on_commit 填复盘时读的账本提交。
4. 研究默认在同一路线内继续。
5. 仅当 Agent 判断需要换路线时，给出诊断与路线选项，以提问结束回到入口，等用户选。

- 复盘不停止研究，没有总次数或总预算。
- 被推荐的候选不必是最新版本，也不必是下一实验的父版本。
- 亏损、计数到达、运行限制或故障都不自动换路线。
- 上次复盘以来的试验与计数按最新推荐的 based_on_commit 读时算，不存。

**输入**　review_cadence 判断、研究状态视图 <Ref id="report.research_state" /> 中的未复盘试验、事实计数 <Ref id="report.research_status" /> 与全部可比候选的绩效指标。

**输出**　recommendation 判断；需换路线时的诊断与路线选项。

**强制**　全部由 research-round skill 指导；代码只提供研究状态视图与事实计数供声明节奏对照，不含停止标志。

</Cap>

<Cap id="A.1.1.4" kind="skill" tier="rehearsal" tierLabel="演练证据" title="用户随时读报告与推荐，样本外验证只由用户发起，观察不改候选资格">

- 用户随时读任一候选的运行报告、比较证据与最新推荐（<Ref id="report.research_state" />），不必等复盘。
- 报告经 <Ref id="report.run_report" /> 从运行行给出：绩效指标经资格视图遮蔽，不可用的绩效指标留空并写原因。
- 报告附总体与样本量、指标计算版本与局限清单；推荐选项附绩效指标与资格。
- 用户认可某候选后，Agent 询问是否发起样本外 out-of-sample 验证 validation，并说明检验什么。
- 验证是 purpose=validation 的试验，只由用户发起；产品不自动登记，循环不以它为前提（<Ref id="research-round/references/validation.md#user-initiated" />）。
- 候选不因被读、被推荐或被验证而获得或失去作父版本的资格。

**输入**　账本中的运行行、比较证据与最新 recommendation 判断。

**输出**　只读的候选报告；用户发起时的验证试验。

**强制**　读报告与发起验证由 skill 指导；绩效指标遮蔽与报告内容由代码只读给出。

</Cap>

### A.1.2　没有终点 [#A-1-2]

两条能力一条由 skill 指导（研究默认持续，运行限制只暂停），一条由代码强制（候选身份与派生资格不受推荐、显著性或达标影响），共同保证循环不会被门槛、计数或裁决终止。输入是账本中的登记、未消耗网格点、判断记录与候选表；输出是恢复后的续做与不带分数的候选清单。

<Cap id="A.1.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="研究不设达标门槛、总次数或总预算，运行限制与环境未就绪只暂停执行">

- Agent 声明的次数到达只触发复盘（<Ref id="research-round/SKILL.md#review-cadence" />）。
- 用户设置的运行限制（时间、并发、花费）只暂停执行，不改变研究状态。
- 暂停时账本中的登记、未消耗的网格点（<Ref id="table:registration_attempt" />）与判断记录保持原样。
- 恢复时 Agent 从账本读回这三样，续做已选路线，不重选路线、不重登记。
- 环境未就绪（运行环境、市场提交、覆盖回执缺失）只报告缺哪一段与可运行范围，不缩窄路线、不否定候选（<Ref id="research-start/SKILL.md#readiness-and-blockers" />）。
- 研究计数只给事实：尝试、审计通过、经济可用、仅诊断、无效、未完成与样本外登记状态（<Ref id="report.research_status" />）；研究计数与研究状态视图都没有停止标志、目标或分数字段。

**输入**　账本中的登记、未消耗网格点与判断记录；用户设置的运行限制。

**输出**　恢复后在已选路线内续做；环境未就绪时的缺口与可运行范围报告。

**强制**　持续与暂停的行为由 skill 指导；账本不含任何可触发停止的字段由代码强制。

</Cap>

<Cap id="A.1.2.2" kind="code" tier="rehearsal" tierLabel="演练证据" title="每个完整版本都是候选，推荐、显著性或达标不改变其身份与派生资格">

- 每个完整策略版本都是候选 candidate，引用名为 strategy_id@revision；模板、人造根与派生版本同样是候选。
- 候选经 <Ref id="ledger.publish_candidate" /> 写入 <Ref id="table:candidate" />，候选表不含分数、推荐、资格或排序字段。
- 亏损或不显著的有效候选照样可作父版本。
- 候选清单 <Ref id="report.candidates" /> 只给身份、父与改动、登记尝试与经济证据可用性，不带分数或排序。

**输入**　发布的完整策略版本。

**输出**　候选表行与不带分数或排序的候选清单。

**强制**　账本表结构强制候选表不含分数、推荐、资格或排序字段；推荐只存在于只追加的判断记录，资格读时给出，都不回写候选。

</Cap>

## A.2　划清谁决定什么 [#A-2]

<Steps>

<Step>

用户从 Agent 给出的推荐与选项中选研究路线 research line，或指定历史候选、模板、人造根；选定前 Agent 不登记、不回放。

</Step>

<Step>

Agent 在路线内提假设 hypothesis、选研发父版本 parent 与比较对照 control、写源码（含仓位等设计变量）、登记并回放，不逐项请用户批准。

</Step>

<Step>

代码对运行做完整性审计与经济证据资格判定：无效只存原因，零成交或缺匹配记录只留诊断。

</Step>

<Step>

代码对有资格的两侧运行给配对检验绩效指标 performance metrics：效应、区间、p 与登记时声明的检验条件，不返回通过或失败；账本不存分数、裁决或状态字段。

</Step>

<Step>

Agent 经 <Ref id="report.research_state" /> 读登记 registration、运行 run 记录、绩效指标与当前判断，把研究优先级 research priority 等判断经 <Ref id="ledger.add_judgment" /> 追加到账本；按声明的复盘节奏复盘 review 并给综合推荐 recommendation，推荐候选与下一实验父版本分别说明。

</Step>

<Step>

用户看报告判断认可、上线与是否发起样本外 out-of-sample 验证；凡属授权事项（实盘、破坏性写、改检查、改研究目标），Agent 停下等用户。

</Step>

</Steps>

### A.2.1　产品代码判定的事 [#A-2-1]

代码只读账本里的运行记录与登记，输出事实、原因与声明的检验条件，没有裁决字段。

<Cap id="A.2.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" tierNote="演练中实际走过：早期曾把零成交运行误读为经济结果，此后由资格检查把零成交只列为诊断，不给区间与 p。" title="审计不过的回放无效；有真实成交且记录互相匹配才有经济证据资格">

1. 每次回放结束后，与运行器和策略源码独立的进程在同一运行环境 runtime image 内只读回放报告，执行完整性审计 <Ref id="engine.audit" />。
2. 审计不通过、审计未运行或运行器非零退出的回放记为无效 invalid；<Ref id="ledger.ingest_run" /> 只写状态、逐条原因与原生摘要，绩效指标列一律置空。
3. 有效运行才写绩效指标与原生报表行。
4. 读取时 <Ref id="qualification.assess" /> 按明确的检查身份算出经济证据资格 comparability 的当前视图，附原因。
5. 比较与对照登记前，<Ref id="qualification.require" /> 作硬门：任一侧不可用即拒绝并返回原因。

- 无效运行不参与任何比较，但仍计入试验 trial 次数（<Ref id="G.1.2.1" />）。
- 有效不等于可比：运行须有真实原生成交，且订单、持仓周期、费用、资金费 funding 与账户记录互相匹配，才具备可比资格并可获得改善、区间与 p。
- 零成交或缺匹配记录的运行只留诊断，绩效指标置空，也不因账户未变而优于亏损对照。
- 资格视图综合审计状态、原始执行捕获与绑定的独立源码审查。
- 资格视图不改写存储的审计结论。
- 报告、候选清单、比较与计数共用这一视图。
- 拒绝时抛出带拒绝码与缺什么的异常，形态与序列化见 <Ref id="ledger.refusal" />。
- 两道判定只回答这次回放是否有效、是否有资格、为什么，不评价策略好坏。

**输入**　回放报告、账本中的运行记录、原始执行捕获与绑定的独立源码审查。

**输出**　运行的有效或无效状态与逐条原因；读取时算出的可比资格视图及原因。

**强制**　代码强制：独立进程执行的完整性审计、入账函数 ledger.ingest_run 与资格函数 qualification.assess / qualification.require。

</Cap>

<Cap id="A.2.1.2" kind="code" tier="verified" tierLabel="已验证" tierNote="演练中检验结果全部由代码算出并附检验条件，推荐只引用绩效指标。" title="比较只返回效应、区间、p 与检验条件，不返回通过或失败">

1. 比较的唯一入口 <Ref id="report.compare" /> 接收一个登记 registration 的引用。
2. 核对登记声明了比较对照 control，且候选运行绑定本登记的网格点。
3. 核对两侧运行都有效且可比，并都通过经济证据资格 <Ref id="qualification.require" />。
4. 取两侧在交易窗口内的账户日收益，核对日钟逐日一致。
5. 调用配对块自助检验 paired block bootstrap <Ref id="report.paired" />：取两侧账户日收益的对数差，按登记声明的块长循环分块，两侧共用同一组块起点共同重抽。
6. 返回效应（平均日对数差与由之换算的年化差）、基本区间、嵌套学生化区间、单侧 p、块长敏感性、功效近似，以及登记时声明的检验条件。

- 第 2 至 4 步任一项不符即拒绝并留下诊断，拒绝形态见 <Ref id="ledger.refusal" />。
- 声明的检验条件是显著性水平与最小改进，均为未校准示例值。
- 输出绑定两侧运行与登记的身份。
- 代码不返回通过、失败或采纳字段。
- 比较不写账本；绩效指标与解释由 Agent 作只追加证据留存（<Ref id="V.4.2.2" />）。
- 绩效指标只服务于诊断、推荐与用户判断。

**输入**　一个登记的引用。

**输出**　绑定两侧运行与登记身份的效应、区间、p、块长敏感性、功效近似与声明的检验条件。

**强制**　代码强制：只读函数 report.compare 是比较的唯一入口，内部调用 report.paired。

</Cap>

### A.2.2　Agent 决定的 [#A-2-2]

Agent 经研究状态视图读候选、绩效指标与当前判断，产出登记、策略源码，以及推荐与研究优先级等判断记录；代码只提供绩效指标与计数，不介入裁决。

<Cap id="A.2.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" tierNote="演练中 Agent 自行决定父版本与对照并在源码中改仓位规则，没有请求授权；所选父版本与当时的推荐候选不同。" title="路线内研究动作由 Agent 自主决定；仓位与风险上限是设计变量而非用户约束">

- 在用户选定的研究路线内，Agent 自主提假设、选研发父版本与比较对照、排研究优先级，不逐项请用户批准。
- 父可为谱系中任一完整候选，亏损或不显著照样可派生。
- 对照须经济证据可用。
- 父与对照分别声明，理由写进登记（<Ref id="research-round/SKILL.md#parent-and-control" />）。
- 研究优先级按预期效应、不确定性、机制佐证、覆盖、信息价值与成本排具体动作；代码不给优先级（<Ref id="research-round/references/feedback.md#priority-ranking" />）。
- 排序与理由经 <Ref id="ledger.add_judgment" /> 记为 priority 判断，每个动作的父版本与对照挂为 parent、control 主体（<Ref id="research-round/references/judgments.md#what-to-record" />）。
- 仓位、单笔风险与名义上限是 Agent 的设计变量：规则写在策略源码里，数量由引擎 engine 账户状态算出。
- 不另设名义上限模仿保证金 margin；资金使用率 capital utilisation 从报告读出（<Ref id="research-round/references/strategy-authoring.md#hard-contract-capital" />）。
- 设计变量不构成用户约束，改动不需要授权，也不得在推荐或反馈里被说成用户约束。

**输入**　用户选定的研究路线；<Ref id="report.research_state" /> 给出的候选、绩效指标与当前判断。

**输出**　登记（含父版本与对照的理由）、策略源码、追加到账本的 priority 判断。

**强制**　skill 强制（<Ref id="research-round/SKILL.md#design-variables" />），eval <Ref id="eval:research-round/own-sizing-not-user-constraint" /> 校验。

</Cap>

<Cap id="A.2.2.2" kind="skill" tier="rehearsal" tierLabel="演练证据" tierNote="演练中最终推荐不是最新版本，而下一实验的父版本另有理由；两者分别记为 recommendation 与 priority 判断。" title="推荐综合全部可用候选并说明取舍；不替用户选路线，也不必是下一父版本">

- 推荐在复盘或入口给出，范围是全部经济证据可用的候选 candidate，含历史候选。
- 综合维度：年化、回撤、夏普、胜率、成本、资金使用率、利润来源（价格盈亏、手续费、资金费拆分）、机制解释与不确定性。
- 推荐一版或一批，并说明取舍。
- 推荐随时可做，不等未来候选研究完，不等于验证。
- 推荐是用户选择研究路线的输入，不是选择本身。
- 推荐候选不必是下一实验的研发父版本：父与对照按研究需要另选，两者分别给理由、分别记录（<Ref id="research-round/SKILL.md#recommendation-vs-next-parent" />）。
- 推荐依据代码给出的绩效指标与计数，不引用任何裁决字段。
- 推荐经 <Ref id="ledger.add_judgment" /> 记为 recommendation 判断，推荐候选挂 recommended 主体；正文写取舍理由，只引用候选、试验、登记包与账本提交，不抄绩效指标数值、计数或资格结论，这些由 <Ref id="report.research_state" /> 读时给出（<Ref id="research-round/references/judgments.md#body-references-only" />）。

**输入**　<Ref id="report.research_state" /> 给出的全部经济证据可用的候选及其绩效指标与计数。

**输出**　追加到账本的 recommendation 判断：推荐候选与取舍理由。

**强制**　skill 强制（<Ref id="research-round/SKILL.md#review-and-recommendation" />、<Ref id="research-start/SKILL.md#recommendation-statement" />），eval <Ref id="eval:research-round/recommendation-not-next-parent" /> 与 <Ref id="eval:research-round/judgment-references-not-copies" /> 校验。

</Cap>

### A.2.3　用户决定的 [#A-2-3]

用户的决定在产品之外做出，账本不含对应状态字段；skill 规定 Agent 在这些点停住等待，eval 校验。

<Cap id="A.2.3.1" kind="skill" tier="rehearsal" tierLabel="演练证据" tierNote="演练中根均由用户选定的模板发布，路线切换等待用户选择。" title="研究路线由用户选定；选定前 Agent 不登记、不回放">

1. Agent 经 <Ref id="report.research_state" /> 读当前判断与读时事实，提出选项：推荐与取舍、多维绩效指标、历史试验的机制解释与重评条件。
2. 用户从中选，或指定推荐范围外的历史候选、策略库模板，或用自己提供的信息源建人造根。
3. 选中项成为当前唯一研究路线的起点，路线内由 Agent 自主派生。

- 用户选定前 Agent 不登记、不回放，不以推荐代替选择。
- 模板根只在没有任何候选或用户明确离开全部现有路线时提出，附其在当前开发窗口的报告；亏损或不显著不触发（<Ref id="research-start/SKILL.md#root-options" />）。
- 人造根由用户发起并提供信息源，Agent 不主动提议（<Ref id="research-start/SKILL.md#artificial-root" />）。
- 用户明确授权选某模板一次即够，不重复请求。

**输入**　Agent 给出的推荐、多维绩效指标与历史试验的机制解释；或用户指定的历史候选、模板、信息源。

**输出**　当前唯一研究路线的起点。

**强制**　skill 强制（<Ref id="research-start/SKILL.md#user-selects-route" />），eval <Ref id="eval:research-start/route-change-waits-for-user" /> 与 <Ref id="eval:research-start/artificial-root-user-initiated" /> 校验。

</Cap>

<Cap id="A.2.3.2" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺用户据报告做出认可或上线决定并发起样本外验证的实际案例；演练未到此步。" title="认可、上线与样本外验证由用户看报告后发起，产品不存其状态">

1. Agent 在复盘与入口给综合推荐（<Ref id="research-round/SKILL.md#review-and-recommendation" />）。
2. 用户看报告后判断是否认可候选、是否上线。
3. 用户表示认可某候选后，Agent 询问是否做样本外验证并说明检验什么。
4. 用户发起后 Agent 才登记验证。
5. 验证结果无论好坏照实报告并找用户。

- 账本与代码不含认可、上线或验证状态字段，研究循环也不以它们为前提。
- Agent 的职责到报告为止。
- 报告验证结果时不换窗口或范围再登记，不挑着报，不用开发窗口绩效指标替代（<Ref id="research-round/references/validation.md#report-as-is" />）。

**输入**　报告与综合推荐。

**输出**　用户发起后的样本外验证登记与照实的验证报告。

**强制**　skill 强制（<Ref id="research-round/references/validation.md#user-initiated" />）。

</Cap>

<Cap id="A.2.3.3" kind="skill" tier="rehearsal" tierLabel="演练证据" tierNote="演练中遇到的阻断都通过修复代码并发布新运行环境或新源码后重新登记解决，未放宽任何拒绝或审计检查。" title="实盘、破坏性写、改检查与改研究目标，Agent 一律停下等用户授权">

- 实盘交易、交易所连接或交易凭据需要授权；研究从不使用。
- 破坏性写需要授权：重置或清空账本，改写或删除已发布记录、封存 seal 产物、备份、运行环境镜像、规范数据输入与历史回执。
- 放宽或收紧代码、测试、配置或 skill 中的任何拒绝与审计检查需要授权，包括为了通过一个失败的检查。
- 改用户的研究目标需要授权。
- 遇到以上事项，Agent 不自行执行也不绕过，先向用户说明。
- 检查阻断时修复源码或代码，发布新候选或新运行环境后重新登记，不改检查本身。
- 新增产品代码前先按 <Ref id="research-round/SKILL.md#value-check-before-code" /> 说明消费者、阻断、预期改善与反证。
- 不在此清单的事（含仓位等设计变量）不需要授权。

**强制**　skill 强制（<Ref id="research-round/SKILL.md#authority" />），eval <Ref id="eval:research-round/authority-stops-before-check-change" /> 校验。

</Cap>

## A.3　何时找用户 [#A-3]

<Steps>

<Step>

Agent 在研究路线内自主推进（<Ref id="A.2.2.1" />），假设、登记、回放、反馈与优先级都不请示用户。

</Step>

<Step>

出现四类时刻之一时停下：候选谱系为空或需离开路线（<Ref id="A.3.1.1" />）、执行被阻断（<Ref id="A.3.1.2" />）、复盘给出推荐（<Ref id="A.3.2.1" />）、样本外出结果（<Ref id="A.3.2.2" />）。

</Step>

<Step>

做选择的时刻产出诊断或精确阻断加选项并保留恢复状态；看结果的时刻产出推荐或绩效指标，写明取舍、局限与不确定性。

</Step>

<Step>

报告以提问结束交给用户；做选择的时刻等待，期间不登记、不回放、不改开发窗口或范围；看结果的时刻不等待，循环继续。

</Step>

<Step>

用户选定路线或范围后，Agent 经 <Ref id="ledger.select_line" /> 写入账本并续做；用户只看结果时按研究优先级继续下一实验。

</Step>

</Steps>

### A.3.1　要用户做选择时 [#A-3-1]

由 skill（research-start 为主、research-round 换路线节配合）指导，输入是研究状态视图、候选清单与代码只读产出的环境事实。

<Cap id="A.3.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="候选谱系为空或需离开当前路线时，Agent 给诊断与选项并等用户选">

- 触发条件只有两种。
- 触发 (a)：账本中没有经济证据可用的候选（candidate），候选谱系为空。
- 触发 (b)：复盘后 Agent 判断当前研究路线内已无值得优先做的后续动作。
- (a) 情况从策略库模板提根节点（root）选项，每个模板附其在当前开发窗口（development window）的首份报告（<Ref id="research-start/SKILL.md#root-options" />）。
- (b) 情况列出历史候选、其他路线、模板或人造根，每项附多维绩效指标与取舍（<Ref id="A.2.3.1" />）。
- 报告以提问结束，等用户选（<Ref id="E.4.1.1" />）。
- 用户选定前不登记、不回放、不改开发窗口与范围，不以推荐代替选择。
- 不要求证明旧路线无价值：旧路线、其候选、证据与判断在账本中原样保留，低优先级方向可随时重评。
- 亏损与不显著不是触发条件，走反馈与优先级（<Ref id="A.1.1.2" />）。
- 研究计数到达不是触发条件，只触发复盘（<Ref id="F.3.1.2" />）。
- 运行限制或故障不是触发条件，走 <Ref id="A.3.1.2" />。

**输入**　研究状态视图（当前 recommendation、priority 与 interpretation 判断及读时事实，<Ref id="report.research_state" />，命令 <Ref id="cli.research_state" />）与候选清单（<Ref id="E.1.1.2" />）。

**输出**　一份诊断（为什么没有起点，或为什么当前路线继续的预期价值低于其他选项）加选项清单，以提问结束。

**强制**　由 skill 强制，无代码拒绝码；用户选定后由 <Ref id="ledger.select_line" /> 写新路线。

</Cap>

<Cap id="A.3.1.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="执行被暂停或阻断时，Agent 报告精确阻断与可运行范围并等用户选">

- 触发 (a)：用户设置的运行限制（时长、并发、机器资源）到达。
- 触发 (b)：运行环境（runtime image）解析失败或身份核对不过（<Ref id="runtime.resolve" />、<Ref id="runtime.validate_identity" />）。
- 触发 (c)：钉住的市场提交（market commit）下所选合约覆盖事实或生命周期回执有缺口（<Ref id="market.diagnose_coverage" />），已登记网格点无法回放。
- 触发 (d)：继续只能靠改用户选定的市场提交或开发窗口。
- 报告给出精确阻断：缺哪一段（镜像、市场提交、哪个合约哪个区间的覆盖或哪个生命周期事件）。
- 报告给出可运行范围：不改范围时仍可回放的网格点与合约。
- 报告给出恢复状态：账本中的登记与未消耗网格点原样保留，恢复后续做（<Ref id="research-start/SKILL.md#pause-and-resume" />）。
- 以提问结束，等用户在三项中选：等待修复后原范围重跑、在可运行范围内继续、改市场提交或开发窗口（后者走 <Ref id="D.1.1.3" />）。
- Agent 不自行删币、缩窗或补数（<Ref id="W.3.3.2" />）。
- 阻断不否定候选身份或路线有效性，覆盖缺口不是经济失败；已完成运行的绩效指标照常可读。
- 不设达标门槛、总次数或总预算（<Ref id="A.1.2.1" />）。

**输入**　运行环境解析结果、按合约的覆盖事实与生命周期回执（只读，<Ref id="E.1.2.2" />）、账本中的登记与未消耗网格点。

**输出**　精确阻断、可运行范围、恢复状态三部分组成的报告，以提问结束。

**强制**　阻断事实由代码产出（运行环境与覆盖读口只给事实、不给绕过）；报告形态与等待由 skill 强制；范围改变只能由用户选定后经 <Ref id="ledger.select_line" /> 写成新路线。

</Cap>

### A.3.2　要用户看结果时 [#A-3-2]

由 research-round 指导，复盘推荐与样本外绩效指标都以报告交给用户。

<Cap id="A.3.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="复盘给出综合推荐时，Agent 报告推荐与取舍后不等待，继续循环">

- 复盘按当前 review_cadence 判断声明的次数或进展节奏触发（<Ref id="F.3.1.2" />），到达即复盘，不停止研究。
- 推荐写明推荐哪一版或哪一批、理由、取舍、不确定性。
- 另写明下一动作的优先级。
- 另写明所选父版本（parent）与比较对照（control）及理由。
- 另写明复盘节奏及理由。
- 三者互不推出，推荐候选不必是下一实验的父版本（<Ref id="F.3.2.2" />）。
- 三者各写成一条判断经 <Ref id="cli.judgment_add" /> 写入（<Ref id="ledger.add_judgment" />）：recommendation 挂推荐候选为 recommended，priority 挂父版本与对照为 parent、control，review_cadence 记节奏（<Ref id="research-round/references/judgments.md#what-to-record" />）。
- 判断正文只引用候选、试验、登记包与账本提交，不抄绩效指标、计数、资格或结果类别，这些由 <Ref id="report.research_state" /> 读时给出（<Ref id="research-round/references/judgments.md#body-references-only" />）。
- 交给用户后不等待：用户可继续（Agent 默认按优先级续做）、换路线（走 <Ref id="A.3.1.1" />）或发起样本外验证（走 <Ref id="X.1.1.1" />）。
- 推荐不是裁决也不是验证，不含采纳门槛或推荐分数；认不认可、上不上线由用户看报告后判断（<Ref id="A.2.3.2" />）。

**输入**　全部经济证据可用的候选及其绩效指标（年化、回撤、夏普、胜率、成本、资金使用率 capital utilisation、利润来源拆分、机制解释、不确定性，<Ref id="E.3.2.1" />），以及研究状态视图中的 interpretation 判断、当前 priority 判断与未复盘试验（<Ref id="report.research_state" />）。

**输出**　一份交给用户看的推荐，以及写入账本的 recommendation、priority、review_cadence 三条判断。

**强制**　由 skill 强制；绩效指标来自代码，Agent 不自评（<Ref id="F.3.1.1" />）；判断写入由 <Ref id="ledger.add_judgment" /> 核对路线、账本提交、主体与取代关系。

</Cap>

<Cap id="A.3.2.2" kind="skill" tier="unverified" tierLabel="待验证" title="样本外验证出结果时，Agent 无论好坏照实报告，不重跑、不出裁决">

- 样本外验证只由用户发起（<Ref id="X.1.1.1" />）。
- 回放前登记被验候选、窗口、范围与检验条件（显著性水平、最小改进）。
- 检验条件数值一律标「未校准示例值」。
- 登记时取公共时间戳凭证，窗口在凭证之后开始。
- 一次登记绑定一次回放，不一致由账本拒绝（<Ref id="X.1.3.2" />）。
- 报告第一部分：登记的检验条件。
- 报告第二部分：与开发报告同口径的绩效指标及其一次性区间（<Ref id="X.2.1.1" />），多候选同一窗口时附校正。
- 报告第三部分：局限。
- 局限一：成交由撮合模型模拟，绩效指标是实盘上限。
- 局限二：短窗口只能否定，写出窗口长度与可分辨效应（<Ref id="research-round/references/validation.md#limits" />）。
- 报告第四部分：用语只说绩效指标或「未被反驳」，不说验证通过（<Ref id="research-round/references/validation.md#wording" />）。
- 无论好坏都报：不改口径、不换窗口或范围再登记、不挑着报、不用开发窗口绩效指标替代。
- 认不认可由用户判断，Agent 不出裁决；报告后循环继续，不以验证结果为前提。
- 待验证：缺实际完成的样本外验证案例。

**输入**　样本外报告（<Ref id="cli.validation_report" />）与该次登记的检验条件。

**输出**　包含检验条件、同口径绩效指标与区间、局限、规范用语四部分的报告。

**强制**　登记一致性、时间戳凭证与绩效指标由代码与账本强制；呈现方式与不重跑由 skill 强制。

</Cap>

## A.4　划定产品代码的范围 [#A-4]

<Steps>

<Step>

提出一项要支持的行为，写明它的消费者与要解的阻断。

</Step>

<Step>

信任边界或 Agent 做不到的事（原子写、并发、权限）进代码，由各包函数以拒绝码强制（A.4.1）。

</Step>

<Step>

属于撮合、订单、成交、结算、风控、账户或保证金的交给引擎，代码只配置与读取，不建与引擎平行的系统。

</Step>

<Step>

其余进按需加载的 skill（A.4.3）；skill 指导的部分不产生账本裁决字段，代码也不设通过门槛、固定次数终止或按大类排除。

</Step>

<Step>

想加的代码先做价值验证（A.4.1.3）。

</Step>

</Steps>

### A.4.1　代码只放什么 [#A-4-1]

代码只放信任边界（不放进代码 Agent 就会自己给自己打分）与 Agent 做不到的账本写协议，加代码前的价值验证是 skill 指导的开发原则。

<Cap id="A.4.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="代码只强制九条信任边界，每条由具名函数拒绝且无绕过">

- 每条边界由所列函数在回放前、回放后或读取时强制。
- 不满足即抛 <Ref id="ledger.refusal" />（拒绝码、缺什么、写入状态），不给绕过途径。
- 边界之外代码不做裁决。
- (1) 登记先于回放并锁定：试验行写入的同一事务里由 <Ref id="registration.bind" /> 把试验绑定到一个已登记网格点。
- 网格点一次性消耗。
- 重试另登记，以 retry_of 指回原登记。
- (1) 登记前每个网格源码须有通过的原生预检 native precheck 与独立源码审查（<Ref id="registration.require_precheck" />）。
- (2) 完整性审计：<Ref id="engine.audit" /> 只读原生报告，不导入策略源码。
- (3) 实质活动 substantive activity 与可比资格 comparability：<Ref id="qualification.assess" /> 在读取时算出当前资格，零成交或缺匹配记录只留诊断。
- <Ref id="registration.check_comparable" /> 核两侧可比。
- (4) 检验结果：<Ref id="report.paired" /> 只给效应、区间与 p，不返回采纳裁决。
- (5) 账本只追加、原子幂等与封存 seal：写入只经 <Ref id="ledger.write" />。
- 回放结束（含中断与宿主失败）由 <Ref id="ledger.seal_capture" /> 原样封存命令、各阶段退出码与原生 stdout、stderr。
- (6) 运行环境钉死与执行身份：<Ref id="runtime.resolve" /> 从镜像清单读出身份，不接受手写身份。
- (7) 市场覆盖与生命周期回执：<Ref id="market.coverage_facts" /> 在固定市场提交上产出覆盖与上市、下架事实。
- (8) 样本外 out-of-sample 登记与重叠拒绝：<Ref id="registration.validation_register" /> 要求窗口起点晚于登记写入时间。
- (9) 试验事实计数：<Ref id="report.research_status" /> 只给计数，不给停止标志、目标或分数。

**输入**　登记与网格源码、回放命令与原生报告、镜像清单、固定市场提交及样本外窗口。

**输出**　通过时写入账本或给出绩效指标；不满足时给出带拒绝码、缺什么与写入状态的拒绝。

**强制**　代码：registration、engine、qualification、report、runtime、market、ledger 包内的所列函数抛 <Ref id="ledger.refusal" />，不给绕过途径。

</Cap>

<Cap id="A.4.1.2" kind="code" tier="verified" tierLabel="已验证" title="账本写入的原子幂等、并发拒绝与最小权限由代码和 Dolt 实现">

- 这些性质 Agent 无法靠自觉保证，由 ledger/db.py 与 cli/main.py 的六个函数和 Dolt 服务实现。
- <Ref id="ledger.init" /> 建库并创建 writer 与 reader 两个账号。
- writer 只能插入，只对固定研究 branch 有写权。
- reader 只能读。
- <Ref id="ledger.connect" /> 按角色取凭据并核模式版本。
- <Ref id="ledger.write" /> 把一次写入放进单一事务提交。
- 操作 ID 由操作种类与规范化载荷的哈希派生。
- 同载荷重试返回原记录。
- 并发写在 <Ref id="table:ledger_head" /> 单行上碰撞即回滚并拒绝（CONCURRENT_WRITE）。
- 提交前跑 <Ref id="table:dolt_tests" /> 校验组。
- <Ref id="ledger.read_as_of" /> 给按精确提交的只读连接。
- <Ref id="cli.ledger_init" /> 与 <Ref id="cli.ledger_sql" /> 是初始化与只读查询的唯一入口。
- 直接 SQL 写入被拒绝（WRITE_VIA_SQL）。
- 服务端账号权限是第二道闸。
- 管理权限只在初始化内部使用，不对外开放。

**输入**　一次写入的操作种类与载荷，或初始化、只读查询请求。

**输出**　已提交的账本记录（同载荷重试返回原记录）、按精确提交的只读连接，或拒绝。

**强制**　代码与账本：ledger/db.py、cli/main.py 的六个函数负责单一事务、操作 ID 与校验组，Dolt 服务端 writer/reader 账号权限是第二道闸。

| 拒绝码 | 条件 |
|---|---|
| `CONCURRENT_WRITE` | 并发写在 ledger_head 单行上碰撞，事务回滚。 |
| `WRITE_VIA_SQL` | 绕过 ledger.write 直接用 SQL 写入。 |

</Cap>

<Cap id="A.4.1.3" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺按此原则决定保留或删除代码的记录案例。" title="加产品代码前先写明价值假设，小范围试出改善才保留">

1. 按 <Ref id="research-round/SKILL.md#value-check-before-code" /> 写明消费者、要解的阻断、预期改善、什么结果算反证。
2. 只有信任边界、修复缺陷或 Agent 做不到的事才进入候选清单。
3. 价值未知的想法先用 skill 规则或 /tmp 工作副本小范围试。
4. 试出改善才长期保留，否则删除。

- 动到拒绝或审计检查本身需用户授权，按 <Ref id="research-round/SKILL.md#authority" /> 停下。

**输入**　一项想加的产品代码。

**输出**　进入候选清单并长期保留，或删除。

**强制**　skill：research-round 的开发原则指导 Agent，代码不强制。

</Cap>

### A.4.2　代码不建什么 [#A-4-2]

三条消极约束由运行器交给引擎的配置、容器命令与账本账号权限实现，可在源码、账本模式与运行环境检视中核对。

<Cap id="A.4.2.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="代码不建平行系统，出口只给事实与绩效指标，不设门槛、终止或大类排除">

- 代码不建与引擎平行的引擎、账本、调度器、策略语言或组件注册器。
- 代码不建优化器、推荐分数、贝叶斯或 Thompson 调度、影子账户或知识图谱库。
- 代码不设通过门槛、固定次数终止或按大类排除方向。
- 候选清单 <Ref id="report.candidates" />、比较入口 <Ref id="report.compare" /> 与研究计数 <Ref id="report.research_status" /> 只给事实与绩效指标，不含裁决、分数、排序或停止字段。
- 账本表也没有这类列。
- 推荐 recommendation、研究优先级 research priority 与复盘节奏 review_cadence 是 Agent 按 <Ref id="research-round/references/judgments.md#what-to-record" /> 经 <Ref id="cli.judgment_add" /> 追加的判断，由 <Ref id="ledger.add_judgment" /> 写入 <Ref id="table:judgment" />。
- 判断正文只引用候选、试验、登记包与账本提交，不存绩效指标、计数、资格或结果类别。
- 研究状态由 <Ref id="report.research_state" /> 读时把当前判断与事实拼出，代码不在其中加分数、排序或停止字段。
- 回放中的事件全部交给 <Ref id="engine.replay" /> 里的引擎处理。

**输出**　只读出口返回的事实与绩效指标；研究状态视图另附 Agent 的当前判断。

**强制**　代码与账本模式：账本模式（含 judgment 表）与四个只读出口的返回字段里不出现分数、通过、停止类字段，可检视核对。

</Cap>

<Cap id="A.4.2.2" kind="code" tier="verified" tierLabel="已验证" title="交易事实全归引擎，运行器只配置回放并读原生报告">

1. 把 <Ref id="engine.account_contract" /> 的固定账户与撮合常量和数据交给 <Ref id="engine.replay" /> 建回放节点。
2. 回放后由 <Ref id="engine.audit" /> 读引擎原生报告。

- 撮合、订单、成交、结算、风控、账户与保证金 margin 全归引擎 engine。
- 代码不重算成交、持仓、余额或盈亏，不在引擎之外维护订单状态。
- 需要交易事实的绩效指标一律取原生报告行。

**输入**　固定账户与撮合常量、回放数据。

**输出**　引擎原生报告。

**强制**　代码：运行器只调用 engine.replay 配置回放、engine.audit 读取报告，源码中没有引擎之外的交易状态。

</Cap>

<Cap id="A.4.2.3" kind="code" tier="verified" tierLabel="已验证" title="研究不碰实盘：回放只读交易所数据，无交易账户与凭据，运行环境断网">

- 回放只读交易所数据 exchange data，不连交易账户、不用交易凭据、不下实盘单。
- <Ref id="runtime.container_command" /> 以无网络、只读根、去除能力、禁止提权、当前用户、不拉取的容器执行运行环境 runtime image。
- 声明的输入只读挂载，唯一可写处是报告目录。
- 回放账户是 <Ref id="engine.account_contract" /> 声明的模拟账户。
- 账本连接经 <Ref id="ledger.connect" /> 按角色取凭据，运行环境内不持有任何账本或交易凭据。
- 涉及实盘、实时交易所连接或交易凭据的请求不由代码提供入口，按 <Ref id="research-round/SKILL.md#authority" /> 停下等用户。

**强制**　代码与账本：容器命令的隔离参数、模拟账户合约与按角色的账本凭据；实盘请求由 skill 规定停下等用户。

</Cap>

## A.5　说明保证到什么程度 [#A-5]

<Steps>

<Step>

</Step>

<Step>

核对通过的写入经 <Ref id="ledger.write" /> 单事务整笔提交；候选、证据文件、运行环境与输入的身份都由字节派生，Agent 不能手写。

</Step>

<Step>

<Ref id="runtime.resolve" /> 把运行环境解析为唯一清单摘要，<Ref id="runtime.inspect_runtime" /> 用探针核对；回放中撮合与账户由引擎组件持有，策略源码不能改写。

</Step>

<Step>

Agent 按 skill 产出独立源码审查与来源三分类，经 <Ref id="registration.record_review" /> 与来源证据包只追加入账；代码只核对绑定与存在，<Ref id="qualification.assess" /> 把审查状态与审计状态并列呈现。

</Step>

<Step>

</Step>

<Step>

只读账号按精确版本运行 <Ref id="report.review_all" />，逐表核对非追加差异、绩效指标重算、登记时序与凭证是否在位；差异只报「发现」，不写任何记录。

</Step>

</Steps>

### A.5.1　强制力分级 [#A-5-1]

分两级：代码与引擎强制；skill 提示，其产出以具名证据入账。

<Cap id="A.5.1.1" kind="code" tier="verified" tierLabel="已验证" title="只有代码契约与引擎原生行为能强制，强制的唯一形态是拒绝">

- 能强制的只有两类：代码契约与引擎原生行为。
- 账本写入：<Ref id="ledger.write" /> 单事务提交，整笔成功或整笔不写；同一 operation_id 重试返回原记录；并发写冲突时，一方由数据库回滚并拒绝。
- 网格点一次性消耗：<Ref id="registration.bind" /> 在写试验行的同一事务里，把试验绑到一个已登记的网格点。
- <Ref id="table:registration_attempt" /> 保证一个网格点只能被消耗一次；无效与中断同样算消耗；重试须另行登记并写 retry_of。
- 运行环境按摘要钉死：<Ref id="runtime.resolve" /> 把标签或摘要引用解析为镜像注册表内唯一的清单摘要并读出身份，身份不能手写。
- 执行字节必须等于登记记录的源码哈希。
- <Ref id="engine.replay" /> 按账户契约配置引擎，并把数据流送入回放节点。
- 撮合、订单状态、风控与账户状态由引擎组件持有，策略源码不能改写。
- 回放中消费条数不等于回执总数，即整次失败。
- 拒绝时抛出 <Ref id="ledger.refusal" />，带大写蛇形拒绝码、缺失项 missing 与期望契约 expected。
- 拒绝的写入状态 write_status 取 not_written，或 unknown＋operation_id。
- 拒绝码的取值由抛出它的边界函数在各自的 refusals 中定义，本节不维护码表。
- 拒绝只说明缺什么，不给绕过办法，也不展开底层数据库的错误文本。
- 拒绝不是记录，不写入任何表。
- 演练中登记太晚、网格点已消耗、源码与登记哈希不符三类拒绝都由代码返回拒绝码，Agent 以新登记或新源码应对。

**输入**　边界函数的参数：写入请求、网格点、运行环境引用与待执行的源码字节。

**输出**　整笔提交的记录，或一个拒绝；命令行据此打印并以非零退出码结束。

**强制**　代码与引擎：账本写入与网格绑定在账本事务内强制，撮合与账户状态由引擎组件持有。

</Cap>

<Cap id="A.5.1.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="skill 只是提示；源码审查与来源分类作为具名证据入账，代码只核对绑定">

- skill 与常驻规则只是提示：Agent 读到后照做，不照做时没有代码拒绝。
- 提示层产出两种具名证据：独立源码审查与来源三分类（定义见 <Ref id="research-round/SKILL.md#named-evidence" />）。
- 独立源码审查 independent source review 在候选发布后、登记前进行，由另一个 Agent 审。
- 审查对原生预检原件按接口 api、因果 causal、活动 activity、就绪 readiness 四项各给结论：通过或失败，各附一句依据。
- 审查流程见 <Ref id="research-round/references/strategy-authoring.md#precheck-and-review" />。
- <Ref id="registration.record_review" /> 把审查结论绑定到被审源码哈希与运行环境身份，只追加为证据包；占用产品保留命名空间即拒绝，拒绝码由该函数定义。
- 来源三分类 source classes：假设的每条理由标为外部依据、本地诊断或自身推测之一。
- 外部依据须写出处、市场、窗口、频率、成本与支持范围。
- 分类规则见 <Ref id="research-round/references/source-evidence.md#three-classes" />；分类随登记的来源证据包入账。
- 代码对两种证据只核对形态与绑定，不复判内容。
- <Ref id="registration.require_precheck" />：每个网格源码都须有同源码、同运行环境、结论为通过的预检与审查记录，否则拒绝登记。
- <Ref id="qualification.source_reviews" /> 只认源码哈希与运行环境都匹配的审查记录；内容哈希不符即拒绝。
- <Ref id="qualification.assess" /> 把审查状态与账户审计状态并列呈现，不合并为一个裁决；绑定审查记为失败的运行不作经济证据，但审计结论本身不因此改写。
- 审查内容是否正确、分类是否诚实由 Agent 负责，不升级为代码裁决。
- 演练中源码审查以证据包入账，并在资格视图中与审计状态并列显示。

**输入**　预检原件引用、四项结论与审查者标识；来源分类随来源证据包提交。

**输出**　证据包编号。

**强制**　内容由 research-round skill 指导，并由 <Ref id="eval:research-round/source-three-classes" /> 校验；绑定、只追加与存在性核对由账本与代码强制。

</Cap>

### A.5.2　信任的来源与上限 [#A-5-2]

信任的来源是内容身份，上限由账号模型决定。

<Cap id="A.5.2.1" kind="database" tier="verified" tierLabel="已验证" title="信任来自由字节派生的内容身份，不来自账号或承诺">

- 内容身份 content hash：相同字节即同一身份，不同字节不能冒充。
- 账本提交哈希：每次写入形成一个提交，Dolt 以内容寻址的 Prolly 树给出根哈希，根哈希相同即数据相同。
- 候选身份：源码精确字节的 SHA-256，在库内派生，引用名为 strategy_id@revision（<Ref id="table:candidate" />）。
- 运行环境身份：镜像清单摘要与平台，由 <Ref id="runtime.resolve" /> 从镜像注册表读出，不能手写。
- <Ref id="runtime.inspect_runtime" /> 在隔离容器内运行探针，核对契约、源码路径与有效配置哈希是否自洽。
- 封存产物身份：证据包内每个文件的原件字节，以及由字节派生的哈希与长度（<Ref id="table:evidence" />）；读回时逐文件重验。
- 执行身份：子进程启动前，试验行写下用途、源码哈希、运行环境摘要、合约集与窗口（<Ref id="table:trial" />）。
- 运行行记录有效配置哈希、输入身份与指标计算版本（<Ref id="table:run" />）；输入身份包括钉住的市场提交（<Ref id="market.resolve_commit" />）与按 AS OF 派生的成员时间路径（<Ref id="table:universe_month" />）。
- 写入时间由服务器触发器填写，Agent 不能提供。
- 账本内的先后由提交顺序证明；dolt_history_\<t> 给出每行在每次提交时的值与提交时间。
- 对外的先后（如样本外登记早于窗口起点）由 RFC 3161 时间凭证证明（<Ref id="table:witness" />），离线验证走 <Ref id="ledger.token_time" />；凭证只证明记录当时已经存在，不证明它唯一。

**输入**　源码字节、镜像注册表中的清单、证据文件字节与执行参数。

**输出**　账本提交哈希、候选、运行环境、封存产物与执行的身份。

**强制**　数据库强制内容寻址与提交历史；代码负责身份派生与逐项核对。

</Cap>

<Cap id="A.5.2.2" kind="database" tier="verified" tierLabel="已验证" title="同一系统用户下只防误操作、不防蓄意；篡改能事后发现，不能阻止">

- <Ref id="ledger.init" /> 建立 writer 账号（只能插入，只对研究账本线有写权）、reader 账号、Dolt branch control 与提交校验组；<Ref id="ledger.connect" /> 按角色取凭据建立连接。
- 这些机制只约束带用户名和密码的 SQL 会话：持有账本服务目录的人，在该目录直接运行命令行即以超级用户进入。
- <Ref id="table:dolt_tests" /> 在提交前跨表校验，失败即拒绝提交；但单次提交可以用跳过参数绕过。
- 因此权限与校验只是留痕保证，不是不可改保证。
- 写入侧的并发碰撞点是 ledger_head 单行，冲突时一方由数据库回滚。
- 篡改不能阻止，只能事后发现：由只读账号按精确版本运行 <Ref id="report.review_all" />。
- 复核逐表读取 dolt_diff_\<table> 与 dolt_history_\<table> 核对非追加差异，diff_type 为修改或删除即是发现。
- 用历史版本的指标计算代码重算绩效指标，并与存储值比对。
- 核对登记时间早于试验，且被执行的源码在登记网格内。
- 核对封存身份与 <Ref id="table:witness" /> 凭证都在位。
- 核对 <Ref id="table:ledger_head" /> 的操作序列连续、无缺号。
- 差异只报「发现」并引用对应的账本提交；不写任何记录，也不自动修复。

**输入**　账本的精确版本，以及只读账号的会话。

**输出**　发现清单，每条引用对应的账本提交。

**强制**　数据库强制权限、提交校验并保存差异历史；发现由代码以只读方式完成。

</Cap>
