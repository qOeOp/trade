# 14　总则：先看全貌：研究循环怎么转，哪些事由你定，哪些由 Agent 定，哪些交给代码检查。

这一章排在全书最后。前面各章讲每一步具体怎么做，这里只回答两件事：研究循环怎么转；你、Agent 和代码各自决定什么。研究循环没有终点：先在入口选一条研究路线（你选定的研究方向），再在路线里反复试验，隔一段复盘一次；你随时可以看。

决定权分三层。你决定研究方向和一切需要授权的事；Agent 在你选定的路线里决定全部研究动作，不逐项问你；代码只在步骤之间核对事实，比如这次回放有没有效、能不能当比较证据，但不判断好坏、不决定下一步。三层之间只通过账本传东西，账本是唯一长期保存的研究记录。

举个例子：你选定了一条路线，并决定保留原来的币池和窗口。之后的假设都由 Agent 自己提、自己登记、自己回放，不用逐个问你；但涉及数据约定、检查边界和本机资源的改动，它要停下来问你，拿到明确授权才做。

## 14.1　说清循环怎么转 [#A-1]

研究循环由入口、迭代、复盘、观察四种活动组成，所有产出都写进账本，循环本身没有终点。

迭代里每一步都是 Agent 照 skill（写给 Agent 的书面工作规程）去做的；代码只在步骤之间做检查，不决定下一步。

### 路线里一次迭代按固定九步走，步与步之间不请你批准 [#A-1-1-2]

在路线里，每次迭代都按同一个顺序走：查来源、写假设、发布候选、预检和独立审查、登记、回放、审计与资格、读比较证据、写反馈并排优先级。顺序和优先级靠 skill 指导；登记、回放、审计与资格、读比较证据这四步的拒绝由代码强制，并写进账本。

顺序固定，每一步都有前一步的产出可查：没审查过的源码登记不了，没登记的不能回放，没有对照的拿不到比较。步间不请批，是因为路线里的研究动作本来就归 Agent，一步一问只会拖慢研究。

1. 查来源：先用账本里留着、仍然适用的资料，缺的再去外部查。理由分三类：外部依据、本地诊断、自己的推测；纯工程修复不需要论文。
2. 写假设：写清五样，即经济理由、来源证据、检验条件（有对照时）、网格、适用条件。父版本可以是谱系里任一完整候选，比较对照另外单独声明。
3. 发布候选：改好的源码经 27 行职责头校验（`DUTY_HEADER_INVALID`）后写进账本，成为一个带版本号的候选。
4. 预检和审查：用锁定的引擎和实际运行环境短跑一次预检，查构造、下单接口、时钟有没有偷看未来、就绪和触发后的活动；再由另一个没参与编写的 Agent 对照父子 unified diff（`diff -u`）审源码四项并追加入账。不通过就修，重新发布、重新预检。
5. 登记：在一次写入里核对登记内容、父子职责头差异（`DUTY_HEADER_MISMATCH`）和执行身份，锁成不可改的登记证据。任何一个网格点的源码，缺少同源码、同运行环境、同输入、同配置且通过的预检和审查，就会被拒绝（`registration.require_precheck`）。每个网格点只能用一次，无效和中断的也算用掉；要重试就另行登记，并注明重试的是哪一次。
6. 回放：每个网格点各跑一次研究回放，产生运行。网格点已经用过、源码或输入对不上，都会被拒绝；改网格、改源码或改意图，都要重新登记。
7. 审计与资格：运行环境里的独立审计器只对账、不重算，不通过就判这次运行无效。实质活动（确实有原生成交且六项活动核对相符）和可比资格都过了，才给经济反馈；零成交只诊断原因，不当比较对照。
8. 读比较证据：只和登记时声明的对照比，用配对的分块自助法给出效应、区间和 p 值（`report.compare`），再经归因拆出四分桥与 11 个切面。登记没有对照（比如根）时，它如实回答没有可比的，指向单运行报告。它不给结论。
9. 反馈与优先级：结论只在登记的适用条件内成立，写成只追加的证据包。连续两轮未实质击败对照时须写出 `Change of approach.` 换方向；再按预期效应、不确定性、机制佐证、覆盖、信息价值和成本，给接下来的具体研究动作排序。

### 写完报告和优先级不算做完，Agent 在同一回合接着跑下一个实验 [#A-1-1-3]

在路线里，Agent 写完报告、解释、推荐、复盘或优先级，都不算这一回合做完。优先级记进账本后，它在同一回合里接着做下一个实验：发布候选、预检、独立审查、登记、回放。只有三种情况会结束回合：碰到要你授权的事，路线该换了，或者你本人打断。

报告和优先级是循环里的一步，不是交付物。停在这里等你说「继续」，等于每一步都要你批准，研究就断成一段一段。回合之间不停靠宿主的目标，Agent 进入路线前自己设（<Ref id="E.4.1.3" />）；回合内不停，是 Agent 在每一步都要守住的部分。

### Agent 决定的 [#A-2-2]

Agent 读研究状态，产出源码、登记和判断；代码只给绩效指标和计数，不下结论。

<a id="A-2-2-1" />

**路线里的研究动作由 Agent 自定；仓位和风险上限是它的设计变量，不是你的约束**

在你选定的路线里，Agent 自己提假设、选父版本和比较对照、排研究优先级，不逐项请你批准。仓位、单笔风险和名义上限也由它定：规则写在策略源码里，下单数量由引擎按账户状态算出。仓位这几项是设计变量，由 [AGENTS.md](https://github.com/qOeOp/trade/blob/main/AGENTS.md) 写明；其余由 skill 规定，并用评测用例检查 Agent 是否照做。

这些都是研究设计的一部分，Agent 需要能自由调整才能找到更好的版本。把它们当成你的约束，等于凭空给研究加了限制，也会让人误以为改它们要你点头。

1. 父版本可以是谱系里任一完整候选，亏损或不显著的照样能往下派生。
2. 对照必须有经济证据资格，和父版本分开声明，两者的理由都写进登记。
3. 优先级按预期效应、不确定性、机制佐证、覆盖、信息价值和成本排具体动作；代码不给优先级。
4. 仓位规则写在源码里，不另设一个名义上限去模仿保证金；资金使用率从报告里读。
5. 改这些设计变量不需要授权，也不能在推荐或反馈里说成是你的约束。

### 用户决定的 [#A-2-3]

你的决定在产品之外做出；账本只记你给的两个研究目标（照你的话写入），不记其余这类状态；skill 规定 Agent 遇到这些事要停下来等你。

<a id="A-2-3-3" />

**动真钱、毁记录、改合格标准或动宿主的事，Agent 一律停下等你授权**

哪些事要你明确授权，以 [AGENTS.md](https://github.com/qOeOp/trade/blob/main/AGENTS.md#needs-the-users-explicit-authority) 为准：改字体；真实下单（Live 由你保存凭据、由你启动，Agent 只写 Live 代码；Paper 只用 Binance 公开数据，不需要授权；研究从不用凭据）；破坏性写入；新建或切换在用的账本或市场目录；放宽或收紧拒绝与审计检查，或改你的两个研究目标；结束宿主进程或改宿主配置；读研究数据密钥以外的凭据；新增存储字段（逐个）；打版本 tag 发布。遇到这些事，Agent 停下来向你说明，等你决定，不自己做，也不绕过去。

这些事要么动真钱，要么会毁掉已有记录，要么会改变「什么算合格」的标准，要么会动到你机器上不归研究管的东西。尤其是检查：Agent 为了让自己的结果过关去改检查，就等于自己给自己打分。被检查挡住时，正确做法是修源码或代码，发布新候选或新运行环境，再重新登记，而不是改检查。不在这份清单上的事（包括仓位这类设计变量）不需要授权。

**规则的验证与删减**

审阅、新增或修改规则时，先说明它保护的具体风险，再用与职责匹配的证据验证作用：执行与身份边界看原生探针、报告、账本审计和隔离测试；出处核实、授权与解释看来源原件、实际工具调用、会话行为和独立检查；工作流程的改进看错误、重复操作及后续决定是否真的改变。账本审计和案例重放不是唯一的验证方式，评测评分通过也不能替代实际行为核对。

未触发或证据不足，记为未验证，不据此删除。确认没有独立作用、已有其他机制充分覆盖，或只增加无用手续的，沿用 product-doctor 的既有删减检验提出删除或合并；拒绝、审计和授权边界的变更仍遵守现有用户授权要求。不新增逐条规则证明表，不把所有 skill 要求搬成代码检查，也不批量删除尚未验证的规则。
