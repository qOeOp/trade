# Market data and universe

Contract specifications, last and mark bars, inferred bid/ask quotes, the complete source aggTrades, open interest and long/short ratios, funding, monthly universe membership, and the Binance and Bybit liquidations recorded through 2026-11-04 with the intervals they were recorded belong to the market database. Each table is stored as plain Parquet files in the <Ref id="table:market_directory">market directory</Ref>; the research ledger stays in Dolt.

[Database overview](/en/docs/design-ledger/)

### 市场目录 [#def-table-market_directory]

金融数据放在普通 Parquet 文件里，路径说明它装的是什么；没有清单，文件里有什么，市场里就有什么。同样的代码和交易所归档导出同样的数据，Git 里的代码就是文件的来历。

```
<市场目录>/
  <表>/<YYYY-MM>.parquet            bar、funding、universe_month、liquidation_watch：一个月，全部合约
  <表>/<YYYY-MM>/<合约>.parquet     agg_trade、quote、metrics、binance_force_order、bybit_all_liquidation：一个月，一个合约
  instrument.parquet               合约条款，追加
  lock                             导入锁文件
```

**写入**

- 文件按表的主键排序、主键严格递增，zstd 3 级压缩，写入参数固定在代码里，同样的行写出同样的字节；读写都用 pyarrow。有哪些表、各表的列在代码的 <Ref id="implementation:impl-market-files-py-TABLES" /> 里
- 价量比例与规则是代码常量：`series.PRICE_SCALE`、`series.VOLUME_SCALE`、`universe.RULE`、`quotes.RULE`、`aggtrades.CODEC`。改规则时删掉受影响的派生文件重导，同一张表里不混两种
- **W.1.3.2**　<Ref id="market.write_file" /> 写临时文件 `.<随机>.tmp` 并 `fsync`（macOS 用 `F_FULLFSYNC`），<Ref id="market.place" /> 按固定次序改名到位、`fsync` 所在目录，最新截至日由它推出的文件（bar）最后放：中途崩溃只会少推进，不会让截至日指向不完整的数据
- **W.1.3.2**　已结束月份的 agg_trade、quote 文件不再写。进行中的月份重写：K 线与资金费已有的日子须与来源重读逐行相同，否则 MONTH_EXISTS；名单须与已存行相同，否则 UNIVERSE_CHANGED；metrics 已存的行原样留下
- **J.3.2.2**　一次只有一个导入：导入全程持有 `lock` 的 fcntl 文件锁，第二个导入拒绝 CONCURRENT_IMPORT。fcntl 锁只在共用一个内核的进程之间互斥：所有写者（market-import 与任何市场写命令）都在这个 compose 项目的容器里跑，共用 Docker 虚拟机的内核；锁管不到的写者由 place 核对目标的 inode 与修改时间拦下（同一拒绝码）

**市场提交**　它包含的最后一天 D：`%Y%m%d` 加 24 个 0，如 `20261103000000000000000000000000`，仍是账本 `market_commit` 的 32 位形状（否则 MARKET_COMMIT_INVALID）。按提交读，读到的是：

| 表 | 读到的行 |
|---|---|
| bar、funding、quote、agg_trade、metrics、爆仓两张表、liquidation_watch | 时间列在 D 当天及以前 |
| universe_month | 月份不晚于 D 次日所在的月：一个月的名单只取决于它之前的日子，所以月末这一天读得到下个月的名单 |
| instrument | observed_at 在 D 次日结束之前：一天的数据次日导入，条款同时观测 |

main 与 head 指最新的截至日：bar、metrics（在最新月份或它前一个月有文件的合约）各自最后完整的一天里较早的那天，没有行的表不算；没有 K 线就没有最新的截至日。爆仓两张表和 liquidation_watch 不参与：它们到录制结束为止，覆盖范围由 liquidation_watch 说明。比它晚的日期、其余引用都是 UNKNOWN_REF。登记、路线和 paper 运行记下的 `market_commit` 都是它。回填或晚到的归档可能改动一个截至日的内容，这时复跑导出的指纹对不上，由 REPRODUCTION_MISMATCH 报出。这一天是月末而下个月还没有名单时，退到它的前一天：月末这个提交等下个月的名单写好才可读，它读到的成员因此不会变。

**账本里早期的市场提交**　<Ref id="implementation:impl-market-files-py-LEGACY" /> 按它们当时持有的最后一天读：

| 市场提交 | 截至日 |
|---|---|
| `l1kfbo4b2of54ijpjnpn02ijdm175aqd`、`53tgna1pa02hb1t9v6r3h6pqh8d2e1s1` | 2026-10-18 |
| `gc305h705ocn5fm3lcjjerln283gek2t`、`6ho8evfcea6p4680qbkeo3mdhaqjscp5`、`1kcbv73ptu3l3clg37g0f0k77c370kk8`、`dbnggsrnquf09evsncorvngiuan1br6a`、`pn5bee9mvj18qj1boc5v9b5faotu4ehb` | 2026-10-25 |

在这些提交上导出，不保证等于当时的导出：那一天以前的数据后来可能补全过。

**没有副本**　市场目录只有本机一份，读者只读本机的文件：文件缺了读为没有这些行。目录丢了，market-import 从交易所归档重算，条款按当时的 exchangeInfo 重新观测。已封存运行的记录照常能读，但钉在旧截至日的运行不能再复现和比较（NO_TERMS），基线要重跑；爆仓三张表没有来源，不能恢复（docs/plans/market-drop-r2.zh.md）。

**键与约束**

- 主键　`symbol`, `ts`, `agg_trade_id`；读取按 `ts, agg_trade_id` 排序，同毫秒状态不合并。
- 行规则　`bid > 0 AND ask > bid`；<Ref id="market.write_file" /> 写入时核对。

### `agg_trade` [#def-table-agg_trade]

### `metrics` [#def-table-metrics]

- 放不进 DECIMAL(38,16) 的值整日拒绝 SCALE_LOSS，不舍入。

**职责与来源**　已存的行原样留下，每次只加新的日子；缺的日子由覆盖读取报为 `missing_days`，每日读数是导入的返回值，不存。归档的主动买卖量比是成交的合计（已导入成交的合约可从 <Ref id="table:agg_trade" /> 精确算出），持仓价值是持仓量乘交易所的价格快照，两者都不存。

**写入方**　命令行 `market import-metrics --month <YYYY-MM> [--symbols <合约> ...]` → <Ref id="implementation:impl-market-metrics-py-import_month" />。持同一导入锁，写入后同样自动发布；每个合约月可以分几次导，每次只追加还没有的日子。

**读取方**　`market coverage` 的 `coverage[].metrics`；回放入口给了 `--metrics` 时由 <Ref id="market.metrics_rows" /> 导出，按 `create_time + 10 分钟` 送给策略。

**关联与边界**　`symbol` 在应用读取时与 <Ref id="table:instrument" /> 条款、<Ref id="table:universe_month" /> 成员关联，没有外键。字段审阅与决定见 docs/plans/binance-open-interest-input.zh.md。

### `liquidation_watch` [#def-table-liquidation_watch]

保存记录服务当时确实在接收的时段：一段时间没有爆仓行，是市场平静还是没在记，靠它分清。事后无法重现。

<TypeTable type={{ "venue": { type: "ENUM('binance','bybit')", description: "交易所", required: true }, "symbol": { type: "VARCHAR(40)", description: "Binance 为空串，表示整家（一条连接收全部合约）；Bybit 是合约名，从确认它订阅的那一帧起", required: true }, "start_time": { type: "BIGINT", description: "时段起点，本机墙上时钟 UTC 毫秒", required: true }, "end_time": { type: "BIGINT", description: "时段终点，不含", required: true } }} />

- 主键　`venue`, `symbol`, `start_time`；时间列是 start_time。
- 行规则　`venue IN ('binance','bybit') AND end_time > start_time`

**读取方**　`market coverage` 的 `coverage[].liquidations` 里各项的 uncovered_intervals_ms（区间里没有时段覆盖的部分）。
