# Market data and universe

Contract specifications, last and mark bars, inferred bid/ask quotes, the complete source aggTrades, open interest and long/short ratios, funding and monthly universe membership belong to the market database. Each table is stored as immutable, content-addressed Parquet files in the market directory, and each market version is listed by one <Ref id="table:market_version">version file</Ref>; the research ledger stays in Dolt.

[Database overview](/en/docs/design-ledger/)

### 版本文件 [#def-table-market_version]

市场的一个版本：一份 JSON，列出该版本的全部数据文件和导入回执，是一份完整快照：读一个版本的数据只需它自己的版本文件；只有 <Ref id="market.imports" /> 找一份回执由哪个版本写入时，沿 parent 链往回读版本文件。市场提交就是版本文件的版本号；登记、路线和 paper 运行记下的 `market_commit` 都是它。

```
<市场目录>/
  files/<sha256>.parquet   数据文件：不可变，按内容命名
  files/<sha256>.json      导入回执：不可变，按内容命名
  versions/<版本号>.json    版本文件，每个版本一份
  head                     最新版本号
  lock                     导入锁文件
```

**键与约束**

- 版本号　版本文件规范 JSON（键排序、`separators=(",", ":")`、UTF-8、不转义非 ASCII）的 SHA-256，按 base32hex（字母表 `0-9a-v`）从高位取前 32 个字符（160 位）
- 只追加　子版本原样列出父版本的全部 `files` 与 `receipts` 条目，`market_schema` 与父版本相同（`market upgrade` 的加一除外）
- 不重叠　同一版本里同表同合约的条目区间两两不相交，同表各文件的主键互不重复：写入时新条目与父版本的条目核对（ENTRY_OVERLAP），<Ref id="market.review" /> 逐版本独立复核
- 数据文件　按表的主键排序、主键严格递增，zstd 压缩，写入参数固定在代码里；读写都用 pyarrow

**存储保证**

- **W.1.3.2**　一次导入先让数据文件和回执落盘，再让版本文件落盘，最后让 `head` 的原子替换落盘：每个文件都写临时文件、`fsync`、改名，再对所在目录（`files/`、`versions/`、放 `head` 的根目录）`fsync`；macOS 上用 `F_FULLFSYNC`（只调 `os.fsync` 不写到盘上）。中途崩溃只留下没被引用的文件，`head` 不变
- **W.1.3.2**　<Ref id="market.read_table" /> 按市场提交读：只读该版本列出的文件，对实际读进来的字节算 SHA-256，对不上即 HASH_MISMATCH；任何时候都重现某次回放读到的内容
- **W.1.3.2**　导入开始时 `head` 的版本文件和它列出的每个文件都要在市场目录里，否则 HEAD_INCOMPLETE
- **J.3.2.2**　一次只有一个导入：导入全程持有 `lock` 的 fcntl 文件锁，第二个导入拒绝 CONCURRENT_IMPORT。fcntl 锁只在共用一个内核的进程之间互斥：市场目录在 Docker 卷上，所有写者（market-import 与任何市场写命令）都在这个 compose 项目的容器里跑，共用 Docker 虚拟机的内核；宿主命令行从不直接写市场目录
- **W.1.3.2**　<Ref id="market.review" /> 由任何读者对任何版本复核：文件都在且哈希对得上、行规则与 <Ref id="market.data_tests" />、同一版本里同表同合约的条目不相交且同表主键不重复、沿父版本链只追加、账本引用的市场提交都在 `head` 的链上（`legacy-20261025` 那两个转换版本除外：它们沿 parent 到 `l1kfbo4…` 全在 CONVERTED 里，其余各项照样核对）、公开副本的 `head` 在本地链上（否则 HISTORY_REWRITTEN）、CONVERTED 里的 8 个版本对得上 `CONVERTED`；只报发现，不改任何东西

**CONVERTED 里的 8 个版本**　账本钉住的 8 个市场提交，版本号是账本钉住的 Dolt 提交号，不由内容算出：`l1kfbo4b2of54ijpjnpn02ijdm175aqd`、`53tgna1pa02hb1t9v6r3h6pqh8d2e1s1`、`gc305h705ocn5fm3lcjjerln283gek2t`、`6ho8evfcea6p4680qbkeo3mdhaqjscp5`、`1kcbv73ptu3l3clg37g0f0k77c370kk8`、`dbnggsrnquf09evsncorvngiuan1br6a`、`pn5bee9mvj18qj1boc5v9b5faotu4ehb`、`iv711v5dpnv5qr62i5ejk3udk431f5k6`。`market/versions.py` 的 `CONVERTED` 写死 \{版本号: 版本文件的 SHA-256\}，<Ref id="market.load_version" /> 读这 8 个版本时核对版本文件的 SHA-256，其余版本核对版本号等于内容算出的号，对不上即 HASH_MISMATCH。`l1kfbo4…` 没有父版本，`53tgna1…`（`legacy-20261025` 的头，加了 BTCUSDT 报价）以它为父版本；main 上的 6 个按提交先后串成父子链。这 8 份版本文件、`CONVERTED_HEAD`（转换来的主线最新版本）及其祖先，和它们列出的全部数据文件都在公开副本里：它们按转换时的切分写成，导入写不出同样的文件。

**公开副本**　Cloudflare R2 桶，公开可读，市场档案的 `origin` 是它的公开地址。它存全部版本文件和回执，instrument、universe_month、bar、funding 的数据文件：它们是导入时观测到的（条款、成员，K 线和资金费里有当时从 REST 取的行），过后拿不回来。metrics、agg_trade、quote 的文件不上传，转换来的版本列出的也不传：回执记着每个归档的 SHA-256，按回执重新导入，写出的文件哈希须等于条目的，回执的 writer 指出写它的代码。<Ref id="market.publish" /> 先上传新版本缺的数据文件和回执，然后上传版本文件，都只建不覆盖（`If-None-Match: *`）；最后以条件写替换 `head`（`If-Match` 发布开始时读到的公开副本 `head` 的 ETag），条件不成立即 PUBLISH_DIVERGED，两个发布者因此不会互相覆盖。写入密钥只在写者手里，由档案的 `upload` 指明。有自己可写市场目录的读者（例如没有写者目录的机器上的宿主命令行）缺的文件从 `origin` 取进自己的市场目录（只取上面上传的那些文件），按读到的字节核对 SHA-256，两处都没有即 MARKET_UNREACHABLE；市场目录只读挂载的读者（compose 里的 ide、paper）从不取，缺文件即 MARKET_UNREACHABLE。

### `market_schema` [#def-table-market_schema]

市场自述：表结构版本、整数价量比例、当前产出范围的规则版本；是版本文件里的一个对象，每个版本一份

- 父子版本相同；只有 `market upgrade` 写的版本把 `version` 加一（加一张表），这个版本不带数据文件，只带一份 `market-upgrade` 回执
- 表不在某版本的 `version` 里时，<Ref id="market.read_table" /> 读为空，导出跳过它；导入这张表拒绝 SCHEMA_MISMATCH，先跑 `market upgrade`

**存储保证**

- **W.1.3.2**　随每个版本写在版本文件里，按市场提交读出该版本使用的规则版本与比例
- **W.1.3.2**　<Ref id="market.review" /> 沿父版本链核对它不变（升级的加一除外）

### `quote` [#def-table-quote]

保存声明规则从 aggTrades 推算的完整买卖价状态变化；来源是近似报价，不是逐档盘口或真实可成交深度。

<TypeTable type={{"symbol": {"type": "VARCHAR(40)", "description": "公开合约名；与同提交条款及生命周期片段对应", "required": true}, "ts": {"type": "BIGINT", "description": "产生此状态的 aggTrade transact_time，UTC 毫秒；允许同毫秒多行", "required": true}, "agg_trade_id": {"type": "BIGINT", "description": "产生此状态的成交编号；区分同毫秒状态并用于来源核对，状态变化筛选后编号不必逐行连续", "required": true}, "bid": {"type": "BIGINT", "description": "推算买价 × 10^market_schema.price_scale；不是观测盘口", "required": true}, "ask": {"type": "BIGINT", "description": "推算卖价，采用同一定标", "required": true}}} />

**键与约束**

- 主键　`symbol`, `ts`, `agg_trade_id`；读取按 `ts, agg_trade_id` 排序，同毫秒状态不合并。
- 行规则　`bid > 0 AND ask > bid`；<Ref id="market.write_file" /> 写入时核对，<Ref id="market.review" /> 复核。
- 五列均为 NOT NULL。没有 bid_size／ask_size、档位、逐侧年龄或来源文件列；导出用合约 max_quantity 填两侧数量，不等于实际盘口深度。

**职责与来源**　只追加输入状态，不存订单、成交、仓位或账户。`quote_rule`、实际读取的每日归档 SHA-256（含用于续接的前日）和日诊断读数保存在该次导入的<Ref id="table:market_receipt">导入回执</Ref>，由 <Ref id="market.imports" /> 读取，不复制成表字段；市场提交钉住输入版本。归档 zip 在下载缓存，不因有哈希就声称原件已存入此表或完成独立备份。

**写入方**　<Ref id="cli.market_import_quotes" /> → <Ref id="market.import_quotes" />；推算与定标分别由 <Ref id="market.derive" />、<Ref id="market.scaled_rows" /> 负责。一个合约月一个文件、一个市场提交；同合约同月已存报价时拒绝，历史行不覆盖。

**读取方**　<Ref id="market.quote_rows" /> 经 <Ref id="market.read_table" /> 按市场提交流式读取，经 <Ref id="market.write_quotes" /> 写为原生 QuoteTick，<Ref id="market.export_episode" /> 把 `counts.quote`、`quote_size` 写入导出回执；报价环境由 <Ref id="engine.execution_account" /> 选择。表结构版本里还没有本表的市场提交读为空流，默认 K 线导出仍可用；报价环境缺有效报价仍按现有检查拒绝。

**关联与边界**　`symbol` 在应用读取时与 instrument 条款、universe_month 成员及生命周期片段关联，没有外键。推算规则和逐合约／时段／用途的证据边界沿用 <Ref id="W.1.2.1" />，原生强平环境沿用 <Ref id="W.4.2.1" />。

### `agg_trade` [#def-table-agg_trade]

保存币安 USD-M 的完整源 aggTrades：官方七个字段加归档里的 symbol，含没有改变推算报价的成交。它是源交易原件，不参与 K 线、报价读取或周期派生；入口请求成交（`--trade-ticks`）时由 <Ref id="market.trade_rows" /> 读出、<Ref id="market.write_trades" /> 写成 TradeTick，只作策略信号输入，不驱动撮合。

<TypeTable type={{ "symbol": { type: "VARCHAR(40)", description: "交易所公开合约名（归档文件名所带）", required: true }, "transact_time": { type: "BIGINT", description: "成交时刻，UTC 毫秒；同毫秒允许多行", required: true }, "agg_trade_id": { type: "BIGINT", description: "交易所聚合成交编号；一个合约内逐日、跨日连续，缺失或重复即拒绝", required: true }, "price": { type: "BIGINT", description: "成交价 × 1e8 的有符号整数，编码 binance-aggtrades-int64-scale8-v1，与 market_schema 的 bar 比例无关", required: true }, "quantity": { type: "BIGINT", description: "成交量 × 1e8，同一编码", required: true }, "first_trade_id": { type: "BIGINT", description: "聚合内第一笔逐笔成交编号", required: true }, "last_trade_id": { type: "BIGINT", description: "聚合内最后一笔逐笔成交编号", required: true }, "is_buyer_maker": { type: "BOOLEAN", description: "买方是否为挂单方；推算报价规则据此分买卖侧", required: true } }} />

**键与约束**

- 主键　`symbol`, `transact_time`, `agg_trade_id`；没有二级索引，没有派生列。
- 八列均为 NOT NULL。价格与数量放不进这个编码（精度损失或整数溢出）即整月拒绝 SCALE_LOSS、不生成版本，不四舍五入、不换编码。aggTrades 本身不带 RPI 等成交类型标记，表也不另加这类字段。

**职责与来源**　只追加的源交易原件，一个合约月一个文件、一个市场提交。编码身份、每日归档的 SHA-256、日读数（行数、首末编号与时刻、最大成交间隔）记在<Ref id="table:market_receipt">导入回执</Ref>里，由 <Ref id="market.imports" /> 读取，不复制成表字段。前一日归档只做续接核对（编号接上、同样的字段与编码校验），不插入；编号缺失、重复或跨日不连续即 SEQUENCE_GAP，不找替代来源、不修补；唯一例外是币安把同一编号重复给了另一笔更晚的成交，两行主键不同，都导入。

**写入方**　命令行 `market import-trades --month <YYYY-MM> --symbols <合约> ...`（一个月的一个或几个合约，各合约的文件各在一个工作进程里写，写完的合约月在锁内依次提交各自的版本；一个合约被拒不撤销其他合约的版本）→ <Ref id="implementation:impl-market-aggtrades-py-import_month" />；表由 `market upgrade` 加进表结构版本。持同一导入锁，提交前跑同样的 <Ref id="market.data_tests" />，写入后同样自动发布；同合约月已存行即 MONTH_EXISTS，当月只到最后一个已收盘 UTC 日，之后不能续写。

**读取方**　目前没有产品读取方：K 线与报价导出、回放都不读它；推算报价 <Ref id="table:quote" /> 另从归档推算，不由本表派生。

**关联与边界**　`symbol` 在应用读取时与 <Ref id="table:instrument" /> 条款、<Ref id="table:universe_month" /> 成员关联，没有外键。字段与编码的决定见第一阶段记录 docs/plans/aggtrades-source-import.zh.md。

### `metrics` [#def-table-metrics]

保存币安 USD-M 每日 `metrics` 归档里的持仓量和三个多空比，每个合约每 5 分钟一行，列名照抄归档。一行描述的是 create_time + 5 分钟那一刻（持仓量与 REST 在该时刻的值逐位一致，2026-10-31 实测），导出时才定可见时刻。

<TypeTable type={{ "symbol": { type: "VARCHAR(40)", description: "交易所公开合约名（归档所带）", required: true }, "create_time": { type: "BIGINT", description: "归档的时间戳，UTC 毫秒，在 5 分钟格点上；不是可见时刻", required: true }, "sum_open_interest": { type: "DECIMAL(38,16)", description: "持仓量，基础资产数量，精确十进制", required: true }, "count_toptrader_long_short_ratio": { type: "DECIMAL(38,16)", description: "头部交易者账户多空比；归档为空时为 NULL" }, "sum_toptrader_long_short_ratio": { type: "DECIMAL(38,16)", description: "头部交易者持仓多空比；归档为空时为 NULL" }, "count_long_short_ratio": { type: "DECIMAL(38,16)", description: "全市场账户多空比；归档为空时为 NULL" } }} />

**键与约束**

- 主键　`symbol`, `create_time`；create_time 必须在 5 分钟格点上，各值不为负。
- 放不进 DECIMAL(38,16) 的值整日拒绝 SCALE_LOSS，不舍入。

**职责与来源**　只追加。每日归档的 SHA-256、每日读数（行数、合并的重复行、各比值的空行数）和没有归档的日子记在<Ref id="table:market_receipt">导入回执</Ref>里，不复制成表字段。归档的主动买卖量比是成交的合计（已导入成交的合约可从 <Ref id="table:agg_trade" /> 精确算出），持仓价值是持仓量乘交易所的价格快照，两者都不存。

**写入方**　命令行 `market import-metrics --month <YYYY-MM> [--symbols <合约> ...]` → <Ref id="implementation:impl-market-metrics-py-import_month" />；表由 `market upgrade` 加进表结构版本。持同一导入锁，提交前跑同样的 <Ref id="market.data_tests" />，写入后同样自动发布；每个合约月可以分几次导，每次只追加还没有的日子。

**读取方**　`market coverage` 的 `coverage[].metrics`；回放入口给了 `--metrics` 时由 <Ref id="market.metrics_rows" /> 导出，按 `create_time + 10 分钟` 送给策略。

**关联与边界**　`symbol` 在应用读取时与 <Ref id="table:instrument" /> 条款、<Ref id="table:universe_month" /> 成员关联，没有外键。字段审阅与决定见 docs/plans/binance-open-interest-input.zh.md。
