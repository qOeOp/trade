### `assess` [#def-qualification-assess]

经济证据资格：读取时按当前判据，对单运行报告里的活动事实、审计结论、执行封存与源码审查算出，附检查身份；不读原生报告、不写账本

```python
def assess(conn: LedgerConnection, run: Mapping) -> dict
```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "只读账本连接（ledger.connect），可指向 AS OF 某一提交" }, "run": { type: "Mapping", description: "run ⨝ trial 行：run_id、trial_id、status（存储审计结论）、source_sha256（候选源码内容哈希）、image_digest（运行环境身份）" } }} />

**返回**　dict：\{economic_evidence_available: bool, reasons: list[str], activity: \{orders, fills, positions, account_rows\}, stored_audit_status, source_check（source_reviews 结果）, execution_capture: \{status, purpose, failed_stages, failures（按异常类型、阶段、合约与消息合并，带次数与拒绝码）, original_missing\}, checker（check_identity 结果）, applicability, limitations: list[str]\}。纯视图，不改写 run.status 与审计结果

**期望行为**

1. 读运行行、单运行报告的活动一节、执行封存在位情况与绑定的源码审查。
2. 按当前判据逐项给出实质活动、可比资格、执行捕获、源码审查四项结论与原因。
3. 新判据要用到封存时没记下的事实时，判为待复核，由调用方经 replay.reproduce 重放后再核。
4. 用于重试判定时只看封存时已定的事实：封存结果，以及登记引用的预检审查在该运行入账时的状态；入账之后才写的审查不能把一次通过的尝试变成可重试。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_RUN` | run_id 在账本中没有封存的运行行（ledger.load_run 透传） |
| `LEDGER_CORRUPT` | 源码审查证据或执行捕获文件的存储内容哈希与重算不符（source_reviews、read_capture 透传） |
| `EXECUTION_IDENTITY` | 执行捕获的试验、源码哈希、运行环境身份或用途与本运行不符（read_capture 透传） |

### `check_identity` [#def-qualification-check_identity]

资格检查身份：检查名、指标计算版本与检查器源码哈希，随每份资格结论输出

```python
def check_identity() -> dict
```

**返回**　dict：\{check: 检查名（判据版本常量，如 economic_evidence_v1）, metrics_revision: 指标计算版本, checker_source_sha256: 本模块字节的 sha256\}

**期望行为**

1. 检查名取模块常量，判据变更时递增版本名；不读账本。
2. 经 ledger.metrics_revision 取指标计算版本。
3. 对本模块字节算 sha256 作检查器源码哈希。
4. 三者组成检查身份，assess、require 的拒绝体与探索目录视图都附带它；同一运行在不同时刻的不同资格由检查身份解释，不由改写解释。

### `mask` [#def-qualification-mask]

绩效指标流出前的唯一遮蔽点：不可用运行的绩效指标整体置空并附资格原因

```python
def mask(output: dict, value: dict) -> dict
```

<TypeTable type={{ "output": { type: "dict", description: "任一读口组装的运行报告字典（运行报告、候选清单条目、分析表、探索目录报告），含绩效指标键、cost_basis 与活动计数" }, "value": { type: "dict", description: "assess（或探索目录按同一判据算出）的资格字典" } }} />

**返回**　dict：同一报告字典，附 availability = value；不可用时全部绩效指标键与 cost_basis 为 None，活动计数、诊断、审计边界与检查身份保留

**期望行为**

1. 把资格字典整体挂到 output.availability，使每份报告都带原因与检查身份。
2. economic_evidence_available 为假时把全部绩效指标键置 None：期末权益、年化、最大回撤、收益回撤比、计划已平/赢/未平与胜率、闭仓与持仓计数、已实现盈亏、手续费、资金费、价格盈亏、未实现盈亏、按年拆分、资金使用率；cost_basis 置 None。
3. 活动计数、原生行数、审计 scope 与 coverage_limits、执行捕获状态、源码审查结论保留为诊断，供 Agent 归因。
4. 可用时不改任何绩效指标；所有读口都经本函数，不另设遮蔽。
5. 活动事实只保留 \{passed, code, 计数\}；终值权益、复利权益、账户行等任何金额都不从不可用的运行里漏出。

### `native_reasons` [#def-qualification-native_reasons]

资格的原生事实：读封存结果里封存时记下的资格事实，逐项给出是否通过与原因码；不读原生报告

```python
def native_reasons(sealed: dict) -> list[str]
```

<TypeTable type={{ "sealed": { type: "dict", description: "运行的封存结果（run_sealed 行）" } }} />

**返回**　list[str]：不可用原因；空列表表示实质活动成立且匹配记录全部对账。只描述事实，不归因

**期望行为**

1. 读最新封存结果的资格事实一节与执行封存的阶段、退出码、异常回执。
2. 逐项给出是否通过、原因码与计数；新判据需要封存时没记下的事实时，该项标为未评估并写进局限，不静默通过也不静默失格。

### `require` [#def-qualification-require]

比较、对照登记与描述统计读口之前的硬门：资格不可用即拒绝并返回原因

```python
def require(conn: LedgerConnection, run: Mapping) -> dict
```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "只读账本连接" }, "run": { type: "Mapping", description: "run ⨝ trial 行，同 assess" } }} />

**返回**　dict：资格可用时返回 assess 的完整资格字典，供调用方随检验结果或登记绑定一并写出；不可用时抛拒绝

**期望行为**

1. 调用 assess 得到当前资格视图。
2. economic_evidence_available 为假即以 ECONOMIC_EVIDENCE_UNAVAILABLE 拒绝，拒绝体携带 run_id、全部 reasons 与整份资格字典，write_status 为 not_written；调用方不得给出改善、区间与 p。
3. 零成交且账户未变的运行同样拒绝，不因未亏损而优于亏损对照。
4. 可用时原样返回资格字典，不做任何写入。

| 拒绝码 | 条件 |
|---|---|
| `ECONOMIC_EVIDENCE_UNAVAILABLE` | assess 判定不可用：零成交、缺匹配记录、原生不对账、存储审计未通过、执行捕获记失败或未完成、绑定源码审查记失败之一 |
| `UNKNOWN_RUN` | 透传 assess |
| `LEDGER_CORRUPT` | 透传 assess |
| `EXECUTION_IDENTITY` | 透传 assess |

### `source_reviews` [#def-qualification-source_reviews]

只认源码哈希与镜像摘要都匹配本运行的独立审查记录；内容哈希不符拒绝；记录身份按其写入时的账本提交核对

```python
def source_reviews(conn: LedgerConnection, run: Mapping) -> dict
```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "只读账本连接；核历史记录时经 ledger.read_as_of 读其写入提交" }, "run": { type: "Mapping", description: "run ⨝ trial 行：run_id、source_sha256、image_digest" } }} />

**返回**　dict：\{status: passed | failed | unreviewed, reviews: [\{bundle_id, sha256, verdict, reviewer, ledger_commit\}], ignored: [\{bundle_id, reason\}], scope: 「Agent 因果职责；审计通过不等于源码有效」\}

**期望行为**

1. 只读产品命名空间 source-review-* 下路径为 source-review.json 的行及其 evidence_bundle 归属（两次读都是主键区间）；重算内容 sha256，与存储哈希不符拒绝 LEDGER_CORRUPT。命名空间之外的同名文件从来不算审查，也不再列为 ignored。
2. 解析 source-review-v1 记录：source_sha256 等于本运行候选源码哈希且 image_digest 等于本运行镜像摘要才计入；不符的记录属于别的候选或运行环境，跳过。
3. 每条记录的写入提交取自一次提交日志读取（record_review 的提交信息是 record_review:\<op_id>），并经 AS OF 核对；不是 record_review 写的审查包退回按历史差异查找。对计入的记录经 ledger.read_as_of 在其写入提交处读当时的试验行，核记录身份与当时试验一致；不一致或无法解析、缺字段的记录列入 ignored 并写原因，不按文件名或后来的探针推断。
4. 汇总：任一 failed 即 failed；否则任一 passed 即 passed；否则 unreviewed。
5. 不写账本；结论作为具名 Agent 证据返回，不替代也不被账户审计替代。

| 拒绝码 | 条件 |
|---|---|
| `LEDGER_CORRUPT` | 证据行存储的 sha256 与重算的内容哈希不符 |
