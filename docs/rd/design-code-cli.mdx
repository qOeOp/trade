### `candidate_export` [#def-cli-candidate_export]

把一个候选的源码导出到临时工作目录，同时写入工作目录说明 AGENTS.md 与文件头模板 strategy-header.md

```python
def candidate_export(
    ledger: path,
    candidate: str,
    output: path,
    at: str | None,
) -> {candidate
```

<TypeTable type={{ "ledger": { type: "path", description: "账本档案路径；命令以读账号打开连接" }, "candidate": { type: "str", description: "引用名 strategy_id@revision" }, "output": { type: "path", description: "尚不存在的文件路径，须在平台临时根之下" }, "at": { type: "str | None", description: "账本版本；缺省取头提交" } }} />

**返回**　\{candidate, source_sha256, path, bytes\}

**期望行为**

1. 核对 output 不存在且位于临时根之下
2. 给出 at 时经 ledger.read_as_of 取只读版本连接；ledger.read_candidate 取字节并核对存储哈希
3. 原样写出字节（不改编码、不加头尾），写后重读文件哈希须等于 source_sha256
4. 返回路径与哈希；该副本是派生新候选或无产品工作树重放的起点
5. 在同一目录写 AGENTS.md：由 research-round 的 templates/workdir-agents.md 填入候选引用与下一步命令；Agent 进入该目录工作时读到它。
6. 在同一目录写 strategy-header.md：research-round 的文件头模板原文。

| 拒绝码 | 条件 |
|---|---|
| `CANDIDATE_NOT_FOUND` | strategy_id@revision 在该版本不存在 |
| `PATH_EXISTS` | 目标文件已存在 |
| `NOT_TEMPORARY_PATH` | 目标不在平台临时根之下 |
| `LEDGER_CORRUPT` | 存储字节或写出文件的哈希不符 |

**使用**　<Ref id="ledger.read_as_of" />、<Ref id="ledger.read_candidate" />、<Ref id="table:candidate" />

### `candidate_list` [#def-cli-candidate_list]

Agent 读候选清单的唯一命令行入口：全部候选的身份、父与改动、登记尝试及其运行状态与经济证据可用性，可按账本版本读历史

```python
def candidate_list(ledger: path, at: str | None) -> JSON
```

<TypeTable type={{ "ledger": { type: "path", description: "账本档案路径，解析为 LedgerProfile（连接位置与只读账号）" }, "at": { type: "str | None", description: "可选账本版本：提交哈希或标签；None 读当前" } }} />

**返回**　JSON：\{ledger_commit, checker: \{check, metrics_revision, source_sha256\}, candidates: [\{strategy_id, revision, source_sha256, entry_class, runtime_contract, description, parent_strategy_id, parent_revision, difference, created_at, attempts: [\{bundle, trial_id, run_id, run_status, availability\}], valid_evidence\}]\}；原样转发 report.candidates 的结果，不加分数、排序或资格标记

**期望行为**

1. 解析 ledger 为账本档案 profile；本命令不自开连接，只读连接由 report.candidates 经 ledger.read_as_of 按 at 打开；at 原样传入，不在命令层解析版本。
2. 调用 report.candidates(profile, at)，取回 \{ledger_commit, checker, candidates\}。
3. 以 JSON 一次性输出；拒绝时按 cli.main 的统一形态输出拒绝码、缺什么与写入状态（恒为未写）。
4. 全程只读；推荐理由与解释由 Agent 另以证据包追加，不在本命令写。

| 拒绝码 | 条件 |
|---|---|
| `LEDGER_REF_NOT_FOUND` | at 解析不到账本里的提交或标签（由 report.candidates 抛出，原样转发） |
| `LEDGER_SCHEMA_MISMATCH` | 所读版本的账本模式版本与当前代码不一致或账本未初始化（转发） |
| `LEDGER_CORRUPT` | 尝试引用的候选在同版本候选表中缺失，或 run 指向不存在的 trial（转发，指明首个不一致行） |

### `candidate_publish` [#def-cli-candidate_publish]

把一份单文件源码发布为候选：带研发父版本与改动说明，或不带父作为根节点

```python
def candidate_publish(
    ledger: path,
    file: path,
    strategy_id: str,
    entry_class: str,
    description: str,
    parent: str (strategy_id@revision) | None,
    difference: str | None,
    op: str | None,
) -> {candidate
```

<TypeTable type={{ "ledger": { type: "path", description: "账本连接档案路径；以写账号打开" }, "file": { type: "path", description: "单文件 UTF-8 策略源码" }, "strategy_id": { type: "str", description: "引用名中的 ID；同一 ID 下修订号递增" }, "entry_class": { type: "str", description: "唯一顶层入口类名" }, "description": { type: "str", description: "这一版本的说明：规则、来源声明与非声明" }, "parent": { type: "str (strategy_id@revision) | None", description: "研发父版本；根节点不填" }, "difference": { type: "str | None", description: "相对父版本的改动说明；与 parent 同有同无" }, "op": { type: "str | None", description: "幂等操作标识；缺省由载荷派生" } }} />

**返回**　\{candidate: strategy_id@revision, source_sha256, parent, runtime_contract, ledger_commit\}

**期望行为**

1. 读 file 的全部字节（普通文件，不跟随符号链接），读不到即拒绝。
2. 把字节与参数原样交给 ledger.publish_candidate；它的全部拒绝原样透传，命令行不另做判断。
3. 返回引用名、内容哈希、父、运行契约与账本提交；此后任何执行装载的字节都必须等于该哈希。
4. 不执行源码、不核对文件头、不读任何运行成绩。

| 拒绝码 | 条件 |
|---|---|
| `SOURCE_UNREADABLE` | file 不是普通文件、是符号链接或读取失败 |
| `（ledger.publish_candidate 的拒绝）` | 形态、引用名、备注、谱系、重复字节与并发写入的拒绝原样透传 |

<TypeTable type={{ "ledger": { type: "path", description: "账本连接档案路径；以读账号打开" }, "candidate": { type: "str (strategy_id@revision)", description: "候选引用" }, "at": { type: "str | None", description: "账本提交或标签；缺省读最新提交" } }} />


<TypeTable type={{ "conn": { type: "LedgerConnection", description: "cli.main 以写账号打开的连接" }, "bundle": { type: "str", description: "证据包名；不得落入产品封存命名空间" }, "files": { type: "list[Path]", description: "原件文件或目录，可为空（只有文本时）" }, "note": { type: "str | None", description: "自由文本，作为包内 note.md 入包" }, "op": { type: "str | None", description: "幂等操作 ID；缺省由 ledger.add_bundle 从包名与逐文件哈希派生" } }} />

| 拒绝码 | 条件 |
|---|---|
| `EMPTY_EVIDENCE` | 既没有文件也没有文本 |

### `evidence_export` [#def-cli-evidence_export]

核验内容哈希后把证据包文件导出到临时目录

```python
def evidence_export(
    conn: LedgerConnection,
    bundle: str,
    output: Path,
    at: str | None,
) -> {bundle
```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "cli.main 以读账号打开的连接" }, "bundle": { type: "str", description: "证据包名（含产品封存包）" }, "output": { type: "Path", description: "尚不存在的目录，须在平台临时根之下" }, "at": { type: "str | None", description: "账本版本（提交、标签或 branch）；缺省为固定研究 branch 的当前提交" } }} />

**返回**　\{bundle, at_commit, path, files: [\{name, sha256, bytes\}]\}

**期望行为**

1. 经 ledger.temporary_path 核对 output 不存在且位于临时根之下，否则 PATH_EXISTS 或 NOT_TEMPORARY_PATH。
2. at 非空时经 ledger.read_as_of 钉到该版本，解析不到即 VERSION_NOT_FOUND。
3. 调用 ledger.load_bundle 读包与逐文件字节并重算哈希；包不存在 BUNDLE_NOT_FOUND，哈希不符 LEDGER_CORRUPT，两种情况都不写出任何文件。
4. 按包内相对路径写入 output，返回清单与所读提交。

| 拒绝码 | 条件 |
|---|---|
| `PATH_EXISTS` | 目标目录已存在 |
| `NOT_TEMPORARY_PATH` | 目标不在平台临时根之下 |
| `VERSION_NOT_FOUND` | at 解析不到提交、标签或 branch |
| `BUNDLE_NOT_FOUND` | 包名在该版本不存在 |
| `LEDGER_CORRUPT` | 文件哈希与记录不符 |

### `execution_recover` [#def-cli-execution_recover]

命令行入口：把从保留工作目录恢复的字节另标追加到原始捕获缺失的预检试验，不补证

```python
def execution_recover(
    ledger: path,
    trial_id: int,
    workdir: path,
    failure_receipt: path,
    op: str | None,
```
