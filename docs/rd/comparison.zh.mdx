### V.1.1　网格点的回放与绑定 [#V-1-1]

全部由代码强制。输入是登记证据包与被执行候选的内容哈希，输出是同一事务写下的试验行、网格点消耗行与执行开始回执，或一条拒绝；账本只追加，事务失败不留半截记录。

<Cap id="V.1.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="网格点即已发布源码，回放即绑定登记">

每个网格点是一个已发布候选（candidate）：研发父版本加登记锁定的那一处改动得到的完整单文件源码，以内容哈希（content hash）唯一标识，引用名 strategy_id@revision；父版本与改动说明须等于登记锁定的内容，否则登记即被拒绝（LINEAGE_MISMATCH，见 <Ref id="T.2.1.1" />）。研究封存回放只经入口 <Ref id="registration" /> 发起：入口读出候选，在写试验行的同一事务里调用 <Ref id="registration.bind" /> 把试验绑定到该登记的一个网格点。绑定核对候选身份、登记证据包、时序与执行身份，任一不符整笔不写、不启动容器并返回拒绝码；各项核对与拒绝码由 <Ref id="registration.bind" /> 定义。通过即在 <Ref id="table:registration_attempt" /> 记下该点被本试验消耗；一点只消耗一次，无效与中断的试验同样算消耗，再试须另登记并写 retry_of（<Ref id="H.4.2.1" />）。绑定只核身份与时序，不核经济内容。由代码强制，账本以单事务与只追加保证原子性。

### V.1.2　回放纪律 [#V-1-2]

由 skill 指导、代码兜底。research-round 的两节分别规定一次跑完登记网格与读数只从产品读口取，各配一个 eval 由独立 Agent 前向检查；代码以网格外源码拒绝、网格点一次性消耗与资格遮蔽兜底。读数侧输入是运行 run 的标识，输出是遮蔽过不可用经济读数并附原因的报告。

<Cap id="V.1.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="按登记网格一次性跑完">

登记后把锁定网格里的每个网格点各回放一次，全部跑完再读读数；不边看结果边加点、换参数或改源码。改网格、改源码或改意图都是新假设，须经 <Ref id="registration.register" /> 重新登记，新点不追加到本次网格；网格外的源码不能借用本次登记回放；已消耗的点不能再跑，同一点再试另登记并写 retry_of。由 skill <Ref id="research-round/SKILL.md#run-the-grid" /> 指导，eval <Ref id="eval:research-round/grid-runs-complete-before-reading" /> 检查。代码兜底：<Ref id="registration.bind" /> 对网格外源码返回 SOURCE_MISMATCH，对已消耗的点返回 GRID_ALREADY_ATTEMPTED；拒绝即按本规则改为新登记，不绕过。

## V.2　核可比性：比之前核对两边同一环境、同一单位、都有可比资格 [#V-2]

可比资格（comparability）核对是配对检验之前的硬门，全部由代码强制、只读不写账本。核对在两个时点用同一个函数：登记时 <Ref id="registration.validate" /> 对声明的比较对照（control）运行核一遍，比较时 <Ref id="report.compare" /> 对候选与对照两侧各核一遍。每一侧按固定顺序核：先核是通过审计的封存（seal）运行，再核运行环境（runtime image）、有效配置、输入内容身份三项与登记的执行身份一致，再核经济证据资格，最后取两侧账户日收益并核 UTC 日钟逐日一致。任一项不过即以具名拒绝码返回并指明哪一项，不进入 <Ref id="V.3.2.1">配对块自助检验</Ref>。配对单位是账户日收益，不是单笔交易。

<Steps>

<Step>

登记时：<Ref id="registration.validate" /> 对声明的对照运行调 <Ref id="registration.check_comparable" /> 与 <Ref id="qualification.require" />，不过即拒绝登记；根登记与声明暂无对照的修复派生不带对照。

</Step>

<Step>

比较入口 <Ref id="report.compare" /> 读登记证据包取声明的对照运行，并核候选运行绑定在本登记的网格上。

</Step>

<Step>

两侧各过 <Ref id="registration.check_comparable" />：封存且通过审计 → 同一运行环境摘要 → 同一有效配置 → 同一输入内容身份。

</Step>

<Step>

两侧各过 <Ref id="qualification.require" />：无实质活动或资格不可用即拒绝，只留诊断。

</Step>

<Step>

两侧各经 <Ref id="ledger.daily_returns" /> 取交易窗口内的账户日收益，核复利对账与两侧日钟逐日一致。

</Step>

<Step>

全部通过才把两条序列交给 <Ref id="report.paired" /> 出读数；任一步拒绝即返回码与冲突项，不写账本。

</Step>

</Steps>

## V.3　做配对检验：读数怎么算 [#V-3]

比较入口 <Ref id="report.compare" /> 核完可比性与两侧经济证据资格、取得逐日对齐的两侧账户日收益后，把序列、登记锁定的检验条件与本次网格点数交给一个只读函数 <Ref id="report.paired" />。检验对象只有登记的那一个维度，即年化收益；方法是配对循环块自助（paired circular block bootstrap）：两侧账户日收益取对数差，按登记块长循环分块、两侧共用同一组块起点共同重抽，中心化后取单侧尾部概率。区间给基本区间与嵌套学生化区间，年化差的百分位区间另列；按本次网格点数做 Bonferroni 校正；块长敏感性、差值集中度与 80% 功效（未校准示例值）下可分辨的最小效应一律加报。全部由代码从日收益算出，只返回读数（reading），不返回裁决；检验条件（显著性水平、最小改进、块长、重抽次数、种子）是登记时声明的未校准示例值，代码只校验形态与范围。

### V.3.2　检验方法 [#V-3-2]

由代码实现：只读函数 <Ref id="report.paired" /> 接收两侧日收益、登记锁定的检验条件与网格点数，输出效应、三种区间、单侧 p、校正后 p 与局限。检验条件的形态与范围在登记时由 <Ref id="registration.validate_design" /> 校验（见 <Ref id="H.3.2.2" />），函数入口再校验一次；函数不写账本。

<Cap id="V.3.2.1" kind="code" tier="verified" tierLabel="已验证" title="配对块自助检验">

输入：对照侧与候选侧按同一 UTC 日钟逐日对应的账户日简单收益（配对单位见 <Ref id="V.2.2.2" />），登记锁定的检验条件 design（method、block_days、resamples、inner_resamples、seed、alpha、minimum_effect、design_reason），网格点数。计算：逐日取 log(1+r_候选) − log(1+r_对照)，观测效应为其均值；按登记块长（未校准示例值：7 天）切成固定长度、首尾循环衔接的块，用登记种子建随机源，两侧共用同一组块起点共同重抽 resamples 次，以保留配对与时间相依结构；重抽均值差减观测效应得中心化分布，单侧 p =（中心化值不小于观测效应的次数 + 1）/（重抽次数 + 1）。输出：平均日对数差、按 365 日历日由两侧平均日对数收益换算的年化差，以及 V.3.2.2、V.3.2.3、V.3.3 规定的各项读数。拒绝：检验条件不合格为 REGISTRATION_INVALID；序列不等长、非一维、不足两个完整块、含非有限值或不大于 -1 的值为 COMPARISON_UNAVAILABLE（<Ref id="ledger.refusal" /> 形态）。同一输入与种子重算结果逐位一致。由代码强制，只给读数不给裁决（见 <Ref id="V.4.1.1" />）。演练中全部比较读数由该函数算出，配对年化差区间跨零的结果被如实报告。

## V.4　出比较证据：读数怎么出、怎么读、留在哪 [#V-4]

### V.4.1　比较读数的内容与身份 [#V-4-1]

<Cap id="V.4.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="结果只读，不裁决">

### V.4.2　结果的适用、读法与留痕 [#V-4-2]

由 skill 指导，规则写在 research-round 的 references/feedback.md。四条规则依次约束读数的适用条件、留痕方式、p 的含义和账户收益差的读法。代码只提供读数本身和证据包写入（<Ref id="ledger.add_bundle" />）；每节由对应的 eval 检验。

<Cap id="V.4.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="条件证据：只在登记的适用条件内成立">

比较读数是条件证据，只在登记的适用条件内成立。适用条件包括源码、改动、参数、输入、窗口与运行环境（runtime image），见 <Ref id="research-round/references/hypothesis.md#conditions" />。读数不推广为对机制的肯定，也不用作排除某个方向的依据（见 <Ref id="research-round/references/feedback.md#no-exclusion" />）。相同条件的重复回放不算另一份独立证据：登记网格点只消耗一次（<Ref id="table:registration_attempt" />），重试必须另行登记并写 retry_of，由 <Ref id="registration.validate" /> 在登记时强制。条件不同的结果不互相抵消，各自保留、分别引用；它们对研究优先级（research priority）的含义见 <Ref id="F.2.1.2" />。强制层：一次性消耗与 retry_of 由代码强制，解读由 skill 指导。

<Cap id="V.4.2.3" kind="skill" tier="verified" tierLabel="已验证" title="p 不是策略有效的概率">

p 是在登记的原假设与配对重抽模型（<Ref id="report.paired" />）下的尾部概率，不是策略或机制有效的概率，也不度量效应大小。未达登记声明的显著性水平，不等于机制无效：跨零的区间读作不确定。达到了也不等于样本外（out-of-sample）有效：开发窗口内的改善只称改善或开发观察（见 <Ref id="research-round/references/validation.md#wording" />、<Ref id="X.2.2.2" />）。登记声明的显著性水平与最小改进属于检验条件，要与效应、区间、p 并列呈现，并标「方法示例值，未校准」（呈现方式见 <Ref id="R.4.1.1" />）。强制层：skill；p 的含义说明由 <Ref id="report.paired" /> 写进局限清单，随结果输出。
