### `check_comparable` [#def-registration-check_comparable]

可比资格：两侧的执行身份逐项比较，身份取自试验行（镜像摘要、合约集、窗口）与开始回执或登记包里的执行身份；不读运行行

```python
def check_comparable(run: Mapping, execution: Mapping) -> None
```

<TypeTable type={{ "run": { type: "Mapping", description: "一侧的运行行与其试验行合并后的记录（由 ledger.load_run 读出）：status、purpose、image_digest、effective_config（JSON）、input_identity（JSON）" }, "execution": { type: "Mapping", description: "对照基准的执行身份 {runtime{image_digest}, effective_config, input_identity}：登记记录里的执行身份；比较入口对候选与对照各调一次" } }} />

| `COMPARABILITY_MISMATCH` | runtime_image、effective_configuration、input_identity 中任一项两侧不等；消息列出所有不等的项 |

### `export_fingerprint` [#def-registration-export_fingerprint]

给出与路径无关的导出内容身份与导出器实现身份；语义模式结果写入输入身份，原始模式在回放执行前后各算一次防中途改动

```python
def export_fingerprint(
    inputs: dict,
    semantic: bool,
) -> {export_content_sha256
```

<TypeTable type={{ "inputs": { type: "dict", description: "registration.market_inputs 的返回值；只读 root 与 membership_file" }, "semantic": { type: "bool", description: "True：回执文件先去掉 seconds 字段再按规范 JSON 重编码后哈希，得身份用语义哈希；False：原始字节哈希，供执行前后比对" } }} />

**返回**　\{export_content_sha256, exporter_source_sha256\}：前者为导出内容身份（语义或原始），后者为导出器实现清单总哈希；两者与导出目录位置、导出时间、是否命中缓存无关

**期望行为**

1. 枚举 root 下全部普通文件（生命周期原件、每合约 Catalog 与回执）并追加成员文件（固定命名 membership.json），按相对路径排序
2. 任一条目为符号链接或成员文件缺失即拒绝，不跟随链接
3. 逐条目把名字长度、名字、内容 SHA-256 喂入总哈希；semantic 为 True 时回执文件先去 seconds 再以排序键、无空白的 JSON 重编码
4. 导出器实现哈希 = 固定清单（导出、生命周期、覆盖、存储、范围模块源码与依赖锁文件）各自 SHA-256 按路径排序后的规范 JSON 总哈希；清单是模块常量，不读调用方输入
5. 返回两项哈希；不写文件、不改导出目录

| 拒绝码 | 条件 |
|---|---|
| `EXPORT_CONTENT_INVALID` | 导出根或成员文件中存在符号链接，或成员文件缺失 |

### `market_inputs` [#def-registration-market_inputs]

按钉住的市场提交 AS OF 把一次回放所需市场输入导出到不可变目录，写成员文件并组装输入身份；登记与回放各调用一次，比对同一身份

```python
def market_inputs(
    market: dict,
    at: str,
    window: dict,
    selection: dict,
    lifecycle_bundle: str | None,
    fresh: bool,
    research: dict | None,
) -> inputs dict
```

<TypeTable type={{ "market": { type: "dict", description: "市场库档案；只以读账号连接" }, "at": { type: "str", description: "研究路线钉住的市场提交引用，经 market.resolve_commit 解析为唯一提交" }, "window": { type: "dict", description: "engine.parse_window 的输出：start、trade_start、end（UTC 纳秒，左闭右开，整分钟对齐）" }, "selection": { type: "dict", description: "{\"universe\": True} 取共同可交易范围内与交易段相交的全部合约，或 {\"symbols\": [...]} 显式清单；二者恰给其一" }, "lifecycle_bundle": { type: "str | None", description: "研究账本中的生命周期证据包名；给出时随导出写入导出根并进入身份" }, "fresh": { type: "bool", description: "True 忽略按提交与窗口键的导出缓存重新导出；False 可命中同键缓存，内容哈希仍逐字节重算" }, "research": { type: "dict | None", description: "研究账本档案，仅读生命周期证据包时需要" } }} />

**返回**　inputs dict：identity\{market_database, market_commit, universe_rule, selection, symbols, export_content_sha256, exporter_source_sha256, lifecycle_bundle?\}、root、membership_file、symbols、exported\{exported, reused, seconds\}、fresh；identity 是登记锁定与回放核对的全部输入身份

**期望行为**

1. 核对 selection 恰含 universe 或 symbols 之一且 symbols 无重复；ledger.connect 以读账号连市场库，market.resolve_commit 把 at 解析为唯一市场提交
2. 按该提交 AS OF 读 table:market_schema 的 universe_rule 与 table:universe_month 全部 (month, symbol) 行，无成员行即拒绝；market.membership_path 合并成每合约 [start_ns, end_ns) 成员时间路径
3. universe 模式合约集 = 成员区间与 [trade_start, end) 相交的全部合约（不排名、不取前 N、下架照收），无相交合约即拒绝；symbols 模式原样采用
4. 给出 lifecycle_bundle 时经 registration.load_lifecycle 读证据包，其市场提交须等于本次提交；拒绝原样透传
5. market.export_catalogs 按提交、合约集与完整输入区间 [start, end) 以 1 分钟周期导出 Catalog、逐合约回执与生命周期原件，任一回执周期不是 1 分钟即拒绝；把 \{commit, universe_rule, membership\} 写成只含本次合约集的成员文件
6. registration.export_fingerprint 语义模式算导出内容哈希与导出器哈希写入 identity 并返回（其拒绝原样透传）；不写账本、不删合约、不缩窗、不补数
7. 返回值另含每合约覆盖回执 receipts；输入身份含 membership（每合约成员时间路径），与 registration.input_key 的保留键一致。

| 拒绝码 | 条件 |
|---|---|
| `SYMBOL_SELECTION_INVALID` | selection 同时给出或都未给出 universe 与 symbols，或 symbols 含重复 |
| `UNIVERSE_EMPTY` | 该市场提交 AS OF 下无成员行，或 universe 模式下没有合约与交易段相交 |
| `LIFECYCLE_INPUT` | 生命周期证据包的市场提交不等于本次提交或缺来源原件（由 registration.load_lifecycle 透传） |
| `EXPORT_TIMEFRAME` | 任一合约的导出回执周期不是 1 分钟 |
| `MARKET_COMMIT_UNRESOLVED` | at 不能解析成唯一市场提交（由 market.resolve_commit 透传） |
| `EXPORT_CONTENT_INVALID` | 导出根或成员文件中存在符号链接，或成员文件缺失（由 registration.export_fingerprint 透传） |

### `exposure_exempt` [#def-registration-exposure_exempt]

判定一个曾执行过待登记源码的试验是否属于免于源码暴露的事前声明预检；只读，不判定预检是否通过

```python
    trial_id: int,
    source_sha256: str (CHAR(64)),
    image_ref: str,

    input_key: dict,

```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "已打开的账本连接，只读使用" }, "trial_id": { type: "int", description: "曾执行该源码的试验；由调用方从 trial 表按 source_sha256 逐条取出" }, "source_sha256": { type: "str (CHAR(64))", description: "待登记网格源码的内容哈希" }, "image_ref": { type: "str", description: "登记声明的运行环境引用，含 @sha256: 摘要" }, "config_key": { type: "dict", description: "登记声明的有效配置身份（registration.config_key 的结果）" }, "input_key": { type: "dict", description: "登记声明的输入身份（registration.input_key 的结果：市场库名、市场提交、范围规则版本、合约集、生命周期证据包等）" } }} />

**期望行为**

1. 按 trial_id 读试验行，不存在即拒绝 TRIAL_NOT_FOUND；trial.purpose 不是 precheck 返回 False。
2. trial.source_sha256 须等于 source_sha256，trial.image_digest 须等于 image_ref 的摘要；任一不同返回 False。
3. 只有登记 prechecks 引用的那一次预检可以免除，且其交易窗口不超过 7 天（未校准示例值）；更长的预检、同源码的其他预检与探索都算暴露。这样预检只能证明源码能跑，不能拿来先看结果再挑。
4. 经 ledger.read_capture 读原始捕获：须有原件（非恢复材料）开始回执、用途为 precheck，并有最终执行封存；缺任一返回 False；哈希不符时透传 LEDGER_CORRUPT；捕获形态不合法即 SOURCE_PRECHECK_REQUIRED。
5. 比对开始回执记录的身份：市场库名、市场提交、范围规则版本与生命周期证据包须与 input_key 逐字相同，预检合约集须为登记合约集的子集；有效配置除窗口与合约集键外须与 config_key 逐键相等。任一不符返回 False。
6. trial_id 出现在 registration_attempt 即返回 False，预检从不消耗网格点。
7. 以上全过返回 True。是否通过由 registration.require_precheck 判定；同一源码的多次预检逐条独立判定。
8. 成员文件哈希与合约集同属「合约范围」：预检在登记范围的子集上运行时，二者都按子集核对，不按逐字相等。

| 拒绝码 | 条件 |
|---|---|
| `TRIAL_NOT_FOUND` | trial_id 在 trial 表中不存在 |
| `LEDGER_CORRUPT` | ledger.read_capture 发现捕获文件内容哈希与 evidence.sha256 生成列不符（属篡改发现，不返回 False） |

核对一个网格源码有同源码、同运行环境、同生命周期输入且通过的原生预检与独立源码审查，否则拒绝

```python
def require_precheck(

```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "只读使用；由 registration.register 与 registration.bind 在各自写事务内调用" }, "review_bundle": { type: "str", description: "登记正文 prechecks 映射里该网格源码引用的审查证据包名" }, "source_sha256": { type: "str (CHAR(64))", description: "该网格源码的内容哈希" }, "image_ref": { type: "str", description: "登记或本次绑定的运行环境引用，含 @sha256 摘要" }, "input_key": { type: "dict | None", description: "输入身份（市场提交、合约生命周期包）；登记时为声明值，绑定时为实际导出值；None 只用于导出输入前的静态核对" } }} />

**返回**　int：通过核对的预检 trial_id；任一不符抛拒绝，不返回部分结论

1. review_bundle 须在 source-review-* 命名空间（只由 registration.record_review 写），否则 SOURCE_PRECHECK_REQUIRED。
2. 经 ledger.load_bundle 读 review_bundle 内 source-review.json：包或文件不存在、format 不是 source-review-v1 即 SOURCE_PRECHECK_REQUIRED；内容哈希不符即 LEDGER_CORRUPT
3. 按审查记录的 trial_id 读试验行：不存在 TRIAL_NOT_FOUND；trial.purpose 须为 precheck，trial.source_sha256 与 image_ref 摘要须同时等于审查记录与传入值，否则 SOURCE_PRECHECK_REQUIRED
4. 经 ledger.read_capture 读该试验的原始执行捕获（不接受恢复材料）：运行器与审计器退出码为零、无回调异常、无中断或未完成标记，否则 SOURCE_PRECHECK_FAILED

7. 同一预检试验的任一 source-review-* 审查结论为 failed，即 SOURCE_PRECHECK_FAILED，不能另找一份通过的审查来登记。
8. 返回预检 trial_id；通过不替代完整性审计，也不授予经济证据资格

|---|---|
| `SOURCE_PRECHECK_REQUIRED` | 审查包或 source-review.json 缺失或格式不符，引用的试验用途不是 precheck，或其源码哈希、运行环境摘要、输入身份与本次不一致 |
| `SOURCE_PRECHECK_FAILED` | 预检原件任一阶段非零退出、回调异常、中断或未完成，或审查四项任一为 failed／unresolved |
| `TRIAL_NOT_FOUND` | 审查记录引用的 trial_id 不在 trial 表 |
| `LEDGER_CORRUPT` | 审查文件或捕获文件的内容哈希与 evidence.sha256 不符 |

### `bind` [#def-registration-bind]

```python
    source_sha256: str,
    trial_id: int,

```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "ledger.open_trial 打开的试验写事务内连接；本函数不开启也不提交事务" }, "registration": { type: "dict", description: "{bundle: 登记包名}；本次执行身份不由调用方给，从试验行与开始回执读" }, "source_sha256": { type: "str", description: "本次被执行源码的内容哈希，与 trial.source_sha256 相同" }, "trial_id": { type: "int", description: "同事务刚插入的试验行主键" } }} />

**期望行为**

1. ledger.load_bundle 读回登记包的 research-plan.json 并重验内容哈希，解析 body 与登记时的 execution；包名不形如 registration-* 或包不存在即 REGISTRATION_INVALID（retry_of 所指登记同样只认 registration-*）。

3. 执行身份逐项比对实际记录：trial.purpose 须为 research；试验行的预热起点、交易窗口与合约集，开始回执 execution.json 的输入身份（经 registration.input_key）、input-coverage.json 的有效配置（经 registration.config_key）、镜像摘要与运行契约，须等于登记的执行身份；任一不等即 EXECUTION_MISMATCH 并指明冲突项。
4. 读 evidence_bundle.created_at 与 trial.created_at（均为服务器触发器时间），登记须严格早于试验，否则 REGISTRATION_TOO_LATE。
5. 查 registration_attempt 是否已存在 (bundle, source_sha256)，存在即 GRID_ALREADY_ATTEMPTED；否则插入 (bundle, source_sha256, trial_id)，主键冲突同样拒绝。
6. 不提交：消耗行由调用方与试验行、执行开始回执同一账本提交落账；之后无效与中断的尝试照样保留此行。

| `LINEAGE_MISMATCH` | 重验时某网格点的研发父版本或改动说明已与登记不符 |
| `SOURCE_MISMATCH` | 被执行源码哈希不在该登记锁定的网格内 |
| `EXECUTION_MISMATCH` | 运行环境摘要、去宿主路径后的生效配置或输入内容身份与登记不逐项相同 |
| `SOURCE_PRECHECK_REQUIRED` | 被执行源码缺少绑定同源码同运行环境的独立预检审查 |
| `SOURCE_PRECHECK_FAILED` | 审查存在但预检退出非零，或审查项中有 failed / unresolved |
| `REGISTRATION_TOO_LATE` | 登记包服务器时间不早于试验行服务器时间 |
| `GRID_ALREADY_ATTEMPTED` | registration_attempt 已存在 (bundle, source_sha256)，含无效与中断的先前尝试 |


1. 已完成：试验有 run 行（passed 或 invalid）或已被 recovery 结案。路线内每个已完成的研究试验，须被某条 interpretation 判断覆盖（主体含该试验或其登记包；被取代的解释也算），否则 INTERPRETATION_REQUIRED，missing 列出试验。例外：运行无效、且它的登记被某个登记的 retry_of 指向（已存的登记，或正在写入的这一个）的试验不需要解释；失败只修复重试，不解释。

4. 计数达到 cadence_trials 而起点之后没有新的 recommendation 即 REVIEW_DUE。

|---|---|

| `REVIEW_CADENCE_REQUIRED` | 派生登记时路线上还没有 review_cadence 判断 |

### `validate` [#def-registration-validate]

```python

    conn: LedgerConnection,
    body: dict,
    execution: dict,
    before_replay: bool,
) -> set[str]
```

<TypeTable type={{ "conn": { type: "LedgerConnection", description: "账本连接（读账号或写事务内的连接均可）；只读，不提交" }, "body": { type: "dict", description: "登记体 JSON。必有十一项：prediction（见 P.2.1.1）、changed_duties、parent（strategy_id@revision 或 null）、control_run（run_id 或 null）、change（一处改动说明）、rationale（external / local / conjecture 三类各一段）、sources（来源证据包名列表）、comparison（与对照比年化收益的检验条件，见 validate_design；control_run 为 null 时为 null）、grid（一到五个 {candidate: strategy_id@revision, params: dict}）、conditions（适用条件）、window（{trade_start, trade_end}）；可选 retry_of（先前登记包名）、prechecks（{网格候选: source-review-* 审查包名}）" }, "execution": { type: "dict", description: "执行身份：{image_ref, image_digest, runtime_contract, effective_config, input_identity}。登记时来自 register 的探测结果，绑定时来自本次试验" }, "before_replay": { type: "bool", description: "False＝登记时核对；True＝绑定前重验：对照资格与审查结论按当前指标计算版本重算，拒绝归属于绑定" } }} />

**期望行为**

1. 核字段集合恰等于十一项必有键（含 prediction 与 changed_duties）加可选键，多一键少一键即拒；有对照（或 comparison 非空）时 comparison 交 validate_design，没有对照时 comparison 为 null、不校验；sources 每个包名须在 evidence_bundle 存在
2. 预测的方向 direction 取 up 或 down；比较的对象固定是年化收益，登记体里没有选维度的字段。
3. 核 changed_duties：每项须是 27 项职责编号之一；根登记必须为空，派生登记至少一项。
4. 切面与职责：某切面可解释哪些职责，取 registration.measure_catalogue 的切面—职责表；预测的切面为空时须写理由，measure 非空时仍须是目录里某个切面的标量。
5. 核 prediction：mechanism 每项的职责在 changed_duties 里，切面与标量在归因目录里（切面为空时须有理由）；changed_duties 每项至少一项预测；根登记的 mechanism 可为空。
6. 核父与对照：parent 为空则 control_run 与 change 也须为空（根），否则 parent 须是 candidate 里的已发布版本且 change 非空；control_run 非空时读 run ⨝ trial，经 check_comparable 与 execution 比三类身份，再经 qualification.require 核经济证据资格；parent 非空而 control_run 为空只允许在 rationale.local 引用父运行的故障或零活动
7. 核窗口：body.window 逐字等于 ledger.current_line 记录的开发窗口；无研究路线记录即拒
8. 核网格：一到五点，每点经 ledger.read_candidate 读 candidate 行，source_sha256 不得重复；每点 parent 与 difference 须等于登记的 parent 与 change；每点 runtime_contract 须等于 execution.runtime_contract
9. 核暴露与审查：对每个网格源码读 trial 中同 source_sha256 的试验行，存在非预检执行且 body 无 retry_of 指向实际消耗它的登记（registration_attempt）即拒；预检免除由 exposure_exempt 判定；每格须经 require_precheck 解析到绑定同源码同镜像摘要、四项均 passed 或 no_opportunity 的审查件
10. 全部通过返回网格源码哈希集合；拒绝消息指明是哪一项、哪一格或哪一类身份冲突
11. prechecks 是映射 \{网格候选 strategy_id@revision: source-review-* 审查包名\}；某格缺项，或所指包名不在 source-review-* 命名空间，即 SOURCE_PRECHECK_REQUIRED。该命名空间只由 registration.record_review 写，Agent 另起名字放的审查文件不被采信。
12. before_replay=True（绑定前重验）时，暴露核对跳过正被绑定的试验和同一登记先前的尝试：它们的消耗由 GRID_ALREADY_ATTEMPTED 判定，不算源码暴露。
13. 无对照的派生登记：代码只核 rationale.local 非空；它是否确实引用了父运行的故障或零活动，由开题审阅判断。
14. research 的 retry_of 沿链传递：暴露核对跳过链上任一登记下的尝试；只有链上每次被消耗的尝试都中断、无效或经 qualification.assess 判为无经济证据资格时才允许重试，否则 RETRY_NOT_ALLOWED（结果不好看不是重试理由）。

### `validate_design` [#def-registration-validate_design]

校验检验条件 comparison 的形态：字段恰为 method、block_days、resamples、inner_resamples、seed、alpha、minimum_effect、design_reason 八项，并核对类型与范围；不评价数值是否合理。数值是方法示例值，随登记锁定。

```python
def validate_design(value: dict) -> None
```

<TypeTable type={{ "value": { type: "dict", description: "登记体或样本外登记体的 comparison 字典" } }} />

**返回**　None；不合即抛出拒绝 REGISTRATION_INVALID，消息指明出错的字段与违反的约束

**期望行为**

1. 键集合恰为八项，多一项或少一项都拒绝
2. method 必须等于 report.paired 所用的方法名 paired-circular-log-mean-v1
3. block_days、resamples、inner_resamples、seed 必须是整数，且不低于各自下限：block_days ≥ 1，resamples ≥ 999，inner_resamples ≥ 99，seed ≥ 0（下限均为未校准示例值）

5. design_reason 是非空的有限长度文本；文本内容由 skill 指导，代码只核对非空
6. 通过即返回 None，不写任何记录

| `REGISTRATION_INVALID` | 不是字典，或字段多于或少于八项；method 不是 paired-circular-log-mean-v1；整数字段类型不对或低于下限；alpha 不是有限数值或不在 (0, 0.5) 内；minimum_effect 为负、非有限或不是数值；design_reason 为空或超长 |

### `membership_unchanged` [#def-registration-membership_unchanged]

核对本次回放的共同可交易范围与登记一致：范围规则相同；登记前各月成员在登记提交与本次提交下逐行相同；窗口月份存在且交给策略的成员路径未剔除成员；不一致抛 MEMBERSHIP_CHANGED

```python
def membership_unchanged(
    market: MarketConnection,
    registration: ValidationRegistration,
    inputs: MarketInputs,
) -> None
```

<TypeTable type={{ "market": { type: "MarketConnection", description: "市场库只读连接，支持按提交 AS OF 读 universe_month" }, "registration": { type: "ValidationRegistration", description: "登记行：market_commit、universe_rule、window_start、window_end、created_at" }, "inputs": { type: "MarketInputs", description: "registration.market_inputs 的结果：本次市场提交、universe_rule、交给策略的成员时间路径" } }} />

**返回**　None；不一致时抛 MEMBERSHIP_CHANGED，原因里给出首个不同的月份与合约

**期望行为**

1. 规则：inputs.universe_rule 不等于 registration.universe_rule 即 MEMBERSHIP_CHANGED。
2. 登记前各月：对月初不晚于登记时间的每个月（含登记当月），market.monthly_universe 分别按 AS OF registration.market_commit 与 AS OF inputs.market_commit 读成员行（合约、上下架事实），逐行比较，任一行不同即 MEMBERSHIP_CHANGED。
3. 窗口月份：窗口 [window_start, window_end) 覆盖的每个月在 AS OF inputs.market_commit 下须存在；缺月即 MEMBERSHIP_CHANGED（环境尚未产出该月，不能用登记提交补）。
4. 未剔除：market.membership_path 按 inputs.market_commit 推出成员时间路径，与交给策略的路径逐合约逐区间比较；任一成员被去掉或区间缩短即 MEMBERSHIP_CHANGED。窗口内下架是生命周期事件，不算剔除。
5. 只读，不写任何表，可在绑定事务内重复调用。

| 拒绝码 | 条件 |
|---|---|
| `MEMBERSHIP_CHANGED` | 范围规则不同；登记前任一月份成员在两个市场提交下不逐行相同；窗口内任一月份不存在；交给策略的成员路径少于按本次提交推出的路径 |

样本外回放启动前，在试验写事务内核对源码、范围、窗口与覆盖、凭证、账户条款与运行环境都与登记一致，并写 validation_binding；第二次绑定拒绝


<TypeTable type={{ "conn": { type: "LedgerConnection", description: "ledger.open_trial 已开的写事务，试验行刚在其中写入；绑定与试验同提交或同回滚" }, "registration_id": { type: "int", description: "要绑定的 validation_registration 主键" }, "trial_id": { type: "int", description: "本次试验 ID，purpose=validation；其 trade_start、trade_end、created_at、image_digest 参与核对" }, "source_sha256": { type: "str", description: "即将执行的策略源码内容哈希，取自导出到容器的字节" }, "inputs": { type: "MarketInputs", description: "registration.market_inputs 的结果：市场提交、范围规则、成员路径、合约集、交易窗口、覆盖回执" }, "identity": { type: "RuntimeIdentity", description: "按摘要钉死的运行环境身份（runtime.resolve）" }, "inspection": { type: "RuntimeInspection", description: "runtime.inspect_runtime 的探针结果，含有效配置与账户条款" }, "market": { type: "MarketProfile", description: "市场库档案，供 membership_unchanged 按提交读名单" }, "checkout": { type: "Path", description: "产品 checkout，供 require_fresh 核对其 HEAD" }, "remote": { type: "str", description: "比对 main 的远端名" }, "tsa_roots": { type: "Path", description: "时间戳机构根证书，供 stamped_at 验签" } }} />

**返回**　None；全部核对通过后在同事务写 validation_binding 一行；任一项不一致抛拒绝，由调用方回滚整个试验事务且不启动容器

**期望行为**

1. 运行环境与产品代码：registration.require_fresh（STALE_CHECKOUT）；runtime.require_main_build(identity, inspection)（RUNTIME_NOT_MAIN）；trial.image_digest 须等于 identity 摘要。
2. 实际身份：输入取本试验的开始回执，不由调用方给；trial.source_sha256 须等于登记候选的源码哈希（SOURCE_MISMATCH），试验行合约集须等于按本次市场提交推出的成员集（MEMBERSHIP_CHANGED）。
3. 登记与源码：读 validation_registration，不存在即 REGISTRATION_UNKNOWN；ledger.read_candidate 取登记候选的源码内容哈希，不等于 source_sha256 即 SOURCE_MISMATCH。
4. 范围：调用 registration.membership_unchanged，不一致即 MEMBERSHIP_CHANGED；窗口内下架由 market.validate_lifecycle 校验的引擎原生事件结算并出回执。
5. 窗口与覆盖：trial.trade_start 与 trial.trade_end 须分别等于登记的 window_start 与 window_end，且 trial.created_at > window_end，否则 WINDOW_MISMATCH（与提交校验 validation_runs_match_their_registration 一致）；replay.input_coverage 的回执须覆盖每个成员合约的预热与交易区间，否则 COVERAGE_INCOMPLETE。
6. 凭证与账户条款：ledger.stamped_at 读登记提交（重试沿 retry_of 链取最初登记提交）的 genTime，无凭证或不早于 window_start 即 REGISTRATION_TOO_LATE；取该候选最近一次有效的研究回放运行，经 registration.config_key 比较其有效配置与 inspection 中影响经济的账户条款（engine.account_contract 规定的账户与撮合常量、保证金、手续费、资金费、标记价来源），不等或无此运行即 CONFIG_MISMATCH。
7. 写绑定：插入 validation_binding(registration_id, trial_id, op_id)；主键或唯一键冲突即 REGISTRATION_CONSUMED。登记一经绑定即消耗，回放中断、审计无效或无实质活动也不释放。

| 拒绝码 | 条件 |
|---|---|
| `STALE_CHECKOUT` | 产品 checkout 的 HEAD 不含 main 的最新提交，或无法证明 |
| `RUNTIME_NOT_MAIN` | 运行环境不是产品镜像源中 main 上的构建，或镜像内源码与依赖锁哈希不等于该版本字节，或试验镜像摘要不符 |
| `REGISTRATION_UNKNOWN` | registration_id 不存在 |
| `SOURCE_MISMATCH` | 即将执行的源码哈希不等于登记候选的源码哈希 |
| `MEMBERSHIP_CHANGED` | 范围规则不同、登记前各月成员在两个市场提交下不逐行相同、窗口月份缺失或成员被剔除 |
| `WINDOW_MISMATCH` | 交易窗口不等于登记窗口，或试验时间不晚于窗口结束 |
| `COVERAGE_INCOMPLETE` | 任一成员合约的输入区间缺覆盖回执 |
| `REGISTRATION_TOO_LATE` | 登记提交无凭证，或凭证 genTime 不早于 window_start |
| `CONFIG_MISMATCH` | 账户条款与该候选最近一次有效的研究回放运行不同，或该候选没有有效的研究回放运行 |
| `REGISTRATION_CONSUMED` | 该登记已绑定过回放，或该试验已绑定别的登记 |
| `CONCURRENT_WRITE` | 两事务改同格为不同值，后到者回滚 |

### `validation_register` [#def-registration-validation_register]

唯一写入 validation_registration：核候选、检验条件、窗口与重试条件，一事务一提交写登记，提交后对该提交取凭证；凭证失败时登记仍在

```python
def validation_register(
    ledger: LedgerProfile,
    candidate: str,
    window_start: datetime (UTC),
    window_end: datetime (UTC),
    universe_rule: str,
    market: str | None,
    design: dict,
    retry_of: int | None,
    op_id: str,
    market_profile: MarketProfile,
) -> dict {registration_id
```

<TypeTable type={{ "ledger": { type: "LedgerProfile", description: "活动账本连接档案，经 ledger.connect 开写事务" }, "candidate": { type: "str", description: "被验候选引用 strategy_id@revision" }, "window_start": { type: "datetime (UTC)", description: "样本外窗口起点，左闭" }, "window_end": { type: "datetime (UTC)", description: "样本外窗口终点，右开；须晚于 window_start" }, "universe_rule": { type: "str", description: "共同可交易范围规则版本" }, "market": { type: "str | None", description: "市场提交引用；经 market.resolve_commit 解析成 market_commit" }, "design": { type: "dict", description: "声明的检验条件；数值为未校准示例值" }, "retry_of": { type: "int | None", description: "修复环境缺陷后再登记时指向的原登记" }, "op_id": { type: "str", description: "幂等 ID；相同 op_id 且载荷相同返回已存在的登记，载荷不同即 OP_ID_CONFLICT" }, "market_profile": { type: "MarketProfile", description: "市场库档案，用来把 market 引用解析成提交" } }} />

**返回**　dict \{registration_id, ledger_commit, created_at, witness: \{status: stamped|failed, stamped_at | None, error | None\}\}：登记 ID、登记提交、服务器登记时间（读自登记行）与凭证结果

**期望行为**

1. 核输入：ledger.read_candidate 解析 candidate，不存在或未发布即 CANDIDATE_UNKNOWN；registration.validate_design 校验 design，不合即 DESIGN_INVALID；时间非 UTC 或 window_start 不早于 window_end 即 WINDOW_INVALID。
2. 定范围身份：market.resolve_commit 把 market 解析成唯一市场提交，与 universe_rule 一并写入登记行；窗口内月份此时不存在，不在此刻核对。
3. 重试核对（给了 retry_of）：原登记须同候选、同窗口、同 universe_rule，且已被 validation_binding 绑定，其试验中断无运行（须有原始执行封存记下中断或宿主失败，没有封存不算中断）、运行无效，或 qualification.assess 判为无经济证据资格；否则 RETRY_NOT_ALLOWED。
4. 写登记：ledger.write 一事务插入一行并提交，事务内读回服务器写入的 created_at；非重试且 window_start 不晚于 created_at 即回滚并 REGISTRATION_TOO_LATE；同 op_id 已存在且载荷相同返回原行，载荷不同即 OP_ID_CONFLICT。
5. 取凭证：由 dolt_diff_validation_registration 中该行 added 的 to_commit 定位登记提交，ledger.witness 对它取 RFC 3161 凭证写入 witness，只发送哈希、按提交幂等。
6. 凭证失败不回滚登记：返回 status=failed 与 error，由 cli.ledger_witness 在窗口起点前补取；绑定时按 genTime 早于窗口起点准入（重试沿 retry_of 链取最初登记的凭证）。
7. 凭证机构地址不合法或取凭证失败都返回 status=failed 与 error，不抛异常；登记已提交，不回滚。

| 拒绝码 | 条件 |
|---|---|
| `CANDIDATE_UNKNOWN` | candidate 无法解析为已发布的候选 |
| `DESIGN_INVALID` | 检验条件字段缺失、多余或取值非法 |
| `WINDOW_INVALID` | window_start 不早于 window_end，或任一不是带时区的 UTC 时间 |
| `RETRY_NOT_ALLOWED` | retry_of 指向的登记不存在、候选／窗口／范围规则不同、尚未绑定回放，或其运行有效且有经济证据资格（结果不好看不是重试理由） |
| `REGISTRATION_TOO_LATE` | 非重试登记的 window_start 不晚于服务器写入的 created_at |
| `CONCURRENT_WRITE` | 写事务与另一事务改同格为不同值，后到者回滚 |
| `OP_ID_CONFLICT` | op_id 已存在而载荷不同 |
