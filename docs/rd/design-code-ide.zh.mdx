# 交易 IDE

研究的页面，本地打开，或经[远程主机](/zh/docs/platform-architecture/#remote)的 GitHub 登录打开。第一个视图从研究账本把一条研究线画成图：按试验编号排开的策略版本谱系，以及回放、预测、源码审阅、推荐与资格变化。检验账本能否还原会话的反向测试归 product-doctor（[references/fidelity.md](https://github.com/qOeOp/trade/blob/main/.agents/skills/product-doctor/references/fidelity.md)），复用这里的数据格式与对比工具。

## 约定

1. 图由产品命令 `research graph` 只从账本读出：只组合产品已有的读取函数、不加自己的规则，同一账本提交永远得到同一张图；图里带该提交上这条路线生效的两个用户目标，从账本读出。
2. 图须通过 `ide.py check`；不为迁就数据放宽格式。
3. 用户在 compose 部署上打开 `http://127.0.0.1:8765/`（`?line=`、`since=`，或 `at=` 看固定版本）；它读活动账本的头，写入提交后就显示。
4. 新渲染器只读视图模型；新图表是新的 widget 类型；图的新事实是新的格式版本，格式、`research graph`、布局、对比与 product-doctor 的反向测试一起改。

## 工具：ide

| 阶段 | 输入 → 输出 | 负责 |
|---|---|---|
| 抽取 | 账本 → graph.json | 一条研究线在账本里的全部记录：版本、本线自己的研究运行（同一窗口与市场日）、审阅与判断（产品命令 `research graph`） |
| 格式 | graph.json（research-graph@3）→ 问题清单 | 图的形状（schema/graph.schema.json） |
| 布局 | graph.json → view.json（research-graph-view） | 画什么、放在哪，以行和本线自己的试验为单位（本线第 n 个试验在 n，标签是它的试验编号），不含像素；按 widget 分块（summary、lineage、progress、scatter、table、notes、candidate-detail、sources），每块自带类型与位置 |
| 渲染 | view.json → 页面 | 像素、颜色、文字与交互；web 渲染器是自包含的单个 HTML 页面，源码一变就重建 |
| 对比 | 两份 graph.json → 差异 | 哪些事实不同，不做归类（供 product-doctor 的反向测试） |

阶段之间只通过这些文档交接，任一阶段可单独替换。渲染器只有一个；另加的渲染器（如经 HTTP 发送 widget 文档的 server，只提供视图、不读写账本）读取同样的 widget。

**服务**　`ide.py serve`（只用标准库，不导入产品包）以子进程调产品命令行：`ledger sql` 读头提交，`research graph --at=<完整哈希>` 取图，`research counts` 取摘要里的试验计数，再经布局得到视图。页面是 web 渲染器的同一份页面、不嵌视图：它读 `/api/view`（200 视图、202 状态、错误为拒绝 JSON），并订阅 `/api/events`（SSE：连上先发当前状态，15 秒心跳，每页只留最新状态）。只在有不带 `at` 的 live 页面开着时才轮询：每 5 秒读一次头，头变了就为每个开着的 live 页面在新头上取一次图，只取最新的，全局同时只取一张；只开着固定 `at` 的历史页面时不读头，图不变。成功的视图只放进程内存（LRU 8，键为库、镜像提交、账本提交、路线、since）。账本头移动后，`research unchanged` 说这次变化碰不到某条指定线的图时，它的视图改记到新提交下，不重画，试验计数（覆盖全账本、会随之变的部分）按新提交读。指定线的页面把最后一张视图存在浏览器（IndexedDB），打开先显示，并告诉服务，服务回答 `unchanged` 或重画；账本不写任何东西。只接受配置的 Host，跨站请求除对页面外壳的文档导航外一律拒绝，不发 CORS 头；图接口自己没有写口。配置了 Agent 或 Paper 地址时，`/api/agent/`、`/api/paper/` 下的请求（含 POST、PUT、PATCH、DELETE）经同样的 Host 与跨站检查后原样转发给那两个服务，Paper 的写请求还须同源并带本服务启动时生成的令牌；配置了 Overview 地址时，`/api/overview/` 下只转发 GET（其他方法回 405），供市场页读全市场快照、单个币的详情和一周内的消息与公告，并供 Live 运行的图表读一个合约一段时间（至多三天）的一分钟 K 线（被请求时从 Binance 公开接口读）；代理不读写账本。

**镜像**　`deploy/` 由 CI（`.github/workflows/ide-image.yml`）构建，推到 `ghcr.io/qoeop/trade-ide`（main 打 `main`，PR 打 `pr-N`），内含构建提交的产品与其浅 `.git` 和建好的页面。它不带自己的库：读 compose 里的 ledger 服务，只拿账本的 reader 账号——ledger 每次启动把只含端口与该 reader 账号的 `service.json` 写进卷 `trade-ledger-readers`，IDE 只读挂载它，看不到 root 密码、写账号和 DoltHub 密钥；两个档案是 compose 配置，账本档案不标生命周期（kind 为 null），所以从不发布。对话代理的代理配置与对话记录放在卷 `trade-ide-agent`（docs/plans/ide-reads-ledger-service.zh.md）。
