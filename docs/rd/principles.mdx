## A.1　说清循环怎么转 [#A-1]

循环由四种活动组成：入口、迭代、复盘、观察。入口由 research-start 承担：从账本 ledger 恢复研究状态 research state，在全部经济证据可用的候选 candidate 上给综合推荐 recommendation 与路线选项，等用户选研究路线 research line。选定后 research-round 在路线内自主迭代：每次迭代以查来源与提假设 hypothesis 开始，经发布候选、原生预检 native precheck 与独立源码审查、登记 registration 锁定、回放产生试验 trial 与运行 run、完整性审计与实质活动 substantive activity 资格、比较证据读数，以反馈与研究优先级 research priority 更新结束。复盘 review 按 Agent 事先在研究状态清单里声明的次数或进展触发，给综合推荐；只有要换路线才回入口由用户选。用户随时读报告，可发起样本外 out-of-sample 验证 validation。数据流只有一个方向：Agent 经命令行写入账本，账本是唯一持久状态；代码只在步骤之间强制登记锁定、审计、资格与读数，不决定下一步、不给裁决。循环没有终点：不设达标门槛、总次数或总预算，运行限制只暂停执行，所有完整版本都是候选。

<Steps>

<Step>

入口：从账本恢复研究状态（候选清单、运行读数、研究状态清单），在全部经济证据可用候选上给综合推荐与路线选项，用户选研究路线；无谱系或用户离开全部路线时才提根选项。

</Step>

<Step>

迭代：查来源→写假设五样→发布候选→原生预检与独立审查→登记并锁定网格点→每点回放一次→审计与实质活动资格→比较证据（效应、区间、p）→反馈与研究优先级；Agent 不逐项请批。

</Step>

<Step>

复盘：声明的次数或进展到达时，在全部可比候选上综合推荐一版或一批并说明取舍，追加到研究状态清单；研究继续。

</Step>

<Step>

换路线：Agent 给诊断与选项回到入口，由用户选；亏损、计数、限制或故障都不自动换路线。

</Step>

<Step>

观察：用户随时读候选报告、比较证据与推荐，可据此发起样本外验证；观察不改变候选身份与派生资格。

</Step>

<Step>

没有终点：运行限制只暂停执行并保留恢复状态；所有完整版本都是候选，推荐与显著性不改变其身份。

</Step>

</Steps>

### A.1.1　循环的步骤 [#A-1-1]

四步都是 skill 指导的 Agent 行为。输入是账本里的候选清单、运行读数与研究状态清单 research state list（按市场与开发窗口 development window 各一份的只追加证据包）；输出是写回账本的登记、证据包与推荐。代码只在步骤之间强制四件事：登记先于回放并锁定网格点、完整性审计、实质活动与可比资格、配对检验读数；代码不决定下一步、不返回裁决。

<Cap id="A.1.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="入口：恢复研究状态并给综合推荐，用户选研究路线">

入口由 research-start 承担，顺序固定为三步。第一步恢复研究状态：经命令行从账本读候选清单（<Ref id="report.candidates" />）、运行读数与最新版研究状态清单（<Ref id="research-start/SKILL.md#resume-from-ledger" />、<Ref id="research-start/SKILL.md#read-state-list" />），会话记忆不算研究状态；清单缺失或落后于账本时以候选清单与事实计数为准并补写新版。第二步给综合推荐与路线选项：范围是全部经济证据可用的候选，仅诊断与无效候选分列不入推荐（<Ref id="research-start/SKILL.md#recommendation-range" />）；推荐是多维综合（年化、回撤、夏普、胜率、成本、资金使用率 capital utilisation、利润来源、机制、不确定性）并说明取舍，每个选项附读数、资格与已试／未试历史（<Ref id="research-start/SKILL.md#option-readings" />）。第三步等用户选研究路线：选项由 Agent 提，选由用户，选定前不登记、不回放，不以推荐代替选择（<Ref id="research-start/SKILL.md#user-selects-route" />）；选定的起点候选、开发窗口与钉住的市场提交写成研究路线证据包（<Ref id="ledger.select_line" />）。只在两种情况下提根节点 root 选项：账本里没有候选谱系 lineage，或用户明确决定离开全部现存路线；根来自策略库模板或用户自建的人造根 artificial root，附首份报告（<Ref id="research-start/SKILL.md#root-options" />）。亏损、低优先级、复盘计数或运行限制都不触发选新根。强制层：skill 指导入口的三步与根的条件；代码只提供只读读口与路线证据包写入，不做选择。

<Cap id="A.1.1.2" kind="skill" tier="verified" tierLabel="已验证" title="迭代：提假设到反馈与优先级，Agent 在路线内自主推进">

路线内一次迭代由 research-round 指导，顺序固定，Agent 不在步骤之间请用户批准。（1）查来源：先取账本中留存且仍适用的资料，再按 research-sources 补检缺口；理由分外部依据、本地诊断、自身推测三类，工程修复不需论文（<Ref id="research-round/SKILL.md#sources-first" />）。（2）写假设五样：经济理由、来源证据、一个比较维度、网格、适用条件（<Ref id="research-round/references/hypothesis.md#five-items" />）；父 parent 可为谱系中任一完整候选，比较对照 control 分别声明（<Ref id="research-round/SKILL.md#parent-and-control" />）。（3）发布候选：改动后的源码经 <Ref id="ledger.publish_candidate" /> 写入账本，得到 strategy_id@revision。（4）原生预检与独立审查：用锁定引擎 engine 与实际运行环境 runtime image 跑 purpose=precheck 的试验，核构造、订单接口、因果时钟、就绪与触发后活动；另一个独立 Agent 审源码四项并经 <Ref id="registration.record_review" /> 只追加入账；失败即修复、重新发布与重预检（<Ref id="research-round/references/strategy-authoring.md#precheck-and-review" />）。（5）登记并锁定：经 <Ref id="registration.register" /> 在一个写事务里核对登记体与执行身份并写成不可变登记证据；每个网格点源码缺少同源码、同运行环境、同输入且通过的预检与审查时拒绝（<Ref id="registration.require_precheck" />）；网格点一次性消耗，无效与中断同样算消耗，重试另登记 retry_of（<Ref id="table:registration_attempt" />）。（6）回放：经 <Ref id="registration" /> 对每个网格点各跑一次 purpose=research 的试验，产生运行；网格点已被消耗、源码或输入身份不符即拒绝；改网格、源码或意图即新登记（<Ref id="research-round/SKILL.md#run-the-grid" />）。（7）审计与资格：运行环境内的独立审计器只对账不重算，不通过即运行无效；实质活动与可比资格都通过才给经济反馈，零成交只诊断原因、不记亏损、不改优先级（<Ref id="research-round/references/feedback.md#availability-first" />、<Ref id="research-round/references/feedback.md#repair-and-retry" />）。（8）读比较证据：经 <Ref id="report.compare" /> 取登记声明的对照，配对块自助给效应、区间、p；无对照、运行未绑定本登记网格、两侧不可比或任一侧无经济证据资格即拒绝并留诊断；不返回裁决。（9）反馈与优先级：结论只在登记的适用条件内成立，写成只追加证据包；按预期效应、不确定性、机制佐证、覆盖、信息价值与成本给后续具体研究动作排优先级，低优先级保留重评（<Ref id="research-round/references/feedback.md#priority-ranking" />）。强制层：步骤顺序与优先级由 skill 指导；(5)(6)(7)(8) 的拒绝由代码强制并写入账本。

### A.1.2　没有终点 [#A-1-2]

两条能力一条由 skill 指导（研究默认持续，运行限制只暂停），一条由代码强制（候选身份与派生资格不受推荐、显著性或达标影响）；它们共同保证循环不会被门槛、计数或裁决终止。输入是账本中的登记、未消耗网格点、研究状态清单与候选表，输出是恢复后的续做与不带分数的候选清单。

<Cap id="A.1.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="研究默认持续：不设达标门槛、总次数或总预算；运行限制只暂停执行">

研究默认持续：不设达标门槛、总次数或总预算；Agent 声明的次数到达只触发复盘（<Ref id="research-round/SKILL.md#review-cadence" />）。用户设置的运行限制（时间、并发、花费）只暂停执行，不改变研究状态：暂停时账本中的登记、未消耗的网格点（<Ref id="table:registration_attempt" />）与研究状态清单保持原样；恢复时 Agent 从账本读回这三样，续做已选路线，不重选路线、不重登记。环境未就绪（运行环境、市场提交、覆盖回执缺失）同样只报告缺哪一段与可运行范围，不缩窄路线、不否定候选（<Ref id="research-start/SKILL.md#readiness-and-blockers" />）。账本给出的研究状态只有事实计数——尝试、审计通过、经济可用、仅诊断、无效、未完成与样本外登记状态——没有停止标志、目标或分数字段（<Ref id="report.research_status" />）。强制层：持续与暂停的行为由 skill 指导；账本不含任何可触发停止的字段由代码强制。

## A.2　划清谁决定什么 [#A-2]

决定权分三层，每层只做一类判断。代码判定事实：这次回放是否有效、是否有经济证据资格、比较读数是多少；它不判好坏，不返回通过或失败。Agent 在用户选定的研究路线 research line 内决定一切研究动作——假设 hypothesis、研发父版本 parent、比较对照 control、研究优先级 research priority——并在入口与复盘 review 时给综合推荐 recommendation。用户决定研究路线、认可与上线、样本外 out-of-sample 验证的发起，以及一切需要授权的事。三层之间只传账本 ledger 里的登记 registration、运行 run 记录与读数 reading；账本没有分数、裁决或状态字段。代码层由信任边界函数强制，Agent 层由 research-round 与 research-start skill 指导并以 eval 校验，用户层在产品之外发生、由 skill 规定 Agent 停下等待。

<Steps>

<Step>

用户从 Agent 给出的推荐与选项中选研究路线，或指定历史候选、模板、人造根；选定前 Agent 不登记不回放。

</Step>

<Step>

Agent 在路线内提假设、选父版本与对照、写源码（含仓位等设计变量）、登记并回放，不逐项请用户批准。

</Step>

<Step>

代码对运行做完整性审计与经济证据资格判定：无效只存原因，零成交或缺匹配记录只留诊断。

</Step>

<Step>

代码对有资格的两侧运行给配对检验读数：效应、区间、p 与登记时声明的检验条件，不返回通过或失败。

</Step>

<Step>

Agent 读读数写反馈、更新研究优先级；按声明的次数复盘并给综合推荐，推荐候选与下一实验父版本分别说明。

</Step>

<Step>

用户看报告判断认可、上线与是否发起样本外验证；凡属授权事项（实盘、破坏性写、改检查、改研究目标）Agent 停下等用户。

</Step>

</Steps>

### A.2.1　产品代码判定的事 [#A-2-1]

两条能力都由代码强制。资格由完整性审计与经济证据资格检查给出，读数由配对检验给出；输入是账本里的运行记录与登记，输出只有事实、原因与登记时声明的检验条件，没有裁决字段。两者都只读账本，拒绝时抛出带拒绝码与缺什么的异常。

<Cap id="A.2.1.1" kind="code" tier="rehearsal" tierLabel="演练证据" tierNote="演练中实际走过：早期曾把零成交运行误读为经济结果，此后由资格检查把零成交只列为诊断，不给区间与 p。" title="有效与可比：审计不过即无效；有真实成交及匹配记录才给改善、区间、p">

由代码强制，分两道判定。第一道是有效性：每次回放结束后，与运行器和策略源码独立的进程在同一运行环境 runtime image 内只读回放报告执行完整性审计 <Ref id="engine.audit" />；审计不通过、审计未运行或运行器非零退出的回放记为无效 invalid。<Ref id="ledger.ingest_run" /> 把无效运行写成状态加逐条原因加原生摘要，读数列一律置空；有效运行才写读数与原生报表行。无效运行不参与任何比较，但仍计入试验 trial 次数（见 <Ref id="G.1.2.1" />）。第二道是经济证据资格 comparability：有效不等于可比。运行须有真实原生成交，且订单、持仓周期、费用、资金费 funding 与账户记录互相匹配，才具备可比资格并可获得改善、区间与 p；零成交或缺匹配记录的运行只留诊断，经济读数置空，也不因账户未变而优于亏损对照。资格由 <Ref id="qualification.assess" /> 在读取时按明确的检查身份算出当前视图，综合审计状态、原始执行捕获与绑定的独立源码审查，附原因，不改写存储的审计结论；报告、候选清单、比较与计数共用这一视图。比较与对照登记前 <Ref id="qualification.require" /> 是硬门：任一侧不可用即拒绝并返回原因，拒绝的形态与序列化见 <Ref id="ledger.refusal" />。两道判定都只回答『这次回放是否有效、是否有资格、为什么』，不评价策略好坏。

由代码强制。比较的唯一入口是只读函数 <Ref id="report.compare" />：输入一个登记 registration 的引用，依次核对——登记声明了比较对照 control；候选运行绑定本登记的网格点；两侧运行都有效且可比；两侧都通过经济证据资格 <Ref id="qualification.require" />；取两侧在交易窗口内的账户日收益且日钟逐日一致——任一项不符即拒绝并留下诊断，拒绝形态见 <Ref id="ledger.refusal" />。核对通过后调用配对块自助检验 paired block bootstrap <Ref id="report.paired" />：取两侧账户日收益的对数差，按登记声明的块长循环分块，两侧共用同一组块起点共同重抽，输出效应（平均日对数差与由之换算的年化差）、基本区间、嵌套学生化区间、单侧 p、块长敏感性与功效近似，并把登记时声明的检验条件（显著性水平与最小改进，均为未校准示例值）一并返回。输出绑定两侧运行与登记的身份。代码不返回通过、失败或采纳字段；比较不写账本，读数与解释由 Agent 作只追加证据留存（见 <Ref id="V.4.2.2" />）。读数 reading 只服务于诊断、推荐与用户判断。

<Cap id="A.2.2.1" kind="skill" tier="rehearsal" tierLabel="演练证据" tierNote="演练中 Agent 自行决定父版本与对照并在源码中改仓位规则，没有请求授权；所选父版本与当时的推荐候选不同。" title="路线内自主推进；仓位、单笔风险、名义上限是 Agent 的设计变量">

## A.3　何时找用户 [#A-3]

找用户只在两类时刻：要用户做选择，要用户看结果。做选择的时刻有两个：候选谱系（lineage）为空或 Agent 判断需要离开当前研究路线（research line），以及执行被运行限制或环境阻断；两者都由 skill 指导 Agent 产出「诊断加选项」并以提问结束等待，用户选定前不登记、不回放、不改范围。看结果的时刻也有两个：复盘（review）给出综合推荐（recommendation），样本外（out-of-sample）验证出了结果；两者都以报告交给用户，Agent 不替用户下结论，也不因此停下循环。阻断事实与样本外读数由代码产出，呈现与等待由 skill 强制；用户的选择经账本写成新的研究路线后 Agent 续做。其他时候 Agent 在路线内自主推进，不逐项请示。

<Steps>

<Step>

Agent 在路线内自主推进（<Ref id="A.2.2.1" />），假设、登记、回放、反馈与优先级都不请示用户。

</Step>

<Step>

出现四类时刻之一时停下：候选谱系为空或需离开路线（<Ref id="A.3.1.1" />）、执行被阻断（<Ref id="A.3.1.2" />）、复盘给出推荐（<Ref id="A.3.2.1" />）、样本外出结果（<Ref id="A.3.2.2" />）。

</Step>

<Step>

按时刻产出对应报告：做选择的时刻给诊断或精确阻断加选项并保留恢复状态；看结果的时刻给推荐或读数并写明取舍、局限与不确定性。

</Step>

<Step>

报告以提问结束交给用户；做选择的时刻等待，期间不登记、不回放、不改开发窗口或范围；看结果的时刻不等待，循环继续。

</Step>

<Step>

用户选定路线或范围后，Agent 把选择写入账本（<Ref id="ledger.select_line" />）并续做；用户只看结果时按研究优先级继续下一实验。

</Step>

</Steps>

### A.3.1　要用户做选择时 [#A-3-1]

两条能力都由 skill 指导（research-start 为主，research-round 的换路线节配合）：输入是账本中的研究状态、候选清单与环境事实（运行环境身份、覆盖与生命周期回执由代码只读产出），输出是诊断或精确阻断加选项清单，以提问结束。Agent 等用户选，不自行开始新路线、不自行缩窄范围；选定后经账本写成新的研究路线。

<Cap id="A.3.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="没有候选谱系或需要离开当前路线时：给诊断与选项，等用户选">

### A.3.2　要用户看结果时 [#A-3-2]

## A.4　划定产品代码的范围 [#A-4]

一项行为放进代码还是 skill，按三条判：只有信任边界（不放进代码 Agent 就会自己给自己打分）与 Agent 做不到的事（原子写、并发、权限）进代码；代码不建与引擎平行的系统，不设通过门槛、固定次数终止或按大类排除；其余研究流程写进按需加载的 skill，用 eval 验证。代码强制的部分在 registration、engine、qualification、report、runtime、market、ledger 各包内以拒绝码落地，只经 cli 命令到达账本；skill 指导的部分不产生任何账本裁决字段。想加的代码先做小范围价值验证再长期保留。

<Steps>

<Step>

提出一项要支持的行为：写明它的消费者与要解的阻断。

</Step>

<Step>

若它是信任边界或 Agent 做不到的事，进代码：由对应函数强制并以拒绝码拒绝，写入只经账本写协议 <Ref id="ledger.write" />。

</Step>

<Step>

若它属于撮合、订单、成交、结算、风控、账户或保证金，交给引擎，代码只配置与读取。

</Step>

<Step>

其余进 skill：只写通用规则，配触发正例、反例与方法用例。

</Step>

<Step>

价值未知的想法先用 skill 规则或工作副本小范围试，有改善才长期保留，否则删除。

</Step>

</Steps>

### A.4.2　代码不建什么 [#A-4-2]

三条都是代码的消极约束：不建平行系统与裁决字段、交易事实全归引擎、研究不碰实盘。它们由运行器交给引擎的配置、容器命令与账本账号权限实现，可在源码、账本模式与运行环境检视中核对。

<Cap id="A.4.2.1" kind="code" tier="rehearsal" tierLabel="演练证据" title="不建平行系统；不设通过门槛、固定次数终止或按大类排除方向">

代码不建与引擎平行的引擎、账本、调度器、策略语言、组件注册器、优化器或推荐分数、贝叶斯或 Thompson 调度、影子账户、知识图谱库；不设通过门槛、固定次数终止或按大类排除方向。只读出口只给事实与读数：候选清单 <Ref id="report.candidates" />、比较入口 <Ref id="report.compare" /> 与研究计数 <Ref id="report.research_status" /> 都不含裁决、分数、排序或停止字段，账本表也没有这类列。推荐、研究优先级 research priority 与复盘节奏由 Agent 按 skill 写进研究状态证据包；回放中的事件全部交给 <Ref id="engine.replay" /> 里的引擎处理。核对方式：账本模式与这三个出口的返回字段里不出现分数、通过、停止类字段。

### A.5.1　强制力分级 [#A-5-1]

强制与提示分开呈现：代码拒绝带拒绝码与写入状态且不入表；skill 层产出的源码审查与来源分类以具名证据包追加，代码只核对其绑定（源码哈希、运行环境身份）与存在性，不复判内容，审查状态与账户审计状态并列显示而不合并为一个裁决。输入是边界函数的参数与证据包，输出是拒绝或追加成功。

<Cap id="A.5.1.1" kind="code" tier="verified" tierLabel="已验证" title="代码契约与引擎原生行为能强制">

本能力规定什么能被强制。能强制的只有两类：代码契约与引擎原生行为。代码契约包括：账本写入核对不成立即拒绝（<Ref id="ledger.write" /> 单事务整笔成或整笔不成，同 operation_id 重试返回原记录，并发写冲突一方由数据库回滚并拒绝）；网格点一次性消耗（<Ref id="registration.bind" /> 在写试验行的同一事务里把试验绑到一个已登记的网格点，<Ref id="table:registration_attempt" /> 使一点只能被消耗一次，无效与中断同样算消耗，重试须另登记并写 retry_of）；运行环境按摘要钉死（<Ref id="runtime.resolve" /> 把标签或摘要引用解析为镜像注册表内唯一的清单摘要并读出身份，身份不能手写）；执行字节必须等于登记记录的源码哈希。引擎原生行为包括撮合、订单状态、风控与账户状态：<Ref id="engine.replay" /> 按账户契约配置引擎并把数据流送入回放节点，之后这些状态由引擎组件持有，策略源码不能改写，消费条数不等于回执总数即整次失败。强制的唯一形态是拒绝：抛出 <Ref id="ledger.refusal" />，带大写蛇形拒绝码、缺失项 missing、期望契约 expected 与写入状态 write_status（not_written 或 unknown＋operation_id），命令行据此打印并以非零退出码结束；拒绝码的取值由抛出它的边界函数在各自的 refusals 中定义，本节不维护码表。拒绝只说明缺什么，不给绕过办法，不展开底层数据库错误文本；拒绝不是记录，不写入任何表。演练中登记太晚、网格点已消耗、源码与登记哈希不符三类拒绝均由代码返回拒绝码，Agent 以新登记或新源码应对。强制层：代码（账本写入与绑定在账本事务内，撮合与账户在引擎内）。

### A.5.2　信任的来源与上限 [#A-5-2]

信任来源由数据库的内容寻址与提交历史承担，代码只负责从字节派生身份并逐项核对；时间先后账本内看提交顺序、对外看时间凭证。上限由账号模型决定：权限与校验只约束经认证的会话，故只是留痕保证；篡改的发现由只读账号按精确版本整体复核事后完成，只报发现不写记录。

<Cap id="A.5.2.1" kind="database" tier="verified" tierLabel="已验证" title="信任来自内容身份">

信任不来自账号或承诺，来自内容身份 content hash：相同字节同一身份，不同字节不可冒充。本能力列出账本依赖的全部身份及其来源。(1) 账本提交哈希：每次写入一个提交，Dolt 以内容寻址的 Prolly 树给出根哈希，根哈希相同即数据相同。(2) 候选身份：源码精确字节的 SHA-256，在库内派生，引用名 strategy_id@revision（<Ref id="table:candidate" />）。(3) 运行环境身份：镜像清单摘要与平台，由 <Ref id="runtime.resolve" /> 从镜像注册表读出，再由 <Ref id="runtime.inspect_runtime" /> 在隔离容器内运行探针核对契约、源码路径与有效配置哈希自洽；不能手写。(4) 封存产物身份：证据包内每个文件的原件字节与由字节派生的哈希、长度（<Ref id="table:evidence" />），读回时逐文件重验。(5) 执行身份：试验行在子进程启动前写下用途、源码哈希、运行环境摘要、合约集与窗口（<Ref id="table:trial" />）；运行行记有效配置哈希、输入身份与读数代码版本（<Ref id="table:run" />）；输入身份含钉住的市场提交（<Ref id="market.resolve_commit" />）与按 AS OF 派生的成员时间路径（<Ref id="table:universe_month" />）。时间：写入时间由服务器触发器填，Agent 不能提供；账本内先后由提交顺序证明，dolt_history_\<t> 给每行每次提交的值与提交时间；对外先后（如样本外登记早于窗口起点）由 RFC 3161 时间凭证证明（<Ref id="table:witness" />，离线验证走 <Ref id="ledger.token_time" />），凭证只证明记录当时已存在，不证明唯一。强制层：数据库（内容寻址与提交历史）与代码（身份派生与核对）。
