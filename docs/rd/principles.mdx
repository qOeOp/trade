# 14　总则：先看全貌：研究循环怎么转，哪些事由你定，哪些由 Agent 定，哪些交给代码检查。

<p className="rd-translation-note">English translation pending: this page shows the Chinese source text.</p>


这一章排在全书最前面，紧接核心概念表。后面各章讲每一步具体怎么做，这里只回答两件事：研究循环怎么转；你、Agent 和代码各自决定什么。研究循环没有终点：先在入口选一条研究路线（你选定的研究方向），再在路线里反复试验，隔一段复盘一次；你随时可以看。

决定权分三层。你决定研究方向和一切需要授权的事；Agent 在你选定的路线里决定全部研究动作，不逐项问你；代码只在步骤之间核对事实，比如这次回放有没有效、能不能当比较证据，但不判断好坏、不决定下一步。三层之间只通过账本传东西，账本是唯一长期保存的研究记录。

举个例子：全池 RSI 演练里，你选定了 RSI 路线，并决定保留原来的币池和窗口。之后十个假设都由 Agent 自己提、自己登记、自己回放，没有一个逐个问过你；但涉及数据约定、检查边界和本机资源的改动，它都停下来问过你，拿到明确授权才做。

## 14.1　说清循环怎么转 [#A-1]

研究循环由入口、迭代、复盘、观察四种活动组成，所有产出都写进账本，循环本身没有终点。

<Steps>

<Step>

入口：Agent 从账本读回研究做到哪了，在所有经济证据可用的候选里给出推荐和几条路线选项；你选定一条研究路线后进入迭代。

</Step>

<Step>

迭代：Agent 在路线里按固定顺序反复试验，从查来源、提假设一直做到反馈和排优先级。

</Step>

<Step>

复盘：试验次数或进展到了 Agent 事先声明的节奏就复盘、给推荐；之后默认回到迭代，只有要换路线才回入口让你选。

</Step>

<Step>

观察：你随时可以读报告和研究状态，也可以发起样本外验证，但这不改变循环走向。

</Step>

<Step>

循环不设达标线、总次数或总预算；运行受限只是暂停，所有完整的版本都留作候选。

</Step>

</Steps>

<a id="A-1-1" />

迭代里每一步都是 Agent 照 skill（写给 Agent 的书面工作规程）去做的；代码只在步骤之间做检查，不决定下一步。

### 路线里一次迭代按固定九步走，步与步之间不请你批准 [#A-1-1-2]

在路线里，每次迭代都按同一个顺序走：查来源、写假设、发布候选、预检和独立审查、登记、回放、审计与资格、读比较证据、写反馈并排优先级。顺序和优先级靠 skill 指导；登记、回放、审计与资格、读比较证据这四步的拒绝由代码强制，并写进账本。

顺序固定，每一步都有前一步的产出可查：没审查过的源码登记不了，没登记的不能回放，没有对照的拿不到比较。步间不请批，是因为路线里的研究动作本来就归 Agent，一步一问只会拖慢研究。

<div className="rd-example">

全池 RSI 演练里，H06 放大单笔预算后结果比 H05 差，Agent 据此提出 H07：按已知的历史资金费方向过滤新入场。H07 照样走完九步：源码审查在登记之前，登记在研究回放之前。十个假设都是这样推进的，没有一步单独问过你。

</div>

1. 查来源：先用账本里留着、仍然适用的资料，缺的再去外部查。理由分三类：外部依据、本地诊断、自己的推测；纯工程修复不需要论文。
2. 写假设：写清五样，即经济理由、来源证据、检验条件（有对照时）、网格、适用条件。父版本可以是谱系里任一完整候选，比较对照另外单独声明。
3. 发布候选：改好的源码写进账本，成为一个带版本号的候选。
4. 预检和审查：用锁定的引擎和实际运行环境短跑一次预检，查构造、下单接口、时钟有没有偷看未来、就绪和触发后的活动；再由另一个没参与编写的 Agent 审源码四项并追加入账。不通过就修，重新发布、重新预检。
5. 登记：在一次写入里核对登记内容和执行身份，锁成不可改的登记证据。任何一个网格点的源码，缺少同源码、同运行环境、同输入且通过的预检和审查，就会被拒绝（<Ref id="registration.require_precheck" />）。每个网格点只能用一次，无效和中断的也算用掉；要重试就另行登记，并注明重试的是哪一次。
6. 回放：每个网格点各跑一次研究回放，产生运行。网格点已经用过、源码或输入对不上，都会被拒绝；改网格、改源码或改意图，都要重新登记。
7. 审计与资格：运行环境里的独立审计器只对账、不重算，不通过就判这次运行无效。实质活动（确实有成交）和可比资格都过了，才给经济反馈；零成交只诊断原因，不记亏损，也不改优先级。
8. 读比较证据：只和登记时声明的对照比，用配对的分块自助法给出效应、区间和 p 值（<Ref id="report.compare" />）。登记没有对照（比如根）时，它如实回答没有可比的，指向单运行报告；对照运行不存在、运行不属于这次登记的网格、两边不可比，或任一边没有经济证据资格，都会被拒绝并留下诊断。它不给结论。
9. 反馈与优先级：结论只在登记的适用条件内成立，写成只追加的证据包。再按预期效应、不确定性、机制佐证、覆盖、信息价值和成本，给接下来的具体研究动作排序；排在后面的保留，以后重新评估。

### 写完报告和优先级不算做完，Agent 在同一回合接着跑下一个实验 [#A-1-1-3]

在路线里，Agent 写完报告、解释、推荐、复盘或优先级，都不算这一回合做完。优先级记进账本后，它在同一回合里接着做下一个实验：发布候选、预检、独立审查、登记、回放。只有三种情况会结束回合：碰到要你授权的事，路线该换了，或者你本人打断。

报告和优先级是循环里的一步，不是交付物。停在这里等你说「继续」，等于每一步都要你批准，研究就断成一段一段。宿主的目标模式能让回合之间也不停，但只有你能开，Agent 开不了；回合内不停，是 Agent 自己能守住的部分。

<div className="rd-example">

比如一条路线的根第一次回放有了经济证据，Agent 写好报告、interpretation 和 priority 后，不问「要不要接着做」，而是直接导出并发布排第一的子候选，跑预检、请另一个 Agent 审源码、登记，再回放。

</div>

## 14.2　划清谁决定什么 [#A-2]

决定权分三层：代码核对事实，Agent 做路线里的研究决定，你定方向和需要授权的事。

<Steps>

<Step>

你从 Agent 给的选项里选研究路线或起点候选；你选之前，Agent 不登记、不回放。

</Step>

<Step>

Agent 在路线里提假设、选父版本和对照、写源码、登记并回放，不逐项请你批准。

</Step>

<Step>

代码审计每次运行、判定能不能当经济证据，对可比的两个运行给出检验结果，但不说通过或失败。

</Step>

<Step>

Agent 读研究状态，追加研究优先级等判断，按节奏复盘并给综合推荐。

</Step>

<Step>

你看报告决定认不认可、要不要做样本外验证；遇到需要授权的事，Agent 停下等你。

</Step>

</Steps>

### Agent 决定的 [#A-2-2]

Agent 读研究状态，产出源码、登记和判断；代码只给绩效指标和计数，不下结论。

<a id="A-2-2-1" />

**路线里的研究动作由 Agent 自定；仓位和风险上限是它的设计变量，不是你的约束**

在你选定的路线里，Agent 自己提假设、选父版本和比较对照、排研究优先级，不逐项请你批准。仓位、单笔风险和名义上限也由它定：规则写在策略源码里，下单数量由引擎按账户状态算出。这条由 skill 规定，并用评测用例检查 Agent 是否照做。

这些都是研究设计的一部分，Agent 需要能自由调整才能找到更好的版本。把它们当成你的约束，等于凭空给研究加了限制，也会让人误以为改它们要你点头。

<div className="rd-example">

全池 RSI 演练里，H03 的父版本是 H02，而当时被推荐的是 H01；H08 的父版本是 H07，对照却是同样 100 预算的 H05。单笔预算从 100 改到 500、又改回 100、再改到 2000，都是 Agent 在源码里改的，没有问过你。推荐和反馈里也不能把这个预算说成你定的限制。

</div>

1. 父版本可以是谱系里任一完整候选，亏损或不显著的照样能往下派生。
2. 对照必须有经济证据资格，和父版本分开声明，两者的理由都写进登记。
3. 优先级按预期效应、不确定性、机制佐证、覆盖、信息价值和成本排具体动作；代码不给优先级。
4. 仓位规则写在源码里，不另设一个名义上限去模仿保证金；资金使用率从报告里读。
5. 改这些设计变量不需要授权，也不能在推荐或反馈里说成是你的约束。

<p className="rd-note">演练中 Agent 自行决定父版本与对照并在源码中改仓位规则，没有请求授权；所选父版本与当时的推荐候选不同。</p>

### 用户决定的 [#A-2-3]

你的决定在产品之外做出，账本不记这类状态；skill 规定 Agent 遇到这些事要停下来等你。

<a id="A-2-3-3" />

**实盘、破坏性写、改检查、改研究目标或动宿主进程，Agent 一律停下等你授权**

遇到下面这几类事，Agent 停下来向你说明，等你决定，不自己做，也不绕过去：实盘交易、交易所连接或交易凭据；破坏性写入（比如清空账本、删改已发布的记录）；放宽或收紧任何拒绝和审计检查；改你的研究目标（最大回撤上限和最低年化）；结束宿主上的进程或改宿主配置，比如回放卡在 Docker 的凭据助手上时。这条由 skill 规定，并用评测用例检查。

这些事要么动真钱，要么会毁掉已有记录，要么会改变「什么算合格」的标准，要么会动到你机器上不归研究管的东西。尤其是检查：Agent 为了让自己的结果过关去改检查，就等于自己给自己打分。

<div className="rd-example">

全池 RSI 演练里遇到过上下架、中文原生身份、内存不足、原件容量这些真实阻断，都是修代码、发布新运行环境或新源码，再重新登记解决的，没有放宽任何一项检查。大原件要分块保存，也是另外拿到了你的授权才做的。

</div>

1. 实盘交易、交易所连接、交易凭据：研究从不使用。
2. 破坏性写入：重置或清空账本，改写或删除已发布的记录、封存的产物、备份、运行环境镜像、规范数据输入和历史回执。
3. 检查：放宽或收紧代码、测试、配置或 skill 里的任何拒绝与审计检查，包括为了通过一个失败的检查。
4. 宿主：结束宿主进程、改宿主配置（比如 Docker 的凭据助手）。
5. 被检查挡住时，正确做法是修源码或代码，发布新候选或新运行环境，再重新登记，而不是改检查。
6. 要加新的产品代码，先说明谁会用它、它解决哪个阻断、预期改善什么、什么情况能证明它没用。不在这份清单上的事（包括仓位这类设计变量）不需要授权。
