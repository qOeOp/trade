# 代码设计：命令行

`cli/`　声明的命令行接口：名词 动词子命令，每条命令一条连接、输出 JSON、拒绝带代码与写入状态。账本的唯一写入口。每条命令的 `--help` 是它的契约（参数含义、读什么、写入什么、返回什么与主要拒绝）；skill 只说何时、为何用它，不复述 help。

每个函数一条：签名、用途、参数、返回、期望行为、拒绝码、使用的别处定义、关联章节与参考资料。

### `candidate_export` [#def-cli-candidate_export]

把一个候选的源码导出到临时工作目录，同时写入工作目录说明 AGENTS.md 与文件头模板 strategy-header.md

```python
def candidate_export(
    profile: db.LedgerProfile,
    candidate: str,
    output: str,
    at: str | None,
) -> dict
```

<TypeTable type={{ "profile": { type: "db.LedgerProfile", description: "cli.main 按 --ledger 解析的研究账本档案；命令以读账号打开连接" }, "candidate": { type: "str", description: "引用名 strategy_id@revision" }, "output": { type: "path", description: "尚不存在的文件路径，须在平台临时根之下" }, "at": { type: "str | None", description: "账本版本；缺省取头提交" } }} />

**返回**　\{candidate, source_sha256, path, bytes, ledger_commit, notes, missing_templates\}；notes 是写出的说明文件，missing_templates 是不在的模板

**期望行为**

1. 核对 output 不存在且位于临时根之下
2. 给出 at 时经 ledger.read_as_of 取只读版本连接；ledger.read_candidate 取字节并核对存储哈希
3. 原样写出字节（不改编码、不加头尾），写后重读文件哈希须等于 source_sha256
4. 返回路径与哈希；该副本是派生新候选或无产品工作树重放的起点
5. 在同一目录写 AGENTS.md：由 CLI 包内的 cli/templates/workdir-agents.md 填入候选引用与下一步命令；Agent 进入该目录工作时读到它。
6. 在同一目录写 strategy-header.md：CLI 包内 cli/templates/strategy-header.md 的原文。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_CANDIDATE` | strategy_id@revision 在该版本不存在 |
| `PATH_EXISTS` | 目标文件已存在，或其目录里已经有 AGENTS.md 或 strategy-header.md |
| `NOT_TEMPORARY_PATH` | 目标不在平台临时根之下 |
| `LEDGER_CORRUPT` | 存储字节或写出文件的哈希不符 |

Agent 读候选清单的唯一命令行入口：全部候选的身份、父与改动、登记尝试及其运行状态与经济证据可用性，可按账本版本读历史

```python
def candidate_list(profile: db.LedgerProfile, at: str | None) -> dict
```

<TypeTable type={{ "profile": { type: "db.LedgerProfile", description: "cli.main 按 --ledger 解析的研究账本档案" }, "at": { type: "str | None", description: "可选账本版本：提交哈希或标签；None 读当前" } }} />

**返回**　JSON：\{ledger_commit, checker: \{check, metrics_revision, source_sha256\}, candidates: [\{strategy_id, revision, source_sha256, entry_class, runtime_contract, description, parent_strategy_id, parent_revision, difference, created_at, attempts: [\{bundle, trial_id, run_status, availability\}], valid_evidence\}]\}；原样转发 report.candidates 的结果，不加分数、排序或资格标记

**期望行为**

1. 解析 ledger 为账本档案 profile；本命令不自开连接，只读连接由 report.candidates 经 ledger.read_as_of 按 at 打开；at 原样传入，不在命令层解析版本。
2. 调用 report.candidates(profile, at)，取回 \{ledger_commit, checker, candidates\}。
3. 以 JSON 一次性输出；拒绝时按 cli.main 的统一形态输出拒绝码、缺什么与写入状态（恒为未写）。
4. 全程只读；推荐理由与解释由 Agent 另以证据包追加，不在本命令写。

| 拒绝码 | 条件 |
|---|---|
| `UNKNOWN_REF` | at 解析不到账本里的提交或标签（由 report.candidates 抛出，原样转发） |
| `SCHEMA_MISMATCH` | 所读版本的账本模式版本与当前代码不一致或账本未初始化（转发） |
| `LEDGER_CORRUPT` | 尝试引用的候选在同版本候选表中缺失，或 run 指向不存在的 trial（转发，指明首个不一致行） |

<TypeTable type={{ "profile": { type: "db.LedgerProfile", description: "cli.main 按 --ledger 解析的研究账本档案；以读账号打开" }, "candidate": { type: "str (strategy_id@revision)", description: "候选引用" }, "at": { type: "str | None", description: "账本提交或标签；缺省读最新提交" } }} />

**返回**　\{candidate, strategy_id, revision, source_sha256, entry_class, runtime_contract, description, parent, difference, created_at, ledger_commit\}

**期望行为**

### `ledger_service` [#def-cli-ledger_service]

启动、停止、查看账本数据库服务

```python
def ledger_service(
    profile: db.LedgerProfile,
    action: str,
) -> dict
```

<TypeTable type={{ "profile": { type: "db.LedgerProfile", description: "cli.main 按 --ledger 解析的研究账本档案" }, "action": { type: "enum start | stop | status | check | run", description: "动词；run 与 check 用于 compose 管的服务" } }} />

**返回**　\{action, running: bool, pid, address, branch, ledger_commit\}；stop 只返回 running=false；check 返回 ledger_commit 与 market_schema；run 在服务退出后返回 server_exit

**期望行为**

1. start：核对服务目录的配置里有该账本数据库，否则 LEDGER_NOT_INITIALIZED；已在运行则返回现状，不重复拉起。
2. start：按档案的地址与数据目录拉起数据库服务进程并写 pid 文件。
3. start 后以读账号经 ledger.read_as_of 读当前提交；读不到即停掉服务并 SERVICE_START_FAILED。服务进程未在时限内接受连接即 LEDGER_START。
4. stop：按 pid 文件发终止信号，等待退出后删 pid 文件；没有 pid 文件返回 running=false。
5. status：探活并返回地址、branch 与当前提交；连接失败返回 running=false，不算拒绝。
6. 服务配置里没有 socket 的服务由 compose 管（docs/plans/ledger-compose-service.zh.md）：经本机回环的 TCP 连接；start 只等它接受连接，读不到账本也不停它；stop 拒绝为 SERVICE_MANAGED。
7. run（compose 的 ledger 服务）：前台运行 Dolt。没有服务配置时只在服务目录、数据目录和档案目录都空时自举：先装 DoltHub 密钥，再从公开副本克隆账本和市场库（远端分支建成本地分支），核对 schema 版本和提交测试，建 root（含 'root'@'%'）和各库账户，最后写服务配置和两个档案；失败就删掉自己建的东西。已有服务配置时每次启动核对提交测试组、记录的库和 schema 版本，并补齐 'root'@'%'。
8. check：以读账号读账本和市场库，schema 版本都对才成功；compose 拿它做健康检查。

| 拒绝码 | 条件 |
|---|---|
| `LEDGER_NOT_INITIALIZED` | start 时服务目录的配置里没有该账本数据库 |
| `SERVICE_START_FAILED` | 服务已起但读不到账本（附下层拒绝码） |
| `LEDGER_START` | 服务进程未在时限内接受连接或已退出（转发自 ledger.start_service） |
| `SERVICE_MANAGED` | stop 一个 compose 管的服务 |
| `BOOTSTRAP_REFUSED` | run 没有服务配置，但服务、数据或档案目录不空；什么也不改 |
| `BOOTSTRAP_FAILED` | run 的自举中克隆失败；已删掉自举建的东西 |
| `DOLTHUB_CREDENTIALS` | run 首次自举时没有 DoltHub 密钥 |
| `SERVICE_CHECK_FAILED` | run 核对不过：提交测试组、记录的库、schema 版本或提交测试，或服务配置带 socket |

2. 调用 registration.validation_register 写登记并取凭证；拒绝原样以 ledger.refusal 形态输出，不改写拒绝码。
3. 凭证 status=failed 时登记仍在，next_actions 指向 cli.ledger_witness，并提示窗口起点前未补到凭证的登记在绑定时被 REGISTRATION_TOO_LATE 拒绝。
4. 只登记，不回放，不做任何经济判断；是否发起由用户决定。

| 拒绝码 | 条件 |
|---|---|
| `CANDIDATE_UNKNOWN` | candidate 无法解析为已发布的候选 |
| `DESIGN_INVALID` | 检验条件字段缺失、多余或取值非法 |
| `WINDOW_INVALID` | 时间不是 UTC，或起点不早于终点 |
| `REGISTRATION_TOO_LATE` | 非重试登记的窗口起点不晚于服务器登记时间 |
| `RETRY_NOT_ALLOWED` | retry_of 不满足重试条件 |
| `CONCURRENT_WRITE` | 并发写同格为不同值，后到者回滚 |
