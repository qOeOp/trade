# 运行结果与封存读数

研究、样本外和关线历史回放各封存一个运行。运行行、逐日收益和持仓周期是承诺：只追加；报告读数单独一张表，只有产品的封存命令能写，可以凭指纹重封替换。

[数据库总览](/zh/docs/design-ledger/)

### `run` [#def-table-run]

运行：一次封存的结论。通过的运行存原生报告的指纹，无效的运行逐条列原因；两者恰有其一

<TypeTable type={{ "trial_id": { type: "INT", description: "所属试验", required: true }, "failure_reasons": { type: "JSON", description: "无效原因（JSON 数组）；通过时为 NULL", required: false }, "status": { type: "ENUM('passed', 'invalid') 生成列", description: "passed 或 invalid，由 failure_reasons 是否为空推出（由 `IF(failure_reasons IS NULL, 'passed', 'invalid')` 生成）", required: true }, "fingerprints": { type: "JSON", description: "每张原生报告的语义哈希和行数；复现、重封和读取时用来核对重新生成的报告", required: false }, "sealed_seq": { type: "BIGINT", description: "封存时的 `ledger_head.seq`（触发器写）：不读 Dolt 历史就能给运行排序", required: true }, "op_id": { type: "VARCHAR(160)", description: "幂等操作 ID：同一载荷重试返回原记录；UNIQUE", required: true }, "created_at": { type: "DATETIME(6)", description: "服务器 UTC 时间，BEFORE INSERT 触发器覆盖调用方给的值", required: true } }} />

**键与约束**

- 主键　`trial_id`
- 唯一　`op_id`
- 索引　`sealed_seq`
- 外键　`trial_id` → <Ref id="table:trial">trial</Ref> `trial_id`
- CHECK　`failure_reasons IS NULL OR JSON_TYPE(failure_reasons) = 'ARRAY'`
- CHECK　`(failure_reasons IS NOT NULL) \<> (fingerprints IS NOT NULL)`

**保护与读写规则**

- 一次写入一个事务、一个 Dolt 提交，并把 `ledger_head` 加一；写账号对本表只有 INSERT，`ledger review` 报告任何被改或被删的行（ROW_CHANGED）
- 运行行、首份读数、逐日收益和持仓周期同一提交写入；捕获因超限被拒的运行也写一行无效运行，消耗这次试验
- 原生报告本身是缓存：重新回放到 `/tmp`，按指纹做语义比较（J.6.2.3）

**写入方**　`ledger.trials.ingest_run`、`ledger.trials.ingest_capture_refusal`

**读取方**　`research runs`、`replay report`、`research status`

### `run_reading` [#def-table-run_reading]

读数：一个通过运行当前的一份报告读数。首次封存时写；指标口径变了，`replay reseal` 重放、指纹逐项相同后用当前代码覆盖，旧值留在 Dolt 历史和公开副本

<TypeTable type={{ "trial_id": { type: "INT", description: "所属运行", required: true }, "report": { type: "JSON", description: "封存报告（JSON 对象）：度量、切面与标量", required: true }, "product_commit": { type: "CHAR(40)", description: "算出这份读数的产品代码提交", required: true }, "op_id": { type: "VARCHAR(160)", description: "重封操作的 ID；首次封存时为 NULL（属于运行那次写入）", required: false }, "computed_at": { type: "DATETIME(6)", description: "服务器 UTC 时间，插入和每次更新都由触发器写", required: true } }} />

**键与约束**

- 主键　`trial_id`
- 唯一　`op_id`
- 外键　`trial_id` → <Ref id="table:run">run</Ref> `trial_id`
- CHECK　`JSON_TYPE(report) = 'OBJECT'`

**保护与读写规则**

- 读数层：写账号对本表另有 UPDATE；触发器不允许把读数挪到别的运行
- `ledger review` 报告不是重封提交改动的读数，以及同时写了承诺行的重封提交（READING_REPLACED_OUTSIDE_RESEAL）
- `ledger review` 还用逐日收益和持仓周期重算利润桥等可推出的值，与读数不符即报告（READING_MISMATCH）

**写入方**　`ledger.trials.ingest_run`（首次）、`replay.reproduce.reseal`（`replay reseal`）

**读取方**　`replay report`、`research status`、`hypothesis compare`
