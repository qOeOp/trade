# F　反馈与研究优先级：一个运行封存之后，Agent 怎样读反馈、决定下一步改什么，何时复盘并给出推荐。

本章定义比较证据之后、下一次登记之前的一段：读一个运行（run）的反馈并拆到部件（F.1），据此排研究优先级（research priority）、写下一假设（F.2），按研究计数触发复盘（review）并给出推荐（recommendation）（F.3）。代码只给只读读口（资格、绩效指标、检验结果、研究计数），口径归 G、R、V 章；判断、排序、推荐由 skill 指导，结果逐条记为判断，只追加入账。代码不设通过门槛、次数停止、方向排除、优化器或推荐分数；换研究路线回入口由用户选。

## F.1　读取反馈：先定资格，再拆部件 [#F-1]

<Steps>

<Step>

</Step>

<Step>

不可用的运行按成因分诊断与修复两路（F.1.1）。

</Step>

<Step>

</Step>

<Step>

登记声明了比较对照（control）时，读检验结果（效应、区间、p 与检验条件，<Ref id="report.compare" />）。

</Step>

<Step>

按 F.1.3 诊断并归类，事实、未证解释与拟改动部件分开写。

</Step>

<Step>

把机制解释、适用与重评条件经 <Ref id="cli.judgment_add" /> 写成 interpretation 判断（主体挂 about，正文只引用不抄写，<Ref id="E.2.1.2" />），交给 F.2 排研究优先级；研究状态由 <Ref id="report.research_state" /> 读时给出。

</Step>

### F.1.1　反馈资格 [#F-1-1]

代码在读取时算出四项资格结论并遮蔽不可用运行的绩效指标，skill 指导 Agent 先读资格、再按成因把不可用运行分为诊断与修复两路。

<Cap id="F.1.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="读任何反馈前先读资格视图，零成交运行只做诊断">

- 经济反馈须四个条件同时成立：实质活动、可比资格（comparability）、原始执行捕获完整、绑定的独立源码审查未失败。
- 实质活动（substantive activity）：有真实原生成交，并有匹配的订单、仓位周期与账户记录。
- 不可用时绩效指标已被代码置空并附原因，Agent 不从原生文件或别的读口补算。
- 零成交或缺匹配记录的运行，按原生订单事件、指标就绪时刻与异常回执把原因归为六类：无信号、指标未就绪、无规则机会、下单未成交、被拒单、异常。
- 这类运行不排在亏损的比较对照之上（账户未变不算优于亏损），不给改善、区间或 p，也不给方向记失败。
- 这次尝试的资格与诊断状态由 <Ref id="report.research_state" /> 读时给出；原因解释经 <Ref id="ledger.add_judgment" /> 写成 interpretation 判断，主体挂该试验（role=about），正文不写资格结论或结果类别（<Ref id="research-round/references/judgments.md#body-references-only" />）。

**输入**　一个运行。

**输出**　经济证据资格（economic evidence availability）：可用或不可用、全部原因与检查身份。

**强制**　资格由代码强制（<Ref id="qualification.assess" />、<Ref id="qualification.mask" />，见 <Ref id="G.4.1.1" />、<Ref id="G.4.1.2" />、<Ref id="G.4.2.3" />）；读法由 skill <Ref id="research-round/references/feedback.md#availability-first" /> 指导，eval research-round/zero-fill-is-diagnostic 检验：把零成交读成零收益或与亏损对照比出正效应即不通过。

| 拒绝码 | 条件 |
|---|---|
| `NO_ECONOMIC_EVIDENCE` | 对无资格运行请求经济报告表。 |
| （比较拒绝，见 <Ref id="V.2.3.3" />） | 比较的任一侧无资格时，比较入口拒绝并只留诊断。 |

</Cap>

<Cap id="F.1.1.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="无效、未完成或预检未过的运行只留修复轨迹，修复后另行登记">

1. 把原因与修复轨迹经 <Ref id="ledger.add_judgment" /> 写成 interpretation 判断，主体挂该试验、登记包或候选（role=about）；正文只引用原件，不写资格结论或结果类别（<Ref id="research-round/references/judgments.md#body-references-only" />）。
2. 改过的源码作为新候选（candidate，<Ref id="C.1.1.2" />），按 <Ref id="research-round/references/strategy-authoring.md#precheck-and-review" /> 重新预检。
3. 经独立 Agent 审查后才登记；源码未改的基础设施失败同样另行登记并写 retry_of。

- 适用三种情形：
- 完整性审计判为无效的运行。
- 原始执行捕获记有失败或未完成阶段的运行（<Ref id="G.4.2.1" />）。
- 原生预检（native precheck，<Ref id="C.6.1.1" />）未通过的源码。
- 不读绩效指标（已被遮蔽）。
- 不给所选方向记亏损，不给未测方向记失败，不改研究优先级，不作复盘判据的依据。
- 试验次数照计（<Ref id="G.1.2.1" />）。
- 已消耗的网格点须另行登记，并以 retry_of 指向实际消耗它的先前登记。

**输入**　无效、未完成的运行或预检未过的源码。

**输出**　一条记原因与修复轨迹的 interpretation 判断，以及另行登记的新候选。

**强制**　拒绝由代码在登记与绑定时强制；记录与修复做法由 skill <Ref id="research-round/references/feedback.md#repair-and-retry" /> 指导，eval research-round/failure-is-repair-not-feedback 检验。

| 拒绝码 | 条件 |
|---|---|
| `SOURCE_PRECHECK_REQUIRED` | 网格源码没有通过的预检审查件。 |
| `SOURCE_PRECHECK_FAILED` | 预检审查件结论为失败或未定。 |
| `GRID_ALREADY_ATTEMPTED` | 已消耗的网格点在原登记下重跑、再次绑定（<Ref id="H.4.2.1" />）。 |
| `SOURCE_ALREADY_EXPOSED` | 重用已执行过的源码而不写 retry_of（<Ref id="H.4.2.2" />）。 |

</Cap>

### F.1.2　绩效指标的读法 [#F-1-2]

代码提供绩效指标与经资格遮蔽的报告表，口径由 R 章定义（<Ref id="R.2.3.1" />、<Ref id="R.3.1.1" />），skill 只定何时读、怎样自算并写进推荐理由。

<Cap id="F.1.2.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺从首个有效根起未经追问即报告这两项并写进推荐理由的演练记录。" title="从首个可用根运行起，每个可用运行都主动读资金使用率与利润来源">

- 从研究路线（research line）里第一个经济证据可用的根节点（root）运行起，每个经济证据可用的运行都主动读，不等用户追问。
- 源码中的仓位或资金预算规则（<Ref id="C.1.4.2" />）一有改动，该改动的运行必读。
- 资金使用率（capital utilisation）：时间加权名义敞口、采样峰值、锁定保证金（margin）与在市时间。
- 资金使用率按 <Ref id="nautilus-report-analysis/SKILL.md#capital-utilisation" /> 从封存敞口表自算。
- 利润来源拆分（profit attribution）：价格盈亏、手续费、资金费（funding）与未平残差，直接读绩效指标，不另行自算。
- 两项对取舍的影响写进 recommendation 判断的理由，正文引用运行与账本提交，不抄数值：利润来源由 <Ref id="report.research_state" /> 读时给出，资金使用率按同一口径从封存敞口表重算（<Ref id="research-round/references/judgments.md#body-references-only" />）。
- 账户收益差连同两项一起解读（<Ref id="V.4.2.4" />）：资金使用率上升带来的收益差不算规则改善，不以放大仓位代替改善。
- 没有敞口表的运行不回答资金使用率，写明缺失；无资格运行的绩效指标已被遮蔽，不读。

**输入**　经济证据可用运行的绩效指标与封存敞口表。

**输出**　注明总体与样本量、引用账本提交的资金使用率与利润来源描述。

**强制**　绩效指标与遮蔽由代码强制；读的时机与用法由 skill <Ref id="research-round/references/feedback.md#capital-and-profit-source" /> 指导，eval research-round/capital-use-read-from-first-root 检验。

</Cap>

<Cap id="F.1.2.2" kind="skill" tier="verified" tierLabel="已验证" title="按入场计划标签 × 出场原因拆贡献，出场原因只读原生记录">

- 交叉表行是入场计划（plan）标签，列是出场原因；每格给闭仓数与闭仓净盈亏，价格盈亏、手续费、资金费分列。
- 仍未平的仓位单列一行，不并入任何出场原因。
- 出场原因只读自引擎原生记录，即持仓行平仓订单（closing_order_id）所带的标签或订单类型。
- 引擎下架结算生成的无标签平仓单按 <Ref id="C.5.2.2" /> 的唯一对应规则只读归属，对应不上就记为未归属。
- 不以盈亏符号、价格水平或距止损止盈的远近推断出场原因。
- 计划统计因缺标签、多标签或不一一对应而被置空时（<Ref id="C.5.2.1" />），该运行不出交叉表，只报原因。
- 交叉表合计须等于产品闭仓拆分，不等就不引用（<Ref id="nautilus-report-analysis/SKILL.md#self-checks" />）。

**输入**　经济证据可用运行经 <Ref id="report.tables" /> 取得的订单表与持仓表。

**输出**　入场计划标签 × 出场原因交叉表。

**强制**　由 skill <Ref id="nautilus-report-analysis/SKILL.md#exit-reason-split" /> 指导，eval nautilus-report-analysis/exit-reason-split 检验。

</Cap>

### F.1.3　诊断顺序、判据与边界 [#F-1-3]

全部由 skill 指导，代码不参与归类、账本不存部件字段；事实读时取，机制解释与部件归类写成 interpretation 判断交给 F.2。

<Cap id="F.1.3.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="按资格、钱从哪来、过程、稳定性、机制五步诊断完才提假设">

1. 资格：实质活动与可比资格是否成立（<Ref id="research-round/references/feedback.md#availability-first" />）；不成立就止于诊断或修复，不进第 2 步。
2. 钱从哪来：读利润来源拆分与资金使用率（<Ref id="research-round/references/feedback.md#capital-and-profit-source" />）；登记声明了比较对照时，同时读检验结果（效应、区间、p 与检验条件，<Ref id="report.compare" />）。
3. 过程：订单漏斗、入场标签 × 出场原因的贡献（<Ref id="nautilus-report-analysis/SKILL.md#exit-reason-split" />）、持仓时长。
4. 稳定性：收益是否只靠某一个平仓年、少数几天或少数合约（<Ref id="R.2.3.2" />、<Ref id="nautilus-report-analysis/SKILL.md#position-structure" />）。
5. 机制：登记时写下的可反驳预测（<Ref id="H.3.1.1" />）是否相符。

- 一个登记网格跑完后开始诊断，前一步写完才进入下一步。
- 五步走完才提下一假设。
- 每步写明引用的登记、运行与账本提交，事实与解释分开写。

**输入**　F.1.1 的资格结论与 F.1.2 的绩效指标。

**输出**　按五步写成的诊断记录（工作副本）；第 5 步得出的机制解释经 <Ref id="ledger.add_judgment" /> 写成 interpretation 判断。

**强制**　由 skill <Ref id="research-round/references/feedback.md#diagnosis-order" /> 指导，eval research-round/diagnosis-order-before-hypothesis 检验：缺步或未走完就提假设即不通过。

</Cap>

<Cap id="F.1.3.2" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺按五部件判据归类的演练诊断记录，以及部件判据可解析的外部依据。" title="用恒等式与五部件判据归类诊断事实，部件不分摊盈亏">

- 恒等式：闭仓净盈亏 ＝ 频次 × 规模 × 单位名义净优势；单位名义净优势 ＝ 毛优势 − 手续费 ＋ 资金费（资金费按方向可正可负）。
- 三个因子相乘，胜率上升与收益下降可以同时出现，不能单看一个因子。
- 毛边际：扣费前不赚，或只靠一个平仓年、少数几天。
- 成本：扣费前为正，被手续费或资金费吃掉。
- 尾部：少数亏损吃掉大部分利润，或回撤相对敞口过大。
- 频率：单笔净优势为正，但计划太少。
- 完整性：审计通过，但独立源码审查或自查发现写法、时钟或保护单问题。
- 一个事实指向多个部件时都写出并说明主次。
- 部件是下一项研究动作的类别，供 F.2 定倾向（<Ref id="F.2.2.1" />）；它不是互相独立的利润来源，不按部件分摊盈亏。

**输入**　诊断事实（报告表与 <Ref id="R.2.3.1" /> 口径的绩效指标）。

**输出**　写进 interpretation 判断正文的部件归类。

**强制**　由 skill <Ref id="research-round/references/feedback.md#five-components" /> 指导；归类只写在 interpretation 判断正文里，账本不存部件字段，代码不校验归类。

</Cap>

<Cap id="F.1.3.3" kind="skill" tier="rehearsal" tierLabel="演练证据" title="诊断只读：自算计数不是试验，结果异常好先查写法">

- 诊断只读封存报告表（<Ref id="report.tables" />）与资格视图。
- Agent 自算的未成交计划价格触及、代理信号计数、反事实机会计数都不是试验（trial）：不写成交，不转成胜率、期望或盈亏，也不进比较。
- 要知道一处改动的真实效果，只能发布新候选、登记并回放。
- 结果异常好时先查写法与审计，再谈经济解释。
- 查三项：成交严格晚于决策 K 线收盘（<Ref id="C.3.1.2" />）、因果时钟、只减仓止损覆盖（<Ref id="G.3.3.1" />）。
- 发现问题就撤回经济解释。
- 经 <Ref id="registration.record_review" /> 追加审查结论，结论绑定源码与运行环境身份。
- 修复后的源码作为新候选登记（<Ref id="F.1.1.2" />）。

**输入**　封存报告表与资格视图。

**输出**　只读诊断结论；发现缺陷时追加审查结论。

**强制**　不产生成交事实由账本写入面强制：Agent 只能追加只引用事实的判断与证据原件（<Ref id="J.2.4.1" />），成交只来自封存回放；读法由 skill <Ref id="research-round/references/feedback.md#read-only-diagnosis" /> 指导，eval research-round/l3-touch-not-pnl 检验。

</Cap>

## F.2　更新研究优先级：决定下一步改什么 [#F-2]

<Step>

</Step>

<Step>

按 <Ref id="F.2.1.1" /> 给研究动作排序，按 <Ref id="F.2.1.2" /> 保留低优先级动作并写重评条件。

</Step>

<Step>

按 <Ref id="F.2.2.1" /> 把部件诊断转成方向倾向，联动改动按 <Ref id="F.2.2.2" /> 合成一个动作。

</Step>

<Step>

按 <Ref id="F.2.3.2" /> 把三路来源汇成候选假设，按 <Ref id="F.2.3.1" /> 写推导记录并选定研发父版本与比较对照（control）。

</Step>

<Step>

经 <Ref id="cli.judgment_add" />（<Ref id="ledger.add_judgment" />）把排序与理由写成一条 priority 判断，父版本与对照挂为 parent、control 主体；机制解释与重评条件写成 interpretation，考虑过的视角写成 search_exposure。

</Step>

<Step>

回 H 提假设，经 <Ref id="registration.register" /> 登记后才回放。

</Step>

</Steps>

### F.2.1　优先级的依据与边界 [#F-2-1]

由 skill 指导、代码不强制：排定下一研究动作的依据，以及哪些结果不构成排除。

<Cap id="F.2.1.1" kind="skill" tier="verified" tierLabel="已验证" title="Agent 按六项依据给下一项具体研究动作排序，代码不排序">

- 研究优先级（research priority）是 Agent 的一条 priority 判断，经 <Ref id="ledger.add_judgment" /> 写入账本，不是产品计算的字段。
- 排序对象是下一项具体研究动作，即一处登记的规则改动及其网格，不是候选的收益名次。
- 依据一：预期效应。
- 依据二：不确定性，即 <Ref id="report.paired" /> 给出的区间、p、块长敏感性与功效近似。
- 依据三：机制佐证，即来源证据与诊断是否支持该机制。
- 依据四：已探索覆盖，即 <Ref id="report.research_state" /> 给出的谱系、解释与搜索暴露里已试过的方向与条件。
- 依据五：该动作的信息价值。
- 依据六：执行成本，包括预检与回放耗时、网格点数。
- 每条排序写明依据；正文只引用所读的候选、试验、登记包和账本提交，不抄绩效指标或计数。
- 排序只借用「预测均值、方差与耗时共同决定下一试验」的思路，判断由 Agent 做。
- 代码不返回优先级、推荐分数或调度建议，也不运行优化器。
- 比较入口因无对照、不可比或任一侧无经济证据资格而拒绝的动作，不进入经济排序，只按 <Ref id="F.1.1.2" /> 修复。
- 排序结果按 <Ref id="research-round/references/judgments.md#what-to-record" /> 写成一条 priority 判断：正文写排序与依据，每个动作的研发父版本与比较对照挂为 parent、control 主体；与 recommendation、review_cadence 分条写，三者互不推出。

**输入**　<Ref id="report.compare" /> 的检验结果、F.1 的部件诊断，以及 <Ref id="report.research_state" /> 给出的当前判断与读时事实（<Ref id="report.research_status" /> 的研究计数、<Ref id="report.candidates" /> 的候选谱系）；数值只来自绩效指标和计数。

**输出**　一条 priority 判断：带依据的研究动作排序，父版本与对照挂为 parent、control 主体，经 <Ref id="cli.judgment_add" /> 追加。

**强制**　由 research-round skill 强制；评测用例 <Ref id="eval:research-round/gross-negative-updates-priority" /> 检查毛边际为负时只更新优先级，<Ref id="eval:research-round/judgment-references-not-copies" /> 检查判断正文只引用不抄写。

</Cap>

<Cap id="F.2.1.2" kind="skill" tier="verified" tierLabel="已验证" title="不显著、亏损、零成交、低频都不构成排除，低优先级动作写重评条件">

- 配对比较不显著、参数亏损或毛边际为负、零成交、低频，都不构成经济排除，也不能据此宣称机制无效。
- p 是原假设成立时出现同等或更极端差值的尾部概率，不是机制有效的概率。
- 没有达到登记时声明的显著性水平与最小改进（未校准示例值），只说明在本次检验条件下没有分辨出效应。
- 零成交和缺匹配记录本身没有绩效指标，只按 <Ref id="F.1.1.1" /> 做诊断。
- 没测过的方向视为未知，不当作更好或更差。
- 低优先级动作保留在 priority 判断的排序里；何时重评（例如哪类新数据、新诊断或新来源到达）、凭什么重评，写进针对相应试验或登记的 interpretation 判断。
- 结果只在登记的适用条件（applicability conditions：源码、改动、参数、输入、窗口、运行环境）内成立，事后不收窄，也不扩大成对机制或方向大类的排除。
- 执行与出场方向始终可研究。

**输入**　检验结果与部件诊断。

**输出**　低优先级动作保留在 priority 判断里，其重评时机与理由写成 interpretation 判断，经 <Ref id="ledger.add_judgment" /> 追加。

**强制**　由 research-round skill 强制，评测用例 <Ref id="eval:research-round/conditions-not-exclusion" />；代码不提供排除视图、方向关闭标志或固定次数停止。

</Cap>

### F.2.2　按部件定改动方向 [#F-2-2]

由 skill 指导：把 <Ref id="F.1.3.2" /> 的部件归类转成带倾向强弱的候选改动方向，联动改动合成一个动作。

<Cap id="F.2.2.1" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺部件倾向提出后经后续登记试验检验的演练记录。" title="五个部件的诊断各给一种方向倾向，倾向不是指令">

- 按 <Ref id="research-round/references/feedback.md#five-components" /> 的诊断给方向倾向；倾向只调整 <Ref id="F.2.1.1" /> 排序里的预期效应与机制佐证两项。
- 毛边际弱：偏向换信号或改进场条件。
- 成本坏：偏向降频、改用挂单、延长持有，或避开资金费（funding）不利的方向。
- 尾部坏：偏向改出场止损或按波动调整仓位。
- 频率低：偏向扩选币规则、扩信号周期或放宽进场。
- 选币规则（排名、前 N、筛选、数量）写在策略源码里，只在环境按月产出的共同可交易范围（universe）内取子集；改选币是一条假设。
- 完整性坏：先修写法，修好的源码作为新候选，重新预检、审查后以 retry_of 登记，不计入经济反馈。
- 执行与出场始终可研究，任何部件诊断都不关闭方向。

**输入**　<Ref id="F.1.3.2" /> 的部件归类。

**输出**　候选改动方向及其倾向强弱。

**强制**　由 research-round skill 指导，代码不强制。

</Cap>

<Cap id="F.2.2.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="同时改变入场与出场的一处改动按一个联动动作登记">

- 一处实际规则改动同时改变入场与出场（例如同一阈值既决定进场又决定离场）时，按一个联动动作登记和描述：一条假设、一个比较维度。
- 联动动作不拆成两条假设，也不给某个部件记独立贡献。
- 由既有规则推导出的量和未启用方法的参数，不算新的改动维度。
- 部件归类描述的是研究动作的类别，不是利润来源归因；利润来源只读报告里价格盈亏、手续费、资金费的拆分。
- 演练中，联动的阈值改动按一个动作登记和说明。

**输入**　一处拟登记的规则改动及其网格。

**输出**　一条假设、一个比较维度的联动动作。

**强制**　代码由 <Ref id="registration.validate" /> 核对每个网格点的父与改动等于登记，不符即拒绝登记；改动粒度的判断由 skill 指导，评测用例 <Ref id="eval:research-round/coupled-change-one-action" />。

</Cap>

### F.2.3　下一假设的来源与推导记录 [#F-2-3]

由 skill 指导：把 F.2.1 的排序、F.2.2 的方向和三路来源写成带推导链、可登记的假设草稿，推导链经 <Ref id="ledger.add_judgment" /> 写成只追加的判断，再回 H 登记。

<Cap id="F.2.3.1" kind="skill" tier="verified" tierLabel="已验证" title="每条下一假设写五项推导记录，只追加、不改写原始登记">

- 第一项：观察事实，只引用试验、登记包和账本提交；绩效指标由 <Ref id="report.research_state" /> 读时给出。
- 第二项：待验证的机制解释，标明未证。
- 第三项：拟改动的部件和那一处规则改动。
- 第四项：与历史候选及其适用条件的关系，即哪些候选在什么条件下试过相近方向、本次条件有何不同。
- 第五项：选定的研发父版本（parent）、比较对照和理由。
- 第一至四项写成一条 interpretation 判断，以 about 挂相关试验或登记包；第五项写进 priority 判断，父版本与对照挂为 parent、control 主体；两条都经 <Ref id="cli.judgment_add" />（<Ref id="ledger.add_judgment" />）只追加，based_on_commit 填所读的账本提交，同 op_id 同载荷重试幂等。
- 回放后的诊断和更正写成新的判断，以 supersedes 指向被更正的那条。
- 已登记的原始计划、理由和来源三分类保持原样，不事后补背书、不改标。
- 代码计数之外考虑过的视角和读过的报告，写成 search_exposure 判断。

**输入**　F.2.1 的排序、F.2.2 的方向和 <Ref id="report.research_state" /> 给出的历史判断。

**输出**　可登记的假设草稿，以及追加到账本的 interpretation、priority 与 search_exposure 判断。

**强制**　登记不可变由账本只追加强制；判断的路线、提交、主体与取代关系由 <Ref id="ledger.add_judgment" /> 核对；记录格式由 skill 指导，评测用例 <Ref id="eval:research-round/later-source-appended-not-backfilled" /> 与 <Ref id="eval:research-round/judgment-references-not-copies" />。

</Cap>

<Cap id="F.2.3.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="三路来源的假设都走完整登记路径，登记后才回放">

1. 写成路线内的候选假设，标明理由属于外部依据、本地诊断还是自身推测。
2. 登记五样。
3. 原生预检与独立审查。
4. 登记后回放。
5. 比较证据。

- 三路来源：报告诊断与反馈（F.1 的诊断和 V 的检验结果）；用户补充的信息或想法；提假设前按 research-sources 检索的论文与可信实践。
- 来源是用户或论文也不免登记，也不直接改源码回放。
- 来源只影响优先级，不证明在本市场有效。
- 没有论文支持的方向仍可低优先级探索。
- 演练中，三路来源的假设都经登记后才回放。

**输入**　F.1 的诊断、V 的检验结果、用户补充的信息或想法、来源研究结果。

**输出**　标明理由类别的路线内候选假设。

**强制**　登记先于回放由 <Ref id="registration.register" /> 和 <Ref id="registration.bind" /> 在代码中强制；其余由 skill 指导，评测用例 <Ref id="eval:research-round/user-idea-registered-as-hypothesis" />。

</Cap>

## F.3　复盘与推荐：次数触发，研究默认持续 [#F-3]

<Steps>

<Step>

读完比较证据、更新研究优先级后，Agent 读 <Ref id="report.research_state" />（命令 <Ref id="cli.research_state" />），用其中的未复盘试验与研究计数对照当前的 review_cadence 判断；未到达则继续登记下一实验。

</Step>

<Step>

到达即复盘：读 <Ref id="report.candidates" /> 的全部候选和各运行的 <Ref id="report.run_report" /> 绩效指标，在全部经济证据可用的候选上综合推荐一版或一批。

</Step>

<Step>

分别写下推荐与取舍（recommendation）、下一实验的父版本与对照及理由（priority）、更新后的复盘节奏（review_cadence），各作为一条判断经 <Ref id="ledger.add_judgment" />（命令 <Ref id="cli.judgment_add" />）追加入账。

</Step>

<Step>

在当前研究路线内继续或调整方向由 Agent 定，然后回到提假设与登记。

</Step>

<Step>

需要换研究路线或选新根时，Agent 给出诊断与选项并以提问结束；用户选定后经 <Ref id="ledger.select_line" /> 写新的路线记录，再登记和回放。

</Step>

</Steps>

### F.3.1　复盘的触发与计数 [#F-3-1]

代码从账本给出只读计数与未复盘试验，Agent 按自己以 review_cadence 判断声明的节奏决定本次是否复盘。

<Cap id="F.3.1.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="复盘所用次数一律读代码给出的研究计数，不自数">

- 计数一律读自 <Ref id="report.research_status" />（<Ref id="report.research_state" /> 的 facts.counts 与之同源），按 <Ref id="R.4.2.1" /> 的口径分列：尝试、审计通过、经济可用、仅诊断、无效、未完成，以及样本外登记状态，并附账本提交。
- Agent 引用这些分项并解释含义；不自评进度，不自己数尝试次数，不按会话记忆计数。
- 可比候选数取经济可用数，经济可用由资格视图 <Ref id="qualification.assess" /> 判定；审计通过数不能当作可比候选数。
- 计数不写进任何判断：判断正文只引用，计数由读口读时给出（<Ref id="research-round/references/judgments.md#body-references-only" />）。
- 读口只读，不返回停止标志、目标或分数，因此本条没有拒绝码。

**输入**　账本中的研究计数（经 <Ref id="report.research_status" /> 读出，或经 <Ref id="report.research_state" /> 的 facts.counts）。

**输出**　Agent 对各分项计数的引用与解释。

**强制**　代码保证计数是账本事实（只读读口）；解释上的偏差由 skill 指导，<Ref id="eval:research-round/counts-read-not-self-assessed" /> 检出。

</Cap>

<Cap id="F.3.1.2" kind="skill" tier="verified" tierLabel="已验证" title="次数节奏只触发复盘，复盘完继续研究，没有停止规则">

- Agent 以一条 review_cadence 判断声明节奏及理由（<Ref id="research-round/references/judgments.md#what-to-record" />），经 <Ref id="ledger.add_judgment" /> 追加入账。
- 节奏可按尝试次数（例如每 5 次尝试，未校准示例值），或按进展事件（例如一批网格跑完、出现实质故障）。
- 节奏可在每次复盘时修改：写一条新的 review_cadence 判断，以 supersedes 指向旧的，正文写修改理由。
- 按尝试次数的节奏以 <Ref id="report.research_state" /> 给出的未复盘试验为准：它取最新 recommendation 的 based_on_commit 之后新增的本路线试验，读时算出，上次复盘时的计数不存。
- 节奏到达只触发复盘；不预设总次数或总预算，没有任何固定次数的停止规则。
- 用户设的运行限制（时长、次数、花费）只暂停执行（<Ref id="research-start/SKILL.md#pause-and-resume" />）。
- 暂停时账本里的登记与未消耗的网格点都保留，恢复后接着做。
- 运行限制不能作为判定方向无效的依据。
- 代码不设停滞计数器，也没有停止字段，<Ref id="report.research_status" /> 与 <Ref id="report.research_state" /> 不返回这类信息。

**输入**　<Ref id="report.research_state" /> 中当前的 review_cadence 判断、未复盘试验与研究计数。

**输出**　本次是否复盘及其理由；需要时一条新的 review_cadence 判断。

**强制**　skill 指导，<Ref id="eval:research-round/review-is-not-stop" /> 检验；代码侧只靠读口不提供停止信息。

</Cap>

### F.3.2　复盘的内容 [#F-3-2]

在全部经济证据可用的候选上综合推荐，并与下一实验的父版本、比较对照分开决定。

<Cap id="F.3.2.1" kind="skill" tier="verified" tierLabel="已验证" title="在截至当时全部经济证据可用的候选上多维综合推荐">

- 比较范围是截至当时全部经济证据可用的候选（candidate，引用名 strategy_id@revision），包括历史候选、非最新版本和其他研究路线上的候选。
- 不只比最近几版，也不等后续候选研究完。
- 范围从 <Ref id="report.candidates" /> 取：全部候选的源码身份、父与改动、每个登记尝试的运行状态与当前经济证据可用性，不带分数和排序。
- 每个候选的绩效指标从 <Ref id="report.run_report" /> 取：已经过资格视图遮蔽，附总体与样本量和局限清单。
- 按 <Ref id="research-start/SKILL.md#option-metrics" /> 的各维综合比较：年化、回撤、夏普、胜率、成本、资金使用率、利润来源、机制解释与不确定性。
- 绩效指标缺失时写原因，不自行补数。
- 可按 <Ref id="nautilus-report-analysis/SKILL.md#pareto-range" /> 自算非劣集描述推荐范围；非劣集不是资格，也不是排序。
- 仅诊断与无效的运行另列，不参加推荐。
- 推荐写成一条 recommendation 判断：推荐候选挂 role=recommended，based_on_commit 填复盘时读的账本提交，经 <Ref id="ledger.add_judgment" />（命令 <Ref id="cli.judgment_add" />）追加入账（<Ref id="research-round/references/judgments.md#what-to-record" />）。
- 判断正文写各维取舍与保留的参考版，只引用候选、试验与账本提交，不抄绩效指标、资格结论或结果类别（<Ref id="research-round/references/judgments.md#body-references-only" />）；这些由 <Ref id="report.research_state" /> 读时附上。
- 推荐不等于样本外验证（validation，只由用户发起，见 <Ref id="X.1.1.1" />），也不等于上线。
- 入口呈现推荐（<Ref id="E.3.1.1" />）时引用本条判据。

**输入**　<Ref id="report.candidates" /> 的候选清单与 <Ref id="report.run_report" /> 的遮蔽后绩效指标。

**输出**　推荐一版或一批，写成一条 recommendation 判断（推荐候选挂 recommended，正文写各维取舍和保留的参考版），经 <Ref id="ledger.add_judgment" /> 追加入账。

**强制**　skill 指导，<Ref id="eval:research-round/all-comparable-candidates" /> 检验；正文只引用由 <Ref id="eval:research-round/judgment-references-not-copies" /> 检验；代码只给不带排序的只读读口。

</Cap>

<Cap id="F.3.2.2" kind="skill" tier="rehearsal" tierLabel="演练证据" title="推荐候选、下一实验的父版本和对照是三项独立决定">

- 三项各写各的理由。
- 推荐候选不必是下一实验的父版本：父可以是候选谱系（lineage，见 <Ref id="table:candidate" />）中任一完整候选（<Ref id="research-round/SKILL.md#parent-and-control" />）。
- 对照必须是经济证据可用的可比运行，但不必是父的运行。
- 下一批动作的排序与理由写成一条 priority 判断，父版本与对照分别挂 role=parent / control（<Ref id="research-round/references/judgments.md#what-to-record" />），经 <Ref id="ledger.add_judgment" /> 追加入账；推荐另记在 recommendation 判断里。
- <Ref id="ledger.add_judgment" /> 不核资格，判断里的对照须经济证据可用是 skill 规则。
- 父与对照及其理由写进登记，由 <Ref id="registration.register" /> 入账，登记内的理由与谱系边由此可查。
- 登记时 <Ref id="registration.validate" /> 分别核对父与对照。
- 根节点不得带对照，由 <Ref id="registration.validate" /> 拒绝。
- 对照经 <Ref id="qualification.require" /> 核资格，不可用即拒绝登记并返回原因。
- 演练记录：登记时选的父与当时的推荐候选不同，对照与父也分别声明。

**输入**　复盘的 recommendation 判断与候选谱系。

**输出**　priority 判断中的父、对照及理由；登记中的父、对照及各自理由。

**强制**　父与对照的合法性由代码在登记时强制（<Ref id="registration.validate" />、<Ref id="qualification.require" />）；推荐与父是否分开由 skill 指导，<Ref id="eval:research-round/recommendation-not-next-parent" /> 检验。

</Cap>

### F.3.3　复盘后的去向 [#F-3-3]

路线内继续或调整由 Agent 定，换路线或选新根交回用户选。

<Cap id="F.3.3.1" kind="skill" tier="rehearsal" tierLabel="演练证据" title="用户选定的路线内，继续或调整方向由 Agent 自主决定">

- 继续当前方向还是调整方向由 Agent 决定，依据写成一条 priority 判断经 <Ref id="ledger.add_judgment" /> 追加入账；不需要用户批准，也不回入口。
- 转向看相对研究价值（按 <Ref id="F.2.1.1" /> 综合排序下一项研究动作），不要求证明旧方向价值归零。
- 旧方向按 <Ref id="F.2.1.2" /> 保留：不显著、亏损、零成交、低频都不构成排除（<Ref id="research-round/references/feedback.md#no-exclusion" />）。
- 旧方向的机制解释、适用条件和重评条件写成 interpretation 判断，主体挂 about 指向相关试验或登记（<Ref id="research-round/references/judgments.md#what-to-record" />）；旧负面结论是当时条件下的判断，不是硬排除（<Ref id="research-round/references/judgments.md#body-references-only" />）。
- 演练记录：路线内方向由 Agent 自主从规模转到过滤，再回到规模；旧参数在新条件下重评结果不利，但仍保留重评。

**输入**　复盘结论与 <Ref id="report.research_state" /> 中未被取代的 interpretation 判断。

**输出**　继续或调整方向的决定及依据，写成 priority 判断（需要时附 interpretation 判断），经 <Ref id="ledger.add_judgment" /> 追加入账。

**强制**　skill 指导；代码不设方向排除。

</Cap>

<Cap id="F.3.3.2" kind="skill" tier="unverified" tierLabel="待验证" tierNote="缺一次演练记录：演练中出现换路线或选新根的需求，Agent 给出选项并等用户选。" title="换路线或选新根时回入口给选项，由用户选定">

1. Agent 回到入口，给出诊断和选项（每个选项附绩效指标与资格），以提问结束。
2. 等用户选择（<Ref id="research-start/SKILL.md#user-selects-route" />），不能用推荐代替用户的选择。
3. 用户选定后，经 <Ref id="ledger.select_line" /> 把起点候选、开发窗口和钉住的市场提交写成新版本的路线记录。
4. 此后才登记和回放；在此之前不登记、不回放。

- 只有在没有候选，或用户明确离开全部路线时，才从模板提根选项（<Ref id="research-start/SKILL.md#root-options" />）。
- 亏损、低优先级、复盘计数、运行限制或运行故障都不会自动触发换路线或选新根。
- <Ref id="registration.validate" /> 要求登记的窗口等于当前路线记录，因此未经新路线记录无法在新路线上登记。

**输入**　复盘诊断与候选绩效指标、资格。

**输出**　给用户的选项与提问；用户选定后的新版本路线记录。

**强制**　登记绑定当前路线记录由代码强制（<Ref id="registration.validate" />、<Ref id="ledger.select_line" />）；是否等用户选择由 skill 指导，<Ref id="eval:research-start/route-change-waits-for-user" /> 检验。

</Cap>
