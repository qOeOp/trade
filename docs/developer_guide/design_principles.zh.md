# 设计原则

## 消息不可变性

消息（请求、响应、事件或命令）一经创建，就不得修改其字段。由此产生的所有权规则，
请参阅[消息总线：消息完整性](../concepts/message_bus.md#message-integrity)。

这一不变量保护了系统所依赖的多项特性：

- **确定性**：每个消费者看到的输入都相同，因而更容易推理、重放和测试系统行为。
- **时间完整性**：消息保留系统发出它时的真实状态。事件和命令始终是事实记录，
  而不会成为状态不断漂移的容器。
- **更安全的并发**：读取方无需通过协调来保护消息载荷，防止其随后被改写。这消除了
  围绕共享状态的一类常见竞态来源。
- **更容易调试**：消息仍然反映原始载荷，因此日志、跟踪、重放工具和死信检查始终有用。
- **可靠的重放与模拟**：重放消息序列会得到与原始运行相同的逻辑输入，从而支持回测、
  事故重建和回归测试。
- **清晰的所有权边界**：组件将传入消息视为输入。如果组件需要不同的表示，就应显式派生
  新的本地状态或创建一条新消息。
- **更好的可审计性**：系统可以回答自己知道什么、何时知道，以及基于这些信息做了什么。
- **更健壮的分布式行为**：序列化消息跨越进程和服务边界时本来就以副本形式传递；采用相同的
  所有权规则，可以使内存模型与这一事实保持一致。
