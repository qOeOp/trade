# Markdown 风格

标准修订版：1

本文档定义 AgentSkills 与采用其本地副本的仓库所共享的 Markdown 基线。维护中的源文件是
AgentSkills 仓库内的 `references/markdown-style.md`。仓库副本应保持逐字节一致；仓库特有的补充内容
应放在单独的本地指南中。

## 语言与扩展

- 使用 [CommonMark](https://spec.commonmark.org/current/) 作为基础规范。
- 表格、任务列表、删除线和自动链接使用 [GitHub Flavored Markdown](https://github.github.com/gfm/)。
- 仅当仓库已有文档说明并支持时，才使用额外的 front matter、Markdown 扩展或渲染器组件。
- 不要引入依赖未记录渲染器扩展的语法。

所链接的规范是参考资料，不是日常前置阅读。只有在本地指南、周边内容和 markdownlint 都无法解决
具体的解析器或渲染器歧义时，才打开它们。

## 强制执行

- 遵循仓库的 `.markdownlint.jsonc` 或等效本地配置。
- 将本标准视为目标风格，将 markdownlint 视为对其机械规则子集的自动执行。
- 本标准与本地配置之间未记录的冲突应视为需要解决的漂移，而非隐含例外。
- 确保仓库 lint 范围内所有人工编写的 Markdown 均通过已配置的 Markdown 检查。
- 不要手动编辑生成的 Markdown；应修改其源并运行生成器。

生成文件、导入的第三方文档和渲染器 fixture 可以使用仓库中已有记录的排除项。

## 标题

- 使用 ATX 标题（`#`、`##`、`###`，依此类推）。
- 将一个 H1 作为首个 Markdown 标题。
- H1 使用标题式大小写。
- H2 及以下标题使用句首式大小写。
- 保持逻辑层级，不要跳过标题级别。
- 每个标题上下各留一个空行。

## 段落与换行

- 段落之间保留一个空行。
- 不要连续添加多个空行。
- 将 100-120 个字符视为软性行长目标。
- 在自然边界处断行；宁可保留稍长的一行，也不要让下一行只剩一到三个单词。
- 必要时允许代码块、表格和长链接目标超过该目标。

## 列表

- 无序列表项使用 `-`。
- 仅在顺序有意义时使用有序列表。
- 有序列表的每个源条目都使用 `1.`，由渲染器提供显示编号。
- 列表缩进和间距应与本地 markdownlint 配置一致。
- 列表前后各留一个空行。

示例：

```markdown
- First item
- Second item

1. First step
1. Second step
```

## 表格

- 表格内容使用 GFM 管道表格。
- 包含首尾管道符。
- 纵向对齐管道符。
- 每列按最宽单元格补齐，并在两侧各留一个空格；这与 Prettier 的默认表格输出一致。
  MD060 检查管道符是否对齐，但忽略单元格内容，因此也接受远宽于实际内容的补齐列。
- 分隔单元格应使用空格补齐（`| ----- |`，而非 `|-----|`）；MD060 同样不检查这一点。
- `normalize markdown table padding` pre-commit hook 会把表格重写为这种形式，无需手工计算字符数。
- 适当时左对齐文本列、右对齐数值列。
- 分隔行应与预期渲染对齐方式一致。
- 除非 Markdown 无法表达所需结构，或仓库已有文档说明需要，否则避免使用 HTML 表格。

示例：

```markdown
| Name  | Value |
| ----- | ----: |
| Alpha |    42 |
| Beta  |    17 |
```

## 代码

- 使用反引号围栏代码块，不使用缩进代码块。
- 每个起始围栏都应指定语言。纯文本或没有更具体语法的输出使用 `text`。
- 记录带围栏的 Markdown 时，使用更长的外层围栏。
- 命令、文件名、函数、类型、环境变量、配置键和标识符使用行内代码。

示例：

````markdown
```rust
fn main() {
    println!("Hello");
}
```
````

运行 `cargo test` 并编辑 `.markdownlint.jsonc`。

## 强调

- 使用 `*italic*` 表示强调。
- 使用 `**bold**` 表示强强调。
- 避免使用没有增加含义的强调。

## 主题分隔线

使用三个连字符：

```markdown
---
```

## 链接与图像

- 使用描述性的链接文本。
- 默认使用行内链接。
- 同一目标在文档中多次出现时，使用引用式链接。
- 避免裸 URL。
- 当仓库渲染器支持时，内部链接保持相对路径。
- 为图像提供有用的替代文本。仅对有意作为装饰的图像使用空替代文本。

## HTML

- 优先使用可移植的 Markdown 语法，而不是原始 HTML。
- 仅当 Markdown 无法表达所需结果，或仓库已有文档说明该元素或组件时，才使用原始 HTML。
- 编辑周边内容时，保留受支持的 front matter、MDX 组件、围栏属性及其他仓库扩展。

## 文件

- 使用 UTF-8 编码。
- 使用 LF 行尾。
- 每个文件以一个换行符结尾。
- 不要留下行尾空白。

## Agent 指南

生成或修改 Markdown 时：

- 对于小范围编辑，应保留周边风格并使用 markdownlint；只有两者都无法解答具体问题时，才加载完整指南。
- 创建文档或大幅重构文档前，只查阅仓库本地 Markdown 指南中的相关章节。
- 除非任务要求变更，否则保留现有文档结构。
- 保持格式与周边内容和受支持的渲染器扩展一致。
- 不要重新格式化无关章节。
- 如果仓库提供了聚焦的 Markdown 检查，请运行它。

## 采用状态

ATX 标题通过 `MD003` 强制执行。重复的 `1.` 有序列表标记和起始代码围栏语言适用于新增或大幅编辑的
内容，但在现有文档完成单独的机械迁移前，`MD029` 和 `MD040` 仍保持禁用。不要仅为迁移这些现有
结构而扩大一次小范围文档变更。
