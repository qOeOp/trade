# 研发长链

研发是一个不停的循环：入口恢复状态并给出综合推荐，用户选研究路线；Agent 在路线内提假设并发布候选，原生预检和独立审查通过后登记并锁定，再回放；完整性审计与实质活动资格决定一次回放算不算经济证据；配对检验给出效应、区间和 p；反馈更新研究优先级，次数触发复盘。所有完整版本都是候选，认不认可由用户看报告后判断。样本外验证由用户发起。

<Mermaid chart={"flowchart LR\n  E[入口：恢复状态与综合推荐] --> H[提假设：候选与来源]\n  H --> P[原生预检与独立审查]\n  P --> N[登记并锁定网格]\n  N --> G[回放：完整性审计与活动资格]\n  G --> V[比较证据：效应、区间、p]\n  V --> F[反馈：优先级与复盘]\n  F --> H\n  F -->|换路线| E\n  V --> T[候选谱系与推荐]\n  T --> E\n  L[策略库：根节点] --> E\n  T -.->|用户发起| X[样本外验证]"} />

一级是章，二级是功能（如何组织组件），三级是组件（如何组织能力），四级是能力。章节页只写规则；每个函数、表、skill 节与 eval 在设计页里逐条写全，章节页通过链接跳转并可悬停预览。能力标验证档位：已验证（有文档依据）、演练证据（在演练中实际走过）、待验证。

## 一、研究怎样开始

<Cards>
<Card href="/zh/docs/entry/" title="1 入口">每次开始研究，或者中断后回来，都从这里进门：读回研究做到哪了，看推荐，选路线。</Card>
<Card href="/zh/docs/library/" title="2 策略库">研究的起点从这里来：把有出处的原版策略或你给的资料写成根，入账后回放一次，拿到第一份报告。</Card>
<Card href="/zh/docs/lineage/" title="3 候选谱系">说清什么算一个候选，以及候选之间怎样靠父版本和改动说明连成一棵棵树。</Card>
<Card href="/zh/docs/strategy-file/" title="4 策略文件">一份策略源码从写出来到能拿去登记，必须守住的几条规矩。</Card>
</Cards>

## 二、一轮迭代

<Cards>
<Card href="/zh/docs/hypothesis/" title="5 提假设">每次回放之前，先想清楚改什么、凭什么、预计会怎样，再把这些写下来锁进账本。</Card>
<Card href="/zh/docs/replay-environment/" title="6 回放环境">每次回放用哪份数据、哪段时间、哪些合约、怎样的账户和撮合，都由代码钉住，策略改不了。</Card>
<Card href="/zh/docs/audit/" title="7 完整性审计与证据资格">回放跑完之后先过两道关：这次回放算不算有效，有效的运行能不能拿来当比较证据。</Card>
<Card href="/zh/docs/report/" title="8 报告">一次运行跑完并通过审计后，把它的成绩算出来、摆出来：有哪些数，谁算，按什么口径，只呈现不裁决。</Card>
<Card href="/zh/docs/comparison/" title="9 比较证据">登记的网格跑完后，回答三件事：候选和对照能不能比，差多少，这个差有多确定。</Card>
<Card href="/zh/docs/attribution/" title="10 绩效归因">比较出结果之后，把两个版本的差拆开：钱从哪来、规模多大、在哪些合约和哪些天、靠哪些交易，再落到具体职责，指向下一个假设。</Card>
<Card href="/zh/docs/feedback/" title="11 反馈与研究优先级">一个运行入账之后，Agent 在这里读反馈、定下一步改什么，登记被复盘停点拦下时复盘并给出推荐。</Card>
</Cards>

## 三、收尾与底座

<Cards>
<Card href="/zh/docs/validation/" title="12 样本外验证：用户发起的一次性检验">你认可一个候选之后，可以在一段登记之后才开始的新行情上，把它只跑一次，照实看结果。</Card>
<Card href="/zh/docs/ledger-runtime/" title="13 账本与运行环境">研究证据存在哪、谁能写、怎么证明没被改动、登记在回放之前，以及回放在什么环境里跑、凭什么能重跑。</Card>
<Card href="/zh/docs/principles/" title="14 总则">先看全貌：研究循环怎么转，哪些事由你定，哪些由 Agent 定，哪些交给代码检查。</Card>
</Cards>
