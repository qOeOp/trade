2026-11-04 用户决定：不买采集服务器，不自采。原服务器采集方案撤销。Mac 上的爆仓记录器已于 06:28 UTC 停止，BTCUSDT、ETHUSDT、SOLUSDT 的 aggTrades 不加实时采集。回测用币安归档，爆仓研究按需用 CryptoHFTData。

## 回测行情

| 数据 | 来源 | 币安缺档时 |
|---|---|---|
| LAST、MARK 分钟 K 线 | 月包，缺的分钟用日包，再用公开 REST | REST 补上 |
| 资金费率 | 月包；没有月包的月份用公开 REST（币安没有资金费日归档，当月全靠 REST） | REST 补上 |
| metrics | 日归档 | 缺的日子留空，`market coverage` 报告 |
| aggTrades | 日归档和前一天，校验编号连续 | 整月不导，成为洞，每月重试一次 |
| 推算报价 | 已存的 aggTrades 按既有规则计算 | 随成交 |

K 线和资金费率保留 REST 补缺。REST 也是币安的公开数据，不算自采，历史抽样和归档一致（[`market-rebuild-from-receipts.zh.md`](market-rebuild-from-receipts.zh.md)）。严格只用归档行不通：

- 当月资金费率没有归档。
- 2026-10-28 的 K 线只有 REST 有。合约池要求月初前连续 30 天有成交，去掉这一天，2026-11 的成员就是空的。

aggTrades 不用 REST 补：它只能回查 48 小时，也不能从原始成交算出币安的聚合编号。

## 独立审阅的处理

审阅提示词是 `market-review-prompt.zh.md`，固定在 `48da8dd2e`，由 Codex 完成。8 条发现都对照代码核实过。

| 发现 | 处理 |
|---|---|
| 记录器连不上也显示健康；Bybit 列表取不到时拖住 Binance | 记录器移除，不修 |
| 恢复时漏了爆仓文件，发布照样成功；spool 按数据日清理 | 恢复手册要求比对文件名；记录器移除后不再清理 |
| 所有输入合约同时缺 MARK 时，60 分钟上限查不到 | 代码如此，改说明文字，不收紧审计。实测 26 个合约的 MARK 最长只缺 30 分钟（2020-01-19、2020-12-17），没有超过 60 分钟的实例 |
| 月份的资金费文件丢了，采集发现不了；月包少一次结算不会问 REST | 恢复手册写明查法。83 个月的文件目前都在 |
| 缺一天会改变合约池 | 规则不变。这是 K 线保留 REST 补缺的原因之一 |
| 从零恢复少 16 个报价月（ETH 12 个、SOL 4 个） | `--quotes-from` 改回 `2020-01`，恢复时自动重算，不用手动步骤；BTC 之前跳过的 12 个月也随之补上 |
| 10-28 缺档挡住后续月份到 12-11 | 下一个已收盘的月全部出齐时，这个月跳过成为洞 |
| `readiness.md` 说补报价会产生新 commit | 改正：截至日不动，不需要新的路线记录 |

服务器相关的部分被上面的决定取代。零成交量分钟的说明错误是已有的诊断发现 20261031-08，单独修。
