# 判断记录取代研究状态清单：存储字段评审

日期：2026-10-17。依据 AGENTS.md「新增存储字段前须经独立子代理评审并记录于 docs/plans/」。

## 决定

研究状态清单作为整份文档逐版写入账本，会抄录账本已有的事实（结果类别、绩效指标、研究计数、资格结论、上次复盘时的尝试计数），由此需要「清单落后时以候选清单为准并补写」的对账规则。决定删除这份文档：

- 账本只存事实与 Agent 的判断。判断逐条一行、只追加，存于 `judgment` 与 `judgment_subject` 两张表。
- 研究状态是读时视图 `report.research_state`：当前判断加读时事实（候选身份与谱系、试验与运行状态、经济证据资格、绩效指标、研究计数）。
- 尚未复盘的试验由 Dolt 提交间差异读时给出，不存。

设计全文见文档站「表结构设计」页 `judgment`、`judgment_subject`，代码设计页 `ledger.add_judgment`、`report.research_state`。

## 评审结论（独立子代理）

批准，附修改；修改已全部写入设计。

| 问题 | 结论 |
|---|---|
| 消费者 | 每种判断都有 Agent 读者：推荐在入口与复盘读，优先级在选下一实验时读，复盘节奏决定是否复盘，解释在写下一假设时读，搜索暴露供 DSR 与样本外多重比较判断。代码只在视图中展示并计算未复盘试验，正文不参与任何判定。 |
| 独立事实 | kind、body、主体、supersedes 都是判断，账本推不出。based_on_commit 推不出：后台入账可能在 Agent 读完、写入之前提交。created_at 按惯例由触发器写服务器时间。上次复盘时的尝试计数改为按 based_on_commit 读时算，不存。 |
| 现有结构能否表达 | 按命名约定的证据包也能做，但引用解析要手写校验器，「每种取最新」要列出并解析全部包，取代关系只能靠代码保证。两张表得到数据库外键与只追加审计。原设计的清单包名还与证据包名格式不符。 |

修改要求：主体引用试验而非运行（覆盖没有运行行的尝试），未复盘按试验算并限定在路线范围；line_bundle 只能是 `research-line-*`，登记包须在 `registration_attempt` 中出现过；supersedes 唯一且同 kind 同路线；based_on_commit 存解析后的哈希且不早于路线包所在提交；写账号对两表只有 INSERT，`dolt_tests` 核对两表的 `dolt_diff` 只出现 added；判断正文只引用不抄写事实，不设结果类别列；删除清单落后规则与两种清单包名约定，旧研究路线的判断与搜索暴露仍计入历史。
