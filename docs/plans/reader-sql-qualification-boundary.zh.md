2026-10-25，用户确认：保留现有只读 SQL 能力；经济证据资格与绩效遮蔽仍由正式读取入口判断；修正文档对权限和整体复核能力的过度表述，不新增命令专用隔离层，不改变现有授权、拒绝、遮蔽或审计检查。

## 当前实现与决定

- `ledger/db.py` 的研究读账号有库级 SELECT，写账号也有 SELECT；`cli.main.ledger_sql` 将查询钉到精确账本版本，并沿用单条读语句检查。保留其诊断和历史核对用途，不删除命令或收紧数据库授权。
- `qualification/availability.py` 的 `assess` 读取运行、封存与源码审查等证据，给出 `economic_evidence_available`；`mask` 在不具备资格时清空绩效字段。原始读数仍在账本中，直接查询不能赋予其经济证据资格。报告的读取口径与所有既有检查保持原状。
- `report.review_all` 检查提交校验、只追加、记录和证据一致性等，不记录或证明每一次历史读取行为。文档删去“整体复核时再查”可以补足读取隔离的保证。
- 当前执行环境中仅禁用 SQL 命令，仍不能阻止直连或内部函数调用。若另需数据保密或不可绕过的读取隔离，需要单独设计凭据与执行边界；本项不增加代理、服务或第二套权限机制。
