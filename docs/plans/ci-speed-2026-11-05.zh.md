# CI 提速：2026-11-05 的测量

`quality` 之前的中位数是 8.4 分钟，其中测试步骤 7.3 分钟（最近 100 次，2026-11-03 至 11-04）。

## 已上线

- #2123 去掉测试步骤的 `PYTHONTRACEMALLOC`。本机 `test_store` 从 121 秒降到 27 秒，`test_commands` 从 118 秒降到 40 秒。泄漏检查不受影响：要看分配位置，在本地带上这个变量重跑该模块。
- #2122 ffmpeg 改用固定版本的 GitHub release。平时只省约 20 秒，主要是不再因 apt 镜像卡住而失败（2026-11-04 失败过两次，其中一次在 `main` 上）。
- #2135 只改 `docs/` 或 `.agents/evals/` 的 PR 跳过测试（用户授权，范围仅限这两个目录）；`main` 上每次提交都跑全量。

## 测过但效果不明显

三组配置并排跑的测试步骤耗时（秒），都已去掉追踪：

| 配置 | 每次耗时 | 中位数 |
|---|---|---|
| 4 并发 | 228、175、237 | 228 |
| 4 并发，去等待，测试库模板 | 224、216、228 | 224 |
| 8 并发，去等待，测试库模板 | 171、146、224、224 | 198 |

- 8 并发（#2125，已关闭）：后来在最新的 `main` 上单独并排跑，8 并发不去等待是 232、243、236 秒，4 并发去等待（#2124）是 152、183、241 秒，看不出 8 并发有收益。
- 同一配置内部能差 60 秒，所以每种配置只跑一次看不出高下；比较时要并排跑，且多跑几次。
- 测试库模板（#2126，已关闭）：`db.init` 占模块总时间 28%，但 CI 上没有可见收益。
- 模块里省下的秒数要除以并发数，才是整体省下的时间。
