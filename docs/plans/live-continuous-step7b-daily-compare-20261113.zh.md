# 连续运行第 7b 步：控制每天自动对照（2026-11-13）

依据：`live-continuous-operation-design-20261110.zh.md` §3.6（每天归档出来后重跑回测，先比 K 线再比决策；
每周对比报告；明显超出回测假设时通知，不自动停）和 §4 第 7 步（无需授权）。7a（#2855）已经给出按交易启动分段的
`live compare` 和 `measures`。本步只做三件事：让控制按时去跑，留下结果，发通知。不改归因、拒绝或运行行为。
初稿经独立子代理评审，结论是修改后通过，五项阻塞都已采纳，见文末。

## 在哪里跑

- Live 控制（`live serve`）新开一个线程 `comparer`。它每个 UTC 小时最多启动一次**对照容器**，从 00:30 起
  （市场导入每天 00:30 UTC 跑一轮，`market/follow.py WAKE`）。对照容器跑 `python -m cli.main live compare-daily`。
- 对照容器是控制的兄弟容器，不是控制里的子进程，因为控制容器只有 768 MB。这 768 MB 由 `live serve`、STOP 等
  `web-command` 子进程和证据探针共用。对照要读整段证据，还要起一个 spawn 的导出进程（pyarrow 和 Nautilus），
  不能在里面跑，否则内存不够时可能杀掉 STOP。
- 对照容器的配置从控制自己的配置抄过来：
  - 控制用 `docker inspect` 读自己的容器，复制镜像、用户、附加组、能力、安全选项和网络；
  - 挂载用 `--volumes-from` 继承：私有根同路径可写，市场目录只读，Docker socket；
  - 自己的内存上限 2 GiB（不含 swap），1 个 CPU；
  - 用完即删（`--rm`）。
- 控制不在容器里时（本机开发），`comparer` 什么也不做。
- 回放的阶段容器仍由 `replay.entry` 创建，用研究回放的限制（`STAGE_MEMORY`）。这个上限是用户 11-11 定的拒绝阈值，
  本步不改，见"风险"。

## 一次对照（`live compare-daily`）

1. **锁**：私有根下的 `compare.lock`，非阻塞。拿不到说明别的对照还在跑（例如第 6 步接管期间两个控制并存），
   本次直接退出。锁由对照容器自己持有，控制退出时不会释放。
   - 全程不持有 `account.lock`，只在读运行状态和写记录时短暂共享读。否则 STOP、维护和发布屏障可能被挡住一小时。
2. **清理**：在锁内删掉
   - 已退出的 `trade-live-compare-*` 阶段容器；
   - `compare-tmp/` 下的旧目录（上次被杀的对照留下的）。
3. **临时目录**：`<私有根>/compare-tmp/<本次>/`，0700，作为 `TMPDIR`。阶段容器由宿主 Docker 按宿主路径挂载，
   所以 `TMPDIR` 必须是同路径挂载的宿主目录。与 Paper 守护进程同样检查：Python 实际用的临时目录必须就是它，
   否则拒绝（Python 在 `TMPDIR` 不可写时会静默退回容器内的 `/tmp`）。
4. **市场**：直接用控制配置里的 `market_root`（`{"root": ...}`，与准备运行读合约条款同一方式），不读档案目录。
5. **对象**：每个 `mode=run`、已经启动过的运行。它要对照的日子是
   `Y = min(结束那天, 昨天)`：正在运行的是昨天；已结束的是结束那天。
   - 有 `Y` 的终态记录（done / failed / empty）就跳过；
   - 记录是 waiting 的，每小时重试。
   - 控制停过几天也不会漏掉已结束的运行。
6. **回放截止**：回放截到 `Y` 的次日 0 点（`--to`）。
   - 运行中的运行，证据一直延伸到此刻，而市场只到昨天。所以证据、分钟结果和订单事件在截止点之后的都不进对照。
   - 资金费率按截止点结算。
   - 7a 的 `--to` 原来只限制汇总窗口，现在也限制回放。
7. **分段**：比**所有**与 `[Y-6, Y+1)` 有交集的交易启动段，每段回放仍从段首 T 开始。
   - 分段之间的汇总按次数相加；不利滑点按成交数加权平均；暂存时长合并后重算中位数和 p90。
   - 一段在截止前不到一整分钟（`LIVE_COMPARE_EMPTY`）时略过。全部略过记 `empty`，表示"没有可比的"，不是失败。
8. **超时**：每段内层 `--timeout-seconds 3600`，`replay.entry` 会自己停掉阶段容器。控制等对照容器最多 6 小时，
   超时后 `docker stop` 它。
9. **阶段容器名**：每次带随机后缀（`trade-live-compare-<run>-<hex>`）。被杀留下的同名容器不会挡住下一次。

## 留什么（执行记录，不进账本）

`runs/<run>/compare.json`，每个运行只留一份，先写临时文件再改名。只在启动过的 `mode=run` 运行下写；
`credentials.py` 对多余条目的检查只针对准备了没启动的运行。内容：

- `day`（Y）、`state`（running / done / waiting / failed / empty）、`code`（失败或等待的拒绝码）；
- `failures`：连续失败的天数；
- `window`、`market_day`、`segments`（每段的编号、窗口、`summary`）；
- `measures`：7 天合并值；
- `unexplained`：未解释的决策差异，最多 20 条（at、class）；`unexplained_count`；
- `look_ahead_suspects`。

几项规则：

- 开始对照前，先写一份 `state=running`。下次进来时如果还是 `running`，说明上次被杀了（例如内存超限）：
  记为 `failed`，`code=stopped`，不会每小时重试下去。
- 完整的 `reconcile.json` 随临时目录删除。要细看时在命令行重跑 `live compare --segment N --to ...`，结果可以重算。

**未解释的决策差异**指 `cause == "unexplained"` 且 `stage == "decision"` 的组。`run_only` / `replay_only` 本来
就是决策阶段。只数决策时间在 `[上次 done 的次日, Y+1)` 之内的，最多回看 7 天，所以同一组不会每天再报一遍。
成交、费用和资金费率的差异进周报。

## 视图和通知（Telegram）

- `live/views.py`：运行视图加 `compare`，就是这份记录。`compare.json` 是符号链接时，与其它记录一样拒绝读取。
  7c 的页面读它。
- `live/notify.py`：
  - `{run}:compare:{Y}`：Y 那份是 done，且有未解释的决策差异。列出条数和第一条的时间。
  - `{run}:compare-week:{Y}`：Y 是星期日，且是 done。列出 7 天的：
    - 未成交入场、部分成交、平均不利滑点；
    - 费用差、权益差；
    - 暂存单数和时长的中位数 / p90；
    - 未解释条数。
  - `{run}:compare-failed:{Y}`：连续失败满 2 天。
  - 关闭条件：已结束、已归档的运行，原来只要消息发完、最后一天之后的日报发出就不再读。现在还要它结束那天的
    对照记录已是终态，或者已过结束后 3 天（例如控制不在容器里、市场一直没覆盖），否则会漏掉结束那天的对照。
- "明显超出回测假设时标出"：本步不设阈值。阈值是新的判断标准，要由用户定；周报只列数字。

## 风险

- **阶段容器的内存上限**：`STAGE_MEMORY = 16g`，是按 62.7 GiB 的工作站定的，没有 `--cpus`。远程主机给 Paper
  的预算是 3.5 GiB，对照的阶段容器不在这个预算里。实际用量：同一测量下，池子 3 年的原生阶段约 0.7 GiB，单合约
  一段远小于此。但上限本身是用户定的拒绝阈值，改它要问用户，本步不改。
- **单段越来越长**：回放从段首 T 跑整段，用时与段长成正比。几个月不重启时，单段可能超过 3600 秒，每天都失败，
  连续两天后通知。增量回放先不做。
- **新的外部依赖**：对照容器调用币安公开期货 REST 取已公布的资金费率（`ledger/paper.py published_settlements`）。
  控制所在的后端网络本来就能出网。
- **合约要在市场导入范围内**：Live 的合约必须在远程主机的 `TRADE_MARKET_ARGS` 里，否则一直 waiting。
  结束的运行 3 天后照样关闭通知。
- **内存数字是估计**：对照容器 2 GiB 没有实测，远程主机的内存和 CPU 数也没有核实。超限时记 `stopped`，
  连续两天失败后通知。

## 验证

- 单元测试：
  - 回放截止切掉证据、分钟结果和订单；
  - 分段选择与合并；
  - 记录的状态转移：running 被杀、waiting、empty、failed 连续计数；
  - 只数窗口内的未解释决策差异；
  - 锁被占用时退出；
  - 对照容器的命令行（从 inspect 抄设置，`--volumes-from`，内存上限）；
  - 视图 `compare`；
  - 三条通知的键和文字；
  - 关闭条件。
- 没有在远程主机上实跑：Docker 兄弟容器的路径映射、真实内存都需要部署后看第一份记录。

## 评审记录（独立子代理，2026-11-13，修改后通过）

阻塞项及处理：

1. **运行中的运行永远 uncovered**：证据延伸到此刻，市场只到昨天，而 `--to` 只限制汇总。
   改为 `--to` 同时截断回放，资金费率按截止点结算。
2. **超时、残留容器和并发**：
   - 加内层超时；
   - 阶段容器名加随机后缀；
   - 加 `compare.lock`，锁内清理残留；
   - 不在对照期间持有 `account.lock`。
3. **子进程环境不全**：
   - 控制的 `HOME=/tmp`，找不到市场档案，改为直接用 `market_root`；
   - `TMPDIR` 不可写时 Python 静默退回 `/tmp`，加了与 Paper 相同的检查；
   - "导出缓存"的说法删掉：`replay_unrecorded` 每次都重新导出。
4. **内存**：对照改在有自己内存上限的兄弟容器里跑；控制不解析 `reconcile.json`。阶段容器上限是用户定的阈值，
   列为风险，不改。
5. **通知丢失或重复**：
   - 结束当天的对照会被关闭条件跳过，改了关闭条件；
   - 未解释差异只数新的，不重复；
   - 缺陷的判定改为 `cause == unexplained` 且 `stage == decision`。

非阻塞项：

- 已采纳：
  - 比所有有交集的分段；
  - `LIVE_COMPARE_EMPTY` 记为 empty；
  - 已结束的运行按"最后对照的日子"判断；
  - 记录里存连续失败数，只留一份；
  - 原子写，拒绝符号链接；
  - 按墙上时钟调度；
  - 长段超时、出网和导入范围写进风险。
- 未采纳：只比 K 线、每周回放（需要用户同意）。
