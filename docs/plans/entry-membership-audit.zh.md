# 禁新仓期间只减仓：实现与原生验证

2026-10-23，用户逐项确认：在成员区间外或 PRE_CLOSE 后，只允许原生 `reduce_only=True` 的退出与保护订单；旧入场挂单以及部分成交后剩余入场量也纳入独立审计。退池不强制立即平仓，重新入池恢复开仓。违规使整次运行无效，不自动撤单、不修改成交或时间，也不跳过现有裸仓和终止检查。

## 现状证据与本次改动

基线为合并 PR #1650 后的 `a29f33ea14d17ecf31be0547d85f385557c59369`。先用固定 `nautilus_trader==2.0.0rc3`、公开 BacktestEngine、固定账户条款和人造行情探针确认：PRE_CLOSE 后仍能开仓、加仓，旧入场限价单可继续成交；这些例子此前能通过完整审计。CLOSE 才会拒绝订单，连减仓也拒绝。工作副本为 `/tmp/trade_preclose_native_probe.py`。

实现复用现有 `input-coverage.json` 中的成员与导出生命周期，不增加任何存储字段或 ledger 列：

- 将纯函数 `episode_membership` 移到 `engine.load`，由运行器和独立审计共同使用；`engine.run` 保留导入名，既有调用不变。
- `entry_windows` 验证回执格式、窗口、市场身份、成员区间和原生生命周期，并按**实际目标合约**得到开仓区间。多段成员区间保留退池空档，重新入池恢复许可；未知目标合约和缺失回执不能回退为全区间允许。
- `entry_findings` 只读原生订单事件：初始化的布尔 `reduce_only`、提交/模拟/释放/修改、原生总量与成交量、撤销/到期等终态。逐单核对活动剩余入场量，不通过净仓抵消猜测增仓，不重建撮合或账户引擎。
- 截止时撤销/到期允许；截止时及之后的入场成交仍违规，旧单即使从未成交也必须结束。没有一分钟宽限。违规逐订单报 `ENTRY_ORDER_OUTSIDE_MEMBERSHIP`，附策略、合约、时间和剩余量；缺失或非法输入/原生标记报 `ENTRY_SCOPE_INVALID`。
- 订单 CSV 的只减仓标记须与原生初始化事件一致。原生结算订单本身为 `reduce_only=True`，本项不按订单名字增加例外。

## 原生回归与边界

`tests/engine/test_entry_membership.py` 用实际引擎、原生事件、原生报告写出和完整独立审计覆盖 PRE_CLOSE 与成员退出两种范围。

| 场景 | 结果 |
|---|---|
| 截止后开仓、加仓；没有只减仓标记的平仓意图 | 拒绝 |
| 未成交旧入场挂单、截止后才成交的旧单 | 拒绝 |
| 普通入场和括号入场先成交 0.250、剩余 0.750 跨过截止 | 拒绝，并定位剩余量 |
| 截止时仍有入场成交 | 拒绝，不让同一时刻其他事件掩盖成交 |
| 截止时原生确认撤销/到期，包括部分成交剩余量 | 通过；已成交旧仓可以继续持有 |
| 撤销部分成交括号单，却没有恢复其被连带撤掉的保护 | 仍被原有裸仓审计拒绝 |
| 按现有原生参考处理器补回只减仓保护 | 通过 |
| 只减仓退出、止损/止盈挂单、持有旧仓、重新入池、原生有价结算 | 通过 |
| 缺回执、非法范围、市场不符、未知合约或非法原生标记 | 拒绝 |

一个重要的原生事实：GTD 请求的到期时刻在两次撮合事件之间时，`OrderExpired` 可能直到下一撮合事件才发出。本审计不把请求时间写成确认时间；只有实际撤销/到期事件按时结束才通过，应安排在截止前完成，不能把设置 GTD 当作已经撤完的证据。

另将同一份完整原生报告分别交给基线审计器和新审计器，做 12 组对照：基线全部通过；新审计拒绝其中 7 组新增风险/活动剩余入场量例子，保留 5 组减仓、持有、补保护、重新入池与结算例子的通过。审计前后逐文件 SHA-256 相同。工作副本结果在 `/tmp/trade-entry-audit-paired.json`；这是同报告审计对照，不是两 OCI 镜像的经济回放等价验收。
