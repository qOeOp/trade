# Live 接入 Runs 工作区

2026-11-07。用户指出独立 Live 页面与现有 IDE 不协调，要求把操作和观察整合进 Runs，并用 stepper 或弹窗承载准备流程。本次修复这项界面与信息结构缺陷。

## 延续现有 Runs

延续 `ide-runs-page-design.zh.md` 中已确认的策略版本上下文、顶部运行选择器、中央画布、右侧 Details 与底部 Trades。移除独立 Live 导航，不建立新的运行列表页或右侧运行列表。原文关于尚未授权 Live 的历史限制已被后续授权与本次用户要求替代；已有版式决定继续适用。

Live 成为同一工作区的实际阶段。Paper 的数字运行 ID 与 Live 的字符串 ID 分开表达；展示状态是非持久的，不把 Live 数据强行转换成 Paper 数据。切换阶段时，工具栏、手机页、Details、Trades、状态栏和数据驱动器使用同一选择，避免旧 Paper 读数残留在 Live 上。

当前 Live 接口提供原生订单/仓位事件、账户观察和运行记录，没有连续权益或行情序列。中央区域呈现可核实的执行活动，并明确缺少图表数据；不能从账户余额、事件数量或 Paper 曲线推导 Live 权益、收益或当前持仓。完整原生事件表进入底部 Trades，账户观察、冻结配置、来源和收尾证据进入 Details。

## 启动与凭据

Runs 的工具栏提供 `New live run` 和已有准备的继续入口。启动弹窗分三步：

1. `Strategy`：从已部署来源中选择，明确自然信号或受控测试副本。
2. `Account & limits`：查看已选择的凭据版本，编辑现有允许参数。`Prepare & review` 是明确的准备请求，冻结本次配置。
3. `Review`：显示实际准备的运行、参数和来源；`Check account` 是显式账户连接操作，结果与请求回执分别展示；`Start live…` 保留现有源码绑定的最终真实交易确认。

步骤条只组织信息，不新增强制预检条件。原实现允许启动时执行账户检查，本次不改其准入范围。每次保存凭据、准备、预检、启动、停止、对账、收尾或请求恢复都仍由用户明确点击触发；选择步骤、打开弹窗、刷新与路由兼容不产生写请求。

桌面弹窗约 720px，只有正文滚动，步骤和操作区清晰；手机采用全屏弹窗。沿用 Radix 的焦点约束和现有样式变量，不引入组件框架。凭据通过按需打开的独立弹窗管理，不常驻中央区域；密钥只存在输入组件的临时状态，提交时清空，关闭后卸载，不进入 URL、草稿、日志或持久状态。

已冻结的准备只能继续原运行。返回编辑不修改原准备，不因弹窗重新打开而自动另建运行。准备动作的返回值携带本次实际请求的观测结果；防重或恢复命中旧请求时返回原目标，不能用页面最后一条回执猜测目标。

## 请求与观察边界

继续使用同一 Live 数据 owner 和原防重复请求协议。`effect_recorded` 仅表示控制效果已记录；预检通过只来自同一运行的 `mode=preflight`、`state=preflight_complete`、`exit_code=0`，并标记读取时间。该状态不代表当前账户仍为空仓，也不替代启动检查。后续进入运行模式后不把旧预检回执显示为正在检查。

关闭弹窗不代表停止、取消或释放。未决请求仍可从 Runs 的操作记录入口查询和按原规则恢复。STOP 保留原独立可用性，不能被分步表单的忙状态、发布暂停或普通写操作禁用条件一起隐藏。读取失败时保留事实陈旧说明，不恢复普通写权限。

只读命令返回值的适配不得改变请求 ID、操作键、同 ID 恢复、未知结果或秘密数据保存规则。后端接口、持久字段、账户/源码/连接/订单检查和 Nautilus 原生执行保持其现有合同。

## 兼容与验证

旧 `rg-shell@3` 的 Live 落点归入 Runs 的 Live 阶段；已有 Paper 数字运行链接和研究版本链接保留。研究数据或 Paper 服务不可用时，仍能查看已保留的 Live 运行和现有停止入口。手机默认选 Paper 的逻辑不得覆盖显式 Live 选择。

验证涵盖既有回测/Paper 图表与 Live 准备、预检中、通过、失败、未知、运行中、停止中、结束、读取失败及发布不可用；检查桌面和手机浅深主题、键盘焦点、关闭重开、旧布局恢复、零隐式 POST、原源码确认及 STOP 独立性。对准备请求的精确归属增加反例：旧未决准备与新点击、重复点击、其他回执交错均不得关联到新随机运行。
