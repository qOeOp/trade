  也应该是差异极小不至于说直接改变策略整体表现"

  抽 14 个文件全部相同；REST 和归档的 K 线、资金费率逐字段相同。

所以"工厂"就是 Git 里的代码：同样的代码、同样的公开归档，导出同样的数据。存储里只放数据本身。

## 1. 存什么、放哪

```
<市场目录>/
  <表>/<YYYY-MM>.parquet            bar、funding、universe_month：一个月一个文件，装全部合约
  <表>/<YYYY-MM>/<合约>.parquet      agg_trade、quote、metrics、爆仓三张表：一个合约一个月一个文件
  instrument.parquet                合约条款：一个文件，只追加
  lock                              导入锁
```

- 文件名就是它装的东西：没有清单、没有 head、没有回执，不按内容哈希命名。列、整数缩放、排序、压缩和写入参数和今天一样。
- **能重算的**（`agg_trade`、`quote`、`metrics`、`bar`、`funding`）只在本机。**算不出来的**（`instrument`、`universe_month`、
  爆仓三张表）同时上传 R2，路径和本机相同。
- **导入范围是配置，不再从回执读。** 部署里写明：K 线的合约名单（今天回执里的 30 个合约）和起始月份 2020-01；成交、报价的
  合约和起始月份；metrics 的合约和起始日 2021-12-01；爆仓表的起始日。今天 `market follow --symbols` 只管
  metrics/报价/成交，K 线名单要单列一个参数，不能混用。

**量。** R2：合约条款和合约池不到 1 MB，爆仓表每天几十 KB 量级（#2081 部署后按实测更新）。本机：和今天一样（约 86 GB，
每年约 15 GB），少了版本文件和回执。读数据的内存不变。

## 2. 写入

- **过完的月份不再变。** 报价和成交只导过完的月份（今天跟随导入本来就按月导它们），从不重写。
- **还在进行的月份**：K 线、资金费率、合约池、metrics、爆仓表每次导入重写这个月的文件——已存的行加上新的日子。重写前，
  已有的日子必须和新文件里的逐行相同，不同就拒绝。今天这个比较只有 K 线、资金费率（`_compare_bars`、`_compare_funding`）
  和合约池（`UNIVERSE_CHANGED`）有；metrics 改成"已存的行原样保留，只追加新日子"，不需要比较；爆仓表的一天不重算，同一天再读
  到不同的行即 `STORED_ROW_DIFFERS`，相同就不写。
- **原子性**：每个文件先写临时文件再改名。一次导入改几个文件时，按"合约池、资金费率、条款、K 线"的顺序，K 线最后——下面的
  截至日由 K 线推出，中途崩溃只会少推进，不会让截至日指向不完整的数据。新月份第一天，上个月导到月末之后，跟随导入
  单独做一次"只写合约池"的导入（第 3 节：上个月最后一天这个截至日要读到它）。
- **只有一个写的人**：`market-import` 服务。宿主和容器之间 fcntl 锁不起作用，所以改名前再核对一次目标文件的 inode 和修改
  时间，变了就拒绝（沿用 `CONCURRENT_IMPORT`）。
- **规则版本**（成交编码、报价推算规则、合约池规则）是代码常量。改规则就删掉受影响的派生文件重新导，不在文件里混两种规则。
  `universe_month` 的行里本来有 `universe_rule` 列，`daily_returns` 的规则检查改从行里读。

## 3. 账本里的 `market_commit`：改成"数据截至哪一天"

账本、登记、引擎、报告、IDE 里有 40 多处用 `market_commit`：研究线钉住它、可比性比较它、引擎核对每个导出回执上的它、
生命周期证据按它命名、IDE 按它取 K 线。它们都只要求"一个 32 位的标识，同一次运行里处处相同"。审阅逐个核过：
这些按字符串比较的地方不用改。

**写法**：最后包含的那一天加补零，仍是 32 位、仍符合现有格式检查，人一眼能看出日期：
`20261103000000000000000000000000` = 数据到 2026-11-03 为止（含这一天）。

**每张表"截至 D"的意思：**

| 表 | 截至 D 读到的 |
|---|---|
| K 线、资金费率、metrics、成交、报价、爆仓 | 数据时间在 D 结束之前的行（metrics 按 `create_time`） |
| 合约池 | D+1 所在月份及以前的月份（一个月的名单只取决于它之前的日子，所以月末这一天读得到下个月的名单） |
| 合约条款 | `observed_at` 在 D+1 结束之前的观测（D 的数据在 D+1 导入，条款同时观测） |

- **最新的截至日**（不带 `--at` 时）= K 线、跟随的 metrics、爆仓表各自"最后一个完整日"里最小的那个，从各文件尾部的统计
  （最大时间）读出，不扫数据。这一天是月末而下个月还没有合约池时，退到它的前一天：月末这个截至日要等下个月的合约池写好才可读，
  它读到的成员因此不会变（第 1 步 PR 的决定：否则月初头两天 paper 启动全部 `UNIVERSE_NOT_COVERING_WINDOW`）。iv71 → 2026-10-31
  因此读到 11 月的合约池，和下面"不承诺相同"一致。
- **解析**：只接受"8 位合法日期 + 24 个 0"且日期不晚于最新截至日；否则 `UNKNOWN_REF`（未来日期也算）。不再支持前缀。
- **导出缓存**：今天按 `commit` 作键（`export.py:599`）。补洞会改变某个截至日已有的数据，所以键里再加上读到的文件的
  路径、大小和修改时间（`stat`，不读内容）。
- **同一个截至日的数据会不会变**：只在补洞、晚到的归档改动 D 之前的日子时变。按用户的前提这种差异极小；
  复跑时导出指纹对不上，现有的 `REPRODUCTION_MISMATCH` 照旧报出来。

**账本里已有的 8 个旧版本号**（l1kf、53tg、gc30、6ho8、1kcb、dbng、pn5b、iv71）：代码里留一张 8 行的表，各对应一个截至日
（数据最后一天：l1kf、53tg → 2026-10-18；gc30、6ho8、1kcb、dbng、pn5b → 2026-10-25；iv71 → 2026-10-31）。
**不承诺它们导出和当时相同**：l1kf、53tg 当时只有 2025 年起的 K 线（预热和合约池都会变），gc30 到 dbng 当时的报价范围各不
相同。用到它们的旧试验按 11-03 定下的规则用新代码重跑、旧记录折叠、只算一次。账本里只有这 8 个市场标识（审阅用
`ledger sql` 核过；`validation_registration` 没有行）。

## 4. 回执现在管的事，各自改成什么

| 今天靠回执做的 | 改成 |
|---|---|
| 跟随导入找下一个月、下一天、补洞（`follow.bar_months`、`missing`、`following`、`holes`） | 看配置的范围里哪些月份、哪些天的文件缺或不全；跟随导入从起始月份到现在逐月补齐，不只往后延 |
| 报价、成交的 `through`、`PARTIAL_MONTH` | 只导过完的月份，不再有半个月 |
| K 线的 `scope`（`IMPORT_SCOPE`、`freshness`） | 部署配置的 K 线名单；`IMPORT_SCOPE` 只留"名单格式不对"这一半，作为参数错误 |
| `codec`、`quote_rule`、`universe_rule` 不同就拒绝 | 规则是代码常量（第 2 节） |
| metrics 的 `from`、`unpublished` | 范围内缺的日子就是没导；跟随导入对最近 `SETTLE_DAYS` 天每天重试。覆盖报告只报"缺的日子"，不再区分"归档没发布"还是"没导" |
| 覆盖报告的每日读数 | 行数取文件尾部统计；`stale_side_adjustments` 从存下的报价推不出来，删掉，`research-start/references/readiness.md` 同步改 |
| 覆盖报告里的 `commit`（哪次导入写的） | 删掉 |
| 归档 SHA-256、`writer` | 删掉 |
| `market publish` 只传新版本的文件和回执 | 见第 5 节 |
| `market review` | 整个删掉；"账本引用的市场标识都能解析"由解析本身保证（8 行的表 + 日期） |

## 5. R2

- 只传 `instrument.parquet`、`universe_month/`、爆仓表的文件。
- **远端没有的文件**：只建不覆盖（`If-None-Match: *`）；行相同就跳过。
- **合约池月份**：只写一次，不同就拒绝。
- **爆仓表的月份（过完与否）和 `instrument.parquet`**：按上次读到的 ETag 条件覆盖（`If-Match`），并且本机文件必须包含远端文件的
  全部行，否则拒绝（沿用 `PUBLISH_DIVERGED` 的意思：远端有本机没有的东西）。这样一份旧的本机副本不会盖掉只追加的条款。
  月内上传过的爆仓月份在月末还会多几行，所以"过完的月份不同就拒绝"对它们不成立（第 1 步实现时的独立审查发现：那样每个月末
  都会全停）。

## 审阅摘要（2026-11-04，独立子 Agent）

改进正文的发现：截至日含不含当天前后矛盾（改为"最后包含的一天"，旧号各减一天）；条款按观测时间截会让旧号导出拒绝

按 11-03 规则重跑；晚到的 metrics、爆仓日、按 `commit` 作键的导出缓存、新月份第一天单独写合约池（截至日取最小完整日、
缓存键加文件 `stat`、合约池同一次导入写）；未来日期要拒绝；跟随导入只往后延、不会补历史月份，恢复时 `_fill_universe`
会拒绝（改成逐月补齐、合约池改比较）；R2 覆盖没有前提条件（加 `If-None-Match`、`If-Match` 和"包含远端全部行"）；

`IMPORT_SCOPE`、`UNIVERSE_CHANGED`、`MARKET_COMMIT_INVALID`、账本的 `HISTORY_REWRITTEN`、`daily_returns` 的规则检查要留；
重写当月只有 K 线、资金费率、合约池有比较；一次导入多个改名要排顺序；跨虚拟机没有锁要核 inode；迁移的核对要用逐行摘要
