# 官方 Nautilus 原生回放迁移 POC

## 配对结果

在隔离工作树中，使用发布的 `nautilus_trader==2.0.0rc3`、原有一年 37 币 LAST/MARK/资金费率数据、同一数量表、一个 100,000 USDT 原生共享账户，对 H18a 与当前 H19a 进行全年配对。研究窗口为 2025-10-07 00:00 UTC 至 2026-10-07 08:30 UTC，交易从 2025-10-17 开始；总止损风险预算 25 bp，单币名义本金上限 5%。没有重新下载数据或用自造撮合/账本替代 Nautilus。

两组的平仓、盈利笔数、逐币统计、订单最终状态和输入覆盖完全相同。H18a 的 2,589 条成交及总手续费 `1,122.22119295` USDT 完全相同；H19a 的总手续费只差 `0.00000467` USDT，Sharpe(365) 相差约 `0.000000163`。配对门槛为原生完整性通过、零拒单/否单、订单身份/状态与交易/持仓数一致、单笔偏差不超过原生合约最小价格/数量单位，以及账户净值和总手续费差不超过 0.01 USDT。两个最终结果均通过。准确比较输出见 `strategies/r1/parity-h18a.json` 和 `parity-h19a.json`；输入回执、运行摘要 SHA-256 及原始报告路径见 `evidence.json`。75 个数据完成回执及数量表的路径和内容联合 SHA-256 是 `056c7a89a4831e089296170b83a754147f5956ee94c956d96d91559eb4e113f9`。

迁移到精简仓库路径 `strategies/r1` 并删除旧源码、服务及 CI/CD 后，使用锁定的官方依赖再次完成同一 37 币 H19a 全年回放。新输出仍为 17,665 单、1,722 笔成交、507 个持仓、期末 `111,664.46988783` USDT；与清理前的本地引擎配对再次通过。回执见 `strategies/r1/parity-cleanup-h19a.json` 和 `evidence.json`。

## 差异机制与修正

本地引擎提交 native OTO 入场与 OCO/OUO 退出子单。官方 rc3 的 bracket 工厂把父单的子单激活列表设为"止损、止盈"。某些入场五分钟 K 线同时触及止损时，第一个止损子单同步成交，尚未受理的止盈子单在官方引擎中被拒绝；本地 `33cadc761` 修复将这一迟到兄弟单取消。简单交换 Python `submit_order_list` 的列表顺序无效，因为原生引擎按父单 `linked_order_ids` 激活。

POC 保留原生 bracket 生成的价格、数量、订单类型、父子关联与 ID，只在 Strategy 中把父单的两个 `linked_order_ids` 改为"止盈、止损"，并用原生 `LimitOrder.from_dict` 重建父单。原生引擎先受理当时通常不成交的止盈，再处理可能立即成交的止损；后者成交时取消已受理的止盈。最终全年两组都零拒单、零否单，订单最终状态与本地引擎一致。这是明确的原生订单生命周期适配，不需要继续维护本地 Rust 撮合引擎。若升级 Nautilus，须重新运行订单生命周期与 37 币配对验收；不能把 rc3 的结果自动外推到新版。

初始未修正回放中，H18a 的 OP 到期单曾呈现"官方过期、本地成交"，造成 91.02 USDT 净值分叉。修正上述子单激活顺序后，该 OP 订单在官方 rc3 与本地引擎的到期时间、成交与止损全部一致；之前的观察是同一时刻拒单恢复动作改变了后续事件流，**不是独立的 GTD 规则差异**。统一延后 GTD 五分钟的诊断尝试还会改变其他应到期订单，已废弃。失败尝试与 rc6 的结果留在 `evidence.json`，不作为产品行为。

官方 rc6 需要将旧 Catalog 迁移为新格式，并把 maker `0.0002` / taker `0.0005` 放到 Venue 费率模型；其未修正的 37 币回放偏离较大，不能直接升版。当前使用 rc3 是有精确配对依据的版本锁定。旧 funding Parquet 为本地扩展格式，薄解码器将其转换为官方 `FundingRateUpdate`；Nautilus 自己处理资金费率结算。

## 对新架构的约束

策略源码是一等公民，外部 Agent 直接使用版本化 Nautilus Python API 与本地回放入口。最小自研层只负责旧数据适配、运行输入/结果身份和研究证据；不复制撮合、账户账本、策略语言或优化器。当前 37 币 H19a 是**一个**固定资金账户中的多标的策略；多个独立策略后续各绑定固定金额账户，分别原生回测与运行。清理旧架构时保留当前 RD 的证据和用户已确认的产品发现，移除内嵌 Nautilus 源码、旧产品服务和旧 CI/CD；清理在隔离分支进行，原 RD 工作树不受影响。
