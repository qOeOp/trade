## 第三次独立字段审阅与最终决定

无市场输入的手动启动探针在产生任何订单前失败：首次是 StrategyId 类型错误，
修正后在手动 start/on_start 中访问订单工厂遇到 `Already mutably borrowed`。
两侧均无订单，空列表相等不能证明语义一致；发布覆盖和回调权益读取仍未证明。
这些工程原件保留在研究证据目录，不作为研究回放或收益证据。

独立子 Agent 对更窄的冻结提案审阅后支持：运行结束读取缓存 `Order.events()`，
把各事件未改写的 `to_dict()` 写为 `order_events.jsonl.gz`。消费者是独立的订单
生命周期、计划风险和保护历史核对；终态订单、成交、持仓无法表达未成交单的
接受、取消、到期、修改事实。原生 API 已存在，结束后读取无需发布回调重入。

仅新增这一原生事实报告：按订单 ID 固定分组，保留每个订单内部事件顺序，gzip
时间头固定为零。不增加全局序号、权益副本、推导状态或风险指标；行顺序不表示
跨订单处理顺序。不能跳过编码失败。文件由现有报告 seal、校验与备份接管。
不修改审计、拒绝条件、策略源或风险限额。

验收由独立读者核对订单集合、每单事件数量、身份和内部顺序、成交事件与 fills
逐项相符、终态与历史相容；同源回放核对订单、成交、持仓、费用、资金费、现金、
收益和策略诊断。新镜像仅在这些核验完成后用于后续研究，不能以进程成功替代。

后续保守小时计划风险读者仍待预注册和验证：权益下界取小时 H 前携带的现金及
H 的全部 USDT 账户状态最小值，加此前 MARK 样本的原生未实现盈亏。先证明 MARK
配置一致、估值和持仓在区间内未变化、事件完整；同小时新单全部预留、取消仍计入，
修改取最不利状态。上界超限只说明此充分证明未通过，不能直接称实际风险违规。
5% 的源规则是计划入场名义金额，不能外推为随后 MARK 名义金额始终受限。
此方法不证明同纳秒全局顺序或每个事件时刻的连续保护。

有自己的绑定，不能冒充活跃源的发布身份。

837 个订单、3190 个事件和 348 个成交逐项核对；原生订单类应用自身历史后，
数量、价格、期限、状态等生命周期字段与终态一致，全部成交事件与原生 fills 对齐。
两个需要明确的原生边界：未成交保护单的 cache position 链接通过父单成交验证；
未成交单的 liquidity_side 可由撮合直接分类而无订单事件，不能从历史重建，费用与
流动性仍只从真实 fills 核对。这些边界保留在读者结果，不生成额外存储字段。

官方 compare_node 的订单、成交、持仓、资金费、现金和收益字段与 D06 一致；
源诊断计数和原生 exposures 数值一致。此处只证明两币的报告采集和同源行为，
不是 P3 风险、37 币策略经济结果或未来独立确认。完整单元测试 169 项通过，
6 项需要专门配置的集成测试跳过。
