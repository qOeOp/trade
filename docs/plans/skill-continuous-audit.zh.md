## 名字检查

### 规则 1：skill 里的 CLI 调用和相对路径必须能解析

- **范围**：只看 `.agents/skills/**/*.md`，代码块除外。评测不查，因为评测会故意引用不存在的命令当反例。
- **哪些片段算 CLI 调用**，满足任一条件即可：
  - 带 `python -m cli.main` 前缀；
  - 首词是 CLI 名词，第二个词符合 `[a-z][a-z-]+`，并且整个片段不超过 3 个词或者带有 `--` 参数。
- **调用片段的检查方法**：
  - 名词和动词必须在 `cli.main._parser()` 里；
  - 独立的 `--` 之前的参数必须属于这个动词；
  - `--` 之后的参数只在 runner 动词上检查，必须属于 `engine/config.py` 的解析器，但要去掉 CLI 自己重建的那几个（`--market-root`、`--market-commit`、`--strategy-file`）。
- **路径**：Markdown 相对链接，以及 `references/…`、`templates/…`、`assets/…` 形式的片段，必须指向存在的文件。
- **当前状态**：在 `02651c498` 上只有 `acquire.md:73` 一处会被首词规则匹配，3 词上限把它排除了。
- **链接的识别**：链接目标只认路径字符，避免把缩进代码块里的正则 `](ip|oi|…)` 当成链接。

### 规则 2：本 PR 不得删掉 skill 和评测仍在引用的名字

- **比较的两端**：PR 的 base 提交（与 `ci-paths` 一样取 `github.event.pull_request.base.sha`，即 main 的当前 tip）和检出的 merge commit。这样被检查的就是合入后的那棵树，main 在分叉之后才新增的引用也能覆盖到。
- **跟踪哪些名字**：形状是标识符（含点号形式，`tables()` 按 `tables` 算）或长参数（`--dir`）的反引号片段。多词命令交给规则 1。
- **名字"存活"的判据**：作为整词出现在任一受版本控制的文件里。排除的文件：
  - `.agents/skills/**/*.md`、`.agents/evals/**`、`docs/**`；
  - 其他 `.md`，`cli/templates/**` 除外。

  skill 的 assets 脚本算在内。
- **报错条件**：某个反引号片段在第一父提交时存活、在 merge commit 时不再存活，而 merge commit 里的 skill 或评测文字仍在引用它。
- **已知的漏报**：一个旧名字只要还留在测试、升级路径或拒绝消息里，就算存活；同名字段只在一张表里改名，也看不出来。这些留给 doctor。
- **已知的误报**：PR 删掉了某个外部名字在代码里的最后一处（比如去掉 `engine/live.py` 里对 `submit_order_list` 的守卫），或者删掉了最后一条提到它的注释，而 skill 仍正当地引用它。这种情况应该很少见，而且多半本来就该回头看一眼 skill。真遇到再加最小的豁免方式，现在不预设。

### 放在哪里

- 脚本是 `.github/scripts/skill-names.py`。quality 里新增 `skill-names` 任务，它只依赖 `uv sync --frozen`，PR 上总是运行，不走 tests 的路径过滤，这样只改评测的 PR 也会被规则 2 覆盖。
- 总闸 `gate` 要求这个任务成功，`tests/test_ci_gates.py` 覆盖了它的各种结果组合。
- push 到 main 时没有 base，只跑规则 1。
- `tests/test_skill_names.py` 覆盖以下情形：
  - 规则 1 对真实解析器的解析结果；
  - 正文、记录号和占位符不算调用；
  - 规则 2 的改名样例：代码把 `closing_order_tags` 改名，skill 和评测还引用旧名，应当报错；
  - 同步改了 skill、或名字只是挪到别的文件，应当放行；
  - 设计页面和 skill 文字不能让一个名字算作存活；
  - 链接和路径的检查。

### 实现后的读数（2026-11-09）

- main 的 `02651c498`：规则 1 是 0 处，规则 2 对比 20 个提交之前也是 0 处，耗时约 10 秒。
- #1577 的阳性对照：规则 2 报出 23 个名字、35 处，包括上文点名的 `closing_order_tags`、`duration_ns`、`progress_check_due`、`--dir` 和 `--source-bundle`，不报任何外部名字。`ledger status` 这类多词命令不在规则 2 的范围内，归规则 1。

- 它新增了一个连只改评测的 PR 也会运行的任务，不改 tests 现有的路径过滤。

## 使用热力图

### 决定：做成 product-doctor 的固定工具（方案 B）

评审曾建议把热力图留作 Agent 在 `/tmp` 的工作（见文末表格），理由是它读两种宿主的会话格式，格式会漂移，而每次重写的脚本没有测试。讨论之后，用户选了 B（2026-11-09，"B吧"，随后"开始实现 B"）：

- 工具在 `.agents/skills/product-doctor/assets/skill_heat.py`，页面模板是同目录的 `skill_heat.html`；
- `tests/product_doctor/test_skill_heat.py` 用样例会话固定两种格式，工具纳入 mypy；
- 每次整体审计都运行（product-doctor 第 1 步）。

**为什么要固定下来**：热力图要靠累加才有意义。用户要的是"多次 doctor 后就有个数据"，而 Claude Code 默认只保留 30 天会话（本机最早的主会话是 10 月 10 日）。每次重写的 `/tmp` 脚本给不出跨次可比的读数，也没有地方留住已经被清理的会话。用户不改保留期（"保留期不用"），要求分析过的会话留在图里，原始记录删了就删了。

### 记录文件

- **位置**：`docs/plans/doctor/skill-heat.jsonl`，随诊断记录的 PR 提交。
- **格式**：每个会话一行，按 id 排序，git diff 里只出现新增或变化的会话。
  - 会话本身：id、宿主、父会话 id（子代理才有）、第一次和最后一次工具调用的时间、是否维护会话；
  - 每个加载过的 skill 文件：第一次加载的时间，以及加载之后用到了这个文件里的哪些标识符。
- **只存观测**：机会、命中、热度都在出图时用当前 skill 文字算，不存段落编号。段落改写或挪动后，它的提交时间会变，较早的会话自然不再算它的机会。
- **再次运行**：磁盘上还在的会话和记录合并，只增不减：每个文件取最早的加载时间，标识符取并集。原始记录已被清理的会话保持原样。从没被扫到就被清理的会话不在图里，所以两次整体审计最好相隔不到 30 天。
- **体积**：2026-11-09 首次运行收进 1,073 个会话，约 0.84 MB（gzip 后约 0.1 MB）。
- **公开**：仓库是公开的，记录文件因此公开了这些会话的 id 和活动时间（诊断记录本来也写会话文件名和时间），不含会话内容。
- **随工具版本**：存的标识符取决于当时的提取规则。改了规则，旧记录仍按旧规则计数，读数前后不完全可比，改规则的 PR 要写明。

### 方法

- **切段**：以空行、标题和顶层列表项为界。标识符取行内反引号片段（围起来的代码块不算），去掉：
  - 占位符、纯小写单词、`True`/`False`/`None`、数字；
  - 带独立数字或 `@数字` 的片段（记录号、运行号）；
  - 单个大写代码，如拒绝码：它们出现在工具输出里，不会出现在调用里；
  - skill 名和 skill 文件路径；
  - 去掉占位符后连自己段落都匹配不上的片段，如 `self.place( <order> )` 剩下的 `self.place( )`。
- **占位符**：小写开头的命令里，全大写的词代表任意参数（`replay report --trial-id RUN`）；`DAILY_WARMUP = True` 这种大写开头的片段整体按字面匹配。
- **独有标识符**：只有一个段落提到（按整词匹配全部 skill 正文）的标识符才计入命中；别的段落也提到的照样列出，但不计入。这修掉了原型的跨段误读：`submit_order_list` 同时出现在研究用法和 Live 禁令里，原型把研究用法的 23 个会话也算成了禁令段的命中。
- **会话来源**：
  - Claude：目录名对应主检出或其 worktree 的 project 目录，含 `subagents/` 下的子代理；记录里的 cwd 必须在主检出下，排除名字恰好以本仓库路径开头的兄弟目录（如 `trade-graph`）；
  - Codex：`session_meta` 的 cwd 在主检出下，或 `git.repository_url` 与 origin 相同（Codex 自己的 worktree）。
- **加载**：Skill 调用、`Base directory for this skill` 消息，或读取 skill 文件的工具调用。
- **机会**：在段落现写法之后加载过该文件的会话。现写法的时间取该段各行沿主线（`git blame --first-parent`，工作区里未提交的行算现在）最新的提交时间，所以分支上的改动从合入算起。
- **命中**：机会会话里，加载之后有工具调用用到该段的独有标识符。匹配的是工具输入里解码后的字符串，读写 skill 或评测本身的调用不算。
- **复制来的调用**：
  - Claude 续接或分叉出的会话，会把原会话的行连同时间和调用 id 一起复制过去。2026-11-09 本机有 7,620 个调用 id 跨文件重复，时间全部精确到毫秒一致；41 组文件中有 39 组首次调用在同一毫秒，此外没有两个无关会话在同一毫秒开始。时间因此存到毫秒。
  - 规则：宿主和开始时间（毫秒）都相同的会话视为一组。组里已经记录过的会话排在前面，其次是先结束的；排在后面的只计晚于前者最后一次调用的调用。原件的记录已被清理时也成立，因为比较只用记录里的时间。
  - 同一次运行里，同一个调用 id 只记给先读到的会话，补上剩下 2 组首次时间不同的情况。
  - Codex 子代理把父会话的历史复制在自己记录的开头，以 `subagent_history_start_ordinal` 为界：之前的行只算加载，不算调用。
  - 评审曾建议按每行的 `sessionId` 判断是否复制来的。核对后发现 7,620 个重复 id 里，5,559 个在两份文件里都带着各自文件自己的 `sessionId`，这个判据会漏掉大部分，所以没用。
- **排除和标记**：
  - 加载过 product-doctor 的会话及其子代理，只计 product-doctor 自己的段落，审计时的 grep 不算照做；
  - 改过 skill 或评测（含 Codex 的 `apply_patch`）、跑过 `plugin eval` 的会话算维护会话，子代理继承父会话的标记，页面默认不计。
- **趋势**：`--compare 日期` 用同一份当前文字，另算一遍只含该日期之前开始的会话的读数；页面并列显示两者，并可按变化排序。`--until` 按会话开始时间截止，跨过截止点的会话会带上之后的调用。
- **已知限制**：skill 文件改名后，按路径记的旧会话不再归到新文件，改名的文件会显得偏冷。
