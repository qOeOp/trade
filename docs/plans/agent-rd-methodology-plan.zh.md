# Agent 投研方法论改造计划

状态：计划，尚未实现。日期 2026-10-10。依据：用户提出的方法论方向及其临时研究报告；四路延伸调研；台账 v132（固定 commit `f8va2hf2e7bae13p08kfs5s8ne1sk3ud`）只读核对；已封存原生报告只读计数；一次独立子 Agent 审阅（字段决定与事实核对，见"新存储事实审阅"）。本计划没有新回测、没有写 Dolt、没有新增字段。台账样本全部是 `development_exposed`，下文数字只用于诊断研究流程，不是策略资格证据。

## 结论

**同意用户方向**：以 Arnott、Harvey、Markowitz（2019）的回测协议作为证据可信度骨架，以 RD-Agent-Quant 的研究外循环与实现内循环作为自动化参考，以 QuantConnect 的 Ideas→Research→Backtest→Paper→Live 作为阶段参照。核对台账和延伸调研后补五处：

1. **补"下一实验怎么选"。** 2019 协议回答"结论为什么可信"，不回答"怎样用有限试验最快缩小不确定性"。台账里的候选并非都是全新机制（C01→C02、C04→C05、C10→C11 有固定父链），但每个候选都只用 >20% 年化与 58%–62% 净胜率联合目标判定，未达即关闭。Platt 的强推断指出：完整策略失败只排除"信号、入出场、仓位、成本"这一整组假设，不排除其中任何部件。所以 12 个经济失败之后仍定位不到瓶颈。每轮实验要先说明排除哪一个具名解释，并写出有分支的结果→动作映射。
2. **把机制响应拆成单独一层。** 本台账的 D 系列只做来源可识别性与事件容量，刻意不看事件后的价格响应（D03："不根据 1357 事件后续收益调参"），随后直接跑全年账户。计划→成交的选择也没有单独测过：按 bundle 计，B03 提交 2,939、有成交 500；C10 为 1,268/612；C11 为 285/151；C12 为 122/59（D09）。
3. **独立确认目前既无数据，也记录不了。** 本机 Catalog 只有 2025-10-07～2026-10-07 一年，27 个运行全在这一年；币池是 2026 名单回溯到 2025。研究 Agent 的训练知识覆盖该窗口大部分时间，而文献显示提示约束和匿名化都挡不住这种泄漏。台账层面，`artifacts register --evidence-grade` 只接受 `development_exposed/unknown`（`research/records/artifacts.py:925`）；初始合同声明过开发暴露的 attempt，会被 `contracts.py:60` 拒绝登记 independent 运行。最干净的确认数据，是候选冻结**之后**才发生的行情。它不需要提前积累：公开归档随时可下载，确认价值来自"确认 attempt 的登记时间早于数据窗口"这个先后顺序，而不是下载时间。用户已同意在限定条件下把这类运行记为 independent（见"用户决定"）。
4. **把自我施加的"不扫参数"改成有界稳健性检查。** 第二轮审计已指出，这是 Agent 自己加的限制，AGENTS 并无此要求。改为事前登记、计入试验数、一次只动一个参数的小网格，用来确认是否处在平台上，而不挑最高点。一次 37 币全年原生回放约 40–97 秒（B03 约 97 秒，C10/C11 约 40–45 秒，按封存时间戳），算力不是瓶颈。稀缺的是试验次数带来的选择偏差和数据暴露。
5. **独立审阅只审能用证据检验的离散事项。** 文献显示：没有外部反馈的自我纠错会让结果变差；只看结论时，审计准确率约 55%，拿到日志和代码后约 82%；不提供回测时，LLM 对因子好坏的判断接近随机。所以审阅者要拿完整轨迹与原生事实，在干净上下文中检查定义清楚的性质，不预测"会不会赚钱"。

用户判断"收益不必逐轮上涨，但连续多轮既没有有效改善、也不能定位失败瓶颈，说明流程需要修正"成立。下文把它落实为事件触发的诊断规则和 Lakatos 意义上的进步/退化检查。

## 方法论来源分工

三类来源分开使用：金融研究协议回答"证据为什么可信"，实验设计与科学方法回答"下一步测什么"，Agent 文献回答"怎样自动执行与反馈"。不把任何论文中的回测改善当作盈利证明。

| 用途 | 来源 | 采纳 | 边界 |
|---|---|---|---|
| 证据可信度骨架 | Arnott, Harvey, Markowitz (2019) 七类：研究动机、多重检验与统计方法、数据与样本选择、交叉验证、模型动态、复杂度、研究文化 | 清单子项：事前存在的假设；记录所有试过的模型与变量（含失败）；是否一找到好模型就停；事前定测试样本；迭代的样本外不算样本外；真正的样本外只有实盘；样本外计入成本；少调上线模型；奖励科学质量而非找到赢家；委托研究有迎合激励 | 清单，无定量阈值；背景是月/季度股票研究 |
| 选择偏差度量 | DSR（Bailey & López de Prado 2014）、有效试验数聚类 ONC（López de Prado & Lewis 2019）、PBO/CSCV（Bailey et al. 2017）、Haircut Sharpe（Harvey & Liu 2015） | 冻结前的诊断；输入是全部试验（含失败）的对齐日收益，台账已有 | 不是质量分或优化目标。按调研子 Agent 的示例估算，一年日收益下 DSR 达 0.95 约需年化 SR 2–3，所以暴露窗口撑不起"已验证" |
| 样本内指标的信息量 | Wiecki et al. (2016)，888 个 Quantopian 算法 | 样本内 Sharpe 对样本外 Sharpe 的 R² 约 0.02；波动率、回撤跨期更稳定 | 美股社区样本 |
| 下一实验选择 | Platt (1964) 强推断；Howard (1966) 信息价值；Rainforth et al. (2024) 贝叶斯实验设计；NIST 序贯小实验 | 每轮至少排除一个具名解释；所有合理结果都导向同一动作就不做；自适应设计在模型设错时会反复查询相近设计，需要有意换解释 | "无分支即零价值"是由 EVSI 定义推出的，未在 Howard 正文核对；噪声大时只能做概率意义上的排除 |

| 预注册的适度 | Olken (2015)；Banerjee et al. (2020)；Nosek et al. (2018) | 只冻结主指标、比较基线、窗口、成本模型与结果→动作映射，其余标为探索；同一数据既生成又检验假设是循环论证；留出数据能把事后解释转为预测 | 背景是新采集数据的 RCT；我们复用同一窗口，冻结部分应更硬 |

| 审阅治理 | Fed/OCC/FDIC SR 26-2（2026-04 取代 SR 11-7）；López de Prado (2018) "10 Reasons"；Man AHL (2015) | 有效挑战三项：专业能力、足够独立、能推动改变；首次使用前验证；质量取决于审阅的严谨与有效而非组织结构；回测是检验终点而非搜索工具；记录所有尝试、事前写下切分与预期 | SR 26-2 明确把生成式/Agent 式 AI 排除在范围外；董事会、内审等银行开销不适用 |

## 改造后的研究协议

Agent 自主选择问题和方法。协议只规定每轮留下哪些可检验的事前承诺，全部写进现有字段：层级写在 `kind` 和 `contract.plan`；主响应写在 `selection.primary_response`；预算、停止和结果→动作映射写在 `contract.plan`；暴露写在 `selection.known_exposure`；结论写在 `decision.scope/next_action`；审阅原文用现有 `review_evidence` material 固定引用。

### 证据阶梯

| 层 | 回答的问题 | 典型证据 | 失败时允许的结论 |
|---|---|---|---|
| L0 记忆 | 前人测过什么，哪些失败约束本轮 | `find`、`show --brief`、`compare` | 不适用 |
| L1 具体化 | 周期、确认时点、识别规则、入场/保护/目标、持有期；预期什么可观察响应 | 操作定义与参照 | 方向尚未被检验 |
| L2 实现与容量（内循环） | 代码是否表达登记规则、时钟是否因果、事件够不够 | 来源样例、BTC/ETH pilot、原生完整性审计 | 修实现；原结果不能评价机制 |
| L3 机制响应 | 事件发生后，市场是否按预测运动；计划在原生生命周期内经历了什么 | 事件时刻起、事前指定跨度的价格响应，对比事前指定的参照（无条件、随机时点或反向）；计划生命周期计数（见下） | 该操作定义没有预测力；不推及整个方向 |
| L4 原生净账户 | 响应能否经成交、费用、资金费、规模变为净优势 | P0-A 分解：毛优势→成本→频次→规模/占用→尾部；目标可达性 | 定位瓶颈层；预测优势尚未变成可交易优势 |
| L5 冻结与确认 | 未参与选择的数据是否支持 | 在确认 attempt 登记之后才发生的窗口上一次性运行；之后纸上观察 | 开发期改善未泛化 |

**L3 的合法边界。** L3 是市场响应与成交模型诊断，不是交易结果：

- 只用价格单位或波动单位描述响应，对比事前参照；不输出 R、USDT、胜率或期望，不和盈亏平衡点比较，不把"触及入场价"当成交，也不把"先触某价位"当出场。
- 计划生命周期诊断只用封存的 orders（parent 提交时间、原生终止时间、入场与止盈价、止损 `trigger_price`），加上经 input-identity 核验一致的同一 5m LAST Catalog；核验不通过就标"不可用"。观察窗口只到 parent 原生生命周期结束。输出按"档 × 原生状态"计数：入场价被触及但未成交、未成交期间价格先到过止盈价位、同柱两边都触及（单列）。已成交的只引用原生子单哪个 FILLED。期末仍 ACCEPTED 和部分成交的 parent 单独分组。
- 措辞沿用 r1-d100："价格触及不是 Nautilus 成交，不编造柱内路径。"
- L3 先作为 Agent 自己预登记的 `diagnostic` attempt 做，reader 冻结在外部配方中。有真实消费者证明价值后，再讨论进入共享工具。

### 每轮事前写清的内容

README 已要求写预算、停止条件、最大 run 数、可用确认数据和事前动作阈值。新增三条：

1. **结果→动作映射要有分支。** 列出主响应的两到三个合理区间及各自触发的下一动作。所有区间都导向同一动作，说明这次实验没有决策价值，应先换问题或换主响应。
2. **目标可达性算术。** 用 pilot 或来源容量估年机会数，用计划几何与 sizing 公式估每笔盈亏量级，算出达到用户目标所需的胜率与次数。若"机制完全成立"也到不了目标，主响应改写为机制或局部改良，并在 scope 中写明不检验联合目标。
3. **失败层定位。** 经济失败后，下一个 L4 候选必须引用 P0-A 读出的失败层（毛优势、成本、频次、规模/占用、尾部）及其证据。定位不了，就先做诊断 attempt。按此规则回看，C10（614 闭仓、毛亏）之后就会触发诊断，与第二轮审计结论一致。

另外两条口径说明：

- **预注册适度。** 冻结主指标、比较基线、窗口、成本模型和结果→动作映射；其余分析允许做，但标为探索，不计入确认证据。探索中的发现变成下一个 attempt 预登记的预测。
- **试验计数。** family 按机制线划分，用于线内预算和停止；选择偏差的计数按 `goal_id` 全局累计，避免"开新线＝预算清零"。凡是影响过选择的 `/tmp` 直接回放，都要在下一个 attempt 的 plan 中声明为已看过的试验。

### 失败分支（在用户分支表上补层级与证据来源）

| 固定证据显示 | 下一动作 | 允许的结论 |
|---|---|---|
| 周期、识别或预期响应未定义 | 补来源研究，新登记具体版本 | 方向未被检验 |
| 代码违背冻结规则或读取未来（L2） | 修实现，形成新运行 | 原结果不能评价机制 |
| 事件后响应与事前参照无可分辨差异（L3） | 关闭该操作定义；新定义须有独立依据 | 该版本无预测力；不推及整个方向 |
| 生命周期诊断显示，未成交计划常先到过止盈价位、已成交计划没有（L3 线索） | 登记入场执行方式的实验（触发方式、挂单深度、时效），不急于换信号 | 成交选择是候选瓶颈，需原生实验确认 |
| 成交子集有毛优势，净值被成本吞掉（L4） | 拆 maker/taker、档数、频次；登记最小成本改动 | 优势未覆盖成本 |
| 净值为正但可达性不足（L4） | 向用户报告；保留为组件或组合候选 | 机制可能成立，设计到不了目标 |
| 仅在已暴露窗口改善 | 记录配对改善与代价，冻结后在登记之后的窗口上确认 | 开发期改善未泛化 |
| 事件少、重叠强或区间过宽 | 标为证据不足；有事前价值才补样本 | 不能宣布有效或无效 |

### 有界稳健性检查

对已有正净值或明确局部改善的候选，允许一次事前登记的网格：一次只动一个参数，每个参数取中心值加两侧各一个值，共 2k+1 格。

- 网格、中心值和"平台"判定规则在看结果前写进 plan；每格都计入试验数。
- 用途是检查结果是否依赖单个参数点。确认时只用事前中心值，不换成网格最优格。
- 全部结果保留，冻结前纳入 DSR/有效试验数诊断。

### 进展检查

"失败层定位"规则在每次经济失败后都适用。此外，连续三个经济失败是一个默认提示（不是硬阈值）：Agent 应回看这条线，回答三件事：

1. 最近几轮各在哪一层失败？
2. 排除了哪些具名解释？哪些事前的新预测被证实？
3. 改动来自机制推出的预测，还是看到亏损后加的过滤？

据此决定继续、转向或停止。第二轮审计就是一次人工进展检查。这些都只读现有的 `decision.layer/outcome/next_action` 和封存报告。

### 独立审阅

| 关口 | 时机 | 审什么 | 不审什么 |
|---|---|---|---|
| G1 设计（可选） | 计划声称检验联合目标、或一条线的首个 L4 运行前 | 操作定义可检验；代码 diff 只改了声明的机制；结果→动作有分支；可达性算术；暴露与试验计数 | 收益预测 |
| G2 冻结 | 登记确认 attempt、知识准入或纸上运行之前 | 结论范围与证据一致；完整试验集合（goal 级）已披露；主指标前后一致；稳健性；替代解释 | 用审阅判断替代确认数据 |

- 审阅者用干净上下文读取固定 attempt、源码、封存报告和工具轨迹，不读作者的叙事摘要，输出指向固定证据的具体发现。
- 按 SR 26-2 的"能推动改变"：G2 的意见未解决时，Agent 按协议不推进冻结、准入或纸上运行。这是研究协议，不是产品拒绝。
- 审阅者先用已知干净的对照案例校准，避免误报。
- 准备晋级的结论，可让 2–3 个干净上下文的 Agent 独立复现关键读数。Menkveld et al. (2024) 显示，分析路径造成的离散约为抽样误差的两倍。

## 代码必要性审计（用户原则 2026-10-10）

这是 Agent 项目。所有要写成代码的东西，都先审一个问题："能否让 Agent 代劳？"Agent 的缺点是结果随机，代码的缺点是要维护。原则是：能不硬编码就用 Agent 能力，这样后期没有维护成本，也更鲁棒。只有满足下列至少一条，才写代码：

1. **信任边界。** 结果等于 Agent 给自己的考卷打分，必须让它无法绕过。例如：给运行贴 independent 标签、身份与哈希绑定、执行器只读。ImpossibleBench 显示，评估器一旦可写就会被改。
2. **现有代码的缺陷。** 已有的读写路径不一致或有缺陷，修它不增加新语义。
3. **Agent 做不到。** 例如需要原子写入、并发控制，或 Agent 没有的权限。

不满足这三条的，交给 Agent，再用不写代码的办法压住随机性：

- 不变量自检：例如逐仓现金流对账到原生 realized_pnl，误差 ≤1e-6；计数守恒。
- 结论引用封存文件与哈希，别人可以复算。
- 关键数字由 2–3 个干净上下文的 Agent 独立复算。
- 审阅子 Agent 拿完整轨迹检查。
- 用已知答案的案例定期重放，检验 Agent 是否守协议。

| 原计划项 | 审计结论 | 理由 |
|---|---|---|
| 确认运行登记 independent（四条件检查） | **保留为代码** | 信任边界：Agent 不能给自己的结果贴"独立"标签。逻辑只是时间先后比较加身份相等，复用现有绑定，维护量很小 |
| 写入时预检（RDP01/05） | **保留为代码**，但只复用读取时已有的同一规则 | 现有缺陷：写入时接受、读取时拒绝。不新增规则，只把同一个校验函数提前调用。先报告，确认不误拒后再拒绝 |
| brief 显示封存核验状态、DAG 去重读取（RDP02/06） | **保留为代码** | 现有缺陷。RDP06 每次对象读取新建一条连接，造成端口耗尽式失败 |
| P0-A 单 run 诊断（`artifacts report`） | **已按此原则落地（#1490）** | 代码只保留 Agent 不该自己给自己打分的读数：封存身份、与审计原生经济对账的闭仓拆分、未实现残差。胜率、持仓时长、订单漏斗、回撤、月度/品种贡献、成本构成交给按需 skill `native-report-analysis`，其中列出原生报表陷阱和引用前自检 |
| B1 配对分析（`compare --analysis`） | **已按此原则落地（#1490）** | 合法性沿用现有 `compare`；只给双方对账读数、冻结的 selection 与事前主响应的配对区间。拒绝信息已带出冲突字段与双方值（`write_status: not_written`），RDP03 已解决 |
| 数据下载工具 | **不做维护工具；Agent 写一次性脚本，冻结为外部配方** | 频率低：补历史一次，每个确认窗口一次。旧下载器 `research/r1_native/prepare.py`（#1481 移出）依赖一个打过补丁的 Nautilus 私有分叉，正式发布的 rc3 没有 MARK 历史 K 线和资金费写入，不能恢复后直接运行；只作为格式规范（回执字段、时间戳、MARK 精度、资金费 schema）。正确性由现有代码把关：input-identity 哈希、`replay_inputs.py` 的回执与资金费覆盖检查、`native_node.py` 的 LAST/MARK 对齐；它们查不出 OHLC 数值或合约条款错误，所以新脚本先重下现有一年中的一个月并逐事件比对 |
| L3 机制诊断 | Agent | 已经是外部配方 |
| 试验计数、有效试验数、DSR、台账自检 | Agent（G2 审阅时做） | 冻结前才做，频率低；输入来自现有 `find` 和封存日收益 |
| 研究协议、审阅模板 | md（研究 skill） | 见下节 |

结果：新增代码只剩一处信任边界改动和三处现有缺陷修复（RDP01/05、RDP02、RDP06）。P0-A/B1 已由另一会话按同一原则瘦身落地。

## 产品形态：一个研究 skill + 现有代码 + 案例评估

用 md 约束 Agent 是社区主流做法：

- AGENTS.md 由 OpenAI 发起，2025-12 与 MCP 一起捐给 Linux 基金会新成立的 Agentic AI Foundation。
- Claude Code 用 CLAUDE.md。
- Agent Skills（SKILL.md）由 Anthropic 于 2025-12 开放为标准，按需加载：启动时只读名称与描述，任务匹配时才读正文与参考资料。

它的局限也有明确证据：

- Claude Code 官方文档把 hooks 定位为"确定性控制，而不是依赖 LLM 选择去执行"。md 只是建议，不是保证。
- ETH 等的 Gloaguen et al.（ICLR 2026 workshop "Agentic AI in the Wild" 海报，arXiv 2602.11988）发现，仓库级上下文文件总体上**没有提高**编码任务成功率（v1 摘要写的是"倾向于降低"，v2/v3 改为"总体没有提高"），推理成本却平均增加 20% 以上。Agent 确实遵守了其中的指令，但大段概览没有帮助。v1 建议只写最少的必要要求；v3 建议只写代码库和 README 里没有的指令，并在部署前评估。该研究针对编码任务，不是研究流程。

因此产品形态定为：

| 层 | 形态 | 作用 |
|---|---|---|
| 研究 skill | `.agents/skills/` 下一个 SKILL.md，正文一页左右：证据阶梯、三条事前要求、失败分支、何时停；参考资料按需加载：可达性算术、G1/G2 审阅模板、L3 合法边界、确认运行。原生账务语义引用已有的 `native-report-analysis`，不重复 | 判断与方法交给 Agent。只在做研究时加载，不常驻上下文 |
| 硬约束 | 现有 Dolt 契约、固定镜像、Nautilus 执行，加上述一处信任边界改动和三处缺陷修复 | 只管"必须成立"的事实与边界 |
| 评估 | 冻结的案例集，用干净上下文的 Claude/Codex 定期重放；下一轮研发后做过程审计 | md 是软约束，只有用评估才能知道它是否起作用，以及是否该删减 |

skill 里的每一条要求，都要能在案例重放或台账审计中观察到是否被遵守；观察不到的要求就删掉。

2026-10-10 补充审计（[skill 产品形态审计](skill-product-form-audit.zh.md)）有三处修正：一是加一层常驻规则（瘦身后的 AGENTS.md）；二是"硬约束"在本机的实际强度只是"内容寻址身份让篡改可被发现 + 正常 API 路径上的防误拒绝"，绕过要靠评估层检测，并非无法绕过（第 148 行的"无法绕过"以此为准）；三是 research-round skill 按"可观察或删除"规则改了几处（见审计第六节）：G1 设计审阅与纸上运行已删除，冻结审阅只在确认与知识准入之前，进展检查改为同一目标三次经济失败后必须作答。本文"进展检查"与"独立审阅"两节以 skill 为准。

## 验收

**案例重放**：干净上下文，Claude 与 Codex 各重复；保留未用于调提示词的案例。

- 模糊方向（只有"支撑阻力有效"）→ 先具体化，不直接跑 L4。
- C11 类设计 → 运行前算出联合目标不可达，改写主响应或不跑。
- B03 → 识别出"收益接近，胜率是约束"，不宣称方向失败。
- C10/C12 → 识别出毛亏，不归咎费用。
- C09 → 写前发现成本说明冲突。
- 计划大量未成交 → 先登记 L3 生命周期诊断，再决定是否换信号。
- 已暴露窗口上的局部改善 → 冻结后登记确认，不称泛化。
- 预算用尽、预期响应持续不出现 → 停止。

**下一轮研发后的过程审计**（不是质量分）：

- 每个 L4 运行都有带分支的结果→动作映射。
- 每个经济失败都定位到层并有证据。
- 有被排除的具名解释，或有被证实的事前预测。
- 没有把可达性不足的运行当作联合目标检验。
- 每个 independent 运行的窗口都晚于其确认 attempt 的登记时间。
- 停止被当作合法结果。

收益不要求单调上升。但若两次进展检查都既没有排除解释、也没有证实新预测，就暂停生成候选，把问题带回用户。

## 用户决定（2026-10-10）

- **补 2023–2025 历史数据：同意。** 用途限于机制在其他市场状态下是否存在的稳健性检查和探索。每次使用都计入暴露；不能记为 independent，也不能当干净留出。来源为 Binance 公开数据；原下载工具已在 #1481 移出产品树，需恢复为维护工具或另写。开工前列出确切文件与体量（按现有格式估计，37 币两年约 0.9 GB）。
- **冻结后的确认运行可以登记为 independent：同意。** 已经独立契约审阅后实现；代码检查策略绑定相同与时间先后；有效配置、镜像与窗口长度写进确认 attempt 的 plan，由 G2 核对（用户 2026-10-10 选定，比原条件宽，已确认）。原条件如下：
  - 候选的完整策略 revision、有效配置、OCI 与成本模型，在确认 attempt 首次发表时已固定，且与开发期最后版本一致；
  - 确认运行的交易窗口起点晚于该确认 attempt 首次发表的 commit 时间（预热可以更早，但不参与评价），所以 2023–2025 历史数据自然不符合；
  - 输入来自确认窗口的独立 Catalog，其 input identity 未被任何开发运行引用（有上一条的时间顺序后，这一条主要是冗余保护，契约审阅时可评估是否保留）；
  - 一次性使用：此后该窗口对后续 attempt 视为开发暴露。
- **写入时预检：先报告、后拒绝。** 第一版只报告；经真实使用确认不误拒后，切换为在 register/publish 写入时拒绝。切换本身已获同意，切换时仍按独立审阅记录规则与测试。
- **联合目标与风险边界：都保持不变。** >20% 年化与 58%–62% 净胜率仍是最终判定线，25bp 总止损风险与 5% 单币名义上限不变。但不再要求每次实验都直接用联合目标判定：中间实验可以用机制或局部改良作主响应，并在 scope 中写明不检验联合目标。研究优先选"机制成立时够得着目标"的设计；按上文算术，小时级、每笔约 80–110 USDT 的结构需要每年上千笔交易才可能达标。

## 不做什么

- 不建研究调度器、工作流引擎、策略语言、信号仓库，也不建第二套交易账本。
- 不加综合质量分、ROI 分、排行榜或必填说明文字。
- 不让工具自动推荐下一候选。
- L3 不输出 PnL 类读数，不冒充成交。
- DSR/PBO 不作资格门槛或优化目标。
- 不改历史记录、角色或已封存文件。
- 不移植 RD-Agent 的 bandit 调度、AlphaAgent 的 LLM 一致性分或 Elo 锦标赛。
