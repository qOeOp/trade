# Paper 运行按策略版本命名

2026-11-09，用户同意（“你的想法可以”）。

## 问题

运行选择器按版本分组，组头是版本名，组里每一行只写编号：`run 6`，续跑链写 `runs 5, 7`。

- 编号不带信息。看一行不知道跑的是什么策略。
- 续跑链每续一次多一个编号，最后会变成 `runs 1, 2, 3, 4, 5, …`。
- 组头一窄就被截断：`price-action-retest-mid3r@1` 和 `price-action-retest-midepisode@1` 都只剩 `price-action-retest-mi…`。
- Unattributed 的行只写研究线，不写策略。
- 页面上的阶段名也用编号：`Paper · runs 5, 7`。

## 改法

一行就是一个运行（续跑链按一个运行算）：

- 第一行写策略版本：版本名放不下就截断，`@修订号` 始终显示。没有声明版本的运行写 `No version declared`。
- 第二行写收益、状态、交易对（最多写两个，再多就写 `N contracts`）。续跑链再加上 `N runs` 和中间暂停、离线的时长。原来写在 Unattributed 行里的说明照旧跟在最后。
- run 编号只出现在悬停提示（`runs 5, 7, continued as one`）、右键菜单的标题、Copy run id 和搜索里。

选择器去掉版本分组，改成平铺，顺序沿用 `runOrder`：有问题的运行在前，然后是其他运行中的，最后是已封存的，各自按新到旧排。同一版本在不同交易对上的运行，靠第二行的交易对区分。

阶段名改成 `Paper · <交易对>`，因为版本名已经显示在工具栏、状态栏和详情卡里。

## 不变的地方

- 续跑链的判定（`model/chain.ts`），链里最新的运行代表整条链。
- 续跑链要让人看出是由几个运行拼成的：原来靠列出所有编号，现在靠 `N runs` 和悬停提示里的编号，账户被重启过的链仍然看得出来。
- 不加存储字段，也不改服务端。
