# D101 单轮预登记：H10 旧 Engine／现行 Node 原生报告差异归因

本登记先于读取 H10 两份完整 CSV 的新增逐项差异。H29a 已公布的严格历史对照 `passed=false`：旧 BacktestEngine 与修复 OTO 子单关联顺序后的 BacktestNode 都有 8,815 个订单、1,887 次成交、934 个已平仓 Position、930 条相同资金费调整，期末权益同为 95,055.27668156 USDT；但订单、账户事件、八个 Position 行和 91 个日收益行不完全一致。D100 已证明真实 1m 对部分同根 OTO 拒单有帮助，但不是通用修复。本轮只诊断**已经发生**的原生差异，不更改 H10/H29a 的规则、数据或账户收益。

## 机制与反证

待检验解释：原生目标先／止损先的关联顺序，改变订单取消或拒绝时的事件发射、`expire_time_ns`、`liquidity_side` 等报告字段；Position 均价／收益与日收益小差可能为报告数值精度或事件排序所致。若相同交易时钟上的实际成交价格、数量、手续费、资金费、每日收盘账户总权益、最终 Portfolio 指标有任何非微小差异，这个“仅表达与浮点差异”的解释即被否定。不能因期末权益相同推断整条净值路径相同。

## 冻结输入、合法对照与预算

只使用既有 `/tmp/r1-rd-h10-full-37` 与 `/tmp/r1-h29a-paired-h10-37-native-repaired` 六类原生报告，以及已落盘的 H10 摘要、H29a 对照摘要和严格比对报告。先按摘要 SHA-256 核对身份，再记录各原始文件 SHA-256；相同排序键与事件时钟上的原生成交、费用、Position 实现净 PnL、账户总权益及每日收盘 equity 逐项比较。订单状态与关联关系单列，不能删除不便解释的事件。对 Position 和日收益差异报告最大绝对/相对差与原值，不用人为容忍度把 `passed=false` 改成通过。若一份 CSV 缺失或身份不合，停止并登记。只准一次冻结的只读分析，不跑新 Nautilus 回测、不换分钟粒度、不修改对照代码与策略、不选择资产或阈值。

主账户核查为 100,000 USDT 起点的期末净值、逐日净值、年化净收益、Sharpe365、日收盘最大回撤；同时保留 934 笔胜负/盈亏比、原生成交、手续费、资金费和所有订单终态。若不能找到相同时钟的每日账户净值，明确报告无法判定，不用 `returns_series` 或 Position PnL 反造账户账本。严格门槛仍按 H29a 旧契约失败；D101 只可说明哪些差异影响经济解释，不能追认 H29a 相对 H10 的正式配对优势。

## 停止条件、暴露窗口与反馈

核查到任何成交/费用/资金费差异、不能对齐的每日账户净值，或原生报告无法区分的实质事件顺序后，停止“纯表达差异”解释，记录最小复现与待修的 Nautilus 所有权边界。若仅有原生事件/浮点表达差异，也保持原严格门槛不通过，未来候选改用事前登记的同代码现行 Node 对照。输入 2025-10-07 至 2026-10-07 08:30 UTC、从 2025-10-17 可交易的 37 币年度，以及 H10/H29a/D100 的所有已发表结果均已暴露。本轮不能称为独立验证。结果须分开写原生事实、未证实解释、下一次最小实验；不建立新研发框架。

**首读连接键修复记录，先于补全报告：** 首版读取器依原生 `trade_id` 连接两份 `fills.csv`，发现该 ID 含运行随机片段，1,887 笔均无法用 ID 跨运行连接；前几行已确认相同客户订单与事件时钟。修复只将成交连接改为 CSV 行顺序，并要求每一行客户订单 ID 与 `ts_event` 相等，原生数量/价格/手续费仍作为待比较字段；不改输入、策略、阈值或经济结论。首轮结果保留在 Git diff/提交记录，不把连接失败误记为成交不同。
