# 市场页数据服务改写成 Go（决定记录）

2026-11-07。`ide/overview` 从 TypeScript（Node）改写成 Go，只用标准库。这个服务不和账本共享逻辑，不是信任边界，
数据全在内存里，数字也不是研究证据，所以收益只看内存。本文记录测量、答案比较和改写后不同的地方。

## 内存

测量用同一个生产镜像 `ghcr.io/qoeop/trade-ide:main`（Node 版本相同），读 `/proc/<pid>/status`。假上游回放录下的真实答案，
节奏和生产一样；连接时先推满 24 小时窗口的爆仓事件，之后按每天 6 万条继续推（线上实测 300 秒 159 条，约每天 4.6 万条）；
旁边的脚本按页面的节奏取 `snapshot`、`news`、`coin`。

| 版本 | 场合 | 运行时长 | RSS | 峰值 |
| --- | --- | --- | --- | --- |
| Node | 假上游，60 分钟之后 | 92 分钟 | 203 到 230 MB，平均 216 MB | 232 MB |
| Go 服务 | 假上游，60 分钟之后 | 74 分钟 | 62 到 86 MB，平均 79 MB | 90 MB |
| Go 原型（只存同样形状的数据） | 假上游 | 18 分钟 | 45 MB | 49 MB |
| Node | 录制配对，每天 6000 条且不再续推，没有页面请求 | 72 分钟 | 164 MB | 164 MB |
| Go 服务 | 同上 | 72 分钟 | 44 MB | 51 MB |
| Node | 本机生产容器 | 14 小时 | 236 MB | 266 MB |

同样负载下省约 137 MB（216 对 79），约 63%。两个版本在第 60 分钟都因小时级数据上一个台阶，之后平稳，窗口从一开始就是满的，
所以这不是爆仓记录在累积。Go 版本没有在真实上游上跑到 14 小时，只跑过 170 秒和 45 秒（后者 35 MB），生产数字要部署后才有。

## 答案比较

两个服务接同一个假上游，`snapshot`、`news`、各币的 `coin`、`health`、错误路径共 17 个请求，比较状态码、响应头和正文。

- **仓库夹具**：17 个全部逐字节相同（只把到达时间抹掉）。第一次有 2 个不同，原因是 OKX 推送先于合约表到达其中一个服务，
  没有合约面值的推送两个版本都丢弃；假上游改成推送延后 30 秒后相同。
- **失败路径**（带 `Retry-After` 的 429、`Retry-After` 不合法的 418、503、500、该是列表却是对象、不是 JSON、读数为空）：
  17 个答案在抹掉 `sources` 后相同；失败的种类相同，`updated` 的有无相同。错误文字除形状和解析失败外相同（见下节）。
- **录制的真实答案按真实节奏跑 72 分钟**，覆盖板块和小时级数据：531 个答案（518 个币各一个 `coin`，再加其余请求）
  全部逐字节相同，只抹掉 `updated` 和 `liquidationsSince` 这两个时间。两边都没有错误，所有种类都已更新。
- **真实上游**：Go 服务直连公开接口 170 秒，518 个币，WebSocket 都连上，BTC 有 6 个交易所。出现 The Block 的 403，见下面。

## 未决：The Block 拒绝 Go 的请求

`https://www.theblock.co/rss.xml` 对 Go 服务返回 403（Cloudflare），隔段时间用同样的请求重复一次还是 403。其余五个源都是 200。
同一时刻生产 Node 版本的 `news.rss` 没有错误，656 条标题中 30 条来自 The Block。所以换成 Go 后 `news.rss` 会一直显示
“The Block: … answered 403”，这些标题没有了，其他源不受影响。

`feeds` 列表没有改，失败保持可见。另试一个客户端身份属于绕过站点的机器人检查，自动权限检查已拒绝，没有试过。这件事由用户决定：

- A：从 `feeds` 删掉 The Block（建议）。少一个源，错误消失。
- B：用户明确决定是否对这个站点用别的客户端身份。
- C：不合并，保留 Node。

## 和 Node 版本不同的地方

- 形状和解析失败的错误文字不同，例如 Node 的 `tickers.flatMap is not a function` 对应 Go 的
  `the answer held no list where one belongs`。HTTP、暂停和“没有读数”的文字相同。
- 新增：WebSocket 单条消息上限 16 MiB，帧不合规时断开重连。Node 的内置客户端没有这个 16 MiB 上限。Host 和方法的拒绝没有改。
- 路径里的 `..` 不再被规范化，答 404。
- JSON 里 U+2028、U+2029 写成转义，值相同。
- RSS 的数字字符引用超过 U+10FFFF 时得到 U+FFFD，不再让整个源失败。
- 十六进制数字字符串读作没有值（Node 的 `Number("0x10")` 是 16）。
- Kraken 一个答案有多个键时，按排序取第一个。
- 结果不是有限数的乘积丢弃。序列化失败答 500。
- 日期解析只认实际来源用到的格式，不是 `Date.parse` 的全部。
- 对外的客户端身份不同（Go 默认 User-Agent 和 TLS 指纹），The Block 的 403 就来自这里。

每台主机的请求上限没有变：权重上限 600，429 和 418 时暂停，错误文字相同。

## 镜像

镜像没有变小。Node 留在镜像里给 `ide/agent` 用，多了一层 Go 二进制（7.08 MB，压缩后约 3 MB）。CI 镜像的压缩层总和：
arm64 从 385.6 MB 到 388.6 MB，amd64 从 400.1 MB 到 403.4 MB。
