# 手机端：只留关键数字和一个紧急操作（2026-11-11 方案）

本文只是方案和设计稿，没有改产品代码；范围等用户决定。它替换 [`ide-mobile.zh.md`](ide-mobile.zh.md)（11-07）里
「页面」「保留、缩减、关闭」和「手机上保留桌面的设计」三节：手机上留哪些东西改由本文决定，留下来的组件仍按那一节
沿用桌面的形状。那份方案的切换规则、服务降级（第 1 步，#2244）和手机尺寸 token 不变。

设计稿：[Trade 手机端方案](https://claude.ai/artifact/DqVQMmxrhQU3sLk2urzuDa)（私有，第 3 版，9 个画面，明暗各一）。

## 用户的话

2026-11-11：现在的手机端是网页的部分缩小和变形版本。手机空间小，展示和网页一样多的内容既难操作，手机也就没有价值。
先确定用户在手机上的场景和目的：一般是紧急操作或看关键数字。没人在手机炒股软件里做深度图表分析，那在网页上做。
手机是身边没有电脑时用的：快速操作一下，粗看行情和持仓。

## 现状（origin/main e33e425a7 实测）

11-07 方案的第 2–5 步都已上线（#2255、#2259、#2272、#2274、#2290 及之后的 Live 合入），做法是把桌面组件全部装回手机：

- **Runs**：首屏是一条运行的权益数字、阶段切换（Backtest / Paper / Live）、图表开关和占 72dvh 的 K 线或权益图；
  目标、表现、盈亏桥、Trades 在下面，持仓要滑到第三屏。横屏变成全屏图。
- **Live**（在 Runs 里切到 Live）：画布、Details、Trades，以及 `Review…`、`New…` 启动向导和 `Live settings…`
  （凭据、Telegram）。也就是说现在能在手机上走到开一个真钱运行的流程。`Request stop` 和桌面一样一点就发。
- **Research**：线列表 → 线页（Graph、Versions、Readings、Table、Gaps）→ 版本页 → 源码比较。
- **Market**：可下钻的完整热力图、Overview / Coins / News、币种 Sheet。
- **Agent**：对话、历史、agent 管理。
- 打开 Runs 和 Research 标签就连 Paper 流：运行 8 运行 5 天后一次约 1.75 MB（未压缩），里面是 5,739 个分钟权益点。
- iOS Safari 带地址栏和底部工具栏时，页面可用高度约 600 pt（模拟器 iPhone 17 Pro 实测）。现在这一屏只够到图表开关。

截图（未入库）：Playwright WebKit 402×874 明暗各一套，模拟器 Safari 一张，桌面 1440×900 的 Runs、线、Market 明暗各一。

## 场景和取舍

| 场景 | 手机 | 手机上是什么 | 只在桌面 |
|---|---|---|---|
| 收到 Telegram 推送（成交、结束、未解决、每日概况），想确认 Live 怎么了 | 保留 | Runs 首页的 Live 卡片：权益和涨跌、最近一次成交、亏损额度用了多少、持仓和保护止损离现价多远、最后观测时间；未解决、Telegram 发不出、服务不应答时顶部出提示条 | 证据、预检、请求日志、对账 |
| Live 已结束但未解决（例如留下没有保护的仓位） | 只看 | 提示条和卡片写出留下的仓位（方向、数量、开仓价、现价、浮动盈亏）和处理去处：桌面对账，或在币安 App 里平仓。手机上不加平仓操作（待决定 1） | 对账、维护 |
| Live 出了问题，要马上停 | 保留 | 运行页底部固定的 `Request stop…` → 底部确认单按当前持仓写出会撤哪些单、平哪些仓 → 按住 1.5 秒发出；之后同一张单显示停止进度 | — |
| 开 Live、Review、凭据、Telegram 设置 | 移出 | 不出现 | 全部 |
| Paper：健康、权益、持仓 | 保留 | 首页一张紧凑卡片；运行页：权益大数字、回报、最大回撤对目标、健康（缺 bar、晚到、异常、保护缺口、最后一根 bar）、持仓 | 图表开关、事件、日志、日历、盈亏桥、成交全表 |
| Paper：启动或停止 | 移出（建议） | 不出现 | 选版本启动、Stop and seal |
| 研究：看一眼每条线走到哪 | 缩成数字 | 一页线列表，每行最前是版本树上的读数徽章（年化 \| 回撤，按目标着色），最后是版本数；点一行就地展开推荐版本、回撤进度和推荐稳定了多少轮 | 谱系、进度柱图、散点、版本表、缺口、版本页、源码 |
| 行情：关键价格 | 保留 | 桌面 Overview 卡的三行（总市值、BTC 占比、恐惧贪婪）；价格表，运行在交易的合约排第一并写出自己的仓位；一层板块热力图，不下钻 | 下钻、币种详情、期权、溢价、爆仓、新闻 |
| Agent 对话 | 移出（建议） | 不出现 | 对话、历史、添加 agent |
| K 线和图表分析 | 移出 | 运行页只有一条不能切换的权益线；横屏不再变全屏图 | 全部图表 |

去桌面的路在右上角齿轮打开的菜单里（和桌面的设置菜单同一个弹出形状）：`Copy link for the desktop` 复制当前运行或线
的地址，电脑上打开就是同一个对象；`Desktop layout` 在这台手机上切到完整 IDE（现有，只在当前标签页内记住）。

## 页面

三个标签：**Runs**（落地页）、**Market**、**Research**。Settings 从标签栏移到右上角菜单，去掉 Agent 标签。

| 画面 | 内容 |
|---|---|
| Runs | 所有运行中的 Live 和 Paper 各一张卡，Safari 带工具栏时也在一屏内；有事时顶部提示条，读不到的数据写明时间 |
| Live 运行页 | 权益大数字和涨跌胶囊、最近成交、权益线（预算和亏损上限两条虚线带价签）、亏损额度、持仓、挂单（止损离现价多远）、关键事实（账户检查、成交数、Telegram 最后发送）、底部固定的停止按钮 |
| 停止确认 / 进行中 | 底部 Sheet 按当前持仓写出会做什么；按住时填充并倒数，松手取消；完成后每一步来自 Live 的运行视图 |
| Paper 运行页 | 同一结构：权益大数字、权益线、目标卡、持仓、健康；没有停止 |
| Market | Overview 卡、价格表、一层板块热力图（桌面的色阶、间隙、徽标和色阶条） |
| Research | 一页线列表，行内读数徽章，点开就地展开 |
| Settings 菜单 | 主题、时区、Copy link for the desktop、Desktop layout、关于 |

## 需要的服务和接口改动

都在读路径上；不加存储字段，不动账本、拒绝检查和研究目标。

| 改动 | 为什么 | 位置 |
|---|---|---|
| Paper 运行列表带上未平仓持仓 | 列表已有回报、回撤、权益、缺 bar、异常、最后一根 bar，只差持仓（合约、方向、数量、开仓价、浮动盈亏）。没有它就得连整条流 | `paper/serve.py` 的 `listing`，从 journal 现算 |
| Paper 权益线降采样 | 运行页只要约 120 个点 | `paper/serve.py` 新的 GET |
| Live 薄列表 | `/api/live` 每个运行带全部分钟权益，连续运行几个月后会很大；首页只要状态、权益、最近成交、持仓、挂单和观测时间 | Live 控制程序的读视图，IDE 只转发 |
| 停止的确认 | 只在页面加一步，服务端 `stop` 不变 | `ide/web` |
| 每条线的推荐读数 | Research 行内徽章要它。现在只在算图的结果里（`summary@1` 的 `reading`），一条未缓存的线约 20 秒 | 依赖账本重构草稿（#2599 等）：读数在封存时算好以后 `/api/lines` 直接带上；在那之前用已缓存的 view，没有就显示 `–` |
| 行情价格（可选） | 手机只要几个币，现在拉整个快照（gzip 86 KB） | `/api/overview/snapshot?coins=` |
| Telegram 消息带运行页链接（可选） | 推送是手机的主要入口 | `live/notify.py`，需要部署地址；Live 控制程序的改动单独一个 PR |

## 独立复查

一个没看过本方案的子代理加载 `artifact-design` 和 `dataviz`，拿用户原话、桌面截图、现在的手机截图和第 1 版画面
并排审，给了 12 条。改了 11 条：

- Live 卡片补上最近成交、亏损额度（桌面的回撤进度条）、止损离现价多远和观测时间；Paper 卡缩小。
- 确认单里还没发生的步骤改成圆点，按住时倒数，填充改浅色，写出现价和点差。
- 手机里的标题字体回到 Supply（第 1 版被页面的中文字体覆盖了）。
- 去掉自造的描边状态胶囊，改成桌面那样的彩色文字；出事时不再三处重复同一件事。
- 权益线加整数刻度、时间轴、起点和亏损上限的价签，暗色渐变加深。
- Market 改用桌面 Overview 卡的键值行，去掉字母圆标；热力块加间隙、右上角涨跌徽标和色阶条，配色按桌面 token
  （`model/heat.ts` 的 24h 阈值 0.1 / 1 / 2.5）；BTC 行下写出自己的仓位。
- Research 徽章放到名字前，去掉重复的读数行和多出来的回报进度条。
- 大数字统一是权益，涨跌放进胶囊，小数同色变淡。
- Settings 移进右上角菜单，去掉页脚。间距回到 4px 网格，标题用 17px。

没照改的：未解决时在手机上加「平仓」按钮（新的真钱操作，Live 控制程序没有这个动作，列为待决定 1）；给按住加一个
不用按住的替代（个人工具只有一个使用者）。

第二轮由同一个子代理核对第 2 版：12 条里 7 条已改好、4 条部分改好，间距仍不齐，另外第 2 版带出一个样式优先级的 bug，
让 Paper 的健康警告变成灰色。第 3 版改了：健康警告恢复琥珀色；未解决改成状态位上的红字；浅色主题的涨跌胶囊文字加深；
预算和亏损上限的标签贴到价签旁，权益面积不再画到亏损上限以下；首页只留每个运行自己的观测时间；Research 列表头写明右列是
版本数；停止单的标题和版本名分两行；Paper 页把健康状况提到余额下面并给权益线补上刻度；分区标题和卡片边框对齐到同一条
12px 边线；分段控件改回桌面的画法。没补的是热力块里的成员条和 Paper 图上的回撤上限线：画上会把曲线压平，回撤上限
已在目标卡里。

## 待用户决定

1. Live 结束后留下仓位时，手机上要能平仓吗？建议第一版不要：Live 控制程序没有这个动作，加它是新的真钱操作。
   手机上写清仓位和去处（桌面对账，或币安 App 平仓）。
2. Paper 能在手机上停吗？建议不能：Paper 不碰钱，没有紧急的理由，停止会封存运行。
3. 手机上还要 Agent 吗？建议不要。要的话只加回对话。
4. Telegram 推送要带运行页链接吗？建议要。
5. 停止用「确认单 + 按住 1.5 秒」吗？建议是。备选：确认单里输入版本号。
6. 价格表放哪些币？建议运行在交易的合约加 BTC、ETH、SOL，固定；自选列表要存储，不建议。
