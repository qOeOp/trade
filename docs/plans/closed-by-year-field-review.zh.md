# 按年拆分读数：字段评审与决定（WS9）

状态：已实施。来源：[rd-round-audit-refactor-plan.zh.md](rd-round-audit-refactor-plan.zh.md) WS9 共识第 3、5 项。

## 要加什么

- `artifacts report` 增加 `closed_by_year`：按已平仓周期的平仓 UTC 年份分组，每年给出 `{closed_trades, price_pnl_usdt, fill_commissions_usdt, reported_funding_usdt}`。
- `artifacts run --explore` 的返回结果增加 `readings`。它用同一套代码读探索产物，输出与 `report` 同名的读数：`native_economics`、`closed`、`closed_by_year`、`closed_trades`、`open_positions`、`unrealized_residual_usdt`、`plans`、`limitations`。
- 不进 `compare --analysis`，不新增 Dolt 存储字段或 schema。

## 独立评审（2026-10-11，独立子代理，只读）

按 AGENTS.md 的四问：

- **消费者**：开题门槛的两条判据（扣费前价格盈亏总体为正；去掉贡献最大的一年后仍为正），以及失败部件表里"毛边际"的判定。
- **独立事实**：每个已对账的平仓周期，按它的 `ts_last`（整数纳秒，与计划读数同一约定）恰好落入一个 UTC 年份。
- **为什么现有字段不够**：`tables()` 加上 Agent 脚本也能算出来，但这个读数决定开题和排除，由想开题的 Agent 自己算，等于自己给自己打分；算错还会误杀假设。
- **结论**：接受，附带修改（见下）。

## 采纳的修改

- **整周期归平仓年。** 资金费跟着周期一起算进平仓年；跨年的周期只计入平仓那一年；期末未平的仓位不计入，与 `closed` 口径一致。首尾两年是不完整年份。
  - 已知局限：持仓数月的策略，跨年收益会落到平仓那一年，"去掉最好一年"这道防线会被削弱一点。按市值逐年重估需要 exposures，并且会混进未实现盈亏，暂不做。
- **手续费和资金费的逐年值保留**，"成本"部件的诊断要用。
- **不加"去掉最好一年"这个值**：它就是总额减去最大的那一年，属于可推导的值，按先例删去。
- **不写"各年相加等于总额"的检查**：同一列表的划分必然相等，这样的检查恒为真。
- **`ts_last` 缺失或不是整数时**，只有这一项为 null，原因写进 `limitations`，以 `closed_by_year is null:` 开头；`closed` 和 `plans` 照常输出。
- **没有平仓周期时输出 `{}`**，与读不出来的 null 区分开。

## 探索读数（实现时发现的缺口）

开题门槛用的是不封存的探索回放，而 `artifacts report` 只读已封存的运行。也就是说，探索阶段原本没有任何产品读数，Agent 只能手写读者。因此 `explore` 直接附上同一套读数。

- 读数来自 Agent 自己的临时产物，没有哈希校验，只用来判断方向；决定不得引用它，要引用就封存后用 `report` 读。
- 运行中途停止、报告不完整时，所有读数为 null，原因写进 `limitations`，回放结果本身照常返回。

## 验证

- 单元测试：
  - 跨年周期整体归入平仓年，`ts_last` 恰为 1 月 1 日 00:00 的算新的一年；
  - 期末未平仓不计入；
  - `ts_last` 缺失时只有这一项为 null；
  - 没有平仓时输出 `{}`；
  - 探索读数与封存读数相同。
- 真实产物：
  - 37 币全年的一次探索产物（D11 的策略），各年合计与 `closed` 总额误差为 0；
  - 已封存的 `RR20261011-D11-C37` 给出相同的逐年值：2025 年 131 笔、价格盈亏 −3782.33；2026 年 795 笔、价格盈亏 −1522.06。两年都是扣费前为负。
- 运行器和镜像没有改动，镜像构建只看 `backtest/`、`pyproject.toml` 和 `uv.lock`。订单、成交和账户经济在结构上就不会变，所以不需要配对原生回放。
