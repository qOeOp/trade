# 账本存储审计：该存什么，什么只是缓存

2026-10-18。依据是已合并的设计文档（研发长链各章与设计页）和一次全池演练的真实运行。这是后续账本交互与存储瘦身的入口：先定判据，再列全部读写路线，最后逐项给出判定。本记录不改代码、不写账本，不涉及现有账本的改写。

## 结论

- 一次全池研究运行，按现在的设计要往账本里写约 1.9 GB 原件，绝大部分是缓存：钉死环境下重放就能再生成，而且封存之后几乎没有读者。
- 体积最大的两项是账户报告逐行原文和逐分钟敞口表，分别约 1.46 GB 和 357 MB（压缩后）。前者每行都重复带着全部合约的保证金明细，而保证金明细没有任何读者。
- 同一事实存了多份：源码字节存三份，覆盖回执每次试验存两份且整条路线都一样，原生摘要与运行器标准输出是同一内容，镜像身份每个运行重复一份。
- 按严格判据，一次研究运行在账本里只需要不到 1 MB：结论、封存时算出的指标、日收益、紧凑的持仓周期和报告指纹。原生报告改为缓存，靠语义比较验证复现。
- 前提已实测：同一源码、同一镜像、同一输入重放两次，语义比较零差异，账户报告、敞口表与日收益连字节都相同。用户 10-18 授权把 AGENTS.md 的存储条款改为本判据（qOeOp/trade#1559）。

## 判据

账本存在是为了两件事：不让 Agent 给自己打分或事后改写历史；让任何结果都能复现。由此，只有四类内容配进账本：

1. **决定和声明**：登记、判断、源码审查结论、研究路线、样本外登记。它们必须钉在时间上，防止事后修改。
2. **观测不到第二次的事实**：运行失败或中断的日志、外部来源原件、时间凭证、交易所数据。
3. **复现其余一切所需的最小身份**：源码字节、镜像摘要、市场提交、有效配置与输入的身份。
4. **在信任边界上一次算出、之后冻结的指标**：审计与资格结论、绩效指标、归因与报告模板里的标量、日收益。

其余都是缓存：确定性回放可以再生成，放 /tmp，账本只留指纹。另有三条约束：

- 同一事实只存一处，其他地方引用它。
- 能从已存内容算出的不存，读的时候算。
- 没有当前读者的不存；将来有人要读，再按那时的需求加。

## 实测依据

ROOT 运行（211 个子策略共用一个账户，一年窗口）的原生输出：

| 文件 | 大小 | 行数 |
|---|---:|---:|
| 账户报告 account.csv | 1.46 GB | 19.4 万 |
| 敞口表 exposures.csv.gz | 357 MB | 2633 万 |
| 持仓报告 positions.csv | 52.7 MB | 3225 |
| 覆盖回执 input-coverage.json | 24.9 MB | — |
| 原生摘要 summary.json | 3.65 MB | — |
| 运行器标准输出 native.stdout.txt | 3.65 MB | — |
| 订单、成交、订单事件、日收益 | 合计约 6.1 MB | — |

后来的版本并发持仓少得多，H07 的账户报告约 2.1 万行；但每行仍带全部在场合约的保证金明细。

在隔离的临时 Dolt 库里实测，本机 1.80.2 与钉住的 2.4.2 结果一致：

| 实验 | 结果 |
|---|---|
| 同一个 20 MB 随机内容存两行 | 第二行只多占 4 KB：按内容去重 |
| 30 MB 账户报告文本存一行 | 约占 2.3 到 2.4 MB；gzip 只要 0.29 MB |

所以完全重复的内容几乎不占空间，它的代价在逻辑：多处要同步、导出和复核要多读。体积的大头是逐行入库的原始报告。

原生报告里的持仓编号和事件编号是随机 UUID，重放不会逐字节相同。设计里的语义比较入口会剔除这些随机列，再逐行比较订单、成交、持仓、账户与资金费，复现靠它来验证。

## 重放确定性实测

运行镜像用本机已有的 #1537 PR 构建（它的运行输入与 main 逐字节一致），按摘要引用，不联网。用一个探针策略在两个一次性账本里各回放一次：10 个主流永续，2025-01-01 至 2025-04-01，1 小时均线交叉多空切换，市价单，固定名义。

| 表 | 行数（两侧） | 语义差异 | 字节 |
|---|---:|---:|---|
| 订单 | 1080 | 0 | 不同，只在随机编号 |
| 成交 | 1080 | 0 | 不同，只在随机编号 |
| 持仓 | 545 | 0 | 不同，只在随机编号 |
| 账户 | 6061 | 0 | 相同 |
| 日收益 | 90 | 0 | 相同 |
| 资金费调整 | 2490 | 完全一致 | — |
| 敞口表 | — | — | 相同 |

两侧期末权益、闭仓 535 笔、盈利 175 笔、夏普与日收盘回撤完全相同，工程一致性比较判通过。

之后在含括号单与限价单的策略上补测，每组都在一次性账本里换进程跑两次：

| 探针 | 范围 | 覆盖的机制 | 结果 |
|---|---|---|---|
| 两档括号单 | 全池 77 个合约，2025-02-08 至 2025-05-01 | 限价入场、止损与止盈子单、单撤另一单、5 千多笔挂单过期、离池撤单平仓；单一时刻最多 300 笔订单 | 订单 14593、成交 8412、持仓 2293、账户 32960 行零差异；2573 条资金费一致；56999 条订单事件按首次出现顺序重编随机编号后完全相同；敞口、账户、日收益逐字节相同；审计发现两次一致 |
| 大额括号单 | 3 个成交清淡的合约，同一窗口 | 33 笔订单分多次成交（部分成交） | 各表零差异；1553 条订单事件重编后相同；敞口、账户、日收益逐字节相同 |

两档括号单探针暴露了探针策略自身的一处竞态（第一档止损平仓撤单时，第二档同一根 K 线成交，新仓没有止损），两次回放的审计都报出同一条发现，这本身也说明结果可复现。没覆盖的还有：下架结算、换一台主机。

## 逐项判定

### 保留：决定、声明与最小身份

| 内容 | 理由 |
|---|---|
| 候选：源码字节与谱系 | 复现的根，不可再生 |
| 试验行 | 次数是多重比较的分母，失败与中断也要计 |
| 网格点消耗行 | 防同一点重跑挑结果 |
| 登记包（含执行身份） | 登记先于回放的证明；执行身份在这里一处存 |
| 源码审查包 | 独立审查的结论 |
| 判断（推荐、优先级、复盘节奏、解释）及主体 | 决定的历史 |
| 样本外登记、绑定、时间凭证 | 一次性检验与时间证明 |
| 来源原件、更正、生命周期事实证据包 | 外部原件可能消失；更正与生命周期是事实 |
| 失败或中断阶段的日志 | 观测不到第二次 |
| 写入头、模式代数、提交校验 | 并发与留痕的基础 |
| 市场库：成交价 K 线、资金费、合约条款、共同可交易范围 | 交易所数据会修订，是复现的输入 |

### 改结构

| 内容 | 现在 | 改为 | 理由 |
|---|---|---|---|
| 研究路线 | JSON 证据包，按包名编号找最新 | 一张只追加的类型化路线表 | 每次登记、判断都要读；同样的信息，不再解析 JSON 和包名 |
| 运行的镜像身份（镜像修订、引擎版本、依赖锁、运行契约、镜像检视） | 每个运行一份 | 不存，按试验的镜像摘要读 | 属于镜像，同一摘要下处处相同 |
| 运行的有效配置与输入身份 | 运行行一份，登记包一份，开始回执又一份 | 研究运行只在登记包里存；探索与预检在开始回执里存哈希 | 绑定时已核一致，多存一份只是多一处要对 |
| 运行的绩效指标列 | 年化、计划胜率与它们的原料并存 | 只存原料：期末权益、计划计数、利润来源各项合计、标记价回撤 | 年化由期末权益与窗口算出，胜率由计数算出，读时算 |
| 日收益表 | 每天一行收益 | 加一列当日平均总名义敞口 | 代替整张逐分钟敞口表，供资金使用与仓位择时 |
| 持仓报告 | 每行原文，含全部成交与资金费事件列表 | 每个闭仓周期一行类型化列：合约、方向、开平时刻、价格盈亏、手续费、资金费、出场类别、平仓单标签 | 利润来源、交易结构、交易配对、出场原因都只用这些 |
| 归因与报告模板的单运行标量 | 读时从逐行报告现算 | 封存时算一次，和绩效指标一起冻结 | 同绩效指标：信任边界上算一次；读时不再需要原始行 |

### 移出账本：只留指纹

| 内容 | 每次规模 | 理由 |
|---|---:|---|
| 账户报告逐行 | 至多 1.46 GB | 回撤、对账、锁定保证金都在封存时算完；保证金明细没有读者 |
| 逐分钟敞口表 | 至多 357 MB | 只用于封存时的回撤与资金使用，以及逐日敞口；都改为封存时的标量与逐日列 |
| 订单事件逐行 | 约 1 MB | 只供封存时的保护单与对账审计；复核时重放 |
| 订单、成交逐行原文 | 约 5 MB | 漏斗计数与费率在封存时算出；逐行明细属于下钻 |
| 开始回执与封存里的源码字节 | 每份约 10 KB | 候选表已有，按哈希引用 |
| 覆盖回执 | 25 MB，每次试验两份 | 由市场提交、合约集与窗口廉价重算；整条路线都一样；导出指纹已在输入身份里 |
| 通过运行的原生摘要全文与标准输出 | 各 3.65 MB | 两者同内容；用到的字段已成指标，全文是缓存 |
| 预检的全部报告文件 | 至多同一次研究运行 | 审查结论已入账；报告可重放复现 |
| 探索的开始回执与封存内容 | 同上 | 探索不作证据，只需计数：试验行、源码哈希与各阶段退出码 |
| 市场库标记价 K 线的开、高、低与成交量 | 标记价行的约四成字段 | 导出只取收盘价；新月份起不存，已存的不删 |

### 删除：没有决定依赖它

| 内容 | 理由 |
|---|---|
| 判断种类「搜索暴露」 | Agent 自报、代码不核；多重比较的次数由账本统计；固定的报告模板也缩小了自选视角的空间 |
| Agent 自由文本证据包 | 与判断重叠；证据包只留来源、登记、审查、更正、生命周期这几类 |

按以上判定，一次 ROOT 规模的研究运行在账本里的原始体积，从约 1.9 GB 降到 1 MB 以内。

## 前提、代价与要你定的事

- **确定性已实测。** 市价单、括号单、限价、单撤另一单、过期、部分成交、同刻多笔订单都零差异。还缺下架结算与换主机；任何一次不一致，原生报告就不能当缓存，判定要重来。
- **下钻要重放。** 固定报告与模板之外的分析，例如某一笔订单的事件序列，要先重放到 /tmp 再读。全池一年的回放耗时还没有测。
- **AGENTS.md 已按本判据改写。** 用户 10-18 授权，见 qOeOp/trade#1559。
- **复核改为重放核对。** 整体复核目前用逐行报告重算绩效指标；改为按复现清单重放，再与封存的指标和指纹比较。
- **现有账本不改写。** 判定只用于按文档重构后的新结构；已有账本与备份保持原样，需要时另行授权。

## 建议顺序

1. 在含下架结算的窗口上重放两次，再换一台主机重放一次。
2. 设计文档按本判定改账本章与报告章：路线表、运行行字段、日收益加列、紧凑持仓周期、封存时算出的模板标量、移出的内容只留指纹。
3. 重构实现时按新结构建表；判定为删除的两类，同步改 skill 与评测用例。
