# 绩效归因：设计依据与纸面推演

2026-10-18。对象是设计文档新增的 P 章「绩效归因」。结论：比较证据能说清差是否可信，却说不清差从哪来。在一条真实研究线的六组比较里，按切面拆差给出两组新读法，并把两组已有读法量化。本记录不改产品代码、不写账本。

## 问题

V 章的配对检验给出效应、区间与 p，F 章再按五步诊断读单个运行。两套结果之间的差没有系统拆解：钱从哪来、在哪些合约和哪些天、靠哪些交易、是不是规模或市场暴露。Agent 自己挑数来解释，等于给自己的工作打分。代码因此只算这几样：账户利润来源桥、每个切面的几个标量、登记预测与实测的对照。明细由 Agent 按 skill 自算并交复算。

## 工作方式

沿用 10-12 那次 Codex 长会话整理 27 项职责的做法：

1. 先写问题和几种表述，再到两个以上索引检索，留查询日志。
2. 起草设计。
3. 交独立 Agent 做架构审阅，逐条处理。
4. 拿真实研究线反查：设计里的切面能否在已有数据上算出来，算出来是否改变结论。

## 纸面推演

研究线：全池 RSI 路线十轮演练（Nautilus 2.0.0rc3，交易窗 2025-10-09 至 2026-10-07，初始 100000 USDT）。数据取自 /tmp/trade-rd10-flat-20261014 下各假设的派生统计、日收益、资金使用复核与结果报告，都由当时的官方读口导出。单位 USDT，Δ 指候选减对照。

下表是闭仓周期口径，不是 P.1.2.1 定义的账户口径：手续费是全部成交（含未平周期），资金费由残差推出。它与实测闭仓资金费只差几个 USDT（H06 −76.0 对 −78.2，H09 1978.1 对 1976.2），但四项相加必然等于闭仓差，所以没有检验对账。账户净值差另列。

| 比较 | 改动 | Δ账户净值 | Δ闭仓净 | Δ价格 | Δ费用 | Δ资金费 |
|---|---|---:|---:|---:|---:|---:|
| H05 对 H04 | RSI14→24 | +547 | +529 | +395 | +202 | −67 |
| H06 对 H05 | 单笔预算 100→500 | −63 | −105 | +325 | −343 | −86 |
| H07 对 H06 | 资金费方向过滤新入场 | +658 | +665 | −282 | +119 | +828 |
| H08 对 H05 | 含过滤，预算 100 | +17 | +18 | −184 | +30 | +172 |
| H09 对 H08 | 预算 100→2000 | +3956 | +3795 | +2776 | −777 | +1796 |
| H10 对 H09 | 分钟量占比 1%→5% | −589 | −603 | −1219 | −543 | +1159 |

Δ费用为正表示候选少付。

只有 H06 和 H07 的结果报告给全了账户口径四项，两者都对上了账户净值：

| 运行 | 价格 | 手续费 | 资金费 | 期末浮动 | 合计 | 账户净值 |
|---|---:|---:|---:|---:|---:|---:|
| H06 | 662.05 | −453.76 | −77.23 | +53.94 | 185.00 | 185.00 |
| H07 | 380.38 | −334.38 | +751.50 | +45.32 | 842.82 | 842.82 |

所以 H07 对 H06 的账户利润桥是：价格 −281.67，手续费 +119.38，资金费 +828.73，浮动 −8.62，合计 +657.82。

各切面给出的读法：

- **新读法，H07**：账户口径下，净改善同样全部来自资金费，价格腿反而下降 282，候选只胜 13 个月里的 6 个。H07 登记时的预测本就针对资金费，并写明不声称资金费单项因果。新的是价格腿变差这一点：过滤改变的不只是资金费。下一假设可以单独检验价格腿，指向 H1、C1。
- **新读法，H09**：预算 20 倍，平均总名义敞口只放大 10.6 倍。单位敞口净收益从 0.65 升到 0.97，VELVET 一个合约贡献了差的 43%。去掉差最大的五天后，剩余差为负。改善高度集中，指向 A2、E2。
- **量化已有读法，H06**：预算放大五倍，价格盈亏只放大约两倍，手续费放大约四倍；费用翻倍后对照净 +127、候选净 −322。F014 当时已记为规模反馈。不成比例可能来自成交量上限截断，这一点是从费用比推断的，H05 和 H06 没有敞口数据来验证。
- **量化已有读法，H08**：同一过滤在预算 100 时日对数收益差合计约 0.0002，在 500 时约 0.0065。F014 当时已把 H05 到 H08 记为交互线索。这四个运行的谱系不是从同一个基础分出两支，形状要由源码审查确认后才能读交互。
- **H05 与 H10**：H05 的读法与账户差一致；H10 价格腿变差被资金费掩盖，F014 当时已有同样的读法。

另一个跨版本的信号：FHE 在 H05 到 H10 六个版本里都排在闭仓净盈亏最差的三个合约之内，ROOT 的原生摘要记为不设止损。这指向 A1、A2 或 F3，演练中没有被当作假设提出。

十组比较的 98.5% 配对年化差区间全部跨零。这些切面读数只能指向下一个假设，不能当结论。

未在推演中算的切面：交易结构与回撤（只有 ROOT 的持仓报告在本地）、市场暴露（本地没有对应窗口的 BTC 日收益副本）。

## 审阅与处理

起草后交独立 Agent 做架构审阅。主要意见与处理：

| 意见 | 处理 |
|---|---|
| 交易配对与现行「不跨运行配对单笔交易」规则冲突（阻断） | 改为两侧各自统计的交易结构；是否放宽这条规则列为待用户定 |
| 预测核对与职责覆盖矛盾，代码核对形同虚设（阻断） | 每个改动职责至少一项预测；职责须在 changed_duties 里，标量须在目录里；没有切面的职责写空切面与理由 |
| 明细切面进代码越过信任边界，与 R.1.2 冲突 | 代码只算利润桥、切面标量与预测对照；明细交 Agent 自算并复算 |
| 利润桥与封存时的利润来源拆分重复，总体未写清 | 沿用已对账的拆分，只补期末浮动；写明账户总体 |
| 市场暴露在 R 章仍是待用户定 | 移出固定目录，列为待用户定 |
| 费用翻倍对返佣和对数尺度不成立 | 改为盈亏平衡费率倍数 |
| 前五占总差在总差接近零时不可读 | 改为占全部绝对差的比例，以及去掉前五天后的剩余差 |
| 交互形状按父指针判断不可靠，事后挑二乘二是未计数的比较 | 在补最后一个角的登记里声明；形状由绑定的源码审查确认；不给 p，区间标未校正；复用配对检验加权重 |
| 缺回撤归因 | 新增回撤切面；胜率差在交易结构里拆成胜率与盈亏比两份 |
| 「按固定顺序读完全部切面」是仪式 | 改为只引用所依据的切面，并逐项核对预测 |
| 下一假设只能取缺省职责，与按归因指向冲突 | 放宽为缺省、不适用或归因指向的职责 |
| 切面目录放在报告模块会加深模块环 | 目录与 27 项职责表放在登记模块 |
| 「改写四组」说法过强 | 改为新增两组读法、量化两组 |

## 字段决定

登记体的 prediction 由一段文本改为结构化子项：mechanism 每项写切面、标量、方向、职责与理由，outcomes 写五类结果的后续动作，可选 interaction 声明二乘二的四个角。prediction 本是登记体的必有键，旧文档列必有键时漏了它，这次一并更正。不新增表；结构化之后，这些子项是登记体内由代码读取的子字段。登记时新增拒绝码 PREDICTION_INVALID，属于收紧登记核对，用户 10-18 已同意这一方案。审阅确认：把 prediction 补成必有键是修缺陷，子项只保留切面、标量、方向、职责、理由五项是最小改法。
