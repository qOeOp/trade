# Live 撤单重试测试的浮点时钟边界

主分支 `1d2be9e44` 的 [quality 运行](https://github.com/qOeOp/trade/actions/runs/42352845390)
在 `test_stop_repeats_a_cancel_while_the_order_stays_open` 失败：第二次撤单预期两次调用，实际一次。
该测试先从主机读取任意 `monotonic()` 起点，再构造 `起点 + 5`；产品用相减结果判断是否已满五秒。

浮点数不保证 `(x + 5) - x == 5`。例如 `x=127.123456789` 时结果为
`4.999999999999986`，产品按原有小于五秒分支暂不重试。用此起点运行原测试、保留全部原断言，
可复现同一失败；`8190.123456789` 也失败，而 100、128、8192 通过。CI 没有保存实际起点，
因此无法恢复那一次的精确操作数。这证明测试夹具有同样的确定性反例，不证明真实撤单永久丢失。

修复只固定测试起点为可精确表示的 `100.0`，账户查询的 `last_query` 也取同一起点。
最后一轮测试到 `110.0` 时正常触及十秒查询间隔，因此补齐 Observer 的 `query_account` mock，
不把查询时间设在未来来避开协作者调用。原五秒门槛、所有撤单次数与原生 cancel-all 断言均保留。
产品实现、拒绝规则和真实账户配置没有修改；没有新增持久字段或调度器。
