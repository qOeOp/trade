# 投研产物保管：最小交付与验收

> 历史快照：本文保留 Git 侧录阶段的设计与验收背景，登记及元数据操作已由 Dolt v2 契约替代。现行操作以 [research-round skill](../../.agents/skills/research-round/SKILL.md) 和[当前架构](../architecture.zh.md)为准。

当前单机实现及真实运行结果见[验收记录](research-artifact-custody-acceptance.zh.md)。以下保留交付范围与验收边界；异机备份和正式目录的运维验收仍待完成。

## 决定

沿用 Trade 的 Git 仓库保存 `attempt.json`、`run.json`、解释和源码历史；原生回放仍只有 `strategies/r1/run_portfolio.py`。新增一个薄的本机命令行保管工具，负责在运行前冻结执行源码、核对输入身份，在运行后封存原生报告，并按运行 ID 校验及恢复。产物根目录由调用方配置，不放入 Git 或 `/tmp`。不引入服务、数据库、任务队列、策略语言或第二套回测账本。

外部 Agent 仍负责提出假设、事前登记和选择回放；本工具不替 Agent 决定候选、对照或经济裁决。封存成功只表示字节可恢复，不表示策略合格。无法通过输入、源码、原生报告及独立审计检查的运行仍应保留为失败证据，但不得标为通过。

## 实现顺序

1. `research.records.artifacts run`：按固定 Git 源码提交取出 R1 Python 文件，连同实际 `uv.lock` 和输入身份复制到临时目录；核对选定币种的 minute/daily Catalog 树及数量 CSV；从冻结源码启动现有 runner，保存 stdout/stderr、摘要、原生 CSV 与审计；再次核对输入字节；逐文件 SHA-256 后原子发布 `<root>/<run_id>`。同一 ID 不覆盖。
2. `verify`、`backup` 与 `restore`：按 manifest 校验全部封存文件，拒绝缺失、额外或被篡改的文件；复制到第二目录、恢复原生报告并再次核对哈希。失败执行保存已产出的诊断材料和明确状态；进程异常中断的 staging 保留待人工核查，不冒充已封存运行。
3. 运行记录带 `artifact_manifest` 引用，读回校验可选连接配置的保管根目录；Git 侧录保留研究脉络，保管目录保留大文件。历史临时运行不追认成已封存。
4. 以真实 R1 BTC/ETH 运行验收：封存、查验、删去工作副本后的恢复、故意篡改拒绝、重复 ID 拒绝及原生订单/账户审计；再以 37 币候选运行确认同一流程。文档与 CLI 帮助通过构建和测试。

## 验收边界

本机验收要求：源码和输入身份可核实，运行及审计与封存 manifest 一致，原始报告可从指定根目录恢复，失败可定位且不覆盖已有运行。根目录的磁盘损坏备份、异机恢复及多 Agent 并发压测仍需独立运维验收；在这些条件就绪前只能称单机保管能力，不能称跨机器灾备或实盘生产部署。研究回放始终只读，不使用交易凭据。
