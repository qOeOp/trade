## 数据与身份决策

- schema 3 的 run 继续表示正式封存结果；trial_id 同时为其主键和指向 trial 的外键。
  run_sealed、run_return、run_cycle 的外键指向 run(trial_id)，不能为一个仅有 trial 的预检写经济读数。
  原来严格的一对零或一关系保持；实际执行前先写 trial，封存结果可能稍后出现或一直缺失。
- 移除第二套自增 run_id。新 CLI、输出、登记对照和导出只使用 trial_id / control_trial_id；
  复现返回原 trial_id 和本次执行的 reproduction_trial_id，二者属于同一身份空间。
- research-plan-v2、ledger-export-v2 区分新的编号语义。没有旧编号别名或原地历史转换。
- 最新研究结果按结果插入提交的顺序选择：查询已有 Dolt 结果插入提交及该提交的 ledger_head.seq。
  不用 trial 启动顺序或存在同值的 created_at 排序，也不新增完成顺序字段。
- 没有新增存储事实、表或列。主键、外键和 JSON 对照字段更名表达的是原有事实；
  再生关系、核验状态和缓存位置均不新增持久标记。

## 预检存储与消费者

保留 candidate 的完整源码、trial 的窗口与镜像、启动回执的输入和配置、原覆盖回执、
执行阶段和结局、原始日志、runtime_failures、summary、audit、语义 fingerprint 及独立 source review。
沿用现有 evidence 内容寻址与 capture 清单，不另存一份技术投影。

完整成功且具备可读指纹的预检，其七种原生表只保存路径、长度和哈希，文件留在 /tmp。
失败、中断、审计未成功或缺指纹的预检继续保留原报告。本次不提高准入要求，不调整现有容量阈值。
后来的成功再生不能替换原始失败或使原审查通过。

`replay report --trial-id P` 读取原技术事实；与 `--directory DIR` 合用时按原清单核验缓存。
缓存缺失时 `replay reproduce --trial-id P --output DIR` 沿原身份创建新的 explore trial M，
比较原指纹，再用 `--reproduction DIR --reproduction-trial M` 读取核验后的明细。
原 summary、audit 和日志始终以原捕获为准；七表的技术字段由固定运行时的完整语义指纹核验，
随机 UUID 的正常变化不要求逐字节相同。再生目录本身必须逐文件匹配其自身封存清单。

独立审查仍核 api、causal、activity、readiness 四项，并绑定原 P。预检报告始终不是经济证据。
正式 tables() 的 positions 仍是存储周期；读取原生明细不能覆盖它。

## 暴露规则调整

成功再生的豁免仅锚定本次登记实际引用、且本来满足短预检豁免的原预检。
再生必须为新的 explore、晚于原执行、源码/镜像摘要/完整窗口/合约/配置/输入一致，
两边原始 capture 的 native、audit、fingerprint 完整成功、没有 runtime failure，且原指纹一致。
复用同一派生核验实现，不新增 purpose、缓存登记或“再生成功”字段。

其他 explore、不匹配、失败、中断、缺指纹和无关预检仍按原暴露规则处理；失败取缓存仍可能影响登记。
已有 failed review 仍否决；重试仍读取原封存时的审查范围。
状态计数识别成功的预检再生，不把读取等价报告再算一次策略试验。
