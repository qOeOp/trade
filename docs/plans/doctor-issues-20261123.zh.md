# Doctor 发现只记在 issue（2026-11-23）

用户 2026-11-23 问「issue承担了保存记录功能 还需要项目内的文档保留嘛」，看过方案后：「就这样改」。取代 2026-11-22「索引仍是唯一的状态记录」「权限项不进 issue」。

## 为什么

同一发现记两处：索引 94 KB，未结 161 行里 146 行是 `fixed`，每个审计和修复 PR 都要改这张表。带 `agent-finding` 的 19 个 issue 全含中文，因为规则没写语言。

## 分工

| 内容 | 地方 |
|---|---|
| 单个发现：证明、补救、讨论、状态、认领、授权原话 | issue，英文，号即 id |
| 复现与验收 | 修复 PR 与回归测试 |
| 设计决定、存储字段评审 | `docs/plans/` |
| 有意保留的形状 | `docs/plans/doctor/index.zh.md`，随代码评审 |
| 完整审计的覆盖与缺项 | 记录文件，只链接 issue |

状态用 GitHub 已有的：开、关（completed / not planned）、重开、标签 `claimed`、`needs-evidence`，新加 `authority`。`authority` 标签不是授权：要评论里有用户原话。

## 迁移

未结且没修好的行开成 issue；三行 `in PR` 的 PR 都已合并，算 `fixed`。146 个 `fixed` 行不逐条开 issue，冻结在旧索引的永久链接里，供整体审计复验。仍开着的 issue 译成英文。

## 代价

issue 可被改写、离线读不到，所以证明也写进修复 PR 与测试。仓库公开，外人能开 issue，只认用户账号开的、带标签的。
