# 2026-11-28 product-doctor 召回考卷与基线

product-doctor 的价值是在可接受的成本内找出真缺陷。原有的 eval 只检查它守不守规矩，测不到它能找到多少问题，所以对 `SKILL.md` 的改动无从判断好坏。本卷用已确认、已修复的历史缺陷当标准答案，量 doctor 的召回。它只作回归检查（见“用法”）：doctor 的设计是按主题一轮轮审计、修复、再审计，不是一次找全，单次召回不是它的目标。

## 考法

| Item | Value |
|---|---|
| 产品树 | `3f10104a1`（2026-11-24 18:18 UTC）。#3654–#3712 等一批缺陷都是在这棵树上发现的，修复都在它之后合并 |
| 作答的 doctor | 作答当时 `origin/main` 的 `.agents/skills/product-doctor`（`21c94f7ed`），拷进产品树替换旧版 |
| 隔离 | 每题一份 `git archive` 副本，`git init` 后只有一个提交，`origin` 是只含该提交的本地裸库；`PATH` 里的 `gh` 换成只报错的壳；`--strict-mcp-config --setting-sources project,local`，不带用户记忆；作答后检查转录里没有 GitHub 或主仓库的访问 |
| 题目 | 只给主题 **Find** 和对象（见下表），不给文件行或症状 |
| 预算 | 每题 60 分钟、40 美元上限；临时账本，不碰活动账本、市场目录、Docker 服务和凭证 |
| 判卷 | 答案在作答前由独立 agent 定稿（[答案](2026-11-28-recall-exam-key.md)），判卷由另一个独立 agent 做：核心缺陷判命中、部分命中、漏；邻近缺陷命中有分、漏不扣；被分拣否定的说法若被报成缺陷记误报；其余发现读代码分为新的可信缺陷、非缺陷或不是缺陷 |

作答命令（每题在其副本根目录，`prompt.md` 为下面模板代入对象和证据目录）：

```sh
PATH=<gh 壳目录>:$PATH env -u GIT_DIR -u GIT_WORK_TREE -u GIT_INDEX_FILE -u ANTHROPIC_API_KEY \
  timeout 5400 claude -p "$(cat prompt.md)" --output-format json --permission-mode bypassPermissions \
  --strict-mcp-config --setting-sources project,local --max-budget-usd 40
```

作答时每题设各自的 `TMPDIR`（短路径，如 `mktemp -d /tmp/dx-<题>-XXXX`），否则一题的清理会停掉另一题的临时账本；无头会话在主 agent 结束这一轮时就退出，模板须要求前台等子 agent 跑完，否则可能交不出报告。

模板要点：用 product-doctor 做主题审计，主题已定为 Find、对象为 `<对象>`，跳过信号脚本和选题；本副本的 `origin/main` 就是被审的树；不用 `gh`、GitHub API 和网页，也不以别的方式查 issue、PR 或后来的提交；不开 issue，把所有发现按 `record.md` 的 issue 形式写进证据目录的 `report.md`，附 `doctor.py report` 和未检查项；只用临时账本；60 分钟，过 70% 不再加工作。

## 漏的原因

42 条未命中（含 3 条部分命中）里没有一条需要发布主机；33 条（D–H）中 26 条只需本地探针，7 条读代码即可。判卷归出的原因：

1. **预算没用完。** 所有题在 60 分钟里只用了 13–35 分钟、9–21 美元。E、D、F、H 的“未检查”清单正好写着后来漏掉的机制（如 E #3671 的 egress 网络创建与其记录之间的崩溃，D #3688 的归档重发）。
2. **对象里有模块没被任何一轮打开。** E 写明 `live_session`、`live_lifecycle`、`live_source` 未检查，11 条核心里 4 条在那里；H 没看 `backtest.ts` 和市场导入视图。
3. **只造单个实体、单步。** 两个运行、通过后接重试、一个实例两个合约、前后两步的缺陷全漏（A #3681、#3790，C #3657、#3659），两次都漏。
4. **参数只取默认、输入只取合法。** A #3760 只在预热为 0 时跑；F 没有喂坏的 `--universe`、缩写选项或坏日期（#3669、#3791、#3714）；B、H 没把恶意 HTTP 输入当成视角（#3697）。
5. **没造出有内容的研究状态。** F、H 嫌造研究线贵，H 只在空账本上看页面，丢了 #3680、#3681、#3685。
6. **怀疑了没探针。** H 的两条部分命中、B 重跑的 #3697 都只写成备注；一行探针就能变成命中。
7. **替身抹掉了缺陷。** G #3693 用同一用户跑归档步骤，root 与非 root 的权限差没了；H #3682 的假 EventSource 会进 CLOSED，而 Chromium 停在 CONNECTING，后者才是缺陷。
8. **反驳只引文档。** C 首跑的反驳者引一份设计文档就把真缺陷 #3674 判成“按设计如此”，没有反证探针；重跑时 #3674 被确认，但另一条“按设计”同样没有探针。
9. **主题审计的视角收窄。** 平价、结构（导入环）、检查（mypy、缺测试）等便宜的静态视角没被选上（E #3660、#3661，E/H #3703，G #3710，D #3705）。

## 第一轮改动（否决）

在 `SKILL.md` 加了约 80 词：Find 跑对象涉及的每组视角、每个模块一轮、用完预算、按使用造多实例和非默认输入、怀疑必须探针或记未检查、替身保留关键差别、“按设计”须有一次运行。训练集 A、C、D、F、G 各跑一次：核心命中 6/26，与基线相同（A 2→3、C 1→0、D 1→0、F 1→2、G 1→1），多了 1 个误报（A 把否定项 #3678 报成缺陷），每题更久更贵，漏因照旧；作答者把漏掉的区域都写进了“未检查”，是嫌造替身贵而停，不是不知道。未合并，未跑 held-out。

这些措辞一半照着漏掉的答案写，违反 skill 文本短、通用、只写运行时要用的原则（`.agents/README.md`）：照考卷调措辞会把 doctor 训练成做题机器，而每次迭代十几题、上百美元，投入产出也不对。

## 用法

不再用本卷迭代 skill 措辞。doctor 的改进由真实审计循环（主题审计、分拣、修复、再审计）里看到的失败驱动，按每轮确认数、每条确认缺陷的花费、反驳推翻数和下一轮的新发现来看。本卷只在大的结构改动前后做回归检查：从 B、E、H（held-out，核心 25，基线命中 3）里跑两三题各一次，看命中和误报是否明显变差；单次波动约每题 ±1 条。考卷只到 `3f10104a1` 这一棵树，答案不改。

## 边界

- 每题只给一个对象，量的是“给定对象时能找到多少”，不量选题；选题信号另行检查。
- 需要发布主机、真实账户或长时间运行的缺陷不在卷里（答案里标为 unconfirmed 的那些），本卷对它们不说什么。
- 答案依据分拣评论和合并的修复；#3667、#3668、#3695、#3700、#3702、#3698、#3699、#3662 是“复现了但不值得改”的边界否定项，判卷时单列。
- 作答的原始报告和转录是 `/tmp` 工作副本，不入库；判卷结论记在本页。
