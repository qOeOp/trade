## 整体结构

包的分层成立：`tests/test_package_layers.py` 通过，deploy 只用标准库，ide 不导入产品包。大多数跨包切分沿着真实的运行时边界：`engine/` 单独装进按摘要固定的镜像，`deploy/` 跑在系统 Python 上，paper 与 live 互不导入，IDE 只经 CLI 到产品。累积的分量在四处：

1. **跨边界的副本。** 每条边界都有理由，但能导入的一侧没有指定主人。宿主抄了 `engine.config` 的哈希规则、主机路径键、运行时契约、捕获名与身份元组，再用固定测试让它们相等，而 `engine.config` 不依赖 Nautilus、可以导入。Paper 与 Live 的运行器管道在 `engine/` 里建了两遍，Live 的副本已经漂移。Live 的拒绝目录并进回放目录，Live 专有的改动会移动研究身份。方向：`engine.config` 与 `engine.compare` 拥有宿主与镜像共用的每个名字；每个运行器自己的拒绝目录；引擎加几个小的共用运行器模块（Redis 子进程、缓存报告、策略构造）。Live 靠共用代码跟上 Paper，不靠复制。
2. **私有名当接口、模块没有主人。** `live/runs.py` 是运行模型，别的模块经下划线函数进去；`ledger.db` 的服务与准备那一半经约 25 个私有调用被用，大多来自 `cli/`，那里放着约 900 行账本服务器；market 的真实词汇是私有的或每模块重抄，`store.py` 混着不相干的东西；`report/status.py` 的五个读取器被 graph 与 history 私下用；`replay/entry.py` 没有公开操作，同一暂存顺序有五份。方向：给每个枢纽一个公开表面，把 `cli/service`、`replica`、`first_run` 移进 `ledger/`。多数是移动不是删除，好处是之后能删掉它们背后的重复推导。
3. **信任边界上被丢弃或做两遍的工作。** 封存算出读数形状的结果又扔掉；coverage 重查 ingest 已定的事；读时复利检查是同义反复；CLI 与包拒同一条件；拒绝目录按抛出点长：一个未知市场日四个码，加上第二张目录和只有测试读的文字。这些要用户授权，因为改拒绝码与检查；它们是保持正确性前提下最大的简化：一个条件一个码，归在路径一定经过的最低层。
4. **重述代码的文字。** 行数最多：`docs/plans` 没有退出规则（约 2,600 行可删）；设计站重述 skill 与 docstring 的机制，已在 HEDGING、`--starting-balance`、视图版本上漂移；docs-site 留着走不到的组件和章节结构的手抄；skill 留着拒绝已强制的句子；评测按发现一条加一个用例；测试带着被取代的基线和 102 个脚本块。方向：设计站引用每条规则并指向主人；计划落地且没人引用就删；产品加拒绝的同一个 PR 删掉被取代的 skill 句子；只留当前契约基线。

动手前要守住的（评论代理列出、没有任何代理验证过的风险）：改名可能让已存的 gen-1 登记无法绑定（`bind` 按当前产品重跑 `validate()`），改名前先用只读 `ledger sql` 查已存的登记正文；改 `engine/` 闭包的各批要新摘要、回放契约决定（v8 与 v9 并存）并证明已封存指纹仍能复现，宜与 -148 和下一次 Nautilus 升级一起；去掉封存里的计算须证明 `run_reading`、`run_cycle` 与日行逐字节不变；真钱 Live 路径的合并要配对证据和用户打的版本标签；CI 把测试当生产夹具（`check-native-runtime.py`、`fresh-install.sh`、`run-tests.py`）；deploy 必须仍只用标准库并与手装模块表一致；拒绝码合并要全量 `git grep`（含 `.agents/evals` 与 `ide/web`）；skill 与评测的改动要排序并先量评测影响；被 pickle 或按字符串分派的名字（graph 子进程、market 进程池任务、`docs/rd` 的 `cli.<fn>` 锚点、约 60 处代码注释引用 `docs/plans` 路径）。
