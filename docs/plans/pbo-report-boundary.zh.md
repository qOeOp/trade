# PBO/CSCV：不纳入默认正式报告

2026-10-25。用户逐项确认：PBO/CSCV 不纳入默认正式报告，不用于资格或自动选策略；保留为候选集合明确时的专项分析，本轮不新增实现。

## 已定边界

- 默认报告不增加 PBO 字段、图表、阈值或资格检查；该项从章节及总待定清单移除，不保留为默认待实现能力。
- 专项分析先明确候选集合、统一执行环境和窗口、完整且日期对齐的收益矩阵及选择标准。连续搜索中的中间版本不直接充当最终候选集合，不把不同镜像、行情或保证金条件的结果混为同一比较。
- PBO 评估特定候选集合下的选择过程，不是单个策略未来有效的概率；CSCV 内部划分不替代产品定义的未来独立验证，也不以降低 PBO 作为策略搜索目标。
- 现有试验计数、配对比较、折扣夏普的分析分工和样本外验证保持原边界，不宣称它们已消除过拟合。不新增分析依赖、命令、持久化字段或运行机制，不改目标、skill 或审计／拒绝检查。

## 现有依据与文档落点

- `report/measures.py` 的度量目录与 `report/comparison.py` 的配对检验均无 PBO 计算；`.agents/skills/nautilus-report-analysis/references/ratios.md` 中的折扣夏普是另一种分析，不等于 PBO 已实现。
- `report/status.py::comparison_table` 按窗口和合约池列出有经济证据的研究版本，包括较早版本；这张表本身未定义 PBO 的候选全集或选择标准，也不保证全部版本执行环境一致。
- [Bailey 等人的原论文第 2.2、5.2 节](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)要求同步收益矩阵，讨论候选信息完整性；针对引导式搜索，列应取各次搜索的最终结果而非中间步骤，并警告不要以 PBO 为搜索目标。[pypbo](https://github.com/esvhd/pypbo)只作参照，不引入为依赖。本轮决定是结合当前产品流程作出的报告边界，不声称 CSCV 不能用于任何自适应搜索。
- 报告的现有目录外分析段落 `R.3.1.6` 解释边界；章节末记录用户决定，总待定清单移除该项。对比章节补充跨章说明，避免仍将参考资料中的 PBO 误读为已实现的全程搜索控制。英文入口保留现有待翻译中文镜像标记。

本轮仅修改文档，不计算活动研究的 PBO、不写账本、市场库或 canonical Catalog，不运行研究回放。
