## 结论

1. **三段切分对人是盲的，对 Agent 不是。** 开发期、否决年和留出期都在研究模型的训练数据之内。文献测到模型对截止前的指数收盘价几乎能背出来，截止后就背不出来。当前流程只在 `hypothesis.md` 里要求 Agent 自报"开发期的记忆不算证据"，留出期和选线都没有覆盖，也没有任何测量。（D1）
2. **研究循环的设计是在同一段 3 年数据上一直搜下去。** 循环不因试验数、达标或换思路而停。推荐版本只有 18 个交易计划，价格盈亏几乎全部来自 2024 年。产品已经报告收缩夏普比率（试验 85 为 0.72），也有换思路、复盘和邻域稳健的规则；缺的是一条按试验数或收缩夏普把研究从"继续在开发期上搜"转向"去拿新数据"的出口。（D2）
3. **唯一干净的证据，即登记之后的前瞻窗口，只能在推荐达到两项目标、用户接受之后才提出，目前没有启动过。** 推荐至今没有同时达到两项目标，这个时机可能一直不来；低频策略又需要很长的前瞻窗口才能分辨效应。（D3）
4. 另有三处较小的缺口：关线留出期结果可以回流到同一留出期的新线设计（D4）；逐步配对比较是名义显著性，没有对整条搜索路径做数据窥探校正（D5）；作者 Agent 同时负责设计、解读和挑选（D6）。

流程已经做对的部分也要记下来，免得修缺陷时把它们改掉：所有试验都入账并计入多重检验、推荐时报告收缩夏普比率、预注册冻结预测、只有登记后的窗口才算样本外、独立的源码审阅不看收益。这几条正是下面几位作者反复要求、而多数研究者做不到的。

## 流程缺陷

### D1 三段切分挡住了人，挡不住 Agent 的训练记忆

**现状。** `line select` 把开发期定为留出期之前的 12 个季度，留出期为截至 Q 的 8 个季度，更早的历史为否决年，只在关线时各跑一次。当前线：开发期 2021-10 至 2024-10，留出期 2024-10 至 2026-09。设计文档 [line-close-history-test](line-close-history-test-20261110.zh.md) 和研究链网站都没有提到研究模型的训练截止。唯一相关的规则是 [hypothesis.md:17](https://github.com/qOeOp/trade/blob/d258a045c5a47dab28ee0611e83c78360d13683c/.agents/skills/research-round/references/hypothesis.md#L17)：Agent 对开发期价格、资金费和事件的训练记忆是回放检查抓不到的前视，不能当依据，并要求对每个依赖的事件说明决策时能否知道。

**外部证据。** Lopez-Lira 等测到前沿模型能以 0.61% 的误差背出截止前的指数收盘价，截止后误差升到 16.87%（表 2）；告诉模型"假装只知道某日之前"也挡不住（§5.5）。Glasserman 和 Lin 的匿名化只能部分去除记忆。Bailey 等在 2014 年就指出，研究者本来能看到全样本时，留出缺乏可信度（§1）。Helm 的现场报告把"模型自身知识造成的前视"列为第一条失败模式，并承认测不出来（§8.1）。DeepQuant 视频 E004 是同一观点的业界说法。

**为什么是缺陷。**

- 写本文的模型（Claude Opus 5.5）按本会话系统信息，知识截止为 2026 年 6 月，覆盖开发期、否决年和整个留出期。其他研究会话所用模型的截止要逐个查明，但只要晚于 2024 年，就覆盖开发期。2022 年的下跌、2024 年的上涨，都是 Agent 设计机制、挑选参数、选择方向时"已经知道"的事。
- 推荐版本 dow-theory@51（试验 85）的价格盈亏在 2021、2022、2023 年三段分别约为 −0.7k、−8.6k、−0.7k USDT，2024 年约 +129.1k，收益几乎全部来自 2024 年上涨中的多头计划（判断 55，现行推荐判断 62 沿用这条结论）。这正是模型记忆最清楚的一段行情。
- 自报规则只覆盖开发期，而留出期的作用恰恰是"设计者没见过"；Agent 无法证明自己没用上记忆，现有规则也不要求测量。技能评测 `exposed-window-no-generalization` 的判分已经接受"整个窗口早于模型训练截止，属于知识暴露"这条理由，说明这个概念在技能行为层存在，但没有落到规则、关线口径或测量上。
- 关线报告把留出结果称为"反驳检验，不是验证"，措辞是对的。但它的反驳力也被削弱：Agent 设计时记得留出期的行情，候选通过留出期的概率被抬高，而报告里没有这条说明。

**修法（由轻到重）。**

1. 把训练截止写进规则和报告口径：研究链网站的验证章节和关线设计里注明，否决年与留出期对人是隔离的，对训练截止晚于它们的模型不是；关线总结同时写出研究所用模型及其公开的训练截止。不需要授权（文档）。
2. 测一次，不靠自报：照 Lopez-Lira 等的做法，在隔离环境里让研究所用的模型回忆 BTCUSDT、ETHUSDT 在开发期、留出期和截止后各月的月末收盘价与重大事件，比较误差。结果作为一次性的诊断记录在 `docs/plans/`，不入账本。不需要授权。
3. 把"晚于研究模型训练截止的历史"标成唯一能在历史上做反驳的数据。目前只有约 2026-07 起的几个月，太短，只能用来发现明显失败。改变关线判定或留出定义属于检查口径，需要用户授权。
4. 把前瞻窗口提前，见 D3。

### D2 研究循环在同一段 3 年数据上没有停止条件

**现状。** [research-round SKILL.md:97–122](https://github.com/qOeOp/trade/blob/d258a045c5a47dab28ee0611e83c78360d13683c/.agents/skills/research-round/SKILL.md#L97-L122)：报告、判断和到期的换思路都不结束循环；只有用户、授权边界或线无法继续才停；两项目标都达到也不停；换思路由 Agent 自己选、自己记录；"Trial counts and budgets do not reject a research direction"，"Poor results never change the line"。用户的两项目标指导解读和优先级，是迭代方向。

**数字。** 当前线 43 个研究试验，有效 12.4 个，开发期 3 年，推荐版本试验 85 的开发期夏普 0.74、年化 25.0%、回撤 31.6%，比较表里只有 18 个交易计划（判断 55 记为 16 个周期），收缩夏普比率 0.72（按有效试验数），价格盈亏几乎全部来自 2024 年（D1）。按 Bailey 等式 (3.1)（假设独立、正态、零技能）：

| 独立试验数 N | 3 年样本上零技能的期望最大年化夏普 | 让期望最大值不超过 1 所需的最短回测年数 |
|---|---|---|
| 12.4（本线有效试验） | 0.97 | 2.8 |
| 43（本线研究试验） | 1.28 | 4.9 |

计算：`python3` 用 `statistics.NormalDist` 按式 (3.1) 直接求值，γ 为欧拉常数。

这张表是上界：式 (3.1) 假设各试验独立，3 年零技能的年化夏普标准差约为 1/√3≈0.58；本线各运行年化夏普的实际离散只有约 0.24（`daily_sharpe_variance` 0.000162 × 365 后开方），因为大多数试验是近似重复。按实际离散，零技能下的期望最大值约为 0.24×1.68≈0.41，试验 85 的 0.74 高于它，这就是收缩夏普 0.72 的来源，比上表更可信。表的用处只在说明方向：试验越是真正不同的方向，开发期上的高夏普越不需要真实效应来解释；产品的收缩夏普会随之下降，但流程不会因此改变下一步。

**外部证据。** López de Prado 在讲座里说回测不是研究工具，用回测就必须控制试验次数、判断是否"用尽运气"（E928–E938、E1039），他的团队对多次访问同一数据的研究扣分（E817–E820）。顶点量化视频 E144–E146：拿回测收益当奖励，AI 就会不断逼近历史数据里的缝隙。DeepQuant 视频 E082：失败就淘汰，不调参。Harvey 和 Liu：折扣随试验数非线性上升。

**为什么是缺陷。**

- 产品已经如实报告收缩夏普比率和有效试验数，推荐还要求邻近常数也成立、要求附多重检验读数；连续分不出差异会触发换思路。这些都在控制"怎样在开发期上搜"，没有一条决定"什么时候不再在开发期上搜"。试验数越来越多，下一步仍然是在同一段数据上再登记一批。
- 以用户目标为迭代方向，又没有停止条件，开发期读数会随搜索越来越不说明问题。本线 43 个试验后推荐版本仍差回撤目标约 17 个百分点（31.6% 对 15%），所以"总能找到达标版本"在本线并未发生；风险在于一旦找到，那次达标的开发期读数恰恰是最不可信的。"期望是迭代目标"本身没错，错在没有区分"开发期读数达标"和"有干净证据达标"。
- 18 个交易计划太少：每个计划对夏普的影响都很大，参数微调很容易只是在重新安排这 18 笔交易。

**修法。**

1. 收缩夏普的计算里已经有零技能下的期望最大夏普（`ratios.md` 的 SR0），只是没有显示。在推荐读数里把它和推荐版本的夏普并列显示，比再加一个读数更直接。报告读数的改动是产品代码，先做独立评审，不新增存储字段，不改检查。
2. 给循环加一条出口：某个读数越过阈值后，Agent 不再登记新批次，而是向用户提出前瞻验证（D3）或换线。阈值本身还没有依据，候选包括收缩夏普低于某值、或有效试验数让最短回测长度超过开发期长度；用户目标对应多少夏普也要先定。这改变了"试验数不拒绝方向"和"只有用户能停"的现行规则，需要用户决定，阈值设计应先由独立评审给方案。
3. 换思路时优先选能增加交易计划数的方向（更多合约、更高频），而不是在 18 个计划上继续调出场和仓位。Chan 的讲座给出同一判断的理由（E023、E028）：信号越少，越容易在一条历史路径上挑中偶然的最优。这是 Agent 的研究判断，写进 `feedback.md` 属于技能改动，需按技能改动规则跑评测。
4. 只调常数（出场距离、拖尾倍数）时，可以照 Chan 的做法在模拟路径上比较，而不是只看 2021–2024 这一条路径（E394、E616–E617）。这是研究方法，模拟脚本放 `/tmp`，不是产品代码；它不能当经济证据（产品报告之外的经济结论不被接受），只能帮 Agent 判断某个常数是否只适配了 2024 年那一段行情。

### D3 唯一干净的证据被放在流程末端，并且从未启动

**现状。** 只有登记之后的窗口算样本外（[SKILL.md:168–175](https://github.com/qOeOp/trade/blob/d258a045c5a47dab28ee0611e83c78360d13683c/.agents/skills/research-round/SKILL.md#L168-L175)）。推荐第一次达到两项目标时告诉用户验证由他启动；用户接受候选后，问一次是否验证。用户也可以随时要求验证。当前账本正式验证登记为 0，本线推荐从未同时达到两项目标，所以这两个时机都没出现过。关线时还会回放 Q 之后到关线日的前瞻段，但它只在关线时跑一次，长度取决于什么时候关线。Paper 已经能用公开实时数据和 Sandbox 成交跑前瞻观察。

**外部证据。** Lopez-Lira 等：只在训练截止之后评估，低频研究要等几年才攒够截止后样本。Bailey 等 §1 的"模型封存"。Helm 的最终裁决就是一次性预注册的样本外检验，结果未通过并照实报告。顶点量化视频的第六道闸门是仿真实盘（E189–E196）。

**为什么是缺陷。** 结合 D1 和 D2：开发期读数越来越不说明问题，留出期对 Agent 不是盲的，剩下唯一能回答"这个策略有没有用"的是登记之后的数据（以及晚于模型训练截止的关线前瞻段）。而提出验证的时机挂在"开发期上达到两项目标"上，这恰好是 D2 说的最不可信的读数。推荐版本 3 年只有 18 个计划，若前瞻窗口的交易频率相同，一年约 6 个计划，两年也分辨不出 25% 年化和零的差别（`validation.md` 本身就要求按计划频率和日收益离散度建议窗口长度）。验证每晚一天开始，干净证据就晚一天出现。

**修法。** 把提出前瞻验证的时机从"开发期上达到两项目标"解开：例如推荐版本改变、或 D2 的出口触发时，Agent 就给出一份具体提案（候选、窗口规则、按计划频率能分辨的效应大小），说明它不需要候选先在开发期达标；研究照常继续。启动验证仍是用户的决定，这里只改提案的时机和内容，属于技能改动。

### D4 关线的留出结果可以流回同一留出期的新线设计

**现状。** 同一季度开的线共享同一个留出期。[feedback.md:58](https://github.com/qOeOp/trade/blob/d258a045c5a47dab28ee0611e83c78360d13683c/.agents/skills/research-round/references/feedback.md#L58) 的"融合"规则让 Agent 从已关线的 `research history` 中挑选规则，挑选依据是"它在本线候选失败的年份里撑得住"。`research history` 返回每个候选的否决年、留出期和前瞻段读数。规则说这些年份不计入目标，但没有说不能读留出期的格子。

**外部证据。** DeepQuant 视频 E077–E079、E085：看过留出结果再调整设计，留出期就变成验证集。顶点量化视频 E168–E169：样本外反复参与调参，就从考卷变成练习题。Sullivan 等：数据窥探可以来自整个研究群体，而不只是一个人。

**已有机制。** `research history` 和关线总结已经读出 `holdout_prior_trials`：此前在同一留出期、同一合约上计入的试验数，关线总结要求写明（Codex 诊断 20261114-15 指出 History 页还没显示它）。

**为什么是缺陷。** 这个计数披露的是"此前有多少试验碰过这段留出期"，不披露"新线的部件是不是因为在这段留出期表现好才被选进来的"。新线如果与已关线共享留出期，按融合规则挑来的部件可能正是这样被选中的；新线关线时再用同一留出期反驳它，结论就偏乐观，而计数看不出这层关系。本条是技能规则主动引导了这条信息流。

**修法。** 在融合规则里写明：只读已关线的开发期和否决年格子；新线与已关线留出期重叠时，不读留出期格子。技能改动，需按规则跑评测；不改检查，不需要授权。

### D5 每步的配对比较是名义显著性，推荐来自整条搜索路径

**现状。** 每次登记比较候选和对照，区间排除零即"改进"。推荐在所有可比候选中选出，报告附收缩夏普比率和有效试验数。

**外部证据。** Sullivan 等对整个规则宇宙做 bootstrap 校正后，名义 p=0.04 的规则变成 p=0.90；按样本内最优选出的规则在样本外名义 p=0.322。Bajgrowicz 和 Scaillet：用错误发现率控制也无法事先选出未来的赢家。

**为什么是缺陷（较小）。** 收缩夏普比率只回答"最优那个的夏普是否大于零"，不回答"沿路径一系列'改进'是否真实"。43 个试验里任何一次"改进"都是名义的。目前影响有限：本线大多数比较本来就分不出差异。

**修法。** 推荐时对本线所有可比运行做一次整体检验（White 的 Reality Check 或 Hansen 的 SPA，用已存的日收益），作为报告读数。这是 Agent 给自己打分的环节，按 AGENTS.md 适合做成产品代码；需要先独立评审，不新增存储字段。优先级低于 D1–D3。

### D6 同一个 Agent 设计、解读并挑选

**现状。** 研究会话内的独立审阅只在两处：预检的源码审阅（不看收益），正式验证结论的第二读者；会话之外还有 `product-doctor` 的产品审计。设计假设、读结果、写推荐、选下一步，都是作者 Agent。

**外部证据。** López de Prado 把单人包办的量化研究比作西西弗斯，主张生产线式分工，回测交给专人（E140–E174）。顶点量化视频 E219–E223：自动化之后，人的价值在于设计问题、设定证伪标准、决定风险边界。

**为什么是缺陷（较小）。** 推荐判断里"为什么保留它"的理由，由读过全部收益的作者写出，没有人在不看作者推理的情况下复核。账本算出的比较和计数已经挡住了最直接的自评，所以这里只是缺少一次独立读法。

**修法。** 把正式验证结论已有的"第二读者"做法扩展到推荐：在推荐第一次达到目标、或推荐版本改变时，让一个没有作者上下文的子代理只读账本证据，检查推荐有没有遗漏、夸大或依赖训练记忆的事件（D1）。技能改动。
