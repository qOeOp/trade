# Binance USD-M Live 接入

2026-11-06。用户要求实现、部署并用约 100 USDT 实测 Live，随后指定使用已有 15m
高收益策略。该金额是测试资金声明，不是可损失全部余额的预算。凭据取用仅限用户指定的
Binance key/secret；真实账户配置写入和具体小额测试范围单独确认，不划转资金。

## 执行归属

新增独立 `engine.live` 与宿主 `live` 入口。Nautilus 2.0.0rc7 原生 Binance execution
client 拥有订单、成交、仓位、账户与对账；不扩展 Paper Sandbox 为真实账户，也不复用模拟
资金、延迟回调、资金费补记或 Paper 检查点。现有研究、Paper 拒绝条件不变。

首次只支持一个私有账户槽、一个运行、一个 BTCUSDT 策略，两个候选顺序验收。账户槽锁不按
API key 分割：同账户的另一个 key 不能被当成另一个资金池。主机锁不能排除手动或其他主机交易；
首次执行要求整个 USD-M 账户没有持仓、普通单和算法单。发现外来订单不得代为取消。

凭据只由私有 Live 控制命令读取，并以私有文件只读挂入 Live runner；Docker argv/env、
浏览器、Paper、公开研究账本和 DoltHub 不持有密钥。预检只执行硬编码生产域名的 GET，拒绝重定向，不输出签名或认证头。
运行时镜像必须来自 CI 并固定 digest。账户配置不由连接过程自动修改。

## 独立存储评审

独立子代理 `live_architecture`（Astra / ultra）评审后批准私有执行目录，不新增 SQL 表或列：

| 原件 | 消费者与不可派生的事实 | 既有记录不足的原因 |
| --- | --- | --- |
| run_id | 启动幂等与容器归属 | 同源码可执行多次；不另加等价 op_id |
| 固定源码、既有候选身份及 universe 输入 | loader 和重新连接 | 研究镜像可后续同步；不得重新解释“最新版本” |
| 既有 runtime identity | 固定实际执行镜像 | tag 与 Git head 不能替代已执行 digest |
| symbols 与实际预算、时限、运行配置 | 预检与重复执行核对 | 不能从最终成交倒推最初声明 |
| 私有 key fingerprint | 拒绝同 run 静默换 key | 原生 account_id 只是本地标签；fingerprint 不证明跨 key 账户不同 |
| 原生 cache 与策略状态字节 | Nautilus 对账及已证明的恢复路径 | UI摘要、repr 与成交列表不足以重建原生执行态 |
| 只追加操作与生命周期观察 | 启停是否尝试、结果是否未决 | 进程消失不证明没有发过订单或账户已空仓 |
| 关键预检/对账时点的私有观察原件 | 初次启动和最终平仓证据 | 后来的 GET 无法重建当时状态 |

同一独立评审补充批准 `origin_candidate` 与 `source` 分离：前者保存原研究候选 ID、revision
和原源码 hash，表示来源；后者保存实际执行源码的 entry class 与 hash。runtime identity 已包含
强制采用的 runtime contract，不在源码身份内重复保存。
适配源码与原源码是不同事实，不能沿用原候选 hash 冒充实际执行身份，也不能把来源关系当成
独立验证标签。runner 仅加载 `source` 所绑定的唯一实际源码文件。

不保存另一套订单、持仓、余额账本，不把派生 PnL 或列表状态写成权威事实。原件和备份保留；
私有目录不属于 research publish 或 Paper seal 输入。

## 原生兼容性与首批策略

固定版原生离线探针确认 Binance Futures 明确拒绝 OCO/OTO 联动 order list。原生单独
条件单与 reduce-only 支持不代表研究 bracket 自动可用；不在产品里暗中拆单或使用本地模拟保护。
Live 源码须保留可追溯的研究信号，并分别验证成交后保护、部分成交、撤单成交竞态和退出。
研究原版保留原样，适配源码及工程验收原件留私有工作目录，不入 Git。

原生 max_notional_per_order 是每单上限，不能当作累计仓位或最大亏损界限；普通 reduce-only
平仓仍受其约束，须留退出价格空间。原生 `cancel_all_orders(strategy_only=True)` 逐个取消本策略
订单，允许沿用；`False` 的全品种撤单不在本次接口范围。

初次预检采用单向、单资产、逐仓 1 倍且关闭自动追加保证金，资金只从真实 USDT 观察读取。
这些是本次小额工程试验配置，不改变用户的研究收益/回撤目标，也不自动写交易所设置。
实际账户读回只保存在私有观察原件；设置确认前只能完成预检与离线验证。

## 停止与恢复边界

STOP 先停新开仓决策，继续接收原生成交回调；取消所属开仓单，保留必要保护，通过原生
reduce-only 退出。只有原生状态与新鲜交易所查询都确认空仓、所属工作单结束后才记录 clean stop。
超时保留未决状态、原件与账户槽，不能提前记成功或释放给另一个策略。

首版恢复限定为同 run 的 reconnect/reconcile-only：加载原生 cache 后对账，不重启旧策略的
任意回调。Paper 的一致切点不能冻结真实交易所；不把冷启动同源码称为完整策略恢复。

## 验收状态

当前已完成固定版 API 与离线原生节点构建、生产 GET-only 账户查询、研究候选只读核实。
2026-11-06 在用户授权范围内，用真实账户和约 100 USDT 测试资金，在远程主机以 CI 镜像执行 7 轮：5 轮完成真实成交闭环，
多空入场、止盈、止损、撤单、定时退出和空仓冷对账通过；GTD 到期未通过，交易所提前返回 `CANCELED`，原因未查明。
这些运行沿用用户账户已有的双向、多资产设置。断线后的真实持仓恢复不在上述结果内。
余额与成交原件只留在私有目录。
完整产品与原生执行验证随实现记录；技术回测审计通过不等于独立样本外收益验证。
