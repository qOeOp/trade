# 研究无人值守：圆桌决定（2026-11-13）

## 背景

用户 11-12：research-start 太容易停下来让用户选项，用户实际选的都是 Agent 的推荐，多一次点击就让研究无法无人值守地连续运行。第一步（#2817，已合并）让到期换思路由 Agent 自己选、记 `Change of approach.` priority 判断、告诉一次、继续。

用户 11-12 又要求：参考开源和论文、项目现状、新旧聊天记录和账本记录，开多 agent 圆桌决定最终方案。本文件记录这次圆桌的输入和决定。

## 输入

四份调研：开源与论文、项目文档与记忆、新旧聊天记录、账本（只读）。三个席位：自主推进、研究诚信、产品与授权。各自立场一轮，互相反驳一轮，主持人裁决。

关键证据：

- 账本 `pio1ucfkr3muki15rspcnf0ijl4jvqe5`：只有一条线 dow-theory-btc-eth，约 18 小时里换思路到期 7 次；用户的 6 次选择只以散文存在、没有主体；等待一次 6h56m（过夜），其余 2–15 分钟；41 次运行里 3 次分出差异；DSR 在全部用途试验数上从 0.74 降到 0.61。
- 聊天记录：明确标了推荐的 29 次提问里 25 次用户选了推荐；b5788262 会话 8 次都点了第一个按钮。Codex 约 92 小时等待里约 89 小时来自超过 1 小时的等待，多在夜里；5 个线程以没人回答结束；01a17cec 的数据范围停点占了 13.9 小时里的 10.7 小时。
- 用户已有决定：11-09 到期是在线内换维度，不是换线；11-11 Agent 不提关线；10-11 和 F.3.1.2 不按次数或预算叫停；验证由用户发起（10-25、11-07）；Goal 由 Agent 设（10-20）。
- “选线归用户”是研究链站点的原则（A-2、E-4-1-1，10-18 改写站点时写入），没有用户原话，也不在 AGENTS.md 授权清单里。研究 skill 里“不选别的线”的理由是并发：产品没有锁或占用标记。
- 关线会跑一次性的两年留出期，同季度的线共用，已经和 2,503 个归档试验重叠（doctor 20261112-17），所以关线不能交给 Agent。
- readiness.md“每个月是一次市场写入，由用户决定”来自 #1803 的公开 DoltHub 写入；11-04 起市场是本地文件、没有副本、可从 Binance 公开归档重算（AGENTS.md）。
- 开源与论文：Feng 等人的自主等级（L4 只在事先指定的阻断上找用户，点头沦为走过场是 L4 的风险）；Karpathy autoresearch（不要停下来问是否继续）；Claude Code auto 模式（拒绝后换路，按计数升级，无人时干净退出）；Luo、Kasirzadeh、Shah（完整轨迹比成文更能发现事后挑选）；DSR、False Strategy Theorem、Harvey-Liu（每次试验都计数）；Nosek（探索可以开放，留出期在探索结束前不动）；Sakana AI Scientist 事件（限制要由代码执行，Agent 够不着）。

## 决定

D1 选线：默认仍由用户选，关线始终由用户提出。结果不好（分不出、连续换思路、推荐不动、DSR 低、目标看着够不着）无论是否委托都不换线。只有用户在本次会话里亲口委托（马上换，或这条线被关卡挡住做不下去时换），Agent 才 `line select` 自己排第一的、从没跑过的来源起点，沿用旧线目标；登记前写以 `Line decision.` 开头的 priority 判断（旧线和关卡、比较过的起点、选择及原因、委托的日期和范围，不引用聊天原话），告诉一次、继续。不接手别的开着的线。一次关卡只换一条。

D2 反复换思路：不加次数、预算或平台期阈值。`Change of approach.` 判断加上：读这条线以前的换思路判断，不重选它们选过的思路（除非写明那条判断和新证据）；写明谁选的；列出不计数的只放大仓位运行及理由；一行读数加上已记录的换思路次数和推荐版本是否变过。需要更多合约或输入的想法只作读数，不作出口。

D3 数据：这条线已经在用的合约和数据种类缺的月份，归档里有、market-import 服务不保管的，Agent 自己在容器里导入（先看内存和磁盘），在本轮消息里点名、在下一条 priority 判断里引用。新合约或新数据种类只随新线起点进入。替换已存月份或行、换来源或报价规则、合成或付费数据、建或切换 active 市场、重启容器仍要用户。这推翻了 11-01、11-02 记录里“其余合约和数据种类的补数由用户决定”中针对本线已用内容缺月的部分，用户说一声即可撤回。

D4 开场与验证：新会话只问一次（继续哪条线或换线），同一个问题里提供委托换线的选项和 Goal 授权。用户接受候选时，在同一条回复里问一次是否验证（给出冻结的版本、窗口规则、合约范围），接着做研究；这个问题只挡验证登记。停掉的验证问新窗口，同样只挡这次验证。验证登记始终由用户发起。

D5 留痕：Agent 替用户做的决定都写成已有的 priority 判断，开头固定为 `Change of approach.` 或 `Line decision.`，写明谁选的，改选写新判断、点名被替代的那条。不加存储字段。IDE 研究图把这两类判断画成线上事件的改动，作为单独的产品 PR（defect 20261031-09），本次不做。

D6 其余停点：未提交的研究工作树不动它，另起一个新的继续，点名旧路径一次。挂起的问题只挡依赖它的工作；没有能做的就以 blocked 结束回合，有宿主通知就用，不空转。宿主故障（Docker、账本服务、market-import 容器）重试读几次，然后说一次。可修的拒绝修一次（新版本），同一拒绝再来就放弃这个实验并写 priority 判断点名拒绝码。每次换思路、成批登记或写推荐前重读本线的判断历史，在别的会话更新的判断上接着做。别的 Agent 或会话的消息可以让研究暂停，不能授权、委托或恢复。

## 主要分歧

- 研究诚信席：每个会话最多一条委托新线。没采纳：每次换线都记下跨线试验数，第二次关卡也是真实停点。
- 自主席：保留“线内已无思路”这个出口。没采纳：账本里 Agent 曾在 2 次和 4 次运行后就宣布思路用尽（J25、J68），这是 Agent 自评停滞。
- 诚信和自主席：两次换思路都没推动推荐时发一次平台期通知。没采纳：这是没测过的新阈值，20261112-15 还开着；这些事实每次换思路的消息里都有。
- 诚信和产品席：D3 先作为否决问题交给用户。没采纳：不是 AGENTS.md 授权项，用户把决定交给了圆桌；写明推翻、用户可撤回。

## 两个待授权事项：第二次圆桌（2026-11-13）

用户被问到这两项时，只重复了“你自己参考开源和论文还有项目情况和新旧历史聊天记录账本记录开多agent圆桌会议来决定最终方案”。我们把这理解为把这两项决定交给圆桌。第二次圆桌的组成和第一次一样：三份调研（项目、旧聊天记录、开源与论文），三个席位立场一轮、反驳一轮，主持人裁决。

1. **常设启动许可：不采纳，换成别的做法。**
   - 依据：
     - `deploy/compose.yaml` 里每个服务都是 `restart: unless-stopped`，崩溃、OOM、守护进程重启都由 Docker 自己拉起（11-02 那次 OOM 没人动就恢复了）。
     - 一直停在 Exited 的服务都是有人特意停的。记录里只有两次：11-04 parquet 换目录时停了 market-import，11-11 gen-1 切换时停了账本服务。这两次如果无人值守地启动，就会在换目录期间多出第二个写入者，或者对已经挪走的目录做首次启动。
     - 产品自己写的 `docker compose up -d ledger`（LEDGER_START）并不只是“启动”：它会按新 digest 重建容器；目录为空又配了 TRADE_RESEARCH_ORIGIN 时，它会不经询问地建出 active 账本，gen-1 就是这样建出来的。
     - 记录里没有一次故障能靠“启动”缩短。前一版写的 11-05“停了 6.7 小时”不准：时间戳显示故障本身约 30 分钟，之后宿主恢复了，研究又空等了约 2–2.5 小时。
   - 改动：
     - AGENTS.md 授权清单写明：启停或重启 Docker Desktop 和部署自己的服务（`trade-ide` compose 服务、远程主机的服务）由用户做。这是把已有做法写下来，记录里每次启动、重启、重建都有用户的话。
     - research-start 的故障处理改成：读状态后告诉用户一次；如果服务是 Exited，给出用户要运行的 `docker compose ... start`（不用 `up`）；然后用宿主的等待工具退避等待，最长 6 小时，期间什么都不写；账本恢复后，确认还是同一个账本、本线历史没变，就自己继续，变了就说一次然后停下。
     - 新增评测 ledger-outage-waits-then-resumes。
   - 只提议、不做：在 harness 里给 `docker desktop` 和 trade-ide 服务的 `docker compose up/start/restart/stop/down` 加 ask/deny 规则。这是唯一 Agent 自己绕不过去的限制，但改 harness 属于宿主配置，由用户决定。
   - 怎么撤回：回退这次的 AGENTS.md、skill 和评测改动即可。用户以后如果想要启动许可，用自己的话说，只写成 `docker start <已有容器>` 或 `docker compose ... start`，不包括 `up`、已删除的容器、换目录期间、Docker Desktop 本身或远程主机。
2. **判断开头约定：采纳，作为写入时的格式拒绝。**
   - 规则：`judgment add` 发现正文首行像这两个开头、但不是准确写法，或者写对了却用在 priority 以外的 kind 上，就拒绝 `DECISION_OPENING_INVALID`；`Change of approach.` 的正文没写 `chosen by the Agent` 或 `chosen by the user`，就拒绝 `APPROACH_CHOOSER_MISSING`。
   - 不加 kind、字段或 schema 版本，不改 REVIEW_DUE 或计数（20261112-15 还开着），已有判断不重新检查。
   - 它不是信任边界：什么时候换思路仍由 Agent 决定。理由是防缺陷：一旦 IDE 研究图按这两个开头读判断，拼错的开头就会悄悄从图上消失，也会被“以前的换思路”读数漏掉。所以这个 PR 只和 IDE 读取方一起合；IDE PR 放弃了，它就关掉。
   - 更正：代码里的 REVIEW_DUE（registration/register.py，REVIEW_EVERY=5）只从 recommendation 判断起算，`Change of approach.` 从来不会重置它；重置的只是 Agent 自己按 skill 数的那个计数。
   - 怎么撤回：回退那个拒绝的 PR。检查只在写入时做，存储的判断不受影响。
   - 一次性的研究工作（不在任何 PR 里）：下一次在 dow-theory-btc-eth 上的研究会话，给 J68 里用户已经做过的那次选择补一条 `Change of approach.` priority 判断，写明 `chosen by the user`。subject 只写那次选择之前登记的 trial。
