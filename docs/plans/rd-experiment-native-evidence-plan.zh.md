# 策略研发：实验组织与原生证据的分步计划

> 历史快照：本文保留 Git 侧录阶段的设计与验收背景，登记及元数据操作已由 Dolt v2 契约替代。现行操作以 [research-round skill](../../.agents/skills/research-round/SKILL.md) 和[当前架构](../architecture.zh.md)为准。

状态：第 1 步的操作契约已写入 [research-round 发表参考](../../.agents/skills/research-round/references/publish.md)；尚待下一条真实新假设检验 Agent 能否独立执行。其余步骤待执行。本文不把开发期回测结果当作独立策略资格，也不改变实盘或风险边界。

## 目标与现有底座

让 RD Agent 自己提出可否证的问题、选择合法对照、登记搜索与数据暴露，并依据 Nautilus 原生报告解释结果和选择下一实验。研究者只设长期目标与风险边界；每轮具体研究方向由 Agent 决定。

复用 [研究记录与封存命令](../../.agents/skills/research-round/references/seal.md)、[现有 compare](../../research/records/cli.py) 和 [F01 四格分析](https://github.com/qOeOp/trade/blob/3b3b4876b869bf0d7f54b74ee69f7f708dea59dd/backtest/r1/checks/compare_factorial.py)（已删除，链接为删除前的固定版本）。详细方法与依据在归档试用台账中为 `material:reports/策略研发 实验组织 证据反馈.md`，需先把归档恢复到独立台账，再用 commit `9794ed307` 的记录 CLI 读取。不新增研究服务、交易账本、撮合器或 Agent 角色。以下步骤按顺序推进，每步验收后才决定下一步的实际改动。

## 1. 固定 Agent 的单轮实验契约

在现有研究指南中写一页操作约束；新假设仍使用现有 `attempt.json` 和事前登记 Markdown，不先扩展 schema。Agent 在读取新结果前必须：

1. `find`、`show --brief`，必要时打开完整记录和原生报告，指出旧证据支持与否定的精确命题。
2. 写出本轮机制、可观察的原生动作、反证条件、主要净账户响应、风险停止条件、合法对照和选择规则。
3. 写出最多尝试多少候选、已看过哪些数据/结果窗口，以及下一次结果是否有独立确认资格。
4. 提交尝试和预登记，再运行新结果。依赖式组合只做有定义的配对；独立可开关且问题涉及交互时才做四格。

**验收：**给 Agent 一个新问题而不逐步指挥，它能在结果出现前产出上述契约；缺失对照、反证条件或数据暴露时不进入经济结论。先用 Markdown 验证这些字段确实有用；只有实际出现漏填或机器核查需求，才将其加入 schema。

## 2. 用一个现有案例盘点证据缺口

先核实 F01 的 `10/11` 原始报告是否仍可读取，再用这组配对作只读试点，按“比较合同与运行完整性 → B 是否激活 → 第一处**可证明**的行为差异 → 订单/仓位/资金/费用/资金费 → 全账户逐期差异与不确定性”的顺序人工读回。每个事实附原生报告位置；无法由当前报告证明的事件或因果环节明确写 `unknown`。F01 旧四格大 CSV 仍是 `/tmp` 临时证据，仅后来 11 格有受管封存；试点不能称旧四格可恢复。若 10 格原始报告已不可用，先记录缺口；需要行级配对时，后续用现有封存命令生成新的同口径配对，不拿旧摘要冒充行级证据。

**产物：**一页证据包样例和“已有字段 / 缺失字段 / 因此不能下的结论”清单。

**验收：**另一位读者能由引用复核已报告的差异；若原始报告或完整事件流缺失，明确标记无法定位首个分叉，结论停在实际可证明的层级。此步不重跑、不修改策略。

## 3. 只补反复需要的确定性证据读取

状态（2026-10-10）：本步骤由[原生回测分析与改良比较实施计划](native-rd-analysis-plan.zh.md)的 P0-A 单 run 诊断与 P0-B1 合法配对分析取代，以该计划为准。

依据第 2 步缺口，优先扩展现有只读 `research.records.cli compare`，而不是建立第二套结果系统。最小输出顺序为：不可比时的具体拒绝原因；原生完整性与动作激活；首个可证明的订单/成交/账户分叉及报告引用；完整共享账户的净差、回撤、费用和资金费；同日配对收益的探索性不确定性及样本暴露限制。统计方法和抽样单位须随问题明确声明，不能将 37 币或多笔订单当成 37 份独立账户。现有报告若无法证明取消请求或账户路径，就输出证据缺口；只有确定需要且 Nautilus 原生事件可取得时，才补最小事件导出。

**验收：**在固定运行上重复执行得到相同结论和引用；输入身份、账户、窗口或审计不符时拒绝增量比较；报告明确区分“动作发生”“开发期经济结果”“独立确认”。不由工具自动生成“策略有效”标签。

## 4. 检验 Agent 是否因此判断得更准

先冻结新题、证据、评分表与工具预算，再比较当前资料条件和新增证据包条件下的 Agent 答案。盲评四件事：是否合法选择对照，是否定位最窄失败层，是否把事实与猜测分开，下一实验能否区分竞争解释且尊重已暴露数据。同时记录耗时、工具调用和维护成本。不能用同一批题边改提示边宣布进步。

**验收：**判断质量改善且检索正确率不下降，额外成本有合理回报，才保留新增诊断能力；否则回退或缩小工具输出。此验收证明的是研发决策质量，不是策略收益提升。

## 5. 进入后续假设循环

每轮按“旧证据 → 事前契约 → 最小合法原生实验 → 证据包 → 有范围的裁决 → 下一问题”执行。Agent 只能给出停止、修执行/数据、保留待确认、提出下一个可否证实验等研究动作。重复看过的年度只提供开发证据；在未参与筛选的数据或前向阶段获得原生净账户、风险与执行证据后，才能讨论更强的有效性结论。没有独立数据时标记待确认，不通过反复调参制造样本外。
