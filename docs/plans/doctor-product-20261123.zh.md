## 2. 产品定义

- **用户**：决定修什么、授权什么的人；执行审计、修复、复核的 Agent（任一宿主）。
- **回答的问题**：哪里坏了、证据是什么；哪些看过、哪些没看；修好的是不是真修好；doctor 说的话有多少经得起独立重跑。
- **不做**：不修产品、不选候选、不改目标、不当 CI 门、不自动开 issue、不存账本、不改索引。值不值得修、补救、根因仍由 Agent 判断。
- **形态**：技能管判断与步骤；`assets/doctor.py`（只用标准库）管能判定的事。证据只在临时目录，结论进既有的 `docs/plans/doctor/` 记录。

## 3. 核心：探针

探针是一个 Python 文件，`probe()` 返回“读到的值，应有的值”。相等是性质成立，不等是缺陷，异常、退出、超时是探针坏了。`control()` 是一个应当给出另一种读数的输入，或用 `--control-tree` 换一棵树。

| 判定 | 条件 |
|---|---|
| `shown` | 主输入是缺陷，对照成立，且两边**读到的值不同** |
| `absent` | 反过来 |
| `indiscriminate` | 两边状态相同，或读到的值相同（可能是常量） |
| `uncontrolled` | 没有对照 |
| `broken` | 任一边坏了，或导入了指定树以外的产品代码 |

树是 `git archive` 副本，子进程只从该树导入：worktree 的 `.venv` 指向主检出，不隔离就会测错代码。不用退出码表示结果，因为模块级失败和崩溃都会占用退出码。

## 4. 命令

| 命令 | 做什么 | 防的是 |
|---|---|---|
| `run` | 执行并记下检出、命令、退出码、输出与产物的哈希 | 覆盖自述；重复页面、空输出、跳过的测试 |
| `probe` | 如上；`--before` 说上次审计时有没有 | 崩溃与无区分力；漏检没有数 |
| `cost` | 至少三个规模，冷热分开，中位数与增长指数；散布盖过差距判 `noisy` | 冷启动当增长 |
| `recheck` | 修复提交、去掉修复的提交、当前 main 三棵树，逐测试比较 | 拿“已合并”当“已修好” |
| `report` | 由证据写出覆盖表、缺项、发现表；缺项时标题是 `Partial audit` | 把部分审计叫全面 |

`report` 恒退出 0。它给名字，不拦写记录、不进 CI；把它做成门是收紧检查，另需授权。

## 5. 覆盖

清单只有一份：lenses.md 的 Assignment，每项有 id 与对象，脚本从那里读，认不出就停下。原有六项外，每次加 `interrupt`（多副作用操作在每步后中断再继续；假件要反映被停掉的东西，`generation` 的死锁正因假 `probe` 永远成功而没被测到）、`fixed`（复验）、`unchanged`（最近改动之外的一处），再从 `recovery`、`security`、`governance`、`operation`、`usability` 里轮换一项。轮换只加一项，是为了不让清单长到没人做完。

用户点名的面落在：业务 = `flow`、`gates`、行为工作流的方法判断；代码 = `gates`、`interrupt`、`cost`、`unchanged`；设计 = `pages`、`consumers`、`usability`；治理 = `governance`；发布 = `interrupt`、`recovery`、`operation`。

“已覆盖”只说明记了命令。读输出、说明漏了什么仍是 Agent 的事；完整审计另派不知结论的子代理重跑代价高的发现。

## 6. 循环怎样算改善

不看发现数。主指标是**独立重跑推翻的说法占比**；次要的是用户先发现的数、上次审计已存在却没找到的占比（都带分母）、复发、`fixed` 行复验结果。一次审计不说趋势。

本轮 Gemini 审计的基线，供下次比较：11 项登记发现，复核推翻或无法成立的探针至少 4 项（`20261122-23`、`20261122-20`、两项发布探针），至少 7 项上次审计已存在；另有“全量测试全过”“IDE 四页”两句覆盖说法不成立。复核由本文作者做，不是盲审，分母也没有完整重跑 11 项，只作量级。

## 7. 评审与回测

独立评审的意见与处置：

| 意见 | 处置 |
|---|---|
| 退出码分不清模块级失败；探针会导入主检出 | 改为返回值、逐测试结果、隔离导入 |
| 代价两个规模不够、冷热混在一起 | 三个以上规模，冷热分开 |
| 解析正文清单脆弱 | 显式 id，认不出即停，测试读真实文件 |
| 证据可能带凭据与本机路径 | 不记环境；技能写明命令不含凭据；报告里坏探针只印错误本身 |
| `interrupt`、`security` 越界 | 限假件、限凭据边界 |
| `verify`、`trend`、盲测 `bench` | 删去。重跑用 `probe` 即可；`trend` 没有使用者；盲测没有排期，且树里的后续修复会泄题，等有使用者再议 |

## 8. 局限

- `run -- true`、编造读数的探针仍骗得过脚本；靠独立重跑和读命令。
- 探针测的是不是要紧的事，脚本不知道；对没想到的类别，召回没有说法。
- 索引里可解析的 145 个 `fixed` 行只有约 47 个带 Python 测试和产品代码，其余 `recheck` 判 `no test`，要用探针。
- 还没有人用它做过一次完整审计；能否多找真问题尚无证据。之后两次完整审计没用到的命令就删。
