# 部分成交、补保护与因果时钟的职责

2026-10-24，用户逐项确认：部分成交数量对齐和保护覆盖沿用既有审计；补挂保护由策略源码按缺口完成；成交晚于决策 K 线收盘继续作为源码契约与独立审查要求。保留现有严格超过一分钟的裸仓阈值，不新增重复审计、策略自报字段或存储字段。

## 当前实现与分工

- `engine.audit.event_report_findings` 累计原生部分成交数量，与订单和成交报告核对；逐笔核对订单、交易身份、数量与成交时间。它证明原生事实一致，不证明信号决策的因果性。
- `engine.audit.uncovered_intervals` 按同一时间戳批量应用事件，读取每个策略与合约的实际持仓、平仓方向有效只减仓止损的剩余覆盖量。持仓超出覆盖的缺口持续严格超过 `BAR_NS`（当前一分钟），才列入区间；`protection` 按事先声明的止损设置决定是否拒绝。
- 短于或恰好一分钟的缺口不拒绝，也不列入 `uncovered_intervals`。审计通过不证明持续保护；该阈值与禁新仓截止没有宽限是两个独立检查。
- 原生部分成交括号单的入场取消或到期可能连带撤去保护。策略读取实际持仓与有效剩余止损量补缺口；现有 `TieredEntry.cover_filled_entry` 原生参考验证了未补被拒、补回通过、多层同时到期只补一次。审计验证覆盖结果，回调和策略特有的竞态仍由独立源码审查核对。
- 原生订单事件能证明提交、成交时刻，不能独立证明任意策略何时形成决策。策略自报时间戳不能替代独立证据。继续由源码契约、原生预检证据、逐计划时间戳核对和绑定源码及运行环境的独立审查承担因果时钟检查。
