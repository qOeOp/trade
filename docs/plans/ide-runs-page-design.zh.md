# 运行页：一个版本的回测 → 模拟盘 → 实盘（设计稿）

2026-11-01 用户提出：IDE 上 Paper 页的职责要重新设计，扩成**一页看一个策略版本的回测、模拟盘和实盘**；
图上通过给画布**隐式分栏**让人分清一段图属于回测、模拟盘还是实盘；Paper 页现在的右栏（Performance、日历）
并进侧边的工具窗，和假设、结论那些内容放在一起；日历不再是独立的岛，进侧栏。看过第一版（并排两栏 +
阶段标尺）后用户又定：**图是连续的，分栏是无感的**——通常回测日期之后才有模拟盘、模拟盘之后才是实盘，
线基本是连续的；三段之间的两段空档去掉；**K 线等指标图也一样连续**。

本文是动手前的设计：先说结论和页面，再列数据来源、授权边界和**用户的决定**（第 8 节，用户 11-01 看过亮暗
两套高保真静态稿后全部通过）。实施按第 10 节分步。
数据路径经三轮对照代码的评审核实，第 6 节逐条写明出处。

## 结论

- **页面以版本为主键，不再以模拟盘运行为主键。** 选中哪个版本（谱系、Versions 树、`#<version>`），
  运行页就显示它的三个阶段；模拟盘运行只是这个版本之下「选中的那条运行」。Details 和运行页从此不会各说各话。
- **画布 = 一张图、一条时间轴、一条线。** 回测、模拟盘、实盘按时间先后首尾相接地画在同一张图上，
  阶段之间的空档（回测窗口末到模拟盘开始、一条运行结束到下一条开始）不占任何宽度；权益线像重启链那样
  接续复利，所以从回测第一天到模拟盘最后一分钟是一条不断的线；K 线、量柱、敞口等副图同样首尾相接。
  分辨阶段只靠每段开头一行 11px 的淡色说明（`Backtest · trial 200`、`Paper · run 6`）和时间轴上日期的
  跳变：没有底色、没有竖线、没有换色。
- **回测段按日分辨率画**，只用账本已存的东西：日收益、持仓周期（无价格）、封存报告里的最深回撤区间。
  页面永远不触发 `replay reproduce`（那会写一条 explore 试验）。
- **实盘授权之前不出现在页面上**（用户 11-02：不占价格轴顶部的位置；真有实盘时，它和模拟盘一样在段首写一个
  `Live · …` 段名）。产品里没有任何实盘代码、
  表或接口，AGENTS.md 要求真实账户、测试网、任何凭据都先经用户明示授权；这页不设任何下单入口。
- **侧栏**：右侧 Details 变成版本的「读数 + 假设 + Performance + 日历 + 证据 + 结论」一个检查器；读数、
  Performance、日历都**跟着选中的阶段**走，不做多列对照（用户 11-01：所有版本都有回测，多数没有 paper 和
  live，两列在它们身上只是空列）；底部新增 Trades 工具窗（原 Trades/Events/Exceptions/Reconciliation 卡）。
- **新增两条只读数据路径**在 IDE 服务上（各跑一条产品命令，和 `/api/view` 同一做法）：
  一条按试验号取回测报告和表，一条（可选，第二步）按日取市场 K 线。不写账本、不加存储字段。

## 1. 页面职责与主键

**叫什么。** 左侧边条第三个按钮（⌥8）从 Paper 改叫 **Runs**：一个版本的各种运行——回测（研究回放）、
模拟盘、实盘。左侧边条的三个按钮**互斥**：Runs 选中时左侧工具窗关闭、编辑区整块是运行页（和今天的
Paper 按钮一样），图拿到全部宽度；点 Versions 或 Sources 回到谱系或源码并重开那个工具窗。页面本身仍是
编辑区的一个视图，不是工具窗。

**两个选择状态。**

- `selection`：选中的版本（谱系选中的版本，镜像在地址的 `#<version>`）。页面显示它。
- `selectedStage ∈ {backtest, paper}` 和 `selectedRun`：选中的阶段和选中的模拟盘运行。
  底部 Trades 窗的作用域、Details 里的读数、Performance、日历和净值桥、状态栏的来源看的是**选中的阶段**；
  工具栏的运行读数、Events 看的是**选中的运行**。不变量：`selectedRun` 为空，或是 `selection` 的运行之一，
  或是一条**无版本的运行**（此时 `selection` 为空，见下）。

**进入方式。** 边条 ⌥8；版本右键菜单新增 `Open runs`；地址带 `#<version>`。谱系和 Versions 树上的 ▶
含义不变——**开始一次模拟盘运行**（⌥-点开选择对话框）——开始后页面自动翻到运行页、选中这条运行。

**选中的运行。** 一个版本可能有多条模拟盘运行（跑完的、失败的、正在跑的、重启接成的链）。图上**全部**按
时间先后接续画出（§2）；工具栏读数、Details、Trades 窗描述选中的一条：默认是正在跑的那条链，
没有就按开始时间最新的那条，封存与否、失败与否不论。选中的阶段默认是模拟盘（有运行时），没有运行时是回测；
换过之后按版本记住（§5）。换运行：点图上那一段开头的说明、或工具栏的运行菜单。
同一版本同时只有一条未封存的运行（守护进程的规矩），所以各段在时间上不会重叠。运行菜单列出**所有**运行（按版本分组，Running 在前；没声明版本的、或声明的版本不在本线视图里的归到
Unattributed 并注明原因）；选别的版本的运行时，先把 `selection` 切到那个版本，再选中它。页面右侧不放
运行列表（10-25、10-26 的决定照旧）。

**回测用哪一次。** 默认取本线上该版本**最新一次有经济证据的研究回放**（视图 `candidate.trials` 中
`purpose = research` 且 `eligible` 的最后一条；研究回放按构造在本线的窗口和市场提交上），不依赖模拟盘
守护进程。Details 的 Replays 表里点另一行研究回放可换成那一次；验证、探索、预检行不可点，提示框写
`Out-of-sample replay: not on this line's window`（视图不带它们的窗口和市场提交，无从按本线画）。

**没有的情况。**

- 版本没跑过模拟盘：图只有回测段，图例第一行开头写 `No paper run · ▶ to start`（▶ 就是开始按钮）；选中的
  阶段是回测。
- 版本没有有效研究回放：图从第一条模拟盘运行开始，图左上角说明写产品的拒绝原因（如 `Backtest · no research
  run with evidence`）；回测阶段选不中。两者都没有：图区一句话 `Nothing to draw: no research run
  and no paper run`。
- 守护进程离线：模拟盘段画最后一次读到的数据并在说明后加 `· daemon offline`，回测段照画；页面不消失。
- 无版本的运行（旧记录 `candidate` 为空，或版本不在本线视图里）：只能从运行菜单进；`selection` 为空，
  选中的阶段是模拟盘；图只有这条运行，左上角说明写 `No version of this line declared for this run`，Details
  显示选版本的提示。
- 链的早先几条运行还在读取时：先画读到的，读齐后重画（和今天的链一样）。

### 2.1 一条时间轴，空档不画

图的横轴只给有数据的时刻留位置：回测的每个交易日一个点，模拟盘的每分钟一个点（按视野换步长），实盘将来
同模拟盘。回测窗口末到第一条模拟盘运行开始之间的几个月、一条运行结束到下一条开始之间的几天，**不占任何
宽度**：前一段的最后一个点紧挨着后一段的第一个点，时间轴上的日期标签从 `Aug` 跳到 `5 Oct`，就是空档存在
过的全部痕迹。一条链**内部**（重启前后两条运行之间）的离线段照 11-01 的决定画：中性色带夹两条发丝线、`Offline 46m`——那是
一条运行里真实发生的事，和阶段之间不属于任何运行的空档不同。

这条规矩对每一张图成立：权益图、K 线图、量柱、敞口带、日收益柱、将来任何指标副图，都是同一条轴上首尾
相接的序列，没有一张图在阶段之间留空。时间轴上每段第一个点的日期标签用正文色（其余标签次要色），不加
刻度线——这是轴上唯一的阶段痕迹。

步长按**视野里的点数**换档（不按时间跨度，因为时间轴有跳变）：取能让视野内各段点数之和放进宽度（每点
≥1.5px）的最细一档；回测段在不粗于日的步长下都是它的天数个点（比日粗时按步长重采样），模拟盘段是视野内秒数 ÷ 步长。回测段一天一个
点，在比日粗的步长下照常重采样；在比日细的步长下仍然一天一个点（它没有分钟数据）。左侧关闭、右侧 Details
开着时绘图区约 1 060px（1680px 窗口）：整段看时步长 2h，一年回测 365 点配四周模拟盘 336 点，各占一半上下——
索引轴给每个点同样的宽度，时间轴的日期告诉读者一年被压在半幅里。**首屏是选中的段**：它铺满绘图区右边 85%，
左边 15% 是前一段的末尾，接续处在屏上（模拟盘四周在 900px 里是 2h 步长 336 点，左边是回测最后约两个月的
日点，约 65 个点）；纵轴范围只按选中段的点算（上下各留 10–20%），前一段的末尾允许从图底出画——那读起来自然是「之前」；
双击说明才到整段。放大进模拟盘段后步长变细，回测段退到视野左外。今天的权益图按秒数跨度换档（两处入口），改为按点数；K 线图已按每根像素宽
换档，只改首次周期。

### 2.2 一条线，接续复利

权益线从回测第一天的起始资金（封存报告的 `cost_basis.account.starting_balance_usdt`，今天的账户合同是
100 000 USDT；未记录时按 §6.3 不画回测权益）画到最后一个模拟盘点，**一条不断的线**：每一段
按前一段的末值接续复利，接续方式同今天重启链的缩放（每段起点映射到前一段末值）——模拟盘链 6–7 自己从
100 000 起步、到 107 156.92，接在回测末值 122 490 之后画成 122 490 → 131 257。重启链把整条链合算回撤和
收益，这只在链内沿用，段与段之间不沿用；一条链算一段，它「自己的」权益与收益是链接续后的值（今天工具栏
显示的那个）。各段自己的读数由各段数据另算，不从接续后的值回推。纵轴是这条接续账户的 USDT；
`Starting balance <起始资金>` 的价格线和标签只在回测起点那一条。读数药丸和图例第二行同时给接续值和这一段
自己的权益与收益（`131,256.55 (run 107,156.92 · +7.16%)`），所以不会把接续值当成模拟盘账户的余额。

派生各层里，**跟着线走的贯穿接缝，属于一段账户的按段算**：配速线是一条——年化目标从回测起点复利到最后
一点，不在段界重起（接缝两侧的「领先 · 落后配速」填色因此也连续）；敞口带全图一个刻度；「低于高点」点阵
全图一个刻度（各段最深值中的最大者），但高点和回撤**在段内算**——模拟盘的第一个点就是它自己的高点，回测
末尾的高点不会让模拟盘背上一段它没有过的回撤；回撤上限地板、最深回撤斜线、日收益柱、日宽也按段。分段在
点的构造处做：每段自己的起始值和运行高点；最深回撤、日收益与日宽按段算好再交给各层。

### 2.3 分辨阶段：只有一行说明

每段开头的图区左上角一行 11px 次要色的说明，用岛色描边（和 Progress 图的目标线标签一样），点阵带从说明
基线下 8px 才开始、不压说明：`Backtest · trial 200`、`Paper · run 6`（一条链一段，以链里第一条运行命名，续跑不改名；两条运行之间的离线段在链内）、`Paper · run 5`
（另一条运行另一段）。段的开头
滚到视野左外时，说明钉在图区左边缘；钉着的说明和下一段的说明相距不足 16px 时不画（下一段的说明优先），
所以首屏上回测末尾那 20% 里多半只剩线、没有字。选中阶段的那条说明用正文色。悬停：提示框给
日期、收益、最大回撤、状态、停止原因、试验用途；点击：选中那个阶段（模拟盘段同时选中那条运行）并把视野
适配到那一段；双击把视野适配回整段。图区宿主可聚焦（点一下即聚焦）；`[` / `]` 只换选中、不动视野，到头
停住；`F` 适配选中的段，`⇧F` 整段。

**未选中的段少画几层**：只画权益线、点阵带、敞口带和（K 线图上的）K 线，不画平仓箭头、最深回撤斜线、深度
标签、日收益柱、持仓底色；选中哪段，哪段才长出细节。首屏左边那 15% 的回测末尾因此只是一条线。

没有别的了：没有底色、没有竖线、没有换色、线宽不变。分辨阶段靠说明的位置、时间轴日期的跳变和图例读数
前缀的阶段词；这正是「隐式」和「无感」的含义。离线色带和缺口斜线仍只出现在模拟盘段内部，不会和阶段边界
混淆，因为阶段边界什么都不画。

实盘：授权之前图上不画任何东西（用户 11-02）；将来的实盘段和模拟盘段一样，只在段首写段名。

### 2.4 各段画什么

**Equity 视图**

| | 回测段（日分辨率，全部来自账本已存表） | 模拟盘段（paper-trading-design §2.3「Account 图」的全部条目） |
|---|---|---|
| 权益线 | 由 `daily_returns` 按起始资金复利，一天一个点，点间直线；接续在前一段之后 | 每分钟一点，接续在前一段之后 |
| 配速线、回撤上限地板 | 配速线贯穿全图（§2.2）；地板按段；`Pace`、`Drawdown limit` 的标签只在选中的段写；多年回测的配速复利后高出图区时，纵轴仍只按权益算，`Pace` 标签钉在图区顶部写 `↑ 数值`（用户 11-02） | 同 |
| 顶部「低于高点」点阵带 | 段内按日点算；刻度全图一个（各段最深值的最大者，回测段的最深值取封存的 `mark_max_drawdown@2`）；图例的 `worst` 写选中段的并带口径（`worst −4.10% · bar-close mark`） | 段内按分钟算，同一刻度 |
| 最深回撤斜线 | **只画封存报告里那一段**：`peak_utc@2 → trough_utc@2` 两端吸附到包住它们的两个日点，标签写深度（`−4.10%`，即 `mark_max_drawdown@2`），提示框写 `peak/trough at minute …, drawn at day ends`；日级算出的三段和封存值不是一个量，不画 | 三段，按分钟算 |
| 日收益柱 | 由日收益直接画；按段判断：某段视野里不足 3 天（今天的规则）或每天不足 3px（新增，柱宽才够 2px）时该段不画 | 由权益路径算，同一规则 |
| 持仓时段底色 | `run_cycle` 开仓→平仓的并集；整段视野下按现有拥挤规则（每 48px 多于一块就不画）可能整体不画 | 同规则 |
| 平仓箭头 | 每个周期在 `ts_closed` 一只，带 `realized_pnl` | 每笔平仓一只 |
| 敞口带（底部 30px） | `mean_gross_notional / 当日权益` 的日阶梯，填成面积（每天不足 1px 时仍是面积，不画成竖线） | 分钟 |
| 不画 | 浮动盈亏填色、费用与资金费带、买入持有（都要分钟数据） | 都画 |
| 对账叠线 | — | Reconciliation 标签开着时画同窗口回放的点线（属于那条运行的段） |

**合约视图**（岛头部的分段控件；合约列表 = 回测周期的 `instrument_id` 去掉 `-PERP.BINANCE` 后与各运行
`symbols` 的并集）

- 模拟盘段：K 线图（成交箭头、交易框、挂单价位、事件带、缺口斜线、离线空白，paper-trading-design §2.3），
  周期按视野自动换档。
- 回测段：有日 K 线路由（§6.2）时画本线市场提交上的 **1d K 线**，一天一根、不随模拟盘段的周期换档（说明
  写 `Backtest · trial 200 · 1d bars`），接在模拟盘第一根之前；持仓周期**只画在底部 18px 事件带里**，开仓到

### 6.1 `GET /api/trial?trial_id=N&at=<ledger commit>`

IDE 服务上的新只读路由，和 `/api/view` 一样以子进程跑产品命令：
`python -m cli.main replay report --trial-id N --at <commit> --tables`，原样返回其 JSON。页面用到的键
（经评审对照 `report/runs.py` 核实）：

- 顶层：`trade_window{input_start, trade_start, trade_end}`、`runtime{image_ref, image_digest}`、
  `headline`（年化收益、最大回撤、Sharpe 等）、`drawdown{mark_max_drawdown@2, peak_utc@2, trough_utc@2, …}`、
  `capital{time_in_market@1, …}`、`cost_basis{account{starting_balance_usdt, execution, …}}`、
  `availability`、`limitations`；没有经济证据时 `headline / drawdown / capital / cost_basis` 被产品遮蔽为 null；
  封存不带 `fees_by_liquidity_side@2`（旧指标修订）时 `cost_basis` 也为 null。
- `tables.positions`（周期：seq、instrument_id、side、ts_opened_ns、ts_closed_ns、realized_pnl、commissions、
  funding、price_pnl、closing_order_type）、`tables.daily_returns`（ts_event_ns、native_return、
  mean_gross_notional；起始资金未知时为 null，`tables.limitations` 带 `ACCOUNT_UNKNOWN`）。
- 路由**不**返回试验的 `instruments` 和市场提交：合约列表用周期里交易过的合约，市场提交用本线的
  （研究回放与线同一市场提交，由图的过滤保证）。

产品的拒绝（`RUN_NOT_PASSED`、没有经济证据）原样透传，图上用它的话写说明——**资格由产品判，IDE 不自己
复刻一遍遮蔽逻辑**，这是选 `replay report` 而不是在服务里拼 `ledger sql` 的原因。

缓存键 `(trial_id, ledger commit)`（`run_sealed` 以指标修订为键，换修订会换提交），和视图一样在进程内
LRU。第一次读要跑一次命令（秒级）：图左上角先写 `Reading trial 200…`，模拟盘段先画；路由失败和产品拒绝
分开写：前者状态栏红标、图上说明写 `Backtest data not served by this IDE`；后者说明写拒绝码和原因。

### 6.2 `GET /api/bars?symbol=&timeframe=1d&start=&end=&at=<market commit>`（可选，第二步）

跑 `market bars --symbol <裸代码> --timeframe 1d --price-type LAST --start --end` 于本线的市场提交；
`start` 向下、`end` 向上取整到整 UTC 日（命令要求）；IDE 服务需要 compose 已经挂进 ide 容器、今天只给
对话服务用的市场档案。只服务 1d：日 K 线由分钟行现算，一年约 52 万行，首读远不止秒级——说明写
`Reading daily bars…`，服务用 `--output` 落临时文件后读回；缓存键 `(market commit, symbol, range)`；
市场库没有的合约返回产品的拒绝。没有这条路由时，回测段的合约视图只画周期带（§2.4）。

## 9. 否决的方案与风险

**否决。**
- 并排两栏 + 阶段标尺（本稿第一版）：用户 11-01 看后否决——图要连续、分栏要无感。
- 一条真实时间轴、回测段铺一层底色、空档压成 24px 的缝：底色会铺满九成宽度，成了换背景；缝要借离线段的
  端点和轴标签；权益线在缝处从 12 万落回 10 万像一次崩盘。接续复利和不画空档正是对这两点的回答。
- 三个独立的岛各一个头部：三条工具条平铺，正是用户否过的「frame 拼出来」的样子。
- 标签页（MetaTrader 的 Forward）：两段看不到一起。
- 把回测叠在模拟盘日期上（QuantConnect 的 OOS 叠线）：研究回放不覆盖模拟盘的日期；覆盖的那条是对账回放，
  已经在；为此重放一次会写 explore 试验。
- 回测合约图上按 K 线高低放成交箭头：周期没有价格，箭头会被读成成交价位。
- 右侧 Details 里放一张 Paper runs 表：用户 10-25、10-26 两次否掉右侧运行列表；图上的段说明加工具栏运行菜单已够。

**风险。**
- 接续复利把模拟盘画在 12 万以上，第一眼会被当成模拟盘账户的余额——读数同时给本段自己的值，工具栏和
  Details 都只写本段自己的；高保真稿里先看。
- 索引轴不按时间给宽度：整段看时一年的回测和四周的模拟盘各占一半上下，读者要靠时间轴的日期知道这一点。
- 日级回撤和分钟级回撤并排会被当成同一个量：脚注、图例基准、回测段点阵带按封存值定刻度是护栏。
- 步长按点数换档、回测段在细步长下被压窄、段内各算派生层，都是对现有权益图层的改动，每个文件 ≤200 行要
  拆新文件。
- `replay report --tables` 每次秒级，日 K 线首读更久；首次打开有等待说明，缓存后无感。
