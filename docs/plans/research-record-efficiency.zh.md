# 投研记录检索效率：机械基准与隔离 Agent 对照

## 已测结果（2026-10-08）

使用真实 H13c、H18a、F01 问题，固定命令各运行 10 次；原始读数在[基准回执](../../reports/research_record_efficiency/retrieval-proxy-20261008.json)。这是**命令层代理指标**，不是独立 Agent 盲评。原台账路线用 `rg` 在最相关的旧台账或 F01 结果文档查词；索引路线用 `research.records.cli` 的 `show` / `compare`。两者输出内容和人工综合成本不同，因此不把命令耗时比值称为 Agent 效率提升。

| 真实问题 | 索引命令中位耗时 / 输出 | 旧文件搜索中位耗时 / 输出 | 已验证的能力 |
| --- | ---: | ---: | --- |
| H13c 从 H13、H13b 怎样演变、各失败在哪层 | `show H13c --brief` 68.43 ms / 1,923 B | `rg H13c` 3.06 ms / 30,757 B | 简要视图保留完整父链、失败层和证据状态。 |
| H18a 与已登记 H15a 对照的账户差 | `compare` 137.40 ms / 1,169 B | `rg H18a` 3.42 ms / 41,493 B | 检查已登记对照、可比合同、原生摘要和审计后返回 +741.36 USDT。 |
| F01 的四格、父贡献及结论 | `show F01 --brief` 68.07 ms / 3,299 B | `rg F01` 3.22 ms / 1,550 B | 一次返回 00/10/01/11 的运行 ID、父关系、失败结论及证据状态。 |
| F01-11 与直接对照 F01-10 的账户差 | `compare` 151.77 ms / 1,152 B | `rg 582.64` 3.20 ms / 912 B | 在合同和审计检查后返回 −582.64 USDT；用 F01-00 冒充直接对照被拒（退出码 2）。 |

原 `show` 对 H13c/F01 分别输出 4,669/23,232 B；新增 `--brief` 后降为 1,923/3,299 B，分别减少 **58.8%/85.8%**，同一命令启动与核证耗时没有明显变化。`rg` 的机器执行速度更快，索引输出也并非每题都更短。当前能确认的是**定向读回、证据状态和错误对照拒绝**，不能据此宣称 Agent 更快、更会选假设，或提高可用策略产出率。

## 隔离 Agent 对照试验（2026-10-09）

在运行前冻结[八道真实题与评分法](../../reports/research_record_efficiency/isolated_trial_protocol_20261009.json)、[逐题答案键](../../reports/research_record_efficiency/isolated_trial_key_20261009.json)。题目覆盖 H13→H13b→H13c 失败链、H18a 父假设与组件、H19a 已登记对照、F01 四格、源码身份和下一步停机规则。每题四个二值点：两个事实、一个证据路径、一个推论或下一步边界；满分 32。同一题序和倒序均安排独立 Agent；每次限 30 次工具调用、八分钟，仅读指定仓库，不运行回测。

索引组有相同旧台账、报告和 `research/records`；对照组只有旧资料。第一版对照工作树的 `git status` 泄露了被删记录的文件名，故在阅卷前把 C1/C2 **整组剔除**，以无该目录、无旧 Git 历史的独立仓库重跑 C1R/C2R；[修正说明](../../reports/research_record_efficiency/isolated_trial_amendment_20261009.json)保留。随后并行复测 C3/I3。原定的 C4/I4 未执行，不能按四组样本报告。逐次时间、调用数和失分见[结果回执](../../reports/research_record_efficiency/isolated_trial_results_20261009.json)。

| 有效试次 | 对照：得分 / 活跃秒 / 工具调用 | 索引：得分 / 活跃秒 / 工具调用 |
| --- | ---: | ---: |
| 正序 C1R / I1 | 30/32 · 45.868 · 15 | 32/32 · 40.522 · 12 |
| 倒序 C2R / I2 | 30/32 · 35.268 · 12 | 32/32 · 54.882 · 13 |
| 正序复测 C3 / I3 | 30/32 · 38.048 · 10 | 32/32 · 53.398 · 15 |
| 三次汇总 | 得分均值 30/32；耗时中位 38.048 秒；调用均值 12.33 | 得分均值 32/32；耗时中位 53.398 秒；调用均值 13.33 |

这里的 **run ID** 是索引中一次具体回测的稳定编号，如 `F01-10-20261008`；`H19a` 是研究尝试，`/tmp/r1-factorial-f01-10-37` 是可删除的输出目录。一个尝试可以有多次运行，因此原始 `H19a-2026-10-08` 和后来的 `F01-10-20261008` 不能混作同一次证据。对照组三次都把应为 +6,762.51088300 USDT 的原始 H19a 对照差写成 F01-10 重跑的 +6,762.51440990；只差 0.00352690 USDT，**经济判断没有实质差异**。

正式 F01 run ID 只存在于索引组资料。对照组答对了四格的策略/尝试映射，却无法报出新增编号；把这点当作 Agent 检索能力差异不公平。保留事前规则下的 32 分原始分数供审计，另剔除这一点做**双方共有信息**的事后敏感性分析：索引组 31/31，对照组 30/31。剩余一分只涉及上面两次运行的精确区分；两组在八道题的下一步/推论边界点均满分，**未测出研究决策质量增益**。31 分分析是事后补充，不能冒充事前冻结的主要终点。

本试验支持的窄结论是：结构化侧录使正式运行编号可查，并帮助这组三个 Agent 区分原始运行与后续重跑；在双方共有信息上只有一个数值极小的运行血缘差异。**未测出速度或调用次数收益**：索引组中位活跃时间多 15.350 秒，平均多一次工具调用。前两对不是同时运行，缓存、调度、Agent 差异和题序都可能影响耗时；调用数是 Agent 自报，根节点墙钟时间、令牌和侧录维护工时未取得。对照仓库缺少旧 Git 历史，结果回执也只保留逐题得分与失分摘要、未存完整原始作答。六次作答、同一批八题不足以估计总体收益、返工成本或策略成功率，更不能据此声称已达到投产效能门槛。后续应补独立题库、完整原始作答存档、记录写入工时，并用未暴露或前向数据检验策略产出。
