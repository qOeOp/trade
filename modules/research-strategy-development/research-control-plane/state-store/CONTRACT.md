# Research State Store Contract

Owns `research_state_store`, including the durable R&D program memory and the Research Control Plane facts.

## Responsibilities

- Issue one create-or-identical Replay L2 Experiment Attachment Authority v1 per authoritative reserved Trial/Reservation. Issuance revalidates the exact Request and full Dataset Manifest、owner-pinned single-epoch source、bounded batch hashes/rows、frame adjacency and Dataset time window；the immutable registry stores only identities/hashes/bounds, not raw depth payload. Update/delete、same-natural-key drift、cross-epoch、unbound frame and expired/non-reserved issuance fail closed. This is a non-economic experiment attachment and is not Runner input or queue/Fill authority.
- Issue one create-or-identical Bar-linked Aggregate Trade Path Authority v1 per authoritative reserved Trial/Reservation. Issuance revalidates the exact Request、Stop-market liquidity binding、Dataset、parent Aggregate Trade/Ordering Admissions and Replay-owned Bar Link；the linked bar must be fully contained in both parent windows and use the Ordering Admission's exact aggregate events hash, while the wider parent window may separately contain closed-bar visibility facts. The range must contain both the entry trigger and a protection-path question. The immutable registry grants no Runner activation、Fill quantity、cost、queue or default-path authority.
- Create and migrate `data/rd_state.db`.
- Own the formal Replay resident queue as immutable work identity plus a globally single active slot. Claim/restart is fenced by `lease_owner + lease_generation + lease_expires_at`; same-owner restart resumes the same generation, expiry requeues for a later generation, completion/dead-letter clears the slot, UPDATE of identity and DELETE are forbidden. Queue state grants no Replay、Review、deployment or trading authority.
- Reconcile each completed、`mechanical_replay/replay_owner` formal Replay Result into exactly one durable Reviewer Agent job. The job preserves immutable Replay/Result identity and a globally single active slot; `lease_owner + lease_generation + expiry` fences admission, same-generation restarts reuse the exact Agent Run time window, expiry rotates to a new Run identity, and pre-existing owner Review is recovered without a second decision. This queue schedules Reviewer work only; Agent output still has no lifecycle authority until `apply_reviewer_decision` accepts it, and it never grants Registry、deployment or trading authority.
- Admit a certified Strategy source into Forward only through an immutable `Certified Strategy Source Binding v1`. The bridge independently joins the completed Registry job、Draft、candidate manifest、Ops adoption result、certified manifest and exact source/archive hashes；the same transaction records `rd_forward_source_admission` and moves `draft_frozen -> forward_observation`. This grants only permission to collect Forward evidence for the exact certified source revision；it cannot hot-load、deploy、promote or trade.
- Record an OHLCV-only `Forward Dataset Candidate v1` only after independently replaying the exact Program and complete ordered candle-segment prefix against the verified bars. `rd_forward_dataset_candidate` is append-only and binds one immutable head/watermark/artifact hash；it is evidence inventory only and grants no Forward Replay admission、deployment or trading authority.
- Record renewable exact-window Forward funding demand deliveries and at most one immutable evidence binding per Dataset Candidate. Admission independently replays Candidate→Program→demand receipt→owner coverage audit/fact→content-addressed numeric slice lineage and verified bytes；it grants only one funding component binding.
- Register an immutable, create-or-identical Forward current-instrument provider certification separately from historical Replay status-provider certification. Admit at most one status/spec binding per Candidate only after revalidating the registered certification and a bounded series of exact owner acquisition evidence from freeze through watermark；the series records that inter-sample history is not proven.
- Derive `Forward Dataset Readiness Assessment v3` from the immutable Candidate、historical registered Request/Manifest and optional admitted funding/current-instrument bindings. Funding and status/spec blockers are removed only by their exact bindings；risk、a new post-freeze decision and formal Manifest remain open，while mark and supplemental blockers follow the historical evidence profile. It must not reuse the historical signal/order as a Forward decision or issue admission authority.
- Upsert current RD program state.
- Upsert hypothesis queue/status rows.
- Append trial and locked holdout-use ledger rows.
- Append lessons learned by kind.
- Issue the P27 Two-Fixed-Partial Cycle Sequence Reservation atomically only while every declared child Reservation still matches a current reserved Trial and active Attempt Lease. The producer freezes exact child hashes/order and cannot estimate successor cash or append a runtime cycle.
- Own Strategy Universe, scope, coverage, and capability registry projections.
- Register immutable, create-or-identical Instrument Status Provider Certification v1 snapshots. Each certification binds a Market Data provider capability/build/normalization tuple to one certifier policy and half-open validity window; update/delete and same-identity content drift are rejected.
- Register immutable, create-or-identical Provider Certification Termination v1 facts. `recorded_at <= effective_at` forbids backdated revocation; one certification has at most one terminal fact. Supersession requires a separately registered, same-provider successor that is admitted at cutover; revocation has no successor. Neither operation updates Certification v1.
- Register a separate immutable Aggregate Trade Provider Certification v1 and non-retroactive Termination v1 lifecycle. Certification binds the actual Market Data capability/build/policy and only permits Archive v1 → Replay Event/Attestation with `external_completeness=not_verified`; status-provider certification cannot substitute for it.
- Issue one create-or-identical Aggregate Trade Evidence Admission v1 per Trial Reservation hash while the Trial remains reserved, the Reservation window is open and the provider certification is admitted. The sidecar binds archive/source-receipt/audit/evidence/attestation hashes and is permanently scoped to pre-integration exact-price-path evidence; it does not mutate Reservation v9, authorize an Attempt, or enter Runner input.
- Issue one create-or-identical Cross-source Ordering Admission v1 for the same Reservation and Aggregate Trade Evidence Admission. Issuance validates the Replay-owned Ordering Attestation、canonical four-source set、aggregate coverage window/events hash、Dataset/status Reservation bindings、active provider certification and reserved Trial state. It persists source/ordered-event/ambiguity/limitation hashes without event payload、execution authority or mutable latest pointer.
- Issue one create-or-identical Decision Observation Bundle Admission v1 per Reservation. Issuance revalidates Request v30、Reservation v9、the registered Ordering Admission、Wire v2、the complete frozen Schedule binding set and portable Bundle while the Trial remains reserved and the Reservation window is open. It persists hashes and a non-economic audit capability only; parent validation is deliberately limited to Wire identity plus Schedule binding, Projection derivation remains uncertified, and no Harness/Runner/economic consumer reads this receipt.
- Issue one create-or-identical Decision Observation Bundle Derivation Admission v1 per Reservation after Bundle Admission. Issuance requires the same authoritative reserved Trial and open Reservation, validates the Replay-owned Attestation schema/self-hash, and aligns its Wire、Schedule、Bundle、Binding Set and every boundary hash with the prior admitted Bundle. The store does not import Replay Engine or claim parent replay; the receipt records `control_plane_parent_replay=not_performed` and grants no Harness/Runner/economic authority.
- Materialize immutable Trial Reservation Snapshot v9 from the reserved Trial、Group、Candidate membership、Experiment Contract and admitted provider certification. The raw snapshot constructor remains an internal compatibility primitive for older Control Plane authorities；new general Trial execution must enter through Replay Trial Reservation Admission v1, which derives rather than trusts its bindings. Effective provider admission is `[certified_at, min(valid_until, termination.effective_at))`；termination never rewrites or implicitly cancels a previously issued Reservation.
- Own immutable Reservation Cancellation v1 receipts. A cancellation binds the full Reservation hash and authoritative Trial/run, is non-retroactive, and permanently rejects new claims at `effective_at`; delivery of an already active claim remains idempotent and the active Attempt is not implicitly stopped.
- Own immutable Attempt Cancellation v1 receipts. Cancellation must match the active Attempt identity and current lease generation, is committed atomically with terminal `cancelled` state, and makes later renew/finalize/checkpoint authority stale. Attempt-only cancellation permits a later retry unless the Reservation is separately cancelled.
- Expose a read-only Attempt Cancellation directive for an exact still-unexpired worker lease, and register one immutable Attempt Cancellation Observation v1 after Runner returns the hash-bound cancelled Run Outcome. Observation is create-or-identical, enforces `cancellation.recorded_at <= observed_at <= registered_at`, and grants no checkpoint/resume authority; polling cadence、cross-process transport and bounded stop latency remain coordinator responsibilities.
- Expose a structural SQLite coordination-port adapter without importing Replay Runner. The adapter composes the existing directive/observation authorities; repeating the same Observation through the port is idempotent and preserves the first successful `registered_at`, while competing content remains rejected. It derives `authority_to_observation_ms`、`observation_to_registration_ms`、`authority_to_registration_ms` from immutable timestamps; these are measurements, not an SLA、durable outbox or transport retry policy.
- Inspect recovery against the authoritative cancellation/Observation registries as `pending` or `already_registered`, then accept pending redelivery through the same create-or-identical Observation registry. Control Plane does not discover、read、mutate or garbage-collect Runner outboxes and does not treat their commit as Result、Checkpoint or Resume authority.
- Own Replay Attempt claim/renew/expire/finalize state. The production claim is only `claimRegisteredReplayAttempt`：it accepts Replay Attempt Admission Request v2，reloads and verifies Request Registration、complete registered Request、Reservation Admission and Snapshot，derives request/reservation hashes，then persists Registration id/hash on the Attempt. For a Registration-bound active Attempt，`issueReplayRegisteredAttemptDispatchAuthority` 在单事务内重读 Registration、registered Request 与 exact current Lease，签发 self-hashed Request/Lease pair；raw compatibility Attempt、stale generation、foreign worker、expired/terminal Attempt 均不得签发。Claims must not precede Registration and must fall inside the Reservation window；one active Attempt per Trial，lease generation is monotonic，terminal rows are immutable，and only completed rows may carry Result/Artifact/checkpoint completeness fields。Reservation expiry does not revoke an already admitted Attempt；its lease remains execution authority。Generic raw claim API 已删除；历史租约/取消测试只能经显式 `test_only_raw_replay_attempt_claim` compatibility fixture，且该 fixture 不属于生产 authority surface。
- Issue `Replay Portfolio Two Fixed Partial Reservation v1` from one immediate SQLite read transaction. Every Lane must resolve to the same frozen Experiment/Trial Group, a current `reserved` Trial, the exact Trial Reservation hash and a matching active Attempt lease request hash；the Portfolio authority window must be contained by both child windows. Caller-supplied source terminal/risk hashes and collateral become frozen inputs but do not grant Review、Lifecycle、search expansion or execution semantics beyond the explicit projection policy.
- Expose a read-only Current Attempt Lease Observation Receipt v1 from one SQLite transaction keyed by Trial. Only the unique `claimed|running` Lease inside `[heartbeat_at, lease_expires_at)` can produce a receipt；terminal/missing/early/expired observations fail closed. Register the official receipt in an immutable create-or-identical SQLite registry：first registration rechecks the exact current Lease inside one immediate transaction and before lease expiry；retries return identical evidence；identity/ref/hash/natural-key collisions、UPDATE and DELETE fail closed；the receipt remains readable after restart. Caller-supplied UTC is not external clock attestation, and the receipt alone does not prove a downstream caller fetched it from this registry.
- Read that immutable registry through a dedicated Lease Observation Registry Read Receipt v1：one transaction must exact-match the registered contract and current `claimed|running` Attempt/Lease, preserve the original `registered_at`, and satisfy `registered_at <= read_at < lease_expires_at`. Missing、terminal、renewed、pre-registration or expired reads fail closed. `read_at` remains caller-supplied UTC, so the receipt proves registry provenance but not independent time.
- Expose Dispatch Clock Attestation v1 through an authority-owned clock port with no caller timestamp parameter. Sample UTC wall time and monotonic nanoseconds before and after the registry/current-Attempt transaction；require a nondecreasing wall bracket, strictly increasing monotonic bracket, completion before Lease expiry, and exact embedded Registry Read Receipt. The production port uses process wall/monotonic clocks；test doubles are injectable, but the contract never claims signed TSA/NTP/remote trusted time.
- Produce Spawn Boundary Revalidation Receipt v1 only for a capsule-bound Request v1. The authority-owned clock brackets a direct single-transaction current-Attempt read；Attempt/ordinal/worker/generation/full Lease hash/expiry must equal the Request and remain active through completion. The producer never imports Replay capsule internals or trusts caller time/state, does not persist a mutable grant, and states the post-read cancellation/fencing race explicitly；Replay owns durable Request/Receipt binding and process launch remains separate.
- Own append-only Replay Checkpoint Receipt v2 registration. A receipt is accepted only inside the exact active Attempt lease generation, binds the immutable versioned diagnostic commit/payload hashes plus certified storage-policy version, and advances `next_source_offset` monotonically. Repeating an already committed receipt is idempotent even after Attempt expiry; new evidence from a stale or terminal lease is rejected. Migrated v1 rows are marked `rd-replay-local-rename-no-fsync-v0` and cannot authorize a v2 resume.
- Own immutable Replay Resume Authorization Snapshot v1 issuance. Authorization may bind only the latest registered Checkpoint Receipt on a `cancelled`/`expired` source Attempt to one later active target Attempt under the same Trial/run/request/reservation authority; target Attempt is unique, lease generation is a floor, and workers cannot mint or mutate this authority.
- Seed the frozen default Universe, Data Surface Registry, capability index, and current coverage map.
- Serve the authoritative Planner context from those facts and scoped KG lessons as a canonical self-hashed `Planner Control Plane Context Snapshot v1`; repeated unchanged reads are byte-semantic identity, and any selected fact change rotates `context_hash`.
- Admit bounded `Planner Proposal Submission v2` through one immediate transaction. Intake revalidates the self-hash、exact current context、active canonical、globally ready Data Surfaces and ready per-canonical links；it persists immutable Proposal identity plus contiguous append-only revisions and returns an accepted-only self-hashed Admission receipt. Same-key drift、revision gaps、scope drift and stale context fail closed without partial writes. Admission creates no Contract、Trial Group、Trial or queue item.
- Issue one immutable Developer Development Brief only from the latest admitted Proposal revision, then receive contiguous append-only Contract Draft submissions. Intake revalidates exact Brief/Proposal hashes、latest-revision freshness、the declared candidate-space hash、canonical、required data、maximum Trial budget and chronology；same-key drift、declared binding drift and stale Brief fail closed. Agent-originated Draft intake atomically stores a self-hashed provenance sidecar binding the exact Agent request/result/submission、Contract Draft submission and frozen source revision；legacy/manual Drafts may omit it but can never enter automatic Registry source release. The receipt remains `received_unvalidated` and never writes formal execution authority.
- Validate only the latest received Draft revision into one append-only `valid|invalid` Validation Record. The owner runs the current full Experiment Contract v3 validator, rechecks Brief freshness、canonical/data/protocol、bounded scalar-enumeration candidate-space membership、normalized candidate assignment set and Trial budget/group bindings, and persists both success and failure evidence idempotently. Validation never writes the Experiment Contract、Candidate、Trial Group、Trial or Replay reservation tables；formal freeze is a later authority boundary.
- Freeze only a current `valid` Validation Record through compiler v1. One immediate transaction revalidates the Draft、derives lexicographically ordered enumerated Candidate identities and a policy-bound Trial Group hash、registers the formal Contract/Trial Group/Candidates、writes the bootstrap lifecycle event and immutable Freeze Record. A registration failure rolls back every fact. The transaction also writes a versioned legacy Proposal compatibility projection solely because the current Experiment table retains that foreign key；Freeze Record remains authority. Freeze leaves Trial Group `registered` and creates no Trial、Reservation or Replay request.
- Start one frozen Experiment only through immutable Experiment Trial Plan v1. One immediate transaction revalidates Freeze/Contract/Group/Candidate identities、current `registered + proposed@v1` state、chronology、complete Candidate coverage and `max_trials`；then starts the Group、appends `pre_run_gate_passed` lifecycle evidence and reserves every contiguous Trial. Any late Trial failure rolls back Group、lifecycle and earlier Trials. The resulting `rd_trial(status=reserved)` facts are Control Plane budget reservations only；Replay Trial Reservation Snapshot v9 remains a later Dataset/harness/policy-bound authority.
- Compile one immutable Experiment Evaluation Work Package per Trial Plan. Compilation rechecks `discovery + running` state、current Plan/Freeze/Draft/Contract identities、registered family/evaluation protocol、exact v3 report/manifest/content bytes、frozen Candidate assignments and canonical runtime cost policy. The package can drive only compatibility evaluation; it does not create Reservation Snapshot、Replay Request or Attempt authority.
- Publish compatibility evaluation only as one atomic Trial-group transaction: all exact already-reserved Trials become completed, one Result is appended and one `compatibility_mechanical_replay` classification is registered. A crash after artifact creation is recoverable by exact package/run identity; positive Reviewer promotion still requires separately classified formal `mechanical_replay`.
- Admit Replay Trial Reservation only through immutable Admission v1. One immediate transaction requires an exact Trial Plan item still in `reserved + running + discovery`，validates the pre-Reservation Execution Spec without accepting embedded Reservation authority，recomputes all Dataset/supplemental/risk/spec/status/provider/harness/assumptions/cost/margin/simulator bindings from the supplied full Manifest and Spec，requires point-in-time universe、complete status history、available-at-issuance evidence、active risk epoch and registered provider provenance，then persists exact Spec/Manifest JSON、their hashes、embedded Snapshot v9 and self-hashed Record。The capability set is the Runner's complete certified set, not caller input；overlapping active Reservations、same-key drift and row mutation fail closed. Admission creates no Replay Request or Attempt.
- Register Replay Request only from one immutable Reservation Admission v1. The caller cannot submit Request fields；one immediate transaction reloads and revalidates the persisted Spec、Manifest、Admission and Snapshot，requires `reserved + running + discovery`、open non-cancelled Reservation window，then performs the only permitted transformation：insert the admitted Reservation ref/hash into the exact admitted Spec。The registry persists the complete Request and self-hashed Record，rechecks every identity/binding plus Request/spec/Manifest hashes，and rejects competing registration、same-key drift、expiry、cancellation or row mutation. Production Attempt Admission v2 now consumes only this registry identity/hash；raw claim remains explicit migration compatibility debt, not canonical authority.
- Materialize one immutable Forward Observation Program only after certified source admission. The owner closes source binding、ready Draft authorization、selected historical Replay registration、symbol/timeframe and strict post-freeze boundary；a resident bridge may then request/renew only the exact open-ended OHLCV demand and append owner-accepted delivery receipts. Neither Program nor receipt creates a Forward Session、Dataset/Reservation、Replay Result、promotion、deployment or trading authority.
- Append only gapless `Forward Observation Candle Segment v1` records after the Market Data owner has selected the exact active demand and proved the bounded window complete. Every row closes the predecessor、demand receipt、subscription plan、coverage audit、MarketDataFact and immutable slice identities；late gaps、unclosed candles、deferred demand、mutable replay and lifecycle drift fail closed. Segment collection does not mint a formal Replay Dataset Manifest or Forward Replay authority.
- Append validated Proposal Revisions and materialize each Proposal at most once.
- Register immutable Trial Groups, Candidates, and Experiment Contracts.
- Write the bootstrap lifecycle event in the same transaction as Experiment registration.
- Atomically append Reviewer Decision, evidence links, lifecycle event, and optimistic-concurrency projection updates.
- Enforce Trial, Result, Decision, lifecycle, candidate-freeze, and KG evidence invariants in SQLite.
- Calculate and verify versioned canonical identity hashes for Proposal, Contract, Candidate, and Trial Group identity.
- Project Experiment, Trial, Result, Decision, and Lesson relations into the minimal KG in owner transactions.
- Rebuild lifecycle projection from append-only event history and verify integrity.

The legacy program-learning trial ledger is `rd_program_trial`. `rd_trial` is reserved for the Control Plane Experiment Trial fact.

## Boundaries

- Does not run experiments or replay.
- Does not promote strategies.
- Does not write `trade.db`.
- Does not call exchange APIs.
