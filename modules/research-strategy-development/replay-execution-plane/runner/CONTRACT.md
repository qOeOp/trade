# Replay Trial Runner

Owns Trial-scoped Replay orchestration, Attempt authority validation, attempt-local idempotency, cooperative cancellation, resumable checkpoint handoff, typed failure, and durable Result Artifact commit.

Artifact Manifest v45 is the success commit marker. Runner 对 Result v43 的 OHLCV、pending-order、entry outcome、Decision Timeline v10 与 liquidity-capacity authority 在首次发布和幂等读取时重验。pre-entry Limit GTC/IOC 与 Stop-market GTC 必须有 PIT 可用且 Request/Reservation/Dataset 一致的 Capacity Attestation。filled 分支必须 terminal full Fill、Fill-after-source EventKey；Limit price 不劣于 limit，Stop 必须绑定 trigger/source/reference 与 `triggered → filled` OrderEvents。`unfilled_at_data_end` 必须全链 resting、Order active；`expired_unfilled` 只属于 Limit earliest-open IOC；`cancelled_unfilled` 必须绑定 matching contract intent、指定 `bar_range`、phase-`90` Cancel EventKey 与 cancelled OrderEvent。若 Schedule v7 含 `authorized_entry_cancel`，Runner 将其置为 pending runtime；effective range 到达后 Harness 必须输出相同 Intent，State Snapshot 为 null；更早 Fill 则 not-reached。Limit touch-before-cancel 与 Stop same-bar post-trigger protection path ambiguity 均为 deterministic-engine typed failure，无 Result/Artifact；后者额外携带 self-hashed path evidence。Run Outcome v35 completed 可携带四类权威 Result/Artifact。

Step Engine may emit Checkpoint v22 only after a complete source-event boundary. Besides existing authority/state it stores active Limit/Stop pending entry、ordered resolution prefix、Decision Timeline v10 and nullable entry transition；resume must not replay a consumed observation、Harness decision、trigger、Fill、expiry or contract Cancel。Runner durably publishes the Attempt/lease-generation/source-offset-bound payload and Diagnostic Checkpoint Commit v2；clean/resume Result hash 必须一致。SQLite reference execution cancellation 已认证；它与订单 Cancel 是不同 authority，remote transport 与 stop-latency SLA 尚未认证。

`replay-cancellation-coordinator` owns the transport-neutral Experiment Runner adapter: every complete boundary polls an injected authority port with the current lease, delegates ordinary renewal when no cancellation exists, and acknowledges a receipt-bound Observation after Run Outcome. The adapter returns Coordination Result v1 with poll count and typed acknowledgement status; acknowledgement failure preserves the exact cancelled Replay outcome、poll count、attempted registration time and original cause instead of pretending registration succeeded. `acknowledgeReplayCancellationOutcome` retries only that validated immutable Observation and never polls or reruns Replay; non-authoritative outcomes are rejected. That helper alone is only an in-process retry seam; durable recovery requires the outbox below. The SQLite implementation remains Control Plane-owned. Authority cancellation publishes no resumable checkpoint/diagnostic commit and removes attempt-local diagnostic files; this is not generic artifact-directory GC. Push/poll/lease-response transport and latency SLA remain deployment decisions.

`replay-cancellation-outbox` adds the certified local durable seam. Durable coordination uses the Runner-owned canonical cancellation-outcome constructor after validating the directive and current lease, then commits one fixed-name, self-hashed Outbox Record v2 through the certified Attempt-local Artifact Store **before returning `cancel` from the Engine source boundary** and before calling `acknowledge`; persisted bytes must equal the later Runner terminal outcome. V2 additionally persists the exact cancellation-generation lease and logical idempotency-key hash, so the record can reconstruct and hash-check its own Attempt namespace without Request/Reservation replay. Persistence failure is retained while the authority cancellation still terminates Engine, then raised as a typed error with the exact cancelled outcome and suppresses ack. Invalid/expired directives never reach the outbox. A restarted coordinator reloads and revalidates the record, then retries only Observation registration；it never polls or reruns Replay. Identical persistence preserves the first `persisted_at`; competing content and byte/hash tamper are rejected. Durable Coordination Result v1 carries the operational outbox commit, but neither record nor commit is a Replay Result/Artifact Manifest、Checkpoint Receipt or Resume authority. The record remains after successful ack so post-commit crash windows collapse to idempotent redelivery；poll 返回至 local commit 仍非跨存储事务，retention/GC、remote store adapter and transport remain undecided.

Durable coordinator admission remains recovery-first for a known invocation. In addition, the certified local store exposes deterministic, read-only two-level Attempt namespace discovery. `recoverDiscoveredReplayCancellationAcknowledgements` first scans and validates the entire set, requires every v2 record to map back to the namespace derived from its idempotency-key/Attempt hashes, then asks Control Plane whether the exact Observation is pending or already registered. Pending records are acknowledged without poll/Runner/Engine；already-registered records are reported without redelivery. Discovery Recovery Result v2 exposes only portable namespace/record/Observation hashes and Attempt generation；it never returns machine-local namespace or outbox refs. Any malformed tree、symlink、legacy v1 record、misplaced namespace、lease/outcome drift or authority hash conflict fails before delivery. V1 remains recoverable only through the explicitly bound legacy helper；there is no heuristic migration. Discovery is local-filesystem-only and does not define remote listing、retention/GC、quarantine or startup SLA.

The outbox namespace is Attempt-scoped, not initial-generation-scoped. Its constructor lease freezes the Attempt identity and a minimum generation; every persist additionally supplies the exact current lease snapshot. A later cancellation may therefore follow monotonic renewals in the same Attempt only when trial/run/request/reservation、attempt id/ordinal/worker remain unchanged, current generation is not below the constructor floor, and the prepared outcome lease hash/generation exactly match that current snapshot. V2 stores that cancellation-generation snapshot；discovery rehydrates it from immutable bytes and cross-checks Observation/outcome/hash before consulting Control Plane. The stale initial generation still fails the known-invocation path；generation rollback、worker replacement or cross-Attempt reuse remain invalid.

If the simulated full close leaves negative isolated collateral, Runner returns typed `liquidation-deficit-unsupported` with the breached snapshot, trigger observation, and `remaining_collateral`; it publishes neither Result nor Artifact and never invents insurance-fund, bankruptcy-price, or ADL facts.

An open position reaching manifest-bound delisting returns `instrument-delisted-with-open-position`, carries the phase-`00` terminal EventKey, is non-retryable, and commits no partial Result. A settlement price requires a separately frozen data contract; Runner does not synthesize one.

`dataset-grid-gap-in-execution-window` is a non-retryable `data_integrity` failure. Its self-validating evidence distinguishes `missing_earliest_executable_bar` from `open_position_grid_gap` and binds exact missing bounds/count. Runner publishes neither Result nor Artifact, whether the failure is raised by admission or source reduction. Retry is meaningful only after Control Plane freezes a different Dataset Manifest/Data Hash; it cannot reinterpret the same immutable input.

`maintenance-margin-breach-while-halted` is a non-retryable `deterministic_engine` failure. Runner preserves exact risk evidence but publishes no Result/Artifact. Resume uses Checkpoint v22 source prefix, so it cannot skip the halt、replay Funding or replay a pending-entry observation.

R4.104 adds **Runner-owned Decision Worker Input Assembly v4** as a pre-execution code-admission seam, not a Trial Runner capability. It embeds the complete R4.103 v3、matching full R4.96 Context Binding、Harness Source Bundle v1 and Build Attestation v2；the builder uses the existing deterministic Bun build path and requires byte-identical rebuilt attestation/artifact, so a merely self-hashed forged artifact is rejected. The published object still declares registry admission and invocation identity unbound, Worker Request/Harness invocation forbidden, and no Decision/Signal/Order/economic authority. Independent validation requires repeating the deterministic build；the object does not prove signed provenance、SBOM、OS sandbox or remote runtime compatibility.

R4.105 adds **Runner-owned Decision Harness Code Admission v1** without integrating Trial Runner execution. The builder validates the fixed process-memory Registry Capability, resolves exactly the v4 `source_bundle_hash`, requires the returned Source Bundle/Build Attestation to equal v4 code evidence, then publishes a deterministic receipt containing the full capability、registration and parent v4. The receipt deliberately records `registry_instance_id=null`、unavailable instance identity、`future_lookup_guarantee=not_proven` and unsigned process-local authenticity. A custom object can implement the same interface, so this is admission-time compatibility evidence—not durable/signed registry provenance, remote availability, invocation identity, Worker Request, Harness execution or any Trial/economic authority.

R4.106 adds **Runner-owned Decision Harness Invocation Identity Set v1** without creating a Worker Request. The builder consumes one complete R4.105 receipt and derives a schedule-ordered logical identity per v3/v2 tuple from the exact existing Worker v9 fields；the live Worker path calls the same pure derivation helper, eliminating formula duplication. The reproducibility pair intentionally shares one logical ID. PID、process instance、execution attempt and retry identities are not materialized；Context remains parent-bound but is not a direct member of the legacy v9 hash. The Set keeps Worker Request null、Harness invocation forbidden and grants no Trial/Decision/Signal/Order/economic authority.

R4.107 adds **Runner-owned Logical Request Identity Upgrade v1** without activating Worker v10. The builder projects each R4.106 entry into Identity Policy v2：target protocol/schema、Context、Code Admission、bundle/artifact and phase-required snapshot hashes are direct formula members；the v9 ID is migration metadata only. Attempt lease/ordinal/worker are excluded from logical identity so renewal and retry cannot perturb the same frozen request；they belong to a later execution envelope. The upgrade remains pre-worker evidence with null Request、no process/attempt identity、forbidden Harness invocation and no Trial or economic authority.

R4.108 adds **Runner-owned Worker Request v10 Materialization v1** without changing the live v9 Worker path. The builder projects every R4.107 identity onto the exact complete v2/v3 input entities and produces a field-whitelisted、self-hashed Request whose content hashes and logical ID are independently recomputed. Attempt/process/lease are deliberately absent；execution admission is not granted、envelope is null、transport is not invoked. Response、execution envelope、Worker/transport certification and all Harness/Trial/economic authority remain future gates.

R4.109 adds **Runner-owned Worker Response v10 Contract v1** without producing a Response. The builder embeds R4.108 and freezes the response field whitelist、ten-field Request echo、typed DecisionOutput/trace hashes and Response self-hash. The descriptor carries zero instances；even a schema-valid candidate is only an unadmitted Worker claim until execution-envelope、reproducibility、Schedule and Harness Receipt admission. Transport/Harness remain forbidden and the v9 Response/Receipt path is unchanged.

R4.110 adds **Runner-owned Attempt-bound Execution Envelope v1** without dispatch. The builder selects one R4.109 logical Request, binds both Replay Execution Request and Worker Request hashes to an exact Control Plane Attempt Lease, and distinguishes worker authority from OS process identity. Renewal requires immutable Attempt fields plus a higher generation and non-regressing heartbeat, producing a predecessor-linked successor；retry under a new Attempt produces a new root with the same logical ID. Lease freshness at dispatch、transport、Response/process receipts and all execution/economic authority remain future gates.

R4.111 adds **Runner-owned Dispatch Lease Admission v1** without dispatch. The builder compares an R4.110 Envelope with the Control Plane current Attempt Lease at one `observed_at`, requires exact Attempt/worker/generation/hash equality, and applies the half-open `[heartbeat_at, lease_expires_at)` window. A renewal invalidates the old Envelope for admission even before its old expiry；a retry requires a new root. This is freshness-only evidence from a Control Plane observation, not independent clock proof or process/transport/Response authority.
