# Replay Data Adapter

Owns normalized Replay input admission: manifest/ref/content-hash binding, RFC 3339 UTC and OHLC invariants, instrument lifecycle, point-in-time universe declaration, closed-bar grid/gap detection, exact funding-event ordering, executable-window selection, evidence-window slicing, contiguous venue-risk/instrument-spec epoch schedules, and supplemental signal-time revision selection. Epochs are ordered half-open intervals; gaps, overlaps, unavailable snapshots, symbol/venue drift, incomplete window coverage, and schedule-hash drift are rejected. The active snapshot at timestamp `t` is resolved before any SourceEvent at `t`.

It consumes immutable data already selected by Control Plane governance. Supplemental records require canonical payload hashes, per-source sequence order and group-local monotonic availability; the view at `signal_time` contains only the last visible revision, while future revisions remain lineage-only. A frozen Requirement Set defines non-overlapping exact input scopes, minimum visible counts and freshness; every supplied revision must match exactly one scope, and missing, stale, window-external, undeclared or multiply matched inputs fail before SourceEvent production. Invalid identity, impossible or future-to-manifest availability, pre-listing/post-delisting facts and hash drift are rejected; admissible grid gaps, incomplete instrument history and survivor-only universes become Result limitations. Instrument accounting remains one full-window invariant even when provenance snapshots change. It does not derive requirements, collect historical venue rules, choose datasets, repair gaps silently, recompute a predeclared Signal, match orders, or make review decisions.
