# Replay Data Adapter

P1.5 adds a standalone non-economic L2 source adapter. It consumes one owner-pinned compacted-epoch descriptor plus bounded Parquet rows, verifies source identity、frame index、raw payload SHA-256、normalized `E/T/U/u/pu` fields、predecessor linkage and first/last coverage, then emits a self-hashed bounded batch. Non-zero offsets require the preceding row; missing frames、time/update reversal、cross-epoch rows or incomplete bounded reads fail closed. `runner_compatibility=not_bound` and `economic_authority=none` remain fixed: this does not modify Dataset Manifest、SourceEvent、Runner、Engine、Fill or Artifact semantics.

M4-P29 slice 1 adds a standalone bar-link materializer. It revalidates the immutable ReplayMarketBar、Kline Source Record and Aggregate Trade Coverage/Event set, requires exact half-open window and PIT chronology, contiguous aggregate and underlying trade ids, and exact open/high/low/close、base/quote/taker-buy volume and underlying trade-count reconciliation. It returns only the self-hashed non-economic Bar Link Attestation；missing、drifted or boundary-inconsistent evidence fails closed. It does not call `prepareReplayInputData`, create production SourceEvents, enter Runner/Engine, or authorize Fill、Ledger、Result、Artifact、queue、partial-fill、slippage or impact semantics.

Owns normalized Replay input admission: manifest/ref/content-hash binding, RFC 3339 UTC and OHLC invariants, instrument lifecycle, point-in-time universe declaration, closed-bar grid/gap detection, exact funding-event ordering, executable-window selection, evidence-window slicing, contiguous venue-risk/instrument-spec/instrument-status epoch schedules, and supplemental signal-time revision selection. Epochs are ordered half-open intervals; gaps, overlaps, unavailable snapshots, symbol/venue drift, incomplete window coverage, and schedule-hash drift are rejected. The active snapshot at timestamp `t` is resolved before any SourceEvent at `t`.

It consumes immutable data already selected by Control Plane governance. Instrument-status provenance must be produced by the `market-data-products` domain and independently hash-bound by Request/Reservation；`complete_history` requires an archive source, complete window coverage, immutable raw-source identity and exact derived-schedule hash。Current or periodic snapshots remain `current_snapshot_only` even when every sampled observation says trading. Supplemental records require canonical payload hashes, per-source sequence order and group-local monotonic availability; the view at `signal_time` contains only the last visible revision, while future revisions remain lineage-only. A frozen Requirement Set defines non-overlapping exact input scopes, minimum visible counts and freshness; every supplied revision must match exactly one scope, and missing, stale, window-external, undeclared or multiply matched inputs fail before SourceEvent production. Invalid identity, impossible or future-to-manifest availability, pre-listing/post-delisting facts and hash drift are rejected. A strict decision lookback rejects grid gaps and a terminal bar that does not close exactly at decision time. Every decision and frozen earliest-executable boundary must resolve to `trading`；每根 bar 的完整 `[open, close]` 不得穿越 `halted` epoch。A missing exact earliest-executable bar returns typed `dataset-grid-gap-in-execution-window` before Fill；普通 post-entry gap 由 Engine fencing。仅当 complete PIT schedule 证明 `[previous.close, next.open)` 全程 halted 且 `next.open` 已恢复交易时，该缺 bar 区间可安全跳过 continuity failure。No layer repairs, forward-fills, synthesizes or treats a missing interval as an observed open-price gap. Incomplete instrument history and survivor-only universes remain explicit limitations. Instrument accounting remains one full-window invariant even when provenance snapshots change. It does not derive requirements, collect historical venue rules, infer halt from absent bars, choose datasets, recompute a predeclared Signal, match orders, or make review decisions.

R4.53 provides a Store/Provider producer path, but Adapter still consumes only its frozen output；it never queries the provider or treats the imported archive finality assertion as a venue signature or external completeness proof.

R4.80 adds a standalone pre-integration cross-source normalizer. It preserves Instrument Status `effective_at/observed_at`、Funding event time、Aggregate Trade `trade_time/available_at` and OHLCV open/close visibility without collapsing effective and available time. It validates each source's native order and content hash, emits an explicit source rank, then publishes a self-hashed ordered envelope and ambiguity groups. Equal timestamps across sources are deterministic but `resolution_limited` because no venue-global sequence exists. This path is not called by `prepareReplayInputData` or Runner and cannot create SourceEvent、Fill、Ledger、Result or Artifact authority.

R4.82 adds an Admission-bound, hash-only SourceEvent projection seam. The Adapter validates the actual Control Plane Ordering Admission and its exact Ordering Attestation, then emits one non-economic projection per ordered envelope while preserving source kind、projected kind、native id/sequence、effective time、availability、payload/envelope hashes and the full cross-source key. It rejects admission/hash/lineage drift and carries `resolution_limited` without upgrading deterministic tie-break into venue order. The projection explicitly does not conform to the current production `ReplaySourceEvent`; payload materialization、Aggregate Trade Engine consumption、Request/Runner binding and economic execution remain unimplemented.

R4.84 adds the Projection-bound Wire v2 materializer. It rebuilds the exact Ordering Attestation from the supplied canonical four-source payload collections before pairing each payload with its hash-only projection；missing、extra、mutated or reordered payloads fail before a Wire Manifest is returned. The adapter also emits a separate legacy parity attestation only when the actual legacy SourceEvent schedule matches every shared Instrument Status、Funding and OHLCV boundary one-to-one. This certifies schedule correspondence only；legacy payload、EventKey、cross-source collision order、Aggregate Trade consumption and Runner authority remain unasserted.

R4.85 adds a self-hashed pre-execution gate over the exact Wire Manifest and Ordering Attestation. `non_economic_schedule_trace` is the sole admitted capability；`economic_exact_trigger` is always rejected, with a distinct reason for `resolution_limited` ordering versus an otherwise exact declared-timestamp schedule whose economic consumer is still uncertified. The gate cannot mint Control Plane admission or Runner authority.

R4.96 adds the non-economic Decision Observation Harness Context Binding builder. It revalidates Request v30、Control Plane Derivation Admission and the admitted Bundle, then derives the existing canonical Harness Context v7 for every frozen Schedule entry and binds it one-to-one to Projection/Binding/Cut/View lineage. It neither materializes Decision Input snapshots nor invokes Worker/Harness/Runner；supplemental、market、state and Worker Request compatibility remain explicitly unbound.

R4.97 adds the non-economic Decision Observation Input Materialization builder. It fully rebuilds the R4.96 binding against Request、Bundle and Derivation Admission, validates Dataset Manifest schema plus Request identity, emits canonical empty supplemental snapshots for `mode=none`, and selects closed-bar market lookbacks from admitted Projection payloads through the existing formal snapshot constructors. It does not re-read raw dataset content, materialize runtime State/non-empty supplemental inputs, create a Worker Request, invoke Harness, or enter Runner.

R4.98 adds a separate Initial Signal Supplemental Input Materialization builder. It accepts only non-empty `signal_time_complete` input, fully binds Request and Dataset Manifest declarations to the supplied revision stream, rejects late-to-manifest、undeclared、multiply matched、missing or stale facts, selects the last PIT-visible revision per fact group, and emits a portable formal Decision Input Snapshot plus selected/future/evaluation hashes. Its scope is the authorized initial signal only；it is not part of the four-source Market Wire and does not certify rolling joins、Worker Request、Harness invocation or Runner admission.

R4.99 adds the non-executing Decision Worker Input Assembly builder. It validates parent self-hashes and exact cross-object Request/context/entry bindings, then emits one tuple-status entry per Context boundary. Empty supplemental may consume R4.97 and become complete except for position-open runtime State；non-empty initial-signal input consumes R4.98 and remains explicitly incomplete until a same-Request Market materialization exists. It never accepts a bare replacement snapshot, derives an invocation id, creates a Worker Request, invokes Harness, or enters Runner.

R4.100 adds the independent Decision Market Input Materialization builder and extracts one shared closed-bar selector from R4.97 without changing R4.97 semantics. The builder fully rebuilds R4.96 lineage, validates Dataset market identity, and emits formal empty or closed-bar-lookback Market Snapshots for any valid supplemental mode. Supplemental completeness remains outside this component；raw Dataset content、State、Worker Request、Harness invocation and Runner admission remain unperformed.

R4.101 adds the Decision Worker Input Assembly v2 builder while retaining v1. It requires one R4.100 Market materialization and exactly one R4.97/R4.98 Supplemental parent with the same Request and Context boundaries. R4.97 embedded Market must exactly equal R4.100 before selection；R4.98 can now produce a complete non-executable initial-signal tuple. Runtime State、source bundle/build/invocation binding、Worker Request、Harness invocation and Runner admission remain outside the builder.

R4.103 does not move runtime assembly ownership into Data Adapter. R4.101 v2 remains this component's terminal static output；Engine alone may compose that immutable object with R4.102 runtime State into v3. Data Adapter does not receive Position/Cash state or create Worker/Harness/Runner authority.
