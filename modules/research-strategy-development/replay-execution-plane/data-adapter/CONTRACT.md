# Replay Data Adapter

Owns normalized Replay input admission: manifest/ref/content-hash binding, RFC 3339 UTC and OHLC invariants, instrument lifecycle, point-in-time universe declaration, closed-bar grid/gap detection, exact funding-event ordering, executable-window selection, evidence-window slicing, contiguous venue-risk/instrument-spec epoch schedules, and supplemental signal-time revision selection. Epochs are ordered half-open intervals; gaps, overlaps, unavailable snapshots, symbol/venue drift, incomplete window coverage, and schedule-hash drift are rejected. The active snapshot at timestamp `t` is resolved before any SourceEvent at `t`.

It consumes immutable data already selected by Control Plane governance. Supplemental records require canonical payload hashes, per-source sequence order and group-local monotonic availability; the view at `signal_time` contains only the last visible revision, while future revisions remain lineage-only. A frozen Requirement Set defines non-overlapping exact input scopes, minimum visible counts and freshness; every supplied revision must match exactly one scope, and missing, stale, window-external, undeclared or multiply matched inputs fail before SourceEvent production. Invalid identity, impossible or future-to-manifest availability, pre-listing/post-delisting facts and hash drift are rejected. A strict decision lookback rejects grid gaps and a terminal bar that does not close exactly at decision time. A missing exact earliest-executable bar returns typed `dataset-grid-gap-in-execution-window` before Fill; a pre-entry gap that lies outside every consumed decision/execution interval may remain a Result limitation. A post-entry gap is fenced by Engine if execution reaches it. No layer repairs, forward-fills, synthesizes or treats a missing interval as an observed open-price gap. Incomplete instrument history and survivor-only universes remain explicit limitations. Instrument accounting remains one full-window invariant even when provenance snapshots change. It does not derive requirements, collect historical venue rules, choose datasets, recompute a predeclared Signal, match orders, or make review decisions.
