# Replay Execution Plane Contracts

Owns the versioned Replay request, Dataset Manifest, instrument-accounting spec, market input, fill, ledger, journal, trial-balance, result, artifact, and fingerprint contracts.

## Certified Result v42 / Simulator Policy v15 capability

- Instrument-status producer implementation and normalization policy each bind both a version and a SHA-256 content hash; version labels alone are not reproducibility authority.
- One asset and one isolated position lane.
- Closed-candle signal with earliest execution at the next bar open.
- Signal-time market submission remains inert until the eligible `bar_open` SourceEvent synchronously drives activation, entry fill, and bracket activation; same-time phase-`10` funding sees the `t-` flat position.
- Append-only submitted/activated/triggered/partial-or-full-filled/cancelled/rejected order events with a strictly increasing per-order sequence and nondecreasing event time.
- Every order event carries the total-order key `(event_time, boundary_phase, source_sequence, event_subphase, stable_event_id)`; equal or backward keys are rejected.
- Trial Reservation Snapshot v9 is owned and issued by Research Control Plane. It binds the half-open new-claim window `[issued_at, expires_at)` plus Request v29 risk/spec/status/decision/entry-execution authority and nullable liquidity-capacity-attestation hash. Runner requires Dataset provenance, Request and Reservation to name the same authority before execution. Replay does not query or mutate Trial/provider registry state.
- Replay Attempt Lease v1, Attempt Cancellation/Observation v1, Checkpoint Receipt v2 and Resume Authorization Snapshot v1 are Control Plane-owned runtime boundary contracts. Artifact v44 persists Decision Evidence Timeline v9、OHLCV Resolution Evidence v3 and Pending Order Resolution v2; Run Outcome v35 carries current fencing、commit/failure state and optional cancellation/ambiguity evidence. Result/Fingerprint bind path economics plus status schedule/provenance/provider-certification identity while Checkpoint v21 remains the pre-derived resume payload. Attempt execution cancellation/checkpoint identity does not alter Result v42 economic fingerprint；contract-owned order Cancel and its optional scheduled decision evidence do.
- Artifact Store Capability v1 freezes one Attempt-scoped port contract: immutable create, full-content SHA-256 collision identity, strong read-after-write, and Manifest-last publication. The certified local snapshot requires hard-link create-if-absent plus temporary unlink. The contract-valid remote target requires conditional put with `If-None-Match: *` and abort/expiry of uncommitted uploads, but it is not an executable capability until an adapter passes the same parity and crash certification.
- Dataset Manifest v11 carries ordered PIT authority and an optional self-hashed Liquidity Capacity Attestation v1. Limit execution requires its symbol/capacity/hash to match Request v29 and Reservation v9, and `available_at <= signal_time`; Result v42 Fingerprint and Artifact v44 bind it. The attestation is a static conservative ceiling with source/derivation provenance, not event-depth or queue-position proof. Gap, coverage, authority or hash drift is a pre-event failure.
- R4.54 adds Control Plane-owned Provider Certification v1 admission and binds one receipt across Dataset Manifest、Request、Reservation、Runner and Fingerprint. Replay validates the resulting closure but does not import the provider implementation, write its store, or treat certification/source finality as venue signatures/external completeness proof.
- R4.57 adds Control Plane-owned Provider Certification Termination v1 without changing Replay wire. Revocation/supersession only fences Reservation issuance at or after its non-retroactive `effective_at`; a previously issued Reservation and its later Attempt lease remain frozen authority. Replay neither queries lifecycle state nor applies a mutable "latest certification" rule.
- R4.58 adds Control Plane-owned Reservation/Attempt Cancellation v1 without changing Replay request/result wire. Reservation cancellation fences only future claim admission; Attempt cancellation fences one exact active lease generation. Runner observes cancellation through its existing external execution-control callback and publishes no partial Result/Artifact; Replay never queries Control Plane tables directly.
- Dataset Manifest v11 also declares one immutable supplemental revision stream and the canonical hash of `Supplemental Requirement Set v1`. Decision Schedule v6 and Timeline v9 bind every exact decision time/sequence/effect, closed-bar Market Snapshot, optional open-position State Snapshot, and input/build/runtime evidence. The certified sequence may include one `authorized_entry_cancel` matching Request's immutable GTC Limit Cancel Intent；its phase is `pending_entry` and State Snapshot must be null. Existing position-open sequence remains no-action, either at most one tighten-only protective-stop replacement or one fixed-quantity partial reduce, then optionally one final full-position reduce-only market exit. Replay cannot add times, change effects, combine replacement with partial reduce, alter triggers during partial resize, or widen quantity.
- Normalized `instrument_delisted`、`instrument_halted`、`instrument_resumed`、`funding`、`mark`、`bar_open` 与 `bar_range` SourceEvents use the same key space；same-time ordering is policy/status selection then phase `00 -> 10 -> 15 -> 20`，delisting sequence precedes status transition，Result v42 persists the consumed prefix only。Supplemental facts form a signal-time input view, not market execution SourceEvents. Mark is risk/valuation evidence; only an exact maintenance breach may create the system forced-liquidation lane.
- Conditional trigger evidence binds the OHLC source class and observed trigger price.
- Market entry and full reduce-only stop or take-profit exit, with sibling cancellation and fill-to-order traceability.
- One optional final strategy exit is opposite-side market, reduce-only, and full-open-position. It is submitted at the closed-bar decision and can activate/fill only at its frozen strictly later bar open. Exact risk, stop gap, and target gap win at the same open; terminal-before-decision becomes not-reached, while a submitted losing exit is cancelled.
- One optional protective-stop replacement is opposite-side stop-market, reduce-only, full-open-position, and tighten-only. At a non-terminal closed-bar decision, the old active stop is cancelled before the replacement is submitted and activated. The replacement must remain on the protective side of the target and must not already be crossed by the decision close; it cannot retroactively trigger inside that bar.
- Composition certification does not add a new wire capability: after replacement, the replacement stop is the sole stop authority. A later strategy-exit Fill cancels that stop and the target; an exact maintenance breach cancels the current stop, target, and any pending strategy exit before the forced Order; a stop Fill cancels the target and pending strategy exit. Every path permits exactly one terminal Fill, and checkpoint resume preserves the same owner/order transitions without re-evaluating committed position-open decisions.
- Direction-symmetry certification mirrors prices around a fixed center: long stop tightening upward maps to short stop tightening downward; mirrored entry/stop Fills produce equal signed PnL/return and identical OrderEvent phase/subphase sequences. If the post-replacement OHLC range touches both current stop and target, both sides select the stop-first conservative path and must publish `ohlcv-stop-target-collision` with `resolution_limited`. This is the certified simple-bracket envelope, not proof of the actual intrabar path or a generic multi-order OHLC resolver.
- OHLCV Resolution Evidence v3 binds each stop/target terminal to SourceEvent/bar、active protection、P1/P2 outcome and cost-aware economics. Every path records frozen-policy adverse execution price、gross realized PnL、exit fee 与 net terminal contribution；the impact envelope records min/max/span/canonical shortfall and explicitly excludes common cashflows. Runner recomputes it from Request、Dataset accounting and entry Fill, then binds canonical price/fee to the actual terminal Fill. Artifact v44 publishes it separately. It is not a full counterfactual equity interval or path probability.
- A terminal market SourceEvent synchronously drives the certified exit-order lane; trigger/fill/sibling-cancel EventKeys remain causally bound to that source boundary.
- Conservative stop-first same-bar collision; stop/TP gap triggers at the observed bar open, then applies adverse slippage.
- `Pending Order Resolution v2` is self-hashed. Request v29/Simulator v15 certify pre-entry `limit + gtc|ioc`: GTC 从 next-open 起逐 `bar_open/bar_range` 观察，open-marketable/strict-cross 在 attested capacity 内全成，touch 不成；数据边界仍无 Fill 时以 active Order 和 `unfilled_at_data_end` 完成。IOC 只观察 earliest-executable `bar_open`，marketable 则全成，否则 resolution 与独立 OrderEvent 都为 `expired`，Result 为 `expired_unfilled`。Fill/expiry EventKey 严格晚于 decisive SourceEvent。ordered resolution chain enters Checkpoint v21、Result v42 and Artifact v44.
- `ReplayEntryCancelIntent v1` 由不可变 Experiment Contract 拥有，只能绑定 pre-entry GTC Limit，且 `requested_at=signal_time`、`effective_at>earliest_executable_time`。R4.74 fixed-intent compatibility 可直接使用；R4.75 可选 Schedule v6 `authorized_entry_cancel`，必须逐字段/哈希匹配同一 Intent。Harness Context v7 的 `pending_entry` 只消费 effective closed-bar Snapshot，State Snapshot 为 null；更早 Fill 以 Fill EventKey 记 not-reached 且不运行 Harness。指定 range SourceEvent phase `20` 先于 Cancel phase `90`：strict-cross Fill 胜；确定未触达时生成 `cancelled` OrderEvent 与 `cancelled_unfilled`；exact touch typed-fail，缺 boundary data-integrity fail，均无 Result/Artifact。未冻结运行时 Cancel、IOC Cancel、FOK/GTD、amend/cancel-replace、multi-order volume allocation、partial liquidity 与 Stop pending integration remain unsupported.
- An observed open-price jump between contiguous bars is a market gap and retains `worse_open`. A missing interval-grid bar is unavailable evidence, not a price observation: missing frozen entry fails before Fill; a reached post-entry gap fails at the prior observed close before any later SourceEvent or checkpoint. `ReplayDataGapFailureEvidence` binds kind, exact bounds, interval, count, and `fail_before_unobserved_interval_effects`. Run Outcome v35 publishes this non-retryable `data_integrity` failure without Result/Artifact. A terminal consumed prefix ending before a future gap remains unchanged.
- A no-bar interval is exempt from that failure only when the complete PIT status schedule proves the entire half-open interval halted and the next observed open is already `trading`. Every decision/effective execution boundary and every supplied bar must resolve wholly to `trading`. During halt, active protection remains pending and Funding/Mark may still mutate ledger/risk; strategy/market fills are forbidden. An exact maintenance breach while halted is typed failure with a non-authoritative breach observation, never a synthetic liquidation Fill or partial Result.
- Per-fill fee/slippage and exact timestamp funding events.
- Every Fill carries the exact filled OrderEvent key; fee/realized-PnL ledger facts reuse the causal Fill key, funding reuses its SourceEvent key, and initial/ending snapshots use explicit phase-`70`/`100` checkpoint keys.
- Every certified Fill produces a post-fill Position Projection with the same EventKey. The Runner now permits one fixed-quantity partial reduce that leaves the Position open; its fee/realized PnL enter the causal ledger, later Funding and Margin use remaining quantity, and the next State Snapshot exposes the resized Position/protection. This does not certify exchange-liquidity partials, multiple partials, add/reversal, or wider matching.
- Dataset Manifest v11 binds the full-window linear-derivative accounting spec, its PIT provenance/status schedules, supplemental/capacity declaration, and an explicit Mark capability. `mark_coverage=none` requires no Mark data; `complete_grid` requires exact event-time availability, strict timestamp/source-sequence order, full endpoint/grid/count coverage, tick alignment, and content-hash binding. Partial or lagged Mark streams are rejected rather than treated as exact.
- Result v42 binds Margin v7、Journal v5、Equity v3、typed entry outcome、ordered pending-order resolutions、Decision Timeline v9 and nullable liquidity-capacity-attestation hash. Request v29 freezes exact-risk liquidation、GTC/IOC Limit entry assumptions and optional contract-owned GTC Cancel；GTC data-boundary、IOC expiry and proven-nonfill Cancel are completed zero-execution Results, while ambiguous touch、OHLCV/halted maintenance breach remain Run Outcome v35 failures without Result.
- `rd-replay-number-v3` converts admitted finite number values into decimal coefficients, performs bps adjustment, notional fee, funding, linear PnL, weighted-average and return division as BigInt rationals, then quantizes once: quantity floors to step; buy execution price ceils and sell price floors to tick; fee expense ceils; signed funding/realized cashflow floors toward negative infinity; weighted average and return use half-away-from-zero at 12 decimal places. Stop/target, OHLC, initial cash, Fill, Position, Ledger and Journal facts must align. Shared language-neutral vectors are independently certified by Bun/BigInt and Python Decimal; this proves arithmetic-policy parity, not arbitrary JSON parser or unbounded-decimal transport equivalence.
- Deterministic Result Artifact and complete identity fingerprint, including numeric, journal, equity, and margin policy hashes/versions.
- Manifest-bound content hash, RFC 3339 UTC timestamps, explicit instrument lifecycle, universe survivorship, observed-through and bar/funding/mark availability policy.

At EOD, Simulator v15 marks an open Position without synthetic Fill；a still-pending GTC Limit publishes an authoritative zero-execution Result while preserving the active Order. An unfilled IOC publishes its TIF-owned expiry at the sole first-open observation；a contract-cancelled GTC binds the exact post-range Cancel key、closed-bar valuation source and optional evaluated Harness receipt. None invents an external cancellation or settlement. Generic runtime cancel/amend/cancel-replace、IOC partial remainder、FOK/GTD、stop loosening、multiple partials、真实 queue/depth partial、multi-entry/reversal、halt settlement、partial liquidation、cross/shared margin and fast mode remain unsupported.

## Certified fixed-quantity partial reduce

`trade.rd-replay-partial-reduce-intent.v1` freezes one opposite-side market reduce-only fixed quantity, strictly smaller than executable entry quantity and increment-aligned. At its strictly later eligible open, risk/stop/target retain priority. If not preempted, Simulator fills the partial Order at phase `20`, then at phase `90` cancels both current protection Orders and submits/activates replacements at unchanged trigger prices for exactly `abs(post-fill position)`, with no intervening SourceEvent. A terminal owner before execution cancels the pending partial Order. Schedule v5 rejects a second partial or any protective-stop replacement in the same run, but permits one later final full exit. Checkpoint v17 preserves pending/filled partial Order、partial Fill、rebuilt bracket generation 与 consumed halt/resume prefix，并以冻结 Intent、最后 OrderEvent 与确定 protection identity/trigger/quantity 重验其语义；clean/resume parity is mandatory.

The certified Manifest can prove frozen halt/resume history but still does not prove a delisting settlement price. An open position reaching delisting therefore produces a non-retryable typed failure with the terminal EventKey and publishes no partial Result; the engine never invents a terminal fill.
