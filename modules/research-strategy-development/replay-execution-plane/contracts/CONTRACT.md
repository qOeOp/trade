# Replay Execution Plane Contracts

Owns the versioned Replay request, Dataset Manifest, instrument-accounting spec, market input, fill, ledger, journal, trial-balance, result, artifact, and fingerprint contracts.

## Certified Result v22 / Simulator Policy v7 capability

- One asset and one isolated position lane.
- Closed-candle signal with earliest execution at the next bar open.
- Signal-time market submission remains inert until the eligible `bar_open` SourceEvent synchronously drives activation, entry fill, and bracket activation; same-time phase-`10` funding sees the `t-` flat position.
- Append-only submitted/activated/triggered/partial-or-full-filled/cancelled/rejected order events with a strictly increasing per-order sequence and nondecreasing event time.
- Every order event carries the total-order key `(event_time, boundary_phase, source_sequence, event_subphase, stable_event_id)`; equal or backward keys are rejected.
- Trial Reservation Snapshot v5 is owned and issued by Research Control Plane. It binds the half-open new-claim window `[issued_at, expires_at)` plus Request v15 risk/spec schedule, supplemental-facts and supplemental-requirement-set hashes; expiry closes fresh/retry/resume-target admission but does not revoke an Attempt claimed inside the window. Runner validates identity, claim window, exact execution-spec hash, dataset/policy/harness hashes and the complete certified capability set before cancellation, idempotency lookup, engine execution or artifact publication. Replay does not query or mutate Trial state.
- Replay Attempt Lease v1, Checkpoint Receipt v2 and Resume Authorization Snapshot v1 are Control Plane-owned runtime authorities. One active Attempt per Trial, heartbeat generation fencing, append-only monotonic checkpoint receipts, expiry takeover, terminal compare-and-set, and latest-receipt-to-target-Attempt authorization are state-store invariants. Artifact v24 persists the storage policy, actual producer lease, complete supplemental revision stream, nullable Decision Harness Source Bundle/Build Attestation, Decision Input Snapshot, nullable Harness Receipt and complete per-Attempt file set; Run Outcome v19 carries the latest accepted lease generation, accepted resume authorization hash when present, typed Reservation-expiry/Harness rejection, and either its authoritative Artifact commit or non-authoritative Diagnostic Checkpoint Commit v2. The Manifest, both commits, and Receipt v2 bind `rd-replay-local-fsync-link-cas-v1`; this proves only the certified local filesystem protocol. Attempt/checkpoint/receipt/authorization identity does not alter Result v22 economic fingerprint; Decision Bundle/Build/Snapshot/Receipt do.
- Artifact Store Capability v1 freezes one Attempt-scoped port contract: immutable create, full-content SHA-256 collision identity, strong read-after-write, and Manifest-last publication. The certified local snapshot requires hard-link create-if-absent plus temporary unlink. The contract-valid remote target requires conditional put with `If-None-Match: *` and abort/expiry of uncommitted uploads, but it is not an executable capability until an adapter passes the same parity and crash certification.
- Dataset Manifest v7 carries non-empty, ordered, contiguous venue-risk and instrument-spec schedules with half-open validity. Request v15 and Result v22 fingerprint bind canonical schedule hashes; the instrument hash covers spec epochs plus the full-window accounting spec. The active epoch at `t` is selected before every SourceEvent at `t`; entry Request risk parameters must match the entry epoch, while each later Margin/liquidation calculation uses and records its event-time risk snapshot. Gap, overlap, incomplete coverage, unavailable epoch, symbol/venue drift or hash mismatch is a pre-event failure. Multiple spec provenance epochs are supported only while accounting fields remain invariant. This is frozen-input verification, not automatic historical venue reconstruction.
- Dataset Manifest v7 also declares one immutable supplemental revision stream and the canonical hash of `Supplemental Requirement Set v1`. The Control Plane-derived set freezes non-overlapping required scopes and `undeclared_input=reject`; the signal-time join and future-revision invariant remain unchanged. A `signal_time_complete` run binds Request `harness_hash` to Source Bundle v1. Registry Capability v2 independently rebuilds Build Attestation v1: Bun metafile inputs equal Bundle+generated worker, output has no residual import, and attestation binds fixed args, artifact bytes/hash, Bun version/executable hash and Worker Protocol v1. Runner materializes exact bytes and executes a fresh-subprocess reproducibility pair under fixed environment, 5s timeout and 1 MiB output cap; both responses must be canonical equal. Capability/Receipt v3 bind primary/verification response hashes and authorized Order. Unknown/tampered/forged bundle/build/runtime/policy, nondeterministic response or Order mismatch fails before Engine; idempotent reads execute zero workers. This is a deterministic source-to-artifact/process protocol, not an OS sandbox, filesystem/network denial, signed provenance or arbitrary dependency SBOM; dynamic multi-decision feature execution remains unsupported.
- Normalized `instrument_delisted`, `funding`, `mark`, `bar_open`, and `bar_range` SourceEvents use the same key space; same-time ordering is policy epoch selection then phase `00 -> 10 -> 15 -> 20`, and Result v22 persists the consumed prefix only. Supplemental facts form a signal-time input view, not market execution SourceEvents. Mark is risk/valuation evidence; only an exact maintenance breach may create the system forced-liquidation lane.
- Conditional trigger evidence binds the OHLC source class and observed trigger price.
- Market entry and full reduce-only stop or take-profit exit, with sibling cancellation and fill-to-order traceability.
- A terminal market SourceEvent synchronously drives the certified exit-order lane; trigger/fill/sibling-cancel EventKeys remain causally bound to that source boundary.
- Conservative stop-first same-bar collision; stop/TP gap triggers at the observed bar open, then applies adverse slippage.
- Per-fill fee/slippage and exact timestamp funding events.
- Every Fill carries the exact filled OrderEvent key; fee/realized-PnL ledger facts reuse the causal Fill key, funding reuses its SourceEvent key, and initial/ending snapshots use explicit phase-`70`/`100` checkpoint keys.
- Every certified Fill produces a post-fill Position Projection with the same EventKey. Accounting separately certifies ordered multi-Fill net average-cost add/partial-reduce/reversal projection and a cash reducer that merges causal fee/realized-PnL/funding facts. The current Runner permits one non-reduce entry followed by a full reduce-only stop/target close or an open EOD terminal Position; it does not expose wider matching until position-at-funding paths reach parity.
- Dataset Manifest v7 binds the full-window linear-derivative accounting spec, its PIT provenance schedule, supplemental declaration, and an explicit Mark capability. `mark_coverage=none` requires no Mark data; `complete_grid` requires exact event-time availability, strict timestamp/source-sequence order, full endpoint/grid/count coverage, tick alignment, and content-hash binding. Partial or lagged Mark streams are rejected rather than treated as exact.
- Result v22 binds Margin v7 and Journal v4. Request v15 freezes exact-risk full liquidation, forced-order priority, trigger-Mark adverse execution, full quantity, independent liquidation fee, and deficit rejection; event-time venue-risk epoch supplies maintenance parameters and liquidation fee. Exact breach embeds Liquidation Execution v2 plus Observation v3 with snapshot provenance and `execution_status=simulated_full_close`; OHLCV breach returns Run Outcome v19 failure evidence with `not_simulated`. Observation is never itself a Result or Fill.
- `rd-replay-number-v3` converts admitted finite number values into decimal coefficients, performs bps adjustment, notional fee, funding, linear PnL, weighted-average and return division as BigInt rationals, then quantizes once: quantity floors to step; buy execution price ceils and sell price floors to tick; fee expense ceils; signed funding/realized cashflow floors toward negative infinity; weighted average and return use half-away-from-zero at 12 decimal places. Stop/target, OHLC, initial cash, Fill, Position, Ledger and Journal facts must align. Shared language-neutral vectors are independently certified by Bun/BigInt and Python Decimal; this proves arithmetic-policy parity, not arbitrary JSON parser or unbounded-decimal transport equivalence.
- Deterministic Result Artifact and complete identity fingerprint, including numeric, journal, equity, and margin policy hashes/versions.
- Manifest-bound content hash, RFC 3339 UTC timestamps, explicit instrument lifecycle, universe survivorship, observed-through and bar/funding/mark availability policy.

The lifecycle component certifies deterministic partial quantity transitions and reduce-only caps; the market-data kernel does not claim real historical liquidity partials. At EOD, Simulator v7 cancels the bracket, creates no synthetic Fill, preserves the open Position, and uses the final exact Mark when certified, otherwise closed-bar close. Exact-risk liquidation is full-close only. Grid-interior paths, limit queue, amend/TIF, multi-entry/reversal, dynamic collateral, partial liquidation, deficit/insurance/ADL, cross/shared margin, and fast mode remain unsupported.

The certified Manifest only proves `delisted_at`, not halt/resume history or a settlement price. An open position reaching delisting therefore produces a non-retryable typed failure with the terminal EventKey and publishes no partial Result; the engine never invents a terminal fill.
