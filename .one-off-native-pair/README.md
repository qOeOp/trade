# Native packaging pairing harness v3

Prepared only. No native replay, Docker call, CI dispatch, host or venue operation has been performed by the preparation lane.

The small harness has three roles: `generator.py` extracts and transforms the existing `PROBE` and `TieredEntry` fixtures using AST, `run_pair.py` creates isolated state and invokes the product CLI, and `verify_pair.py` reads the resulting evidence. `baseline.json` pins the unchanged engine, lock and fixture inputs read at e03. The host runtime checkout itself is required to equal the actual candidate image's CI build revision, which can be a PR merge SHA.

Only the following execution files are intended for a disposable CI branch: `generator.py`, `run_pair.py`, `verify_pair.py`, `test_offline.py`, `baseline.json`, and this README. They contain transformations of existing repository fixtures, not a complete strategy body. **Do not commit `generated-sources/`, any receipt, market, run or verification artifact.** Complete source files are generated only in `/tmp`/`RUNNER_TEMP`.

`run_pair.py` creates an empty Docker config in its own `work/` directory and fixes the Docker endpoint to `unix:///var/run/docker.sock` for its allowlisted child environment. It reads no default Docker config, `.env`, trading key or default ledger profile. Every ledger write uses the original CLI. The temporary ledger's own service is stopped through `ledger service stop` on success or failure; old processes/artifacts are untouched. No deletion of evidence is implemented.

Upload **only `$RUNNER_TEMP/native-pairing/evidence/`**, with `if: always()`. This includes complete generated engineering sources, their SHA manifest, input file hashes, native reports/audits/fingerprints, actual trial-start receipts, CLI stage outputs and verification results. Do not upload `work/` (database, temporary profile, service metadata, empty Docker config, private initialization output). No environment dump is written.

The child `TMPDIR` is the whole new output root so the product admits both `work/` and `evidence/` under GitHub's non-`/tmp` temporary path. Derived export caches may therefore be siblings of those directories; upload none of them.

## v3 closure of the native schema false rejections

The complete generated source files, generator, and baseline remain **byte-for-byte v2**. The passive diagnostic schema is still `pairing-clock-v2`; no source branch, trading rule, diagnostic callback or stop declaration changed. v3 changes only verifier expectations, a pure BarType/version precondition, the synthetic test controls and this documentation. The runner checks that pure value precondition before creating any workspace/service. The independently rerunnable verifier checks it too.

Pinned rc7 emits `...-15-MINUTE-LAST-INTERNAL`, while the original Probe keeps a composite `self.quarter` ending `@1-MINUTE-EXTERNAL`. Native Standard and Composite values are unequal. Therefore the unchanged `if bar.bar_type == self.quarter` branch is never entered by emitted internal bars. The bracket-placement branch is **not covered by Probe**. Probe covers external/internal clocks, native periodic and alert timers, timer-driven market activity, fees, funding and account economics; `USES_STOP_LOSS=False` remains explicit. Protection independently covers partial entry, GTD expiry, surviving stop, target cancellation and flatness.

Every emitted internal bar at/after trade start falls through to `self.n += 1`. Thus the fixed two-day Probe window has 2,880 external-minute callbacks, of which 2,875 are post-trade, plus 191 internal callbacks, and the unchanged source counter must be 3,066. The verifier retains the actual ordered bar callback sequence to derive each `A-<instrument>-<n>` on the 41st counted callback and its exact `bar.ts_event + 90_000_000_007` deadline. It requires every such alert through the final input time, not a single example. Periodic `T-<instrument>` events must match every `start + k*(37 minutes + 13 microseconds)` through that same horizon. The full event/init/callback causal checks remain intact.

First and last internal bar requirements are derived independently from the declared input window, **never from the observed trace's own edges**. The current Probe starts exactly at 2026-01-01 00:00 UTC and ends at 2026-01-03 00:00 UTC. Its first input is funding at start; its last input is the minute/MARK at end minus 1 ms. Native startup registers aggregation before the first data, with the clock already at start. The immediate start-boundary timer has no initialized bar builder, so no bar is emitted then. The first full close is start plus 15 minutes. The final streaming batch supplies no explicit end; rc7 sets the run boundary to the last input timestamp, and `end()` flushes only through that boundary. Consequently the END-aligned bar is not emitted. v3 requires all **191** standard internal bars from start+15m through end−15m (Jan 1 00:15 through Jan 2 23:45); deleting any first, last or middle bar fails even if the source counter and alerts are rewritten consistently.
