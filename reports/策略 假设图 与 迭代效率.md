# 把策略分叉变成可检验的研究
> 归档研究材料：本文保留起稿时判断；仓库内证据链接固定在提交 `163478559`。后续实现与效能试验以正式记录为准。

**结论：你的方法有价值，但价值在于把策略研发变成有来源、可比较、可回退的假设搜索，而不是蜂窝形状本身。** 学术界分别研究了研究来源图、组件筛选与交互实验、以及反复回测造成的选择偏差；这些成果支持“从 origin 分叉、保留失败、再有理由地融合”，却没有证明蜂窝布局能提高量化策略成功率。最重要的修正是把“假设如何延伸”“源码实际从哪里来”“哪次原生运行检验了它”“哪个运行是合法经济对照”分开记录。`A1B1C8G14` 可以是人看的昵称，不能承担身份和血缘。效率来自每次测试能排除或支持一个清楚的机制，并在昂贵回放前先过便宜门槛；最终效益要分别测检索与决策质量，以及此前未暴露数据上的真实策略资格。当前 Trade 的五条历史尝试、两次运行侧录只证明小样例可以读回，尚未测得效率或收益增量。

## 论文支持保留研究谱系，未证明蜂窝布局有效

**来源与假设演化已有严肃的模型和软件先例。** W3C PROV-DM 区分实体、活动、使用、生成、派生和修订，并强调“活动使用了旧实体且生成了新实体”本身不足以断定两者存在派生关系。这直接提醒我们：A 的源码从 origin 分支、A 的经济假设受 origin 启发、A 的回放与 origin 对比，是三种不同事实。DISK 研究展示了新数据到来后重新检验和修订科学假设并保留来源的工作流；VisTrails 保留计算实验的参数变动、分支和运行历史。这些是研究脉络可实现的依据，既非金融样本外收益证据，也非蜂窝 UI 的效果试验。([W3C PROV-DM](https://www.w3.org/TR/prov-dm/); [Gil 等，DISK](https://ojs.aaai.org/index.php/AAAI/article/view/11157); [VisTrails 用户手册](https://www.vistrails.org/usersguide/v1.7/html/intro2.html))

**量化研发最危险的是只留下最后一个好看的格子。** White 的 Reality Check 和 Hansen 的 SPA 处理从一批候选中选优后的基准比较；Bailey 等的 PBO/CSCV 评估样本内被选中者在样本外排名失效的风险；DSR 考虑多次尝试、Sharpe 估计误差与非正态性。它们的共同前提是知道候选集合及同口径表现，而非只知道赢家。Dwork 等还证明：根据前次结果不断提出新分析，会让反复查询的 holdout 也被过拟合。因此 A、B、A1、A1B、参数扫掠、手工淘汰的组合和无订单结果都要进入试验清单；不能通过删掉失败蜂窝、改名字或登记下一条假设，把已看过的年度重新变成“独立测试”。([White，2000](https://doi.org/10.1111/1468-0262.00152); [Hansen，2005](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=264569); [Bailey 等，PBO](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf); [Bailey 与 López de Prado，DSR](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf); [Dwork 等，2015](https://arxiv.org/abs/1506.02629))

## 来源保持多父无环，知识引用可以有环

**origin→A/B→A1→A1B 是合理的多父来源图；“再回到旧想法”要生成新节点。** 每个已经提出或测试的候选有一个稳定、无语义的 `attempt_id`，另有可改的 `alias=A1B`。A1B 的假设关系可以同时指向 A1 与 B：一条说明保留 A1 的什么机制，另一条说明引入 B 的什么机制；两条都须写明预期改善、可能冲突以及什么观察会否定组合。若代码实际以 A1 的源码为基底，`code_parent` 只指向那个源码身份，B 机制的引入由源码差异和假设边说明。`run_id` 再指向实际执行的源码摘要、输入身份、Nautilus 版本、窗口、成本、共享账户、原生报告及证据等级；`control_run_id` 单独表示冻结的经济对照。一次假设可被多次运行，一份源码也可被不同问题复用，故不能把这些节点和“父亲”压成一个字段。W3C 的来源顺序约束和 AiiDA 将因果数据血缘与更丰富的 workflow 逻辑链接区分的实践，支持这样的分层。([W3C PROV 约束](https://www.w3.org/TR/prov-constraints/); [AiiDA 来源图概念](https://aiida.readthedocs.io/projects/aiida-core/en/stable/topics/provenance/concepts.html))

**有环的是研究者的知识关联，不应是版本产生顺序。** 新节点 R 可以 `revisits=A`，表示在新数据或新机制下重试旧想法；另一条结论可以 `challenges` 旧结论，但要注明争议只对哪个时间窗、成本和账户口径成立。引用、比较、反驳关系可以互相指向并形成环；实际衍生与运行产生的因果顺序仍为 DAG。若 A1B 后又吸收 C8，建立新节点、保存两个来源和真正变更，不要回写 A1B 或把祖先序列塞进 `A1B1C8G14` 唯一键。长名字无法表达多父贡献、同一候选多次运行、旧结论被更正及跨线复用。图界面只应按查询展示局部谱系、差异和证据状态；来源图研究已经指出全图会带来 provenance overload。([Anand 等，来源图导航](https://www.cs.ucdavis.edu/~ludaesch/pubs/Navigation-model-WORKS-2009.pdf); [DVC 实验比较的 only-changed 视图](https://doc.dvc.org/user-guide/experiment-management/comparing-experiments))

现有 Trade 试点已用 Git 内 `attempt.json`/`run.json`、`parents[]`、`code_parent` 和 `control_run_id` 表达部分关系；下一步是验证“多父贡献、回访、反证”在真实决策中的查询价值，而非先换图数据库。DVC、MLflow 与 Qlib 提供运行、参数和产物比较的产品参考，但其代码基线或 run 层级不能自动解释假设贡献；Trade 仍应让 Strategy 源码与 Nautilus 原生订单、资金费、成交和共享账户报告充当执行事实。([DVC 实验管理](https://doc.dvc.org/user-guide/experiment-management); [MLflow run 搜索](https://www.mlflow.org/docs/latest/ml/search/search-runs/); [Qlib Recorder](https://github.com/microsoft/qlib/blob/main/docs/component/recorder.rst))

## 融合 A1 与 B，先证明交互值得测

**A、B 整体不达标，不等于它们的单个机制毫无用处；A1“好像有点效果”也还不是已验证组件。** 先写经济理由：例如 A1 改善入场筛选，B 限制高资金费暴露，预期两者影响不同的错误来源；再确认它们是能在同一 origin 上独立开关的两个机制。若 A1 和 B 其实改的是同一止损阈值，或 B 的效果依赖 A1 才能定义，那么普通二因子解释不成立，应先拆清机制。跨领域的 MOST 方法把组件筛查、组合精炼和最终确认分开；NIST 的二因子设计说明同时识别单项与交互需要共同基线。把这些方法用于 Trade 是**实验设计推断**，不是论文已在量化市场验证了 A1B。([Collins 等，MOST](https://pubmed.ncbi.nlm.nih.gov/16097907/); [NIST 全因子设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri333.htm))

| 同一冻结条件下的候选 | A1 开关 | B 开关 | 必须回答的问题 |
| --- | ---: | ---: | --- |
| origin（00） | 关 | 关 | 没有两个改动时的共同基线是什么？ |
| A1（10） | 开 | 关 | A1 独自改变什么、损失什么？ |
| B（01） | 关 | 开 | B 独自改变什么、损失什么？ |
| A1+B（11） | 开 | 开 | 组合是否优于基线及两个单项，交互是否稳定？ |

对预先选择、定义清楚且可加的响应 `Y`，交互差是 `Y11−Y10−Y01+Y00`。同一数据、时间窗、37 币共享资金账户、费用与资金费规则、Nautilus 版本和风险边界下才能比较；还须读原生订单完整性、逐期净账户表现、资金占用、回撤与不同窗口。**Sharpe 和最大回撤不是可加贡献，四格差分也不是市场因果效应。** 组合可能通过共享资金争用改变成交，所以即使净值改善，也要查实际执行路径，不能直接宣布“两个 alpha 协同”。若四格不齐，只能说观察到一个组合结果，不能标记交互已证实。([NIST 交互的定义](https://www.itl.nist.gov/div898/handbook/pri/section5/pri594.htm); [Nautilus 原生报告](https://nautilustrader.io/docs/latest/concepts/reports/))

组合空间会按 `2^k` 增长，`A1B1`、`A1C`、`A6D3`、`C8G14` 逐格填满图的做法很快耗尽预算。高效规则应是：只有明确互补机制、预计可改变下一步决策、具备合法对照的组合，才拿到原生回放预算。先用来源、输入、数据质量、交易规则、容量或费用的便宜检查否掉无效候选；再做少量同口径原生配对及必要的四格实验；冻结候选和选择规则后在此前未暴露区间或后继市场数据确认。部分因子设计可以省运行数，但会混杂某些主效应与交互，不能当作“免费测完所有组合”。任何依据开发验证结果新生的 A1B1，都需要把该数据记为已暴露。([NIST 部分因子设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri334.htm); [NIST 确认运行](https://www.itl.nist.gov/div898/handbook/pri/section4/pri46.htm); [Dwork 等，2015](https://arxiv.org/abs/1506.02629))

## 先量化研究决策，后验证独立策略结果

**蜂窝图的近期目标应是减少错查、错比和重复回放。** 用 Trade 真实历史题目做预先封存的交叉盲评：一组 Agent 用现有 Markdown 与文件搜索，另一组用 Git 侧录和局部谱系查询，第二批交换条件；固定模型、工具、时间和可见证据。题目包含 H13→H13b→H13c 的失败层级、H19a/H18a 的合法配对、一次审计结论的更正以及一条旧负结果的再利用。测正确父假设、源码身份、对照、原始证据及权威更正的找对率，完成时间、误报漏报、证据可打开率、记录维护时间；再盲评 Agent 提出的下一试验是否可否证、是否换了机制、是否有合法对照并遵守共享账户风险边界。图若只是使页面漂亮或查询更快却增加错误，就没有证明 ROI。([W3C PROV-DM](https://www.w3.org/TR/prov-dm/); [来源图导航研究](https://www.cs.ucdavis.edu/~ludaesch/pubs/Navigation-model-WORKS-2009.pdf))

**策略成功率是滞后且更难归因的终点。** 后续应固定研究时长、计算预算、候选登记和选择规则，对比每单位成本形成的可复核决策数、无效或重复回放比例，以及最终冻结候选在真正未暴露或前向数据中的净收益、Sharpe、回撤、完整性与账户风险联合资格。现有已暴露的一年不能因为有图而变成新的独立样本；样本不足就报告“不知道”，不能给出猜测的成功率提升百分比。PBO、DSR、SPA 可在拥有完整候选集与对齐净回报后作诊断，但任何一个指标都不足以单独认证可交易性，且不应把 PBO 本身变成优化目标。([Bailey 等，PBO](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf); [Bailey 与 López de Prado，DSR](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf); [Hansen，2005](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=264569))

## Conclusion

你的设想值得保留为**假设谱系与组合试验方法**：让分叉解释“为何改”，多父融合解释“取了谁的什么机制”，冻结对照解释“比谁好”，失败和回访解释“往哪退、何时可重试”。先让 Agent 通过有类型关系和原生证据检索这些答案，再比较局部图、表格和蜂窝布局哪种更快更准。只有当按图选择的后继试验在固定预算下形成更多可信结论，并在独立数据中产生合格策略时，才能进一步声称它提高了投研效能或策略发现率。
