# 让实验组织与原生证据共同校准策略研发
> 归档研究材料：本文保留起稿时判断；仓库内证据链接固定在提交 `163478559`。后续实现与效能试验以正式记录为准。

**结论：策略研发需要两条相互约束的工作链。**Agent 负责从既有正反例选择一个能被否证的问题，预先固定合法对照与停止条件，再根据事实选择下一实验；原生回放和确定性统计工具负责证明运行可比、机制确实触发、完整账户发生了什么，以及差异有多不确定。RD-Agent(Q) 的公开实现展示了“假想—实现—回测—反馈”循环，但其因子反馈主要压缩为 IC、扣成本年化收益和最大回撤，不能直接替代共享账户的逐订单诊断；QuantConnect 的官方流程则强调先核对订单行为、再比较纸面与回测、最后解释表现衰减。两者都没有公开证明连续自适应试验后的选择偏差已经自动解决。对 Trade，最小产品形态是**现有 Git 尝试/运行记录 + Nautilus 原生报告 + 只读诊断与统计结果 + Agent 的有证据反馈**，无需另一套回测引擎、账本或研究服务。([RD-Agent(Q) 论文](https://arxiv.org/html/2505.15155); [RD-Agent(Q) 反馈代码](https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/developer/feedback.py); [QuantConnect Paper Testing Agent](https://www.quantconnect.com/docs/v2/ai-assistance/predefined-agents/paper-testing-agent); [Trade 当前架构](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/architecture.zh.md#L5))

## Agent 先定义可被推翻的问题，再选择最小合法实验

**下面是建议的操作契约，不是已经由某个通用 Agent 自动保证的方法。**RD-Agent(Q) 的 Specification、Synthesis、Implementation、Validation、Analysis 五阶段说明怎样传递假想和反馈；其“有微小改善即可替换最好因子”的公开提示不适合作为 Trade 的策略资格规则。NIST 实验设计要求先定目标、响应、可操作因素与合法组合。Trade 的 `find/show/compare`、`attempt.json` 和预登记已经提供部分骨架；每轮新假想的反证条件、候选搜索预算和已读数据窗口应由 **RD Agent 在看结果前自行提出并登记**，再受确定性检查约束。用户只需给长期目标和不可越过的风险边界，无需逐轮指定研究方向。([RD-Agent(Q) 论文 §2](https://arxiv.org/html/2505.15155); [RD-Agent(Q) 公开提示](https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/prompts.yaml); [NIST 实验目标](https://www.itl.nist.gov/div898/handbook/pri/section3/pri31.htm); [当前记录指南](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/records/README.md#L13))

## F01 说明组合变差时如何从事实收窄解释

**F01 的 A 是整套 H19a 宽摆动双层计划，B 是持仓后确认线跌破时取消未成交入场。**B 在 H15a 与 H19a 两个底座都能独立开关，因此事前登记 `00/10/01/11` 四格；四格固定 37 币、原生共享账户和成本口径。先过合成生命周期与两币执行门槛，再跑完整年度；B 未触发就停止组合效果的经济解释。这个设计回答“B 在 A 已存在时的条件增量”和“同一 B 的效果是否因底座变化而不同”，并不把 A 的选择器、止损和持有寿命拆成彼此独立的因子。([F01 预登记](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-factorial-line-cancel-prereg.zh.md#L5); [NIST 两因素交互](https://www.itl.nist.gov/div898/handbook/pri/section3/pri32.htm))

**当前已证实的窄事实是：这个已暴露年度的完整账户里，11 比 10 少 582.64 USDT，而 01 比 00 多 741.36 USDT。**11 发生 37 次 B 取消请求，正数量成交入场从 881 降到 853；佣金从 971.32 降到 930.52 USDT，净资金费调整从 +46.21 变成 +29.17 USDT，但期末净权益下降。四格同步 52 周重采样的 `11−10` 年化日收益差 95% 探索性区间是 [−3.78,+1.24] 个百分点，交互区间是 [−5.01,+1.84]；两者跨零且没有校正此前候选筛选。11 同时未达事前的年化与胜率联合目标，因此可裁决**“当前组合未通过开发期经济门槛”**，却不能裁决“B 一般无效”或“负交互已被独立证实”。([F01 原生四格结果](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-factorial-line-cancel-result.zh.md#L11); [F01 比较脚本及统计限制](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/strategies/r1/compare_factorial.py#L187); [F01 裁决](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-factorial-line-cancel-result.zh.md#L22))

**下一步诊断应先查第一处分叉，不应按这 582.64 USDT 反推某一笔取消的独立损益。**建议对齐 10/11 的第一条不同取消/订单事件，核其后是否改变成交、仓位、原生账户锁定与可用资金、sizing、手续费和资金费，再定位差额在哪些日期扩张；若完整事件流未保留，则停在“取消动作改变整体账户路径”这一可证范围。当前 `compare_factorial.py` 已核四格口径、动作计数、账户及同步收益，并给探索性区间，`cli compare` 只提供描述性摘要；统一的首个事件分叉证据包还未验收。旧 F01 四格大 CSV 仍在 `/tmp` 且标 `temporary`，后来仅 11 格有本机受管重跑封存，不能把旧四格称作都已可恢复。([F01 比较代码](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/strategies/r1/compare_factorial.py#L110); [Trade `compare` 输出](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/records/cli.py#L446); [F01 归因边界](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-factorial-line-cancel-result.zh.md#L20); [当前保管状态](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/records/README.md#L55))

## 用一页证据包约束 Agent 的反馈与下一步

**最小证据包建议只包含五段：**①问题、父假想、合法对照、预定主响应与停止条件；②每格源码/输入/账户身份及完整性、动作激活；③带原生事件 ID 的首处分叉和其后账户路径，不能证明则标缺口；④净账户点估计、回撤/费用/资金费、同步逐期差和区间的方法与限制；⑤候选搜索史、样本暴露、独立确认状态以及允许的结论范围。这些是对现有记录和原生报告的**只读组合视图建议**，不是新增状态主表、引擎或自动“有效”标签。证据不足时，Agent 的反馈应原样给缺口，并只提出能补上关键缺口的最小行动。([现有记录与状态边界](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/records/README.md#L28); [原生报告](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/strategies/r1/run_portfolio.py#L194); [White 2000](https://doi.org/10.1111/1468-0262.00152); [Trade 架构边界](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/architecture.zh.md#L19))

**反馈的固定写法建议是“本轮问题和对照 → 已证事实及引用 → 仍未知的机制环节 → 可被下一次观察推翻的解释 → 下一实验及停止条件”。**先验证执行/数据错误；若动作正确且固定账户的负差清楚，就拒绝当前组合、保留 A 与失败的 AB 记录；若方向区间宽或搜索历史缺失，就写不确定并停止在同一暴露年度追分；只有预先冻结的新数据确认，才讨论更强的有效性表述。这个反馈规则综合了 RD-Agent(Q) 的假想—反馈字段、QuantConnect 的事实/根因区分、NIST 的预定目标和选择偏差文献，**是 Trade 的建议契约而非这些来源提供的现成功能**。([RD-Agent(Q) 反馈代码](https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/developer/feedback.py); [QuantConnect Paper Testing Agent](https://www.quantconnect.com/docs/v2/ai-assistance/predefined-agents/paper-testing-agent); [NIST 实验目标](https://www.itl.nist.gov/div898/handbook/pri/section3/pri31.htm); [Cawley–Talbot 2010](https://www.jmlr.org/papers/v11/cawley10a.html))

**方法论是否提高 Agent 的准确度也要独立测。**现有八题隔离试验中，索引组三次均 32/32、旧资料组三次均 30/32；双方共有信息的事后敏感性是 31/31 对 30/31，差异主要是精确运行身份，下一步推论边界两组都满分。索引组中位活跃时间还多 15.35 秒，因此目前不能说记录已经提高研究决策质量或效率。下一轮应预先封存新题、正确证据路径和评分表，盲评“是否合法对照、是否找准失败层、是否给可否证下一步、是否拒绝已暴露样本晋级”，同时记录时间和读报告成本；长期结果再看冻结候选在未暴露数据上的原生净账户和风险。([当前隔离试验与限制](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/research-record-efficiency.zh.md#L16); [Dwork 等自适应数据分析](https://arxiv.org/abs/1506.02629))

## Conclusion

真正的闭环不是“回测给分，Agent 按分改规则”，而是**每次结果先缩小可被证明的命题，再选择最便宜、最能区分两种解释的下一实验**。证据包越能显示原生行为与不确定性，Agent 越有机会避免错误解释；但已暴露年份、缺失候选和执行模型误差不会因为报告更漂亮而消失。当前最值得验证的改进，是在现有文件和脚本上做一份可复核的首分叉/统计读回，并用新题盲评它是否真的提高下一步判断的正确率；F01 的研究结论仍以开发期失败和未知的稳定交互为界。([F01 现有范围](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-factorial-line-cancel-result.zh.md#L22); [Trade 架构](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/architecture.zh.md#L29); [当前 Agent 试验](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/research-record-efficiency.zh.md#L31))
