# 让投研记录真正服务策略迭代
> 归档研究材料：本文保留起稿时判断；仓库内证据链接固定在提交 `163478559`。后续实现与效能试验以正式记录为准。

**结论：这项设计值得做，但原稿把数据模型定得过早，也没有证明它能提高策略成功率。** 外部论文与开源项目支持保存精确运行输入、失败试验、候选集合、数据暴露和可追溯产物；它们不支持直接推出“四类记录”、新服务或某个胜率提升。对当前 Agent 选题、Git 管策略源码、Nautilus 负责交易事实的项目，第一版应是 **Git 中可校验的少量研究侧录，加长期保存的原生报告，以及按 ID 读回的命令行工具**。设计的直接目标是让下游 Agent 更准确地找到可复用的机制、选合法对照、识别失败层级和回退点；是否因此产生更多可用策略，必须另作前瞻验证。本文给出选择依据、最小数据结构与一个同时测检索、决策和成本的试点；所有效果数字目前均未实测。

## 标准证明要保存谱系，金融论文要求保留整个选择过程

**W3C PROV-DM 的可借鉴部分是“实体、活动、责任主体及其关系”，不是数据库或文件格式。** 策略源码、数据回执和原生报告可以视为实体；修改、来源核查和回放是活动；执行的 Agent 是责任主体。尤其要避免把“运行使用了某版本”自动当作“新策略由它修订”，也不能把源码父版本自动当作经济对照。`code_parent`、`hypothesis_parent`、`control_run`、`fixes_run` 应有不同含义和明确依据；这些键是本项目的领域设计，并非 PROV 的标准字段。FAIR 原则同样支持持久标识、可检索元数据、限定关系、详细来源，以及原物丢失后仍保存可读的元数据；它明确不指定 JSON、RDF 或服务架构。([W3C PROV-DM](https://www.w3.org/TR/prov-dm/)) ([FAIR 原文](https://www.nature.com/articles/sdata201618))

**可复现研究的最低要求是把解释绑定到实际结果，而非整段 Agent 对话。** Sandve 等人的规则要求保留影响结果的输入、程序版本、参数、工作流程和自定义脚本的精确版本，并从文字结论追到结果与中间产物。因此，`git commit` 只能辅助定位；若运行时有未提交修改，它不能单独证明实际执行字节。当前 R1 `summary.json` 已记录多个源码 SHA-256 和 runner SHA-256，并导出订单、成交、仓位、账户与逐期收益，但尚无一份统一冻结源码包、锁文件、Catalog 输入身份和全部产物哈希的运行清单；`SOURCE_COMMIT` 还是来源原型常量，不应被读作当前运行提交。([Sandve 等，2013](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1003285)) ([本仓库 runner](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/strategies/r1/run_portfolio.py#L193)) ([来源常量](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/strategies/r1/replay_util.py#L10))

**金融研究增加了一个通用实验工具不会替我们解决的问题：选择偏差。** PBO 论文把多候选在同步时点上的回报组成矩阵，研究样本内选优如何在样本外失效；DSR 论文要求考虑除赢家外的试验数量及其绩效分布，并区分执行试验数与有效独立试验数。这支持记录失败、弃用、只读诊断和被选择候选的全集，保存同口径逐期收益与数据暴露状态；它不意味着把 S/D/H 编号数量直接代入 DSR，也不意味着当前 H 系列已有某个可量化的过拟合概率。用同一已暴露年度反复改策略，即使本次假设先于本次回放登记，也不能反推这一年是未触碰的独立验证集。([Bailey 等，PBO 作者版](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)) ([Bailey 与 López de Prado，DSR 作者版](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf))

## 开源项目提供记录层级，却没有现成的投研因果模型

**Qlib 的 Recorder 是量化领域最直接的产品形态参考：experiment 下有多个 recorder/run，可查参数、指标、状态和产物，官方实现基于 MLflow。** Qlib 的工作流还包含自己的模拟执行栈，因此这里只借“研究集合—运行—产物”的读回方式，不引入另一套撮合、账户或策略语言。MLflow 已提供 run ID、标签、指标搜索、数据输入及 artifact store；其父子 run 示例主要组织调参试验，不表达“父假设被什么证据否定”。Nautilus 的 Catalog 和原生订单、成交、持仓、账户报告仍是本项目交易事实的唯一来源。([Qlib Recorder 文档](https://github.com/microsoft/qlib/blob/main/docs/component/recorder.rst)) ([Qlib 工作流文档](https://github.com/microsoft/qlib/blob/main/docs/component/workflow.rst)) ([MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/)) ([Nautilus Reports](https://nautilustrader.io/docs/latest/concepts/reports/))

**MLflow 与 DVC 解决的重心不同。** MLflow 的 metadata backend 与 artifact store 分离，适合大量 run 的筛选及界面读回；但 Nautilus 报告必须由本项目显式记录，工具既不会判断共享账户口径，也不会自动验证资金费、部分成交或独立资格。DVC Experiments 以 Git 基线保存受跟踪的工作区实验，比较文件化参数和指标；它适合需要版本化大输入和可声明流水线依赖的阶段，但本地实验 ref、远端 artifact 与 Git 共享要分别管理，且未跟踪文件不会自动进入快照。两者的默认父子/基线关系都不能代替 `hypothesis_parent` 或合法 `control_run`。([MLflow Tracking API](https://mlflow.org/docs/latest/ml/tracking/tracking-api/)) ([MLflow 存储架构](https://mlflow.org/docs/latest/self-hosting/architecture/backend-store/)) ([DVC Experiments](https://doc.dvc.org/user-guide/experiment-management)) ([DVC 运行与依赖](https://doc.dvc.org/user-guide/experiment-management/running-experiments))

对本仓库，已有 `results/` JSON 摘要和长篇 `RD_EXPERIMENTS.md`，同时 R1 README 明说 `/tmp` 回放目录只是本地证据。**当前更紧急的是把研究判断连到可长期打开的原生报告，而不是先建 UI。** H19a 的配对回放证明，同一 runner、数据窗口和共享账户下可有可比较对照；第一次独立审计又把部分成交后取消的父单误判为缺保护，修正审计后才通过。若只检索“通过/失败”摘要，下游 Agent 会把被纠正的解释当成事实。因此应保留旧审计及更正关系，并让最新结论指向原生事件和报告哈希。([R1 README](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/strategies/r1/README.md#L38)) ([H19a 配对与审计更正](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/r1_native/RD_EXPERIMENTS.md#L1183))

## 第一版用两种侧录和受管产物，暂缓四对象注册表

**建议的产品形态是文件契约加读回工具，而非独立投研服务。** Git 保存 `attempt.json`、`run.json`、短篇 Markdown 判断和 JSON Schema；每次原生运行的较大 CSV、源码包或可准确恢复的源码引用、输入 manifest、哈希清单放到有备份与保留规则的非 `/tmp` 受管目录。文件先写到 staging，校验后封存并发布不可复用的 `run_id`；旧文件缺失时保留引用和 `unavailable`，不补造“可复现”。CLI 最初只需按 ID 读回假设父链、源码父链、冻结对照、失败/更正和证据可用性，并在比较前检查账户、时间、数据、费用与原生完整性。JSON Schema 负责键与类型校验；Markdown 保存不能压成枚举的研究解释；原生 CSV/Parquet 保存行级事实。([JSON Schema 规范说明](https://json-schema.org/understanding-json-schema/reference/schema)) ([Nautilus Reports](https://nautilustrader.io/docs/latest/concepts/reports/))

**原草案“四类记录”是待检验提案，不是标准给出的最小模型。** 第一版可以只把研究尝试和实际运行独立成两类：没有运行的来源核查也有 `attempt`；一次假设可有 pilot、失败、修复和完整配对等多个 `run`。证据引用先内嵌在两者的 typed `refs` 中，跨研究复用到一定程度再独立成 evidence registry；Strategy 版本先用 Git 引用加实际源码包 digest，不另造与 Git 竞争的版本主表。`attempt` 至少含稳定 ID、研究问题、父假设及其确切失败、机制差别、事前可否证条件、拟用对照与读取前封存凭据；`run` 至少含所属 attempt、角色、实际执行源码和依赖身份、Nautilus 版本、输入数据及可交易窗口、共享账户/费用口径、状态、原生报告 URI/哈希和完整性结论。未发生的运行不生成 `run`；旧记录不可还原的字段明确写 `unknown`，不得把事后补录伪装成事前登记。该缩减是基于当前读回需求的工程推断，需要用历史样例检验。([当前设计草案](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/research-record-contract.zh.md#L23)) ([Qlib Recorder 文档](https://github.com/microsoft/qlib/blob/main/docs/component/recorder.rst))

关系要服务下游动作，而不是为了画完整图谱：`hypothesis_parent` 回答下一条想法承接了哪个被否定命题，`code_parent` 回答实际源码如何回退，`control_run` 指向已冻结且同口径的反事实对照，`fixes_run` 连接修正前后解释；另记 `comparison_family_id`、候选集合、选择指标和已暴露窗口，防止只保存赢家。选择“下一个假设”时，Agent 应能检索同机制的正反例与论文/来源，先做最窄的来源或原生事件否证；比较改善时系统只能在同账户、同数据与窗口、同费用定义且报告可复核时给出相对数。结构化索引**提供可审阅的候选与约束，不自动选择研究方向**。([W3C PROV-DM](https://www.w3.org/TR/prov-dm/)) ([Bailey 等，PBO 作者版](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)) ([本仓库 D59/D60 门槛](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/r1_native/RD_EXPERIMENTS.md#L1163))

何时升级也要由观察触发：若实测按 ID 找证据、跨机制筛选或多 Agent 并发已使文件工具成为瓶颈，可从 Git 侧录与产物 manifest **重建 SQLite 派生索引**；SQLite 支持常见组合索引。若再需要共享 run UI、跨机器 artifact store 和更复杂检索，优先做 MLflow Tracking 小样本 PoC，仍由 Git 契约保存假设与资格语义；若主要瓶颈是大 Catalog/产物版本及流水线复现，再评估 DVC。当前未安装或试跑 MLflow/DVC，Python 3.14 兼容性、数百 MB 上传时间、并发性能、备份成本以及本仓库集成工时均**未验证**，不能宣称哪个工具已有更高 ROI。([SQLite 索引文档](https://www.sqlite.org/lang_createindex.html)) ([MLflow Tracking Server](https://mlflow.org/docs/latest/self-hosting/architecture/tracking-server/)) ([DVC 远端存储](https://doc.dvc.org/user-guide/data-management/remote-storage))

## 交叉试点先测决策效能，再等待独立策略结果

**现有资料只能确认痛点，不能给出结构化记录带来的收益率。** F25 的“八个完整候选”统计截止 H12，不能当成今天的全集；后来 H14a 与 H19a 等又增加了完整经济回放。D59 来源门槛失败没有新订单或收益分数，H19a 两币 pilot 仅是完整性门槛，H19a/H18a/H15a 同窗口年度配对仍是已暴露样本。这些类别若混成“实验数”和“成功率”，基线就失真。H06 别名检索得到双零集却误报精确一致，以及 H19a 审计更正，已经提供检索错误和解释回退的真实测试题。([F25 历史截面](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-native-rd-findings.zh.md#L267)) ([F24 别名误判](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/docs/plans/r1-native-rd-findings.zh.md#L259)) ([H19a 台账](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/r1_native/RD_EXPERIMENTS.md#L1181))

试点应先封存一组真实任务、答案与裁判依据，覆盖 H13 假设失败链、H18a/H19a 配对、一个负结果跨研究复用以及审计更正。用两个难度相近的批次，让同一组 Agent 在“现有台账+文件搜索”和“少量经核实的侧录+按 ID 查询”之间交叉切换，并对调顺序；固定模型、工具、时间、计算预算，盲评输出。旧历史只补可证实字段，不能把已见答案倒填为预登记。先量化**父假设/源码/对照/原生报告/权威更正找对率、误报漏报率、完成时间、原始证据打开率**；再让 Agent 提出下一研究动作，按预先公布的评分表评估是否定位最窄失败层级、提出不同且可否证的机制、给出合法对照与来源、费用、资金费、Sharpe、回撤和共享账户约束，并拒绝已暴露年度的参数扫优。读回更快但错误更多，应判为失败。

下游效率还须在固定研究预算中观察：从登记到明确停止/通过门槛的时间、重复或无效回放比例、可复核的同账户配对结论数、每个有效结论的计算量与人工时、侧录本身的写入和维护成本。**完整回放次数不是越多越好**：若早期来源核查正确否掉错误机制，少跑昂贵年度回放可能是收益。可以事前将“正确率不下降、决策评分改善、节省的检索/返工时间超过录入成本”设为继续投资的工程门槛；这是拟议的验收规则，绝非已观测效果。还要记录学习效应、补录优势、同期 Nautilus/数据修复、市场时期与模型变化；交叉与盲评只能减少，不能消除这些混杂。

**“策略迭代成功率提高”是更长的独立结果，不能由上述代理指标代替。** 只有将后继策略和选择规则预先冻结，在此前未暴露的时间段或前向数据中，按原生订单完整性、净收益、胜率、Sharpe、回撤和账户风险联合验收，并同时保有完整源码、对照与数据身份，才能观察是否产生合格策略。一个小试点即使显著改善检索和下一步决策，也只能证明记录改善了研究输入；新市场期不足时必须写“尚未观察”，不能用已暴露一年中更好的点估计当成果。([Bailey 与 López de Prado，DSR 作者版](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)) ([H19a 已暴露配对](https://github.com/qOeOp/trade/blob/163478559baa8560d2dd8670ab25847c4804d7e6/research/r1_native/RD_EXPERIMENTS.md#L1183))

## Conclusion

最应先开发的是**可信关系和证据读回能力**：让 Agent 能从失败找到下一条可证伪假设，从候选找到真正可比的对照，从解释找到原生事实。存储技术应服从这几个问题的实测难度；现在建服务、图数据库或第二套回测工作流都缺乏证据。下一步的研究不是继续添加字段，而是用少数真实失败链完成侧录和盲测试点；若它既未减少错误，也未改善决策质量，就应缩减或推翻这份设计。
